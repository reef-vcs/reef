# R1.25 Zero-step repository onboarding

Phase 1 · Size M · Depends on: R1.05 (`Repositories.Register`, `resolve_repo`), R1.22 (the CLI skeleton and `--repo` resolution), R1.21 (`ws run` is the command this most often fires from) · Unblocks: R1.24 (the quickstart drops its "register" step and its jj prerequisite), R1.27 (`reef init` builds on this), RX.07

## Context

Phase 1 ships "as a standalone tool against existing jj repositories" (`docs/design.md`, Roadmap), and R1.22's `--repo` resolution requires the repository to have been registered first. For a human following the quickstart that is two steps (`jj git init --colocate`, `reef repo register`). For an agent dropped into a plain git checkout and told to use Reef it is a dead end: `reef ws run` answers `NotFound: repository containing /path`, and the agent has no way to know that the fix is to install a second tool, read its documentation, and initialize a `.jj` directory. Both steps can be done by Reef itself, visibly and reversibly, the first time a command needs a repository.

This ticket makes any `reef` command that resolves `--repo` by path register the repository on the way, and makes registration create the jj side of a colocated repository when the path is a git repository without one. The user's checkout gains a `.jj` directory and one line in `.git/info/exclude`; nothing else changes, and `rm -rf .jj` undoes it.

### What was verified while writing this ticket

- `reef_lib::jj::Repo::open` returns `OpenError::NotAJjRepo(path)` when neither the path nor any ancestor has a `.jj` directory (`crates/reef-lib/src/jj/repo.rs:144`), and `RegisterError::Open` wraps it with its kind (`crates/reef-daemon/src/repo/registry.rs:22`), so a plain git repository registers today as `NotFound`.
- `reef_lib::jj::Repo` has `init_internal_git` and `init_colocated_git` (`repo.rs:248`, `:271`). `init_colocated_git` goes through `GitBackend::init_colocated` (jj-lib 0.46.0 `git_backend.rs:246`), which calls `gix::ThreadSafeRepository::init_opts` on the workspace root, and gix 0.88.0 refuses when `.git` is already a directory (`gix/src/create.rs:190`, "Refusing to initialize an existing directory"). An existing git repository therefore needs `jj_lib::workspace::Workspace::init_external_git(settings, workspace_root, git_repo_path)` (jj-lib `workspace.rs:260`) with `git_repo_path = <root>/.git`, which reef-lib does not wrap yet.
- jj-lib writes nothing to `.git/info/exclude` (no match in `jj-lib-0.46.0/src`); the `jj` CLI adds `/.jj/` there itself when it colocates. Reef has to do the same or `git status` in the user's checkout shows `.jj/` as untracked.
- `Repo::is_colocated` compares the git backend's repository path with `<root>/.git`, both canonicalized (`repo.rs:289`), so a repository initialized through `init_external_git` on `<root>/.git` reports colocated, and R1.05's `import_git_refs` (`crates/reef-daemon/src/workspace/create.rs:511`) brings `main` and the other branches into jj's view before the first workspace is created.
- `WorkspaceManager::resolve_repo` (`crates/reef-daemon/src/workspace/manager.rs:313`) maps an absolute path with no registered root to `DbError::NotFound { what: "repository containing", id: <path> }`; the CLI sends the current directory when `--repo` is absent (R1.22). `RegisterRequest` has one field, `path` (`repositories.proto:19`).
- The daemon's `Config.identity` (`crates/reef-daemon/src/config.rs:612`) and `reef_lib::jj::settings::user_settings(&Identity)` (`settings.rs:129`) give the `UserSettings` that `init_external_git` needs for the empty working-copy commit it creates.
- A git worktree or submodule checkout has a `.git` *file*, not a directory. `init_external_git` pointed at a file fails inside gix; this ticket refuses earlier with a hint rather than surfacing that error.

## Decisions

- **Registration can initialize jj alongside git.** `RegisterRequest` gains `enum IfNotJj { FAIL = 0; INIT_ALONGSIDE_GIT = 1; } IfNotJj if_not_jj = 2;` and `RegisterResponse` gains `bool initialized_jj = 3;`. With `INIT_ALONGSIDE_GIT`, on `NotAJjRepo` the daemon walks up from `path` for a directory containing `.git`; if `.git` is a directory it calls the new `reef_lib::jj::Repo::init_in_git_repo(root, settings)` (a wrapper over `Workspace::init_external_git(settings, root, &root.join(".git"))`), appends `/.jj/` to `<root>/.git/info/exclude` unless a line equal to `/.jj/` or `.jj/` or `.jj` is already there (creating `info/` and the file if missing), and continues with the normal register path. If `.git` is a file, `InvalidArgument` with the message `<root> is a git worktree or submodule; run from the main checkout` and the `next` of R1.26 empty. If there is no `.git` either, the error stays `NotFound` with the hint `not a git or jj repository; run git init first`. Reef never creates a repository from nothing in Phase 1.
- **Colocated, never an internal store.** The user keeps using `git` in the checkout; jj's view imports git refs on every Reef operation that opens the repository (R1.05), and nothing is exported back (a Phase 1 limitation R1.24 already lists). `init_internal_git` stays for tests.
- **Implicit registration is the CLI's doing, not the daemon's.** When a command resolves `--repo` by path and the daemon answers `NotFound` whose chain starts with `repository containing`, the CLI calls `Register { path, if_not_jj: INIT_ALONGSIDE_GIT }`, prints `reef: registered <root>` (with ` and initialized jj alongside git` when `initialized_jj`) on stderr unless `--quiet`, and retries the command once. A second `NotFound` is returned as-is. This applies to every command that takes `--repo` (`ws create`, `ws run`, `ws list --repo`, `ws gc --repo`, `store build`, `store list --repo`); it never applies to `repo forget` or to a `--repo` given as an id or prefix. The daemon mutating a user's checkout as a side effect of resolving a path would be invisible; the CLI makes it one visible line.
- **Opt out at two levels.** A global flag `--no-register` (so `reef ws run --no-register` fails as today), and `[repo] auto_register = true` in `config.toml` (R1.04's loader, unknown keys still errors; `reef config show` prints it). `reef repo register` itself gains `--no-init` to refuse a non-jj repository as it does today, and registers colocated by default.
- **`repo register` of an already registered path stays `AlreadyExists`** (R1.22); the implicit path never reaches that case because it only runs after a `NotFound`.
- **Identity for the initial commit** comes from the daemon's `Config.identity` exactly as every snapshot does. No prompt for a name or email, ever (R1.26's contract).
- **Logging and audit.** One `info` event `repository initialized alongside git` with `repo` and `root` fields (R0.09 field names), and the `Register` response says so, so `ws run -o json` output never hides that the checkout was changed.
- **ADR 0024, "Repository onboarding: implicit registration and jj alongside git"**, records the mutation-of-the-user's-checkout decision, the colocated-only choice, the exclude line, and the alternatives: the daemon doing it silently (rejected: invisible side effect), requiring `jj` on `PATH` and shelling out to `jj git init --colocate` (rejected: a second install for the agent to discover, and jj-lib already does it), and an internal store under `.jj` only (rejected: the user's `git` would stop seeing jj's commits, and R1.05's ref import is built for colocated).

The `if_not_jj` and `initialized_jj` fields above, with comments naming this ticket. `reef_daemon::client::Client::register_repository` gains an `if_not_jj` parameter; existing callers pass `FAIL`.

### `crates/reef-lib/src/jj/repo.rs`

```rust
/// Creates the jj side of a colocated repository in the existing git
/// repository at `root` (`root/.git` must be a directory), with one empty
/// working-copy commit on top of git's HEAD, and opens it. The equivalent of
/// `jj git init --colocate` in a checkout that already has `.git` (R1.25).
pub async fn init_in_git_repo(root: &Path, settings: &UserSettings) -> Result<Self, InitError>;
```

`InitError` gains `NotAGitRepo(PathBuf)` (no `.git` directory) and `GitFile(PathBuf)` (`.git` is a file), both `InvalidArgument` under `Classify`. A test in `crates/reef-lib/tests/jj_spike.rs` creates a git repository with `gix` (one commit on `main`), calls `init_in_git_repo`, and checks `is_colocated()` and that `main` is visible after `import_git_refs`. The exclude line is the daemon's job (below) and is tested there with `gix`'s status, so neither test needs a `git` binary.

### `crates/reef-daemon/src/repo/registry.rs`

`RepoRegistry::register` takes `if_not_jj: IfNotJj`. On `OpenError::NotAJjRepo` with `INIT_ALONGSIDE_GIT`: `find_git_root(path)` (walk up for `.git`), then `Repo::init_in_git_repo`, then `write_jj_exclude(&root)`, then proceed as before. `RegisterError` gains `GitWorktree(PathBuf)` and `NotARepository(PathBuf)` with the messages in Decisions. `write_jj_exclude` is a `pub(crate) fn` in `crates/reef-daemon/src/repo/exclude.rs`, idempotent, unit tested for the three existing-line spellings and for a missing `info/` directory.

### `crates/reef-daemon/src/config.rs`

`[repo] auto_register = true` (`FileConfig.repo.auto_register`), listed in `KEYS`, shown by `reef config show`, and added to the configuration table in the Phase 1 README ("State directory and configuration"). ADR 0013's section list gains `[repo]`; its status stays accepted.

### `crates/reef-vcs/src/cli/mod.rs`, `repo.rs`

`--no-register` on `Global`. `Ctx::call_with_repo` (or an extension of `Ctx::call`) implements the retry: it needs to know whether the request's `repo` was a path, so commands pass `RepoArg::Path(abs) | RepoArg::Named(text)` instead of a bare string; `--repo` parsing decides which (an existing absolute or relative path that exists on disk is a path, anything else is a name). `repo register` gains `--no-init`. The stderr line uses `Out::note` so `--quiet` silences it and JSON mode keeps stdout clean.

## Implementation notes

- `find_git_root` stops at the filesystem root and at the first `.jj` found on the way up (then it is a jj repository the path resolution should have found: re-run `Repo::open` on that directory rather than initializing inside a jj repository).
- The exclude write happens before `register` records the row, so a crash between the two leaves a valid colocated repository that the next command registers normally.
- `init_external_git` creates jj's working-copy commit from an empty tree with git's HEAD commit as parent (jj's "files already in path are not snapshotted" behavior); the user's checkout is the default workspace and Reef never snapshots it (R1.13 watches only Reef workspaces), so this is harmless. Say so in the ADR, because it looks alarming in `jj log`.
- Keep the retry to exactly one; an agent in a loop must not be able to make the CLI register a path repeatedly.

## Verification

```sh
d=$(mktemp -d) && cd "$d" && git init -q && git commit -q --allow-empty -m init
REEF_STATE_DIR=$(mktemp -d) reef ws run -- sh -c 'echo hi > hi.txt'
# stderr: reef: registered <d> and initialized jj alongside git
ls -a "$d" | grep -c '^\.jj$'            # 1
grep -c '^/\.jj/$' "$d/.git/info/exclude" # 1
git -C "$d" status --porcelain           # empty
```

## Out of scope

- Creating a repository where none exists (`reef init` in an empty directory is R1.27's command name, and it refuses the same way).
- Exporting jj bookmarks back to git refs (Phase 4).
- Registering repositories found by scanning a directory tree.
- Windows paths and `.git` junctions (RX.05).

## Risks

- A user's `jj` binary newer than jj-lib 0.46 may upgrade on-disk formats when they run it in a Reef-initialized repository (ADR 0008's compatibility statement). The quickstart's limitations list gains a line.
- Tools that do not honor `info/exclude` (some IDE indexers) will see `.jj/`; the alternative, editing `.gitignore`, mutates tracked content and was rejected in the ADR.
- The path-versus-name heuristic for `--repo` can misclassify a 16-hex-character directory name that happens to exist; it then registers that directory, which is what the user pointed at.
