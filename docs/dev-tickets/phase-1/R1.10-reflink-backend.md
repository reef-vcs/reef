# R1.10 Reflink backend (btrfs, XFS)

Phase 1 · Size S · Depends on: R1.08 (the per-file clone walk, the `DirCloner` seam, and the base cache's incremental path) · Unblocks: nothing directly; it is the copy-on-write backend for Linux machines where the daemon cannot mount overlays (R1.09) but the state directory is on btrfs or XFS

## Context

Design, "Workspaces": "Linux with btrfs or XFS: Reflink copy. Metadata per file. Disk per workspace: modified files only." On Linux the preferred backend is overlayfs (R1.09), which needs either `CAP_SYS_ADMIN` or the `fuse-overlayfs` binary. A developer laptop on btrfs, or a container without FUSE, has neither, and this backend gives it per-file copy-on-write at the cost of one `ioctl` per file. There is no directory-level clone on Linux, so creation is O(files) syscalls; the exit criterion ("under one second on APFS and overlayfs") does not name reflinks, and this backend is expected to miss it on the large preset. R1.12 records by how much.

### What was verified while writing this ticket

- `reflink-copy` 0.1.30 (`src/sys/unix/linux.rs`): `reflink(from, to)` opens `from`, creates `to` with `O_EXCL` through an auto-removed temporary handle, calls `rustix::fs::ioctl_ficlone(&dest, &src)`, and persists `to` with the source's permissions. It does not set the mtime (the new file's mtime is "now"), does not handle directories or symlinks (the crate's own doc says the Linux error for those is "inscrutable" and it wraps it), and is "not atomic" (a temporary file is created then renamed). `reflink_or_copy` falls back silently and is not used here. `check_reflink_support` returns `ReflinkSupport::Unknown` on every platform but Windows, so availability is probed by a trial clone.
- `FICLONE` (`ioctl_ficlone`) requires both files on the same filesystem and a filesystem that implements `remap_file_range`: btrfs, XFS with `reflink=1` (the `mkfs.xfs` default since xfsprogs 5.1), bcachefs, and OCFS2. ext4 and tmpfs return `EOPNOTSUPP`; a cross-filesystem call returns `EXDEV`. Cloned extents are shared until written; `st_blocks` of the clone reports the full size, so `disk_usage` must not sum it (same as APFS, R1.08).
- R1.07's `copy_tree` restores the mtime of every regular file it produces through a `FileCopier` with `nix::sys::stat::utimensat`, which needs no write-open and so works on the read-only files `reflink` may create.
- GitHub's `ubuntu-24.04` runner (image 20261012.334.1, kernel 6.17.0-1022-azure, from `actions/runner-images` `Ubuntu2404-Readme.md` read on 2026-10-16) has its root filesystem on ext4. Testing the reflink path in CI therefore needs a loop-mounted btrfs or XFS image, which needs `sudo` (available: GitHub documents passwordless sudo on its Linux runners), and lives in R1.09's privileged `overlayfs` CI job rather than the default matrix.

## Decisions

- **Per-file FICLONE through `reflink_copy::reflink`, over R1.07's `copy_tree`.** `ReflinkCloner` implements `FileCopier` with `reflink(from, to)`; the walk creates directories and symlinks and restores mode and mtime. A clone failure is an error, never a copy: `BackendError::Unavailable` for `EOPNOTSUPP`/`EXDEV` (the filesystem changed since the probe), `BackendError::Io` otherwise.
- **Probe**: available if Linux, the target directory and the base cache directory are on the same filesystem (`fs_util::same_volume`), and a trial `reflink` of the one-byte probe file (`bases/.probe`, as in R1.08) into the target directory succeeds. The result is cached per repository for the daemon's lifetime; a `--path` on another filesystem is probed on its own.
- **Shares the base cache with R1.08** including the incremental `ensure_from` path: `ReflinkBackend` implements `DirCloner` by walking with `copy_tree` + `ReflinkCloner`, so a new base is built by cloning the nearest base (O(files) ioctls, still far cheaper than a full check-out of 100k files) and checking out the diff. On btrfs, a subvolume snapshot would be O(1) and is listed as a follow-up, not done here.
- **`swap_base` returns `NeedsCheckout`**, `tear_down` is `remove_tree_async`, `disk_usage` is the stat-only comparison with the base's `tree_state`, all exactly as R1.08.
- **Selection order** (README): after overlayfs and fuse-overlayfs, before copy. On a machine where both overlay tiers are unavailable and the state directory is btrfs or XFS, `auto` picks reflink; otherwise copy, with R1.07's warning.
- **No `cfg` on the filesystem type.** The backend compiles on every Linux and is selected by the probe, never by a config-time guess. On macOS the module is compiled out (`cfg(target_os = "linux")`); APFS is R1.08's.

## Deliverables

### `crates/reef-daemon/src/backend/reflink.rs` (`#[cfg(target_os = "linux")]`)

```rust
/// Per-file reflink (FICLONE) materialization for btrfs and XFS.
pub struct ReflinkBackend;

pub(crate) struct ReflinkCloner;
impl FileCopier for ReflinkCloner {
    fn copy_file(&self, from: &Path, to: &Path) -> io::Result<()> { reflink_copy::reflink(from, to) }
}

impl DirCloner for ReflinkBackend {
    fn clone_dir(&self, from: &Path, to: &Path) -> io::Result<()> { fs_util::copy_tree(from, to, &ReflinkCloner).map(drop).map_err(io::Error::from) }
}

impl Backend for ReflinkBackend {
    fn kind(&self) -> BackendKind { BackendKind::Reflink }
    fn materialize(&self, base: &BaseEntry, ws: &WorkspacePaths) -> Result<(), BackendError>;   // copy_tree(base.path(), ws.root(), &ReflinkCloner)
    fn disk_usage(&self, base: &BaseEntry, ws: &WorkspacePaths) -> Result<DiskUsage, BackendError>;
    fn swap_base(&self, ws: &WorkspacePaths, from: &BaseEntry, to: &BaseEntry) -> Result<SwapOutcome, BackendError>;  // NeedsCheckout
    fn tear_down(&self, ws: &WorkspacePaths) -> Result<(), BackendError>;
}

/// Trial reflink of the probe file from `base_dir` into `target_dir`.
pub(crate) fn probe_reflink(base_dir: &Path, target_dir: &Path) -> Probe;
```

`materialize` logs `tracing::info!(workspace_id, backend = "reflink", files = counts.files, elapsed_ms, "workspace materialized")`.

### `crates/reef-daemon/src/backend/mod.rs`

Register `ReflinkBackend` under `#[cfg(target_os = "linux")]` in `probe` and `backend_for`, after the overlay kinds and before `Copy`.

### `crates/reef-daemon/src/backend/fs_util.rs`

No change. `reflink` persists the file with the source permissions, which may be read-only (`0o444`); R1.07's `restore_mtime` uses `utimensat` by path, so the mode does not block it.

### CI

In R1.09's `overlayfs` job (which already runs under `sudo`), add a step that creates a 2 GiB sparse file, `mkfs.btrfs` it, loop-mounts it at `/mnt/reef-btrfs`, and runs the reflink conformance test with `REEF_TEST_REFLINK_DIR=/mnt/reef-btrfs`; the test skips with a message when the variable is unset. `btrfs-progs` is installed with `apt-get install -y btrfs-progs` in the same step. Do the same for XFS (`xfsprogs`, `mkfs.xfs -m reflink=1`) at `/mnt/reef-xfs`, running the suite twice. If R1.09 has not landed, this ticket adds the job with only the reflink steps and R1.09 extends it.

### Tests

In `reflink.rs` (`#[cfg(all(test, target_os = "linux"))]`), skipped with `eprintln!("skipped: REEF_TEST_REFLINK_DIR not set")` unless the variable names a directory on a reflink-capable filesystem:

1. `reflink_clone_preserves_mtime_mode_and_shares_blocks`: materialize a tree with a 4 MiB file; assert mtime, mode, size equal; `free_bytes` delta under 1 MiB; append to the clone and assert the source unchanged.
2. `probe_reports_unsupported_on_tmpdir`: `probe_reflink` on `tempfile::tempdir()` (ext4 or tmpfs on CI) reports unavailable with `EOPNOTSUPP` or `EXDEV`.
3. `materialize_fails_rather_than_copies`: with the base on the reflink filesystem and the target on `/tmp`, `materialize` returns `Unavailable` and leaves no partial tree (the daemon removes partial trees, but the walk must fail on the first file, so assert the root contains no regular files).

The `Backend` contract is R1.11's suite, which adds `reflink` to its matrix gated on the same variable.

## Implementation notes

- `reflink_copy` depends on `rustix` 1 with the `fs` feature; it is already in the dependency tree through other crates (`rustix` 1.1.x is present in the registry), so the build cost is small.
- The walk's per-file cost is one `open`, one `open(O_EXCL)`, one `ioctl`, one `rename`, one `utimensat`, one `chmod`: about 100k × 6 syscalls for the large preset. Expect a few seconds; measure and record in the PR and in `docs/benchmarks.md` (R1.12).
- Directory mtimes are not preserved (consistent with R1.07).
- Symlinks: `copy_tree` recreates them; never hand a symlink to `reflink`, which would follow it on Linux and clone the target.

## Acceptance criteria

- [ ] `ReflinkBackend` compiles and is registered on Linux only; macOS builds are unaffected.
- [ ] On a btrfs or XFS loop mount in CI, the three tests above pass and R1.11's suite passes for `reflink`; on the default ext4 runner, the tests and suite skip with a visible message.
- [ ] A clone's files have the base's mtimes, sizes, and modes; a write to a clone leaves the base unchanged.
- [ ] A clone across filesystems fails with `Unavailable`; nothing is copied.
- [ ] `just ci` passes.
- [ ] The PR records `materialize` wall time and free-space delta for the `large` preset on a btrfs loop mount (any Linux machine or the CI job's log).

## Out of scope

- btrfs subvolume snapshots as an O(1) directory clone (follow-up; needs `ioctl(BTRFS_IOC_SNAP_CREATE_V2)` and a subvolume per base).
- XFS or btrfs on macOS, ZFS (no FICLONE until OpenZFS 2.2 block cloning; probe decides), NFS.
- overlay mounts (R1.09), eviction (R1.17).

## Risks

- A filesystem that reports success for `FICLONE` but copies internally (some network filesystems) would pass the probe and give no sharing; the free-space check in R1.12 would show it.
- `reflink-copy`'s temporary-file-then-rename leaves a stray temporary on a crash mid-walk; the daemon's removal of a partial tree covers it.
