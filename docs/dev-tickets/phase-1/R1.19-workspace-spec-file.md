# R1.19 Workspace spec file

Phase 1 · Size S · Depends on: R1.01 · Unblocks: R1.20 (store declarations), R1.13 (snapshot excludes), R1.15 (lease default per repository)

## Context

The design puts dependencies and build state outside the tree: "The workspace spec declares shared stores to mount or link in" and "Build outputs never enter a snapshot" (`docs/design.md`, Workspaces). Lease length is "a product decision" the repository should be able to tune. All three are per-repository facts that belong in the repository, next to the code, so that every workspace created on a commit gets the same stores, excludes, and lease that the commit's authors intended. That file is `reef.toml` at the repository root.

This ticket delivers the parser, the validation rules, and the one place the daemon reads the file from. R1.20 consumes `[[store]]`, R1.13 consumes `[snapshot] exclude`, and R1.15 consumes `[workspace] lease`. Nothing in this ticket mounts, excludes, or leases anything.

### What was verified while writing this ticket

- `toml` 1.1.8 and `serde` 1 are workspace dependencies after R1.04 (`toml` is added there; `serde` with `derive` is already declared). `humantime-serde` 1.1.1 (added by R1.04) deserializes `"30m"` into `std::time::Duration` with `#[serde(with = "humantime_serde")]`.
- jj-lib 0.46.0: `MergedTree::path_value(&self, path: &RepoPath) -> BackendResult<MergedTreeValue>` (`merged_tree.rs:221`) resolves a path in a tree, and `Store::read_file(&self, path: &RepoPath, id: &FileId) -> BackendResult<Pin<Box<dyn AsyncRead + Send>>>` (`store.rs:229`) reads a blob. `RepoPathBuf::from_internal_string("reef.toml")` builds the path. So a file can be read from a commit's tree without a working copy.
- `#[serde(deny_unknown_fields)]` on every spec struct is what makes unknown keys errors, including nested tables.

## Decisions

- **The file is `reef.toml` at the repository root, read from the target commit's tree**, not from the registered root's working copy on disk. The human's checkout at the root may be on another change; the workspace being created is on the target commit, and its stores and excludes must match that commit's lockfiles and layout. The same rule makes the result deterministic for a given commit and keeps `reef store build --rev` (R1.20) consistent with `ws create`. If the tree has no `reef.toml`, the spec is `Spec::default()` (no stores, no excludes, daemon lease default).
- **Parsing lives in `reef_lib::spec`**, so `reef-lib` tests, the daemon, and later the CLI (`reef spec check`, Phase 2) share one parser. `reef-lib` gains `toml` and `humantime-serde` as dependencies.
- **Schema, exactly** (every key optional, no others):

  ```toml
  [workspace]
  lease = "30m"                      # humantime duration; capped at the daemon's lease.max

  [snapshot]
  exclude = ["target/", "node_modules/"]   # gitignore syntax, relative to the workspace root

  [[store]]
  name = "node_modules"              # [a-z0-9][a-z0-9_-]{0,63}
  lockfile = "pnpm-lock.yaml"        # path relative to the root, must exist in the tree
  mount = "node_modules"             # path relative to the root; the store appears here
  build = ["pnpm", "install", "--frozen-lockfile"]   # argv, no shell
  [store.env]                        # optional, added to the build command's environment
  CI = "1"
  ```

  `build` is an argv array, never a shell string, so a spec cannot smuggle shell syntax and the same spec runs identically on both platforms. A repository that needs a shell writes `["sh", "-c", "..."]` explicitly.
- **Validation is strict and happens at parse time**: unknown keys anywhere are errors; `name` matches the pattern above and is unique among stores; `mount` and `lockfile` are relative, normalized (no `.`, `..`, empty components, leading `/`, or trailing `/`), and `mount` is not the root and not a prefix of or equal to another store's `mount` or `lockfile`; `exclude` entries are non-empty and contain no NUL; `lease` is at least 1 minute (shorter leases flap on the 10 s tick). Existence of `lockfile` in the tree is checked by the daemon when the spec is loaded for a commit, not by the parser, because the parser does not see the tree.
- **Mount paths are always excluded from snapshots and ignored by the watcher.** The spec loader adds every `mount` to the effective exclude list it returns, so R1.13 and R1.20 do not each have to remember to.
- **One error type**, `SpecError`, `Classify` → `InvalidArgument` for syntax and validation, `Io`/`Internal` for read failures through jj-lib, `NotFound` for a declared lockfile missing from the tree.
- **ADR 0021** records the file name, the read-from-tree rule, argv-not-shell, and the alternatives.

### `crates/reef-lib/src/spec.rs`

```rust
//! The repository's workspace spec, `reef.toml` at the root (ADR 0021).

pub const SPEC_FILE: &str = "reef.toml";

#[derive(Clone, Debug, Default, PartialEq, Eq, serde::Deserialize)]
#[serde(deny_unknown_fields, default)]
pub struct Spec {
    pub workspace: WorkspaceSpec,
    pub snapshot: SnapshotSpec,
    #[serde(rename = "store")]
    pub stores: Vec<StoreSpec>,
}

#[derive(Clone, Debug, Default, PartialEq, Eq, serde::Deserialize)]
#[serde(deny_unknown_fields, default)]
pub struct WorkspaceSpec {
    #[serde(with = "humantime_serde")]
    pub lease: Option<Duration>,
}

#[derive(Clone, Debug, Default, PartialEq, Eq, serde::Deserialize)]
#[serde(deny_unknown_fields, default)]
pub struct SnapshotSpec {
    pub exclude: Vec<String>,
}

#[derive(Clone, Debug, PartialEq, Eq, serde::Deserialize)]
#[serde(deny_unknown_fields)]
pub struct StoreSpec {
    pub name: String,
    pub lockfile: String,
    pub mount: String,
    pub build: Vec<String>,
    #[serde(default)]
    pub env: BTreeMap<String, String>,
}

#[derive(Debug, thiserror::Error)]
#[non_exhaustive]
pub enum SpecError {
    #[error("invalid {SPEC_FILE}")]
    Parse(#[source] toml::de::Error),
    #[error("store {name:?}: invalid name; use [a-z0-9][a-z0-9_-]{{0,63}}")]
    StoreName { name: String },
    #[error("store {name:?} is declared twice")]
    DuplicateStore { name: String },
    #[error("store {name:?}: {field} must be a normalized relative path, got {value:?}")]
    StorePath { name: String, field: &'static str, value: String },
    #[error("store {name:?}: mount {mount:?} overlaps {other:?}")]
    MountOverlap { name: String, mount: String, other: String },
    #[error("snapshot.exclude entry {index} is empty or contains NUL")]
    Exclude { index: usize },
    #[error("workspace.lease {0:?} is shorter than one minute")]
    LeaseTooShort(Duration),
    #[error("store {name:?}: lockfile {lockfile:?} is not in the tree")]
    LockfileMissing { name: String, lockfile: String },
    #[error("reading {SPEC_FILE} from the tree")]
    Read(#[source] BackendError),
}

impl Spec {
    /// Parses and validates the text of a `reef.toml`.
    pub fn parse(text: &str) -> Result<Spec, SpecError>;
    /// Every path a snapshot must exclude: `snapshot.exclude` plus each store's `mount`
    /// as an anchored directory pattern (`/node_modules/`).
    pub fn effective_excludes(&self) -> Vec<String>;
    pub fn store(&self, name: &str) -> Option<&StoreSpec>;
}

impl StoreSpec {
    pub fn lockfile_path(&self) -> &RepoPath;   // validated, so infallible after parse
    pub fn mount_path(&self) -> &RepoPath;
}
```

Keep `RepoPath` out of the public struct fields (they stay `String` so the type derives `Deserialize` plainly); the two accessors convert with `RepoPath::from_internal_string`, which cannot fail after validation (comment the invariant).

### `crates/reef-lib/src/jj/spec.rs`

```rust
impl Repo {
    /// Reads `reef.toml` from `commit`'s tree. `Ok(None)` when the tree has none.
    /// Checks that every declared lockfile exists in the tree.
    pub async fn spec_at(&self, commit: &Commit) -> Result<Option<Spec>, SpecError>;
    /// The raw bytes of `path` in `commit`'s tree, for lockfile hashing (R1.20).
    pub async fn read_file_at(&self, commit: &Commit, path: &RepoPath) -> Result<Option<Vec<u8>>, ReadError>;
}
```

`spec_at`: `commit.tree().path_value(SPEC_FILE)` → `MergedTreeValue`; if absent return `None`; if it is not a resolved regular file (a conflict, symlink, or tree) return `SpecError::Parse`-style error naming the kind; else `read_file` the blob, decode UTF-8, `Spec::parse`, then `LockfileMissing` for any store whose `lockfile_path()` is absent. Add the `Classify` impl: `Parse`, `StoreName`, `DuplicateStore`, `StorePath`, `MountOverlap`, `Exclude`, `LeaseTooShort` → `InvalidArgument`; `LockfileMissing` → `NotFound`; `Read` → `classify_by_source`.

### `crates/reef-daemon/src/spec.rs`

```rust
/// What the daemon derives from a spec for one commit.
pub(crate) struct ResolvedSpec {
    pub spec: Spec,
    pub lease: Option<Duration>,          // capped at config.lease.max by the caller
    pub excludes: Vec<String>,            // Spec::effective_excludes()
}

pub(crate) fn resolve(spec: Option<Spec>) -> ResolvedSpec;
```

R1.05's create flow calls `Repo::spec_at(&target_commit)` on the repository thread and stores `ResolvedSpec` on the in-memory workspace handle; R1.13 reads `excludes`, R1.15 reads `lease`, R1.20 reads `spec.stores`. The spec is read once per create and move (R1.06); a `reef.toml` edited inside a workspace takes effect for workspaces created later, never for the running one. Document this in the quickstart (R1.24).

### `crates/reef-lib/tests/spec.rs`

1. `empty_text_is_default`: `Spec::parse("")` equals `Spec::default()`.
2. `full_example_parses`: the schema example above; assert each field, `env` map, and `effective_excludes() == ["target/", "node_modules/", "/node_modules/"]`.
3. `unknown_key_is_rejected`: top-level `[foo]`, `workspace.foo`, and `store.foo` each give `Parse`; the message names the key.
4. `build_must_be_an_array`: `build = "pnpm install"` is `Parse`.
5. `store_name_rules`: `Node_Modules`, `-x`, 65 characters, empty → `StoreName`; duplicate → `DuplicateStore`.
6. `paths_are_normalized_relative`: `mount = "/node_modules"`, `"./node_modules"`, `"a/../b"`, `"node_modules/"`, `""` → `StorePath`; `lockfile` likewise.
7. `mount_overlap`: two stores with `mount = "vendor"` and `"vendor/x"` → `MountOverlap`; a mount equal to another store's lockfile → `MountOverlap`.
8. `lease_bounds`: `"30s"` → `LeaseTooShort`; `"1m"` ok; `"25h"` ok (capping is the daemon's).
9. `exclude_entries`: `[""]` → `Exclude`; `["a\0b"]` → `Exclude`.
10. `spec_at_reads_from_tree` (`#[tokio::test]`, fixture via `Repo::init_internal_git`): write `reef.toml` with one store and `pnpm-lock.yaml`, snapshot, `spec_at(&wc_commit)` returns it; delete the lockfile, snapshot, `spec_at` → `LockfileMissing`; delete `reef.toml`, snapshot, → `Ok(None)`.
11. `spec_at_ignores_disk`: after test 10's first snapshot, overwrite `reef.toml` on disk with garbage without snapshotting; `spec_at` on the snapshotted commit still parses.

### `docs/adr/0021-workspace-spec-file.md`

Status `accepted`. Context: dependencies outside the tree, excludes, lease tuning, per-commit determinism. Decision: `reef.toml`, read from the commit's tree, strict schema, argv builds, mounts auto-excluded. Consequences: a running workspace does not pick up spec edits; repositories without the file work with defaults; adding a key is a schema change reviewed like an API change. Alternatives: read from disk at the root (rejected: wrong change), `.reef/config.toml` directory (rejected: one file is enough until Phase 4 needs sparse profiles; name the directory as the migration path), shell strings for `build` (rejected: platform drift, injection surface), `package.json`-style per-ecosystem detection (rejected: magic; Phase 2 may add presets on top).

Add the index row in `docs/adr/README.md`.

## Implementation notes

- `humantime_serde` with `Option<Duration>`: use `#[serde(with = "humantime_serde", default)]`; the crate's `with` module handles `Option`.
- Path validation: split on `/`, reject empty, `.`, `..`, and backslash components (a backslash is a valid filename byte on Unix, but a spec with one is almost certainly a Windows path; reject and say why in the error). Compare overlaps on component vectors, not string prefixes, so `vendor` does not overlap `vendors`.
- `MergedTreeValue` for a resolved file is `Merge::resolved(Some(TreeValue::File { id, .. }))`; use `into_resolved()` and match `TreeValue::File`. Symlinks and submodules at `reef.toml` are errors with a message, not panics.
- Blob read: collect the `AsyncRead` with `tokio::io::AsyncReadExt::read_to_end` (tokio is a dependency of `reef-lib` only in dev; use `futures::AsyncReadExt` if jj-lib's `AsyncRead` is the `futures` trait; check which `AsyncRead` `store.rs` imports and use the matching extension trait).
- Error `Display` strings follow ADR 0009: lowercase, no trailing period, identifiers in fields.

## Out of scope

- Building, sealing, mounting, or verifying stores (R1.20).
- Applying excludes to the ignore chain (R1.13) or the lease default (R1.15).
- A `reef spec check` command (Phase 2, with the CLI as a thin client).
- Sparse profiles and prefetch hints (Phase 4).
- Reading the spec for the user's own `default` workspace; Reef does not manage it in Phase 1.

## Risks

- Reading the spec from the tree means a repository whose `reef.toml` is only on disk (never snapshotted) gets defaults. The quickstart tells users to snapshot or commit it; `ws create` logs at `info` when a root has `reef.toml` on disk but the target tree does not.
- `toml` 1.x changed its error type surface from 0.8; pin the workspace version and match on `toml::de::Error` only through `Display`.
