# R1.02 Materialization backend trait and base cache

Phase 1 · Size M · Depends on: R1.01 · Unblocks: R1.05 (create flow), R1.07, R1.08, R1.09 (implement the trait), R1.17 (evicts base cache entries)

## Context

Design: "Copy-on-write materialization. Creation shares every unchanged byte with the store" and the per-platform table in `docs/design.md`, "Workspaces". Every backend starts from the same thing: a directory holding the target tree, materialized once per machine per tree, that overlayfs uses as its lower layer and the clone backends clone. That directory is the base cache. The trait is the seam between "the daemon wants a workspace at this path on this tree" and "this platform does it with clonefile / FICLONE / a mount / a copy".

Departure from `dev-phases.md`, recorded in the README: the backend does not capture the writable layer as a tree. jj-lib's working copy scans the merged directory and builds the tree (R1.13). Backends materialize, measure, swap, and tear down. The base cache moves here from R1.08 because every backend needs it, and so this ticket is M rather than S.

### What was verified while writing this ticket

- `LocalWorkingCopy::init(store, working_copy_path, state_path, op_id, name, &settings)` leaves the empty tree checked out; `locked_wc.check_out(&commit) -> CheckoutStats` (on `LockedWorkingCopy`, async) writes every file of `commit`'s tree relative to the empty tree and updates the file states with each file's real mtime and size; `locked_ws.finish(op_id)` saves `tree_state` and `checkout` under `state_path` with `NamedTempFile` + rename. `CheckoutStats { updated_files, added_files, removed_files, skipped_files }`.
- `TreeState::save` writes the protobuf `tree_state` with `tree_ids`, `conflict_labels`, `file_states` (path, type, mtime, size), `sparse_patterns`, and `watchman_clock`. No absolute path is stored, so the file is valid for any directory that holds byte-identical files with the same mtimes and sizes. `TreeState::reset` sets `mtime 0, size 0` placeholders, which forces a rehash of every file on the next snapshot.
- `MergedTree { store, tree_ids: Merge<TreeId>, labels }`; `MergedTree::tree_ids() -> &Merge<TreeId>`; `Commit::tree() -> MergedTree`. A resolved tree has one id; a conflicted tree has `2n+1`.
- `walkdir` 2.5.0 (Unlicense/MIT); `std::os::unix::fs::MetadataExt::blocks()` is in 512-byte units on macOS and Linux.
- Filesystem type: macOS `libc::statfs` fills `f_fstypename` (`"apfs"`); Linux `nix::sys::statfs::statfs(path).filesystem_type()` compares with `nix::sys::statfs::{BTRFS_SUPER_MAGIC, XFS_SUPER_MAGIC, OVERLAYFS_SUPER_MAGIC, TMPFS_MAGIC, EXT4_SUPER_MAGIC}` (constants present in nix 0.31's `statfs` module; confirm `XFS_SUPER_MAGIC` is exported, else compare the raw `0x58465342`).

## Decisions

- **Trait and types exactly as the README fixes them**, in `reef_daemon::backend`. `materialize` receives a `BaseEntry` and `WorkspacePaths` and must leave `ws.root` holding the base's files with mtimes and sizes preserved. `tear_down` must remove `root`, `upper`, and `work` and never follow symlinks out of them; on a root that does not exist it returns `RootMissing` (`NotFound`), which R1.11 checks. `swap_base` returns `SwapOutcome::TreeReplaced` or `NeedsCheckout`.
- **`probe(dir)` is a free function returning `Vec<Probe>`**, one per `BackendKind`, each `Available` or `Unavailable(reason: String)`. Each backend ticket adds its probe body; this ticket wires the registry and ships `Copy` as always available. Selection order for `auto` is overlayfs, fuse-overlayfs, apfs, reflink, copy.
- **A `BackendKind` is stored as its lowercase name** in `workspaces.backend` (`copy`, `apfs`, `reflink`, `overlayfs`, `fuse-overlayfs`). `BackendKind::from_str` is the inverse.
- **Base cache key is the tree id string**: the hex of the single tree id for a resolved tree, or the hex ids joined with `+` in `Merge` order for a conflicted tree. Materializing a conflicted tree writes jj's conflict markers, which is what jj does for a working copy; R1.11 has one such case.
- **Materialization goes through jj-lib**, never through a hand-written tree walker: a throwaway `LocalWorkingCopy` whose working copy path is `bases/<tree-id>.tmp/` and whose state path is `bases/<tree-id>.tmp.state/`, `check_out` from the empty tree, `finish`. Then rename `.tmp.state` to `<tree-id>.state` and `.tmp` to `<tree-id>`, in that order, and insert the `base_cache` row last. A directory without a row is incomplete and removed at daemon start.
- **The base's `tree_state` is the seed for every workspace on that tree.** Backends preserve mtime and size; the conformance suite (R1.11) checks it. The `checkout` file is not copied (it names the materialization's op id and name; the workspace writes its own on `init`).
- **Base entries are immutable by convention.** The daemon never writes under `bases/<tree-id>/` after the rename. Permissions are left as checked out (jj writes `0644`/`0755`), because clone and copy backends need to read them and overlayfs needs them readable; making them read-only would break the `Copy` backend's mtime restoration order. R1.11 asserts no write happens.
- **Disk usage is an estimate** computed as the README says; `DiskUsage::files_changed` counts files whose mtime or size differs from the base's `tree_state`, read through a small reader of that proto added to `reef_lib::jj` (`tree_state_entries(state_dir) -> Vec<(path, mtime_ms, size)>`), or, for overlay backends, the upper directory's entries.
- **The repository's jj settings** (identity, `max_new_file_size`) are the ones the daemon built (R1.04); the base cache takes them from the `RepoHead`.

### `crates/reef-daemon/src/backend/mod.rs`

```rust
pub mod base_cache;
pub mod copy;        // R1.07 fills it; this ticket leaves a compiling stub that returns Unavailable
pub mod probe;

#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash, Serialize, Deserialize)]
#[serde(rename_all = "kebab-case")]
pub enum BackendKind { Copy, ApfsClone, Reflink, Overlayfs, FuseOverlayfs }
impl BackendKind { pub const AUTO_ORDER: [BackendKind; 5] = [Overlayfs, FuseOverlayfs, ApfsClone, Reflink, Copy]; pub fn as_str(self) -> &'static str; }
impl FromStr for BackendKind { ... }   // "apfs" for ApfsClone

#[derive(Clone, Debug)]
pub struct WorkspacePaths { pub id: WorkspaceId, pub root: PathBuf, pub upper: PathBuf, pub work: PathBuf, pub state_dir: PathBuf }
impl WorkspacePaths { pub fn under(repo_dir: &Path, id: WorkspaceId) -> Self; }   // repo_dir = <state>/repos/<repo-id>

#[derive(Clone, Debug, Default, PartialEq, Eq)]
pub struct DiskUsage { pub allocated_bytes: u64, pub files_changed: u64 }

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum SwapOutcome { TreeReplaced, NeedsCheckout }

#[derive(Debug, thiserror::Error)]
#[non_exhaustive]
pub enum BackendError {
    #[error("backend {kind} is not available here: {reason}")] Unavailable { kind: BackendKind, reason: String },
    #[error("workspace root {0} already exists")] RootExists(PathBuf),
    #[error("workspace root {0} does not exist")] RootMissing(PathBuf),   // tear_down on a root that is already gone
    #[error("{op} {path}")] Io { op: &'static str, path: PathBuf, #[source] source: io::Error },
    #[error("mount {path}")] Mount { path: PathBuf, #[source] source: io::Error },    // used by R1.09
    #[error("{tool} exited with {status}: {stderr}")] Tool { tool: String, status: String, stderr: String },  // fuse-overlayfs
}
impl Classify for BackendError { Unavailable→Unavailable, RootExists→AlreadyExists, RootMissing→NotFound, Io/Mount→PermissionDenied or Io by source, Tool→Internal }

pub trait Backend: Send + Sync {
    fn kind(&self) -> BackendKind;
    fn materialize(&self, base: &BaseEntry, ws: &WorkspacePaths) -> Result<(), BackendError>;
    fn disk_usage(&self, base: &BaseEntry, ws: &WorkspacePaths) -> Result<DiskUsage, BackendError>;
    fn swap_base(&self, ws: &WorkspacePaths, from: &BaseEntry, to: &BaseEntry) -> Result<SwapOutcome, BackendError>;
    fn tear_down(&self, ws: &WorkspacePaths) -> Result<(), BackendError>;
}

/// Constructs the backend for `kind` without probing. Each backend ticket adds its arm.
pub fn backend_for(kind: BackendKind) -> Box<dyn Backend>;
/// Picks the backend for `kind` ("auto" resolves by probe order) for a workspace root under `dir`,
/// checks the probe, and constructs it through `backend_for`.
pub fn select(kind: BackendChoice, dir: &Path) -> Result<Box<dyn Backend>, BackendError>;
pub enum BackendChoice { Auto, Named(BackendKind) }
```

`materialize`, `swap_base`, and `tear_down` are synchronous and blocking; the daemon calls them from `spawn_blocking` (R1.03 threading).

### `crates/reef-daemon/src/backend/base_cache.rs`

```rust
#[derive(Clone, Debug)]
pub struct BaseEntry { pub repo_id: RepoId, pub tree_id: String, pub path: PathBuf, pub state_dir: PathBuf, pub bytes: u64, pub files: u64 }
impl BaseEntry { pub fn tree_state_file(&self) -> PathBuf { self.state_dir.join("tree_state") } }

pub struct BaseCache { db: Arc<Db>, dir: PathBuf /* <state>/repos/<repo-id>/bases */ }

#[derive(Debug, thiserror::Error)] #[non_exhaustive]
pub enum BaseCacheError { Db(#[from] DbError), Io { .. }, Materialize(#[from] reef_lib::jj::materialize::MaterializeError), Incomplete(PathBuf) }

impl BaseCache {
    pub fn new(db: Arc<Db>, repo_dir: &Path, repo_id: RepoId) -> Self;
    /// Returns the entry for `tree_id`, materializing it through `materialize` if absent. Bumps last_used_at.
    pub fn ensure(&self, tree_id: &str, materialize: impl FnOnce(&Path, &Path) -> Result<MaterializeStats, MaterializeError>) -> Result<BaseEntry, BaseCacheError>;
    pub fn get(&self, tree_id: &str) -> Result<Option<BaseEntry>, BaseCacheError>;
    pub fn entries(&self) -> Result<Vec<BaseEntry>, BaseCacheError>;
    pub fn remove(&self, tree_id: &str) -> Result<u64 /* bytes freed */, BaseCacheError>;   // R1.17 calls it
    /// Deletes `*.tmp`, `*.tmp.state`, and row-less directories. Called at daemon start.
    pub fn sweep_incomplete(&self) -> Result<Vec<PathBuf>, BaseCacheError>;
}
```

`ensure` takes a closure because the jj part must run where the repository's `Repo` lives (the repository thread or a workspace thread, R1.03); the closure receives `(tmp_tree_dir, tmp_state_dir)`. The cache serializes concurrent `ensure` calls for one `tree_id` with a per-key `Mutex` in a `HashMap` so two creates on the same change materialize once.

### `docs/adr/0015-materialization-backends-and-base-cache.md`

Status `accepted`. Context: per-platform CoW primitives, one daemon, many workspaces per tree. Decision: the trait, the base cache keyed by tree id and materialized through jj-lib, `tree_state` seeding, the selection order, no capture in the backend. Consequences: a tree is written once per machine; the first snapshot of a workspace is a no-op scan; backends must preserve mtimes; disk usage is an estimate; base cache growth is bounded by R1.17. Alternatives: backends build trees themselves (reimplements jj's snapshot); base cache keyed by commit (duplicates trees across rewrites); materialize by walking `MergedTree` by hand (loses jj's conflict materialization and EOL handling).

## Implementation notes

- Shared filesystem helpers live in `reef_daemon::backend::fs_util`, created here with `allocated_bytes(path)`, `free_bytes(path)` (`statvfs`), `same_volume(a, b)` (`st_dev`), and `changed_files_vs_base(base, ws)` (below); R1.07 extends the module with the copy walk, mtime restore, trash rename, and background deletion. Backend tickets must not grow private copies of these.

- `check_out` from the empty tree on the `large` preset is the O(repository) number; print it to stderr in test 1 as the bench fixture does, and put the figure in the PR.
- Do the rename of `.tmp.state` before `.tmp`: a `<tree-id>` directory with no `.state` is treated as incomplete by `sweep_incomplete`; the reverse would not be detected.
- `WorkspacePaths::under` computes `root = repo_dir/ws/<id>`, `upper = repo_dir/ws/<id>.upper`, `work = repo_dir/ws/<id>.work`, `state_dir = repo_dir/wc/<id>`.
- The `BaseCache` per-key mutex map is a `Mutex<HashMap<String, Arc<Mutex<()>>>>`; do not hold the outer lock while materializing.
- `disk_usage` for clone and copy backends is the shared helper `fs_util::changed_files_vs_base(base, ws)` that backends call; overlay backends override.

## Out of scope

- Any real CoW primitive (R1.07 to R1.10) and the conformance suite (R1.11).
- Eviction (R1.17); incremental base materialization from a nearby base (R1.08).
- Seeding a workspace's state from the base (R1.05 does it using `BaseEntry::tree_state_file`).

## Risks

- `jj_lib::protos` may be private; the fallback decoder above is the mitigation.
- Checking out a 100k-file tree through `LocalWorkingCopy` may take tens of seconds; it is once per tree per machine and the first `ws create` on a new change pays it. R1.08's incremental path is the fix if it matters.
- `nix` statfs magic constants vary by target; gate with `cfg(target_os)` and fall back to "unknown" rather than failing the probe.
