# R1.05 Workspace service: create, list, release

Phase 1 · Size M · Depends on: R1.02, R1.03 · Unblocks: R1.06 (move), R1.12 (the `create_api` benchmark group), R1.13 (watcher hooks into the manager), R1.15 (heartbeat), R1.20 (store mounting in `Create`), R1.21 (`ws run` calls `Create`, `Release`, `Snapshot`), R1.22 (CLI), R2.01 (the schema it replaces)

## Context

This is the first end-to-end path of the phase: an agent asks for a workspace on a change and gets a directory. It joins R1.01's jj workspace creation, R1.02's base cache and backend, and R1.03's daemon into the `Repositories` and `Workspaces` gRPC services, defines the error mapping ADR 0009 prepared `ErrorKind` for, and records the API in ADR 0017. Leases are issued here with the configured default length; the heartbeat and expiry loop are R1.15, so until then a lease simply records when it would expire.

### What was verified while writing this ticket

- `tonic::Status::with_details(code, message, details: Bytes)`; `prost::Message::encode_to_vec` gives the bytes for a generated `ErrorDetail`; `Status::details()` returns them on the client.
- jj-lib: `MutableRepo::edit` and `check_out` (R1.01); `View::workspaces_for_wc_commit_id(&CommitId) -> Vec<WorkspaceNameBuf>` lists other workspaces on the same commit; `jj_lib::git::import_refs(mut_repo, &GitImportOptions)` (async) with `GitImportOptions::from_settings(&UserSettings)` (git.rs:148; confirm the impl block is `GitImportOptions`) imports git refs in a colocated repo; it needs a transaction and returns `GitImportStats`. A colocated repository is one whose jj store is git at `<root>/.git` (`Repo` can tell by `root.join(".git").exists()` and the store type; jj-lib's `GitBackend::git_repo_path` is the exact check if exposed).
- `WorkingCopy::tree()` and `LocalWorkingCopy::load` (R1.01) reopen a workspace after a daemon restart.

## Decisions

- **Services and request shape as the README fixes them.** `repo` on every repository-scoped request accepts a repo id, a unique id prefix, or an absolute path inside a registered root (`Db::repository_containing`).
- **Create flow**, in order, with the thread each step runs on:
  1. (tokio) Validate the request, resolve the repository, pick the backend (`backend::select` with the request's `backend` or `workspace.backend`), allocate `WorkspaceId`, compute `WorkspacePaths` (request `path` overrides `root`; must not exist).
  2. (repo thread) In a colocated repo, `import_refs` in its own transaction if it changes anything. Resolve `change`/`new_on` through `Repo::resolve_revision` (default: `main` bookmark, else the `default` workspace's wc commit). For `change`, if `workspaces_for_wc_commit_id` lists another Reef workspace, the response carries `shared_change = true` (allowed; R1.13's divergence rule applies).
  3. (repo thread, then a blocking thread) `BaseCache::ensure(tree_key)` with the materialize closure calling `Repo::materialize_tree` on the repository thread (`call_async`). The repository thread is blocked for the duration of a cold materialization; `Status` and other repositories are not.
  4. (blocking) `backend.materialize(&base, &paths)`.
  5. (repo thread) `Repo::create_workspace(name, root, state_dir, StartPoint, "reef: create workspace <id>")`. The returned `Repo` for the workspace is moved into a `WorkspaceHandle` held by the manager.
  6. (blocking) Seed: copy `base.tree_state_file()` over `state_dir/tree_state`. On any error, `reset_to(commit)` instead and log at `warn`.
  7. (tokio) Insert the `workspaces` row (`state = active`) and issue the lease in one transaction; return.
  On failure after step 4, tear down the backend materialization; after step 5, also `forget_workspace`. Partial state never leaves a row behind.
- **Release flow**: `state = releasing`; final snapshot (R1.13's path; until R1.13 lands, `Repo::snapshot` on the workspace thread, kind `final`); `forget_workspace` on the repo thread; `backend.tear_down`; remove `state_dir`; lease `end_reason = released`; `reclaims` row with `reason = released`; `state = released`. A failed final snapshot aborts release with `attention = final-snapshot-failed` and the directory intact unless `force = true`.
- **List and Inspect** read SQLite only, except `Inspect` with `snapshot_first = true`, which runs a snapshot first (default in the CLI, off in the API). `Inspect` adds `disk_usage` from the backend and `other_workspaces_on_change`.
- **Snapshot RPC**: explicit snapshot of one workspace, returns the `op_id` and whether anything changed. R1.13 replaces its internals; this ticket implements it with `Repo::snapshot` on the workspace thread followed by `note_committed` on the repository thread.
- **Errors**: the README mapping, with `ErrorDetail { kind, chain }` in status details. The `Client` decodes details back into `ClientError::Rpc { kind, message, chain }` and `Classify` returns `kind`.
- **The manager** (`reef_daemon::workspace::Manager`) owns `HashMap<WorkspaceId, Arc<WorkspaceEntry>>` with `entry.handle: Arc<std::sync::Mutex<Option<reef_lib::jj::Repo>>>` (the workspace's jj handle), `entry.backend: Box<dyn Backend>`, `entry.paths`. On daemon start it loads every `active` workspace row, reopens the jj handle with `Repo::open_workspace`, and re-selects the backend by the stored name (overlay backends remount in R1.09).
- **Proto package `reef.daemon.v0`**, one file per service plus `types.proto` and `error.proto`.

### `docs/adr/0017-daemon-api-v0-and-error-mapping.md`

Status `accepted`. Context: ADR 0004 chose gRPC; ADR 0009 built `ErrorKind` for this. Decision: package `v0` as explicitly pre-stable, the services and the request shape, `ErrorDetail` in status details, the `ErrorKind` to `Code` table, `op_id` on every mutating response, ids as hex strings. Consequences: R2.01 can rename freely before `v1` (no compatibility promise); clients get a machine-readable kind without parsing messages; every new error type must map. Alternatives: `google.rpc.Status`/`ErrorInfo` (richer, needs `tonic-types`; revisit in R2.01); string-matching messages (rejected).

## Implementation notes

- Keep the generated types out of `Manager`'s signatures; `service/` converts between `WorkspaceRecord` and `proto::Workspace` in one `From` impl per type.
- `materialize_ms` and `base_was_cached` in `CreateResponse` are what R1.12 reads; keep them accurate.
- A `Create` while another `Create` on the same tree is materializing waits on the base cache's per-key mutex, not on the repository thread.
- Restart (`load_active`): when `meta.rematerialize_pending` is set (written by R1.18's restore), every `active` row whose path or state dir is missing is rematerialized through R1.18's `rematerialize(ws)` and the flag is cleared after the pass. Otherwise a row whose path no longer exists is marked `reclaimed` with a `reclaims` row `detail = "directory missing at start"`, because nothing can be snapshotted; log at `error`. Until R1.18 lands only the second rule exists.
- Owner default when the request's `owner` is empty: the client fills it (R1.21, R1.22); the service rejects empty owners with `INVALID_ARGUMENT`.

## Out of scope

- Heartbeat and expiry (R1.15); `Move` (R1.06); the watcher (R1.13); `Gc` (R1.17).
- CLI subcommands (R1.22) beyond what `Client` exposes.
- Revsets, remote bookmarks, or creating bookmarks.
- Authentication; socket permissions are the access control (ADR 0004).

## Risks

- `import_refs` on a large colocated repo can be slow and writes an operation each time refs moved; it runs only when a bookmark name is being resolved, and the PR records its cost on the fixture.
- Copying `tree_state` relies on backends preserving mtimes; a backend that does not (caught by R1.11) makes every first snapshot a full rehash, not a correctness problem.
- If `Repo::create_workspace`'s op lands but `LocalWorkingCopy::init` fails, the cleanup path must `forget_workspace`; the failure test above exercises only the backend step, so add a second injected failure for this step if a cheap hook exists.
