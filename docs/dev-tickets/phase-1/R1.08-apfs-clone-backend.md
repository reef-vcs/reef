# R1.08 APFS clone backend (macOS)

Phase 1 · Size M · Depends on: R1.02 · Unblocks: R1.10 (shares the per-file clone walk and the incremental base cache), R1.20 (stores are linked into workspaces this backend creates)

## Context

Design, "Workspaces": "macOS: APFS file clones over a materialized snapshot. Metadata per file, no data copied. Disk per workspace: modified files only." And under "Hard problems": "macOS has no overlayfs. APFS clones give copy-on-write at the file level but require materializing a snapshot once per machine." The base cache (R1.02) is that once-per-machine materialization; this backend clones it into each workspace.

The phase exit criterion is twenty workspaces on the 100k-file synthetic repo, each created in under one second on APFS. The measurements below show that only a single directory-level `clonefile(2)` call meets it; a per-file clone walk is an order of magnitude too slow and exists here only as the fallback.

### What was verified while writing this ticket

Measured on the authoring machine (Apple M2 Max, 12 cores, macOS 27.0.1, APFS, `target/synth/large`: 102,005 files in 8,336 directories, 592 MB on disk), source and destination on the same volume:

| Method | Wall time | Free-space delta | mtime preserved |
| --- | ---: | ---: | --- |
| `clonefile(2)` on the directory, one call (three runs) | 1.00 s, 1.05 s, 1.20 s | 29.5 to 30.5 MiB | yes |
| `clonefile(2)` per file over an `os.walk`, Python | 13.3 s | (same) | yes |
| `cp -cR` (`copyfile(3)` with `COPYFILE_CLONE` per item) | 15.2 s | (same) | yes |
| `cp -R` (plain copy, R1.07's baseline) | 25.9 s | 632 MiB | no |
| `rm -rf` of a clone | 4.3 to 4.4 s | | |

- `man 2 clonefile` (macOS 27): "If src names a directory, the directory hierarchy is cloned as if each item was cloned individually. However, the use of clonefile(2) to clone directory hierarchies is strongly discouraged. Use copyfile(3) instead." The call is atomic ("all new objects being created successfully or no new objects"), `dst` must not exist, errors are `ENOTSUP` (filesystem without clone support), `EXDEV` (different filesystems), `EEXIST`, `EACCES`. Flags: `CLONE_NOFOLLOW` (clone a symlink itself; "applicable only if the source is not a directory"), `CLONE_NOOWNERCOPY`, `CLONE_ACL`. setuid and setgid bits are cleared on regular files. The man page's discouragement is noted in ADR 0015's consequences; the 13-fold difference is why the directory call is used anyway, with the per-item path as the fallback the man page recommends.
- `man 3 copyfile`: `COPYFILE_CLONE_FORCE` fails rather than falling back, but "there is no support for cloning directories: if a directory is provided as the source, an error will be returned". `COPYFILE_CLONE | COPYFILE_RECURSIVE` clones per item with a silent copy fallback, which is what `cp -c` does and what the table shows at 15 s. Neither is used.
- `libc` 0.2.190 (`src/unix/bsd/apple/mod.rs`) binds `clonefile(src, dst, flags: u32)`, `clonefileat`, `fclonefileat`, `copyfile`, and the `COPYFILE_*` constants. `CLONE_NOFOLLOW = 0x0001`, `CLONE_NOOWNERCOPY = 0x0002` are in `<sys/clonefile.h>`; check whether `libc` exports them and define them locally if not.
- `reflink-copy` 0.1.30 on macOS calls `clonefile(src, dst, CLONE_NOOWNERCOPY)` (`src/sys/unix/macos.rs`) and documents that a directory source clones the hierarchy. It does not pass `CLONE_NOFOLLOW`, so a symlink source is followed; the per-file walk handles symlinks itself and only hands regular files to it.
- `clonefile` requires both paths on one APFS volume. The state directory (`~/Library/Application Support/reef`) and `/private/tmp` are both on the Data volume on a default install, which is why the measurements above worked from the scratch directory. A workspace `--path` on another volume gets `EXDEV`.
- Volume support can be queried with `getattrlist(2)` and `VOL_CAP_INT_CLONE` (man page, "Compatibility"); a trial clone of a probe file is simpler and is what `probe` does.
- Rust's `std::fs::copy` on macOS already tries `fclonefileat` and silently falls back to `fcopyfile` (verified in `library/std/src/sys/fs/unix.rs`), so it cannot serve as the clone primitive: a failed clone must be an error here.

## Decisions

- **Directory `clonefile` first, per-file walk second, never a plain copy.** `materialize` calls `clonefile(base.path(), ws.root(), CLONE_NOOWNERCOPY)` once. On `ENOTSUP` or `EXDEV` it returns `BackendError::Unavailable` (the probe should have caught this; a late failure means the filesystem changed under us). On any other error from the directory call (the man page's discouragement suggests edge cases with very large hierarchies or special files) it logs at `warn` with the errno and falls back to `fs_util::copy_tree` with an `ApfsCloner` whose `copy_file` is `reflink_copy::reflink` (the per-file path, 13 s on the large preset). A failure in the per-file path is an error, not a copy.
- **Probe**: `BackendKind::ApfsClone` is available for a directory if the platform is macOS, the directory and the repository's base cache directory are on the same volume (`fs_util::same_volume`), and a trial `clonefile` of a one-byte probe file in the base cache directory into the target directory succeeds. The probe records the reason otherwise (`different volume`, `ENOTSUP`).
- **Mtimes come for free.** `clonefile` copies attributes including modification time (the table confirms it; R1.11 tests it), so the seeded `tree_state` (R1.02) is valid without any fix-up. The per-file fallback walks with `copy_tree`, which restores mtimes.
- **Symlinks** are cloned as symlinks by the directory call (verified: the synthetic tree's 10 symlinks survive with their targets). The per-file path recreates them through `copy_tree`.
- **Incremental base materialization** (`BaseCache::ensure_from`, this ticket's second half). When a base for tree T is requested and the cache holds another base B for the same repository, the backend clones B's directory with one `clonefile` into `bases/<T>.tmp/`, seeds a temporary `LocalWorkingCopy` state from B's `.state/`, and runs `locked_wc.check_out(&commit_T)` so jj applies only the diff between B and T, then `finish`, then renames the state to `bases/<T>.state/` and `.tmp` to `bases/<T>/`, in R1.02's order. The candidate B is the entry with the most recent `last_used_at`. A full check-out (R1.02's path) is used when the cache is empty or the clone of B fails. The daemon never writes to a base after the rename, so cloning B is safe even while workspaces are cloned from it.
- **`swap_base` returns `NeedsCheckout`** without touching the tree: the daemon applies the diff with jj's `check_out`, which writes only changed files into the workspace (those lose their clone sharing, which is the right cost). An alternative, re-cloning the new base and copying the upper-layer files over, would need the list of modified files and is not worth it in Phase 1.
- **`disk_usage`** is R1.02's stat-only comparison with the base's `tree_state`: allocated blocks of every file whose mtime or size differs, plus every file not in the base. `st_blocks` on an unmodified clone reports the full shared size, so a naive sum is useless; this is why the comparison exists. Documented as an estimate (a file rewritten with identical content and a new mtime counts as changed).
- **`tear_down`** is `fs_util::remove_tree_async` (rename, delete in the background; 4.4 s for the large preset).
- **`--path` on another volume** (R1.05's `Create`) falls back to `BackendKind::Copy` with a `warn` and the backend recorded as `copy` in the row, as the README states.

## Deliverables

### `crates/reef-daemon/src/backend/apfs.rs` (`#[cfg(target_os = "macos")]`)

```rust
/// APFS clone materialization: one `clonefile(2)` of the base directory,
/// per-file clones as the fallback.
pub struct ApfsBackend;

/// `clonefile(2)` with `CLONE_NOOWNERCOPY`. Errors carry the errno.
pub(crate) fn clonefile(src: &Path, dst: &Path, flags: u32) -> io::Result<()>;

/// Clones one regular file. Used by the per-file fallback and by R1.10's
/// shared walk on Linux through the `FileCopier` trait.
pub(crate) struct ApfsCloner;
impl FileCopier for ApfsCloner { fn copy_file(&self, from: &Path, to: &Path) -> io::Result<()> { reflink_copy::reflink(from, to) } }

impl Backend for ApfsBackend {
    fn kind(&self) -> BackendKind { BackendKind::ApfsClone }
    fn materialize(&self, base: &BaseEntry, ws: &WorkspacePaths) -> Result<(), BackendError>;
    fn disk_usage(&self, base: &BaseEntry, ws: &WorkspacePaths) -> Result<DiskUsage, BackendError>;
    fn swap_base(&self, ws: &WorkspacePaths, from: &BaseEntry, to: &BaseEntry) -> Result<SwapOutcome, BackendError>;  // NeedsCheckout
    fn tear_down(&self, ws: &WorkspacePaths) -> Result<(), BackendError>;
}

/// Trial clone of a probe file from `base_dir` into `target_dir`.
pub(crate) fn probe_apfs(base_dir: &Path, target_dir: &Path) -> Probe;

/// Clones `from` to `to` (both directories, `to` absent) with one call.
pub(crate) fn clone_dir(from: &Path, to: &Path) -> io::Result<()>;
```

`materialize` emits `tracing::info!(workspace_id, backend = "apfs", elapsed_ms, method = "dir" | "per-file", "workspace materialized")`.

### `crates/reef-daemon/src/backend/base_cache.rs` (extend R1.02)

```rust
impl BaseCache {
    /// Like `ensure` (same shape: synchronous, keyed by tree id, the jj part in a
    /// closure), but clones `nearest` with `cloner` and has the closure check out
    /// only the diff. The closure receives `(tmp_tree_dir, tmp_state_dir)` holding
    /// the clone and a copy of `nearest`'s state.
    pub(crate) fn ensure_from(
        &self,
        tree_id: &str,
        nearest: Option<&BaseEntry>,   // None or any failure: Err, and the caller falls back to `ensure`
        cloner: &dyn DirCloner,
        check_out_diff: impl FnOnce(&Path, &Path) -> Result<MaterializeStats, MaterializeError>,
    ) -> Result<BaseEntry, BaseCacheError>;
}

/// Implemented by backends that can clone a whole directory cheaply.
pub(crate) trait DirCloner: Sync { fn clone_dir(&self, from: &Path, to: &Path) -> io::Result<()>; }
```

`ApfsBackend` implements `DirCloner`. The daemon (R1.05's create flow) calls `ensure_from` instead of `ensure` when the selected backend has a `DirCloner`, passing as `nearest` the entry from `entries()` with the most recent `last_used_at`. The incremental path: clone B to `<T>.tmp/`, copy B's `.state/` to `<T>.tmp.state/` (R1.02's naming, so `sweep_incomplete` finds leftovers), then the closure runs `Repo::materialize_tree_from(&commit_T, tmp_root, tmp_state)`, added to `reef_lib::jj::materialize` here, which loads a `LocalWorkingCopy` on them (`LocalWorkingCopy::load(store, tmp_root, tmp_state, &settings)`) instead of initializing an empty one, `start_mutation`, `check_out(&commit_T)`, `finish(op_id)`. Then the two renames. On any failure, remove both temporary directories and return the error; the daemon then falls back to `ensure` (the full path). Emit `tracing::info!(tree_id, from_tree_id, files_changed = stats.updated_files + stats.added_files + stats.removed_files, elapsed_ms, "base materialized incrementally")` (`CheckoutStats` fields, verified in jj-lib 0.46.0 `working_copy.rs`: `updated_files`, `added_files`, `removed_files`, `skipped_files`, all `u32`).

## Implementation notes

- `clonefile` takes C strings; use `CString::new(path.as_os_str().as_bytes())`. Call through `libc::clonefile`; map `-1` to `io::Error::last_os_error()`. `libc` 0.2.190 does not export the `CLONE_*` flag constants (verified by grep); define `const CLONE_NOFOLLOW: u32 = 0x0001;` and `const CLONE_NOOWNERCOPY: u32 = 0x0002;` locally with a comment citing `<sys/clonefile.h>`.
- The directory clone needs the destination's parent to exist and the destination to be absent; `ws.root()`'s parent is the repository's `ws/` directory, created by R1.04's layout.
- A clone of the base includes the base's `.gitignore` and the synthetic manifest; both are tree content and belong there.
- For the probe file, use `bases/.probe` (created once, one byte) and clone it to `<target_dir>/.reef-probe-<pid>`; remove the clone afterwards. Do not leave probe files in a workspace root.
- `ensure_from` must take the repository thread for the jj transaction-free parts? No: `check_out` on a `LocalWorkingCopy` needs the store and a commit but no transaction; it can run on a blocking thread. It does need `settings`; take them from the `RepoHead` by value (`UserSettings: Clone`).
- `CheckoutStats` in jj-lib 0.46.0 (`working_copy.rs`) has `updated_files`, `added_files`, `removed_files`, `skipped_files`; a non-zero `skipped_files` in a base build is an error (the base must be complete).
- `reflink_copy::reflink` on macOS refuses to overwrite; the walk guarantees a fresh path.

## Acceptance criteria

- [ ] On macOS, `probe` reports `ApfsClone` for a directory on the same volume as the base cache and `materialize` of the `large` fixture takes under one second wall on the authoring machine (manual, three runs of test 7 recorded in the PR).
- [ ] A clone's files have the base's mtimes and sizes; the first snapshot after creation reports `changed == false` without rehashing (asserted by R1.11 once it lands; until then by test 1 and a manual check).
- [ ] Writing to a file in a workspace does not change the base (test 2) and costs roughly the written blocks.
- [ ] `ensure_from` produces a correct base from a sibling base and falls back to a full check-out when cloning fails.
- [ ] A `--path` on another volume selects `copy` with a warning rather than failing or silently copying under the `apfs` name.
- [ ] Linux builds are unaffected (`cfg(target_os = "macos")` everywhere; `cargo check --target x86_64-unknown-linux-gnu` is not required, CI covers it).
- [ ] ADR 0015 (R1.02) gains a note, or this PR adds a dated paragraph to it before it is accepted, recording the directory-`clonefile` measurement and the man page's discouragement.
- [ ] `just ci` passes.

## Out of scope

- Linux reflinks (R1.10), overlay mounts (R1.09).
- Base cache eviction (R1.17).
- A per-workspace APFS snapshot or a separate APFS volume per workspace (would give whole-tree copy-on-write without per-file metadata; needs `diskutil` and root).
- Preserving ACLs, xattrs, or ownership through the clone (`CLONE_NOOWNERCOPY` deliberately does not).

## Risks

- Apple discourages directory `clonefile`. If a macOS update breaks or slows it, the per-file fallback keeps the backend working at 13 s per workspace and the exit criterion fails; the ADR records that the alternative is a volume-level snapshot.
- `clonefile` returning `ENOSPC` on a later overwrite ("it is possible for a subsequent overwrite of an existing data block to return ENOSPC", man page) surfaces as an agent's write failing on a nearly full disk, which R1.23's disk-full test exercises.
- The one-second measurement is on an M2 Max with a warm page cache; GitHub's `macos-15` runners (3 vCPU M1, 7 GB) will be slower. R1.12 publishes both; the criterion is judged on the authoring class of hardware and the runner number is trend data.
