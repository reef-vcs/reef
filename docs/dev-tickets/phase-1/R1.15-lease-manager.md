# R1.15 Lease manager

Phase 1 · Size M · Depends on: R1.05, R1.13 · Unblocks: R1.17 (GC deletes reclaimed rows), R1.18 (restore expires leases with grace), R1.21 (`ws run` heartbeats), R1.23 (kill and reclaim tests)

## Context

The design's "Leased" rule (`docs/design.md`, Workspaces): every workspace records an owner, a change, a purpose, and a lease the agent's session must heartbeat; when the lease lapses the daemon takes a final snapshot, records it in the operation log, and reclaims the directory, so a crashed agent leaves a snapshot and a log entry, not a directory. This is the phase exit criterion "killing an agent process mid-edit leaves a snapshot in the store and no directory on disk after the lease expires" and the reason worktree failure 3 ("no owner and no expiry") goes away. The design also warns that lease tuning is a product decision: too short and a slow agent loses its workspace mid-task, too long and disk fills; the snapshot-on-expiry design makes a wrong default recoverable.

R1.01 created the `leases` and `reclaims` tables and R1.05 issues a lease on `Create` with the default length. This ticket adds the heartbeat, the expiry loop, the grace and restart rules, and the reclaim pipeline, and writes ADR 0019.

### What was verified while writing this ticket

- `MutableRepo::remove_workspace(&name)` (jj-lib 0.46.0 `repo.rs`): calls `maybe_abandon_wc_commit` (abandons the working-copy commit when it is discardable: empty tree relative to its parent, no description, not referenced elsewhere) then `view.remove_workspace(name)`. A non-empty working-copy commit stays as a visible head. This is what `jj workspace forget` does and what reclaim uses.
- `MutableRepo::update_wc_commits` runs inside `rebase_descendants`; forgetting a workspace in the same transaction as another workspace's snapshot is safe because the transaction is serialized on the repository thread (R1.03).
- The lease and reclaim rows and the `workspaces.state` values are R1.01's schema, repeated below.

## Decisions

- **Lease shape.** One active lease per workspace (`workspaces.lease_id`), rows kept forever until R1.17 deletes the workspace. `length_ms` is the request's `lease_ms` (R1.05's `CreateRequest.lease_ms`, field 8, 0 meaning the repository's `reef.toml` `[workspace] lease`, else `lease.default`). A request above `lease.max` is `InvalidArgument`, not a silent cap; a `reef.toml` value above it is capped with a `warn`, because the repository's authors cannot know every daemon's maximum. `grace_ms` is `lease.grace` at issue time; it is not per request.
- **Heartbeat.** `Workspaces.Heartbeat { repo, workspace_id, lease_id } -> { lease_id, expires_at, heartbeat_every }` sets `expires_at = now + length_ms` and `last_heartbeat_at = now`. A `lease_id` that is not the workspace's current one is `Conflict` ("lease superseded"); a workspace that is `released` or `reclaimed` is `Conflict` ("workspace reclaimed at <time>"); an unknown workspace is `NotFound`. Heartbeat never snapshots and never touches jj.
- **Expiry tick.** A tokio interval of `lease.tick` (10 s) runs `SELECT ... FROM leases WHERE ended_at IS NULL AND expires_at + grace_ms < :now` and reclaims each hit, sequentially, on the daemon's reclaim task (one at a time per daemon; reclaim is rare and the final snapshot holds the workspace lock anyway). A heartbeat that arrives after `expires_at` but before `expires_at + grace_ms` revives the lease, which is the point of the grace: a slow agent that misses one heartbeat does not lose its directory.
- **Reclaim pipeline** for a workspace `W` (also used by R1.18's restore for leases it decides to expire, and by `Release` through the shared function with `reason = released`):
  1. `UPDATE workspaces SET state = 'releasing'`; `Scheduler::untrack(W)` so no watcher snapshot races the final one.
  2. If the workspace root exists: `Scheduler::snapshot_now(W, Final, Some("lease expired"))`, description `reef: final snapshot of workspace <ws-id> (lease expired)`. If the root is missing (the agent or a human deleted it), skip with `snapshot_taken = 0` and `detail = 'workspace root missing'`.
  3. On a failed final snapshot: `attention = 'final-snapshot-failed'`, `state` back to `active`, log at `error` with the chain, keep the lease row open (so the next tick retries), and rate-limit the error to once per 10 ticks per workspace. Nothing is torn down while a snapshot might still be possible.
  4. On success or skip: on the repository thread, `remove_workspace(reef-<ws-id>)` in a transaction described `reef: release workspace <ws-id>`; `workspace_store().forget`; then `backend.tear_down(paths)` (R1.02), remove the `wc/<ws-id>` state dir; insert `reclaims { reason: 'expired', final_op_id, snapshot_taken, freed_bytes (disk usage measured before tear-down), at, detail }`; `UPDATE leases SET ended_at = now, end_reason = 'expired'`; `UPDATE workspaces SET state = 'reclaimed', lease_id = NULL`.
  5. `tracing::info!(workspace_id, lease_id, repo, op_id, "workspace reclaimed")`, preceded by `info!(.., "lease expired")` at step 1.
- **Restart grace.** At daemon start, before the first tick, `UPDATE leases SET expires_at = MAX(expires_at, :now + :restart_grace) WHERE ended_at IS NULL`, logged with the count. The first tick therefore reclaims nothing that was alive at shutdown; R1.18's restore applies the same statement and additionally the grace to everything.
- **Shutdown** (R1.03) snapshots dirty workspaces with `kind = Shutdown` and leaves leases untouched; expiry resumes after restart with the grace above.
- **Owner is informational.** Nothing checks that a heartbeat comes from the owner; the lease id is the capability. RX.01 reviews this.
- **Defaults** (README): `default = 30m`, `max = 24h`, `grace = 5m`, `restart_grace = 5m`, `heartbeat = 60s` (what `ws run` uses), `tick = 10s`. Tests override all of them to seconds.

### `crates/reef-daemon/src/lease/mod.rs`

```rust
pub struct LeaseConfig { pub default: Duration, pub max: Duration, pub grace: Duration, pub restart_grace: Duration, pub heartbeat: Duration, pub tick: Duration }
pub struct LeaseManager { /* db, scheduler, repo threads, backend registry, config */ }
impl LeaseManager {
    pub fn issue(&self, ws: WorkspaceId, repo: RepoId, owner: &str, length: Option<Duration>) -> Result<LeaseRow, LeaseError>;   // used by Create
    pub fn heartbeat(&self, ws: WorkspaceId, lease: LeaseId) -> Result<LeaseRow, LeaseError>;
    pub fn apply_restart_grace(&self) -> Result<usize, LeaseError>;
    pub fn start_expiry_loop(self: Arc<Self>) -> JoinHandle<()>;
    pub async fn reclaim(&self, ws: WorkspaceId, reason: ReclaimReason) -> Result<ReclaimOutcome, ReclaimError>;  // the pipeline; Release calls it with Released
    pub async fn tick_once(&self) -> Result<Vec<WorkspaceId>, LeaseError>;   // what the loop calls; tests call it directly
}
#[derive(Clone, Copy)] pub enum ReclaimReason { Released, Expired, Restore }
pub struct ReclaimOutcome { pub snapshot_taken: bool, pub final_op: Option<OperationIdHex>, pub freed_bytes: Option<u64> }
#[non_exhaustive] pub enum LeaseError { NotFound(WorkspaceId), Superseded { workspace: WorkspaceId, lease: LeaseId }, Reclaimed { workspace: WorkspaceId, at: SystemTime }, TooLong { requested: Duration, max: Duration }, Db(#[from] rusqlite::Error) }
```

`LeaseError` and `ReclaimError` implement `Classify` (`Superseded`/`Reclaimed` → `Conflict`, `TooLong` → `InvalidArgument`).

`[lease]` section as above, with validation: `grace <= default`, `restart_grace <= max`, `heartbeat < default` (warn, not error, when `heartbeat >= default / 2`).

### `docs/adr/0019-leases-and-reclaim.md`

Status `accepted`. Context: worktrees have no owner and no expiry; the design's lease rule and the "lease tuning is a product decision" warning; what jj's `workspace forget` does. Decision: lease id as capability, heartbeat semantics, grace, restart grace, the reclaim pipeline and its refusal to tear down after a failed final snapshot, defaults and why (30 minutes covers a long test run between heartbeats from a live `ws run`; 5 minutes of grace covers a daemon or machine pause; 24 hours is the longest unattended workspace a human can ask for). Consequences: a dead agent's directory lives at most `length + grace + tick`; disk is bounded by live leases; a human who runs `reef ws create` by hand must heartbeat or pass a long lease (R1.22's `--lease`). Alternatives: process-bound leases (pid liveness; rejected: the daemon cannot see processes on another machine or in a container); no grace (rejected: one missed heartbeat would reclaim); reclaim without a final snapshot when the snapshot fails (rejected: that is the one way to lose work).

### `crates/reef-daemon/tests/leases.rs`

Test config: `lease.default = 2s`, `max = 10s`, `grace = 1s`, `restart_grace = 3s`, `tick = 500ms`; `TestDaemon` with the `small` preset.

1. `heartbeat_extends`: create; heartbeat at 1 s; `Inspect.lease.expires_at` moved by about 2 s; `last_heartbeat_at` updated.
2. `expired_lease_is_reclaimed`: create, write a file, stop heartbeating; after 4 s: directory gone, `wc/<id>` gone, `Inspect.state == RECLAIMED`, `lease.end_reason == "expired"`, a `reclaims` row with `reason = 'expired'` and `snapshot_taken = 1`, the op log head's description starts with `reef: release workspace` and its parent is the final snapshot containing the file, and the jj view has no `reef-<id>` workspace.
3. `grace_revives`: stop heartbeating; at `expires_at + 0.5 s` heartbeat succeeds; at 4 s the workspace is still active.
4. `heartbeat_after_reclaim_is_conflict`: as 2, then `Heartbeat` → `FAILED_PRECONDITION` with `ErrorDetail.kind == "Conflict"`.
5. `superseded_lease_is_conflict`: heartbeat with a random lease id → `FAILED_PRECONDITION`.
6. `too_long_is_invalid`: `lease_ms = 11_000` → `INVALID_ARGUMENT`.
7. `restart_applies_grace`: create; stop the daemon; sleep past expiry; start a daemon on the same state dir; `tick_once` reclaims nothing; `expires_at >= start + 3 s`; after 4 s it is reclaimed.
8. `final_snapshot_failure_keeps_directory`: `chmod 000` the workspace root (Unix, skipped as root); let the lease expire; after two ticks the directory exists, `attention == "final-snapshot-failed"`, `state == ACTIVE`; `chmod 755`; next ticks reclaim with `snapshot_taken = 1`.
9. `missing_root_is_reclaimed_without_snapshot`: `rm -rf` the root; expire; reclaimed with `snapshot_taken = 0` and `detail` mentioning the missing root; no final snapshot operation.
10. `release_uses_the_pipeline`: `Release` produces a `reclaims` row with `reason = 'released'` and the lease `end_reason = 'released'`.
11. `empty_wc_commit_is_abandoned`: create and release without writing; the workspace's commit is no longer a visible head; with a write, it is.

## Implementation notes

- Compute "now" once per tick and pass it to the query; SQLite integer arithmetic on milliseconds is exact.
- The reclaim task must not hold the SQLite connection across the final snapshot; read what it needs, drop the lock, snapshot, re-acquire.
- `tick_once` returns the ids it reclaimed so tests can drive it deterministically instead of sleeping on the interval; the loop is `loop { interval.tick().await; let _ = self.tick_once().await; }` with errors logged.
- Reclaim and `Release` of the same workspace can race; `UPDATE workspaces SET state = 'releasing' WHERE id = ? AND state = 'active'` with the changed-row count decides who proceeds.
- `freed_bytes` is `backend.disk_usage` before tear-down (R1.02's estimate); the `reclaims` row says so in `detail` when the backend reported `None`.
- Telemetry fields: `workspace_id`, `lease_id`, `repo`, `op_id`, `elapsed_ms`; messages `lease issued`, `lease renewed` (debug), `lease expired`, `workspace reclaimed`, `final snapshot failed`.

## Out of scope

- `reef ws run`'s client-side heartbeat loop (R1.21) and the `--lease` CLI flag (R1.22).
- Automatic GC after reclaim (R1.17 is manual in Phase 1).
- Presence or notifications about expiring leases (R2.10).
- Session identity as owner (R3.03).

## Risks

- The grace window lets a dead agent's directory survive `grace` longer; 5 minutes is cheap in disk and avoids false reclaims on a paused machine, but the defaults are the product decision the design flagged and R1.23's measurements may move them.
- A final snapshot that keeps failing (permission denied forever) keeps the directory forever and spams one error per 10 ticks; `reef ws list` shows the attention flag so a human can `release --force`, which R1.22 provides as "reclaim without snapshot" with an explicit confirmation.
- Clock jumps (sleep, NTP) move `now`; expiry uses wall-clock milliseconds because leases must survive restarts, so a forward jump can expire leases early. Restart grace covers the restart case; the sleep case is accepted.
