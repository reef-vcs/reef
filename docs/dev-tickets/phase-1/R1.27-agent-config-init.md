# R1.27 `reef init`: agent configuration for a repository

Phase 1 · Size S · Depends on: R1.26 (`docs/agent-guide.md` is the content; the no-prompt contract), R1.25 (`init` registers and colocates the repository first) · Unblocks: R1.24 (the quickstart's "set up your agent" step), R2.13 (adds the MCP entry to the same command), R2.25 (packages the same files as harness plugins), RX.07 (scenario B)

## Context

R1.26 makes Reef learnable from the tool. This ticket covers the other path to an agent: the harness already knows. Every mainstream coding agent reads instruction files from the repository root before its first command, and most of them read the same one, `AGENTS.md`. If those files mention Reef, the agent's first command is `reef ws run` and R1.26's guide is never needed. Reef should write those files, conservatively, on request, from the same source text as `reef guide`, so there is one guide and it cannot drift.

Reef never starts an agent or holds its prompt (`docs/design.md`, Goals and non-goals). Writing a Markdown file an agent will read is on the right side of that line; the harness remains the thing that runs the agent.

### What was verified while writing this ticket

From the harness vendors' documentation as fetched on 2026-10-21 (formats change; the renderers below are small and tested so a change is a one-file fix):

- `AGENTS.md` (agents.md): plain Markdown at the repository root, no required sections, nested files allowed with nearest-wins; read by Codex, Cursor, Gemini CLI, Copilot's coding agent, Aider (with configuration), opencode, Zed, Jules, Devin, Junie, Amp, Windsurf, and others.
- Claude Code: project skills live at `.claude/skills/<name>/SKILL.md` with YAML frontmatter where every field is optional, `name` defaults to the directory name, `description` tells the model when to use it, and unrecognized fields are ignored. Claude Code also reads `CLAUDE.md` at the repository root (documented behavior, not re-fetched this session); many repositories make `CLAUDE.md` a one-line `@AGENTS.md` import.
- Claude Code MCP project scope is `.mcp.json` at the root, `{"mcpServers": {"<name>": {"command", "args", "env"}}}`, also written by `claude mcp add --transport stdio --scope project <name> -- <cmd>`. The MCP server itself is R2.13; this ticket does not write `.mcp.json`.
- Cursor: project rules are `.cursor/rules/*.mdc` (a `.md` there is ignored) with frontmatter `description`, `globs`, `alwaysApply`; Cursor also reads `AGENTS.md`.
- Claude Code's `--bare` mode skips `CLAUDE.md`, skills, and `.mcp.json` entirely (headless documentation), which is why RX.07's "no configuration" scenario uses it and its "after `reef init`" scenario does not.

## Decisions

- **One command, `reef init [PATH]`.** It does, in order: R1.25's registration with jj initialized alongside git (so `init` in a plain git checkout is the whole setup), then writes the agent files for the harnesses it detects or is told. Flags: `--agents <auto|all|none|claude,cursor,...>` (default `auto`), `--user` (also write the user-level Claude Code skill at `~/.claude/skills/reef/SKILL.md`), `--check` (write nothing; exit 0 if every file it would write is already current, 3 if any is missing or stale, listing them), `--print` (write nothing; print the `AGENTS.md` section to stdout, for a human or agent to paste), `--no-register`. No `--force`: `init` never overwrites text it did not write.
- **Detection (`auto`).** Always `AGENTS.md`. `claude` when `CLAUDE.md` or `.claude/` exists at the root or `--user` is given; `cursor` when `.cursor/` exists. `all` writes every renderer. Detection is by files in the repository, never by scanning the user's home directory or `PATH` for agent binaries.
- **Managed sections, never whole files, for `AGENTS.md` and `CLAUDE.md`.** Content goes between `<!-- reef:begin v1 -->` and `<!-- reef:end -->`. Missing file: create it with the section (for `CLAUDE.md`, only when `claude` is selected). File without markers: append a blank line and the section. File with markers: replace between them, byte-for-byte identical outside. `CLAUDE.md` that contains `@AGENTS.md` on a line of its own gets nothing (it already imports the section). The `v1` is the section format version; a future `init` replaces older versions.
- **Whole files Reef owns**: `.claude/skills/reef/SKILL.md`, `.cursor/rules/reef.mdc`, and the user-level skill. These are overwritten when stale because the frontmatter says `generated-by: reef init`; a file at that path without that line is left alone and reported as `skipped`.
- **Content comes from `docs/agent-guide.md`** (R1.26): the short form into `AGENTS.md`/`CLAUDE.md` sections, the full text into the skill and the Cursor rule, each with a one-line preface naming the version of `reef` that wrote it and `reef guide` as the live source. Skill frontmatter: `name: reef`, `description: Isolate work in this repository in a Reef workspace (reef ws run), find out where you are (reef here), and read errors' next field for the fix.` Cursor frontmatter: the same `description`, `alwaysApply: false`.
- **Output.** Text: one line per file, `wrote`, `updated`, `unchanged`, or `skipped (<why>)`. JSON: `{"registered": {...} | null, "files": [{"path", "action", "reason"}]}`. `init` never commits, snapshots, or stages anything; it says `files written, not committed` once on stderr.
- **Reef's own repository runs `reef init --check` in CI** once the command exists (a `just` recipe and a step in `ci.yml`), and the committed `AGENTS.md`, `CLAUDE.md`, and skill are what `init` generates. Dogfooding is the test that the generated text is what a real agent in this repository reads.
- **Why not write `.mcp.json` now**: there is no server until R2.13. R2.13 adds the `mcp` renderer to this command and nothing else changes.

## Deliverables

### `crates/reef-vcs/src/agents/mod.rs` (new module, pure functions)

```rust
pub(crate) enum Harness { AgentsMd, ClaudeMd, ClaudeSkill { user: bool }, CursorRule }
pub(crate) fn detect(root: &Path, user: bool) -> Vec<Harness>;
pub(crate) fn render(h: &Harness, guide: &Guide, version: &str) -> String;
/// Splices `section` between the markers in `existing` (None when the file does not exist).
pub(crate) fn splice(existing: Option<&str>, section: &str) -> Splice; // Create | Append | Replace | Unchanged | SkipImports
pub(crate) fn plan(root: &Path, harnesses: &[Harness], guide: &Guide, version: &str) -> Vec<FileAction>;
pub(crate) fn apply(plan: &[FileAction]) -> io::Result<()>;
```

`Guide { short: &'static str, long: &'static str }` comes from R1.26's embedded `docs/agent-guide.md`. Unit tests for `splice` on every branch, including CRLF files (preserve the line ending in use) and a file whose markers are out of order (treated as no markers, with the file reported `skipped (markers damaged)` rather than appended to).

### `crates/reef-vcs/src/cli/init.rs`

The command: register (R1.25's client call with `INIT_ALONGSIDE_GIT`, honoring `--no-register`), `plan`, then `--check` / `--print` / `apply`.

### Reef's own `AGENTS.md`, `CLAUDE.md`, `.claude/skills/reef/SKILL.md`

Generated by the command and committed. `CLAUDE.md` is a one-line `@AGENTS.md` (so the `SkipImports` branch is exercised in CI).

### `justfile`, `.github/workflows/ci.yml`

`just agent-files` runs `cargo run -p reef-vcs -- init --agents claude --no-register --check`; CI's `check` job runs it after the build.

### `crates/reef-vcs/tests/init.rs`

- `fresh_git_repo_gets_agents_md_only`: no `CLAUDE.md` or `.cursor/`; after `init`, `AGENTS.md` exists with markers, no other file was created, `repo list` shows the repository.
- `detects_claude_and_cursor`: with `.claude/` and `.cursor/` present, writes the skill, `CLAUDE.md` section, and the rule.
- `appends_to_existing_agents_md_without_touching_the_rest`: a file with user text before; bytes outside the markers compare equal.
- `replaces_a_stale_section`: a `v1` section with old text is replaced; a second run reports `unchanged`.
- `claude_md_importing_agents_md_is_skipped`.
- `foreign_skill_file_is_not_overwritten`.
- `check_exit_codes`: 3 before, 0 after.
- `print_matches_section`: `--print` output equals the section `init` would write.
- `user_skill`: with `HOME` set to a temp dir, `--user` writes `~/.claude/skills/reef/SKILL.md`.
- `init_is_non_interactive`: runs with stdin closed (R1.26's contract).

## Implementation notes

- Write files atomically (temp file in the same directory, then rename) so an agent reading `AGENTS.md` mid-write never sees a half file.
- Respect an existing file's trailing-newline convention and CRLF; the splice tests cover both.
- The user-level path is `$HOME/.claude/skills/reef/SKILL.md`; do not consult `$XDG_CONFIG_HOME`, Claude Code does not.
- Keep renderers to string templates in the module; no templating crate.

## Verification

```sh
d=$(mktemp -d) && cd "$d" && git init -q && git commit -q --allow-empty -m init && mkdir .claude
reef init && cat AGENTS.md && ls .claude/skills/reef
reef init --check; echo $?      # 0
printf 'mine\n' > AGENTS.md && reef init && head -1 AGENTS.md   # mine
```

## Out of scope

- `.mcp.json` and `claude mcp add` (R2.13).
- Packaging as a Claude Code plugin or other harness packages (R2.25).
- Harness-specific files beyond the four above (Codex, Gemini CLI, Copilot, opencode all read `AGENTS.md`; Aider and Gemini CLI need a setting the quickstart mentions in one line).
- Writing into subdirectories (nested `AGENTS.md` in monorepos).

## Risks

- Vendor formats move. The renderers are string templates with tests against fixtures copied from the vendors' documentation, so a change is a small PR; the `generated-by` line and section version make re-running `init` the upgrade path.
- Some teams review every byte of `AGENTS.md`; appending to it unasked would be rude, which is why `init` is explicit, `--print` exists, and nothing runs it implicitly.
