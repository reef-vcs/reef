> Amended 2026-10-21 when R1.25 to R1.28 were added (see the README's departures list). The audience is now a developer with any git or jj repository who runs agents on a laptop or a VM; jj is not a prerequisite and `reef repo register` is not a step.

## Context

Phase 1 "can ship as a standalone tool against existing jj repositories" (`docs/design.md`, Roadmap). A tool ships with a page that gets a reader from nothing to a reclaimed workspace in ten minutes. The README still says "Phase 0 is in progress. Nothing user-facing runs yet"; this ticket replaces that with what runs, writes `docs/quickstart.md`, and drafts what the Phase 1 release notes say. The audience was a developer who already uses jj; since R1.25 it is a developer with any git or jj repository (Reef initializes jj alongside git itself and registers on first use).

Every command in the quickstart is executed on both platforms before the PR and its output pasted, trimmed, into the page, so the page is a test record as much as a guide.

### What was verified while writing this ticket

- The commands and flags below are the ones R1.22 fixes (command surface), R1.21 (`ws run`), R1.20 (`store build`), R1.18 (`backup`, `restore`), and R1.04 (`config show`). Any that change during implementation change here in the same PR.
- `cargo install --git https://github.com/reef-vcs/reef reef-vcs` installs only `reef`; `cargo install` builds only the named package's binaries. R1.22's autostart looks for `reef-daemon` next to `reef` and on `PATH` and otherwise runs `reef daemon run` from the `reef` binary itself (`cli/autostart.rs`), so one binary is a complete install and the quickstart never installs the `reef-daemon` crate. (Corrected 2026-10-21; the earlier text said both crates were needed.) R1.28's installer and Homebrew formula ship both binaries anyway, for service managers.
- jj 0.46.0 is what the daemon's repositories are compatible with (ADR 0008); the quickstart says "a repository created by jj 0.46 or opened by it".

## Decisions

- **One page, `docs/quickstart.md`**, under 250 lines, in the order install, run an agent, set up your agent, watch it reclaim, inspect and undo, shared stores, backup, configuration, limits. No separate "concepts" page; the design doc is linked for that. Each section is a numbered command block followed by the expected output.
- **The quickstart does not require jj.** It starts in any git checkout; the first `reef` command registers it and initializes jj alongside git (R1.25), and the page shows the one stderr line that says so and what was added (`.jj/`, one `info/exclude` line). A repository that is already a jj repository works the same without the init. `jj git init --colocate` is no longer required: the page mentions it once as what Reef did for you, not as a step.
- **The README's status line becomes a Phase 1 status line** with a link to the quickstart; the "Repository layout" and "Design" sections gain the `docs/quickstart.md`, `docs/load-tests.md`, and phase-1 tickets links; the issues link moves to `phase-1`. Nothing else in the README changes; it describes the whole project, not the phase.
- **Release notes live in `CHANGELOG.md`** at the root, Keep-a-Changelog layout, one `## 0.1.0` section drafted by this ticket as "Unreleased" and renamed by whoever cuts the release (no release process exists until R4.17; the ticket writes the notes so they are not reconstructed from git log later). Each later phase adds its own section.
- **Known limitations are a section, not a footnote**: watcher snapshots are local-only; two workspaces editing one change diverge; colocated repositories do not export to git from Reef (bookmarks are imported, not exported); `jj` CLI use on the registered root is fine but on a Reef workspace directory is not (no `.jj` there); Windows unsupported; the symlink store tier is advisory against a same-user process; `reef.toml` is read from the commit, not from disk; a `jj` binary newer than jj-lib 0.46 may upgrade on-disk formats when run in a repository Reef initialized (ADR 0024); tools that do not read `.git/info/exclude` see `.jj/`.
- **No screenshots, no asciinema**; plain text output blocks, trimmed to the lines that matter, with `...` for the rest.

## Deliverables

### `docs/quickstart.md`

Outline, with the commands each section runs:

1. **What you get** (3 sentences): leased copy-on-write workspaces on an existing jj repo, snapshotted continuously, reclaimed when the agent goes away.
2. **Install**: the installer one-liner from R1.28 first (`curl -fsSL https://raw.githubusercontent.com/reef-vcs/reef/main/install.sh | sh`), then `brew install reef-vcs/tap/reef`, `cargo binstall reef-vcs`, and `cargo install --git https://github.com/reef-vcs/reef reef-vcs` as "from source"; check `reef --version`, optional `reef completions zsh`. Requirements: macOS 13+ on APFS, or Linux with kernel overlayfs (daemon with `CAP_SYS_ADMIN`, typically root in a VM or container) or `fuse-overlayfs` on `PATH`, or btrfs/XFS for reflinks; otherwise the copy backend, which works everywhere and is slow on big trees. `jj` 0.46.
3. **Start the daemon**: `reef daemon start`, `reef daemon status`; where the state lives (`reef config show` output trimmed to `state_dir`, `socket`, `workspace.backend`); that any `reef` command autostarts it.
4. **No setup**: `cd your-repo` (git or jj) and go straight to the next section; the first command prints `reef: registered ... and initialized jj alongside git`, and this section shows that line, `reef repo list`, and exactly what changed in the checkout (`.jj/`, `/.jj/` in `.git/info/exclude`) and how to undo it (`reef repo forget`, `rm -rf .jj`). `reef repo register` is mentioned as the explicit form.
5. **Run an agent in a workspace**: `reef ws run --purpose "fix the flaky test" -- claude -p "..."` (or `-- bash` for a shell); what the agent sees (`pwd`, `REEF_WORKSPACE`, and `reef here`'s output from inside); `reef ws list` from another terminal showing the lease ticking; the change id and how to see the agent's edits from the main checkout (`jj log -r <change>`, because Reef workspaces are jj workspaces and snapshots are jj operations).
5a. **Set up your agent** (short): `reef init` in the checkout writes `AGENTS.md`, `CLAUDE.md`, and the Claude Code skill so the agent starts in a workspace on its own; `reef init --user` for every repository on this machine; `reef guide` is what the agent reads and what to paste anywhere else; `reef init --check` in CI. One sentence each for Aider and Gemini CLI needing a setting to read `AGENTS.md`.
6. **Watch it reclaim**: `reef ws create --lease 1m -o json`, write a file in the path, wait, `reef ws list --all` showing `reclaimed`, `jj log` showing the final snapshot; "kill -9 the agent" variant with `ws run`.
7. **Two agents on one change** (short): `ws create --change <id>` twice, what `divergent` in `ws list` means and that nothing is lost; resolution is a jj operation today (`jj squash`/`jj abandon` on the root checkout) and a Reef operation in Phase 2.
8. **Shared dependency stores**: a `reef.toml` example for a pnpm repository, `reef store build node_modules`, `reef store list`, `ws create` output showing the mount; the symlink caveat.
9. **Move a workspace**: `reef ws move <id> --new-on main`.
10. **Backup and restore**: `reef backup ~/reef-backup`, what it contains, `reef daemon stop && reef restore ~/reef-backup && reef daemon start`, that leases get a grace period after restore.
11. **Configuration**: the `config.toml` keys a user is likely to touch (`lease.default`, `workspace.backend`, `watcher.backend`, `gc.undo_window`), with `reef config show` as the reference; `reef ws gc`.
12. **Known limitations in Phase 1**: the list from Decisions.
13. **Where next**: design doc, dev-phases, ADR index, how to report issues (issue template from R0.08).

## Unreleased (Phase 1: leased copy-on-write workspaces)

### Added
- `reef-daemon`, a per-machine service over a Unix socket (gRPC, `reef.daemon.v0`), with a SQLite state database, structured logs, and graceful restart.
- Workspaces on existing jj repositories: `reef ws create|list|inspect|release|move|gc`, each a jj workspace materialized copy-on-write (APFS clones, overlayfs or fuse-overlayfs, reflinks, or a plain copy).
- Continuous snapshots driven by a filesystem watcher (notify; Watchman optional), with staleness and divergence handling that never discards an agent's edits.
- Leases with heartbeats, expiry, and reclaim with a final snapshot; `reef ws run` as the agent entry point.
- `reef.toml` workspace spec: lease default, snapshot excludes, shared dependency stores built once per lockfile and mounted read-only.
- `reef backup` and `reef restore`, and a quiesce RPC for filesystem snapshots.

## Implementation notes

- Run every command block on a fresh macOS user account (or a clean `REEF_STATE_DIR`) and on a Linux VM with root (overlayfs tier) and without (fuse-overlayfs tier); paste outputs; where they differ by platform, show one and note the difference in a sentence.
- Keep the example repository small and real: a clone of a small public jj-using repository, or the user's own; do not use the synthetic generator in the quickstart.
- Link every ADR the limitations rest on (0008, 0014, 0016, 0018, 0022, 0024) inline.
- The `claude -p` example must not imply Reef launches or configures the agent; the design is explicit that it does not.
- Markdown style as the rest of `docs/`: sentence-case headings, fenced `sh` blocks for commands and `text` blocks for output, no HTML.

## Out of scope

- A hosted documentation site, versioning of docs, and search (RX.04).
- Signed binaries and notarization (R4.17); the installer, tap, and binstall metadata are R1.28's and the quickstart only uses them.
- Documentation of the API or the proto schema for SDK authors (R2.01, R2.06, R2.07).
- Tutorials for specific agent runtimes beyond the one-line `ws run` example and the `reef init` step; R1.27 owns what `init` writes.

## Risks

- The quickstart goes stale the moment a flag changes; the `quickstart_commands_exist` test catches removed commands but not changed semantics, so each Phase 1 ticket that changes a documented behavior after this lands must edit the page (add it to the PR template checklist: "quickstart updated if user-facing behavior changed").
- The Linux root versus non-root split doubles the verification work; if only one tier can be exercised before the PR, say which in the page and the PR.
