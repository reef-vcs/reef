# R1.09 overlayfs backend (Linux)

Phase 1 · Size L · Depends on: R1.02 · Unblocks: R1.20 (read-only bind mounts of shared stores reuse the privilege probe and the mount helpers), R1.23 (the Linux half of the 200-workspace load test runs on this backend)

## Context

Design, "Workspaces": "Linux: overlayfs: read-only snapshot as lower layer, thin writable upper layer. Cost to create: mount, milliseconds. Disk per workspace: modified files only." This is the backend that makes the exit criterion ("each created in under one second on APFS and overlayfs") trivial on Linux: a mount is a few milliseconds regardless of tree size, and the upper layer holds exactly the files the agent wrote. It is also the only backend whose `disk_usage` is exact rather than an estimate, because the upper directory is the per-workspace state.

The README fixed the privilege model (see "Departures from dev-phases.md"): kernel overlayfs when the daemon has `CAP_SYS_ADMIN`, `fuse-overlayfs` otherwise, no user namespaces in Phase 1. This brief implements both tiers behind one module, the probe that picks between them, re-establishing mounts on daemon start, cleanup of stale mounts, the `privileged-tests` feature, and the CI job that runs the kernel tier as root.

### What was verified while writing this ticket

- Kernel documentation (`docs.kernel.org/filesystems/overlayfs.html`, read 2026-10-16): mount syntax `mount -t overlay overlay -olowerdir=/lower,upperdir=/upper,workdir=/work /merged`; `workdir` "needs to be a directory on the same filesystem as upperdir"; `upperdir` "must support the creation of trusted.* and/or user.* extended attributes, and must provide valid d_type in readdir responses, so NFS is not suitable"; reusing upper or work paths of another mount "may fail with EBUSY". `-o userxattr` switches the xattr namespace to `user.overlay.*` "for unprivileged mounting". While mounted, "changes to the underlying filesystems are not allowed" (undefined behavior, "though it will not result in a crash or deadlock"); offline changes to the lower tree are allowed only if `metacopy`, `index`, `xino`, and `redirect_dir` were not used. With `redirect_dir` off (the documented default when `CONFIG_OVERLAY_FS_REDIRECT_DIR` is unset), renaming a lower or merged directory fails with `EXDEV`. Whiteouts in the upper layer are character devices `0/0` or zero-size files with `trusted.overlay.whiteout`; an opaque directory has `trusted.overlay.opaque = "y"`. Multiple lowers are colon-separated, top layer first. The page says nothing about inotify; fsnotify is implemented at the VFS layer, so events on the merged directory are expected to work and R1.13's tests confirm it.
- `fuse-overlayfs` (`containers/fuse-overlayfs`, `fuse-overlayfs.1.md`, read 2026-10-16): `fuse-overlayfs [-f] [-d] [-o OPTION[,OPTION2,...]] mountpoint` with `-o lowerdir=`, `upperdir=`, `workdir=`, plus `uidmapping`, `gidmapping`, `squash_to_root`, `squash_to_uid`, `squash_to_gid`, `static_nlink`, `noacl`, `xino=off|auto|on`, `ino32_t`; `-f` runs in the foreground (it daemonizes otherwise); unmount with `fusermount -u`; "can be used by unprivileged users". Ubuntu 24.04 (noble) packages `fuse-overlayfs 1.13-1` (packages.ubuntu.com). On Ubuntu 24.04 `fuse3` provides `fusermount3`; use it and fall back to `fusermount`.
- `nix` 0.31.3 (`src/mount/linux.rs`, features `mount` which pulls `uio`): `mount(source: Option<&P1>, target: &P2, fstype: Option<&P3>, flags: MsFlags, data: Option<&P4>)`, `umount(target)`, `umount2(target, MntFlags)` with `MntFlags::MNT_DETACH` and `MNT_FORCE`; `MsFlags::{MS_RDONLY, MS_BIND, MS_REMOUNT, ...}`. `nix` has no capability API; `CAP_SYS_ADMIN` is bit 21 of the `CapEff` line in `/proc/self/status`, which is what the probe reads before attempting a trial mount.
- GitHub's `ubuntu-24.04` runner (image 20261012.334.1, kernel 6.17.0-1022-azure, systemd 255, Podman 4.9.3 and Buildah 1.33.7 preinstalled): passwordless `sudo` is documented by GitHub for Linux runners; `fuse-overlayfs` is not in the preinstalled package list and is installed from apt in the CI job; `/dev/fuse` is expected to exist (Podman rootless depends on it) and is marked **unverified until the job's first run**.
- The kernel docs' "changes to underlying filesystems are not allowed" applies to the base cache entries that serve as lower layers: R1.02 makes entries immutable after their rename, and R1.17's eviction must skip any entry referenced by an `active` workspace, which the README already states.

## Decisions

- **Two tiers, one module.** `OverlayBackend { tier: Tier::Kernel | Tier::Fuse }` reports `BackendKind::Overlayfs` or `BackendKind::FuseOverlayfs`. Materialize, swap, tear down, and disk usage are the same code with the mount and unmount calls abstracted behind `trait Mounter { fn mount(&self, lower, upper, work, target) -> Result<()>; fn unmount(&self, target, lazy: bool) -> Result<()>; fn is_mounted(&self, target) -> Result<bool>; }`.
- **Probe order**: kernel first, FUSE second. Kernel: `CapEff` has bit 21, and a trial mount of an empty lower/upper/work triple under `<state>/repos/<repo-id>/ws/.probe/` succeeds and unmounts. FUSE: the `fuse-overlayfs` binary is on `PATH` (or `workspace.fuse_overlayfs` in config names it), `/dev/fuse` opens read-write, and the same trial mount through the binary succeeds within 5 s. Each unavailable tier records its reason (`no CAP_SYS_ADMIN`, `EPERM`, `ENODEV` (overlay module missing), `fuse-overlayfs not on PATH`, `/dev/fuse: <errno>`, `trial mount timed out`).
- **Kernel mount options**: `lowerdir=<base>,upperdir=<ws>.upper,workdir=<ws>.work` plus `redirect_dir=on` (so agents can rename unmodified directories; without it a `mv` of a lower directory fails with `EXDEV`, which build tools do not expect), `index=off`, `metacopy=off`. If the mount fails with `EINVAL`, retry once without `redirect_dir=on` and log at `warn` that directory renames across layers will fail. `userxattr` is not passed on the kernel tier (the daemon is privileged; `trusted.*` works). Mount flags `MsFlags::empty()`; the mount is `nosuid` only if the config asks (`workspace.overlay_nosuid = false` by default, since agents run build tools that may need setuid helpers; RX.01 revisits).
- **FUSE mount**: `fuse-overlayfs -o lowerdir=<base>,upperdir=<ws>.upper,workdir=<ws>.work <ws root>` without `-f`, so it daemonizes and the mount survives a daemon restart like a kernel mount. The daemon waits for the mountpoint to appear in `/proc/self/mounts` with fstype `fuse.fuse-overlayfs` (poll every 50 ms, 5 s timeout). Unmount with `fusermount3 -u` (fall back to `fusermount -u`), lazy unmount `fusermount3 -uz`.
- **`materialize`**: create `<ws>.upper/` and `<ws>.work/` (`0700`) as siblings of the root, create the root, mount. The lower is `base.path()`; its `.state/` sibling is not visible through the mount. Nothing is copied; mtimes are the lower's.
- **`swap_base`** returns `SwapOutcome::TreeReplaced`: unmount, remove upper and work (`remove_tree_async`), recreate them, mount with the new base as lower. The daemon then calls `locked_wc.reset(&target)` and reseeds the `tree_state` from the new base (README). The old upper is deleted, not kept: R1.06 guarantees a final snapshot before the swap, so the writable layer is in the store.
- **`tear_down`**: `umount`; on `EBUSY` (an agent still has its cwd or an open file inside), `umount2(MNT_DETACH)`, which hides the mount from the namespace immediately while the kernel keeps it alive for the holders. Then remove upper and work with `remove_tree_async`, and remove the root directory (now empty). "No directory on disk after the lease expires" holds from the caller's view as soon as the lazy unmount returns.
- **Daemon start**: for every `active` workspace row whose backend is an overlay kind, check `/proc/self/mounts` for the root. Present: nothing to do (kernel mounts and daemonized `fuse-overlayfs` survive a daemon restart). Absent, or present but `stat` fails with `ENOTCONN` (a FUSE mount whose server died): lazy-unmount if needed, then mount again with the existing upper (the agent's edits are in it). A workspace whose upper is missing is marked `attention = 'upper-missing'` and left to the lease to reclaim.
- **Stale mount cleanup**: on start, every mount under `<state>/repos/*/ws/` whose root has no `active` row is lazily unmounted and its upper and work removed, logged at `warn` with the path.
- **`disk_usage`**: `allocated_bytes` over `<ws>.upper/` (whiteouts are tiny but counted), `files_changed` = number of regular files, symlinks, and whiteouts in the upper. Exact.
- **Feature `privileged-tests`** on `reef-daemon`: gates tests that need `CAP_SYS_ADMIN` (kernel tier conformance, the loop-mount reflink tests of R1.10). Not a code feature; it only enables tests, so it must not change any `cfg` in `src/`.
- **Not done in Phase 1**: user-namespace mounts (ADR 0016 records why: a mount in a private namespace is invisible to a shell outside it; the option returns with a sandboxed `reef ws run`), `squash_to_uid` mappings, multiple lower layers (a future "base plus shared store" stack), `metacopy`.
- **ADR 0016** "overlayfs on Linux: privilege tiers": context (what each tier needs, what GitHub runners and typical VMs offer), decision (the two tiers, the probe, the options above), consequences (a daemon run as root serves kernel mounts; an unprivileged one needs `fuse-overlayfs` installed or falls back to reflink/copy; lower layers must be immutable, which constrains R1.17), alternatives (user namespaces with `setns` from `ws run`; a setuid mount helper; `bubblewrap`).

## Deliverables

### `crates/reef-daemon/src/backend/overlay/mod.rs` (`#[cfg(target_os = "linux")]`)

```rust
pub struct OverlayBackend { tier: Tier }
pub(crate) enum Tier { Kernel, Fuse { binary: PathBuf } }

pub(crate) trait Mounter: Send + Sync {
    fn mount(&self, lower: &Path, upper: &Path, work: &Path, target: &Path) -> Result<(), MountError>;
    fn unmount(&self, target: &Path, lazy: bool) -> Result<(), MountError>;
}

/// Reads `/proc/self/mounts` and reports whether `target` is a mountpoint and its fstype.
pub(crate) fn mount_info(target: &Path) -> io::Result<Option<MountInfo>>;

/// `CapEff` bit 21 from `/proc/self/status`.
pub(crate) fn has_cap_sys_admin() -> io::Result<bool>;

/// Trial mount in `probe_dir`; both tiers.
pub(crate) fn probe_overlay(probe_dir: &Path, config: &OverlayConfig) -> Vec<Probe>;

impl Backend for OverlayBackend {
    fn kind(&self) -> BackendKind;
    fn materialize(&self, base: &BaseEntry, ws: &WorkspacePaths) -> Result<(), BackendError>;
    fn disk_usage(&self, base: &BaseEntry, ws: &WorkspacePaths) -> Result<DiskUsage, BackendError>;
    fn swap_base(&self, ws: &WorkspacePaths, from: &BaseEntry, to: &BaseEntry) -> Result<SwapOutcome, BackendError>;  // TreeReplaced
    fn tear_down(&self, ws: &WorkspacePaths) -> Result<(), BackendError>;
}

/// Daemon start: re-establish or clean up mounts for `rows` (active workspaces).
pub(crate) fn reconcile_mounts(paths: &Paths, rows: &[WorkspaceRecord]) -> Result<ReconcileReport, BackendError>;   // Paths: R1.03, WorkspaceRecord: R1.01
```

`MountError` is `thiserror` with `{ Mount { target, source: nix::Error }, Unmount {..}, Busy { target }, Spawn { binary, source }, Timeout { target }, NotMounted { target } }`, `Classify` mapping `EPERM` to `PermissionDenied`, `EBUSY` to `Conflict`, the rest to `Io`.

### `crates/reef-daemon/src/backend/overlay/kernel.rs`

`KernelMounter` over `nix::mount::mount(Some("overlay"), target, Some("overlay"), MsFlags::empty(), Some(options))` with the options string built from the paths (escape `:` and `,` in paths as the kernel docs describe: `\:` and `\,`), the `EINVAL` retry without `redirect_dir=on`, `umount`/`umount2(MNT_DETACH)`.

### `crates/reef-daemon/src/backend/overlay/fuse.rs`

`FuseMounter { binary }` spawning `fuse-overlayfs -o lowerdir=..,upperdir=..,workdir=.. <target>` with `std::process::Command`, stdin null, stderr captured into the error on non-zero exit, then polling `mount_info` until the fstype is `fuse.fuse-overlayfs`; unmount via `fusermount3 -u` / `-uz`.

### Tests

In `overlay/` (`#[cfg(all(test, target_os = "linux"))]`):

1. `has_cap_sys_admin_matches_id` : equals `nix::unistd::geteuid().is_root()` on CI (not strictly the same thing, but true on the runner; document the assumption).
2. `mount_info_parses_proc_mounts`: parse a fixture string with escaped spaces (`\040`) and overlay options.
3. `kernel_options_escape_separators`: a lower path containing `:` and `,` is escaped.
4. `fuse_overlayfs_mounts_and_unmounts` (skipped unless `fuse-overlayfs` on `PATH` and `/dev/fuse` opens): mount a 3-file lower, write a file through the merged view, assert it is in upper and not in lower, unmount, assert the root is empty.
5. `kernel_overlayfs_mounts_and_unmounts` (`#[cfg(feature = "privileged-tests")]`, skipped unless `has_cap_sys_admin`): the same through `KernelMounter`, plus: rename a lower directory through the merged view succeeds (`redirect_dir=on`), delete a lower file and assert a whiteout (char device 0/0 or `trusted.overlay.whiteout`) in upper, `disk_usage.files_changed` counts it.
6. `tear_down_with_open_file_uses_lazy_unmount` (privileged): keep a `File` open inside the mount, `tear_down`, assert the root is gone from `/proc/self/mounts` and the open file still reads.
7. `reconcile_remounts_missing_and_cleans_stale` (privileged): materialize two workspaces, unmount one by hand, delete the row of the other, run `reconcile_mounts`, assert the first is mounted again with its upper intact and the second is unmounted and its upper removed.

R1.11's suite runs for both kinds with the same gating.

## Implementation notes

- `nix::mount::mount` wants `&str`/`&Path`-like `NixPath` arguments; the options string is a `&str`.
- Parsing `/proc/self/mounts`: fields are space-separated with octal escapes for space, tab, newline, backslash; the second field is the mountpoint, third the fstype. Compare canonicalized paths.
- `umount2` with `MNT_DETACH` returns immediately; the directory is then an ordinary empty directory and can be removed.
- `fuse-overlayfs` without `-f` forks; the `Command` returns when the parent exits, which is before the mount is ready, hence the polling.
- A FUSE mount whose server has died answers `stat` with `ENOTCONN` ("Transport endpoint is not connected"); `mount_info` shows it still mounted. Treat `ENOTCONN` as "needs lazy unmount and remount".
- Running cargo as root in CI writes root-owned files into `target/`; the `chown` step is mandatory or the next job's cache restore fails.
- `index=off` matters: with `index=on`, the kernel pins the upper/lower pair and re-mounting with a different lower fails; `swap_base` needs a fresh upper anyway, but keep it off.
- Overlay on top of a base that is itself a reflink or clone is fine; the base cache does not care.

## Acceptance criteria

- [ ] On a root daemon (CI job, kernel tier), R1.11's suite passes for `Overlayfs`; on an unprivileged daemon with `fuse-overlayfs` installed, it passes for `FuseOverlayfs`; on a machine with neither, `probe` reports both unavailable with the reasons above and `auto` falls through to reflink or copy.
- [ ] `materialize` of the `large` fixture on the kernel tier takes under 50 ms (number in the PR from the CI log or a Linux machine); `disk_usage` of a fresh workspace is 0 bytes and 0 files.
- [ ] Writing a file through the merged view lands in the upper only; deleting a lower file produces a whiteout; renaming a lower directory succeeds on the kernel tier with `redirect_dir=on`.
- [ ] `tear_down` with an open file inside succeeds via lazy unmount and leaves no directory.
- [ ] After killing and restarting the daemon, active overlay workspaces are mounted again with their upper layers intact; stale mounts with no row are cleaned.
- [ ] The `overlayfs` CI job runs on every PR and passes; its root step is last and chowns `target/`.
- [ ] ADR 0016 exists with the alternatives above; the index row is added.
- [ ] `just ci` passes.

## Out of scope

- User-namespace mounts and `setns` from `reef ws run` (ADR 0016, follow-up).
- A multi-layer stack (base plus shared stores as extra lowers).
- `metacopy`, `nfs_export`, `xino`, uid/gid mapping options.
- macOS (R1.08) and reflinks (R1.10).

## Risks

- `/dev/fuse` on GitHub runners is unverified; if absent, the FUSE conformance step is marked `continue-on-error` with a tracking note until a runner that has it is found, and the kernel step remains the gate.
- Kernel overlay behavior differs across distributions (`redirect_dir` default, `userxattr` availability); the `EINVAL` retry covers the common case and the probe's trial mount catches the rest before a workspace is created.
- Lazy unmounts keep the kernel mount alive until the last holder exits; an agent that never exits holds the upper's inodes, so disk is freed late. The lease model already assumes processes die; R1.23 kills them.
