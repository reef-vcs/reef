# R1.07 Plain copy fallback backend

Phase 1 · Size S · Depends on: R1.02 · Unblocks: R1.11 (the first backend the conformance suite runs against), R1.08 and R1.10 (share the tree walk and mtime helpers), R1.12 (the baseline every other backend is compared with)

## Context

Design: "Workspaces are caches, not truth" and the materialization table in `docs/design.md` ("Workspaces"), whose last row is "Fallback". The copy backend is that row for Phase 1: a full copy of the base cache entry into the workspace root. It exists so that every platform and filesystem works (tmpfs, ext4 without reflink, a `--path` on another volume, a network mount), so that the conformance suite (R1.11) has a backend to run against before the copy-on-write ones land, and so that the benchmarks (R1.12) have the number the design is trying to beat.

It also extends R1.02's `fs_util` module with the filesystem helpers the other backends share: the tree walk that creates directories, copies or clones files, recreates symlinks, and restores mtimes and executable bits, and the "rename, then delete in the background" teardown. Allocated-bytes accounting, free-space measurement, same-volume detection, and the stat-only comparison with the base are R1.02's and already in the module.

### What was verified while writing this ticket

- On the authoring machine (Apple M2 Max, macOS 27.0.1, APFS, `target/synth/large`: 102,005 files, 592 MB on disk), `cp -R` of the tree takes 25.9 s wall (19.6 s system) and consumes 632 MiB of free space; the copied files get a new mtime. The same tree cloned with one directory `clonefile(2)` takes 1.0 to 1.2 s and 30 MiB (R1.08). This is the gap the copy-on-write backends close, and the reason the copy backend must never be selected silently when a better one is available.
- `std::fs::copy` is not a plain copy. On macOS (Rust's `library/std/src/sys/fs/unix.rs`, `copy` for `target_vendor = "apple"`) it tries `fclonefileat` first and falls back to `fcopyfile` with `COPYFILE_ALL`; on Linux it uses `io::copy` over the kernel's `copy_file_range`, which btrfs and XFS implement as a reflink when they can. So a "copy" through `std::fs::copy` may silently be a clone, and a clone may silently be a copy. The copy backend uses it anyway (a free clone is fine for the fallback); the clone backends (R1.08, R1.10) do not, because they must fail loudly when cloning is impossible.
- `std::fs::copy` copies permission bits (so the executable bit survives) but not mtime. `std::fs::File::set_modified` (stable since Rust 1.75) needs a handle opened for writing, which fails on a read-only (`0o444`) file once `fs::copy` has applied the source mode. `nix::sys::stat::utimensat` (nix 0.31, feature `fs`) sets the times by path without opening the file, and with `UtimensatFlags::NoFollowSymlink` never follows a symlink; the walk uses it.
- `std::fs::read_link` and `std::os::unix::fs::symlink` recreate symlinks verbatim; `std::fs::symlink_metadata` is needed so a symlink is not followed during the walk. `walkdir` 2.5 (`WalkDir::new(root).follow_links(false)`) yields symlinks as entries with `file_type().is_symlink()`.
- Allocated bytes: `std::os::unix::fs::MetadataExt::blocks()` is in 512-byte units on both macOS and Linux; `libc::statvfs` (0.2.190, `src/unix/mod.rs`) gives `f_bavail * f_frsize` for free space on both. Same-volume detection is `MetadataExt::dev()` equality on the two directories.
- `rm -rf` of a 102,005-file clone takes 4.3 to 4.4 s on APFS. Workspace teardown must not spend that on the caller's critical path.

## Decisions

- **Module layout.** `crates/reef-daemon/src/backend/copy.rs` holds `CopyBackend`; `crates/reef-daemon/src/backend/fs_util.rs` (created by R1.02) gains the shared helpers below. `fs_util.rs` is R1.02's module, extended here. Both are `pub(crate)` except what the conformance suite and benchmarks need (`pub` with docs). The trait, `BackendKind`, `WorkspacePaths`, `BaseEntry`, `DiskUsage`, `SwapOutcome`, `BackendError`, and `probe` are R1.02's and are not redefined here. This brief assumes the accessors `ws.root()`, `ws.upper()`, `ws.work()` on `WorkspacePaths` and `base.path()`, `base.state_dir()`, `base.tree_id()` on `BaseEntry`; if R1.02 named them differently, use its names.
- **Copy is the last choice in the selection order** (README: overlayfs, fuse-overlayfs, apfs, reflink, copy). `probe` always reports `BackendKind::Copy` as available. Selecting it under `workspace.backend = "auto"` logs at `warn` once per repository with the reasons the others were unavailable, so a user who expected copy-on-write finds out.
- **The walk preserves what jj's `tree_state` keys on**: mtime (`utimensat`, set after the content is written and after the mode, so nothing touches the file afterwards; it works on read-only files because it does not open them), size (implied by content), file type, and the executable bit (`std::fs::copy` carries the mode; the walk re-applies `0o755` versus `0o644` masked by the source mode anyway, so the behavior is identical on every backend). Ownership, ACLs, and xattrs are not copied. Directories get mode `0o755`; their mtimes are not preserved (jj does not track directories).
- **Symlinks are recreated as symlinks** with the same target string, never followed, including dangling ones. The `.gitignore` in the base is a regular file and copies like any other.
- **Hard links in the base are not preserved**; each path is copied independently. jj's checkout never creates hard links, so a base never contains them.
- **Teardown is rename-then-delete.** `fs_util::remove_tree_async(path)` renames `path` to a sibling `<name>.trash-<nanos>` (an atomic `rename` on the same filesystem) and removes the renamed tree on `tokio::task::spawn_blocking`. The caller sees the directory gone immediately. On daemon start, `<state>/repos/*/ws/*.trash-*` leftovers are removed. The copy backend's `tear_down` uses it; R1.08 and R1.10 use it; R1.09 uses it for the upper and work directories after unmounting.
- **Free space is measured with `statvfs`**, through R1.02's `fs_util::free_bytes(path) -> io::Result<u64>`. The benchmarks and the load test use it; `disk_usage` does not.
- **Disk usage for copy is the full allocated size of the tree** (`fs_util::allocated_bytes(root)`), with `files_changed` from the stat-only comparison against the base's `tree_state` that R1.02 specifies for clone and copy backends. For the copy backend `allocated_bytes` is honest (nothing is shared) and that is the point: `ws list` shows the cost.
- **Errors**: `BackendError` variants from R1.02 carry the path. Interrupted materialization (a failure halfway) leaves a partial tree; the daemon (R1.05) removes it with `remove_tree_async` and reports the error. The backend does not clean up on its own.

## Deliverables

### `crates/reef-daemon/src/backend/fs_util.rs` (extends R1.02)

R1.02 created the module with `allocated_bytes`, `free_bytes`, `same_volume`, and `changed_files_vs_base`; this ticket adds:

```rust

/// How one regular file is produced in the destination tree.
pub(crate) trait FileCopier: Sync {
    /// Creates `to` from `from`. `from` is a regular file. Must leave `to`
    /// with the same size as `from`; mode and mtime are restored by the walk.
    fn copy_file(&self, from: &Path, to: &Path) -> io::Result<()>;
}

/// Copies the tree at `src` to `dst` (which must not exist), creating
/// directories, producing regular files through `copier`, recreating
/// symlinks verbatim, and restoring mode bits and mtimes on regular files.
/// Returns the number of regular files, symlinks, and directories created.
pub(crate) fn copy_tree(src: &Path, dst: &Path, copier: &dyn FileCopier) -> Result<TreeCounts, TreeError>;

/// Sets `to`'s mtime to `from_meta`'s with `nix::sys::stat::utimensat`
/// (`NoFollowSymlink`), so read-only files work and symlinks are not followed.
pub(crate) fn restore_mtime(to: &Path, from_meta: &fs::Metadata) -> io::Result<()>;

/// Renames `path` to a `.trash-<nanos>` sibling and deletes it in the
/// background. Returns once the rename is done.
pub(crate) async fn remove_tree_async(path: &Path) -> io::Result<()>;

/// Removes leftover `*.trash-*` siblings under `dir` synchronously (daemon start).
pub(crate) fn sweep_trash(dir: &Path) -> io::Result<u64>;

/// Executable-bit view of a mode, as jj records it.
pub(crate) fn is_executable(mode: u32) -> bool;
```

`TreeError` is a `thiserror` enum `{ Walk { path, source }, Create { path, source }, Copy { from, to, source }, Symlink { path, source }, Metadata { path, source } }` implementing `Classify` (`PermissionDenied` or `Io` by `classify_by_source`). `copy_tree` walks with `walkdir` (`follow_links(false)`, `sort_by_file_name()` so failures are deterministic), creates each directory before its children, and for regular files calls `copier.copy_file` then `set_permissions` with the source mode masked to `0o777`, then `restore_mtime`. It refuses to run if `dst` exists (`AlreadyExists`).

### `crates/reef-daemon/src/backend/copy.rs`

```rust
/// Full-copy materialization. Works everywhere; costs O(tree) time and disk.
pub struct CopyBackend;

impl FileCopier for CopyBackend {
    fn copy_file(&self, from: &Path, to: &Path) -> io::Result<()> { fs::copy(from, to).map(drop) }
}

impl Backend for CopyBackend {
    fn kind(&self) -> BackendKind { BackendKind::Copy }
    fn materialize(&self, base: &BaseEntry, ws: &WorkspacePaths) -> Result<(), BackendError>;   // copy_tree(base.path(), ws.root(), self)
    fn disk_usage(&self, base: &BaseEntry, ws: &WorkspacePaths) -> Result<DiskUsage, BackendError>;
    fn swap_base(&self, ws: &WorkspacePaths, from: &BaseEntry, to: &BaseEntry) -> Result<SwapOutcome, BackendError>;  // Ok(SwapOutcome::NeedsCheckout), no filesystem work
    fn tear_down(&self, ws: &WorkspacePaths) -> Result<(), BackendError>;   // remove_tree_async(ws.root()), blocking on the rename only
}
```

`disk_usage` returns `DiskUsage { allocated_bytes: allocated_bytes(root), files_changed }` with `files_changed` computed by R1.02's shared `fs_util::changed_files_vs_base(base, ws)` helper (stat-only comparison against the base's `tree_state`).

`tear_down` is synchronous in the trait; it performs the rename and spawns the deletion on the runtime's blocking pool (`tokio::runtime::Handle::try_current()`; when there is no runtime, as in the conformance suite's synchronous tests, it deletes inline).

### `crates/reef-daemon/src/backend/mod.rs`

Register `CopyBackend` in `probe` (always available, last in order) and in the backend constructor the daemon uses (`backend_for(kind) -> Box<dyn Backend>`), as R1.02 laid them out.

### Daemon start

In R1.03's start sequence, call `fs_util::sweep_trash` on every `<state>/repos/<repo-id>/ws/` directory and log the count at `info` if non-zero.

### Tests

`crates/reef-daemon/src/backend/fs_util.rs` unit tests (in `#[cfg(test)] mod tests`, each in a `tempfile::tempdir()`):

1. `copy_tree_preserves_mode_mtime_and_symlinks`: a tree with a `0o755` file, a `0o644` file, a relative symlink, a dangling symlink, an empty directory, and a nested directory; after `copy_tree`, every regular file has the same mode (masked `0o777`), size, and mtime (compare `modified()` to the millisecond; APFS and ext4 keep nanoseconds, but jj compares milliseconds), both symlinks have the same target, the empty directory exists.
2. `copy_tree_refuses_existing_destination`.
3. `remove_tree_async_hides_the_directory_before_deleting`: after the call returns, `path` does not exist; after awaiting the background task (expose a test hook returning the `JoinHandle`), no `.trash-*` sibling remains.
4. `sweep_trash_removes_leftovers`.
5. `allocated_bytes_counts_blocks`: a 1 MiB file reports at least 1 MiB; a sparse file (`set_len` without writing) reports less than its length.
6. `same_volume_true_for_siblings`.

The backend itself is tested by R1.11's conformance suite; this ticket adds only a smoke test `copy_backend_materializes_small_tree` in `crates/reef-daemon/src/backend/copy.rs` that materializes a 100-file tree from a hand-built `BaseEntry` (R1.02's test helper for building one from a directory, or a `BaseEntry::for_tests(path)` constructor if R1.02 did not add one) and asserts `disk_usage().allocated_bytes >= bytes written`.

## Implementation notes

- `walkdir` is a new dependency of `reef-daemon` (workspace entry `walkdir = "2"` from the README table; add it to `[workspace.dependencies]` if R1.02 did not). `nix` with feature `fs` is added under `[target.'cfg(unix)'.dependencies]` for `utimensat`.
- The order per regular file is copy content, set mode, set mtime. `utimensat` takes the path, so a `0o444` source mode does not block the last step; `File::set_modified` would need a write-open and is not used.
- `fs::copy` returns `Err(InvalidInput)` when the source is not a regular file; the walk only hands it regular files.
- The millisecond truncation of mtimes: jj stores `MillisSinceEpoch` and compares equal if the truncated values match; `utimensat` with the source's full timestamp (`MetadataExt::mtime` and `mtime_nsec`) is exact anyway on APFS, ext4, XFS, and btrfs.
- On macOS, `fs::copy` of a file on APFS is already a clone (`fclonefileat`). The copy backend's measured cost on this machine will therefore be close to R1.08's per-file path (about 13 s for the large preset) rather than the 26 s of `cp -R`. Record the measured number in the PR; it is the baseline R1.12 publishes.
- `tear_down` for a `.trash-*` rename needs the parent directory writable and the rename to stay on one filesystem, which it does because the sibling is in the same directory.

## Acceptance criteria

- [ ] `CopyBackend` implements `Backend` and `probe` lists `BackendKind::Copy` on macOS and Linux for any directory.
- [ ] `fs_util::copy_tree` produces files whose mode (masked `0o777`), size, and mtime equal the source's, and recreates symlinks (including dangling) verbatim; the unit tests above pass on both OSes in CI.
- [ ] `tear_down` returns with the workspace root gone; the deletion happens in the background and leaves no `.trash-*` sibling once complete; `sweep_trash` runs at daemon start.
- [ ] Selecting the copy backend under `auto` logs one `warn` naming why the other backends were unavailable.
- [ ] `just ci` passes.
- [ ] The PR records `materialize` wall time and free-space delta for the `large` preset on the authoring machine (via the R1.11 suite's timing output if it has landed, otherwise a `#[ignore]` test).

## Out of scope

- Any clone primitive (R1.08, R1.10), overlay mounts (R1.09).
- The base cache and the trait (R1.02); the conformance suite (R1.11); benchmarks (R1.12).
- Preserving ownership, ACLs, xattrs, hard links, or directory mtimes.
- Copying into a destination that already exists (the daemon guarantees a fresh root).

## Risks

- `std::fs::copy` cloning behind our back makes the "copy" backend's numbers on APFS look better than a true copy would. That is acceptable for a fallback and is stated in `docs/benchmarks.md` by R1.12.
- Background deletion races with a `ws create --path` to the same path immediately after a release: the rename frees the path at once, so a new workspace can take it; the old `.trash-*` deletion continues independently.
