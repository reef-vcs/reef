# R1.04 Daemon configuration and state directory layout

Phase 1 · Size S · Depends on: R1.03, R0.09 · Unblocks: R1.18 (backup retention, layout to copy), R1.22 (moves `reef config show` into its CLI skeleton), R2.08 (remote listener config), every ticket that reads a `[section]` below

## Context

The design's Architecture section says the daemon "keeps its own configuration and state directory rather than reading Jujutsu's user configuration", and the durability section names the backup retention window as a setting. R1.03 resolved only the state directory and the socket. This ticket adds `config.toml` with every section Phase 1 tickets read, the environment overrides, the complete directory layout, `reef config show`, and the jj settings the daemon builds from its own identity (ADR 0008 noted that jj-lib records empty `operation.hostname` and `operation.username` unless told otherwise).

### What was verified while writing this ticket

- `toml` 1.1.8 (MIT OR Apache-2.0) with serde `derive`; `humantime-serde` 1.1.1 provides `#[serde(with = "humantime_serde")]` for `Duration` fields, parsing `"30m"`, `"500ms"`, `"7d"`.
- `etcetera` 0.11.0: `choose_base_strategy()` picks XDG on every Unix including macOS; the Apple layout is `etcetera::base_strategy::Apple` with `data_dir()` = `~/Library/Application Support`. `Xdg::state_dir()` honoring `XDG_STATE_HOME` with the `~/.local/state` default: present in the crate's XDG strategy, return type (`Option<PathBuf>` or `PathBuf`) unverified; handle both.
- jj-lib's bundled defaults (`config/misc.toml`) set `operation.hostname = ""` and `operation.username = ""` and `git.abandon-unreachable-commits = true`, `git.executable-path = "git"`, `git.record-synthetic-predecessors = true`, `git.write-change-id-header = true`, so `GitSettings::from_settings` and `GitImportOptions::from_settings` work without Reef adding git keys. `UserSettings::operation_hostname()` and `operation_username()` are read once at settings construction (`settings.rs:177`).
- `nix` 0.31.3 (MIT): `unistd::gethostname()` and `unistd::User::from_uid(getuid())` behind features `hostname` and `user` (feature names from nix's `Cargo.toml`; confirm the exact spelling when adding).

## Decisions

- **Config file, overrides, layout, and schema exactly as the README fixes them.** Unknown keys are errors (`#[serde(deny_unknown_fields)]`), so a typo cannot silently disable a setting.
- **Precedence**: built-in default, then `config.toml`, then the three environment variables (`REEF_STATE_DIR`, `REEF_SOCKET`, `REEF_CONFIG`) and the R0.09 log variables, then command-line flags. `reef config show` records which layer won per key.
- **`[identity]` defaults** are `name = "reef"`, `email = "reef@<hostname>"` computed at load; the effective value is what `config show` prints. `operation.hostname` is the machine hostname and `operation.username` the OS user, not configurable in Phase 1.
- **Durations in config are `std::time::Duration`** everywhere in Rust; the TOML form is humantime's.
- **`workspace.root` is a template** containing the literal `<repo-id>`; `Config::workspace_root(repo_id)` substitutes it. The default is `<state>/repos/<repo-id>/ws`.
- **Validation** on load: `lease.default <= lease.max`, `lease.tick < lease.grace`, `watcher.debounce < watcher.fallback_interval`, `base_cache.max_entries >= 1`, `snapshot.max_new_file_size` parses; a violation is `ConfigError::Invalid { key, reason }`.
- **`reef config show`** is added to the existing `reef` binary with clap now; R1.22 restructures the CLI around it. It does not need the daemon: it resolves configuration the same way the daemon does and prints it.

## Deliverables

### `crates/reef-daemon/src/config.rs` (extends R1.03)

```rust
#[derive(Clone, Debug, Deserialize, Serialize)]
#[serde(deny_unknown_fields, default)]
pub struct FileConfig {
    pub daemon: DaemonSection, pub identity: IdentitySection, pub log: LogSection,
    pub lease: LeaseSection, pub watcher: WatcherSection, pub workspace: WorkspaceSection,
    pub base_cache: BaseCacheSection, pub gc: GcSection, pub backup: BackupSection, pub snapshot: SnapshotSection,
}
pub struct DaemonSection { pub socket: Option<PathBuf>, pub pid_file: Option<PathBuf> }
pub struct IdentitySection { pub name: String, pub email: Option<String> }
pub struct LogSection { pub keep_days: u32 }
pub struct LeaseSection { #[serde(with = "humantime_serde")] pub default: Duration, pub max: Duration, pub grace: Duration, pub restart_grace: Duration, pub heartbeat: Duration, pub tick: Duration }
pub struct WatcherSection { pub backend: WatcherBackend /* Auto | Notify | Watchman */, pub debounce: Duration, pub min_interval: Duration, pub fallback_interval: Duration, pub max_concurrent_scans: Option<usize>, pub watchman_threshold_files: u64 }
pub struct WorkspaceSection { pub backend: BackendChoiceConfig /* "auto" or a BackendKind */, pub root: String, pub fuse_overlayfs: String /* "fuse-overlayfs" */, pub overlay_nosuid: bool }
pub struct BaseCacheSection { pub max_entries: usize }
pub struct GcSection { pub undo_window: Duration, pub git_executable: String /* "git" */, pub reindex_limit: u64 /* 100000 */ }
pub struct BackupSection { pub retention: Duration, pub quiesce_max: Duration /* 60s */, pub sqlite_pages_per_step: u32 /* 256 */ }
pub struct SnapshotSection { pub max_new_file_size: ByteSize }

/// Fully resolved, validated configuration.
pub struct Config { pub paths: Paths, pub file: FileConfig, pub identity: Identity /* effective */, pub operation: OperationIdentity { hostname, username }, pub log: LogOptions, pub sources: BTreeMap<String, Source> }
pub enum Source { Default, File, Env, Flag }
impl Config {
    pub fn load(overrides: &PathOverrides) -> Result<Config, ConfigError>;   // the one entry point; R1.03's Daemon::start takes a Config built here
    pub fn workspace_root(&self, repo: RepoId) -> PathBuf;
    pub fn jj_settings(&self) -> Result<UserSettings, SettingsError>;
    pub fn to_effective_toml(&self) -> String;   // what `reef config show` prints, with `# source:` comments
}
```

`ConfigError` gains `Parse { path, #[source] toml::de::Error }`, `Invalid { key: String, reason: String }`, `UnknownKey` (from toml's error text, re-wrapped so the message names the file).

### `crates/reef-vcs/src/main.rs` and `crates/reef-vcs/src/cli/config.rs`

clap `Cli { #[command(subcommand)] command: Command }` with `Command::Config(ConfigArgs { #[command(subcommand)] Show })` plus global `--state-dir`, `--socket`, `--config` flags (the same `PathOverrides`). `reef config show` prints `Config::to_effective_toml()`; `-o json` prints the `FileConfig` as JSON with a `sources` object. The unknown-key and validation errors exit 2 (`InvalidArgument`).

### `crates/reef-daemon/src/main.rs`

Uses `Config::load` instead of R1.03's minimal construction. The `log` section feeds `LogOptions.keep_days`.

### `docs/adr/0013-daemon-state-directory-and-configuration.md`

Status `accepted`. Context: one daemon per machine, many repositories, agents that never read config, backups that copy the layout. Decision: the layout, the file, the precedence, the three environment overrides, the identity rules, jj's user config never read. Consequences: everything the daemon owns is under one directory (backup copies it; `rm -rf` resets it); the socket path length limit applies to the state dir path; a new section is a schema change reviewed like an API. Alternatives: reading jj's config (couples Reef to jj's user identity and ignore rules); generic env mapping (undiscoverable; rejected); per-repository config in `.jj` (the repository is not Reef's).

### Tests (`crates/reef-daemon/src/config.rs` unit tests, `crates/reef-vcs/tests/config_show.rs`)

1. Defaults load with no file; every default matches the README table (assert each value).
2. A file overriding `lease.default = "2h"` wins over the default and `sources["lease.default"] == File`.
3. `REEF_SOCKET` wins over `daemon.socket` in the file; `sources` says `Env`.
4. Unknown key `leas.default` → `ConfigError::UnknownKey` naming the key and file.
5. `lease.default = "2d"` with `max = "24h"` → `Invalid { key: "lease.default" }`.
6. `workspace_root` substitutes `<repo-id>`.
7. `jj_settings()` sets `operation.hostname` to the real hostname (read back with `settings.operation_hostname()`).
8. `reef config show` prints TOML that `toml::from_str::<FileConfig>` accepts (round trip) and contains `# source: default` lines; `-o json` parses.

## Implementation notes

- Keep `Paths::resolve` (R1.03) and let `Config::load` call it, then read the file at `paths.config_file`.
- `toml` 1.x emits errors with spans; keep the span text in the message, it is what makes a typo findable.
- The default `identity.email` uses the full hostname, lowercase, not just the first label.
- `to_effective_toml` is hand-written per section (the `toml` serializer cannot emit comments); a test keeps it in sync by round-tripping.

## Out of scope

- Reloading configuration without a restart.
- Per-repository configuration beyond `reef.toml` (R1.19).
- `reef daemon start|stop|status` and the rest of the CLI (R1.22).
- Any remote listener settings (R2.08).

## Risks

- `etcetera`'s macOS behavior (XDG by default) differs from the README's `~/Library/Application Support`; the brief uses the Apple strategy explicitly on macOS. If that type is not exported, build the path from `$HOME` directly.
- `humantime-serde` rejects `"1.5h"`-style fractions in some versions; document integer units.
