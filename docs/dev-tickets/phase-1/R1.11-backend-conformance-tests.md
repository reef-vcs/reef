# R1.11 Backend conformance tests

Phase 1 · Size M · Depends on: R1.07 (the first backend to run it against; R1.02 for the trait and base cache, R1.01 for `create_workspace`) · Unblocks: R1.06 (adds its `swap_base` case to this suite), R1.12 (benchmarks reuse the fixture), and every backend (R1.07, R1.08, R1.09, R1.10) must pass it before it is selectable under `auto`

## Context

Four backends on two operating systems implement one trait, and the daemon treats them interchangeably: it seeds jj's `tree_state` from the base and expects the first snapshot to be a no-op, it expects `swap_base` to leave the workspace in one of exactly two states, it expects `tear_down` to make the directory vanish, and it expects the base cache entry to stay byte-identical whatever an agent does in a workspace. None of that is checked by the backends' own unit tests. This ticket is the single suite each backend runs, so that a backend-specific bug (a clone that does not preserve mtimes, an overlay that leaks a whiteout into the lower, a copy that follows symlinks) is caught by the same assertion on every platform.

The suite is generic over `&dyn Backend`. One `#[test]` per `BackendKind` probes availability and runs the suite or skips with a visible message; the privileged kinds are gated as R1.09 describes.

### What was verified while writing this ticket

- jj's `tree_state` keys on mtime and size (`FileState { file_type, mtime: MillisSinceEpoch, size, .. }` in jj-lib 0.46.0 `local_working_copy.rs`), so "the first snapshot after materialization is a no-op" holds exactly when every regular file in the workspace has the base's mtime (to the millisecond) and size. A snapshot with the seeded state reports `changed == false` and `SnapshotStats`-level scan time proportional to a stat walk, not a read.
- APFS (the authoring machine) is case-insensitive by default and `tempfile::tempdir()` lands on it; ext4 on CI is case-sensitive. The suite detects case sensitivity by creating `A` and checking whether `a` exists, and skips the case test with a message rather than asserting either way.
- Directory `clonefile` and overlay mounts preserve mtimes by construction; `std::fs::copy` and `reflink_copy::reflink` do not, and R1.07's `copy_tree` restores them. The suite is what proves each path did.
- The synthetic generator (`reef_testing::synth`, `small` preset: 1,000 text files, 3 binaries of 8 MiB, 10 symlinks, one ignored `target/`, executables at `executable_fraction`) already contains every file kind the suite needs; `synth::mutate` modifies, adds, and deletes files in place, so "modify the workspace" is one call.

## Decisions

- **Location**: `crates/reef-daemon/tests/backend_conformance.rs` (one integration test binary) with the suite in `crates/reef-daemon/tests/common/backends.rs` next to R1.03's `common/mod.rs`. Fixture building (synthetic tree, jj repository, base cache entry in a temp state directory) is `common::backends::BaseFixture`, also used by R1.12 and R1.06.
- **One suite function**, `run_conformance(backend: &dyn Backend, fx: &BaseFixture, opts: SuiteOptions) -> ConformanceReport`, which runs every case in order, collects failures, and panics at the end with all of them, so one run shows everything that is wrong with a backend. Cases that cannot run (case-insensitive filesystem, missing privilege) are reported as skipped with a reason, not as passes.
- **One `#[test]` per kind**: `conformance_copy`, `conformance_apfs` (`cfg(target_os = "macos")`), `conformance_reflink` (Linux, gated on `REEF_TEST_REFLINK_DIR`), `conformance_fuse_overlayfs` (Linux, probe), `conformance_overlayfs` (Linux, `feature = "privileged-tests"`, probe). A test whose probe says unavailable prints `skipped: <kind>: <reason>` and returns; `conformance_copy` never skips.
- **The suite asserts the daemon-facing contract, not the mechanism**: it does not look at upper directories or clone block sharing. Mechanism tests belong to each backend. The one exception is base immutability, which every mechanism must guarantee.
- **The "first snapshot is a no-op" case goes through jj** the way R1.05's create flow does: `fx.repo.lock().create_workspace(name, ws.root, ws.state_dir, StartPoint::Edit(fx.commit), ..)` (R1.01, which writes `checkout` and an empty `tree_state` through `LocalWorkingCopy::init`), then copy `fx.base.tree_state_file()` over `ws.state_dir/tree_state` (the seeding), then `snapshot()` on the returned `Repo` and assert `changed == false`. Opening the seeded state with `Repo::open_workspace` alone would fail: the seed has `tree_state` but no `checkout`.
- **Timing is recorded, not asserted**: `materialize` and `tear_down` wall times and the free-space delta are printed per kind as a Markdown row (`| kind | preset | files | materialize ms | free delta MiB | tear_down ms |`) so a PR can paste them. R1.12 is where numbers are compared.
- **Large files**: the `small` preset's 8 MiB binaries exceed jj's default 1 MiB `max_new_file_size`, which is irrelevant to the backend but means the fixture repository is created with `user_settings_with_max_new_file_size(.., 16 MiB)` as the benchmarks do, so they are tracked and part of the base.

## Deliverables

### `crates/reef-daemon/tests/common/backends.rs`

```rust
/// A synthetic tree, a jj repository around it, and a base cache entry for its
/// first commit, in a temporary state directory.
pub struct BaseFixture {
    pub state: tempfile::TempDir,       // short name (`reef-XXXX`) so socket paths fit later
    pub repo_root: PathBuf,
    pub repo: std::sync::Mutex<reef_lib::jj::Repo>,   // case 5 calls R1.01's `create_workspace` on it; Mutex because `Repo` is not `Sync` and the fixture is a `OnceLock`
    pub repo_id: RepoId,
    pub base: BaseEntry,
    pub commit: CommitIdHex,
    pub manifest: reef_testing::synth::Manifest,
}

impl BaseFixture {
    pub fn small() -> Self;                           // Preset::Small, seed 42
    pub fn with_spec(spec: &Spec, seed: u64) -> Self;
    pub fn workspace_paths(&self, id: &WorkspaceId) -> WorkspacePaths;   // under <state>/repos/<repo-id>/ws/
    pub fn second_commit(&self, ops: MutateOps) -> (CommitIdHex, BaseEntry);  // mutate in the repo root, snapshot, ensure a second base
}

pub struct SuiteOptions { pub skip_case_sensitivity: bool, pub label: &'static str }
pub struct ConformanceReport { pub passed: Vec<&'static str>, pub skipped: Vec<(&'static str, String)>, pub failed: Vec<(&'static str, String)>, pub timings: Timings }

pub fn run_conformance(backend: &dyn Backend, fx: &BaseFixture, opts: SuiteOptions) -> ConformanceReport;
```

Cases, each a function `fn case_<name>(backend, fx, ws) -> Result<(), String>` run in this order with a fresh `WorkspaceId` each (except where noted):

1. `materialize`: after `materialize`, every path in the manifest (text files, binaries, symlink targets, `.gitignore`) exists under the root; `walkdir` of the root and of the base yield the same relative paths and file types.
2. `mtime_and_size_preserved`: for every regular file, `modified()` truncated to milliseconds and `len()` equal the base's; for every executable in the manifest, the mode has `0o100`.
3. `symlinks`: each manifest symlink is a symlink with the same target; a dangling symlink added to the base fixture (`BaseFixture` adds `dangling -> missing-target` before building the base) is a symlink in the workspace.
4. `empty_directory`: an empty directory in the base (the fixture adds `empty/`) exists in the workspace.
5. `first_snapshot_is_noop`: see Decisions.
6. `modify_is_private`: `synth::mutate(root, 1, modify 50, add 10, delete 10)` in the workspace; the base's files are byte-identical to before (compare a SHA-256 over the base tree computed before and after, excluding nothing) and the base's `.state/` directory is unchanged.
7. `disk_usage_tracks_changes`: fresh workspace `disk_usage().files_changed == 0`; after case 6's mutation, `files_changed >= 60` (50 modified + 10 added; deletes may or may not count) and `allocated_bytes` is at least the bytes of the added files; after appending 4 MiB to one binary, `allocated_bytes` grows by at least 4 MiB.
8. `large_file_modify`: append 1 byte to an 8 MiB binary; the workspace file is 8 MiB + 1, the base file is 8 MiB.
9. `swap_base`: build a second base with `fx.second_commit(modify 20, add 5, delete 5)`; on a fresh workspace, `swap_base(from, to)`; on `TreeReplaced`, the root now matches the second base exactly (paths, sizes, mtimes) and a file written before the swap is gone; on `NeedsCheckout`, the root still matches the first base and the written file is still there (the daemon's checkout is not the backend's job). Both outcomes are legal; the case asserts the outcome's promise.
10. `tear_down`: after `tear_down`, the root does not exist, no `.trash-*` or `.upper`/`.work` sibling for that id remains once the background deletion is awaited (`fs_util` test hook, or poll up to 30 s), and the base is still byte-identical.
11. `tear_down_twice_is_not_found`: a second `tear_down` on the same paths returns `BackendError::RootMissing` (`NotFound`, R1.02), not a panic.
12. `case_sensitivity` (skipped unless the state directory is case-sensitive): add `A.txt` and `a.txt` with different contents to a second fixture base; both materialize with their contents.
13. `base_immutable_after_all`: the SHA-256 of the base tree equals the value taken before case 1.
14. `materialize_into_existing_fails`: `materialize` into a root that already contains a file returns `AlreadyExists` and does not touch the file.

Timing: cases 1 and 10 record wall time; `fs_util::free_bytes` is sampled before 1 and after 1 for the delta.

## Implementation notes

- The tree digest for base immutability: walk sorted by path, hash `path\0type\0size\0mtime_ms\0` plus file content for regular files and the target for symlinks. Directory mtimes are excluded (backends do not preserve them).
- `BaseFixture` builds the repository with `reef_lib::jj::Repo::init_internal_git` and one snapshot (as `crates/reef-lib/benches/common/mod.rs` does), then calls R1.02's `BaseCache::ensure`. Building the `small` fixture is about one second; build once per test binary with `OnceLock` and give each backend test its own workspace ids under the shared state directory. The overlay tests mount under that directory, so it must not be on tmpfs with `noexec` restrictions that break FUSE; a plain `tempfile::tempdir()` under `/tmp` is fine on CI.
- The overlay kinds need `WorkspacePaths` with `upper` and `work` siblings; `fx.workspace_paths(id)` returns them for every kind so the suite is kind-agnostic.
- Case 10's wait for background deletion: expose `fs_util::drain_background_deletions()` for tests (a `tokio` `JoinSet` or a counter the test polls).
- Run the suite's cases in a `tokio` current-thread runtime when a case needs `remove_tree_async`; the backends' `tear_down` falls back to inline deletion without a runtime (R1.07), so either works.

## Acceptance criteria

- [ ] `cargo nextest run -p reef-daemon --test backend_conformance` passes on macOS (`copy`, `apfs`) and on Linux (`copy`, plus `fuse_overlayfs` where available) in the default CI matrix; `overlayfs` and `reflink` pass in the privileged job once R1.09 and R1.10 land.
- [ ] A deliberately broken backend (a test-only `BrokenCopy` that skips mtime restoration, kept under `#[cfg(test)]` in `common/backends.rs`) fails cases 2 and 5 and no others, proving the suite's sensitivity.
- [ ] Every skipped case prints `skipped: <case>: <reason>`; every backend test that cannot run prints `skipped: <kind>: <reason>`.
- [ ] The timing row is printed for every kind that ran.
- [ ] `just ci` passes.

## Out of scope

- Mechanism-level assertions (block sharing, upper-layer contents, clone syscalls): each backend's own tests.
- Benchmarks and the phase targets (R1.12).
- The daemon's create flow (R1.05) and the move flow (R1.06); R1.06 adds its per-backend `Move` case to this suite when it lands.
- Windows.

## Risks

- Millisecond truncation can hide a backend that preserves mtimes only to the second; the suite compares milliseconds, which is what jj compares, so a backend that passes is good enough for jj.
- A case-insensitive state directory on macOS skips case 12, so a backend bug in case handling would surface only on Linux CI. Acceptable: APFS clones and copies do not rename paths.
