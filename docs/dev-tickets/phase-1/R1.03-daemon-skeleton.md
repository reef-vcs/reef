# R1.03 Daemon skeleton over a Unix socket

Phase 1 · Size M · Depends on: R1.01 (`Db`, migrations, `RepoId`, `RepositoryRecord`), R0.09 · Unblocks: R1.04 (config file), R1.05 (services), every integration test in the phase (`TestDaemon`)

## Context

Design principle 8 and ADR 0004: agents talk to a local daemon over gRPC on a Unix socket, and the CLI is a thin client. `reef-daemon` today is `main.rs` that initializes logging and exits. This ticket makes it a long-running service with one RPC (`Daemon.Status`), the process plumbing a daemon needs (single-instance lock, pid file, log file, graceful shutdown), the threading model ADR 0008 demands for jj-lib, the protobuf build pipeline every later service uses, and an in-process start API so tests do not spawn binaries.

### What was verified while writing this ticket

- tonic 0.14.6 (MIT): `Server::add_service(&mut self, svc) -> Router<L>` (feature `router`), `Router::serve_with_incoming_shutdown(self, incoming, signal)` where `incoming: Stream<Item = Result<IO, IE>>`, `IO: AsyncRead + AsyncWrite + Connected + Unpin + Send + 'static`. tonic implements `Connected` for `tokio::net::UnixStream` on unix (connect info `UdsConnectInfo`); the crate's `examples/src/uds` is the reference. `tokio_stream::wrappers::UnixListenerStream` (tokio-stream 0.1.19) wraps `UnixListener` into that stream.
- Client side: `Endpoint::connect_with_connector(connector)` where `connector: tower::Service<Uri>` whose response implements `hyper::rt::io::{Read, Write}`; a tokio `UnixStream` needs `hyper_util::rt::TokioIo` (hyper-util 0.1.21). `Endpoint::try_from("http://[::]:0")` is the dummy URI; the connector ignores it.
- tonic-prost-build 0.14.6: `Builder::compile_fds(self, fds: FileDescriptorSet) -> io::Result<()>`, `build_server(bool)`, `build_client(bool)`, `file_descriptor_set_path`. protox 0.10.0: `protox::compile(files, includes) -> Result<FileDescriptorSet, protox::Error>`, pure Rust, no `protoc`. The `FileDescriptorSet` type is `prost_types::FileDescriptorSet` (prost-types 0.14 must match prost 0.14; add it as a build-dependency).
- `tonic::Status::with_details(code, message, details: Bytes)` and `Status::details(&self) -> &[u8]` (used by R1.05).
- fd-lock 4.0.4: `RwLock::new(File)`, `try_write()` returns `WouldBlock` when another process holds it. tracing-appender 0.2.5: `rolling::daily(dir, prefix)` and `non_blocking(writer) -> (NonBlocking, WorkerGuard)`; the guard must live as long as the daemon.
- jj-lib 0.46.0: `ReadonlyRepo { loader: RepoLoader, operation: Operation, index: Box<dyn ReadonlyIndex>, change_id_index: once_cell::sync::OnceCell<Box<dyn ChangeIdIndex>>, view: View }` with `ReadonlyIndex: Any + Send + Sync`, `ChangeIdIndex: Send + Sync`, `OpStore: Any + Send + Sync`, `Store { backend: Box<dyn Backend>, .., caches in Mutex }`. Every field is `Send + Sync` at the type level, so `Arc<ReadonlyRepo>: Send + Sync` holds; the static assertion below makes it a compile error if a bump changes that. `MergedTree { Arc<Store>, Merge<TreeId>, ConflictLabels }` is likewise `Send + Sync`. `Workspace` (holding `Box<dyn WorkingCopy>`) is `Send` but not `Sync` (ADR 0008).

## Decisions

- **Process model as the README fixes it**: tokio multi-thread runtime; one repository thread per registered repository; workspace work on `spawn_blocking` with `pollster::block_on`; ids and `Arc<ReadonlyRepo>` cross threads; `fd-lock` single instance; SIGTERM/SIGINT graceful shutdown with a 5 s budget for in-flight RPCs.
- **Binary interface**: `reef-daemon [--state-dir DIR] [--socket PATH] [--config FILE] [--foreground]`. `--foreground` is the default and the only mode in this ticket; detaching is `reef daemon start`'s job (R1.22) and done by spawning, not by forking inside the daemon.
- **`Config` is introduced here minimally** (`state_dir`, `socket`, `log`), resolved by `reef_daemon::config::Paths::resolve(overrides)` from `REEF_STATE_DIR`, `REEF_SOCKET`, and the platform defaults in the README. R1.04 adds the TOML file and every other section without changing these fields.
- **Logs**: stderr as R0.09 configured, plus `<state>/logs/daemon.log` as daily-rotated JSON through `tracing-appender`; both layers share one `EnvFilter`. `logging::init` grows a `file: Option<PathBuf>` option and returns the `WorkerGuard` inside a `LoggingGuard` the daemon holds until exit.
- **The proto pipeline**: `crates/reef-daemon/proto/reef/daemon/v0/daemon.proto`, compiled by `build.rs` with `protox` into `OUT_DIR`, included by `src/proto.rs` as `pub mod reef { pub mod daemon { pub mod v0 { tonic::include_proto!("reef.daemon.v0"); } } }` and re-exported as `reef_daemon::proto::v0`. Generated code is not committed. `cargo doc` must stay warning-free: add `#![allow(missing_docs, clippy::pedantic, ...)]` with a reason on the generated module only.
- **`Daemon.Status`** returns version, pid, uptime, state directory, socket path, schema version, registered repository count, and (from R1.02) backend probes.
- **The in-process API** `Daemon::start(config) -> Result<DaemonHandle, StartError>` runs the same code path as `main`, on the caller's runtime (tests use `#[tokio::test(flavor = "multi_thread")]`). `DaemonHandle { socket_path(), shutdown() -> impl Future, join() }`.
- **Repository threads are started by `RepoRegistry`** (`reef_daemon::repo::RepoRegistry`), which this ticket creates with `open(record) -> RepoHandle` and `close(id)`; R1.05 fills in registration. A `RepoHandle` runs `call(|head: &mut RepoHead| -> T) -> impl Future<Output = Result<T, RepoThreadError>>` by sending a boxed job and awaiting a oneshot. The thread reloads at head after any job that reports it committed an operation (`RepoHead::note_committed(new_repo)`).
- **Start sequence**: open the database and apply migrations → sweep leftovers (`*.trash-*` under `repos/*/ws/`, `*.tmp` and `*.gc` under `repos/*/bases/`; the sweep functions arrive with R1.07, R1.02, and R1.17 and are no-ops until then) → reconcile overlay mounts (R1.09, no-op until then) → start one repository thread per registered repository → load active workspaces (R1.05) → apply the lease restart grace (R1.15) → bind the socket. The order is a documented list in `daemon.rs` that later tickets extend in place.
- **Repository thread jobs** are `Box<dyn FnOnce(&mut RepoHead) + Send>` with a oneshot reply, plus two control messages this ticket implements for R1.18: `Pause(oneshot::Receiver<()>)` blocks the thread until the sender resumes it (with a deadline the caller sets), and `Shutdown`. After every job that committed a transaction the thread reloads at head.
- **Binary entry**: `reef_daemon::run_main(args: DaemonArgs) -> anyhow::Result<()>` is the whole of `main.rs`'s body so `reef daemon run` (R1.22) can call it in-process. `StatusResponse` carries `repositories` and `active_workspaces` counts (the latter 0 until R1.05).
- **Client wrapper**: `reef_daemon::client::Client::connect(socket) -> Result<Client, ClientError>` holding a `Channel`; `status()` here, one method per RPC in later tickets. The CLI and tests only use `Client`, never the generated clients directly.

### `crates/reef-daemon/src/repo/mod.rs` and `repo/thread.rs`

```rust
pub struct RepoHead { pub id: RepoId, pub root: PathBuf, pub colocated: bool, pub settings: UserSettings, pub repo: reef_lib::jj::Repo /* the user's default workspace, loaded at head */ }
impl RepoHead { pub fn readonly(&self) -> Arc<ReadonlyRepo>; pub async fn reload(&mut self) -> Result<(), OpenError>; }

pub struct RepoHandle { id: RepoId, tx: std::sync::mpsc::Sender<Job> }
type Job = Box<dyn FnOnce(&mut RepoHead) + Send>;
impl RepoHandle {
    pub fn call<T: Send + 'static>(&self, f: impl FnOnce(&mut RepoHead) -> T + Send + 'static) -> impl Future<Output = Result<T, RepoThreadError>>;
    pub fn call_async<T, F>(&self, f: F) -> ...;  // f returns a non-Send future; the thread drives it with pollster::block_on
}
pub struct RepoRegistry { handles: Mutex<HashMap<RepoId, RepoHandle>> }
impl RepoRegistry { pub fn open(&self, record: &RepositoryRecord, settings: UserSettings) -> Result<RepoHandle, OpenError>; pub fn get(&self, id: RepoId) -> Option<RepoHandle>; pub fn close(&self, id: RepoId); pub fn close_all(&self); }
```

The thread loop: `for job in rx { job(&mut head) }`; after each job, if `head.dirty` (set by `note_committed`), `reload` at head. `close` drops the sender, the loop ends, the thread is joined on `close_all` (shutdown).

Static assertions in `repo/mod.rs`:

```rust
const _: () = { fn assert_send_sync<T: Send + Sync>() {} fn _check() { assert_send_sync::<Arc<jj_lib::repo::ReadonlyRepo>>(); assert_send_sync::<jj_lib::merged_tree::MergedTree>(); } };
```

`reef-daemon` needs `jj-lib` as a direct dependency for these type names only; add it with a comment, or re-export the two types from `reef_lib::jj` and avoid the direct dependency (preferred).

### `crates/reef-daemon/src/server.rs`, `daemon.rs`, `service/daemon.rs`

```rust
pub struct Daemon;   // in daemon.rs
impl Daemon { pub async fn start(config: Config) -> Result<DaemonHandle, StartError>; }
pub struct DaemonHandle { .. }
impl DaemonHandle { pub fn socket_path(&self) -> &Path; pub fn shutdown(&self); pub async fn join(self) -> Result<(), StartError>; }

pub struct AppState { pub config: Config, pub db: Arc<Db>, pub repos: Arc<RepoRegistry>, pub started: Instant, pub shutdown: CancellationToken /* tokio-util */ }
```

`start`: resolve paths, create the state dir `0700`, acquire the lock, open the db, write the pid file, remove a stale socket file (only after the lock is held), bind the listener, `chmod 0600` the socket, spawn the server task with `serve_with_incoming_shutdown(stream, shutdown.cancelled())`, log `daemon started` with `socket`, `state_dir`, `pid`. `shutdown`: cancel the token; the server stops accepting; in-flight RPCs get 5 s (`tokio::time::timeout` around the server future's completion); then `repos.close_all()`, remove the socket and pid files, release the lock. R1.13 and R1.15 hook their final snapshots into a `ShutdownHooks` list that `shutdown` runs after the server stops.

`service/daemon.rs`: `DaemonService` implementing the generated `daemon_server::Daemon` trait for `Status`.

### `crates/reef-daemon/tests/daemon.rs`

1. `status_answers_over_socket`: version equals `CARGO_PKG_VERSION`, pid equals `std::process::id()`, uptime grows.
2. `second_instance_is_refused`: `Daemon::start` twice on one state dir → `StartError::Lock(Held { pid })`.
3. `stale_socket_is_replaced`: create a stray file at the socket path; start succeeds.
4. `shutdown_removes_socket_and_pid`: after `stop`, neither file exists; the lock file remains.
5. `socket_mode_is_0600` and `state_dir_mode_is_0700`.
6. `log_file_is_json_lines`: `logs/daemon.log*` first line parses as JSON with `message == "daemon started"`.
7. `binary_runs_and_stops_on_sigterm`: spawn `env!("CARGO_BIN_EXE_reef-daemon")` with `REEF_STATE_DIR`, wait for the socket, `Client::status`, send SIGTERM (`nix::sys::signal::kill` or `libc::kill`), exit status 0 within 10 s.
8. `repo_thread_runs_jobs_in_order_and_reloads`: register a synthetic repo through `RepoRegistry::open` directly, `call` two jobs, the second sees the first's op id after `note_committed`.
9. `socket_path_too_long_fails_early`: `REEF_SOCKET` of 120 characters → `ConfigError::SocketPathTooLong`.

### `docs/adr/0012-daemon-process-model-and-threading.md`

Status `accepted`. Context: jj-lib futures are not `Send` and do blocking I/O (ADR 0008); hundreds of workspaces; one SQLite writer. Decision: the threading model above, the single-instance lock, graceful shutdown, in-process start for tests. Consequences: every jj mutation is serialized per repository, which is the write lock R1.18 quiesces; scans parallelize across workspaces; a slow transaction delays every snapshot of that repository (measured by R1.23). Alternatives: one thread per workspace holding its own loaded repo (N loaded indexes); running jj-lib on tokio with `spawn_local` (one local set per thread anyway); a process per repository (no shared SQLite, more sockets).

## Implementation notes

- tonic's `Router` is generic over the layer; keep the server function non-generic by building the router inside `start`.
- `Connected for UnixStream` is behind no feature in tonic 0.14, but the `transport` default feature must stay on.
- `serve_with_incoming_shutdown` ends when the signal future resolves; in-flight connections are drained by hyper's graceful shutdown. The 5 s budget wraps the join.
- `spawn_blocking` threads default to 512; that is also the cap for concurrent scans before the semaphore; R1.13 sets the semaphore.
- `tokio-util` is needed for `CancellationToken`; add it (0.7) to the workspace.
- Test 7 needs `nix` or `libc` as a dev-dependency; use `nix` (R1.09 and R1.21 add it as a regular dependency later) with feature `signal`.

## Out of scope

- Any service beyond `Daemon.Status` (R1.05, R1.15, R1.17, R1.18).
- The config file and the full `Config` (R1.04); repository registration (R1.05).
- Detaching, `reef daemon start|stop` (R1.22).
- TLS or TCP listeners (R2.08).

## Risks

- `compile_fds` output may lack the file descriptor set that `tonic-reflection` would want later; not needed in Phase 1.
- If `tonic` 0.14's `Connected` impl for `UnixStream` is gated differently than remembered, implement `Connected` on a newtype wrapper around `UnixStream` that forwards `AsyncRead`/`AsyncWrite`.
- `tracing-appender`'s non-blocking writer drops lines when its buffer is full under load; acceptable for the daemon log, documented in `logging.rs`.
