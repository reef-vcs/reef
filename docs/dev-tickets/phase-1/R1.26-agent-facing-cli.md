# R1.26 Agent-facing CLI contract: guide, hints, and `reef here`

Phase 1 · Size M · Depends on: R1.22 (the CLI, `CliError`, `Out`), R1.21 (`ws run`'s environment), R1.05 (`ErrorDetail`) · Unblocks: R1.27 (renders the same guide into harness files), R1.24 (the quickstart points agents at `reef guide`), R2.13 (MCP tool descriptions reuse the guide and the hint fields), RX.07

## Context

Design principle 8 says no agent should regex a log. R1.22 delivered half of that: JSON on a pipe, exit codes by `ErrorKind`, and `{"error": {"kind", "message"}}`. The other half is that an agent which has never heard of Reef must be able to learn it from the tool, because no model's training data contains Reef yet and no human will be in the loop to explain it. Today an agent that runs `reef` gets clap's usage text, an agent that fails gets a message with no fix in it, and an agent inside a workspace has no one-call way to learn where it is and what it may do.

This ticket writes down the contract the CLI makes with an agent, implements its Phase 1 surface, and tests it so it cannot regress silently. The three visible pieces are `reef guide` (and `reef` with no arguments), `hint` and `next` on every error that has a known fix, and `reef here`.

### What was verified while writing this ticket

- `Out::error_object` emits `{"error": {"kind", "message"}}` (`crates/reef-vcs/src/cli/out.rs:185`); `CliError` variants carry a kind and a message only (`cli/error.rs`). The daemon's `ErrorDetail` is `kind` and `chain` (`proto/reef/daemon/v0/error.proto:7`). R1.20 already puts a fix into a message ("Unavailable with the `reef store build` hint"), as text an agent would have to parse.
- The CLI reads stdin nowhere but `ws run`'s terminal check (`cli/ws_run.rs:388`; `autostart.rs:146` gives the daemon `Stdio::null()`), and opens no editor or pager. The non-interactive rule below is a guarantee of what exists, plus a test so it stays true.
- `clap_builder` 4.6.7 (the locked version) has `Command::infer_subcommands` (`builder/command.rs:1840`) and `visible_alias`; clap's `suggestions` feature, on by default, prints "a similar subcommand exists" for near misses (clap documentation, not re-measured).
- `ws run` exports `REEF_WORKSPACE`, `REEF_WORKSPACE_PATH`, `REEF_REPO`, `REEF_SOCKET` (`cli/env.rs:10`), so a process inside a workspace can name it without guessing from the path.
- `Workspace` carries id, change id, path, state, divergent, attention, lease (with computed state), last snapshot time and op, local snapshot count, and mounted stores (`types.proto:56` to `:93`): everything `reef here` prints, with no new RPC.
- `resolve_workspace` accepts an id or unique prefix only (`workspace/manager.rs:336`); `resolve_repo` already accepts an absolute path (`:313`). `here` from a shell that `cd`'d into a workspace without `ws run` needs the path form, added below.
- The crate has no tokenizer and should not grow one for a size test; four bytes per token is the usual estimate for English and shell text, so the guide's budget is written in bytes.

## Decisions

- **The contract, recorded as ADR 0025 "Agent-facing CLI contract"**, in five rules the rest of the CLI (and R2.05's rewrite) must keep:
  1. *Never interactive.* No prompt, pager, editor, or confirmation dialog; confirmation is a flag; stdin is read only by `ws run`'s child. Every command must complete with stdin closed.
  2. *Every error carries its fix when one is known.* JSON errors have `kind`, `message`, and optionally `hint` (one sentence) and `next` (an argv array an agent can run verbatim, no shell syntax). Text mode prints `hint: ...` and `next: reef ...` on stderr after `error:`.
  3. *The tool explains itself in-band.* `reef` with no arguments and `reef guide` print the agent guide: the model in a paragraph, the commands that matter, the environment, output and exit-code rules. The long form fits in 1,600 bytes (about 400 tokens); `reef --help` fits in 60 lines.
  4. *One call answers "where am I".* `reef here` reports the workspace, change, lease, and the next sensible command, in 12 lines or one JSON object.
  5. *Names are additive.* Aliases and prefix inference are added, never used to rename; the names in R1.22's command surface stay valid for the life of the 0.x line.
- **`hint` and `next` plumbing.** `ErrorDetail` gains `string hint = 3; repeated string next = 4;`. The daemon sets them where the fix is known: no sealed store for a lockfile → `reef store build <name>`; repository not registered and `--no-register` in effect (R1.25) → `reef repo register <path>`; lease expired or workspace released → `reef ws create --repo <id>`; ambiguous id prefix → hint listing candidates, no `next`; `Conflict` on `ws move` → `reef ws inspect <id>`. They are attached in the one place ADR 0017 maps errors to statuses (`crates/reef-daemon/src/error.rs`), from a `fn advice(&self) -> Option<Advice>` on the service error enums, so no handler formats hints into messages anymore (R1.20's message is rewritten to use the field). The CLI adds its own: daemon unreachable with `--no-autostart` → `reef daemon start`; `ws run` with no command → the usage line; a stub (`not implemented until R1.xx`) → none. `CliError` gains `advice: Option<Advice>` on `Daemon` and `Refused`.
- **`reef guide`** prints `docs/agent-guide.md`, embedded with `include_str!` so the published document and the binary cannot drift. The file has two parts split by an HTML comment `<!-- reef:long -->`: the short form (at most 40 lines; R1.27 pastes it into `AGENTS.md`) and the long form. `reef guide` prints both; `reef guide --short` prints the first. Content, in order: what a workspace is (leased, copy-on-write, snapshotted continuously, nothing lost on release or kill); the commands an agent uses (`reef ws run -- <cmd>`, `reef here`, `reef ws create`, `reef ws list`, `reef ws release`), each with one example; the environment variables inside `ws run`; output rules (JSON when piped, `-o json` to force, one object or array per command, `error.hint` and `error.next`); exit codes; what Reef does not do yet (undo, status, diff: Phase 2; use `jj` on the registered root meanwhile). No markdown headings deeper than `##`, no tables (they tokenize badly). `reef` with no subcommand prints the guide and exits 0 instead of clap's usage error and 2; in JSON mode the object is `{"guide": "<text>", "commands": [["ws","run"], ...]}` where `commands` lists every leaf subcommand from clap's `Command` tree, so a harness can generate tool stubs from it.
- **`reef here`.** Resolves the workspace by `REEF_WORKSPACE` if set, else by the current directory: `resolve_workspace` learns to accept an absolute path, matching a workspace whose `path` is the path or an ancestor of it (`workspaces.path` is canonical; compare after `canonicalize` of the cwd). Calls `Inspect` with `snapshot_first = false` by default (`here` must be cheap and side-effect free; `--snapshot` opts in). Text output, at most 12 lines: `workspace`, `path`, `change`, `state` (with `divergent` and `attention` appended when set), `lease` (`active, 27m left, heartbeat every 60s` or `expired 3m ago`), `last snapshot` (`12s ago (op abcdef12)` or `none yet`), `stores` (names, or omitted), and `next:` with one suggestion chosen by state: active and healthy → `reef ws release <id>` when done; expired → `reef ws create --repo <repo>`; divergent → `reef ws inspect <id>`; outside any workspace → `reef ws run -- <command>` plus which registered repository (or none) contains the directory. JSON: the `Workspace` object plus `"next": [...]` and `"in_workspace": bool`. Outside a workspace `here` exits 0: not being in one is an answer, not an error.
- **Aliases and inference.** `infer_subcommands(true)` on the root and every noun; `visible_alias`: `workspace` for `ws`, `new` for `ws create`, `ls` for `list` (on `ws`, `repo`, `store`), `rm` for `ws release`, `status` is *not* aliased (R2.02 owns `reef status`). `reef guide` has alias `agent-guide`. Completions (R1.22) pick aliases up from clap.
- **Help for a model.** Each subcommand's `about` is one line; `long_about` at most five lines; one example in `after_help` for `ws run`, `ws create`, `here`, `init` (R1.27). Subcommand `display_order` puts the agent path first: `ws`, `here`, `guide`, then `repo`, `store`, `daemon`, `config`, `backup`, `restore`, `completions`.
- **`REEF_OUTPUT`** environment variable as the default for `-o` (clap `env`), so a harness that gives its agent a pty can still get JSON everywhere by setting one variable in the environment.
- **`ws list` gains `--limit N`** (default 100, newest first, `truncated: true` in the JSON array's wrapper when cut). The one list that grows unbounded in Phase 1; `repo list` and `store list` do not.

## Deliverables

### `crates/reef-daemon/proto/reef/daemon/v0/error.proto`

The two fields. `reef_daemon::error::Advice { hint: String, next: Vec<String> }`, serialized into the detail and read back by `ClientError`.

### `crates/reef-daemon/src/error.rs`, `src/service/*.rs`, `src/workspace/*.rs`

`advice()` on `ManagerError`, `StoreError`, `RegisterError`, `LeaseError`, returning the cases in Decisions; a unit test per case that the `next` argv's first two words are a real subcommand (the test calls into `reef-vcs`'s clap `Command` through a `#[doc(hidden)] pub fn command_tree()` in `reef_vcs`... the daemon cannot depend on the binary crate, so the test lives in `crates/reef-vcs/tests/cli.rs` instead and drives each error through a `TestDaemon`).

### `crates/reef-vcs/src/cli/error.rs`, `out.rs`

`Advice` on `CliError`; `Out::error` prints `hint:` and `next:` lines; `error_object` includes the fields when present.

### `docs/agent-guide.md`, `crates/reef-vcs/src/cli/guide.rs`

The guide and the command. A unit test asserts `include_str!("../../../../docs/agent-guide.md").len() <= 1600`, the short part `<= 40` lines, no line over 100 columns, and no `|` table rows.

### `crates/reef-vcs/src/cli/here.rs`, `crates/reef-daemon/src/workspace/manager.rs`

The command and the path form of `resolve_workspace` (`WorkspaceRecord` lookup by path prefix: `SELECT ... WHERE state = 'active' AND ? = path OR ? LIKE path || '/%'`, with the longest match winning).

### `crates/reef-vcs/src/cli/mod.rs`, `ws.rs`

Aliases, inference, display order, `REEF_OUTPUT`, no-argument behavior, `--limit`.

### `crates/reef-vcs/tests/cli.rs`

- `no_args_prints_guide_and_exits_zero`; `guide_json_lists_every_leaf_command` (walks clap's tree and compares).
- `help_fits_sixty_lines` for `reef --help` and each noun's `--help`.
- `every_command_completes_with_stdin_closed`: every leaf subcommand run with `Stdio::null()` stdin and bogus arguments exits within 5 s with a non-hanging status (any code), including `ws run -- true`.
- `missing_store_error_carries_next`: a repository whose `reef.toml` declares a store with no build; `ws create -o json` exits 6 with `error.next == ["reef","store","build","<name>"]`; text mode stderr has `next: reef store build <name>`.
- `every_next_is_a_real_command`: drives each `advice()` case and checks `next[0..2]` against the clap tree.
- `here_inside_ws_run`: `ws run -- reef here -o json` reports `in_workspace: true` and the right id; `here_by_path`: `cd` into the workspace path without the env, same answer; `here_outside`: exit 0, `in_workspace: false`, `next` starts `["reef","ws","run"]`.
- `aliases_and_prefixes_resolve`: `reef workspace ls`, `reef ws cr --help`, `reef ws new --help` all exit 0.
- `reef_output_env_forces_json` on a pty (`assert_cmd` cannot allocate one; use `script -q` on both platforms or `portable-pty` as a dev-dependency, whichever is already in the tree; otherwise the test checks precedence without a pty: `REEF_OUTPUT=text` with piped stdout yields text).
- `ws_list_limit_and_truncated`.

### `docs/adr/0025-agent-facing-cli-contract.md`

The five rules, the byte budget and why bytes, the reasons `here` exits 0 outside a workspace and takes no snapshot by default, and alternatives: a separate `reef-agent` binary (rejected: two things to discover), hints only in messages (rejected: that is the regex the principle forbids), a tokenizer dependency for the budget (rejected: build weight for a test).

## Implementation notes

- Write the guide first and read it as the model would: no prior knowledge, 400 tokens, must be able to run `ws run` correctly afterwards. Then cut it by a third.
- `next` is an argv, never a string, and never contains placeholders like `<id>`: the daemon knows the id; put it in. When it cannot (no repository), omit `next` and give a `hint`.
- The no-argument behavior needs `Cli::try_parse` with `arg_required_else_help(false)` and `subcommand_required(false)`, then an explicit branch; keep clap's exit code 2 for every other usage error so R1.22's table holds.
- `here`'s relative-time formatting reuses `render.rs`'s helpers from R1.22; do not add a crate.

## Acceptance criteria

- [ ] All tests in Deliverables pass on both platforms.
- [ ] `reef guide | wc -c` ≤ 1600 and `reef --help | wc -l` ≤ 60 on both platforms.
- [ ] `grep -rn "run \`reef\|run reef " crates/reef-daemon/src --include=*.rs` finds no hint formatted into a message string (all go through `advice()`).
- [ ] ADR 0025 written and indexed; the Phase 1 README CLI table gains the rows for guide, hints, `here`, aliases, `REEF_OUTPUT`.
- [ ] `just ci` passes.

## Verification

```sh
reef | head -5                                   # the guide, exit 0
reef guide | wc -c                               # <= 1600
reef ws run -- sh -c 'reef here; reef here -o json | jq .next'
reef ws create --repo /nonexistent -o json; echo $?   # 3, with error.hint
reef workspace ls                                 # alias works
```

## Out of scope

- `reef status`, `diff`, `log`, undo (Phase 2, R2.02 and R2.03).
- The MCP server and machine-readable schema for the API (R2.13, R2.24).
- Localization; the guide is English.
- Measuring real token counts with a tokenizer (RX.07 measures them end to end with a real model).

## Risks

- The guide is the single most-read text Reef ships to agents and will be argued over; the byte budget and the "read it as the model would" note are there so the argument has a stopping rule.
- Prefix inference makes future subcommand additions potentially ambiguous (`ws re` once `ws rename` exists); clap errors rather than guessing, and the test suite's alias cases catch a prefix that stops working.
- `hint` text that mentions a command which later changes name; `every_next_is_a_real_command` catches `next`, and a `grep` in CI over `hint` strings for `reef ` followed by an unknown subcommand is a cheap addition if it happens once.
