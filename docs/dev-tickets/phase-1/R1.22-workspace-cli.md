# R1.22 CLI for workspaces

Phase 1 · Size M · Depends on: R1.05 (services and `Client`), R1.17 (`Maintenance.Gc`), R1.04 (`reef config show` already added a subcommand to the binary), R1.06, R1.18, R1.20, R1.21 add their own subcommands to the skeleton this ticket builds · Unblocks: R1.24, R2.05 (rewrites nothing here; it removes jj-lib from the binary's reach, which this ticket already keeps to the daemon crate's client)

## Context

"API first, CLI second. A local daemon speaks a typed protocol. The CLI and an MCP server are thin clients" (design principle 8). The `reef` binary from R0.01 does nothing but log `starting`; R1.04 adds `reef config show`. This ticket turns it into the Phase 1 CLI: every workspace operation, daemon lifecycle, repository registration, and maintenance, all as calls to `reef_daemon::client::Client` over the Unix socket, with JSON when stdout is not a terminal so agents never parse text (`docs/design.md`, Technology choices: "Emits JSON by default when stdout is not a terminal").

The README fixes the command list, output modes, exit codes, prefix handling, and autostart. This ticket also owns the CLI skeleton (`Ctx`, output, exit mapping, the client trait) that R1.06, R1.18, R1.20, and R1.21 plug into; those tickets add their subcommand modules and their tests, and this brief lists their command surface so the skeleton reserves it.

### What was verified while writing this ticket

- `clap` 4 with `derive` and `env` is a workspace dependency (R0.01); `clap_complete` 4.6.11 (MIT OR Apache-2.0) generates completions for bash, zsh, fish, elvish, and PowerShell from the same `Command`.
- `assert_cmd` 2.2.2 (MIT OR Apache-2.0) runs `env!("CARGO_BIN_EXE_reef")` with `.env()` and asserts on status, stdout, and stderr; `predicates` is its companion and comes as its dependency.
- `std::io::IsTerminal` (stable since 1.70) decides the default output mode.
- `std::env::current_exe()` locates `reef-daemon` beside `reef` for autostart; `which`-style `PATH` search is a ten-line loop over `std::env::split_paths`, no crate.
- `std::os::unix::process::CommandExt::process_group(0)` plus `Stdio::null()` detaches the daemon from the CLI's terminal and process group; the daemon's own single-instance lock (R1.03) makes a race between two autostarting CLIs harmless (one exits 1, the other wins, both then connect).

## Decisions

- **Command surface, final for Phase 1** (owner in brackets):

  ```text
  reef daemon run [--foreground is implied]           [R1.22]  run the daemon in this process (exec reef-daemon)
  reef daemon start | stop | status                   [R1.22]
  reef config show                                    [R1.04]
  reef repo register [PATH] | list | forget <REPO>    [R1.22]
  reef ws create [--repo R] [--change C | --new-on REV] [--purpose P] [--owner O] [--lease D] [--path DIR] [--skip-missing-stores]   [R1.22]
  reef ws list [--repo R] [--all]                     [R1.22]  --all includes released and reclaimed
  reef ws inspect <WS> [--no-snapshot]                [R1.22]
  reef ws release <WS> [--no-snapshot]                [R1.22]
  reef ws move <WS> (--change C | --new-on REV)       [R1.06]
  reef ws run ...                                     [R1.21]
  reef ws gc [--repo R] [--dry-run]                   [R1.22]
  reef store build <NAME> [--rev REV] [--timeout D] [--force] | list   [R1.20]
  reef backup <DIR> | restore <DIR>                   [R1.18]
  reef completions <SHELL>                            [R1.22]  (addition to the README list; reported)
  ```

  Global flags: `-o, --output <text|json>`, `--socket <PATH>` (overrides `REEF_SOCKET`), `--no-autostart`, `--timeout <D>` (RPC deadline, default 30 s; `store build`, `backup`, and `ws run` manage their own), `-q, --quiet`, `-v` (sets `REEF_LOG=debug` for the CLI's own logs, which go to stderr).
- **Thin client.** The binary crate depends on `reef_daemon::client` and `reef_daemon::proto` only. No `reef_lib::jj` import in `reef-vcs` (`grep` in the acceptance criteria). R2.05 then removes `reef-lib` from the crate entirely once the few remaining types (ids, `ErrorKind`) move to the proto crate.
- **Repository resolution**: `--repo` accepts an id, an id prefix, or a path; without it the CLI sends the current directory as the path and the daemon resolves it (the daemon walks up from the path to a registered root, R1.05). The CLI never resolves ids itself; every `repo` and `workspace` field is passed through and the daemon answers `INVALID_ARGUMENT` listing candidates on an ambiguous prefix, which the CLI prints as-is.
- **Output modes.** `-o json` or non-terminal stdout: one JSON object per command, one JSON array for `list` commands, serde-derived from the proto types through `reef_daemon::client::json` (a `serde::Serialize` layer over the generated messages so field names are stable snake_case and timestamps are RFC 3339). `-o text` or a terminal: aligned columns for lists (hand-written padding over `unicode-width`-free ASCII; ids and hashes are ASCII and names are truncated at 40 columns), `key: value` blocks for single objects, nothing for commands with no result beyond success (`release`, `forget`), where text mode prints one line `released <ws-id>` on stderr instead. Colors are not used in Phase 1.
- **Errors**: stderr `error: <chain>` in both modes, plus in JSON mode `{"error":{"kind":"not_found","message":"..."}}` on stdout, so an agent reading stdout always gets one JSON value. Exit codes from `ErrorKind` as the README's table: `InvalidArgument` 2, `NotFound` 3, `AlreadyExists` 4, `Conflict` 5, `Unavailable` 6, `PermissionDenied` 7, `Io` 8, `Internal` 1. clap's own usage errors are 2 as well. The kind comes from the `ErrorDetail` in the gRPC status (R1.05); a status with no detail maps by `tonic::Code` with the inverse of R1.05's table.
- **Autostart**: on `Unavailable` connecting to the socket, unless `--no-autostart` or the command is `daemon status`/`daemon stop`, locate `reef-daemon` (same directory as `current_exe()`, then `PATH`), spawn it detached with `REEF_STATE_DIR`, `REEF_SOCKET`, `REEF_CONFIG`, and `REEF_LOG*` passed through, and poll the socket every 100 ms for up to 5 s. Print `reef: started daemon (pid N)` on stderr. `reef daemon start` is the same code path invoked explicitly, idempotent (exits 0 with `already running` if the socket answers `Status`).
- **`daemon stop`** reads `<state>/daemon.pid`, checks the pid answers `Status` on the socket (so a stale pid file is not killed), sends SIGTERM, waits up to 15 s for the socket to go away, exits 0; `--force` sends SIGKILL after the wait. `daemon status` prints version, pid, uptime, socket, state dir, repository and workspace counts from `Daemon.Status` (R1.03's message gains `repositories` and `active_workspaces` counts; reported).
- **`daemon run`** is `exec`-like: it calls `reef_daemon::run_main()` in-process (the same function `reef-daemon`'s `main` calls) so a user who only installed `reef` can still run a daemon in the foreground. The `reef-daemon` binary stays for service managers.
- **`ws create` prints the path** on stdout in text mode, nothing else, so `cd "$(reef ws create)"` works; JSON mode prints the full object.
- **Duration and size flags** parse with `humantime::parse_duration` and the byte-size parser from `reef_lib::jj::settings` (re-exported through the daemon crate as `reef_daemon::client::parse_byte_size`, so the binary does not import `reef_lib`).
- **Completions**: `reef completions zsh` writes to stdout; `just` gets a `completions` recipe that installs them for the current shell; the quickstart mentions it.

### `crates/reef-vcs/src/cli/mod.rs`

```rust
#[derive(clap::Parser)]
#[command(name = "reef", version, about, propagate_version = true)]
pub struct Cli { #[command(flatten)] global: Global, #[command(subcommand)] command: Command }

#[derive(clap::Args, Clone)]
pub struct Global {
    #[arg(short, long, global = true, value_enum)] output: Option<Output>,   // text | json
    #[arg(long, global = true, env = "REEF_SOCKET")] socket: Option<PathBuf>,
    #[arg(long, global = true)] no_autostart: bool,
    #[arg(long, global = true, default_value = "30s", value_parser = humantime::parse_duration)] timeout: Duration,
    #[arg(short, long, global = true)] quiet: bool,
    #[arg(short, long, global = true, action = ArgAction::Count)] verbose: u8,
}

#[derive(clap::Subcommand)]
pub enum Command { Daemon(daemon::Args), Config(config::Args), Repo(repo::Args), Ws(ws::Args), Store(store::Args), Backup(backup::Args), Restore(restore::Args), Completions { shell: clap_complete::Shell } }

pub struct Ctx { pub client: Client, pub out: Out, pub timeout: Duration }

pub fn main() -> ExitCode;                                  // never panics on a daemon error
pub(crate) async fn connect(global: &Global) -> Result<Client, CliError>;   // autostart lives here
```

### `crates/reef-vcs/src/cli/out.rs`

```rust
pub(crate) enum Output { Text, Json }
pub(crate) struct Out { mode: Output, quiet: bool }
impl Out {
    pub(crate) fn detect(flag: Option<Output>) -> Self;       // IsTerminal on stdout
    pub(crate) fn object<T: Serialize + TextRender>(&self, value: &T) -> io::Result<()>;
    pub(crate) fn list<T: Serialize + TextRow>(&self, values: &[T]) -> io::Result<()>;
    pub(crate) fn done(&self, text: &str);                     // stderr line in text mode, nothing in json
    pub(crate) fn error(&self, err: &CliError);                // stderr always; stdout JSON object in json mode
}
pub(crate) trait TextRender { fn render(&self, w: &mut dyn Write) -> io::Result<()>; }
pub(crate) trait TextRow { const HEADER: &'static [&'static str]; fn row(&self) -> Vec<String>; }
```

### `crates/reef-vcs/src/cli/{daemon,repo,ws,store,backup,restore,config}.rs`

One module per noun, `Args` with a `Subcommand`, and `pub(crate) async fn run(ctx: &Ctx, args: Args) -> Result<(), CliError>`. `ws.rs` contains `create`, `list`, `inspect`, `release`, `gc`, and dispatches `move` and `run` to `ws_move.rs` (R1.06) and `ws_run.rs` (R1.21); `CreateTarget` (`--repo`, `--change`/`--new-on`, `--path`, `--skip-missing-stores`) is defined in `ws.rs` and flattened by both `create` and `run`. `store.rs`, `backup.rs`, `restore.rs`, and `ws_move.rs` are stubs that print `not implemented until R1.xx` and exit 1 until their tickets land, so the surface compiles and `--help` is complete from this ticket on.

### `crates/reef-vcs/tests/cli.rs`

With `TestDaemon` (via `reef_daemon::testing`) and `assert_cmd`:

1. `help_lists_every_command`: `reef --help` names `daemon`, `config`, `repo`, `ws`, `store`, `backup`, `restore`, `completions`; `reef ws --help` names `create list inspect release move run gc`.
2. `json_when_piped`: `reef repo list` with stdout piped is a JSON array; with `-o text` it is a header line plus rows.
3. `repo_register_and_list`: register the synthetic repo by path; `list` shows id, root, `colocated: false`; registering again exits 4 and prints `{"error":{"kind":"already_exists",...}}` in JSON mode.
4. `ws_create_prints_path`: text mode stdout is exactly the path plus newline; the path exists; JSON mode has `id`, `path`, `change_id`, `lease.expires_at`.
5. `ws_list_and_inspect`: after create, `list` has one row with state `active`; `inspect <4-char prefix>` works; `inspect zzzz` exits 3; an ambiguous prefix (create a second workspace, find a shared prefix by brute force or use the daemon's test hook) exits 2 and lists candidates.
6. `ws_release`: exits 0, prints `released <id>` on stderr in text mode and nothing on stdout; `list` no longer shows it, `list --all` does with `released`.
7. `ws_gc_dry_run`: `--dry-run` reports categories with zero bytes on a fresh daemon and exits 0.
8. `exit_codes`: a table test driving `conflict` (release twice → 5), `unavailable` (`--socket /nonexistent --no-autostart` → 6 with `daemon is not running`), `invalid_argument` (`ws create --change` with no value → 2 from clap).
9. `autostart_spawns_daemon`: with a fresh `REEF_STATE_DIR` and no daemon, `reef repo list` starts one (stderr `started daemon`), succeeds, and `reef daemon status` shows the pid; `reef daemon stop` ends it within 15 s and the pid file is gone. Uses `CARGO_BIN_EXE_reef-daemon` beside `CARGO_BIN_EXE_reef` (cargo builds both into the same directory).
10. `daemon_stop_refuses_stale_pid`: write a pid file with a pid that is not a daemon (the test's own pid); `daemon stop` exits 3 with `no daemon answering`; the test process is not signalled.
11. `completions_generate`: `reef completions bash` exits 0 and the output mentions `reef`.
12. `no_jj_lib_in_binary` (a build-time check, not a runtime test): `grep -rn 'reef_lib::jj' crates/reef-vcs/src` is empty; implemented as a test that reads the sources from `CARGO_MANIFEST_DIR`, like R0.09's field-name test.

## Implementation notes

- Build the tokio runtime once in `cli::main` (`rt-multi-thread` is already a feature); `ws run` needs the full runtime for signals.
- `Out::detect`: `IsTerminal::is_terminal(&io::stdout())`; `-o` overrides. Do not consult `TERM` or `CI`.
- Text tables: compute column widths over the rows, pad with spaces, two-space gutters; `ws list` columns are `ID  STATE  CHANGE  OWNER  LEASE  BACKEND  ATTENTION  PATH`, with `LEASE` as a relative time (`12m left`, `expired 3m ago`) and `CHANGE` as the 8-character prefix of the reverse-hex form. JSON carries full values.
- Autostart must not inherit the CLI's stdin or the terminal: `Stdio::null()` for all three and `process_group(0)`; the daemon's stderr log still goes to its log file (R1.03).
- `daemon stop` on macOS: `kill -0` via `nix::sys::signal::kill(pid, None)` to check existence; then `Status` over the socket; then SIGTERM.
- Keep every subcommand's `run` under 60 lines by pushing rendering into `TextRender`/`TextRow` impls in `client::json` or a `render.rs`.
- `clap`'s `env = "REEF_SOCKET"` on `--socket` plus `global = true` makes the variable work for every subcommand.

## Out of scope

- Any command that reads or writes jj state directly; everything goes through the daemon.
- `reef status`, `log`, `diff`, `describe`, `undo` (R2.02, R2.03, R2.05).
- Colors, progress bars, interactive prompts, pagers.
- `reef mcp` (R2.13).
- Windows paths and named pipes (RX.05).
- Packaging and installers (R1.24 points at `cargo install`; a release process is R4.17).

## Risks

- clap derive with many flattened structs produces long `--help` output; keep `about` strings to one line and rely on `long_about` only for `ws run`.
- The autostart race on a shared state directory with two CLIs is settled by the daemon's lock, but both CLIs may print `started daemon`; acceptable, documented in the quickstart.
- Test 9 leaves a daemon running if the test fails before `stop`; `TestDaemon`-less tests must register a `Drop` guard that SIGTERMs the pid from the pid file.
