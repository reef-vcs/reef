# R1.01 Repository and workspace schema in SQLite

Phase 1 · Size S · Depends on: R0.04 · Unblocks: R1.02 (base cache rows and `BaseEntry` keys), R1.03 (the daemon opens `Db` and reports `schema_version`), R1.19 (spec file lease defaults feed the lease row); every later ticket reads these tables

## Context

The daemon serves many repositories from one machine and must remember, across restarts, which directories are leased workspaces, who owns them, what change they are on, and when their lease lapses (`docs/design.md`, "Workspaces": leased, inventory owned by the daemon; "Durability and backup": Reef metadata is authoritative except leases). ADR 0003 chose SQLite, one database per machine, every row keyed by repository. This ticket writes the schema, the Rust access layer, and the id types every other Phase 1 ticket uses, plus the jj-lib additions that make a Reef workspace exist at all: a jj working-copy commit and working copy with its state kept outside the tree.

`reef_lib::jj::Repo` (R0.04) opens the user's own workspace. It cannot yet create a second jj workspace for the same repository, resolve a change reference, or forget a workspace. Those go here because R1.02 (base cache) and R1.05 (create flow) both need them and neither should be the one to add jj-lib calls to `reef-lib`.

### What was verified while writing this ticket

jj-lib 0.46.0 and jj-core 0.46.0 source from `~/.cargo/registry`. Re-verify against the crate when implementing.

- `jj_lib::local_working_copy::LocalWorkingCopy::init(store: Arc<Store>, working_copy_path: PathBuf, state_path: PathBuf, operation_id: OperationId, workspace_name: WorkspaceNameBuf, user_settings: &UserSettings) -> Result<Self, WorkingCopyStateError>` and `LocalWorkingCopy::load(store, working_copy_path, state_path, user_settings)` are public. The state path is any directory; nothing requires it to be `<root>/.jj/working_copy`. `init` writes `checkout` (operation id and workspace name) and an empty `tree_state` into `state_path`. The working copy has the empty tree checked out after `init`.
- `jj_lib::workspace::Workspace::new(workspace_root: &Path, repo_path: PathBuf, working_copy: Box<dyn WorkingCopy>, repo_loader: RepoLoader) -> Result<Workspace, PathError>` is public and canonicalizes the root. `RepoLoader` is `Clone`; `Workspace::repo_loader()` returns it, so the user's `Workspace` (which `Repo::open` already loads) hands out the loader for every Reef workspace of that repository.
- `Workspace::init_workspace_with_existing_repo` is what `jj workspace add` uses. It creates `<root>/.jj`, checks out a new commit on top of the root commit (`MutableRepo::check_out(name, &store.root_commit())`), writes `.jj/working_copy/type`, and registers the root with `repo.loader().workspace_store().add(name, root)`. Reef copies the order but not the `.jj` directory.
- `MutableRepo::check_out(name: WorkspaceNameBuf, commit: &Commit) -> Result<Commit, CheckOutCommitError>` writes a new empty commit with `commit` as parent and calls `edit`. `MutableRepo::edit(name, &commit) -> Result<(), EditCommitError>` abandons the workspace's previous working-copy commit if it is empty and unreferenced, adds `commit` as a head, and sets the pointer. `MutableRepo::remove_workspace(name: &WorkspaceName) -> Result<(), EditCommitError>` (async) does the same abandon-if-empty step and removes the pointer. Both are what `jj workspace forget` and `jj edit` use.
- `jj_lib::repo::Repo::resolve_change_id_prefix(&HexPrefix) -> IndexResult<PrefixResolution<ResolvedChangeTargets>>` (async) returns every commit with the change id, each tagged `ResolvedChangeState::{Visible, Hidden}`; more than one visible target means the change is divergent. `HexPrefix::try_from_hex(&str) -> Option<HexPrefix>`. `Index::resolve_commit_id_prefix(&HexPrefix) -> PrefixResolution<CommitId>` (async on the `Index` trait, `repo.index()`). `PrefixResolution::{NoMatch, SingleMatch(T), AmbiguousMatch}`.
- `View::get_local_bookmark(&RefName) -> &RefTarget`; `RefTarget::is_absent()`; a conflicted bookmark is a `RefTarget` with several adds. `RefName` is a borrowed str newtype in `jj_lib::ref_name`.
- `jj_lib::workspace_store::WorkspaceStore` (re-exported from jj-core) has `add(&WorkspaceName, &Path)`, `forget(&[&WorkspaceName])`, `rename`, and a path lookup. The default implementation is `SimpleWorkspaceStore`, a protobuf file under `.jj/repo`. `repo.loader().workspace_store()` returns `&Arc<dyn WorkspaceStore>`.
- `WorkspaceNameBuf(String)` in `jj_lib::ref_name`; construct with `WorkspaceNameBuf::from("reef-...")`. jj's change id `reverse_hex` form uses the digits `z` to `k` for `0` to `f`; `HexPrefix::reverse_hex` is public, a `ChangeId::reverse_hex` method was not confirmed. The CLI helper below hand-rolls the 16-character mapping rather than depending on it.
- `rusqlite` 0.40.2 (MIT): the `backup` module is behind feature `backup`; `bundled` compiles SQLite in. `PRAGMA user_version` is read with `conn.query_row("PRAGMA user_version", [], ..)` and written with `conn.pragma_update(None, "user_version", n)`; `pragma_update` exists on `Connection` in 0.3x and is assumed in 0.40 (check docs.rs if the build complains).

## Decisions

- **Ids are 64 random bits, 16 lowercase hex characters.** `RepoId`, `WorkspaceId`, `LeaseId` are distinct newtypes over `[u8; 8]` generated from `rand::rng()`. They implement `Display`, `FromStr` (exactly 16 hex chars), `serde::{Serialize, Deserialize}` as strings, and `rusqlite::types::{ToSql, FromSql}` as `TEXT`. Prefix matching (at least 4 characters, unique) is a query helper, not part of the type.
- **The jj workspace name is `reef-<ws-id>`.** The user's `default` workspace is never touched.
- **Working-copy state lives outside the tree**, at `<state>/repos/<repo-id>/wc/<ws-id>/`, built with `LocalWorkingCopy::init` and `Workspace::new`. No `.jj` directory is created in a Reef workspace. The workspace is registered in jj's `WorkspaceStore` so `jj workspace list` shows it, and forgotten on release.
- **Starting points are `Edit(commit)` or `NewOn(commit)`**, mapping to `MutableRepo::edit` and `MutableRepo::check_out`. Resolution of user input to a commit is `Repo::resolve_revision`: change id prefix first (hex; a divergent change is an error naming every visible commit), then commit id prefix, then local bookmark name. No revset language.
- **Schema as in the README**, migration `0001_initial.sql` creating `repositories`, `workspaces`, `leases`, `reclaims`, `meta`. Migrations are numbered SQL files embedded with `include_str!` and applied by `PRAGMA user_version`: `0001_initial` (R1.01), `0002_base_cache` (R1.02), `0003_snapshots` (R1.16), `0004_stores` (R1.20), `0005_watchman` (R1.14: `workspaces.watcher`, `repositories.tracked_files`). A migration's number is fixed by this list, not by landing order; migrations are independent so they apply in any order. Migrations are applied in a transaction each, `PRAGMA user_version` is the applied count, and a database newer than the binary is an error, not a downgrade.
- **One connection, one mutex.** `Db` holds `std::sync::Mutex<rusqlite::Connection>`; every method takes the lock for one short statement or transaction. WAL mode, `foreign_keys = ON`, `busy_timeout = 5000`, `synchronous = NORMAL`. SQLite's single writer is the daemon (ADR 0003).
- **Rows are never deleted by state changes.** `workspaces.state` moves `active → releasing → released` or `→ reclaimed`; R1.17 deletes old terminal rows.
- **Timestamps are `INTEGER` unix milliseconds UTC**, converted at the edges with `time::OffsetDateTime`.
- **The `workspaces.lease_id ↔ leases.workspace_id` cycle** is accepted: SQLite checks foreign keys at statement time, and both tables are created in one migration with `workspaces` first. Inserting a workspace and its first lease is one transaction: insert the workspace with `lease_id NULL`, insert the lease, update the workspace.

```rust
    pub async fn resolve_revision(&self, text: &str) -> Result<Resolved, ResolveError>;

    /// the new workspace sharing this repository's loader, and the op id.
    pub async fn create_workspace(&mut self, name: &str, root: &Path, state_dir: &Path, start: StartPoint, description: &str) -> Result<(Repo, OperationIdHex), CreateWorkspaceError>;

    /// Reopens a workspace created by `create_workspace` after a restart.
    pub fn open_workspace(&self, root: &Path, state_dir: &Path) -> Result<Repo, OpenError>;

    /// `jj workspace forget`: removes the pointer (abandoning an empty
    /// working-copy commit) and the WorkspaceStore entry. Records one operation.
    pub async fn forget_workspace(&mut self, name: &str, description: &str) -> Result<OperationIdHex, ForgetWorkspaceError>;

    /// Seeds the working copy state so it believes the tree on disk is `commit`'s
    /// without hashing anything: `locked_wc.reset(&commit)`. Files are rehashed on the next snapshot.

```

`create_workspace` steps, in order: resolve nothing (caller passes commit ids); `tx = self.repo.start_transaction()`; `Edit` → `tx.repo_mut().edit(name, &commit)`, `NewOn` → `tx.repo_mut().check_out(name, &commit)`; `new_repo = tx.commit(description)`; `self.repo = new_repo` (the caller's `Repo` adopts the new head, like `snapshot` does); `LocalWorkingCopy::init(store, root, state_dir, new_op_id, name, settings)`; `Workspace::new(root, repo_path, Box::new(wc), loader.clone())`; `workspace_store().add(name, root)`; build `Repo { workspace, repo: self.repo.clone() }`. The seeding of `tree_state` (copying the base's file) is R1.05's job, done between `init` and the first snapshot; `reset_to` is the fallback.

`open_workspace`: `LocalWorkingCopy::load(store, root, state_dir, settings)`, `Workspace::new`, `Repo { workspace, repo: self.repo.clone() }`.

### `docs/adr/0014-workspace-model-on-jj.md`

Status `accepted`. Context: Reef workspaces must be cheap, many per change, reclaimable, and invisible to the agent as anything but a directory. Decision: every Reef workspace is a jj workspace with its own working-copy commit; the working-copy state lives in the daemon state directory; names are `reef-<id>`; the user's `default` workspace is untouched; starting points are edit or new-on; workspaces are registered in jj's WorkspaceStore. Consequences: `jj workspace list` shows Reef workspaces; a Reef workspace directory is not a jj repo (`jj status` inside it fails, by design until R2.05 gives agents the API); two workspaces editing one change diverge (ADR 0018 says how); jj's working-copy lock file lives in the state dir, so two daemons cannot share one. Alternatives: `.jj` inside the workspace (clone cost, deletable by agents); one jj workspace per change with a Reef-side overlay (reimplements jj's working copy); child commits per workspace (changes what "on a change" means).

## Implementation notes

- `Workspace::new` canonicalizes `root`; overlay mount points and APFS clone targets are real directories, so this is fine, but keep the canonical path in `workspaces.path`.
- `LocalWorkingCopy::init` needs `Arc<Store>`: `self.repo.store().clone()`.
- jj's `WorkspaceStore::add` wants an absolute normalized path "in the same manner as the repository path"; pass the canonicalized root.
- `resolve_revision` on a hex that is both a valid change id prefix and a commit id prefix prefers the change id, as jj does; document.
- `rusqlite` `bundled` adds about 15 s to a cold build; note the cold and warm CI durations in the PR as R0.04 did.
- Keep `Db` methods synchronous. Callers on tokio threads wrap them in `spawn_blocking` only if a statement is slow; none here is.

## Acceptance criteria

- [ ] `Db::open` on an empty path creates the schema at `user_version == 1`; opening again is idempotent; a hand-bumped `user_version = 99` fails with `TooNew`.
- [ ] `PRAGMA journal_mode` is `wal` and `PRAGMA foreign_keys` is `1` on an opened `Db`.
- [ ] Every `CHECK` string set in `0001_initial.sql` equals the Rust enum's `as_str` set (test).
- [ ] Id types round-trip through `Display`/`FromStr`, serde, and `ToSql`/`FromSql`; prefix lookups return `Ambiguous` for a non-unique prefix and `InvalidArgument` for one under 4 characters.
- [ ] `issue_lease` on a workspace with an unended lease is `Conflict`.
- [ ] `cargo test -p reef-lib` passes `jj_workspace.rs` tests 1 to 8 on macOS and Linux.
- [ ] A Reef workspace directory created by `create_workspace` contains no `.jj`.
- [ ] ADR 0014 exists and the ADR index row is added.
- [ ] `just ci` passes.

## Risks

- jj-lib may add required fields to `LocalWorkingCopy::init` or change `Workspace::new` in a bump; both are in the `jj` module only (ADR 0008's seam).
- `rusqlite` 0.40 may have renamed `pragma_update`; fall back to `execute("PRAGMA user_version = ?")` built by formatting the integer.
- `WorkspaceStore::add` may refuse a root that does not contain `.jj`; if so, skip registration and record in ADR 0014 that `jj workspace list` will not show Reef workspaces.
