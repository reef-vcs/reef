# R1.18 Local backup and restore

Phase 1 · Size M · Depends on: R1.04, R1.15, R1.16 (the `snapshots` index it restores and reconciles), R1.17, R1.22 (`reef backup` and `reef restore` replace its stubs) · Unblocks: nothing in Phase 1; R4's store backup reuses the manifest shape

## Context

The design's durability section (`docs/design.md`, "Durability and backup") names what must be protected: the jj repository (objects, operations, views, heads) and Reef's SQLite metadata; everything else (workspaces, base caches, working-copy state) is a cache rebuilt from those. It specifies the backup: hold the write lock briefly, copy SQLite through its online backup API, copy the immutable object and operation files without a lock, copy the operation heads last so the backup never references an operation it does not contain. Restore points a daemon at the copy, keeps workspace records, rematerializes directories on demand, and treats every lease as expired with a grace period so nothing is reclaimed on the first tick. A filesystem snapshot of the state directory is an acceptable substitute, so the quiesce step is exposed on its own. This is the phase exit criterion "a backup taken while agents are writing restores to a daemon that serves the same changes and operation log, with no workspace lost and no lease reclaimed on the first tick", and `backup.retention` is what R1.17's GC reads.

### What was verified while writing this ticket

jj-lib 0.46.0 (`repo.rs`, `simple_op_store.rs`, `simple_op_heads_store.rs`, `git_backend.rs`, `default_index/store.rs`, `workspace.rs`) and rusqlite 0.40.2.

- `.jj/repo/` layout written by `ReadonlyRepo::init`: `store/` (backend; `store/type` names it), `op_store/` with `operations/<op-hex>` and `views/<view-hex>` files (one immutable file per object), `op_heads/heads/<op-hex>` (an empty file per head; `update_op_heads` creates the new head's file then removes the old ones), `index/` (`op_links/`, `segments/`, `type`; rebuildable, see R1.17), `submodule_store/`, `workspace_store/` (the jj workspace registry, `workspace_store/index` in `SimpleWorkspaceStore`). Each store directory has a `type` file.
- Git objects: an internal-git repository keeps them under `.jj/repo/store/git/`; a colocated one has `.jj/repo/store/git_target` (a file holding the relative path to the `.git` directory) and the objects under `<root>/.git/objects/`. Loose objects and packs are immutable; `git gc` (R1.17) is the only writer that removes or rewrites them, hence the shared maintenance lock.
- rusqlite 0.40.2 `backup::Backup::new(from: &Connection, to: &mut Connection)` and `run_to_completion(pages_per_step: c_int, pause_between_pages: Duration, progress: Option<fn(Progress)>)`; `step(n)` returns `More | Done | Busy | Locked`. The destination may be a fresh file database. The crate feature is `backup`.
- `Workspace` initialization writes `<state>/type` with the working-copy implementation name (`local`) beside the working-copy state, which restore must reproduce when it recreates a `default` workspace.
- Not verified: `PRAGMA wal_checkpoint(TRUNCATE)` through rusqlite (`execute_batch` is enough); whether `git gc` can run concurrently with the object copy on packed repositories with multi-pack indexes (the maintenance lock makes it moot).

## Decisions

- **Scope of a backup.** A backup is of the daemon's state: the whole SQLite database plus the authoritative jj state of every registered repository, or of one repository with `--repo` (SQLite is still copied whole; it is small). A backup is a directory the caller names; nothing is written under the state directory.
- **Layout.** `<dest>/manifest.json`, `<dest>/reef.sqlite3`, `<dest>/repos/<repo-id>/repo/` (the `.jj/repo` copy without `index/`), `<dest>/repos/<repo-id>/git/` for colocated repositories (the `.git` copy without `index`, `logs/`, `hooks/`, `*.lock`), `<dest>/repos/<repo-id>/heads.json` written last. `manifest.json`: `{ version: 1, created_at, daemon_instance_id, reef_version, jj_lib_version, state_dir, repos: [{ id, root, colocated, jj_repo_path, op_heads: [..], files, bytes }], sqlite: { pages, bytes }, complete: true }`. `complete` is written in a final rewrite of the manifest after every `heads.json` exists; a manifest without it is an interrupted backup and restore refuses it.
- **Order per backup** (`Backup` RPC, under the maintenance lock from R1.17):
  1. `meta.last_backup_started_at = now`.
  2. SQLite: `PRAGMA wal_checkpoint(PASSIVE)` then `Backup::new(&db, &mut dest).run_to_completion(256, 10ms, None)` from the daemon's connection to `<dest>/reef.sqlite3`. Heartbeats keep working during this (the online backup restarts a step if the source changed; `run_to_completion` handles `Busy`/`Locked`).
  3. Per repository, pause its repository thread (the same mechanism as quiesce, below) and under that pause: read the op heads (`op_heads/heads/*`), copy `op_store/operations`, `op_store/views`, every `type` file, `workspace_store/`, `submodule_store/`, and `store/git_target` or `store/type`; resume the thread. This is the "write lock held briefly" window; it copies files proportional to operation count, not object count.
  4. Without the pause: copy the git objects directory (`store/git/` or `.git/objects` plus `.git/packed-refs`, `refs/`, `HEAD`, `config`), preserving mtimes (R1.07's `utimensat`-based `restore_mtime`, which works on read-only git objects) so R1.17's `git gc --prune` sees the same ages after restore. New objects appearing meanwhile are harmless extras; the heads read in step 3 reference only objects that existed then, because jj writes objects before operations.
  5. Write `heads.json` with the heads from step 3; after all repositories, rewrite `manifest.json` with `complete: true`; `meta.last_backup_at = now`.
- **Quiesce** on its own: `Maintenance.Quiesce { repo (optional), max_ms } -> { token, quiesced_at }` pauses every (or the named) repository thread's job queue, the watcher scheduler (events keep queueing), the lease tick, and GC; runs `PRAGMA wal_checkpoint(TRUNCATE)`; and returns. `Resume { token }` releases. A quiesce auto-resumes after `max_ms` (default and cap `backup.quiesce_max = "60s"`) so a crashed caller cannot wedge the daemon, and a second `Quiesce` while one is active is `Unavailable`. While quiesced, `Heartbeat` returns `UNAVAILABLE` with the resume time in the status message; on resume, every active lease gets `expires_at = max(expires_at, now + lease.grace)` so the pause cannot expire anyone. Snapshot, Create, Release, Move, and Gc wait on the pause (they run on the repository thread) up to their own deadlines. The filesystem snapshot a user takes between `Quiesce` and `Resume` contains a consistent SQLite file (checkpointed) and jj state (no writer).
- **Restore is offline.** `reef restore <dir> [--into <state-dir>] [--repo <id>] [--root <path>] [--force]` runs with no daemon on the target state directory (it takes `daemon.lock`; `Unavailable` if a daemon holds it). It refuses an incomplete manifest. It copies `reef.sqlite3` into place (replacing any existing database only with `--force`), then for each repository in the manifest: the target `.jj/repo` is the manifest's `jj_repo_path` (or `<root>/.jj/repo` with `--root`); if it exists and its op heads are not all in `heads.json` (the live repository is newer than the backup) restore refuses unless `--force`; otherwise it writes the `repo/` copy (with `index/` absent, so jj rebuilds it on first load) and, for colocated repositories, the `git/` copy. With `--root` pointing at a directory without a `default` working copy, restore recreates it: `LocalWorkingCopy::init(store, root, root/.jj/working_copy, head op id, "default", settings)`, `<root>/.jj/working_copy/type = "local"`, then `check_out` of the `default` workspace's working-copy commit from the restored view so the directory holds the files. Finally restore runs R1.15's `apply_restart_grace` with `lease.restart_grace` on every active lease and sets `meta.restored_from = <dir>`, `restored_at`, and `meta.rematerialize_pending = 1`.
- **Rematerialization on demand.** Restored `active` workspaces have no directory and no `wc/<id>` state. Without a marker, R1.05's start-up pass would mark them `reclaimed` ("directory missing at start"), so restore sets `meta.rematerialize_pending = 1` and R1.05's pass, when the flag is set, rematerializes every `active` row whose path or state dir is missing and clears the flag after the pass; without the flag R1.05's reclaim rule applies. This ticket adds `rematerialize(ws)`: base cache `ensure` for `base_tree_id`, backend `materialize`, `LocalWorkingCopy::init` at the restored `commit_id` with the base's `tree_state` seeded, re-register in jj's `WorkspaceStore` if missing, re-watch. Edits made after the last snapshot before the backup are gone; that is the design's statement that directories are caches. The row keeps `commit_id`, `change_id`, owner, purpose, and lease.
- **GC interaction.** `backup.retention` (30 d) and `meta.last_backup_at` feed R1.17's `keep_newer` floor so a restored database never references an object GC removed after the backup.
- **Config**: `[backup] retention = "30d"`, `quiesce_max = "60s"`, `sqlite_pages_per_step = 256`.

### `docs/adr/0020-local-backup-format.md`

Status `accepted`. Context: the four state classes from the design table and which are authoritative; jj's on-disk layout and what is immutable; SQLite's online backup; the GC interaction. Decision: the directory layout and manifest, the five-step order and why heads come last, quiesce as a standalone RPC with auto-resume, offline restore with the refusal rules, rematerialization on demand, retention as a GC floor. Consequences: a backup is restorable by file copy without Reef for the jj part (it is a `.jj/repo` directory); the index is never backed up; a restored workspace loses edits since its last snapshot (bounded by the watcher debounce); `--force` is the only way to go backwards in time and is spelled out. Alternatives: `tar` of the state directory with the daemon stopped (rejected: stops agents; still the documented fallback); backing up working-copy state and workspace directories (rejected: caches); SQLite file copy (rejected: unsafe with WAL and a writer).

### `crates/reef-daemon/tests/backup.rs`

Test config: `lease.default = 30s`, `restart_grace = 5s`, `tick = 500ms`, `watcher.debounce = 100ms`.

1. `round_trip_under_load`: `TestDaemon` with the `small` preset; create 5 workspaces; spawn 5 writer tasks that append a line to a file every 50 ms for the whole test; after 1 s start `Backup` to a temp dir; when it finishes, note each workspace's `last_snapshot_op` at that moment; keep writing for 1 s; stop the daemon; delete `<root>/.jj/repo`, the state dir's `repos/`, and `reef.sqlite3`; `restore` into the same state dir with `--force`; start a daemon; assert: `Repositories.List` has the repository, `Workspaces.List` shows 5 `ACTIVE` workspaces with `lease.expires_at >= start + 5 s`, each workspace's `commit_id` is in the restored view and its file content at that commit matches what the backup captured (not necessarily the last write), the op heads equal `heads.json`, `tick_once` reclaims nothing, and a new write in each workspace snapshots normally afterwards.
2. `manifest_is_consistent`: for each op head in `heads.json`, walking its ancestors through the restored repository succeeds (no missing operation or view file); for each workspace's `commit_id`, `get_commit` succeeds (no missing object).
3. `incomplete_backup_is_refused`: delete `complete` from a manifest; `restore` → error naming the manifest.
4. `newer_live_repo_is_refused`: take a backup, snapshot once more, `restore` without `--force` → error; with `--force` → succeeds and the later operation is gone.
5. `quiesce_blocks_writes_and_auto_resumes`: `Quiesce { max_ms: 2000 }`; `Snapshot` on a workspace does not complete within 1 s; `Heartbeat` → `UNAVAILABLE`; after 2.5 s both succeed and the lease's `expires_at` was extended by at least `lease.grace`.
6. `resume_token_is_checked`: `Resume` with a wrong token → `NOT_FOUND`; second `Quiesce` while active → `UNAVAILABLE`.
7. `restore_to_new_root`: `restore --root <empty dir>`; the directory has `.jj/repo`, `.jj/working_copy/type == "local"`, and the files of the `default` workspace's commit; `jj status` there succeeds when `jj` is on `PATH` (skipped otherwise with a message).
8. `colocated_repo_round_trips`: as 1 with a colocated fixture (`Workspace::init_colocated_git`), asserting `.git/objects` was copied and the restored repository opens.
9. `gc_respects_retention`: with `gc.undo_window = 0s`, `backup.retention = 1h`, take a backup, snapshot twice more, `Gc`; the commit hidden after the backup is still present; with `retention = 0s` it is pruned.
10. `rematerialize_on_demand`: after restore, each workspace's directory exists only after the daemon's start-up pass (assert the log line), none is `reclaimed`, `meta.rematerialize_pending` is cleared, and the base cache has one entry per distinct tree.

## Implementation notes

- `copy_tree` must preserve mtimes (`fs::copy` does not): R1.07's `fs_util::restore_mtime` after each file, which uses `utimensat` by path because git's loose objects are read-only and a write-open would fail. Use `walkdir` and skip by file name (`index`, `logs`, `hooks`) only at the `.git` top level, never inside `objects/`.
- Pause the repository thread with a job that holds a `std::sync::mpsc` or `Notify` wait; the thread's queue backs up behind it, which is the intended write lock. Keep the pause for step 3 under 100 ms on the `medium` fixture (measure and record).
- The SQLite backup reads through the daemon's own connection; `Backup::new` takes `&Connection`, so hold the db mutex for the duration of `run_to_completion` or open a second read connection for the backup (preferred: a second connection on the same file; WAL allows it).
- Restore of a database written by a newer schema version is refused (`PRAGMA user_version` higher than the binary knows).
- `heads.json` is a JSON array of hex strings; restore compares it to the live `op_heads/heads/` listing.
- `jj_lib_version` is `env!("CARGO_PKG_VERSION")` of jj-lib surfaced through `reef_lib::jj::JJ_LIB_VERSION` (a `const` added here).

## Out of scope

- Store backup (Postgres, object bucket) and federation (R4.x).
- Scheduled backups, retention of backup directories, encryption, or remote destinations; the user points a tool at the directory.
- Backing up workspace directories, base caches, or working-copy state (caches by design).
- Ephemeral mode streaming to a store (R4.x).

## Risks

- `--force` restore rewinds a live repository; the refusal rule and the explicit flag are the guard, and the quickstart (R1.24) says so.
- A backup taken during a `git gc` would copy packs being rewritten; the maintenance lock prevents it inside Reef, but a user running `git gc` by hand in a colocated repository is outside the lock. Document it.
- Recreating a `default` working copy on `--root` restore writes jj's working-copy state files through jj-lib's public `LocalWorkingCopy::init`; the `type` file is the one piece written by hand, and a jj-lib change to that layout breaks test 7, which is why the test runs `jj status`.
- Large colocated repositories make the unpaused object copy long; progress streaming exists so the CLI can show it, and the copy is restartable only by starting over (no incremental backup in Phase 1).
