# R0.02 Toolchain pinning and dev tooling

Phase 0 · Size S · Depends on: R0.01 · Unblocks: R0.03

## Context

After R0.01 the workspace has its final crate shape but no toolchain pin, no lint policy, no formatter config, no task runner, and no hooks. The local machine that produced these tickets has Rust 1.96.0 installed while stable is 1.99.1, and jj-lib 0.46.0 (pinned by R0.04) declares `rust-version = "1.97.1"`. So the pin matters immediately: without it, R0.04 fails to compile on a contributor's machine with a confusing error from deep inside jj-lib.

`just` is not installed on the authoring machine; `cargo-nextest`, `cargo-deny`, and `cargo-audit` are. `pre-commit` (the Python tool) is not installed and is not wanted.

## Decisions

- **`rust-toolchain.toml` pins `1.99.1`** with `rustfmt` and `clippy` components and the `minimal` profile. Bump policy: move the pin to the newest stable whenever a ticket needs it or at the start of each phase, in its own PR titled `Bump toolchain to x.y.z`.
- **MSRV (`rust-version`) is `1.97.1`**, set in `[workspace.package]`. Policy: MSRV = max(jj-lib's `rust-version`, the oldest release that has a feature we rely on). It is a floor, not a promise; CI builds only on the pinned toolchain.
- **`just` is the task runner.** Recipes are the single definition of each command. CI calls the same recipes (R0.03) so a green local `just ci` means green CI.
- **Tests run through `cargo nextest`** when available, with `cargo test` as fallback inside the recipe. Doctests still run through `cargo test --doc` because nextest does not run them. The recipe deliberately omits `--all-targets` so criterion benches (R0.06) are not executed as tests; `just build` and `just lint` keep `--all-targets` so benches still compile under `-D warnings`.
- **Lints are configured in `[workspace.lints]`**, not in source attributes. `clippy::all` and `clippy::pedantic` at `warn`, plus a short allow list. CI promotes warnings to errors with cargo's `build.warnings = deny` (R0.03), so in practice every lint in the table blocks a merge. Source-level `#[allow]` requires a comment giving the reason.
- **`cargo deny`** checks licenses, bans, and sources on every CI run; advisories run but do not block (new advisories against transitive deps should not break unrelated PRs). `cargo audit` is not added; deny covers it.
- **Git hooks via `core.hooksPath`** pointing at `.githooks/`, installed by `just setup`. No Python `pre-commit`. The hook runs format check and clippy. Bypass with `REEF_SKIP_HOOKS=1` or `git commit --no-verify`.
- **`.editorconfig`** for non-Rust files (Markdown, TOML, YAML): 2-space indent, LF, trailing newline, trim trailing whitespace except in Markdown.

### `Cargo.toml` additions

In `[workspace.package]`:

```toml
rust-version = "1.97.1"
```

Replace the `[workspace.lints.rust]` stub from R0.01 with:

```toml
[workspace.lints.rust]
unsafe_code = "warn"
missing_docs = "warn"
rust_2018_idioms = { level = "warn", priority = -1 }
unused_qualifications = "warn"
unreachable_pub = "warn"

[workspace.lints.clippy]
all = { level = "warn", priority = -1 }
pedantic = { level = "warn", priority = -1 }
# Allowed pedantic lints, with reasons. Keep this list short and justified.
module_name_repetitions = "allow"   # `workspace::WorkspaceId` is the clearer name
must_use_candidate = "allow"        # too noisy on plain getters
missing_errors_doc = "allow"        # error enums are documented at the type, not every fn
missing_panics_doc = "allow"        # panics are bugs; documenting them legitimizes them
# Lints we turn up beyond pedantic.
unwrap_used = "warn"                # clippy.toml allows it in tests
expect_used = "warn"
dbg_macro = "warn"
print_stdout = "warn"               # binaries opt out per-module with a comment
print_stderr = "warn"
todo = "warn"
unimplemented = "warn"
```

`priority = -1` on the group lints is required so the individual entries override the groups (cargo warns otherwise).

The two placeholder `main.rs` files from R0.01 use `println!`; add `#[allow(clippy::print_stdout, reason = "CLI output")]` on `main` or switch them to writing via `std::io::stdout().write_all`. R0.09 replaces them anyway.

### `justfile`

```just
set shell := ["bash", "-euo", "pipefail", "-c"]

default:
    @just --list

# One-time contributor setup: hooks, nextest.
setup:
    git config core.hooksPath .githooks
    cargo install cargo-nextest --locked || true
    cargo install cargo-deny --locked || true
    cargo install just --locked || true

build:
    cargo build --workspace --all-targets

# Unit and integration tests via nextest when present, else cargo test. Doctests always via cargo test.
test *ARGS:
    if command -v cargo-nextest >/dev/null; then cargo nextest run --workspace {{ARGS}}; else cargo test --workspace {{ARGS}}; fi
    cargo test --workspace --doc

lint:
    cargo clippy --workspace --all-targets --all-features -- -D warnings

fmt:
    cargo fmt --all

fmt-check:
    cargo fmt --all -- --check

doc:
    RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps --document-private-items

deny:
    cargo deny check licenses bans sources

deny-advisories:
    cargo deny check advisories

bench *ARGS:
    cargo bench --workspace {{ARGS}}

# Everything CI runs, in CI order.
ci: fmt-check lint build test doc deny

clean:
    cargo clean
```

Tabs vs spaces: `just` accepts either but they must be consistent within a file; use four spaces.

### `.githooks/pre-commit`

```bash
#!/usr/bin/env bash
# Installed by `just setup` (git config core.hooksPath .githooks).
# Skip with REEF_SKIP_HOOKS=1 or `git commit --no-verify`.
set -euo pipefail
if [[ "${REEF_SKIP_HOOKS:-0}" == "1" ]]; then exit 0; fi
cd "$(git rev-parse --show-toplevel)"
cargo fmt --all -- --check
# cargo fmt only sees files reachable from a crate root; also check every staged Rust file.
git diff --cached --name-only --diff-filter=ACMR -z -- '*.rs' | xargs -0 -r rustfmt --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
```

`cargo fmt` skips files no crate root reaches, which is why the staged-file `rustfmt` line exists: without it the verification below commits successfully. `chmod +x`. Commit with the executable bit (`git update-index --chmod=+x .githooks/pre-commit` if needed).

## Implementation notes

- Run `rustup update` (or `rustup toolchain install 1.99.1`) first; the pin will trigger an install on the next `cargo` call anyway.
- Expect the new lints to flag the placeholder crates (`missing_docs` on the `main` fns, `print_stdout`). Fix them rather than lowering the lint.
- `unreachable_pub` will be noisy once real modules exist; it is intentional. Items that are `pub` but only used in-crate should be `pub(crate)`.
- `cargo deny check` needs network on first run to fetch the advisory DB.

## Acceptance criteria

- [ ] `rustup show` inside the repo reports `1.99.1` as active.
- [ ] `just ci` passes from a clean clone (after `just setup`) with no warnings.
- [ ] `cargo clippy --workspace --all-targets -- -D warnings` passes.
- [ ] `cargo fmt --all -- --check` passes.
- [ ] `cargo deny check licenses bans sources` passes.
- [ ] The pre-commit hook blocks a commit containing an unformatted file and allows it with `REEF_SKIP_HOOKS=1`.
- [ ] `cargo build` with `rust-version` temporarily set above the toolchain fails with the expected MSRV error (sanity check that the field is honored); then restore.

## Out of scope

- The CI workflow itself (R0.03).
- Any lint fixes in code that does not exist yet.
- `cargo-audit`, `cargo-udeps`, `cargo-machete` (consider in a later tooling pass).

## Risks

- A pedantic lint may turn out to be wrong for jj-lib-heavy code in R0.04 (for example `needless_pass_by_value` on `Arc` parameters). Add to the workspace allow list with a comment; do not sprinkle `#[allow]`.
- `rustfmt`'s `style_edition = "2024"` reorders imports relative to 2021; the one-time reformat commit should be separate from other changes in the PR.
