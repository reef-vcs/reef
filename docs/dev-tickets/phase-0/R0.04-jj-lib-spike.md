# R0.04 jj-lib embedding spike

Phase 0 · Size M · Depends on: R0.01 · Unblocks: R0.06, R1.01, R1.13

## Context

Design principle: build on jj-lib, not a fork of the jj binary (`docs/design.md`, "Technology choices", and ADR 0002). Nothing in the repository has exercised jj-lib yet. This spike is the phase exit criterion "the daemon can open an existing jj repository through jj-lib, create a snapshot, and read the operation log", extended per `dev-phases.md` with listing changes and undoing one operation.

The output is not throwaway. The functions written here become the first real contents of `reef-lib` (a `jj` module) and R0.06 benchmarks the snapshot path through them. The written findings go into ADR 0008 and are the input to R1.01 and R1.13.

### What was verified about jj-lib 0.46.0 while writing this ticket

Source was downloaded from crates.io and inspected. Treat these as starting points and re-verify against the actual crate; the API is 0.x and moves.

- `rust-version = "1.97.1"`, edition 2024. Features: `default = ["git"]`, `git = ["dep:gix"]`, `testing = ["git"]`, `watchman = ["dep:watchman_client", "dep:tokio"]`. tokio is optional and only pulled by `watchman`.
- 0.46 split a `jj-core` crate out; `jj_lib` re-exports `backend`, `matchers`, `op_store`, `repo_path`, `merge`, `object_id`, `ref_name`, `dag_walk`, `signing`, `workspace_store` and others from it. Paths such as `jj_lib::matchers::EverythingMatcher` still resolve.
- Loading: `jj_lib::workspace::Workspace::load(&UserSettings, &Path, &StoreFactories, &WorkingCopyFactories) -> Result<Workspace, WorkspaceLoadError>`. Factories from `jj_lib::default_backend_factories::{default_backend_factories, default_working_copy_factories}`.
- Repo: `workspace.repo_loader().load_at_head().await -> Arc<ReadonlyRepo>` and `load_at(&Operation)`. Both async. Head resolution merges divergent op heads automatically.
- Settings: `jj_lib::settings::UserSettings::from_config_and_home_dir(StackedConfig, Option<PathBuf>)`. `jj_lib::config::StackedConfig::with_defaults()` includes jj-lib's `config/misc.toml`, which sets `user.name = ""` and `user.email = ""`, so settings construct without user config. Add a `ConfigLayer::parse(ConfigSource::User, "...")` layer setting `user.name`/`user.email` for the spike's commits. jj-cli's extra defaults (`max-new-file-size = "1MiB"` etc.) live in jj-cli, not jj-lib, so `SnapshotOptions` fields must be filled explicitly.
- Working copy: `workspace.start_working_copy_mutation().await -> LockedWorkspace`; `locked_ws.locked_wc().snapshot(&SnapshotOptions) -> (MergedTree, SnapshotStats)`; `locked_ws.finish(OperationId).await`. `SnapshotOptions { base_ignores: Arc<GitIgnoreFile>, progress: Option<&SnapshotProgress>, start_tracking_matcher: &dyn Matcher, force_tracking_matcher: &dyn Matcher, max_new_file_size: u64 }`.
- Stale detection: `jj_lib::working_copy::WorkingCopyFreshness::check_stale(locked_wc, &wc_commit, &repo)`; the simple test is `locked_wc.old_operation_id() == repo.op_id()`.
- Transactions: `repo.start_transaction() -> Transaction`; `tx.set_is_snapshot(true)`; `tx.set_workspace_name(..)`; `tx.repo_mut()` gives `MutableRepo`; `mut_repo.rewrite_commit(&commit).set_tree(tree).write().await -> Commit`; `mut_repo.set_wc_commit(workspace_name, commit_id)`; `mut_repo.rebase_descendants().await`; `tx.commit(description).await -> Arc<ReadonlyRepo>`.
- jj-cli's reference snapshot flow is `WorkspaceCommandHelper::snapshot_working_copy` in `jj-cli-0.46.0/src/cli_util.rs` around line 2091. Copy its order: lock working copy, check stale, snapshot, compare `tree_ids_and_labels()` with the wc commit's, start transaction with `set_is_snapshot(true)`, rewrite commit with new tree, `set_wc_commit`, `rebase_descendants`, commit transaction, `locked_ws.finish(new_repo.op_id())`.
- Op log: `jj_lib::op_walk::walk_ancestors(&[Operation]) -> impl Stream<Item = OpStoreResult<Operation>>`; `Operation::{id, parent_ids, parents().await, view().await, metadata()}`; `OperationMetadata { start_time, end_time, description, hostname, username, is_snapshot, workspace_name }`.
- Undo: jj-cli `commands/undo.rs` computes the target op, then restores the parent op's view: `tx.repo_mut().set_view(parent_op.view().await?.store_view().clone())` and commits with description `undo: restore to operation <hex>`. It then checks out the restored working-copy commit on disk via `Workspace::check_out(op_id, old_tree, &commit)`.
- Diff between trees: `MergedTree::diff_stream(&other, &dyn Matcher)` (async stream) in `jj_lib::merged_tree`.
- View: `repo.view().wc_commit_ids() -> &BTreeMap<WorkspaceNameBuf, CommitId>`, `get_wc_commit_id(&WorkspaceName)`, `heads()`.
- Repo init without the jj CLI: `Workspace::init_internal_git(&settings, root, gix::hash::Kind::Sha1).await` and `init_colocated_git(&settings, root, gix::hash::Kind::Sha1).await`, both returning `(Workspace, Arc<ReadonlyRepo>)`; `init_simple(&settings, root)` uses the simple backend, which is not what users have. `gix` is re-exported by jj-lib only through its types; add `gix` as a direct dependency only if the `Kind` path cannot be reached via `jj_lib`, and if so match jj-lib's `gix` version exactly. jj-lib has no `testutils` on crates.io; build fixtures through these.
- Everything async is runtime-agnostic. jj-cli uses `pollster::FutureExt::block_on`. The underlying I/O is blocking inside the futures.

## Decisions

- **Pin `jj-lib = "=0.46.0"`** with default features (git backend is required to open real repos). No `watchman` feature yet (R1.14).
- **The spike lives in `reef-lib` as module `jj`** (`crates/reef-lib/src/jj/`), with submodules `settings`, `repo`, `snapshot`, `oplog`, `undo`. Public API is async. No blocking wrapper in the library; callers choose their executor.
- **Fixtures are created through jj-lib**, using `init_internal_git` (the layout `jj git init` produces without `--colocate`) and `init_colocated_git` (what most real users have). A third fixture path uses the real `jj` binary if it is on `PATH`, else the test is skipped with a visible message. CI does not install `jj` in this ticket.
- **Snapshot semantics match `jj` defaults**: `base_ignores` chains the repo's `.gitignore` files via `GitIgnoreFile::chain_with_file(&self, prefix: &RepoPath, file: PathBuf)` from `GitIgnoreFile::empty()` the way jj-cli does (`base_ignores()` in cli_util.rs), `start_tracking_matcher = EverythingMatcher`, `force_tracking_matcher = NothingMatcher`, `max_new_file_size = 1 MiB`. Files above the limit are reported in `SnapshotStats::untracked_paths`, not an error, matching jj's behavior where a too-large new file is left untracked and reported.
- **Undo is "restore to parent operation"** for the spike. The jj-cli undo-stack logic (jumping over earlier undos) is not replicated; note it in the ADR as something R2.03 must handle.
- **Measurements are part of the deliverable**: wall time to open, snapshot (clean and with 50 modified files), walk 100 ops, undo, on the R0.05 generator's `large` preset if R0.05 has landed, otherwise on a 10k-file tree the test creates itself. Numbers go in ADR 0008.
- **Tests use `#[tokio::test]`.** Add `tokio` (workspace dep already declared in R0.01) as a dev-dependency.

### `crates/reef-lib/src/jj/mod.rs`

```rust
//! Embedding of jj-lib. This module is the only place in Reef that talks to
//! jj-lib types directly; everything above it uses Reef's own types.

pub mod oplog;
pub mod repo;
pub mod settings;
pub mod snapshot;
pub mod undo;

pub use repo::{OpenError, Repo};
```

Keep jj-lib types out of the public signatures where a Reef type is cheap to define (ids as newtypes over hex strings or `Vec<u8>`), and leave them in where wrapping would be busywork for a spike (`MergedTree`, `Commit`). Record in the ADR which jj-lib types leak and why.

### `crates/reef-lib/src/jj/settings.rs`

```rust
pub struct Identity { pub name: String, pub email: String }

pub fn user_settings(identity: &Identity) -> Result<UserSettings, SettingsError>;
```

Builds `StackedConfig::with_defaults()`, adds a `ConfigLayer` (source `User`) with `user.name`, `user.email`, and `snapshot.max-new-file-size = "1MiB"` (so the value lives in config, read back when building `SnapshotOptions`), then `UserSettings::from_config_and_home_dir(config, None)`. Document that jj's user config files (`~/.config/jj/config.toml`) are deliberately not read; the daemon will have its own config.

### `crates/reef-lib/src/jj/repo.rs`

```rust
pub struct Repo {
    workspace: jj_lib::workspace::Workspace,
    repo: Arc<jj_lib::repo::ReadonlyRepo>,
}

#[derive(Debug, thiserror::Error)]
#[non_exhaustive]
pub enum OpenError { NotAJjRepo(PathBuf), Load(#[from] WorkspaceLoadError), Repo(#[from] RepoLoaderError), ... }

impl Repo {
    pub async fn open(path: &Path, settings: &UserSettings) -> Result<Self, OpenError>;
    pub fn workspace_root(&self) -> &Path;
    pub fn repo_path(&self) -> &Path;          // the .jj/repo dir
    pub fn op_id(&self) -> OperationIdHex;      // newtype String
    pub fn wc_commit(&self) -> Result<Commit, _>;  // current workspace's wc commit
    pub async fn reload_at_head(&mut self) -> Result<(), OpenError>;
    pub fn heads(&self) -> Vec<ChangeSummary>;  // change id, commit id, description, is_wc
}
```

`open` uses `Workspace::load` with the default factories. If `path/.jj` does not exist walk up parents like jj does (`DefaultWorkspaceLoader::new` already does the search; confirm and rely on it, map its "not found" error to `NotAJjRepo`).

### `crates/reef-lib/src/jj/snapshot.rs`

```rust
pub struct SnapshotOutcome {
    pub changed: bool,                 // false if tree unchanged; no op written
    pub op_id: OperationIdHex,         // new head op if changed, else current
    pub wc_commit: CommitIdHex,
    pub untracked: Vec<(String, UntrackedReasonKind)>,
    pub stats: SnapshotTiming,         // scan, write, commit durations
}

#[derive(Debug, thiserror::Error)]
#[non_exhaustive]
pub enum SnapshotError { Stale { wc_op: OperationIdHex, repo_op: OperationIdHex }, Snapshot(#[from] jj_lib::working_copy::SnapshotError), ... }

impl Repo {
    pub async fn snapshot(&mut self, description: &str) -> Result<SnapshotOutcome, SnapshotError>;
    pub async fn changed_paths_in_wc(&self) -> Result<Vec<ChangedPath>, DiffError>;  // wc commit tree vs first parent tree
}
```

`snapshot` follows the jj-cli order listed above. On stale working copy (`old_operation_id() != repo.op_id()`), return `Stale` rather than attempting jj-cli's recovery; the ADR notes that R1.13 must decide whether to reload at the wc's op or at head. `tx.set_is_snapshot(true)` and `tx.set_workspace_name(..)` must be set so the op log entry is marked as a snapshot (R1.16 relies on being able to distinguish snapshot ops).

`changed_paths_in_wc` uses `diff_stream` with `EverythingMatcher` and yields `(RepoPath as String, Added|Modified|Removed)`.

### `crates/reef-lib/src/jj/oplog.rs`

```rust
pub struct OpEntry {
    pub id: OperationIdHex,
    pub parents: Vec<OperationIdHex>,
    pub description: String,
    pub start: SystemTime, pub end: SystemTime,
    pub hostname: String, pub username: String,
    pub is_snapshot: bool,
    pub workspace: Option<String>,
}

impl Repo {
    pub async fn op_log(&self, limit: usize) -> Result<Vec<OpEntry>, OpLogError>;  // newest first
}
```

Uses `op_walk::walk_ancestors(&[self.repo.operation().clone()]).take(limit)` and collects with `futures::StreamExt`. Timestamps come from `OperationMetadata.start_time/end_time` (`Timestamp { timestamp: MillisSinceEpoch, tz_offset }`).

### `crates/reef-lib/src/jj/undo.rs`

```rust
impl Repo {
    /// Restores the view of the current head operation's first parent and
    /// checks the restored working-copy commit out on disk.
    pub async fn undo_last(&mut self) -> Result<UndoOutcome, UndoError>;
}
pub struct UndoOutcome { pub undone: OperationIdHex, pub restored_to: OperationIdHex, pub new_op: OperationIdHex }
```

Steps: `let target = self.repo.operation().clone()`; `let parent = target.parents().await?.first()` (error if root op); `let view = parent.view().await?`; `let mut tx = self.repo.start_transaction()`; `tx.repo_mut().set_view(view.store_view().clone())`; `let new_repo = tx.commit(format!("undo: restore to operation {}", parent.id().hex())).await?`; then check out the restored wc commit: `let commit = new_repo.store().get_commit(new_repo.view().get_wc_commit_id(ws_name)?)`; `self.workspace.check_out(new_repo.op_id().clone(), None, &commit).await`. Merged-op-heads and cross-workspace refusal logic from jj-cli are out of scope and listed in the ADR.

### `crates/reef-lib/tests/jj_spike.rs`

Integration tests, each in a `tempfile::tempdir()`:

1. `open_internal_git_repo`: `Workspace::init_internal_git`, drop it, `Repo::open` the directory, assert `op_log(10)` has one entry (`initialize repo`) and `heads()` has one wc commit with empty description.
2. `open_colocated_repo`: same with `init_colocated_git`; additionally assert `.git` exists at the root.
3. `open_from_subdirectory`: open `root/sub/dir` and get the same `workspace_root`.
4. `open_non_repo_fails`: `OpenError::NotAJjRepo`.
5. `snapshot_records_new_file`: write `a.txt`, `snapshot("test")`, assert `changed`, the op log head `is_snapshot == true` with `workspace == Some("default")`, `changed_paths_in_wc()` == `[("a.txt", Added)]`, and a second `snapshot` returns `changed == false` with the same op id.
6. `snapshot_respects_gitignore`: `.gitignore` with `ignored/`, files in and out of it; only the non-ignored file appears.
7. `snapshot_reports_large_file_as_untracked`: a 2 MiB new file is in `untracked` with the too-large reason; a 2 MiB file that was already tracked (write small, snapshot, grow, snapshot) is snapshotted.
8. `op_log_walks_parents_newest_first`: three snapshots, `op_log(10)` returns 4 entries with correct parent links.
9. `undo_restores_previous_view_and_disk`: snapshot `a.txt`, `undo_last()`, assert the head op description starts with `undo: restore to operation`, `wc_commit` tree no longer contains `a.txt`, and `a.txt` is gone from disk after checkout. Then assert a new snapshot of the (now clean) tree returns `changed == false`.
10. `stale_working_copy_detected`: open the repo twice (two `Repo` values on the same directory), snapshot through the first, then snapshot through the second without reload; expect `SnapshotError::Stale`. Then `reload_at_head` on the second and snapshot succeeds.
11. `open_repo_created_by_jj_cli` (skipped unless `which jj` succeeds; print `skipped: jj not on PATH`): `jj git init --colocate`, write a file, `jj` snapshots on `jj status`; then `Repo::open` sees the wc commit with that file and `op_log` includes jj's own `snapshot working copy` op.
12. `timing_report` (`#[ignore]`, run by hand and in the ADR): build a tree with `reef_testing::synth` `large` preset if available (R0.05) else generate 10k files inline; measure open, first snapshot, no-op snapshot, 50-file mutation snapshot, `op_log(100)` after 100 snapshots, `undo_last`. Print a Markdown table.

### `docs/adr/0008-jj-lib-embedding-findings.md`

Status `accepted`. Sections per template. Required content:

- **Exposed and usable as-is:** the list above (load, snapshot, transactions, op walk, view restore, diff streams, git-backed and internal repos, gitignore handling, colocated layout).
- **Not exposed or not present:** leases, any notion of ownership or expiry; copy-on-write materialization (the working copy is a full checkout in `LocalWorkingCopy`); filesystem watching (jj's `fsmonitor` is a Watchman client behind a feature, not a notify-based watcher); a structured conflict API beyond `Merge<TreeId>`/`MergedTree` (R3.25 needs to map); no hooks for "snapshot taken" events; per-workspace locking is file-based under `.jj/working_copy`; the `testing` feature is for jj's own tests.
- **Gotchas:** async with blocking I/O inside (daemon must call from `spawn_blocking` or a dedicated thread; decide in R1.03); stale working copy handling is the caller's job; `max_new_file_size` and ignores must be supplied, nothing is read from the user's jj config unless we do it; jj-lib writes `.jj/working_copy/` state on `finish`, so two processes on one working copy need the lock discipline jj uses; divergent op heads are merged silently on `load_at_head`; `rust-version` 1.97.1; `gix` adds roughly N seconds to a cold build (fill in measured); crate is 0.x and 0.45 to 0.46 changed edition, MSRV, and crate structure (`jj-core` split), so bumps are tickets.
- **Measurements** table from test 12 on the authoring machine, with the machine and preset named.
- **Which jj-lib types leak** through `reef_lib::jj` and the plan to wrap them (R1.01 for ids, R2.01 for everything crossing the API).
- **Decision:** continue with jj-lib; list the first upstream contributions worth proposing (a snapshot-event hook, a public notify-based fsmonitor, cheaper `check_stale`).

## Implementation notes

- Start by running `cargo add jj-lib@=0.46.0 -p reef-lib` and `cargo build -p reef-lib` to see the compile cost before writing code. If 0.46.0 fails to build on 1.99.1 for any reason, fall back to `=0.45.1` (MSRV 1.89, edition 2021-era API) and change the pin everywhere, including `docs/dev-tickets/phase-0/README.md`.
- Read `jj-cli-0.46.0/src/cli_util.rs` (`snapshot_working_copy`, `base_ignores`, `update_working_copy`) and `commands/undo.rs` before writing `snapshot.rs` and `undo.rs`. `cargo vendor` or `~/.cargo/registry/src/*/jj-cli-0.46.0` after `cargo fetch` with a temporary dev-dependency is the quickest way to get the source locally; remove the dependency afterward.
- jj's working copy lock is a file lock; tests that open the same directory twice must drop `LockedWorkspace` before the second `Repo` acts.
- Internal-git and colocated repos both store jj's op store under `.jj/repo/op_store`; `init_internal_git` keeps the git objects under `.jj/repo/store/git`.
- Clippy pedantic will complain about `Arc` arguments and `async fn` in traits; add workspace allows with reasons rather than attribute spam.

## Out of scope

- Any Reef-side storage (SQLite) or workspace records (R1.01).
- Watcher-driven snapshots (R1.13), Watchman (R1.14).
- Wrapping every jj-lib type; the ADR lists what leaks.
- Reproducing jj-cli's undo-stack semantics, cross-workspace undo refusal, or git HEAD reset on undo in colocated repos (document in the ADR; R2.03).
- Writing to git refs or exporting to git (R4.14 onward).

## Risks

- jj-lib 0.46.0 may not build on the pinned toolchain or may have a yanked transitive dependency; the fallback to 0.45.1 is pre-authorized above.
- `rebase_descendants` after a snapshot can be slow on repos with many descendants of the wc commit; note timing in the ADR but do not optimize.
- Colocated repos: jj-cli also imports/exports git refs around snapshots (`git::import_refs`); the spike does not, which means `jj` CLI and Reef can disagree about bookmarks on a colocated repo. State this in the ADR as a R1 decision (likely: Reef runs `import_refs` on open).
