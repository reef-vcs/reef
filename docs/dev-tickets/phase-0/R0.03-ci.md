# R0.03 CI on macOS and Linux

Phase 0 · Size S · Depends on: R0.02 · Unblocks: R0.06 (benchmark artifact upload)

## Context

Phase 0 exit criterion: "CI runs build, test, clippy, and rustfmt on macOS and Linux on every push." The repository is on GitHub (`reef-vcs/reef`). There is no `.github/` directory yet. R0.02 defined the `justfile` recipes; CI must run those recipes, not restate them, so local and CI never drift.

The workspace will pull jj-lib and gix from R0.04 onward, which makes cold builds take several minutes. Caching is therefore not optional.

## Decisions

- **GitHub Actions**, one workflow file `ci.yml`, triggered on `push` to `main` and on `pull_request`. Concurrency group per ref with `cancel-in-progress: true` so superseded pushes stop.
- **Runners:** `ubuntu-24.04` and `macos-15` (Apple Silicon). Intel macOS is not tested. Windows is explicitly absent until RX.05 decides.
- **Toolchain comes from `rust-toolchain.toml`** via `actions-rust-lang/setup-rust-toolchain@v2`, which reads the file and configures `Swatinem/rust-cache` automatically. Do not hardcode a version in the workflow.
- **`just` installed via `extractions/setup-just@v4`.** `cargo-nextest` and `cargo-deny` via `taiki-e/install-action@v2` with `tool: cargo-nextest,cargo-deny`.
- **Warnings are errors everywhere**: `CARGO_BUILD_WARNINGS: deny` and `RUSTDOCFLAGS: -D warnings` at workflow `env`. cargo's `build.warnings` setting (stable since 1.97) fails the build on lint warnings in workspace crates without touching `RUSTFLAGS`, so dependencies compile exactly as they do locally and the cache key is unaffected. `setup-rust-toolchain@v2` sets the same variable through its `build-warnings` input, whose default is `deny`. rustdoc is not covered by `build.warnings`, hence the separate `RUSTDOCFLAGS`. Clippy already runs with `-D warnings` from the `just lint` recipe.
- **Jobs:** `fmt` (ubuntu only), `deny` (ubuntu only), `check` matrix over the two OSes running lint, build, test, doc in that order, and a final `ci-ok` job that `needs` all of them and exists so branch protection can require a single check. `deny-advisories` runs with `continue-on-error: true`.
- **No benchmark job here.** R0.06 adds a separate `bench.yml`.
- **Dependabot** for GitHub Actions and Cargo, weekly, grouped, so action pins do not rot.
- **Timeouts:** 30 minutes per job. If the jj-lib build pushes macOS over that, raise it in R0.04.

## Deliverables

### `.github/workflows/ci.yml`

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:

concurrency:
  group: ci-${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

env:
  CARGO_TERM_COLOR: always
  CARGO_INCREMENTAL: 0
  CARGO_BUILD_WARNINGS: deny
  RUSTDOCFLAGS: -D warnings
  RUST_BACKTRACE: 1

permissions:
  contents: read

jobs:
  fmt:
    name: rustfmt
    runs-on: ubuntu-24.04
    timeout-minutes: 10
    steps:
      - uses: actions/checkout@v7
      - uses: actions-rust-lang/setup-rust-toolchain@v2
        with:
          cache: false
      - uses: extractions/setup-just@v4
      - run: just fmt-check

  deny:
    name: cargo deny
    runs-on: ubuntu-24.04
    timeout-minutes: 15
    steps:
      - uses: actions/checkout@v7
      - uses: actions-rust-lang/setup-rust-toolchain@v2
      - uses: taiki-e/install-action@v2
        with:
          tool: cargo-deny
      - uses: extractions/setup-just@v4
      - run: just deny
      - run: just deny-advisories
        continue-on-error: true

  check:
    name: ${{ matrix.os }}
    runs-on: ${{ matrix.os }}
    timeout-minutes: 30
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-24.04, macos-15]
    steps:
      - uses: actions/checkout@v7
      - uses: actions-rust-lang/setup-rust-toolchain@v2
      - uses: taiki-e/install-action@v2
        with:
          tool: cargo-nextest
      - uses: extractions/setup-just@v4
      - name: Lint
        run: just lint
      - name: Build
        run: just build
      - name: Test
        run: just test
      - name: Docs
        run: just doc

  ci-ok:
    name: CI passed
    if: always()
    needs: [fmt, deny, check]
    runs-on: ubuntu-24.04
    steps:
      - run: |
          echo '${{ toJSON(needs) }}'
          [[ "${{ needs.fmt.result }}" == "success" && "${{ needs.deny.result }}" == "success" && "${{ needs.check.result }}" == "success" ]]
```

Pin each action to a major tag as shown; these were the current majors on 2026-10-15 (`checkout` v7, `setup-rust-toolchain` v2, `setup-just` v4, `install-action` v2). Dependabot keeps them current.

### `.github/dependabot.yml`

```yaml
version: 2
updates:
  - package-ecosystem: github-actions
    directory: /
    schedule:
      interval: weekly
    groups:
      actions:
        patterns: ["*"]
  - package-ecosystem: cargo
    directory: /
    schedule:
      interval: weekly
    groups:
      cargo-minor:
        update-types: ["minor", "patch"]
    ignore:
      - dependency-name: jj-lib   # bumped deliberately, see ADR 0008
```

## Implementation notes

- The `fmt` job disables the cache because it compiles nothing.
- `setup-rust-toolchain@v2` no longer sets `RUSTFLAGS` (v1 set it to `-D warnings`). It sets `CARGO_BUILD_WARNINGS` from its `build-warnings` input, default `deny`; the workflow `env` carries the same value so it is visible in the file. Do not pass `rustflags` to the action.
- Test the workflow on a branch by opening a draft PR. Both OS jobs must go green before merging. Record the cold and warm job durations in the PR description; R0.04 will compare after adding jj-lib.
- `macos-15` and `macos-26` were both offered on GitHub-hosted runners on 2026-10-15. Stay on `macos-15` until an Xcode or OS need forces a move; if it is retired, move to `macos-26` and note the substitution in the PR.
- `just test` on CI runs doctests too; there are none yet, which is fine.

## Acceptance criteria

- [ ] The workflow runs on a pull request and on a push to `main`.
- [ ] `fmt`, `deny`, `ubuntu-24.04`, `macos-15`, and `CI passed` all report success on the PR for this ticket.
- [ ] Introducing a `println!` without an allow in `reef-lib` on a scratch branch makes the `check` jobs fail (warnings are errors). Revert before merge.
- [ ] A second push to the same PR cancels the in-progress run of the first.
- [ ] Warm-cache `check` job time on Linux is under 5 minutes for the current (jj-lib-free) workspace.
- [ ] The badge renders in the README.

## Out of scope

- Benchmarks in CI (R0.06).
- Release builds, signing, Homebrew (R4.17).
- Coverage reporting. Add `cargo-llvm-cov` in a later tooling pass once there is code worth measuring.
- Windows.

## Risks

- Action version drift. Mitigated by Dependabot.
- macOS runner queue times. If they become a bottleneck, keep macOS on `push` to `main` plus PRs touching `crates/**`, using `paths` filters; not needed yet.
