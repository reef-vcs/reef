# R0.08 Contributor docs

Phase 0 · Size S · Depends on: nothing (read R0.02's justfile and R0.03's workflow to keep the setup section accurate; land after them if possible) · Unblocks: nothing directly

## Context

The repository has a README, a license, two design documents, and no contributor-facing process. The README's "Contributing" section says code contributions will make sense once Phase 1 has a skeleton. Phase 0 is that skeleton. This ticket adds the files GitHub's community profile expects and settles the one legal decision that is painful to change later: DCO or CLA.

The existing commit history has a consistent style (imperative, sentence-case subject, no trailing period, no `feat:` prefixes, e.g. `Add placeholder reef-daemon and reef-lib crates for the crates.io names`) and should be codified rather than replaced.

## Decisions

- **DCO, not CLA.** Apache 2.0 project, no corporate owner, low friction is the goal. Contributors add `Signed-off-by:` via `git commit -s`. Enforcement via the DCO GitHub App (`https://github.com/apps/dco`) installed on the org, documented as a manual step; no custom CI check. Recorded in ADR 0010.
- **Contributor Covenant 2.1** as the code of conduct, unmodified except for the contact address.
- **Issue templates as YAML forms** (`.github/ISSUE_TEMPLATE/*.yml`), three of them: bug report, feature or design proposal, and a "ticket" form for rows from `docs/dev-phases.md` so each phase ticket becomes an issue with a stable shape. Blank issues disabled; config points discussions-type questions at GitHub Discussions (enable Discussions manually; document).
- **One PR template** with a checklist that mirrors `just ci` and the ADR rule.
- **Commit message convention** as observed in history. Ticket IDs (`R0.04`) go in PR titles and in the commit body's first line when a commit implements a ticket, not as a subject prefix.
- **Branch model:** `main` protected, feature branches, squash merge by default so each ticket is one commit on `main` with the PR description as body. Document; apply the repository setting by hand.
- **`SECURITY.md`** is included as a minimal stub pointing at GitHub private vulnerability reporting, so the community profile is complete. R6.05 writes the real disclosure policy.
- **Agent-authored contributions are welcome and expected.** CONTRIBUTING says so, and asks that PRs from agents state which model produced them in the PR body, which matches the project's own provenance principle and the existing `Co-Authored-By` lines in history.

### `docs/adr/0010-dco-instead-of-cla.md`

Template sections. Context: Apache 2.0, open ecosystem goal, no legal entity to hold a CLA, contributions expected from many small contributors and from agents. Decision: DCO with `Signed-off-by`, enforced by the DCO app. Consequences: no copyright assignment, which means relicensing later would need every contributor's consent; low friction; agent-authored commits are signed off by the human who submits them, who thereby certifies the DCO on the agent's behalf. Alternatives: CLA via CLA Assistant (friction, needs an entity); nothing (unclear provenance of contributions, which contradicts the project's own thesis).
