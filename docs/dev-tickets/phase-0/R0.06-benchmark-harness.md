# R0.06 Benchmark harness

Phase 0 · Size S · Depends on: R0.04, R0.05 · Unblocks: R1.12, RX.06

## Context

The design's first goal is "operations cost O(what changed), never O(repository size)". That is only checkable with benchmarks that exist before the daemon does. This ticket sets up criterion with one real benchmark, snapshotting the synthetic repository through `reef_lib::jj` (R0.04) on trees from `reef_testing::synth` (R0.05), and publishes results from CI as artifacts. It is deliberately not a regression gate; RX.06 adds thresholds once there is a baseline worth protecting.

## Decisions

- **criterion 0.8** (already in `[workspace.dependencies]`). Verify the 0.8 API on docs.rs before writing; `criterion_group!`/`criterion_main!` and `Criterion::bench_with_input` are expected to still exist. Enable `html_reports`.
- **Benches live in `crates/reef-lib/benches/`**, one file per subject: `snapshot.rs` now. Workspace creation benches (R1.12) go in `reef-daemon/benches/` later.
- **Fixture size is controlled by `REEF_BENCH_PRESET`** (`small` | `medium` | `large`, default `medium`). CI runs `medium` on every push to main and `large` on a weekly schedule, because `large` fixture setup plus jj's first snapshot of 100k files takes minutes. Local runs default to `medium` so `cargo bench` finishes in a coffee break.
- **Fixtures are built once per process** under `target/bench-fixtures/<preset>-<seed>/` and reused across benchmark functions and across runs; the manifest check in `generate` makes this idempotent. The jj repo is initialized by `jj_lib::workspace::Workspace::init_internal_git` through a helper in `reef_lib::jj` (add `Repo::init_internal_git(path, settings)` wrapping `Workspace::init_internal_git(.., gix::hash::Kind::Sha1)` in this ticket if R0.04 did not).
- **Each iteration must start from a known state.** For "snapshot after N mutations", the bench's setup closure applies `mutate(modify = N)` with a per-iteration seed and the routine snapshots; the teardown is the next iteration's mutation (files are modified in place, so there is no restore step; the tree drifts but stays the same size). Use `iter_batched` with `BatchSize::PerIteration`, sample size 10, measurement time 30 s for `medium`.
- **Snapshot limits:** set `max_new_file_size` to 16 MiB for benches so the generator's 8 MiB binaries are tracked rather than reported as untracked; the no-op snapshot should find nothing to do.
- **Output:** criterion's `target/criterion/` directory plus a plain-text summary produced with `--output-format bencher` captured to `bench-results.txt`. Both uploaded with `actions/upload-artifact@v4`, retention 90 days. No comparison or comment on PRs yet.
- **Benchmarks are not run on PRs**, only on `main` pushes and the schedule. PR CI compiles them (`cargo bench --no-run` is part of `just build` via `--all-targets`) so they cannot bit-rot.

## Deliverables

### `crates/reef-lib/Cargo.toml`

```toml
[dev-dependencies]
criterion.workspace = true

[[bench]]
name = "snapshot"
harness = false
```

### `crates/reef-lib/benches/common/mod.rs`

```rust
pub struct Fixture { pub root: PathBuf, pub preset: Preset, pub seed: u64 }

pub fn fixture() -> Fixture;            // reads REEF_BENCH_PRESET, builds tree + jj repo if absent
pub fn runtime() -> tokio::runtime::Runtime;   // current-thread is fine; jj-lib does blocking I/O
```

Fixture setup: `reef_testing::synth::generate(root, &Spec::preset(p), seed, false)`; if `root/.jj` is absent, `Repo::init_internal_git`, then open and take one initial snapshot so later benches measure incremental cost, not the first full scan. Record first-snapshot time to stderr; it is the "O(repository size)" baseline worth knowing.

### `crates/reef-lib/benches/snapshot.rs`

Benchmarks, all in group `snapshot/<preset>`:

1. `noop`: `Repo::snapshot` on an unchanged tree. Measures the scan cost jj pays to discover nothing changed. This is the number Phase 1's watcher-driven snapshots must beat.
2. `modify_1`, `modify_50`, `modify_500`: `mutate(modify = N)` in setup, `snapshot` in routine.
3. `add_50`: `mutate(add = 50)`.
4. `op_log_100`: `Repo::op_log(100)` after the fixture has at least 100 ops (the mutation benches create them; if fewer exist, loop snapshots in setup until 100).
5. `open`: `Repo::open` on the fixture; measures load cost (reads op heads, view, index).

Throughput reporting: set `group.throughput(Throughput::Elements(files_in_tree))` for `noop` so criterion prints files/second.

### `.github/workflows/bench.yml`

```yaml
name: Benchmarks

on:
  push:
    branches: [main]
  schedule:
    - cron: "17 6 * * 1"     # Mondays 06:17 UTC: large preset
  workflow_dispatch:
    inputs:
      preset:
        description: Synthetic repo preset
        default: medium
        type: choice
        options: [small, medium, large]

permissions:
  contents: read

jobs:
  bench:
    name: bench ${{ matrix.os }}
    runs-on: ${{ matrix.os }}
    timeout-minutes: 90
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-24.04, macos-15]
    env:
      REEF_BENCH_PRESET: ${{ github.event_name == 'schedule' && 'large' || inputs.preset || 'medium' }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions-rust-lang/setup-rust-toolchain@v1
      - uses: extractions/setup-just@v3
      - name: Run benchmarks
        run: cargo bench --workspace -- --output-format bencher | tee bench-results.txt
      - name: Fixture summary
        run: cat target/bench-fixtures/*/.reef-synth.json | jq -c '{files,dirs,bytes}' || true
      - uses: actions/upload-artifact@v4
        with:
          name: bench-${{ matrix.os }}-${{ env.REEF_BENCH_PRESET }}-${{ github.sha }}
          path: |
            bench-results.txt
            target/criterion/
          retention-days: 90
```

Do not set `RUSTFLAGS=-D warnings` here; benches are compiled by CI already, and this workflow should not fail on a lint.

## Implementation notes

- `cargo bench` builds with the `bench` profile (release + debug assertions off). `[profile.release] debug = 1` from R0.01 applies; good for `perf`/Instruments.
- criterion and `-D warnings`: `cargo bench --no-run` under `just build` compiles benches with warnings as errors in CI; keep benches lint-clean.
- The tokio runtime: build one `Runtime` per bench file and `block_on` inside the routine; do not use `#[tokio::main]`.
- Fixture location must be inside `target/` so `cargo clean` removes it and `.gitignore` already covers it.
- `large` fixture generation plus the initial snapshot on the macOS runner may take 5 to 10 minutes; the 90-minute timeout is for the scheduled run.
- Snapshot benches mutate the fixture; `noop` must therefore run a snapshot in its own setup once (so the tree is clean) before measuring.

## Acceptance criteria

- [ ] `cargo bench -p reef-lib` runs to completion locally on the `medium` preset and produces `target/criterion/snapshot/medium/*/report/index.html`.
- [ ] `just bench-quick` finishes in under 3 minutes locally including fixture generation.
- [ ] `bench.yml` succeeds on a `workflow_dispatch` run with `preset: medium` on both OSes and uploads two artifacts containing `bench-results.txt` and `target/criterion/`.
- [ ] `bench-results.txt` contains lines for all seven benchmarks in `test ... bench:` bencher format.
- [ ] `docs/benchmarks.md` has the baseline table filled from that run.
- [ ] `cargo clippy --workspace --all-targets -- -D warnings` stays clean with the benches present.

## Out of scope

- Regression thresholds and failing builds on slowdowns (RX.06).
- Comparing across commits in CI (consider `critcmp` or `bencher.dev` under RX.06).
- Workspace creation and disk usage benches (R1.12).
- Benchmarks of the git backend's object writes separately from snapshotting.

## Risks

- criterion 0.8 API drift from what is written here; adjust to the real API and keep the benchmark names.
- GitHub-hosted runners are noisy; the artifacts are for trend reading, not for precise numbers. Say so in `docs/benchmarks.md`.
- jj's first snapshot of 100k files writes 100k git blobs into the internal git store; if it exceeds the timeout on macOS, run `large` on Linux only in the schedule and note it.
