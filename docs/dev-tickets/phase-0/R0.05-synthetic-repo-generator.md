# R0.05 Synthetic repository generator

Phase 0 · Size S · Depends on: R0.01 · Unblocks: R0.06, R1.10, R1.21

## Context

Phase 0 exit criterion: "A synthetic repository generator produces a 100k-file tree for benchmarks." Phase 1's exit criteria measure twenty workspaces on "the 100k-file synthetic repo", and R1.21 fills disks and kills agents against it. The generator therefore has to be deterministic (same seed, same bytes, on both platforms), fast enough to run in CI setup, and shaped like real source trees rather than flat directories of random bytes: realistic depth, fan-out, file size distribution, a handful of large binaries, and the ability to mutate a chosen number of files so a snapshot has something to find.

`reef-testing` (created by R0.01, `publish = false`, no reef dependencies) is where this lives, as a library plus a `reef-synth` binary.

## Decisions

- **Library first, binary second.** `reef_testing::synth::{Spec, generate, mutate, Manifest}` is the API benches and tests use; `reef-synth` is a clap wrapper over it.
- **Determinism:** `rand_chacha::ChaCha8Rng::seed_from_u64(seed)` for all randomness. `StdRng` is not stable across `rand` versions. Every derived decision (path names, sizes, contents, which files `mutate` picks) comes from that one stream in a fixed order, so the generator is single-threaded by construction. Parallel *writing* is allowed only if content generation stays sequential (generate `(path, bytes)` in order, write with a thread pool). Measure first; 100k small files should write in well under 30 s on APFS and ext4 single-threaded.
- **Tree shape:** parameterized by `files`, `max_depth`, `fan_out` (directories per directory, Poisson-ish around the mean), and `files_per_dir` mean. Directory and file names drawn from a fixed word list (embedded, about 200 plausible identifiers like `auth`, `handlers`, `migrations`, `utils`) with numeric suffixes to avoid collisions. Extensions drawn from a weighted list: `.rs .py .ts .go .md .json .toml .yaml .txt` with weights favoring code. Content is pseudo-source: lines of 20–80 chars built from the word list and punctuation, so sizes are realistic and the bytes are compressible like code (matters for jj's git backend and later chunking benchmarks).
- **Size distribution:** log-normal with configurable median (default 2 KiB) and a cap (default 256 KiB) for text files. Separately, `binaries` large files (default 3) of `binary_size` each (default 8 MiB) at random depths with `.bin`/`.png`/`.wasm` extensions, contents from the RNG (incompressible). This exercises jj's `max_new_file_size` path (1 MiB default) in benches, so benchmarks must configure the limit explicitly; R0.06 handles that.
- **Manifest:** `generate` returns and writes `<root>/.reef-synth.json` listing spec, seed, total bytes, file count, directory count, the list of binary paths, and a BLAKE3-free "fingerprint" (the seed and spec are the identity; do not hash 100k files on every run). Presence of the manifest with a matching spec and seed lets callers skip regeneration (`generate` checks and returns early unless `force`).
- **`mutate`:** given root, seed, and `count`, picks `count` existing text files from the manifest deterministically, appends or replaces one line, and returns the changed paths. Also supports `--add N` (new files in existing dirs) and `--delete N`. Updates the manifest. This is what "snapshot after 50 changes" benchmarks use.
- **Presets:** `small` (1,000 files, depth 4), `medium` (10,000, depth 5), `large` (100,000, depth 6), `xl` (1,000,000, depth 7; opt-in only, not used in CI). Named so tickets can say "the large preset".
- **No VCS initialization here.** `reef-testing` cannot depend on jj-lib (dependency rule from R0.01). R0.06 initializes the jj repo around the generated tree. The generator writes a top-level `.gitignore` with `target/`, `node_modules/`, `.reef-synth.json` so the manifest never enters a snapshot.
- **Ignored and hidden paths:** generate a few `target/`-style ignored directories with files in them (default 2% of files) so ignore handling is exercised by default. Flag `--no-ignored` turns it off.
- **Symlinks and permissions:** generate `symlinks` (default 10) relative symlinks to files in the tree and mark `executables` (default 1% of files) with mode 0755 on Unix. These are what R1.09 conformance tests need. Windows: skip symlinks, no error.

### `crates/reef-testing/src/synth/mod.rs`

```rust
#[derive(Clone, Debug, Serialize, Deserialize, PartialEq)]
pub struct Spec {
    pub files: u64,
    pub max_depth: u8,
    pub fan_out: f64,
    pub files_per_dir: f64,
    pub median_size: u64,
    pub max_text_size: u64,
    pub binaries: u32,
    pub binary_size: u64,
    pub ignored_fraction: f64,
    pub symlinks: u32,
    pub executable_fraction: f64,
}

impl Spec {
    pub fn preset(name: Preset) -> Spec;
}

#[derive(Clone, Copy, Debug, clap::ValueEnum)]
pub enum Preset { Small, Medium, Large, Xl }

#[derive(Clone, Debug, Serialize, Deserialize)]
pub struct Manifest {
    pub spec: Spec,
    pub seed: u64,
    pub files: u64,
    pub dirs: u64,
    pub bytes: u64,
    pub binaries: Vec<PathBuf>,
    pub text_files: Vec<PathBuf>,   // relative, sorted; needed by mutate
    pub generator_version: u32,      // bump when output for a given (spec, seed) changes
}

pub fn generate(root: &Path, spec: &Spec, seed: u64, force: bool) -> Result<Manifest, SynthError>;
pub fn mutate(root: &Path, seed: u64, ops: MutateOps) -> Result<Mutation, SynthError>;
pub fn load_manifest(root: &Path) -> Result<Option<Manifest>, SynthError>;

pub struct MutateOps { pub modify: u32, pub add: u32, pub delete: u32 }
pub struct Mutation { pub modified: Vec<PathBuf>, pub added: Vec<PathBuf>, pub deleted: Vec<PathBuf> }
```

`text_files` in the manifest for the `large` preset is 100k paths, a few MiB of JSON; acceptable. Store relative paths with forward slashes.

### `crates/reef-testing/src/synth/{names.rs, content.rs, tree.rs}`

- `names.rs`: embedded word list and extension weights; `fn dir_name(rng, idx)`, `fn file_name(rng, idx) -> (String, Ext)`.
- `content.rs`: `fn text(rng, bytes) -> Vec<u8>` producing newline-terminated pseudo-source of approximately `bytes` length; `fn binary(rng, bytes) -> Vec<u8>`.
- `tree.rs`: builds the directory plan first (a `Vec<DirPlan>` with depth and child counts drawn from the RNG), then assigns files to directories until `spec.files` is reached, then writes. Progress to stderr every 10k files when stderr is a terminal.

### `crates/reef-testing/src/bin/reef_synth.rs`

```
reef-synth gen   --out <dir> [--preset large | --files N --depth D ...] [--seed 42] [--force]
reef-synth mutate --root <dir> [--seed 7] [--modify 50] [--add 0] [--delete 0]
reef-synth info  --root <dir>        # prints the manifest summary as JSON
```

`gen` prints the manifest summary (files, dirs, MiB, elapsed) as one JSON line to stdout. Uses `anyhow` for errors. Exit code 2 on usage errors (clap default), 1 on I/O errors.

### `justfile` additions

```just
# Generate the large synthetic repo under target/synth/large (idempotent).

    cargo run -p reef-testing --bin reef-synth --release -- gen --out target/synth/{{preset}} --preset {{preset}} --seed 42
```

### Tests: `crates/reef-testing/tests/synth.rs`

1. `deterministic`: generate `small` twice with seed 1 into two temp dirs; walk both, compare relative path sets and the content bytes of every file (sorted); identical. Also compare manifests.
2. `seed_changes_output`: seed 1 vs seed 2 differ in at least one path.
3. `counts_match_spec`: `small` yields exactly `spec.files` regular files (excluding symlinks and the manifest), `binaries` binaries, `symlinks` symlinks (Unix), and the ignored fraction within ±1% of spec.
4. `size_distribution`: for `medium`, median text size within 25% of `median_size`, no text file above `max_text_size`, every binary exactly `binary_size`.
5. `mutate_is_deterministic_and_disjoint`: `mutate(modify=50, add=5, delete=5)` with seed 7 twice from identical trees yields identical path lists; modified, added, and deleted sets are disjoint; deleted files no longer exist; manifest updated.
6. `regenerate_skips_when_manifest_matches`: second `generate` with same spec/seed returns within 50 ms and does not rewrite files (check mtimes unchanged); `force = true` rewrites.
7. `large_preset_performance` (`#[ignore]`): generate `large` into a temp dir; assert elapsed < 60 s and print it. Run by hand; number goes in the PR.
8. `gitignore_present`: root `.gitignore` contains the manifest filename and the ignored directory names.

## Implementation notes

- Generate the full plan in memory before touching disk; 100k `(PathBuf, size)` entries is a few tens of MB and makes the write loop simple and parallelizable later.
- Use `std::fs::create_dir_all` once per directory from the plan, not per file.
- Use `BufWriter` per file; files are small so `write_all` of a pre-built `Vec<u8>` is enough.
- Content generation must not pull from the RNG in a data-dependent number of calls that varies by platform (for example, do not seed from path hashes that depend on `OsStr` encoding).
- Keep binary sizes and counts out of the hot path: generate them last.
- `fan_out` and `files_per_dir` are means; draw with `rand_distr::Poisson` if `rand_distr` is added, else a simple geometric draw from the RNG. Prefer no extra dependency.

## Acceptance criteria

- [ ] `just synth large` produces `target/synth/large` with 100,000 regular files (verify with `find target/synth/large -type f ! -name .reef-synth.json | wc -l` → 100000 plus 3 binaries plus ignored files; the manifest states exact counts).
- [ ] Same spec and seed produce byte-identical trees on macOS and Linux. Verify by generating `small` with seed 1 on both CI runners, computing `find . -type f | sort | xargs shasum -a 256 | shasum -a 256`, and comparing the two digests printed in the CI logs (add a temporary step to the PR's CI run and remove it, or keep it as a `synth-determinism` job if cheap; the latter is preferred and should be under 30 s).
- [ ] `large` generates in under 60 s on the authoring machine; time recorded in the crate README.
- [ ] All tests in `tests/synth.rs` pass; `large_preset_performance` run once by hand.
- [ ] `reef-synth gen`, `mutate`, and `info` work from the command line with the documented flags.
- [ ] `cargo clippy -p reef-testing --all-targets -- -D warnings` clean.

## Out of scope

- Initializing a jj or git repository around the tree (R0.06 does it for benches; a `--init-jj` flag would require jj-lib here, which the crate layout forbids).
- Realistic git history (many commits); only the working tree is synthetic.
- Content that parses as valid code; symbol-level benches (R2.13+) will need a different generator or real repositories.

## Risks

- 100k-path manifests make `mutate` load a few MiB of JSON; fine for now, switch to a binary manifest if it shows up in bench setup time.
- APFS case-insensitivity: names are lowercase ASCII with numeric suffixes, so no case collisions are possible by construction. Keep it that way.
