# R0.01 Workspace layout and crate roles

Phase 0 · Size S · Depends on: nothing · Unblocks: R0.02, R0.04, R0.05, R0.09

## Context

The repository currently has a Cargo workspace with three placeholder crates that exist only to reserve the names `reef-vcs`, `reef-lib`, and `reef-daemon` on crates.io (all published at 0.0.0). Each has a `Cargo.toml`, a one-paragraph `README.md`, and a `src/lib.rs` holding a doc comment. The workspace `Cargo.toml` is:

```toml
[workspace]
resolver = "2"
members = ["crates/*"]

[workspace.package]
version = "0.0.0"
edition = "2021"
license = "Apache-2.0"
repository = "https://github.com/reef-vcs/reef"
homepage = "https://github.com/reef-vcs/reef"
```

This ticket turns that into the real workspace shape every later ticket builds on. It does not add functionality. The design's architecture section (`docs/design.md`, "Architecture") and the technology table drive the crate boundaries: agents talk to a local daemon over gRPC; the daemon owns snapshots, workspaces, merge, and queries; the CLI and MCP server are thin clients.

## Decisions

- **Four crates.**
  - `reef-lib`: data model, jj-lib embedding, workspace model, merge engine, query layer. No I/O server code, no CLI code. Everything in here must be usable by a process that is not the daemon (tests, benches, future tooling).
  - `reef-daemon`: the long-running service. gRPC API (from R1.03 onward), workspace materialization backends, lease manager, watchers, logging initialization. Library crate plus a `reef-daemon` binary target.
  - `reef-vcs`: the umbrella crate that produces the `reef` binary (CLI, and later `reef mcp`). Also exposes a library that re-exports `reef_lib` and `reef_daemon` so a downstream Rust user can depend on one crate.
  - `reef-testing`: `publish = false`. Synthetic repository generator (R0.05), fixture builders, test helpers. Must not depend on any other reef crate so `reef-lib` can dev-depend on it without a cycle.
- **Dependency direction** is strictly `reef-vcs` → `reef-daemon` → `reef-lib`. `reef-lib` never depends on `reef-daemon`. Enforce by review, and add a unit test in `reef-testing` that parses `cargo metadata` and asserts the edges (see Deliverables).
- **Edition 2024** for the whole workspace. jj-lib 0.46 is edition 2024 and so are its examples; staying on 2021 would make every borrowed snippet need translation.
- **Binaries get a `main.rs` now**, even though they do nothing, so that R0.09 has an edge to initialize logging at and R0.03 has binaries to build. They print the crate name and version and exit 0. No clap yet.
- **Workspace-level dependency table.** All third-party versions are declared once in `[workspace.dependencies]` and referenced with `workspace = true`. Seed the table with everything Phase 0 will use so later tickets only flip `workspace = true` on.
- **Workspace-level lints.** Every crate has `[lints] workspace = true`. R0.02 fills in the lint set; this ticket adds only the plumbing and `unsafe_code = "warn"`.
- **No `src/bin/` directories.** One binary per crate, at `src/main.rs`, named explicitly via `[[bin]]`.
- **Crate-level `README.md` files stay** (crates.io renders them) and are rewritten to describe the crate's role and its position in the dependency graph.

## Deliverables

### `Cargo.toml` (workspace root)

```toml
[workspace]
resolver = "2"
members = ["crates/*"]
default-members = ["crates/reef-lib", "crates/reef-daemon", "crates/reef-vcs"]

[workspace.package]
version = "0.0.0"
edition = "2024"
license = "Apache-2.0"
repository = "https://github.com/reef-vcs/reef"
homepage = "https://github.com/reef-vcs/reef"
authors = ["Reef contributors"]

[workspace.dependencies]
# Internal
reef-lib = { path = "crates/reef-lib", version = "0.0.0" }
reef-daemon = { path = "crates/reef-daemon", version = "0.0.0" }
reef-testing = { path = "crates/reef-testing" }

# Core
jj-lib = "=0.46.0"            # R0.04 turns this on in reef-lib
thiserror = "2"
anyhow = "1"
tracing = "0.1"
tracing-subscriber = { version = "0.3", features = ["env-filter", "json", "fmt", "time"] }
time = { version = "0.3", features = ["formatting", "macros"] }   # RFC 3339 timestamps for the JSON log layer (R0.09)
serde = { version = "1", features = ["derive"] }
serde_json = "1"
tokio = { version = "1", features = ["rt-multi-thread", "macros", "sync", "fs", "time"] }
pollster = "1"
futures = "0.3"
clap = { version = "4", features = ["derive", "env"] }
rand = "0.10"
rand_chacha = "0.10"
tempfile = "3"
camino = "1"

# Dev and bench
criterion = { version = "0.8", features = ["html_reports"] }

[workspace.lints.rust]
unsafe_code = "warn"

[profile.release]
debug = 1          # keep symbols for profiling benches
```

Notes:
- `default-members` excludes `reef-testing` so a bare `cargo build` does not build dev tooling; `--workspace` still includes it. R0.03 CI uses `--workspace`.
- Verify each version above exists with `cargo info <crate>@<version>` as part of this ticket (`cargo update --dry-run` is a no-op here, because `[workspace.dependencies]` entries nothing references are never resolved). `rand` 0.10.3 and `rand_chacha` 0.10.0 were the latest on crates.io on 2026-10-15 and pair with each other; the pair is only used by R0.05.
- Do not add `jj-lib` as a dependency of any crate in this ticket. Adding it costs minutes of compile time and R0.04 owns that step. The entry in `[workspace.dependencies]` is inert until referenced.

## Implementation notes

- Run `cargo fmt` after editing (edition 2024 formatting differs from 2021 in a few places; this avoids a noisy diff in R0.02).
- `cargo publish --dry-run -p reef-lib` must pass. It will fail if a path dependency lacks a `version`. That is why `[workspace.dependencies]` carries `version = "0.0.0"` for internal crates. The dry run compiles the packaged crate against the registry, where `reef-lib` and `reef-daemon` 0.0.0 are empty placeholders, so the `reef-daemon` and `reef-vcs` dry runs pass only while those crates use nothing from their siblings. From R0.09 onward run them with `--no-verify`; a real release bumps all three versions together (R4.17).
- Rust 1.96 is installed locally and edition 2024 compiles on it. R0.02 moves the pin to 1.99.1.
- Delete nothing in `target/`.

## Acceptance criteria

- [ ] `cargo build --workspace` and `cargo test --workspace` pass on the current local toolchain.
- [ ] `cargo metadata --no-deps` lists exactly four workspace members.
- [ ] `./target/debug/reef` prints `reef-vcs 0.0.0`; `./target/debug/reef-daemon` prints `reef-daemon 0.0.0`.
- [ ] `tests/crate_graph.rs` in `reef-testing` passes and fails if an edge `reef-lib → reef-daemon` is added (check by temporarily adding it).
- [ ] `cargo publish --dry-run -p reef-lib`, `-p reef-daemon`, `-p reef-vcs` each succeed (dry-run does not need credentials). `reef-testing` is skipped because `publish = false`.
- [ ] Every crate `Cargo.toml` has `[lints] workspace = true`.
- [ ] `docs/adr/0007-crate-layout.md` exists and follows the template.
- [ ] No crate depends on `jj-lib` yet.

## Verification

```sh
cargo build --workspace
cargo test --workspace
cargo metadata --no-deps --format-version 1 | jq '.packages[].name'
cargo publish --dry-run -p reef-lib && cargo publish --dry-run -p reef-daemon && cargo publish --dry-run -p reef-vcs
./target/debug/reef && ./target/debug/reef-daemon
```

## Out of scope

- Lint levels, rustfmt and clippy config, toolchain pin (R0.02).
- Any jj-lib code (R0.04).
- clap, tracing, error types (R0.09 adds the first real contents of `main.rs`).
- Bumping the version to publish a non-placeholder release.

## Risks

- A version in the table may have moved on; check with `cargo info` and keep majors matched for `rand`/`rand_chacha`.
- `cargo publish --dry-run` may complain about the `readme` path or missing `description`; fix in the manifest, not by removing the check.
