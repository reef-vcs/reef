# R0.09 Error and logging conventions

Phase 0 · Size S · Depends on: R0.01 · Unblocks: R1.03 (daemon skeleton needs the logging init), R1.04 (configuration carries the log options); R1.05's gRPC error mapping builds on the error shape

## Context

R0.04 writes the first real library code and already needs error enums. R1.03 needs structured logs on day one because the daemon is long-running and agents will not read its stderr. Deciding error and logging shape before more than one module exists is cheap; deciding it after Phase 1 is a rewrite. The design calls for structured responses everywhere and for every API call to return the op log entry it created; errors crossing the API must therefore be data, not strings, which starts with the library error types.

## Decisions

- **Libraries use `thiserror` 2 enums, one per module or per operation family**, named `<Thing>Error` (`OpenError`, `SnapshotError`), `#[non_exhaustive]`, with `#[source]`/`#[from]` for causes. No `Box<dyn Error>` and no `anyhow` in `reef-lib` or in `reef-daemon`'s library code. Variants carry the identifiers a caller needs to act (`path`, `workspace_id`, `op_id`), never pre-formatted messages. `Display` text is lowercase, no trailing period, no "error:" prefix, and does not repeat the source's message (so chained display reads naturally).
- **Binaries use `anyhow`** in `main.rs` and nowhere else. `main` returns `anyhow::Result<()>`; the top-level error is printed with its chain (`{:#}`) and exits 1. Test code may use `anyhow` and `unwrap` (clippy config from R0.02 allows it in tests).
- **No panics for expected conditions.** `unwrap`/`expect` in library code need a comment proving the invariant; clippy warns on them (R0.02). `unreachable!` is acceptable with a comment.
- **Every library error type implements a `kind()` method returning `ErrorKind`**, a small `#[non_exhaustive]` enum shared across the workspace (`NotFound`, `AlreadyExists`, `InvalidArgument`, `Conflict`, `Unavailable`, `PermissionDenied`, `Internal`, `Io`). This is the bridge to gRPC status codes in R1.05 and to CLI exit codes in R1.22; defining it now keeps every error mappable without a giant match later.
- **`tracing` for all diagnostics.** No `log` crate, no `println!`/`eprintln!` outside `main.rs` and CLI output paths (lint from R0.02). Events are structured: `tracing::info!(workspace_id = %id, change_id = %cid, "snapshot taken")`; the message is a short lowercase phrase and the fields carry the data. Field names are standardized in a `reef_lib::telemetry::fields` module of `&str` constants so greps and dashboards work: `repo`, `workspace_id`, `change_id`, `op_id`, `commit_id`, `agent_id`, `lease_id`, `backend`, `path`, `elapsed_ms`, `error`.
- **Spans per operation**: every public async entry point in `reef-lib` and every RPC handler later gets `#[tracing::instrument(skip_all, fields(...))]` with the identifying fields and `err` so errors are logged once, at the boundary, with their chain. Inner code does not log errors it returns.
- **Levels:** `error` = the daemon could not do what it was asked and someone must look; `warn` = degraded but handled (fallback backend, retry); `info` = state transitions (workspace created, lease expired, snapshot taken); `debug` = per-step detail; `trace` = per-file or per-request payload detail. Default filter `info`.
- **Subscriber configuration lives in `reef-daemon`** (`reef_daemon::logging`), because the CLI depends on the daemon crate and both binaries use the same init. `reef-lib` only emits.
- **Environment:** `REEF_LOG` holds the `EnvFilter` directive (default `info`), `REEF_LOG_FORMAT` is `pretty` | `json` (default: `pretty` when stderr is a terminal, `json` otherwise). Logs go to stderr. `RUST_LOG` is honored as a fallback if `REEF_LOG` is unset, because every Rust user tries it first.
- **JSON format** is `tracing-subscriber`'s `json` layer with `flatten_event(true)`, `with_current_span(true)`, `with_span_list(false)`, timestamps in RFC 3339 UTC, and a `target` field. Field names above appear as top-level keys. This is the format the daemon's log file will use in R1.03.
- **Secrets never appear in fields.** Session keys and tokens (Phase 3) are `Debug`-redacted; the convention is written now so the types are built that way.

## Deliverables

### `crates/reef-lib/src/error.rs`

```rust
/// Coarse classification shared by every error type in the workspace.
/// Maps to gRPC status codes and CLI exit codes at the edges.
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
#[non_exhaustive]
pub enum ErrorKind { NotFound, AlreadyExists, InvalidArgument, Conflict, Unavailable, PermissionDenied, Io, Internal }

/// Implemented by every error type that crosses a crate boundary.
pub trait Classify { fn kind(&self) -> ErrorKind; }
```

Implement `Classify` for the R0.04 error types (`OpenError`, `SnapshotError`, `OpLogError`, `UndoError`) in their modules. Coordinate with R0.04 if it is in flight: whichever lands second adds the impls.


Note: `tracing` macros take field names as identifiers, not strings, so the constants serve documentation, tests, and log consumers; the macros must use the same spelling. Add a unit test in `reef-lib` that greps `crates/reef-lib/src/**/*.rs` (located from `env!("CARGO_MANIFEST_DIR")`) for `tracing::(info|warn|error|debug|trace)!` invocations and asserts every `name = ` field is in the allowed set or ends in `_count`/`_ms`/`_bytes`. Binaries are outside its scope, which is why `main.rs` may log `version`. Keep the test simple (regex over lines); it exists to stop drift, not to parse Rust.

Also in this file: `pub struct Timed` helper or a `fn elapsed_ms(start: Instant) -> u64`, used by the R0.04 snapshot path to emit `elapsed_ms`.

### `crates/reef-daemon/src/logging.rs`

```rust
#[derive(Clone, Debug)]
pub struct LogOptions {
    pub filter: Option<String>,   // REEF_LOG, then RUST_LOG, then "info"
    pub format: LogFormat,        // Pretty | Json | Auto
}

#[derive(Clone, Copy, Debug)]
pub enum LogFormat { Auto, Pretty, Json }

impl LogOptions { pub fn from_env() -> Self; }

/// Installs the global subscriber. Returns an error if one is already set.
pub fn init(opts: &LogOptions) -> Result<(), LoggingError>;
```

Uses `tracing_subscriber::registry()` with an `EnvFilter` and either `fmt::layer().pretty()`-style human output (compact, not the multi-line `pretty()`; use `fmt::layer().with_target(false).with_timer(...)`) or the JSON layer described above. Terminal detection via `std::io::IsTerminal` on stderr. Add `tracing-subscriber` and `tracing` to `reef-daemon` dependencies (workspace entries exist).

### `docs/adr/0009-error-and-logging-conventions.md`

Template sections. Context: structured API, long-running daemon, agents as log consumers, gRPC mapping ahead. Decision: everything under "Decisions" above, condensed. Consequences: every new error enum needs a `Classify` impl (cheap); no free-form error strings means adding a variant when a new failure appears, which is the point; JSON logs are the daemon's default, so human readers use `REEF_LOG_FORMAT=pretty`. Alternatives: `anyhow` everywhere (loses the ability to map errors to status codes without string matching); `snafu` (fine, but `thiserror` is what jj-lib and most of the ecosystem use); `log` + `env_logger` (no spans, no structured fields); `slog` (unmaintained relative to tracing).

## Implementation notes

- `tracing-subscriber` features needed: `env-filter`, `fmt`, `json`, and `time` for RFC 3339 timestamps through `fmt::time::UtcTime`, which also needs the `time` crate with `formatting` and `macros`. Both are already in `[workspace.dependencies]` from R0.01; reference them with `workspace = true`.
- `#[instrument]` on async fns that hold `&mut self` across awaits works; `skip_all` avoids requiring `Debug` on every argument.
- Clippy pedantic will flag `missing_errors_doc`; allowed in R0.02.
- Test `logging::init` in an integration test with `REEF_LOG_FORMAT=json` by capturing stderr from a child process (`std::process::Command` on the built `reef-daemon` binary via `env!("CARGO_BIN_EXE_reef-daemon")`) and asserting the first line parses as JSON with `level`, `timestamp`, `message == "starting"`, and `version` keys. Same for `pretty` asserting it is not JSON and contains `starting`.
- Test that `REEF_LOG=debug` enables a `debug!` event and the default does not.

## Acceptance criteria

- [ ] `reef_lib::error::{ErrorKind, Classify}` exist and every public error enum in `reef-lib` implements `Classify`.
- [ ] `reef_lib::telemetry::fields` exists and the field-name drift test passes.
- [ ] `reef_daemon::logging::init` works in `pretty` and `json` modes; the two child-process tests pass on both OSes.
- [ ] `./target/debug/reef-daemon 2>&1 | head -1` is a JSON object when stderr is a pipe; in a terminal it is a human-readable line.
- [ ] `grep -rn 'println!\|eprintln!' crates/*/src` returns only lines inside `main.rs` files or lines with an `allow(clippy::print_` attribute and a reason.
- [ ] `grep -rn 'anyhow' crates/reef-lib/src crates/reef-daemon/src` returns nothing outside `main.rs`.
- [ ] ADR 0009 exists; the ADR index row is updated.
- [ ] `just ci` passes.

## Out of scope

- Mapping `ErrorKind` to `tonic::Status` (R1.05) and to CLI exit codes (R1.22).
- Log files, rotation, and the daemon's log directory (R1.03).
- OpenTelemetry export, metrics (RX.03).
- Redaction machinery for secrets; only the rule is stated now.

## Risks

- `tracing-subscriber`'s JSON layer formatting options have shifted between minor versions; pin to the workspace version and test the output shape rather than assuming field names.
- If R0.04 and R0.09 land in either order, one of them must add the `Classify` impls; say which in the PR.
