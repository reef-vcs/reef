# R2.24 `reef schema`

Phase 2 · Size M (the row says S; see "Size") · Depends on: R2.01 (`reef_api::FILE_DESCRIPTOR_SET`), R2.05 (the thin `reef` and `reef_client::json`), R2.27 (the VCS commands and their JSON), R2.13 (the tool table whose output shapes this publishes), and issue #114 (the brief views, ADR 0045) · Unblocks: none listed (R2.25's packages and R2.06 and R2.07's SDKs can read what it prints; R2.17's re-measure of the MCP fixed cost is settled here)

## Context

A harness that wants Reef as tools has three partial sources today, and a person has to put them together. `reef --help` describes the commands in prose. `reef guide -o json` lists every leaf command as its words and nothing else (`cli/guide.rs:50`). `reef mcp`'s `tools/list` gives input schemas for 21 tools and no output shapes, because ADR 0035 decision 5 left `outputSchema` to this ticket. The API's descriptor set is built with comments in `reef-api` and exported as a constant, but nothing outside Rust can get at it. No source says what any command prints.

The row asks for one command that prints the CLI's command tree and the API's services and messages as JSON Schema, and the API as a protobuf descriptor set, so a harness can generate tool definitions without a person writing them. Four earlier briefs promised work to this one:

- **ADR 0035 decision 5 and R2.13** (`R2.13-mcp-server.md` lines 127, 309, 341): derive JSON Schemas from `reef_client::json` and add them to the MCP tools as `outputSchema`, list wrappers included.
- **R2.05** (lines 326, 356, 363): read the command tree from clap and the API from `reef_api::FILE_DESCRIPTOR_SET`, and derive output schemas from `reef_client::json`, "where every output type lives".
- **R2.27** (lines 119, 340, 378): the VCS commands' types live in `reef_client::json` so their schemas are derived in one place.
- **R2.17** (lines 226, 469): R2.24 re-measures the MCP fixed cost and the break-even.

Three open issues bear on it. **#116**: the tool list costs more than six questions save (break-even 15.2 questions), and declaring output schemas would make it larger. **#122**: a live agent's first call is `reef --help`, so every line added to it is paid in every session. **#114 and #123**: the piped default is now brief JSON (ADR 0045), so a schema has to describe what is actually printed, in each form.

### What was verified while writing this ticket

Reef at `6228101` (#144 merged; API revision 14). Paths are under `crates/` unless they start with `docs/`.

## Decisions

### Size

M. The row's S assumed the schemas fall out of existing types. They do, but four pieces have to be written and each needs its own test: a walk of clap's tree into input schemas; a table from every leaf command to what it prints, in each form; a converter from the descriptor set to JSON Schema under the proto3 JSON mapping; and output schemas on the MCP tool table. Deriving `JsonSchema` on about 100 types is mechanical, but the enum-valued string fields need a helper so their values are listed. Checking that real output validates needs a validator and a test that runs every command. No API change, no daemon change, no new crate.

### The command

```
reef schema [PART [NAME]...]
reef schema --descriptor-set
```

- **`reef schema`** prints the whole document (below).
- **`PART`** is `cli`, `mcp` or `api`: only that part, with the `$defs` it reaches.
  - `reef schema cli ws list`: one command. Its words resolve as clap resolves them (names, visible aliases, unique prefixes), so `reef schema cli workspace ls` is the same command.
  - `reef schema mcp get_status`: one tool.
  - `reef schema api WorkspaceService`, `reef schema api reef.api.v1.Workspace`: one service with its methods' messages, or one message, by full name or by its name in `reef.api.v1`.
  - A name that matches nothing fails with kind `not_found`, reason `SCHEMA_NAME_NOT_FOUND`, a hint naming the part, and `next: ["reef", "schema", "<part>"]`. It exits 3.
- **`--descriptor-set`** writes the bytes of `reef_api::FILE_DESCRIPTOR_SET` to stdout, a serialized `google.protobuf.FileDescriptorSet` with source info, whatever `-o` says, as `file read` writes bytes. It conflicts with `PART`.
- **Always JSON.** A schema has no text form. Pretty-printed with `-o json`, `-o text`, or a terminal; compact with `-o brief` or on a pipe, ending in a newline. There is no `TextRender`.
- **Offline.** It reads no configuration, connects to no daemon, starts none and registers nothing, like `guide` and `completions`. It describes the binary that runs. `--remote` and `REEF_REMOTE` are accepted and ignored, as `guide` ignores them; the document's `reef.version` says which binary answered.
- **In `--help`**, after `mcp`: "Print the commands, MCP tools and API as JSON Schema, to generate tool definitions." One line, about 90 bytes on a help #122 counts. It is not in `docs/agent-guide.md`: the reader is whoever generates tool definitions, not the agent.

### The document

One JSON object, which is also a JSON Schema 2020-12 resource: every member that is not a keyword is an annotation, and every schema lives under `$defs`, so `{"$ref": "urn:reef-vcs:schema:0.3.0#/$defs/Inspected"}` resolves against it.

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "urn:reef-vcs:schema:<version>",
  "reef": {"version", "commit", "target", "schema_version": 1,
           "api_package": "reef.api.v1", "api_revision": 14, "api_digest"},
  "cli": {
    "global": {"input": {…}, "argv": {…}},
    "commands": [{"command", "aliases", "about", "input", "argv", "output"}],
    "errors": {"document": {"$ref": "#/$defs/ErrorDocument"},
               "exit_codes": {"ok": 0, "internal": 1, "invalid_argument": 2, …}}
  },
  "mcp": {"command": ["reef", "mcp"], "instructions", "tools": [{…}],
          "error_result": {…}},
  "api": {"services": {"reef.api.v1.WorkspaceService": {"description", "methods": {…}}}},
  "$defs": {…}
}
```

- **`$id`** is a URN with the CLI's version, since Reef has no domain that would serve it. `reef.commit` and `reef.target` are `--version`'s (`build.rs`). `api_digest` is `reef_api::API_DIGEST`.
- **`$defs` names.** `reef_client::json`'s types by their Rust name (`Workspace`, `RepoStatus`); the brief views as `brief.<Name>`; the CLI's own types as `cli.<Name>`; the MCP wrappers as `mcp.<Name>`; API messages by full name (`reef.api.v1.Workspace`). The renames are `#[schemars(rename = "…")]`, which leaves serde alone.
- **Order.** Keys print sorted (the build has no `serde_json/preserve_order`, ADR 0035), `commands` in clap's order, `tools` in `TOOLS`' order, methods in declaration order. Two runs print the same bytes.

### Commands: inputs from clap

Each leaf command (the same set as `guide::leaf_commands()`) gets:

- **`command`**: its words. **`aliases`**: every visible alias spelling, as word lists. **`about`**: clap's `about`.
- **`input`**: a plain JSON Schema object a harness can use as a tool's input schema unchanged. One property per argument that is not hidden and not global, keyed by clap's id (the field name, `snake_case`), with the help as `description`, `required` from clap, and `default` when clap has one. The value type, from `ValueParser::type_id()`:

  | clap | JSON Schema |
  | --- | --- |
  | `ArgAction::SetTrue`, `SetFalse` | `boolean` |
  | `ArgAction::Count` | `integer`, `minimum: 0` |
  | `u8` to `u64`, `usize` | `integer`, `minimum: 0` |
  | `i32`, `i64` | `integer` |
  | `String`, `PathBuf`, `OsString` | `string` |
  | possible values (`ValueEnum`, a string list) | `string` with `enum` of the visible names |
  | `Duration` | `string`, described "a duration such as `30s` or `2h`" |
  | `history::when` | `string`, described "an RFC 3339 time or a duration ago" |
  | `(String, String)` (`--env KEY=VALUE`) | `string`, `pattern: "^[^=]+="` |
  | `ArgAction::Append`, or more than one value | `array` of the above |

  Any other type fails test 3, so a new one is classified on purpose.
- **`argv`**: how to turn an input object back into words, beside `input` so `input` stays plain. Per property: `{"flag": "--at-op"}`, with `"short": "-r"` when there is one, or `{"position": 0}` for a positional, `{"after_dashes": true}` for a `trailing_var_arg` (`ws run -- <command>`), `"repeat": true` when an array is passed as the flag once per element, and `"conflicts_with"` from `Command::get_arg_conflicts_with`. A boolean flag is passed when true; a count is the flag that many times.
- **`global`**: the global flags once, in the same two forms, not repeated on every command.
- **`output`**: below.

The leaf `reef` alone (the guide) is not a command entry; `guide` is.

### Outputs from the JSON types

`crates/reef-vcs/src/cli/schema/outputs.rs` holds `OUTPUTS`, one row per leaf command (under `cli`, whose modules own the CLI's output types):

```rust
pub(crate) struct OutputRow {
    pub(crate) command: &'static [&'static str],
    /// What `-o json` prints; `None` when stdout is never JSON.
    pub(crate) json: Option<Shape>,
    /// What the brief form prints: the same, or a view.
    pub(crate) brief: Brief,
    /// What a pipe gets without `-o`.
    pub(crate) piped: Piped,         // Brief | Text
    /// One value per line (`op watch`, `presence watch`).
    pub(crate) lines: bool,
    /// The value ends stdout, after another program's output (`ws run`).
    pub(crate) last_value: bool,
    /// Exits with another program's code and still prints the result
    /// (`ws run`, a failed `store build`).
    pub(crate) result_on_failure: bool,
    /// What stdout carries when `json` is `None`, or a note on placement.
    pub(crate) note: Option<&'static str>,
}
```

`Shape` is `Object(fn(&mut SchemaGenerator) -> Schema)` or `List(…)`, built by `object::<T>()` and `list::<T>()`; `Brief` is `Same` or `View(Shape)`. The document's `output` is:

```json
{"json": {"$ref": "#/$defs/Inspected"}, "brief": {"$ref": "#/$defs/Inspected"},
 "piped": "brief", "lines": false, "last_value": false, "result_on_failure": false}
```

- **Rows decided here.** `ws list` → list of `Workspace`, brief list of `brief.Workspace`; `status` → `RepoStatus`, brief `brief.RepoStatus`; `diff` → `Diff`, brief `brief.Diff`; every other command's brief is `Same`, since it prints its full JSON compactly (ADR 0045 decision 2). `here` → `oneOf` `cli.Inside` and `cli.Outside`, told apart by `in_workspace` (`const` true or false). `init` → `oneOf` `cli.InitJson` and `cli.PrintJson`. `config show` → `{"type": "object"}`, noted "the daemon's configuration as `reef-daemon config show --json` prints it". `ws run`, `config`, `guide`, `init` and `file read` default to `text`, and their `-o brief` is their JSON, compact. `ws run`'s note: "the command's own output, then the report as the last line". `mcp` → `None`, "the MCP protocol"; `completions` → `None`, "a shell script"; `daemon run` → `None`, "nothing; the daemon's logs go to stderr". `file read` → `FileRead`, noted "with `-o json`; otherwise the file's bytes". `schema` → `{"type": "object"}`, "this document". A `#[serde(transparent)]` wrapper's row names the inner type.
- **Errors.** Any command that fails prints `ErrorDocument` in the JSON forms (ADR 0025). It is not repeated per command: `cli.errors.document` says so once, with the exit code of each kind from `reef_error::ErrorKind::exit_code` and `kind_text`.
- **The CLI's own types stay where they are** and derive `JsonSchema` there. R2.05's "where every output type lives" was never quite true, and moving 13 CLI-specific types into `reef-client` for this would be churn with no reader.

### Deriving the schemas

- **`reef-client` depends on `schemars`** (workspace, as `reef-vcs` has it). Every `Serialize` type in `json` and `brief` adds `schemars::JsonSchema` to its derive. Doc comments become `description`s, which is what they were written as.
- **Settings**: `reef_client::schema::settings()` returns `SchemaSettings::draft2020_12().for_serialize()`. Output types are described as they serialize, so `Option<T>` is required and nullable, `skip_serializing_if` is optional, and `#[serde(skip)]` fields (`Lease::expires_at_ms`, `Presence`'s) are absent. Nothing sets `additionalProperties: false`, so a newer Reef's added keys (ADR 0034's additive rule) never fail an older schema.
- **Enum-valued strings list their values.** A field filled by a name function gets `#[schemars(schema_with = "…")]` with a function built from that name function: `reef_client::schema::names(f)` evaluates `f` over `0..=255` and `i32::MAX`, collects the distinct names in first-seen order (`unknown` among them, from `i32::MAX`), and returns `{"type": "string", "enum": […]}`, with `null` added for an `Option` field. The values come from the code that prints them, so they cannot drift; no list is written by hand.
- **Brief views** derive `JsonSchema` as `brief.<Name>`, so their `required` and optional keys come from the same `skip_serializing_if` attributes that print them. Their fields carry no doc comments; `reef_client::schema::describe_brief` copies each property's `description` (and `enum`) from the full type's same-named property, which ADR 0045's subset rule makes the same key with the same value. Test 7 checks the subset at the schema level.
- **The MCP wrappers** in `mcp/results.rs` derive `JsonSchema` as `mcp.<Name>`.

### The API from the descriptor set

`crates/reef-vcs/src/schema/api.rs` decodes `FILE_DESCRIPTOR_SET` into a `prost_reflect::DescriptorPool` (`reef-vcs` gains `prost-reflect` as a normal dependency, no features) and writes the `reef.api.v1` package. No crate does this conversion for prost-reflect, and the package uses a handful of features, so it is about 250 lines in the repository. The schemas describe **canonical proto3 JSON as a printer emits it** (the mapping in the protobuf documentation), which is what a gateway that turns tool calls into requests sends and receives through protobuf-es's or prost-reflect's JSON:

- **Messages** are `$defs` entries under their full names, `type: object`, properties keyed by `json_name` (lowerCamelCase), with no `required` (proto3 has no required fields) and no `additionalProperties: false`. The leading comment is the `description`, the message's and each field's.
- **Scalars**: `bool` → `boolean`; `string` → `string`; 32-bit integers → `integer` with their range; 64-bit integers → `string`, `pattern: "^-?[0-9]+$"` (`^[0-9]+$` unsigned), since printers emit them as strings; `bytes` → `string`, `contentEncoding: base64`. `float` and `double` are not used; the converter maps them to `number` and test 5 has none to check.
- **Enums** → `string` with `enum` of the value names (`WORKSPACE_STATE_ACTIVE`), as printers emit them. Parsers also accept numbers; the schema does not list them.
- **`repeated`** → `array`; **`map<K, V>`** → `object` with `additionalProperties` of `V`.
- **`oneof`**: its members are ordinary optional properties, and the message gains one `{"not": {"required": [a, b]}}` per pair of members under `allOf`, so two members set is invalid. Proto3 `optional` (a synthetic oneof) is an ordinary property.
- **Well-known types** are inlined, not `$defs`: `Timestamp` → `string`, `format: date-time`; `Duration` → `string`, `pattern: "^-?[0-9]+(\\.[0-9]{1,9})?s$"`. Any other `google.protobuf` message referenced from the package fails test 4.
- **Services**: `api.services[<full name>]` is `{description, methods}`; each method `{path, input: {$ref}, output: {$ref}, client_streaming, server_streaming, access, idempotency, description}`. `access` is `read`, `write` or `admin` from `reef_api::access(path)`; `idempotency` is the method's `idempotency_level` (`no_side_effects`, `idempotent`, or `unknown`).
- **The v0 package** (`reef.daemon.v0`) is not described; it is served only to name a version mismatch.

Comments are the API's, written for implementers (ADR 0035 decision 12 kept them out of the MCP tools for that reason). Here they belong: the document is read once by whoever generates code, not by an agent in every session.

### MCP tools, and why `tools/list` does not change (#116)

- **Each tool gets an output schema.** `ToolDef` gains `output: fn() -> Arc<JsonObject>`, built as its input schema is: a self-contained root schema of the result type (`Inspected`, `mcp.ChangeAt`, `mcp.Workspaces` over `brief.Workspace`, and so on) under `for_serialize()`, run through the same `compact` and `inline_enums` as the inputs. It is self-contained (its own `$defs`), since a tool definition cannot point into another document.
- **`reef schema mcp` publishes the definitions**: each tool exactly as `tools/list` gives it (`name`, `title`, `description`, `inputSchema`, `annotations`), plus `outputSchema`; the server's `instructions`; and `error_result`, the self-contained schema of `ErrorDocument`, which `isError` results carry.
- **`tools/list` stays as it is, with no `outputSchema`.** This departs from ADR 0035 decision 5 and R2.13's three lines, and is the decision the ADR records. Three reasons:
  1. **Cost.** Every session that loads the server pays for `tools/list` whether it calls a tool or not; at 21,211 bytes it already takes 15.2 questions to repay (#116). The output schemas are larger than the inputs (`RepoStatus` alone reaches `Workspace`, `Lease`, `Change`, `FileChange` and more), so declaring them would raise the break-even further.
  2. **What a model does with it.** A harness shows the result to the model either way; the shape in the description ("Returns {workspaces, next_page_token}") is what tells the model what to expect, in a sentence.
  3. **Errors.** MCP requires structured results that conform to a declared `outputSchema`, and some clients check error results against it as well. Reef's error results are `{"error": …}` (ADR 0035 decision 6), so a declared schema would have to be `anyOf` the result and the error, on every tool.

  A harness that wants output schemas, to type a client or check results, reads them from `reef schema mcp`. If #116 is resolved by deferred loading, where a tool's definition is fetched only when it is used, declaring them becomes cheap; that is a change for #116's ticket, behind its own measurement.
- **R2.17's re-measure.** `tools/list` and the instructions are unchanged byte for byte, so the fixed cost and the break-even are unchanged and no `tokens.yml` dispatch is needed. The PR does two things instead. Test 12 prints what `tools/list` would cost with the output schemas declared, in bytes, and the PR records that number as a comment on #116. And `docs/token-benchmark.md`'s fixed-cost section gains one sentence saying R2.24 publishes output schemas through `reef schema mcp` without declaring them, with that number.

### Stability

- **`reef.schema_version`** is 1, and changes only when the document's own layout changes incompatibly (a member renamed or moved). Additions to the layout do not change it.
- **The content follows what it describes.** Command names and full JSON only grow (ADR 0025 decision 5, ADR 0034); so do their schemas. Brief views may drop or keep keys in a minor release (ADR 0045 decision 5); each `brief.*` def's description ends "Which keys this view keeps may change in a minor release." The API's schemas change with `api_revision` and only by addition (ADR 0029).
- **No API revision.** Nothing in `reef-api` changes; `API_DIGEST` is untouched.

### Where the code lives

- `crates/reef-client/src/schema.rs` (new, `pub mod schema`): `settings()`, `names()`, `describe_brief()`.
- `crates/reef-vcs/src/schema/` (new, `mod schema` in `main.rs`): `mod.rs` builds the document and prunes `$defs` to what a part or a name reaches; `api.rs` converts the descriptor set.
- `crates/reef-vcs/src/cli/schema/` (new): `mod.rs` has `Args`, `run` and the `cli` part, and the `Schema` variant of `Command` follows `Mcp`; `commands.rs` walks clap; `outputs.rs` holds `OUTPUTS`. They live under `cli` because the CLI's own output types are private to its modules.
- `crates/reef-vcs/src/mcp/tools.rs`: `ToolDef::output` and `pub(crate) fn definitions() -> Vec<Value>`; `list()` is unchanged.

### Documentation

- **`docs/adr/0050-published-schemas.md`** (accepted), indexed in `docs/adr/README.md`; ADR 0035 gains "Amended by: 0050" in its header.
  - **Decisions:**
    1. One offline command, `reef schema [PART [NAME]...]` and `--descriptor-set`, always JSON.
    2. The document: one JSON Schema 2020-12 resource with `cli`, `mcp`, `api` and shared `$defs`, a URN `$id`, and the version, revision and digest.
    3. Inputs from clap as plain JSON Schema, with `argv` beside them.
    4. Outputs derived from the types that print them, under the serialize contract, per form, with enum values from the name functions.
    5. The API as canonical proto3 JSON, converted from the descriptor set in the repository.
    6. MCP output schemas published, not declared in `tools/list` (amends 0035 decision 5): cost (#116), descriptions already name the shape, and error results.
    7. Stability: `schema_version`, no `additionalProperties: false`, brief views as ADR 0045 says.
  - **Alternatives:**
    - Hand-written schemas: they drift, and nothing would check them.
    - A committed copy of the document with a drift test, like `API_DIGEST`: every output change would regenerate a file of several hundred kilobytes; the validation tests check the same thing against real output.
    - `outputSchema` in `tools/list`, always or behind `reef mcp --output-schemas`: the cost above, and a flag nobody's configuration would set.
    - `protoc-gen-jsonschema` or `buf`'s plugins: a Go or `protoc` toolchain at build time, which R1.03 and R2.01 avoided.
    - OpenAPI: the API is gRPC, and nothing serves it as REST.
    - Extending `reef guide -o json`: the guide is prose for agents and stays small.
    - A separate schema crate: two modules and a dependency do not need one.
- **`CHANGELOG.md`**, Added: "`reef schema` prints the CLI's commands (inputs, and output in each form), the MCP tools with output schemas, and the API's services and messages as one JSON Schema document; `reef schema --descriptor-set` prints the API's protobuf descriptor set (ADR 0050, linked). The MCP tools' `tools/list` is unchanged."
- **`README.md`**: unchanged. It describes releases ("Phase 2 so far (0.2.0)"), and no ticket merged since 0.2.0 has edited it; the release that ships `reef schema` adds it.
- **`docs/token-benchmark.md`**: the one sentence above.
- **`docs/dev-phases.md`** and this directory's README: done with this brief.

## Implementation notes

- **Shared `$defs`.** Build one `SchemaGenerator` from `settings()` for the whole document and call `subschema_for::<T>()` per row, so each type is defined once; then `take_definitions`. A part or a name prunes `$defs` by walking `$ref`s from what it keeps.
- **A type and its brief view in one generator.** Without the renames both would be `Workspace`; schemars would number one of them, which is not a stable name. Test 6's equality of two builds would not catch that, so check the names in test 7.
- **`flatten`** (`Created`, `Inspected`, `LogEntry`, `FileDiff`, `ChangeSummary`, `here`'s `Inside`, the MCP `HistoryPage`, `DiffPage`, `FileRange`) comes out of schemars as merged properties or `allOf`; either validates. Leave it as schemars writes it.
- **`here`'s discriminator.** `#[schemars(extend("const" = true))]` on `Inside::in_workspace`, `false` on `Outside`'s.
- **Brief view lifetimes.** `JsonSchema` derives for structs with a lifetime and `&'a str` fields. If one view cannot derive (a borrowed slice of views), give it a `schema_with` that names the inner view's def.
- **`ws run`'s output** reaches stdout after the child's. Test 9 runs `true`, whose stdout is empty, so the report is the whole of stdout.
- **The MCP output schemas reuse `compact`**, which drops `null` beside a type. That is right for inputs, where a missing key means unset, and wrong for outputs, where `null` is printed. Give `compact` a flag that keeps `null` for outputs; test 11 fails without it.
- **Descriptions** of `reef_client::json` were written as Rust docs and sometimes name Rust items (`[`json`]`). Strip rustdoc link brackets in `describe_brief` and in a transform on the generator, so `[`Workspace`]` prints as `` `Workspace` ``.
- **`jsonschema` usage**: `jsonschema::draft202012::options()` with format validation off (the schemas' `format`s are annotations), built once per schema and reused. Its default features fetch `$ref`s over HTTP; every reference here is local.
- **macOS and Linux** build the same code: there is no `cfg(target_os)` in this ticket.

## Performance expectations

- `reef schema` takes under 100 ms in a release build and under 1 s in a debug build; it decodes 220 KB once and generates the rest.
- The PR reports the size of the whole document, of each part, of the largest single-command document, and of the `outputSchema`s summed (test 12). No budget: the document is fetched once by a generator, not per session. A harness that wants one command fetches `reef schema cli <words>`.
- Nothing changes for any other command: the derive adds code that runs only when a schema is asked for.

## Out of scope

- `outputSchema` in `tools/list` (#116's ticket, if deferred loading makes it cheap).
- Schemas of text output, and of `reef-daemon`'s own commands (its `config show --json` is described as an object, nothing more).
- Attaching the document and the descriptor set to GitHub releases, so a harness can read them without installing Reef (R2.25 packages per harness and can add both to the release workflow).
- Generating SDKs from the document (R2.06 and R2.07 generate from the protos or the descriptor set).
- A catalog of error reasons in the document: reasons are additive constants in `reef_api::error` and the CLI, and the schema says `reason` is a string.
- The v0 API.
- Shrinking the help, the tool list or brief views (#122, #116, #123).

## Risks

- **A wrong row passes unnoticed** when no test runs that command in that form. Test 9's list of rows not run says which are unchecked and why, and test 10 adds every VCS test's invocations; the remaining gap is the commands that need a stopped daemon or a remote listener.
- **schemars' output for an edge** (`flatten` of an `Option`, a transparent wrapper, a borrowed view) may not match what serde prints. Tests 9 to 11 validate real output, so a mismatch fails a test rather than shipping.
- **Proto3 JSON printers differ** in small ways (protobuf-es prints `Duration` and 64-bit integers as the mapping says; some print enums as numbers when asked). The schema follows the canonical mapping; test 5 pins it to prost-reflect's printer.
- **Document size.** Proto comments are long. If the whole document passes 1 MB, the PR says so; the parts and names exist so no reader needs all of it.
- **`jsonschema` moves fast** (0.60 after many 0.x releases). It is a dev-dependency; a break costs a test-only update.

## Choices this brief made, and why

- **Derive, don't write**: the schemas come from the types and the name functions that print, so they cannot drift; real output is validated against them.
- **One document that is also a schema**: a reader gets everything with one call and resolves `$ref`s with any 2020-12 validator.
- **`input` plain and `argv` beside it**: a harness can hand `input` to a model as is, and use `argv` to build the command line.
- **Canonical proto3 JSON for the API**: it is what a gateway sends and receives, and a printer can check it.
- **Output schemas published, not declared**: the session cost of `tools/list` is #116's open problem; publishing gives generators the shapes without adding to it.
- **No committed copy**: the tests check real output, which a committed file would not.
- **Offline and ignoring `--remote`**: the document describes the binary; the daemon's version is the API part's `api_revision`, which any client already checks.

## What later tickets inherit

- **Every PR that adds a command** adds its row to `OUTPUTS` and runs it in test 9's script, or lists it there with a reason; test 2 and test 9 fail until it does.
- **Every PR that adds an output type** derives `JsonSchema`; an enum-valued string uses `names`. A brief view (#123) derives as `brief.<Name>` and changes its command's row to `View`.
- **Every PR that adds a tool** gives it an `output`; test 11 fails until its result validates.
- **#116** can declare `outputSchema` from `ToolDef::output` when its measurement allows; R2.17's break-even is re-measured then.
- **R2.25** can ship `reef schema mcp`'s definitions in a harness package, and attach the document and the descriptor set to releases.
- **R2.06 and R2.07** generate from the descriptor set, which `reef schema --descriptor-set` also gives to tooling outside Rust.
- **R6.01**'s specification can start from the API part, which carries every service, method, message and comment.
