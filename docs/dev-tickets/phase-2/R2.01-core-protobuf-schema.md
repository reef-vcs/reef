# R2.01 Core protobuf schema: `reef.daemon.v1` and the `reef-api` crate

Phase 2 · Size L · Depends on: R1.05 (the v0 schema and `Client` this replaces), every merged Phase 1 ticket (their RPCs are carried over) · Unblocks: every other Phase 2 ticket (each adds to files this ticket creates), R3.01, R3.05, R4.01

## Context

Phase 1's API is `reef.daemon.v0`: seven proto files written one ticket at a time, generated inside `reef-daemon`, reached by clients through `reef_daemon::client::Client`. ADR 0017 called it "explicitly pre-stable" and promised that R2.01 "can rename and renumber freely before `v1`". Phase 2 adds the read side (status, log, diff), the write side (describe, undo, abandon, squash), the virtual workspace, subscriptions, presence, replay, symbols, queries, remote tokens and client-side store builds. Writing those services one ticket at a time, as Phase 1 did, would review the API eleven times in pieces. This ticket writes the whole v1 schema once, reviews it once as an API, and gives it a home no client has to link jj-lib to reach.

That home is a new crate, `reef-api`. Today a Python SDK, the MCP server or `reef schema` would have to depend on `reef-daemon` to reach the generated code, and `reef-daemon` pulls in jj-lib, SQLite and every backend. After this ticket the dependency order is `reef-vcs → reef-daemon → reef-lib → reef-api`, and `reef-api` depends on tonic, prost and serde only.

### What was verified while writing this ticket

Reef at `d156d1e` (0.1.0); crates as locked in `Cargo.lock`.

## Decisions

- **Package `reef.daemon.v1` in `crates/reef-api/proto/reef/daemon/v1/`**, one file per service plus `types.proto` and `error.proto`, exactly the files the README lists: `daemon`, `types`, `error`, `repositories`, `workspaces`, `changes`, `operations`, `events`, `trees`, `presence`, `symbols`, `queries`, `remote`, `maintenance`, `stores`. Every message and RPC any Phase 2 ticket implements is written here, with its field numbers, and the daemon answers the unimplemented ones with `UNIMPLEMENTED` and the hint `not implemented until R2.xx` (one table in `crates/reef-daemon/src/service/stubs.rs` maps RPC to ticket). Later tickets add fields and RPCs; they do not restructure. Within v1 every change is additive (README, API v1).
- **v0 is deleted in this PR.** The client, the CLI, the bench, every integration test and the daemon's services move to v1 in the same change. Nothing outside this repository depends on v0 (ADR 0017), and two schemas served at once would be two to keep in step.
- **Carry-over rule.** Every v0 field keeps its meaning and, where the README does not rename it, its name. Renames: `Daemon.Status` messages become `DaemonStatusRequest`/`DaemonStatusResponse` (so `Workspaces.Status` can have `WorkspaceStatusRequest`); `HeartbeatRequest.workspace_id` becomes `workspace`, as every other workspace-naming field; `ListWorkspacesRequest` gains `Page page` and the response `next_page_token`; `BackupProgress` gains the `summary` the CLI used to read from the manifest file (so R2.05's CLI needs no daemon type); `InspectResponse` keeps `snapshot_count`, `local_snapshot_count` and `recent_snapshots`. Field numbers are reassigned freely in v1 and frozen from this PR on.
- **Naming.** Nouns for services, verbs for RPCs, `<Verb><Noun>Request`/`<Verb><Noun>Response` except where v0's name already follows the rule (`GcRequest`, `BackupRequest`, `QuiesceRequest`, `ResumeRequest`, `BuildStoreRequest`). `repo` on every repository-scoped request (a repo id, unique prefix, or absolute path inside a registered root, as v0); `rev` for a revision; `change` for a change id; `op` for an operation id; `workspace` for a workspace id, prefix, or path inside it. Ids are lowercase hex strings. Timestamps are `google.protobuf.Timestamp`, durations `google.protobuf.Duration`.
- **Pagination** (README): `message Page { uint32 page_size = 1; string page_token = 2; }` on every request whose list can grow (`Workspaces.List`, `Changes.Log`, `Operations.Log`, `Trees.List`, `Symbols.Lookup`, `Queries.Run`), `string next_page_token` on the response. `page_size` 0 means 100; above 1,000 is clamped. The token is opaque: base64url of `{ cursor, filter_hash }`, and a token whose `filter_hash` does not match the request is `INVALID_ARGUMENT`. `reef_api::page` holds the encoder and decoder so every service pages the same way.
- **Errors**: `error.proto` is v0's `ErrorDetail { kind, chain, hint, next }` unchanged, and ADR 0017's `ErrorKind` to `Code` table is unchanged. `UNIMPLEMENTED` (tonic's code) is used only for stubs; its detail carries `kind = "Internal"`, so an old-style client maps it to exit 1 as R1.22's CLI stubs did.
- **`reef-api` crate**: `crates/reef-api/{Cargo.toml, build.rs, proto/, src/{lib,proto,error,advice,client,json,page}.rs}`. Dependencies: `tonic`, `tonic-prost`, `prost`, `prost-types`, `tokio` (`net`, `io-util`), `tokio-stream`, `hyper-util`, `tower`, `serde`, `serde_json`, `thiserror`, `tracing`, `time` (RFC 3339), `nix` (`hostname`, `user`; for `default_owner`). Build-dependencies: `protox`, `tonic-prost-build`, `prost`, `prost-types`. Never jj-lib, gix, rusqlite or `reef-lib`. `publish` is allowed (it is what SDK authors and R2.13 read).
  - `reef_api::proto::v1` is `tonic::include_proto!("reef.daemon.v1")` with the same lint allowances as today's `proto.rs`, generated with `build_server(true).build_client(true)`, so the daemon reaches `reef_api::proto::v1::workspaces_server::{Workspaces, WorkspacesServer}` and the client `reef_api::proto::v1::workspaces_client::WorkspacesClient`.
  - `reef_api::DESCRIPTOR_SET: &[u8]` is `include_bytes!(concat!(env!("OUT_DIR"), "/reef.daemon.v1.bin"))`, the `FileDescriptorSet` protox returned, encoded by `build.rs`, with source info (comments) and the imported well-known types. `reef_api::SCHEMA_HASH: &str` is its BLAKE3 hex, computed once at first use (`std::sync::LazyLock`; `blake3` is already a workspace dependency).
  - `reef_api::error` is today's `reef_lib::error` moved verbatim (`ErrorKind`, `Classify`, `classify_by_source`, `ErrorChain`) plus the client-side half of today's `reef_daemon::error`: `code_of`, `kind_name`, `parse_kind`, `kind_from_status`, `detail_of`. `reef_lib::error` becomes `pub use reef_api::error::*;` so the 99 importing files compile unchanged. `status`, `status_from` and `advice_of` stay in `reef_daemon::error`: they downcast daemon error types.
  - `reef_api::advice` is `Advice` and `Advise`, moved; `reef_daemon::error` re-exports them so the daemon's twelve `impl Advise` blocks compile unchanged.
  - `reef_api::client` is today's `reef_daemon::client` moved, with one method per v1 RPC, the stubbed ones included (so later tickets add server code only); `WorkspacesApi` and `default_owner` come along. `reef_api::json` is `client/json.rs` moved, with its own RFC 3339 formatter over `time` instead of `reef_daemon::model::Timestamp`, and `ROOT_CHECKOUT` (the `CreateResponse.start` value for the root checkout, today `reef_daemon::workspace::ROOT_CHECKOUT`) defined here and re-exported by the daemon. JSON field names do not change (the `cli-shape` artifact pins them); new types for the new responses are added with the services that fill them, not here.
  - `reef_daemon::client` and `reef_daemon::client::json` are removed, not re-exported: 30 files change their imports, and a re-export would let the next ticket keep writing `reef_daemon::client`.
- **Reflection on the socket**: `server::router` adds `tonic_reflection::server::Builder::configure().register_encoded_file_descriptor_set(reef_api::DESCRIPTOR_SET).build_v1()`. R2.08's listeners do not add it.
- **`Daemon.Status` gains** `api_version = "v1"`, `schema_hash` (`reef_api::SCHEMA_HASH`), and the fields later tickets fill, empty until then: `seqs` (the newest event sequence per repository, R2.09), `web_url` and `remote_listen` (R2.08). The event sequence is per repository, not per daemon, so a client resuming one repository's subscription needs no other repository's number; `Event.seq`, `Operation.seq`, `SubscribeRequest.resume_after_seq`, `LogOperationsRequest.after_seq` and `ReplayRequest.seq` are all that repository's.
- **ADR 0029, "Daemon API v1 and the `reef-api` crate"**: supersedes 0017 (its error mapping is restated, not changed), amends 0007 (five crates, the new bottom crate, the rule that `reef-api` never depends on jj-lib). Alternatives: keep generating inside `reef-daemon` and let clients depend on it (rejected: every client links jj-lib); `google.rpc.Status` with `ErrorInfo` through `tonic-types` (revisited as 0017 asked; rejected: no client needs it and both SDKs decode `ErrorDetail` in a few lines); serve v0 and v1 side by side for one release (rejected: v0 promised nothing).
- **`docs/api.md`** is written for a client author: the transport (socket; remote in R2.08), authorization (the socket; tokens in R2.08), ids and revisions, pagination, errors and `ErrorDetail`, then every service with its RPCs, one paragraph each, and which ticket implements the stubbed ones. The Fable review of this PR is the API review; the review table in the PR names each schema finding.

## Implementation notes

- Do the move in three commits so the review can follow: (1) create `reef-api` with v0 moved byte-for-byte under the new package name and everything compiling; (2) the schema review: renames, new files, stubs, `docs/api.md`; (3) reflection, `Status` fields, paging, tests. Each commit passes `just ci`.
- `tonic::include_proto!` needs the package name; `protox` names the generated file `reef.daemon.v1.rs`. Keep `proto.rs`'s lint allowances.
- `prost::Message::encode_to_vec` in `build.rs` needs `prost` as a build-dependency (it is already a workspace dependency).
- The daemon's `convert.rs` has one `From` per type; the new types (`Change`, `Operation`, `FileEntry`, ...) get their conversions in the tickets that fill them, not here. Here only `Workspace.presence` (left unset) and `Daemon.Status` change.
- `HeartbeatRequest.workspace_id` → `workspace` touches `cli/ws_run.rs`'s heartbeater and `WorkspacesApi`; the fake daemon in `tests/ws_run.rs` too.
- Streaming stubs: tonic's generated trait wants a `Stream`; return `Ok(Response::new(Box::pin(tokio_stream::once(Err(stub(ticket))))))`.
- `json.rs`'s `rfc3339` over `time`: `OffsetDateTime::from_unix_timestamp_nanos` formatted with `time::format_description::well_known::Rfc3339` at millisecond precision, matching `model::Timestamp::to_rfc3339`'s output byte for byte (a unit test compares the two on a few values before the daemon's helper is left as the only daemon-side one).
- Shared target directory: this ticket changes `build.rs` and the protos. Before building in the Reef workspace or at the root, `touch crates/reef-api/build.rs crates/reef-api/proto/reef/daemon/v1/*.proto` in the checkout you build (the Phase 1 dogfooding note).
- `docs/api.md` is checked by `scripts/doc-links.sh`; link each service section to its proto file.

## Risks

- **The schema review finds something after the PR.** Within v1 every change is additive, so a bad field is deprecated by comment, not removed; a bad shape costs a new field or RPC beside the old one. The field-number fixture (test 3) makes the freeze visible.
- **A 41-file rename hides a semantic change.** The three-commit structure and the `cli-shape` diff keep the move mechanical and observable; the review reads commit (2) alone for semantics.
- **Messages shaped before their implementation.** `Change`, `Operation`, `FileEntry`, `Frame` are shaped from jj-lib's types as verified above; a later ticket that needs a field adds one. The risk is a field here that nothing ever fills; test 2 forces a comment on each, and `docs/api.md` says which ticket fills it, so an orphan is visible at the phase's end.
- **`tonic-reflection`'s generated client may not exist** for test 8; the fallback is a raw `tonic::client::Grpc` call with the reflection request encoded by hand, or `grpcurl` in Verification only.
