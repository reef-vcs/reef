# R2.01 Core protobuf schema

Phase 2 · Size L · Depends on: R1.05 (the v0 services this ports, with everything Phase 1 added to them) · Unblocks: R2.02, R2.03, R2.04, R2.05, R2.06, R2.07, R2.08, R2.09, R2.10, R2.11, R2.12, R2.24, R3.05

## Context

Phase 1 shipped its API as `reef.daemon.v0` (ADR 0017): seven files in `crates/reef-daemon/proto/reef/daemon/v0/`, five services (`Daemon`, `Repositories`, `Workspaces`, `Maintenance`, `Stores`), explicitly pre-stable, with stringly typed states, `op_id` strings on mutating responses, unpaginated lists, and a raw `ErrorDetail` in the status details. 0.1.0 shipped it on 2026-10-25. Phase 2 puts every client on one typed API: the CLI becomes a thin client (R2.05), an MCP server (R2.13), Python and TypeScript SDKs (R2.06, R2.07), a web UI (R2.18), and a remote listener (R2.08) all speak it. This ticket writes that API, `reef.api.v1`, moves the daemon and the CLI onto it, and retires v0.

Two lessons from an abandoned first attempt at this ticket shape the brief:

- **The schema must be the single authority for every later Phase 2 ticket.** The attempt sketched the read and write services loosely; the tickets implementing them disagreed with the sketch in about fifty places, and since v1 freezes field numbers, it was redesigned during implementation. Here every RPC that R2.02 to R2.04 and R2.09 to R2.12 implement is declared in full, with field numbers, and the daemon answers the unimplemented ones with a structured error. Later tickets implement and add; they do not change. A declared RPC that proves wrong is deprecated and replaced, never edited.
- **A version mismatch must say so.** The attempt broke `reef daemon stop` and `reef daemon status` across the v0 to v1 change with an empty `internal` error: a v1 client calling a 0.1.0 daemon gets tonic's bare `UNIMPLEMENTED` with no message and no details, which `kind_from_status` maps to `Internal`. Every direction of mismatch is specified below and tested.

### What was verified while writing this ticket

Reef at `2fdb422`; tonic 0.14.6, prost 0.14.4, protox 0.10.0, prost-reflect 0.16.5, tonic-types 0.14.6, jj-lib 0.46.0 (with jj-core 0.46.0).

- **Where the empty `internal` comes from.** A method of a known service that the generated server does not have answers with `grpc-status: 12` in the headers and no message (tonic-build `src/server.rs:172`); an unknown service hits tonic's router fallback, `Status::unimplemented("")` (tonic `src/service/router.rs:138`). `reef_daemon::error::kind_of_code` (`error.rs:224`) maps `UNIMPLEMENTED` to `Internal`, and `ClientError::from(Status)` (`client/mod.rs:74`) keeps the empty message.
- **`reef daemon stop` needs `Daemon.Status`.** `cli/daemon.rs:147` reads the daemon's pid from `Status` and signals only when the pid file agrees; a CLI that cannot read status cannot stop a daemon. `status_of` serves `daemon status` and `daemon start` too (`:78`, `:109`). `connect` (`cli/mod.rs:431`) never calls `Status`.
- **A response can be rewritten after routing.** `Server::layer` (tonic `transport/server/mod.rs:624`) wraps every service, and `Status::into_http` (`status.rs:607`) is public, so a tower layer can see the request path and replace a bare `UNIMPLEMENTED` response with a structured one. `reef_daemon::server::router` (`server.rs:22`) builds the router in one place.
- **Codegen.** `crates/reef-daemon/build.rs` compiles with `protox` (no `protoc`) and `tonic-prost-build`. protox's `Compiler` has `include_source_info`, `include_imports`, `descriptor_pool()` (a prost-reflect `DescriptorPool`) and `encode_file_descriptor_set()`, and bundles `google/protobuf/descriptor.proto`. prost-reflect reads custom method options: `DescriptorPool::get_extension_by_name` (`descriptor/api.rs:495`), `MethodDescriptor::options()`, `DynamicMessage::get_extension` (`dynamic/mod.rs:462`). Both are already in `Cargo.lock`. `tonic_types::Status` is the generated `google.rpc.Status`; tonic-types is not yet a dependency.
- **jj-lib 0.46.** Operation metadata carries `attributes: HashMap<String, String>` (renamed from tags), written with `Transaction::set_attribute` (`transaction.rs:90`), and `workspace_name`. `RepoLoader::load_at(&Operation)` (`repo.rs:828`) loads any operation's view. `revset::parse` (`revset.rs:1537`) with `RevsetParseContext` (`:3622`) parses jj's revset language; `trunk()` and `immutable_heads()` are jj-cli aliases, not jj-lib built-ins. `jj_lib::graph::GraphEdgeType` is `Missing`, `Direct`, `Indirect` (jj-core `graph.rs:81`). `reef_lib::jj::OpEntry` (`oplog.rs:19`) has no attributes and there is no lookup of one operation by id; `walk_op_log` walks from the head.
- **The CLI's contract.** JSON error objects are `{"kind", "message", "hint"?, "next"?}` with kind texts and exit codes from `ErrorKind` (`cli/error.rs:144`, ADR 0025); `docs/agent-guide.md` is 1,534 of its 1,600 bytes. `same_cli_both_platforms` (`reef-daemon/tests/integration.rs:863`) writes `target/cli-shape-<os>.json`, the key sets of the CLI's JSON. `client/json.rs` builds that JSON from the generated messages and maps strings such as `state` and `attention` through unchanged.
- **Model enums the v1 enums mirror**: `Attention` has eight reasons, `mount-failed` included (`model/mod.rs:126`); `BackendKind`, `WatcherKind`, `SnapshotKind`, lease end reasons (`released`, `expired`, `restored`).
- **Tooling.** `buf` is not installed on the development Mac and no CI job uses it. CI runs on `ubuntu-24.04` and `macos-15` with `actions/checkout@v7`; nothing is published to crates.io (R1.28 ships binaries), so a new crate needs no release change beyond the version bump list.

## Decisions

- **Package `reef.api.v1`, in a new crate `reef-api`.** The protos live in `crates/reef-api/proto/reef/api/v1/`. The package says "api", not "daemon": R4.01's store serves these same services to the same clients (ADR 0004: "clients do not care which they are talking to"), and the store's own daemon-to-store protocol gets its own package then. The crate holds the protos, the generated messages, clients and servers, the descriptor set, and small helpers for the error detail, and depends on no other Reef crate. That is what lets R2.05 build a CLI with no path to jj-lib, and lets R2.24 and the SDKs find the schema in one place. ADR 0007 deferred "a separate `reef-proto` crate" to this ticket. The dependency direction becomes `reef-vcs` → `reef-daemon` → `reef-lib`, with `reef-daemon` → `reef-api` and `reef-vcs` → `reef-api` added and `reef-lib` never depending on it. `reef_daemon::proto` is deleted; code names `reef_api::v1`. `reef_daemon::client::Client` stays where it is, ported to v1; R2.05 decides where the thin client finally lives.
- **v0 is retired, except for a frozen beacon.** `daemon.proto` and `error.proto` move unchanged in wire terms to `crates/reef-api/proto/reef/daemon/v0/` (package `reef.daemon.v0`, header comment "frozen at 0.1.0; served only for version detection"); the other five v0 files are deleted. The daemon serves the v1 services plus `reef.daemon.v0.Daemon/Status`, filled from the same data as v1's `GetDaemonStatus`. Nothing else of v0 is served, and no v0 handler code survives.
- **Every direction of version mismatch has an answer.** The daemon is a separate long-lived process; an upgrade replaces the binaries but leaves the old daemon running.
  - *New CLI, 0.1.x daemon.* Every v1 call gets a bare `UNIMPLEMENTED`. `Client` never returns that as is: on `UNIMPLEMENTED` without a Reef detail it asks `GetDaemonStatus` (with `skip_backends`), then the v0 `Daemon/Status`, and returns `ClientError::Incompatible { socket, method, daemon_version, daemon_api ("v0" or "v1"), active_workspaces }`, kind `Unsupported`, reason `API_VERSION_MISMATCH`. Its message: `the daemon at <socket> is reef 0.1.0 (API v0) and cannot serve reef 0.2.0 (API v1)`. The CLI then **restarts the daemon if it is idle**: when autostart is allowed (`--no-autostart` not given), the daemon reports no active workspaces, and its pid agrees with the pid file as `daemon stop` already checks, the CLI stops it, starts the current one as autostart does, prints `reef: restarted the daemon (reef 0.1.0, API v0, was running)` on stderr, and runs the command once more. The failed call changed nothing on the old daemon, so the rerun is safe. Otherwise it fails with exit code 9, `hint` "This reef is newer than the running daemon, which has N active workspaces; stop it when they are done and the next command starts the new one", and `next` `["reef", <the global path flags>, "daemon", "stop"]`.
  - *`reef daemon status`, `stop`, `start` against a 0.1.x daemon.* `status` and `stop` fall back to the v0 `Daemon/Status` and work: `status` prints the v0 fields with `api: "v0"` and a note naming `reef daemon stop`; `stop` signals exactly as today. `start` applies the restart rule above, and reports the incompatibility when the daemon is busy.
  - *0.1.x CLI, new daemon.* The 0.1.x `daemon status` and `daemon stop` work through the beacon. Every other v0 call is rewritten by the daemon's `CompatLayer` into `FAILED_PRECONDITION` with a v0 `ErrorDetail { kind: "Conflict", chain: [<message>], hint }`: the message `this daemon is reef 0.2.0 and serves API v1; this client speaks API v0`, the hint "Upgrade reef to 0.2.0 or later; `reef --version` shows this one." `Conflict` because 0.1.x knows no `Unsupported` and treats `Conflict` as the caller's to fix (exit 5, logged at `warn`). The daemon logs `warn` with the path.
  - *A v1 client newer than a v1 daemon* (a method added in a later revision). The `CompatLayer` turns the bare `UNIMPLEMENTED` into `UNIMPLEMENTED` with kind `UNSUPPORTED`, reason `UNKNOWN_METHOD`, metadata `method`, `daemon_version`, `api_revision`, and a hint to stop the daemon so the next command starts the current one. The CLI applies the same restart-if-idle rule when the daemon's version differs from its own. A declared but unimplemented RPC answers with reason `NOT_IMPLEMENTED` from its own stub, and the CLI restarts for that one only when the versions differ.
  - *A v1 daemon newer than a v1 client.* Additions only: an old client ignores unknown fields, and an enum value it does not know arrives as its number. `client/json.rs` prints an unknown enum value as `unknown` and an unknown `ErrorKind` as `internal`.
- **Naming follows buf's `STANDARD` and `COMMENTS` lint rules**, so the shape is checked by a tool and not by memory. Services end in `Service`, and RPCs are verb-noun (`CreateWorkspace`, not `Create`) because every request and response is named `<Rpc>Request` and `<Rpc>Response`, used by that RPC alone, and unique in the package. Enum values carry the enum's prefix and zero is `<ENUM>_UNSPECIFIED`; prost strips the prefix in Rust. Every element has a leading comment saying what it means, its unit, and what empty or zero means; R2.13 turns these into tool descriptions and R2.24 publishes them. Files are one per service plus `options.proto` and `error.proto`; under buf's `FILE` breaking rules a message cannot move between files later, so the placement below is final. Imports form no cycle; each file's imports are listed in the sketch below.
- **References in requests.** `repo` is a repo id, a unique id prefix of four or more hex characters, or an absolute path inside a registered root, as in v0. `workspace` is a workspace id, a unique prefix, or an absolute path inside an active workspace's directory; where a request names a workspace, `repo` may be empty. `revision` is a jj revset expression that must resolve to exactly one commit: none is `NOT_FOUND`, several are `INVALID_ARGUMENT` (a divergent change id names two commits; use a commit id). `@` is the request's `workspace`'s working-copy commit, and invalid without one. `trunk()` is R1.31's default start bookmark and `immutable_heads()` is `trunk() | tags()`, both Reef aliases. `at_operation` is an operation id or unique prefix: the read answers from that operation's view, and empty means the current head. R2.02 implements revision resolution and `at_operation`. Until it does, the ported `change` and `new_on` fields of `CreateWorkspace` and `MoveWorkspace` keep Phase 1's resolution (change id prefix in hex or reverse hex, then commit id prefix, then local bookmark). That is the same commit for every input except a bookmark whose name is also a valid id prefix.
- **Ids are full lowercase hex strings in responses, change ids included.** One alphabet for every id; git SHA-1 now and BLAKE3 in Phase 4 are hex of different lengths, which strings absorb (ADR 0011). Requests accept change id prefixes in hex or jj's reverse hex (`z`-`k`), whose alphabets are disjoint. The CLI keeps printing both spellings (`change_id_reverse_hex` in its JSON). Reef's own ids are 16 hex characters.
- **Time.** Instants are `google.protobuf.Timestamp`, UTC, named `<event>_at`. Intervals a client sets or that are policy are `google.protobuf.Duration` (lease length, grace, heartbeat interval, TTL, timeout, quiesce maximum). Measured elapsed times are `uint64 <name>_ms` (timings, scan time, uptime). This replaces v0's `lease_ms`, `length_ms` and `grace_ms`.
- **Enums for closed sets the daemon defines** (workspace state, backend, watcher, attention, lease state and end reason, snapshot kind, store mount mode, backup step), replacing v0's strings. Zero is `UNSPECIFIED`, and the enum's comment says what zero means: "not set" in a record, "the default" in a request (`MISSING_STORES_UNSPECIFIED` behaves as `FAIL`). Free text and open sets stay strings (owner, purpose, agent, bookmark names, error reasons).
- **Scalar presence.** A scalar is `optional` only where zero is a meaningful value distinct from the default; in this schema that is `GetDiffRequest.context_lines`, `EditFilesRequest.description` and `FileEdit.executable`. Messages have presence already.
- **Every List RPC is paginated from the first revision.** Adding pagination later would silently truncate old clients. Each takes `int32 page_size` (0 means 100; above 1,000 is clamped to 1,000; negative is `INVALID_ARGUMENT`) and `string page_token`, and returns `string next_page_token`, empty on the last page. Tokens are opaque base64url, bound to the request's other fields: a token sent with different filters is `INVALID_ARGUMENT`, reason `INVALID_PAGE_TOKEN`. A token over jj state pins the operation the first page was read at, so later pages come from the same view. `GetDiff` pages files the same way. Lists that are not RPCs (`GetStatus`'s workspaces and heads) are capped at 100 with a total count beside them.
- **Filtering is typed fields, not filter strings**, except `ListChanges.revset`, which is jj's language (its comment says so, so an alternative server may refuse it with `UNSUPPORTED`). Within a repeated filter field values are ORed; across fields they are ANDed.
- **No field masks.** Responses are small, heavy parts are opt-in flags (`skip_disk_usage`, `include_effects`, diff `format`), and updates are explicit RPCs (`DescribeChange`), not masked patches. Partial responses would complicate every SDK for no measured gain.
- **Operations in responses.** A response reports an operation it created as an `Operation` message (`operation`, or a role such as `final_snapshot`), and refers to one it did not create by id (`<role>_operation_id`). Every `ACCESS_WRITE` RPC's response has an `Operation operation` field, except `RenewLease`, `ReportPresence` and `ClearPresence`, which record none. The field is unset when nothing was recorded (an unchanged snapshot). R2.01 fills `Operation` from the operation it just wrote: id, parents, description, times, host, user, `is_snapshot`, attributes, `jj_workspace` and `workspace_id`, `kind` and `snapshot_kind` (known from the RPC that wrote it), and `agent` (the workspace's owner). It leaves `effects` unset; R2.02 computes them and fills them wherever an `Operation` is built.
- **Reads that depend on a workspace's files snapshot it first.** `GetStatus` with a workspace, and `ListChanges`, `GetChange`, `GetDiff`, `ReadFile` and `ListFiles` when their revset or revision involves `@`, take a snapshot through the scheduler before answering, as jj does before every command. `skip_snapshot` answers from the last recorded snapshot instead, and a read `at_operation` never snapshots. `GetWorkspace` keeps v0's opposite default (`snapshot_first`, off), because it reads the record and `reef here` must stay free of side effects. Such reads are `IDEMPOTENT`, not `NO_SIDE_EFFECTS`.
- **Streaming.** Server streaming only: subscriptions (`SubscribeOperations`, `SubscribePresence`) and long operations (`Backup`, `BuildStore`). No client or bidirectional streaming in R2.01's schema: the web UI reaches the API over gRPC-web (R2.18), which carries neither. A later RPC that needs client streaming for a bulk upload must be `ACCESS_ADMIN`, and the web UI never calls it. A subscription frame with no entries is a keepalive, sent at least every 30 s. `ReadFile` returns at most 1 MiB per call (`limit`), under tonic's 4 MiB message default.
- **The error model is `google.rpc.Status` with one Reef detail.** The gRPC code comes from the kind. `grpc-status-details-bin` holds a `google.rpc.Status { code, message, details: [Any(reef.api.v1.ErrorDetail)] }` (type URL `type.googleapis.com/reef.api.v1.ErrorDetail`), which Python's `grpcio-status`, Connect-ES's `findDetails`, and `tonic-types` decode with stock tooling. v0's raw detail bytes did not decode that way. `ErrorDetail` carries `kind`, `reason`, `chain`, `hint`, `next` and `metadata`. `reason` is an UPPER_SNAKE constant naming the specific condition, empty when there is none; reasons are API and documented on the RPCs that return them. R2.01 defines `NOT_IMPLEMENTED`, `UNKNOWN_METHOD`, `API_VERSION_MISMATCH` and `INVALID_PAGE_TOKEN`; later tickets add theirs through `reef_daemon::error::reason_of`, which works like `advice_of`. `ErrorDetail` with `ErrorKind` is chosen over `google.rpc.ErrorInfo` (ADR 0017 asked R2.01 to revisit it): `ErrorInfo` has no place for `hint`, `next`, or the chain, and two details would need keeping in step.
- **A ninth error kind, `Unsupported`.** It means the daemon cannot serve the request as asked: a declared RPC it does not implement, a method it does not know, or a version mismatch. It maps to `UNIMPLEMENTED`, is a caller error (logged at `warn`), has exit code 9 and kind text `unsupported`, and is added to `reef_lib::error::ErrorKind`, the daemon's code table, `KINDS`, `kind_name`, the CLI's `kind_text`, and the guide's exit-code line. The table is the same for the rest: `NotFound` → `NOT_FOUND`, `AlreadyExists` → `ALREADY_EXISTS`, `InvalidArgument` → `INVALID_ARGUMENT`, `Conflict` → `FAILED_PRECONDITION`, `Unavailable` → `UNAVAILABLE`, `PermissionDenied` → `PERMISSION_DENIED`, `Io` and `Internal` → `INTERNAL`, `Unsupported` → `UNIMPLEMENTED`. The CLI's JSON error object gains `reason` when it is not empty.
- **Every RPC states its access and, where it holds, its idempotency, in the schema.** `options.proto` defines `enum Access { READ, WRITE, ADMIN }` and the method option `(reef.api.v1.access)`; every method sets it, and `reef-api`'s build fails if one does not. `READ` reads state and may snapshot a workspace it reads (a snapshot records what is already on disk). `WRITE` records operations on the changes, workspaces, leases or presence the request names. `ADMIN` has daemon-wide or host-level effects: registration, GC, backup, quiesce, store builds. Reads that never snapshot also set the standard `idempotency_level = NO_SIDE_EFFECTS`, and retry-safe calls `IDEMPOTENT`. This is the threat model's requirement 2 for R2.08, whose scopes are sets of access levels plus field rules (a remote `CreateWorkspace` with a `path` is refused). R2.13 maps `READ` to read-only tool hints. `reef_api::access(method_path)` serves the table to the daemon.
- **Versioning.** v1 only grows: no field, enum value, message or RPC is removed, renumbered, renamed or moved. A field that should not have been is marked `[deprecated = true]` and stops being filled after a CHANGELOG note. `buf breaking` with the `FILE` rules (field names matter to generated SDK code, and files to Python modules) enforces this against `main` in CI. `reef_api::API_REVISION` (1 here) increases by one with every schema change. A test recomputes a BLAKE3 digest of the v1 descriptors with source info stripped, so comments do not count, and fails until `API_REVISION` and `API_DIGEST` are both updated. `GetDaemonStatus` reports the revision so a client can check before it calls something new. A v2 would be a new package served beside v1, never a change to v1.
- **What R2.01 implements and what it only declares.**

- **Tooling.** Codegen stays `protox` plus `tonic-prost-build` in `crates/reef-api/build.rs`, so building needs no `protoc` and no `buf`. `buf` (v2 config, `buf.yaml` at the repository root, module `crates/reef-api/proto` with `reef/daemon/v0` excluded) lints (`STANDARD`, `COMMENTS`), checks formatting (`buf format`), and checks breaking changes (`FILE`) against the pull request's base. It runs in a new CI job and in `just api`, which `just ci` runs. Its version is pinned in CI. - **ADR 0029, "Daemon API v1"**, records all of the above as the API's conventions, and adds an API review checklist that every pull request touching `crates/reef-api/proto` is reviewed against. That checklist is how "reviewed as an API, not generated from code" is met from here on. ADR 0017 becomes `superseded by 0029`; ADRs 0009 and 0025 are not edited, and 0029 states its additions to them: the `Unsupported` kind, exit code 9, and `reason` in the JSON error.

## The v1 schema

This is the schema of record. Field names, numbers, types, enum values and RPC names are final, and the implementation transcribes them. Each element's trailing note here becomes a leading comment there, worded for a reader of the SDK (buf `COMMENTS`). `[R, NSE]` after an RPC means `option (reef.api.v1.access) = ACCESS_READ; option idempotency_level = NO_SIDE_EFFECTS;`. `[R, I]` and `[W, I]` use `IDEMPOTENT`, and `[W]` and `[A]` set only `ACCESS_WRITE` and `ACCESS_ADMIN`. Every file starts `syntax = "proto3"; package reef.api.v1;`. Enum values are written without their prefix below (`ACTIVE = 1` in `WorkspaceState` is `WORKSPACE_STATE_ACTIVE = 1`), and every enum has `<PREFIX>_UNSPECIFIED = 0`, whose meaning follows the enum name.

```proto
// options.proto — imports google/protobuf/descriptor.proto
enum Access { READ = 1; WRITE = 2; ADMIN = 3; }              // UNSPECIFIED is never valid on a method
extend google.protobuf.MethodOptions { Access access = 50701; }

// error.proto — the Any in google.rpc.Status.details of every v1 error
enum ErrorKind { NOT_FOUND = 1; ALREADY_EXISTS = 2; INVALID_ARGUMENT = 3; CONFLICT = 4; UNAVAILABLE = 5;
                 PERMISSION_DENIED = 6; IO = 7; INTERNAL = 8; UNSUPPORTED = 9; }   // UNSPECIFIED: read as INTERNAL
message ErrorDetail {
  ErrorKind kind = 1;
  string reason = 2;                    // UPPER_SNAKE, documented per RPC; empty when none
  repeated string chain = 3;            // the error's message, then each source's, outermost first
  string hint = 4;                      // one sentence; empty when the fix is unknown
  repeated string next = 5;             // an argv starting "reef", runnable verbatim; never a placeholder
  map<string, string> metadata = 6;     // per reason, documented with it
}

// operations.proto — imports timestamp, options
service OperationService {
  rpc ListOperations(ListOperationsRequest) returns (ListOperationsResponse);           // [R, NSE] R2.02
  rpc GetOperation(GetOperationRequest) returns (GetOperationResponse);                 // [R, NSE] R2.02
  rpc UndoOperation(UndoOperationRequest) returns (UndoOperationResponse);              // [W] R2.03
  rpc SubscribeOperations(SubscribeOperationsRequest) returns (stream SubscribeOperationsResponse);  // [R, NSE] R2.09
}
enum OperationKind { SNAPSHOT = 1; CREATE_WORKSPACE = 2; RELEASE_WORKSPACE = 3; MOVE_WORKSPACE = 4; DESCRIBE = 5;
                     ABANDON = 6; UNDO = 7; EDIT = 8; IMPORT_REFS = 9;
                     EXTERNAL = 10;     // written by another jj client, such as `jj` in the registered root
                     OTHER = 11; }      // written by Reef, not one of the above (repository initialization)
enum SnapshotKind { WATCHER = 1; EXPLICIT = 2; FINAL = 3; MOVE = 4; SHUTDOWN = 5; }
message Operation {
  string id = 1; string repo_id = 2; repeated string parent_ids = 3; string description = 4;
  google.protobuf.Timestamp started_at = 5; google.protobuf.Timestamp ended_at = 6;
  string hostname = 7; string username = 8; bool is_snapshot = 9;
  OperationKind kind = 10;
  SnapshotKind snapshot_kind = 11;      // when kind is SNAPSHOT
  string workspace_id = 12;             // the Reef workspace it was recorded for, from jj's `reef-<id>`; empty if none
  string jj_workspace = 13;             // jj's workspace name when it is not a Reef workspace (`default`)
  string agent = 14;                    // attribute `reef.agent`, else the workspace's owner; empty if unknown
  map<string, string> attributes = 15;  // jj's operation attributes, verbatim
  OperationEffects effects = 16;        // unset when not computed; see each RPC
}
message OperationEffects {
```

### What later tickets inherit

- **R2.02** implements `GetStatus`, `ListChanges`, `GetChange`, `GetDiff`, `ListOperations` and `GetOperation`. It also implements revision resolution with the two aliases, `at_operation`, `OperationKind` classification of operations Reef did not just write (by `reef.kind` attribute, else Phase 1's description prefixes, else `EXTERNAL`), and `OperationEffects` (from the view difference of an operation and its parents), filling effects wherever an `Operation` is built. It switches `CreateWorkspace` and `MoveWorkspace` to revision resolution. The default log set is: every active workspace's working-copy commit, their ancestors back to `trunk()`, `trunk()` itself, and every visible mutable head.
- **R2.03** implements `DescribeChange`, `AbandonChange` (how a divergent change is resolved, R1.13) and `UndoOperation`. From then on every operation Reef writes carries the attributes `reef.kind`, `reef.workspace` and `reef.agent`, where `agent` is the caller's `reef-agent` request metadata or else the workspace's owner. `SnapshotWorkspace` is its "snapshot now" and is already implemented.
- **R2.04** implements `FileService`. **R2.09** implements `SubscribeOperations` (cursors, frames, keepalives, `CURSOR_EXPIRED` when history is gone). **R2.10** implements `SubscribePresence` and the daemon's own `LEASE` and `PROGRESS` entries. **R2.11** implements `ReportPresence` and `ClearPresence`. **R2.12** builds replay on `at_operation` and `ListOperations`' time bounds, and adds what else it needs as new fields. **R2.15** adds symbol fields to `GetDiffRequest` and `FileDiff` at the next free numbers, and **R2.23** starts answering `GetStatus` with the `INDEX` and `WALK` sources already declared. **R2.08** adds a token service and enforces `access`. **R2.24** exports `reef_api::FILE_DESCRIPTOR_SET`. **R3.05** and **R4.01** add their own services or packages.
- Each of them returns errors with documented reasons, bumps `API_REVISION` for any schema addition, and is reviewed against ADR 0029's checklist.

**ADR 0029's API review checklist.**
1. `buf breaking` passes against `main`; nothing is removed, renumbered, renamed or moved.
2. `API_REVISION` and `API_DIGEST` are bumped.
3. Every new element has a leading comment giving its meaning, its unit, and what empty or zero means.
4. A new enum's zero is `_UNSPECIFIED`, with its meaning stated.
5. A new RPC sets `access` (and `idempotency_level` where it holds), and its request and response are named after it.
6. A List RPC has `page_size`, `page_token` and `next_page_token`.
7. A `WRITE` RPC's response has `Operation operation`.
8. References use `repo`, `workspace`, `revision` and `at_operation` as defined, and ids are full hex.
9. Errors' kinds and reasons are documented on the RPC.
10. The RPC is implemented or answers `NOT_IMPLEMENTED`.
11. CHANGELOG lists the addition.

Alternatives for the ADR: staying in `reef-daemon` (the CLI and the SDKs would need the daemon crate to reach the schema); `reef.daemon.v1` (the store will serve the same API); keeping v0 served beside v1 for a release (two handler sets for a pre-1.0 API with days-old users, and v0's raw error detail kept alive); `google.rpc.ErrorInfo` (above); AIP-160 filter strings and field masks (above); declaring only the R2.01 row's services (the abandoned attempt); `protoc` with `buf generate` for codegen (a toolchain dependency for every build, against R1.03's choice); no automatic restart (an agent's first command after an upgrade would fail, the friction RX.07 measures).

## Implementation notes

- Order: write the protos and `reef-api` first and get `buf lint` and `buf format` clean; send the protos for review before porting anything (the PR's first commit), then port the services, then the client and the CLI, then the compatibility path.
- Transcribe the sketch. If something in it cannot be implemented as written, stop and raise it rather than adjusting the schema silently; the brief and the PR change together. That rule is what keeps R2.02 onward additive.
- prost enum fields are `i32` in structs; use the generated accessors (`workspace.state()`, `set_state`) and convert to model enums in `convert.rs` only. `client/json.rs` maps each enum to the exact Phase 1 string (`apfs`, `fuse-overlayfs`, `stale-recovered`, `final`, `waiting`, `attaching`), and `WatchState::Attached` and `Unspecified` to `null`, so the CLI's JSON does not move.
- `CompatLayer`: record `req.uri().path()` in `call`, and map the response future. Rewrite only when `grpc-status` is `12` in the headers and `grpc-status-details-bin` is absent, so the declared stubs' own details pass through. Build the replacement with `reef_api::error::status(..).into_http()`. For the v0 detail, encode `reef_api::v0::ErrorDetail` as the raw details bytes, exactly as 0.1.0 decodes them.
- `Client`'s probe after a bare `UNIMPLEMENTED` costs two calls at most and runs only on that error; `GetDaemonStatus { skip_backends: true }` keeps it off the filesystem. The CLI's rerun must wrap the whole command dispatch, not one RPC, so `ws run` restarts before it spawns anything.
- The extra `Repo::operation` read on create is one small file; run `create_api` on `small` before and after and record both in the PR (printed, not gated).
- `buf` before pushing: `buf format -w`, `buf lint`, and `buf breaking --against <the registered root>/.git#branch=main`. A Reef workspace has no `.git`, so point `--against` at the repository's own root. On this PR the breaking check has nothing to compare and is expected to report no v1 files on `main`.
- Linux-only test files (`inotify_instances.rs`, `overlay_restart.rs`, the privileged tests) use the ported types and are not compiled on the Mac. Before pushing, in the privileged `ubuntu:24.04` container (`docs/benchmarks.md`, "Linux"), run `CARGO_BUILD_WARNINGS=deny cargo build --workspace --all-targets`, clippy with and without `--all-features`, and the overlayfs job's root filter.

## Out of scope

- Implementing any declared RPC: revset resolution, operation classification beyond the RPCs that write the operation, effects, status, diff, files, subscriptions and presence are R2.02 to R2.11.
- New CLI commands (`reef status`, `log`, `diff`, `undo`, `schema`), removing jj-lib from the CLI, and moving `Client` out of `reef-daemon` (R2.05, R2.24).
- Remote access, tokens, TLS, and enforcing `access` (R2.08); gRPC-web and gRPC reflection (R2.18 and later); SDK generation and publishing (R2.06, R2.07); `reef-agent` request metadata, whose first writer is R2.03.
- Request ids for retrying `CreateWorkspace` without a duplicate, and rate or size limits on the socket (the threat model lists the latter).

## Risks

- **The declared surface may be wrong somewhere.** Sixteen RPCs are designed before the tickets that implement them have briefs. The rule (deprecate and replace, never edit) means a mistake costs an unused declaration, not a migration; ADR 0029's checklist and the up-front review of the protos are the mitigation. The likeliest friction is R2.02's `OperationEffects` and the default log set, which are specified by meaning, not by algorithm.
- **The upgrade window.** A 0.1 `ws run` session whose daemon is stopped mid-run loses its heartbeats: the new daemon answers its v0 `Heartbeat` with `FAILED_PRECONDITION`, and its lease lapses after length plus grace. The automatic restart never fires while workspaces are active, and the CHANGELOG says to stop the daemon after sessions end; a user who stops it by hand during one gets this.
- **The restart touches a running process.** It reuses `daemon stop`'s pid agreement and never signals a daemon with active workspaces. A daemon whose pid file disagrees is reported, not stopped.
- **The port is wide.** Every test and the bench change their types, and an assertion lost in translation would hide a regression; the unchanged CLI JSON shape and the unchanged test count are the check, and the PR states both.
- **buf is a new tool.** Its output and its version move independently of Rust's; CI pins the version, and `reef-api` never needs buf to build, so a contributor without it can still build and test, with only `just ci` asking for it.
- **Descriptor digest stability.** The digest depends on protox's encoding of the descriptors; protox is pinned in `Cargo.lock`, and the test runs on both platforms in CI. A protox upgrade that changes encoding changes the digest without a schema change, and the PR that upgrades it updates `API_DIGEST` but not `API_REVISION`, with a note.
