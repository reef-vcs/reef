## 1. Claude Code: an issue on `anthropics/claude-code`

**Title:** WorktreeCreate providers: a release for subagent worktrees, a resume event, and the session's pid

**Body:**

> `WorktreeCreate` and `WorktreeRemove` let a hook replace git worktree creation "with a different version control system" ([hooks](https://code.claude.com/docs/en/hooks#worktreecreate)). Reef, a workspace manager for coding agents, uses them to hand each session a copy-on-write workspace instead of a worktree: <link to docs/workspace-provider.md>, adapter <link to the reef-workspaces plugin>. A provider like this hits four gaps, each with a workaround today:
>
> 1. **Subagent and workflow worktrees are never released.** Per the docs, Claude Code "keeps the worktree your WorktreeCreate hook made for it and doesn't run your WorktreeRemove hook" when a subagent or workflow agent finishes. A provider has to keep every subagent's workspace until the main session ends, and then until a lease runs out. Could `WorktreeRemove` (or a new `WorktreeRelease`) fire when a subagent's hook-made worktree is done with, even if the directory is kept?
> 2. **No event says a session resumed in a hook-made worktree.** On `--resume` or `--continue`, the session returns to its stored worktree path, and no worktree hook runs. A provider that ties a workspace's life to the session's process has to infer the resume from `SessionStart` with matcher `resume` and its `cwd`. Could `SessionStart` (or a `WorktreeResume`) carry `worktree_path` when the session resumes in one?
> 3. **The session's pid.** A provider keeps a hook-made worktree alive while the session runs. Today it walks up the hook's process tree past the shell to find the session. Could the common hook input carry the session's pid?
> 4. **JSON from command hooks.** HTTP hooks return `hookSpecificOutput.worktreePath`; command hooks return a path on stdout. Accepting the same JSON from a command hook would let a provider return an id beside the path.
>
> Reef's tests drive these hooks the way Claude Code runs them, and could serve as a conformance check: <link>. Measured with Claude Code <version>: <the live check's record: how hooks are spawned, whether resume fires `SessionStart` with the worktree as `cwd`>.

## 2. Codex: a comment on [openai/codex#50528](https://github.com/openai/codex/issues/50528)

> This issue asks for managed worktrees "created and removed by an external command (copy-on-write checkouts)". For a concrete shape: Reef implements one such command as a small documented contract, <link to docs/workspace-provider.md>:
>
> - `create`, `attach` and `release` take JSON on stdin (or flags) and print JSON, or just the path. `--at FIELD=POINTER` maps the harness's own event onto the fields, so the harness defines its event and the provider adapts.
> - **The holder rule**: the workspace lives while a named process (the session) runs, and is reclaimed with a final snapshot some time after it exits. A crashed session leaves nothing behind for long, and a resumed one finds its directory.
> - **Attach on resume**: a restarted session takes its directory back.
>
> One harness already exposes this point as a documented hook: Claude Code's `WorktreeCreate` and `WorktreeRemove` command hooks, with the event on stdin and a path on stdout ([docs](https://code.claude.com/docs/en/hooks#worktreecreate)). opencode v2 exposes it as a worktree strategy plugin ([source](https://github.com/anomalyco/opencode/blob/dev/packages/plugin/src/promise/worktree.ts)). Since external PRs are not accepted, which shape would the maintainers want: a configured command with JSON in and a path out, or something else? Reef would adapt to it.
