# R2.27 VCS commands in the CLI

Phase 2 · Size L · Depends on: R2.04 (`FileService`, the last of the v1 services these commands call), R2.05 (`reef-client`, `--agent`, the three not-found reasons), and through them R2.02 and R2.03 · Unblocks: R2.24 (`reef schema` describes the whole command tree); R2.17 measures tokens through these commands

## Context

R2.02, R2.03 and R2.04 implemented the read side, the write side and the file API of `reef.api.v1`, and each left its commands to the CLI: `reef status`, `log` and `diff` (R2.02), `reef describe`, `abandon` and `undo` (R2.03), and whether the CLI reads files (R2.04). R2.05 had all of it in its row; its brief split the row, kept the thin client as R2.05 (merged as #82), and wrote this ticket's decisions as Part B of `R2.05-cli-as-thin-client.md`. That draft predates R2.05's code. This brief is Part B checked against the code as #82 left it, with the names fixed, the decisions it left open made, and what R2.05 did differently from its brief accounted for.

The commands are thin: each resolves which workspace or repository it means, makes one or two calls through `reef_client::Client`, and prints the response as JSON or text. The work is in the parts every command shares: the scope rule, the JSON for v1 messages that Phase 1's types never covered, and the CLI's own `hint` and `next` for the API's error reasons, which the daemon cannot write because it does not know which command sent a request. One daemon change: a reason for a snapshot that fails before a read or a write, so the CLI can offer `--no-snapshot` without reading a message.

After this ticket an agent never needs `jj` to see or undo what agents did: the guide's "Not yet" section, which still says "run `jj` in the repository's own root", goes, and the quickstart's `jj diff`, `jj file show` and `jj abandon` become `reef` commands.

Part B was written before #82. Checked against the code, these change:

### Scope: which workspace and repository a command means

Every new command except `op log` and `op show` resolves a scope once, in `cli/scope.rs`, before its own call. In order:

1. **`--workspace <WS>`**: `GetWorkspace { repo: <--repo's text or empty>, workspace: <WS>, snapshot_first: false, skip_disk_usage: true }`. A `WS` that exists on disk is sent as its canonical absolute path (the daemon reads only absolute paths as paths); anything else as given, an id or unique prefix. `--repo` alongside narrows the lookup to that repository.
2. **`--repo <REPO>`** alone: the repository, and no workspace, even when run inside one. `RepoArg::parse(REPO)`, then `GetRepository` through `call_with_repo`, so a path in an unregistered checkout registers it as every other command does.
3. **`REEF_WORKSPACE`** when set and not blank (as `here` reads it): looked up as in 1. Not found is an error, with the daemon's advice; it never falls back to the directory.
4. **The current directory**, canonical: looked up as in 1. Reason `WORKSPACE_NOT_FOUND` means "not in a workspace", and the scope is the repository containing the directory, as in 2 with the directory as the path. Any other error is returned.

The result is `Scope { repo: Repository (id, root), workspace: Option<Workspace>, dir: PathBuf, from_flags: bool }`: `dir` is the workspace's `path` or the repository's `root`; `from_flags` is true for 1 and 2. Every request the command then sends carries `repo: <repo id>` and `workspace: <workspace id>` (full ids, so nothing resolves twice) or an empty `workspace`.

The lookup is one RPC (two in a repository root outside every workspace), about a millisecond each over the socket. A scope workspace in any state is accepted: reads of a released workspace's commits work, and the daemon refuses `GetStatus` and writes on an inactive one with its own `next`.

`op log` and `op show` need only a repository: `--repo`, else the repository of the scope steps 3 and 4 find. `op log`'s `--workspace` is a filter (repeatable, `filter.workspaces`), never a scope, and takes the same path handling as 1. `undo` resolves the full scope: it sends the workspace, which `UndoOperation` snapshots first and checks out afterwards.

### Paths

- **Given paths** (`diff`'s `PATHS`, `file read`'s and `file list`'s `PATH`): an absolute path inside `dir` is made repository-relative. A relative path, when the scope came from steps 3 or 4 and the canonical current directory is inside `dir`, is relative to the current directory, as `jj` takes paths: joined to it, normalized lexically (`.` and `..` components resolved without touching the disk, since the path may exist only at another revision), and stripped of `dir`. Otherwise (`--workspace` or `--repo` given, or the current directory outside `dir`) a relative path is repository-relative as given. A path that leaves `dir` is refused before the command's call: exit 2, kind `invalid_argument`, reason `INVALID_PATH`, message `<path> is outside <dir>`, hint as in the table below. Separators are `/`; the API's own checks then apply.
- **`file list` with no `PATH`** lists the current directory when the relative rule applies and the current directory is not `dir` itself, else the root. `diff` with no paths diffs every path, wherever it is run, as `jj diff` does.
- **Printed paths are repository-relative**, in JSON and text, in every command: the API's form, the same from any directory. A `next` always carries `--workspace` or `--repo`, so the paths in it are repository-relative too and it runs verbatim from anywhere.

### The commands

Shared argument groups, flattened into each command that takes them:

- `ScopeArgs`: `--workspace <WS>` ("A workspace id, unique prefix, or path inside it [default: the one you are in]") and `--repo <REPO>` ("The repository (id, id prefix, or path), and no workspace").
- `ReadArgs`: `--at-op <OP>` (visible alias `--at-operation`; "Read at this operation (id or unique prefix) instead of now") and `--no-snapshot` ("Read the last snapshot instead of snapshotting the workspace first").

| Command | Arguments | Calls |
| --- | --- | --- |
| `status` | `[--max-files N] [--no-snapshot]`, scope | `GetStatus { repo, workspace, skip_snapshot, max_files }` |

`op` is a noun with `log` and `show` (visible alias `operation`, `infer_subcommands`); `file` is a noun with `read` (visible alias `cat`) and `list` (visible alias `ls`). `--help` lists the new top-level commands right after `here`, in the table's order: `status`, `log`, `show`, `diff`, `describe`, `abandon`, `undo`, `op`, `file`, then `guide` and the rest as now. Each has a one-line `about` and, for `log`, `diff`, `describe` and `file read`, an `after_help` example. `ws snapshot` goes after `ws inspect` in `ws`.

Rules across the table:

- **Defaults.** `REV` and `-r` default to `@`, which needs a workspace in scope (else the daemon's `WORKSPACE_REQUIRED`, with the CLI's hint). `log` without `-r` sends an empty revset: Reef's default log set, `trunk() | working_copies() | mutable()`. `diff` with no revision flag diffs `@` against its parents (`from_revision` and `to_revision` empty); `-r X` is `to_revision: X`; `--from A` alone is `A` against `@`; `--to B` alone is `B` against its parents, the same as `-r B`; `-r` conflicts with `--from` and `--to` (clap). `--stat` is `DIFF_FORMAT_STAT`, `--summary` `DIFF_FORMAT_SUMMARY`, neither `DIFF_FORMAT_HUNKS`; `--context N` sets `context_lines`; `max_lines_per_file` is left 0 (1,000).
- **Limits.** `log` and `op log` take `--limit N`, default 100, `0` for all. They read pages of `min(N, 1000)` (1,000 when `N` is 0) and stop once they hold `N`; when more exist, stderr says `reef: showing the first N changes (operations); --limit 0 shows all` in both modes, unless `-q`, as `ws list` notes its cut. `status --max-files N` is passed through (0 means 100, the API's rule). `diff`, `show` and `file list` follow every page; `file read` follows `offset` to `size`.
- **Never interactive.** `describe` requires `-m` (clap: a usage error naming `--message`); several `-m` values are joined with a blank line, as `jj describe` joins them, and `-m ''` clears the description. `ws snapshot -m` takes one value. Nothing reads stdin or opens an editor.
- **`undo` names its operation.** `[OP]` is optional to clap so that its absence can carry a `next`: with none, after the scope resolves, exit 2, kind `invalid_argument`, message `name the operation to undo`, hint "Name the operation to undo; `reef op log` lists them, newest first.", `next` `reef op log --repo <repo id>`. There is no "undo the last operation": watchers and other agents record operations every second, so the last one is rarely the caller's (R3.26 scopes undo by agent). **`abandon`'s `REV` is required by clap** (a usage error): `@` is the change the caller stands on, the wrong default to make implicit.
- **`--expected-commit`** is `expected_commit_id`, passed as given; the daemon requires a full commit id (`INVALID_COMMIT_ID` otherwise).
- **`op log` filters** map to `OperationFilter`: `--workspace` to `workspaces`, `--change` to `changes` (hex or reverse-hex prefixes), `--by` to `agents`, `--kind` to `kinds`. `--kind` is a clap `ValueEnum` of the `reef.kind` names (`snapshot`, `create-workspace`, `release-workspace`, `move-workspace`, `describe`, `abandon`, `undo`, `edit`, `import-refs`, `external`, `other`), so anything else is a usage error that lists them. `--effects` sets `include_effects`. `--by`, not `--agent`, since a subcommand cannot reuse the global flag's name.
- **`ws snapshot`** with `WS` sends it (an existing path made canonical and absolute, as for `--workspace`). Without, it resolves the scope's steps 3 and 4 only; outside every workspace that is exit 2, kind `invalid_argument`, reason `WORKSPACE_REQUIRED`, message `not in a workspace`, hint "Name the workspace, or run this inside one.", `next` `reef ws list`. It is the explicit form of what `ws inspect` does on the way to its report and `ws run --keep` does at exit: a snapshot of kind `explicit`, with `-m` as the operation's description (empty for the daemon's `reef: snapshot workspace <id>`).
- **`file read` prints raw bytes, even on a pipe**, as `config show` prints TOML: the bytes are the machine-readable form, and `reef file read a.rs | …` must work. `-o json` or `REEF_OUTPUT=json` asks for the object (`main` adds `Command::File(args) if args.is_read()` to the arms that default to text). Each 1 MiB range is written as it arrives, so memory stays at one range; ranges after the first send `revision: <the first response's commit_id>` and `skip_snapshot: true`, as `read_file_to_end` does, so a write in between cannot mix two versions. A symlink prints its target and a conflict jj's materialization with markers, as `ReadFile` returns them. With `-o json` the whole file is read into the one object.
- **`file list` prints a list**: a JSON array of entries (ADR 0025, "one array for lists"), without the commit; `reef show <REV>` names it.
- **No `reef file edit`.** `EditFiles` is for agents without a directory, which reach it through MCP (R2.13). From a shell, the workspace is the editor.
- **Exit codes** are the error kinds', as for every command. A diff with differences, a status with changed files, and a log with conflicts all exit 0.
- **The agent name** (`--agent`, `REEF_AGENT`, R2.05) reaches every operation these commands cause, through the client: describe, abandon, undo, `ws snapshot`, and the snapshots reads take first.

### Write results and divergence (issue #80)

`describe`, `abandon`, `undo` and `ws snapshot` run in a workspace scope can leave that workspace's change divergent: through #80's window, or because another workspace on the same change wrote meanwhile. The responses do not say so for the caller's workspace (only `DescribeChangeResponse.change.divergent` covers the described commit), so:

- **After the write**, when the scope has a workspace, the command reads it once more (`GetWorkspace`, no snapshot, no disk usage) and returns it as `workspace` in its JSON; `null` in repository scope. A failure of that read is a stderr warning, `reef: could not read workspace <id> after the write: <error>`, and `workspace: null`; the write succeeded, so the exit is 0.
- **When `workspace.divergent`** is true, stderr says, in both modes and unless `-q`: `reef: workspace <id> is divergent: its change <change, 12 reverse hex> has more than one commit. See them with: reef log --workspace <id> -r 'change_id(<reverse hex>)'; abandon the one to drop with reef abandon <commit id>.` The exit stays 0.
- **`here`** points a divergent workspace at the same command: hint "Its change is divergent: two or more commits of one change. List them, then abandon the one to drop (reef abandon <commit id>).", `next` `reef log --workspace <id> -r 'change_id(<reverse hex>)'`. The note and `here` build that argv through one function and quote it with `shell_line`, so the parentheses survive a shell. A workspace with another attention reason keeps `next` `reef ws inspect <id>`.
- `log`'s text marks divergent changes, `status` lists `divergent_change_ids`, and every `Change` and `Workspace` in JSON has `divergent`. When #80 is fixed, the note simply fires less; nothing here changes.

### JSON

The new types live in `reef_client::json`, beside Phase 1's, so R2.13 can reuse them and R2.24 derives their schemas in one place. Conventions, as Phase 1's set them:

- Keys are the v1 field names, `snake_case`. Ids are full lowercase hex. Every object with a `change_id` also has `change_id_reverse_hex` (lists of ids, such as `parent_change_ids`, stay hex). Timestamps are RFC 3339 with milliseconds (`json::rfc3339`). A string the API leaves empty to mean "none" (`trunk_bookmark`, `old_path`, an effect's `commit_id` or `previous_commit_id`, an operation's `workspace_id`, `jj_workspace` or `agent`, `file_id`) prints as `null`; free text (`description`) stays a string, empty or not. Counts are numbers. An unset message field is `null`.
- Enums print as lowercase names with `-` between words, an unknown value as `unknown`, an unset one as `null`: entry types `file`, `executable`, `symlink`, `directory`, `conflict`, `submodule`; file changes `added`, `modified`, `deleted`, `renamed`, `copied`; status sources `snapshot`, `index`, `walk`, `last-snapshot`; graph edges `direct`, `indirect`, `missing`; change effects `created`, `rewritten`, `abandoned`, `hidden`; operation kinds the `reef.kind` names; snapshot kinds as `ws inspect` prints them (`watcher`, `explicit`, `final`, `move`, `shutdown`), through a new `snapshot_kind_opt` that is `None` for unset. Error metadata is the API's, verbatim (`type` is `ENTRY_TYPE_DIRECTORY`, not `directory`).
- **`Change`**: `change_id`, `change_id_reverse_hex`, `commit_id`, `parent_commit_ids`, `parent_change_ids`, `description`, `author` and `committer` (`Signature`: `{name, email, at}`), `tree_id` (`null` when conflicted), `empty`, `conflict`, `divergent`, `immutable`, `hidden`, `bookmarks`, `tags`, `workspace_ids`, `jj_workspaces`.
- **`LogEntry`**: a `Change`'s keys (flattened) plus `edges` (`[{commit_id, kind}]`). `log` prints an array of them.
- **`Operation`**: `id`, `repo_id`, `parent_ids`, `description`, `started_at`, `ended_at`, `hostname`, `username`, `is_snapshot`, `kind`, `snapshot_kind`, `workspace_id`, `jj_workspace`, `agent`, `attributes` (object), `effects`: `null` unless computed, else `{changes: [{change_id, change_id_reverse_hex, kind, commit_id, previous_commit_id}], bookmarks: [{name, remote, commit_id, previous_commit_id, conflicted}], working_copies: [{workspace_id, jj_workspace, commit_id, previous_commit_id}], change_count, bookmark_count}`. `op log` prints an array; `op show` one object. Phase 1's types keep naming operations `op_id`; these are whole operations, so they are `operation` and their own key is `id`.
- **`FileChange`**: `path`, `kind`, `old_path`, `old_type`, `new_type`. **`FileDiff`**: a `FileChange`'s keys plus `binary`, `conflict`, `lines_added`, `lines_removed`, `hunks` (`[{old_start, old_lines, new_start, new_lines, lines}]`), `truncated`, `old_no_final_newline`, `new_no_final_newline`, `too_large`, `invalid_utf8`. With `--summary` the line counts are 0 and `hunks` empty, and with `--stat` `hunks` is empty, as the API returns them; the shape never changes with the flag.
- **`Diff`** (`diff`): `{from_commit_ids, to_commit_id, at_operation, total_files, files}`.
- **`ChangeSummary`** (`show`): a `Change`'s keys plus `at_operation`, `files` (`FileChange`s) and `total_files`.
- **`RepoStatus`** (`status`; `json::Status` is `daemon status`'s): `repository` (Phase 1's `Repository`), `at_operation`, `repository_status` (`{trunk, trunk_bookmark, active_workspaces, active_workspace_count, heads, head_count, conflicted_change_ids, divergent_change_ids, last_operation}`, `active_workspaces` as Phase 1's `Workspace`), `workspace_status` (`{workspace, working_copy, parents, changed_files, changed_file_count, conflicted_paths, conflicted_path_count, source, snapshot}`, or `null` in repository scope).
- **Writes**: `Described` `{change, operation, workspace}`; `Abandoned` `{abandoned_commit_id, operation, workspace}`; `Undone` `{operation, snapshot, undone_operation_id, workspace}`; `Snapshotted` (`ws snapshot`) `{changed, commit_id, scan_ms, operation, workspace}`. `operation` is `null` when nothing was recorded (a describe to the same text, an undo with nothing to revert, a snapshot that found nothing), `workspace` as above.
- **`FileEntry`** (`file list`): `{path, type, file_id}`. **`FileRead`** (`file read -o json`): `{path, type, file_id, size, commit_id, at_operation, content, content_base64}`: `content` is the bytes as a string when they are valid UTF-8, else `null` with `content_base64` set (standard alphabet, padded); exactly one of the two is non-null. `base64` becomes a dependency of `reef-client`.
- **The error object gains `metadata`**: `ErrorDetail.metadata` as a JSON object of strings, present only when not empty (`#[serde(default, skip_serializing_if = "BTreeMap::is_empty")]`, so the helper protocol still parses old documents). An agent reads `AMBIGUOUS_REVISION`'s `commit_ids` or `EXPECTED_COMMIT_MISMATCH`'s `commit_id` as data instead of out of a message. Every command's errors carry it, Phase 1's too; text mode is unchanged. Additive (ADR 0025 decision 5).

### Text

Short, one record per line where there is a list, no colors, no pager, for a person or a model reading a terminal. Ids: changes by 12 reverse-hex characters, commits and operations by 12 hex.

- `status`: `Workspace <id> on <change> <commit> <first description line or (no description)>`, `Parent <change> <commit> <first line>` per parent, `Changed files (<count>):` and one line per file (`A path`, `M path`, `D path`, `R old -> new`, `C old -> new`), `… and N more` when capped, `Conflicted paths (<count>):` when any; then `Repository <id> at <root>`, `Trunk <bookmark> <change> <commit>` (or `Trunk none`), `Workspaces: <count> active`, `Heads: <count>`, `Conflicted changes:` and `Divergent changes:` lines when not empty. With `--no-snapshot`, a last line `(as of the last snapshot; edits since may be missing)`. In repository scope, the repository part only.
- `log`: one line per change: `@` when the scope's workspace is on it, else a space; the change; the commit; bookmarks; the markers `conflict`, `divergent`, `empty`, `immutable`, `hidden` that apply; and the description's first line or `(no description)`. No graph: the JSON's `edges` carry it, and R2.19 draws it.
- `show`: `key: value` lines (`change`, `commit`, `author` and `committer` as `name <email> at`, `bookmarks`, `parents`), the description indented four spaces, then the summary lines as in `status`.
- `diff`: per file, git-style: `diff --git a/<old> b/<new>`, `rename from`/`rename to` or `copy from`/`copy to` lines, `--- a/<old>` or `--- /dev/null`, `+++ b/<new>` or `+++ /dev/null`, then each hunk's `@@ -s,l +s,l @@` and its `lines` as they come; `Binary files differ`, `File too large to diff (over 16 MiB)`, and `(conflict)` where they apply; `(diff truncated at 1,000 lines)` when `truncated`; `\ No newline at end of file` after the hunks when either side lacks one. For reading: it is not promised to `git apply` (no index or mode lines). `--stat`: `<path> | +A -R` per file and `<N> files changed, +A -R`. `--summary`: the summary lines.
- `describe`, `abandon`, `undo`, `ws snapshot`: one line on stderr through `out.done`: `described <change> as <commit>` (or `<change> already has that description`), `abandoned <commit>`, `undid <op> as <op>` (or `nothing to undo in <op>`), `snapshot <op> of <ws>: <commit>` (or `nothing to snapshot in <ws>`). The divergence note follows when it applies.
- `op log`: `<op> <ended_at> <kind>[/<snapshot kind>] <workspace id or -> <agent or -> <first description line>`. `op show`: the same fields as `key: value` lines, then effects, one per line (`created <change> <commit>`, `rewritten <change> <old> -> <new>`, `bookmark <name> -> <commit>`, `working copy <ws> -> <commit>`).
- `file list`: one path per line; in a non-recursive listing directories end in `/`. `file read`: the bytes.

`log`'s and `file list`'s text are not tables, so they print through a `#[serde(transparent)]` wrapper (`LogLines`, `FileLines`) that implements `TextRender`; `Out::list` stays the headed table.

### Errors: the CLI's advice for API reasons

The daemon's hints are in the API's words and, for these reasons, carry no `next`: it cannot know which command, if any, sent the request. The CLI does. In `cli/advice.rs`:

- **The daemon's `next` wins.** An error whose advice has a `next` keeps its advice as sent (those are already `reef` argv): `WORKSPACE_NOT_FOUND` (`reef ws list --all`), `REPOSITORY_NOT_REGISTERED` under `--no-register` (`reef repo register <path>`), `REPOSITORY_NOT_FOUND`, a workspace that is not active (`reef ws create --repo <id>`), and a write's snapshot failure (`reef ws inspect <id>`).
- **Otherwise the table** below, keyed by reason and, where noted, by what the command was given, replaces the hint (or keeps the daemon's where it says so) and sets `next` where the fix is a command the CLI can build. A reason not in the table keeps the daemon's advice.
- **Every `next` is built from known values**: the scope, the command's own arguments, and the error's metadata. Never a placeholder. "Scope flags" means `--workspace <workspace id>` when the scope has a workspace, else `--repo <repo id>`; `--repo` means `--repo <repo id>`. "Own argv" is the process's arguments with `reef` as the first word, which runs from the directory it ran in.
- **The result is `CliError::Advised { error: ClientError, advice: Advice }`**: kind, reason, message and metadata the error's, advice the table's. Errors the CLI raises before a call with a reason (`INVALID_PATH`, `WORKSPACE_REQUIRED` for `ws snapshot`) are a new `CliError::Precheck { kind, reason: &'static str, message, advice }`. `Refused` is unchanged.

### `SNAPSHOT_FAILED`

The one daemon change. A reason constant in `reef_api::error` ("A workspace could not be snapshotted before a read or a write; metadata `workspace_id`. Kind: the snapshot error's own."), mapped in `reason_and_metadata` for `ReadError::Snapshot` and `ManagerError::RewriteSnapshot`. `ReadError::Snapshot` becomes `Snapshot { workspace: WorkspaceId, source: Box<ManagerError> }`, filled at `reading.rs:110` from the record it snapshots. Both are outermost in their chains, so the reason shadows any reason of the cause (a snapshot that failed because the workspace vanished is `SNAPSHOT_FAILED`, which is what the caller needs to know). Kinds, messages and advice are unchanged; the write path's `next` (`reef ws inspect <id>`) still wins. The "Errors:" paragraphs that say "a failed snapshot's own error" (`changes.proto`'s header, `status.proto`, `files.proto`'s `ReadFile` and `ListFiles`) and "when a workspace could not be snapshotted first" (`AbandonChange`, `UndoOperation`, `EditFiles`) name the reason. Comment changes and a constant: `API_REVISION` stays 3 and the digest does not change.

### `status` stops being an orientation guess

`reef status` is a command, so `status` leaves `ORIENTATION_GUESSES`; `info`, `where`, `whereami` and `whoami` keep pointing at `reef here`. The two answer different questions and both stay: `here` is the cheap "where am I, what next" (no snapshot, no diff); `status` snapshots and lists what changed.

### Prefixes that change

ADR 0025 foresaw this; full names never break, and an ambiguous prefix is a usage error listing the candidates, never a guess. `reef s` and `reef st` (today `store`) become ambiguous (`show`, `status`, `store`; `status`, `store`); `reef d` (today `daemon`) becomes ambiguous (`daemon`, `describe`, `diff`); `reef a` (today `guide`, through its `agent-guide` alias) becomes ambiguous with `abandon`, if clap counts aliases in inference (the test pins whichever it does). `reef sto`, `reef da`, `reef ag`, `reef gu` and every full name keep working. No alias is added for `status`: making `st` mean `status` would silently change what `reef st ls` does.

## Implementation notes

- **Order**: `scope.rs` and its path functions with test 22; the JSON types and their unit tests; `status`, `log`, `show`, `diff` (tests 1 to 6); `CliError::Advised`, `Precheck`, `metadata` and `advice.rs` with tests 15, 18 and 21, since every command feeds them; the writes and `undo` (7 to 9, 14, 16); `op` (10); `ws snapshot` (11); files (12, 13); the daemon reason (17, 20); `here`, prefixes and the updated tests (3, 19, 23, 24); then the guide, quickstart, README, ADR and CHANGELOG.
- **Reuse, do not copy**: `RepoArg`, `call_with_repo`, `absolute`, `Out`, `shell_line`, `json::reverse_hex`, `json::rfc3339`, `json::Workspace` and `json::Repository`. The divergence note and `here` build the same argv through one function in `scope.rs`.
- **Lexical normalization** of given paths: resolve `.` and `..` by components against the canonical current directory, without `canonicalize` (the path may not exist at the working copy, only at `-r`). `dir` is compared canonical, as the daemon records workspace paths and roots canonical.
- **`show`'s second call** sends `to_revision` as the commit id `GetChange` returned and `at_operation` as its `at_operation`, with `skip_snapshot`, so it reads the same view and never snapshots twice.
- **`file read`'s streaming**: write each range with `out.raw` as it arrives; the first response's `size` decides when to stop; an empty range before `size` ends the read (the file shrank between ranges cannot happen, since later ranges read the same commit, but do not loop on it).
- **Own argv**: `std::env::args_os()`, first word replaced by `reef`, non-UTF-8 arguments lossily converted; the `next` is advice, and a command with non-UTF-8 arguments is rare enough.
- **`metadata` through `CliError`**: `metadata()` returns the `ClientError::Rpc` map for `Daemon`, `Advised` and `OldDaemon` (empty for `Incompatible`), and nothing for the rest; `Precheck` carries none.
- Linux: nothing here is `cfg(target_os = "linux")`. Test 17 skips as root, so CI's root kernel-overlay job does not cover it; the unprivileged jobs do. Before pushing, in the privileged `ubuntu:24.04` container (`docs/benchmarks.md`, "Linux"), run `CARGO_BUILD_WARNINGS=deny cargo build --workspace --all-targets` and clippy with and without `--all-features`.

## Risks

- **Prefix breakage.** `reef s`, `reef st`, `reef d`, and possibly `reef a`, stop resolving. An agent that learned them gets a usage error listing the candidates, not a wrong command; full names in the guide and the docs are unaffected.
- **The advice table can drift from the daemon's reasons.** A reason added later without a row keeps the daemon's API-worded hint, which is correct if awkward. Test 21 lists the rows; a later brief that adds a reason a CLI command can hit says whether it needs a row, and adds it in the same PR.
- **Implicit registration from a read.** `reef status` in an unregistered git checkout registers it and initializes jj alongside git, as `ws create` and `ws run` do. That is the existing rule (R1.25) and `--no-register` opts out; a read command doing it may surprise someone running `reef status` to look. The stderr line says what happened, and `reef repo forget .` undoes it.
- **Paths in and out differ in a subdirectory.** A path printed from `src/` is `src/a.rs`, and passed back from `src/` it means `src/src/a.rs`. jj has the same split for some commands and git for most; the rule is the one that keeps `next` runnable from anywhere. An absolute path, or `--workspace`, always works.
- **Divergence after writes stays visible until #80 is fixed.** An agent that writes files in its workspace while describing or undoing there will see the note more often than it should. The note says exactly how to resolve it.

## Choices this brief made, and why

- **The scope is resolved once by the CLI**, with one extra lookup, rather than sending paths for the daemon to resolve on each call: the CLI needs the workspace's directory for paths and its id for every `next`.
- **Printed paths are repository-relative**: one form per path, the API's, and the form every `next` takes.
- **Writes return the workspace afterwards**: one cheap read makes divergence visible where it happens, without waiting for #80 or for the agent to run `here`.
- **The CLI owns `next` for the API's reasons**, rather than the daemon building CLI argv from request fields: only the CLI knows which command ran, and MCP and SDK callers keep hints in the API's words.
- **`undo` and `abandon` require their argument**: with watchers and several agents recording operations, "the last one" and "the one I am on" are the wrong defaults to make implicit.
- **`file read` and `file list`, not `file edit`**: reading another revision without checking it out is useful from a shell; editing from a shell is what a workspace is for.
- **One daemon reason** rather than reading the hint: the CLI never parses messages (R2.05 removed the last place it did).
