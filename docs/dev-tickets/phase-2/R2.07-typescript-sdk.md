# R2.07 TypeScript SDK

Phase 2 · Size S · Depends on: R2.01 (the v1 schema and error envelope), R1.28 (the release workflow), R2.06 (ADR 0038 and the shared `just sdk-proto`, `sdk-version-check` recipes; the two can land in either order if whichever is second adds its section) · Unblocks: R2.11 (presence from the handle), R2.18 (the web UI imports this package's generated code and uses Connect's gRPC-web transport)

## Context

The second SDK ADR 0004 promised, for the harnesses and agents written in TypeScript. Beyond what R2.06 says for Python, this package has a second consumer: the web UI (R2.18) runs in a browser against the daemon's web listener (R2.08) with gRPC-web, and must share one generated code base with the Node client so the two cannot drift. That is why the codegen is `@bufbuild/protobuf` and the transports are Connect's: the same generated service descriptors work with `createGrpcTransport` (Node, HTTP/2, the Unix socket) and `createGrpcWebTransport` (browser), and the Rust `Client`'s method list is mirrored on both.

### What was verified while writing this ticket

Reef at `d156d1e`; npm and sources fetched on 2026-10-25.

- **Versions**: `@bufbuild/protobuf` 2.16.0, `@bufbuild/protoc-gen-es` 2.16.0, `@bufbuild/buf` 1.75.0, `@connectrpc/connect` 2.2.0, `@connectrpc/connect-node` 2.2.0, `@connectrpc/connect-web` 2.2.0, `@grpc/grpc-js` 1.14.6, `pnpm` 12.15.0 (`npm view`). **`@connectrpc/connect-node@2.2.0` declares `engines.node: ">=22"`** and peer-depends on `@bufbuild/protobuf ^2.7.0` and `@connectrpc/connect 2.2.0`. The local Node is v22.16.0 and exposes `Symbol.dispose` and `Symbol.asyncDispose` (checked), which `await using` compiles to.
- **The Unix socket path through Connect.** `createGrpcTransport` (connect-es `packages/connect-node/src/grpc-transport.ts`) spreads its options, forces `httpVersion: "2"`, and passes them to `validateNodeTransportOptions` (`node-transport-options.ts`), whose `NodeHttp2TransportOptions.nodeOptions` is documented as "Options passed to the connect() call of the Node.js built-in http2 module" and is handed to `new Http2SessionManager(baseUrl, pingOptions, options.nodeOptions)`; the manager calls `http2.connect(authority, http2SessionOptions)` with that object unchanged (`http2-session-manager.ts`). Node's `http2.connect` options accept `createConnection`, "an optional callback that receives the `URL` instance passed to `connect` and the `options` object, and returns any `Duplex` stream that is to be used as the connection for this session", and "any `net.connect()` or `tls.connect()` options" (nodejs.org/api/http2.html). So `createGrpcTransport({ baseUrl: "http://reef", nodeOptions: { createConnection: () => net.connect(socketPath) } })` is the supported route, and `nodeOptions: { path: socketPath }` (net.connect's Unix-socket option) is the one-liner alternative; the daemon ignores the `:authority` the dummy `baseUrl` produces, as it ignores the Rust client's `http://[::]:0` (`crates/reef-daemon/src/client/mod.rs:114`). Supplying a `sessionManager` makes `nodeOptions` ineffective; the SDK does not.
- **`@grpc/grpc-js`** accepts `unix:` and `unix:///abs/path` targets (grpc/grpc `doc/naming.md`: supported by "most gRPC implementations", Unix only; grpc-js implements the naming scheme). It is the fallback if the Connect route fails in practice.
- **Errors on the wire.** tonic puts the status details bytes, base64-encoded, into the `grpc-status-details-bin` trailer (tonic 0.14.6 `src/status.rs:561-567`). connect-es's gRPC protocol (`packages/connect/src/protocol-grpc/trailer-status.ts`, `findTrailerError`) reads that trailer first and decodes it with `decodeBinaryHeader(statusBytes, StatusSchema)`, `google.rpc.Status`, with no `try`/`catch` and no fallback to `grpc-status`; a successful decode yields a `ConnectError` whose `details` carry each `Any` and whose `metadata` is the trailer map, and `error.findDetails(schema)` decodes a detail by schema. Today's daemon sends raw `ErrorDetail` bytes, which are not a `google.rpc.Status` (its field 1 is a string where `Status.code` is an int32), so the decode fails or misreads; **this SDK depends on R2.01 adopting the standard envelope** (see "Proposed departure from the README", shared with R2.06).
- **Publishing.** docs.npmjs.com, "Generating provenance statements": `npm publish --provenance` needs `permissions: id-token: write`, a GitHub-hosted runner, npm ≥ 9.5.0, `--access public` on a first publish, and a public `repository` field in `package.json` matching the publishing repository (case-sensitive); `NPM_CONFIG_PROVENANCE=true` or `publishConfig.provenance` are equivalents; with npm trusted publishing (OIDC) configured on npmjs.com, provenance is automatic and no token is needed, otherwise `NODE_AUTH_TOKEN` from a secret. `reef-vcs` on npm: `npm view reef-vcs` errored (consistent with no such package; the log was not read) and `reef` exists at 0.0.1; the implementer confirms the name is free before the first publish.
- **Rust side**: `Client::connect` and the per-RPC methods (`client/mod.rs:135-363`) are the list this wrapper mirrors; `default_owner` (`client/mod.rs`) is the owner string `ws run` sends; `cli/env.rs:10-17` the four `REEF_*` variables; `cli/ws_run.rs:530-620` the heartbeater's backoff and lapse warning this handle copies.

## Decisions

- **Node 22+** (`engines.node >= 22`), because `@connectrpc/connect-node@2` requires it and Node 20 left maintenance in April 2026. See the departure note.
- **Layout.** `sdk/typescript/`: `package.json` (name `reef-vcs`, `type: module`, `exports` for `.` and `./gen`, `files`, `repository` pointing at `reef-vcs/reef` with `directory: sdk/typescript`, `packageManager: pnpm@12.x` pinned to the version in use), `tsconfig.json` (ES2022 target, `module: NodeNext`, strict), `buf.yaml` (module root `proto`), `buf.gen.yaml` (`local: protoc-gen-es`, `out: src/gen`, `opt: target=ts`), `proto/` (the `just sdk-proto` copy), `src/gen/` (generated, committed), `src/{index,socket,errors,client,workspace,owner}.ts`, `tests/`, `README.md`. A `pnpm-workspace.yaml` at the repository root lists `sdk/typescript` and `ui`; `ui` is R2.18's.
- **Codegen is committed.** `pnpm gen` runs `buf generate` (the `@bufbuild/buf` npm package, no system `protoc`; buf resolves the well-known types itself). `src/gen` is committed so consumers who clone do not need buf, and CI's drift check is `pnpm gen && git diff --exit-code src/gen`. protoc-gen-es v2 emits message schemas and service descriptors in one plugin; no `protoc-gen-connect-es`.
- **Transport.** `createGrpcTransport({ baseUrl: "http://reef.sock", nodeOptions: { createConnection: () => net.connect(socketPath) } })`, HTTP/2 over the Unix socket. The first integration test proves it against a real daemon; if it fails for a reason the test can name, the fallback is `@grpc/grpc-js` with a `unix:` target and `@grpc/proto-loader`-free generated clients (protoc-gen-es types plus a tiny grpc-js call shim), decided in the PR and recorded in ADR 0038. The transport is created once per `Client` and shared by every service client (`createClient(ServiceDesc, transport)` from `@connectrpc/connect`).
- **Socket resolution** (`src/socket.ts`, `defaultSocket()`): the same rule as R2.06's `default_socket()` and the daemon's (`REEF_SOCKET`; `REEF_STATE_DIR` or the platform default state directory; `$XDG_RUNTIME_DIR/reef/daemon.sock` only for the default state directory on Linux; macOS `~/Library/Application Support/reef/daemon.sock`). No `config.toml`. Windows throws `ReefError("Unavailable")`.
- **`Client`.** `new Client({ socket?, autostart = false, timeoutMs = 60_000 })`; `client.daemon.status()`, `client.repositories.*`, `client.workspaces.*`, `client.changes.*`, `client.operations.*` (`subscribe` returns an `AsyncIterable` of frames), `client.trees.*`, `client.presence.*`, `client.symbols.*`, `client.queries.*`, `client.maintenance.*`, `client.stores.*`: one async method per RPC taking a partial request object (protobuf-es's `MessageInit`) and returning the response message. `autostart: true` runs `reef daemon start` from `PATH` with `child_process.execFile` (10 s) before connecting; the default is not to. Connection failures surface as `DaemonNotRunning` with `next = ["reef","daemon","start"]`. Stubbed services (R2.01) throw `ReefError` with `code = Code.Unimplemented` and the daemon's hint.
- **Errors.** `class ReefError extends Error { kind, chain, hint, next, code: Code, cause?: ConnectError }`, with `kind` one of the eight names, built in one function `fromConnectError` from the `ErrorDetail` found by `error.findDetails(ErrorDetailSchema)` (the envelope R2.01 ships), falling back to the code-to-kind table (`crates/reef-daemon/src/error.rs:300-310`) when no detail is present; `ReefError.is(e, "NotFound")` and per-kind subclasses as in Python. A `ConnectError` with `Code.Unavailable` and no HTTP response becomes `DaemonNotRunning`.
- **Workspace handle.** `client.workspace({ repo?, purpose?, owner?, change?, newOn?, leaseMs?, backend?, missingStores?, keep?, snapshotOnExit = true }): Promise<Workspace>`: calls `Create` (`repo` defaults to `process.cwd()`, owner to `<user>@<host>:<pid>`), then heartbeats on `setInterval` every `lease.heartbeatEvery` (a `Duration` message: `Number(seconds) * 1000 + nanos / 1e6` ms), the timer `unref()`ed so a forgotten handle does not keep the process alive (the lease then lapses and the daemon reclaims); a failed heartbeat retries with backoff (1 s doubling to 30 s), a lapse is logged once through the handle's `onWarning` callback (default `console.warn` off; the SDK never prints unless asked), a `Conflict` sets `lapsed` and stops the timer. `Workspace` has `id`, `path`, `repoId`, `changeId`, `lease`, `workspace`; `heartbeat()`, `snapshot()`, `release()`, `move()`, `inspect()`, `env()` (the four `REEF_*` variables), `run(argv, options)` (`execFile` in `path` with that environment, resolving to `{ code, stdout, stderr }`), and `[Symbol.asyncDispose]` = `release()` so `await using ws = await client.workspace(...)` releases at scope exit; `client.withWorkspace(opts, fn)` is the callback form that always releases, exceptions included, for code bases without `using`. R2.11 adds presence through a `presence` hook left as a no-op here.
- **Web consumers.** The package exports `reef-vcs/gen` (the generated schemas and service descriptors) and `createReefClient(transport)` which builds the same namespaced client over any Connect `Transport`, so R2.18 passes `createGrpcWebTransport({ baseUrl, interceptors: [bearer(token)] })` and gets `client.workspaces.list()` with the same types. `Client` (the Node class with socket resolution and autostart) lives in a Node-only entry; the browser entry imports nothing from `node:*`. The package's `exports` map separates `.` (Node) from `./web` and `./gen`.
- **Versioning and publishing.** `package.json`'s `version` equals `scripts/version.sh` (checked by `just sdk-version-check`, shared with R2.06). `release.yml` gains `publish-npm` after `release`: `pnpm install --frozen-lockfile`, `pnpm build`, `npm publish --provenance --access public` in `sdk/typescript` with `permissions: id-token: write` and `NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}` (an automation token the user creates; if npm trusted publishing is configured for the package instead, the secret is dropped and the step stays). Dry runs and PRs: build, `pnpm test`, `npm pack`, `npm publish --dry-run`, and a smoke install of the tarball into a scratch project that imports `reef-vcs` under Node 22 on both runner OSes. ADR 0038 gains its TypeScript section (Connect over Node's http2 with `createConnection`, committed codegen, provenance).

## Tests

1. `socket.test.ts`: the resolution table from R2.06's test 1, with `process.platform` and `process.env` stubbed.
2. `client.test.ts::status over the unix socket`: `await new Client().daemon.status()` returns the daemon's version. This is the test that proves the Connect route; its failure mode is named in the PR if the fallback is taken.
3. `client.test.ts::not running`: a dead socket path → `DaemonNotRunning` with `next`; `autostart: true` starts one when `reef` is on `PATH` (skipped otherwise).
4. `errors.test.ts`: `inspect` of an unknown workspace throws `NotFound` with `kind`, `chain`, `code === Code.NotFound`; the missing-store fixture throws `Unavailable` with `next.slice(0,3)` equal to `["reef","store","build"]`; recorded trailers decode without a daemon.
5. `workspace.test.ts::await using releases`: a block with `await using ws = await client.workspace({ repo, purpose: "t" })` creates a directory, a write is in `ws.snapshot()`, the lease stays `ACTIVE` across 5 s, and after the block the workspace is `released` and the path gone; `ws.run(["sh","-c","echo $REEF_WORKSPACE"])` prints the id.
6. `workspace.test.ts::withWorkspace releases on throw`; `keep leaves it leased`; `lapsed lease stops heartbeats and the next call throws Conflict` (as R2.06's 6 to 8).
7. `client.test.ts::every RPC has a method`: walks the generated service descriptors' `methods` and the client's namespaces.
8. `web.test.ts`: `createReefClient` over a `Transport` stub records the method called and the request shape; the `./web` entry imports no `node:` module (a test that bundles it with esbuild for the browser platform and asserts no `node:` externals).
9. Packaging: `npm pack` lists `dist/`, `dist/gen/`, `README.md`, `LICENSE`; the tarball installs into a scratch project and `import { Client } from "reef-vcs"` type-checks and runs test 2.

## Implementation notes

- Keep `baseUrl` a fixed dummy (`http://reef.sock`); the daemon's router does not check `:authority`. If tonic ever does, the fix is in one place.
- `heartbeatEvery` arrives as a protobuf-es `Duration` (`seconds: bigint`); convert once in `workspace.ts` and clamp below 1 s to 1 s as a guard.
- Deadlines: pass `timeoutMs` per call through Connect's `CallOptions`; streams get none.
- The handle must stop its timer on `release()` and on `Conflict`; test 6 checks the process exits promptly after the suite (vitest reports hanging handles).
- `exports` with separate `types` conditions for `.`, `./web`, `./gen`; a bundler test (test 8) guards the browser entry.
- Pin `@connectrpc/connect` and `@connectrpc/connect-node` to the same version (peer dependency is exact).

## Out of scope

- Presence (R2.11), the remote transport (R2.08 adds `new Client({ remote, token })`), the web UI itself (R2.18).
- A browser bundle on a CDN; consumers bundle `reef-vcs/web` themselves.
- Deno and Bun; they may work through Node compatibility and are not tested.
- Windows.

## Risks

- **The envelope** (shared with R2.06): without R2.01's `google.rpc.Status` envelope, every daemon error reaches this SDK as a decode failure inside connect-es, with no recoverable `kind`. The departure below is the fix; the fallback is the grpc-js transport, which hands trailers over raw.
- **`createConnection` through Connect** is verified by reading connect-es's source, not by running it; test 2 is the proof and the fallback is decided in advance.
- **Node 22 floor** excludes harnesses still on Node 20; they can use the CLI or grpc-js. Recorded in the README and ADR 0038.
- **Committed codegen drifts** from the proto when someone edits a proto without `pnpm gen`; the CI diff check catches it on the PR, not later.

## Proposed departure from the README

*Accepted 2026-10-25, all three: the README now says Node 22+, pnpm 12, and the `google.rpc.Status` envelope (R2.01 implements it).*

Two items. (1) **Node 22+, not 20+**: `@connectrpc/connect-node@2.2.0` requires `node >= 22`, and Node 20 is past maintenance. (2) **The error envelope**, as in R2.06: connect-es decodes `grpc-status-details-bin` as `google.rpc.Status` with no fallback, so R2.01 must wrap `ErrorDetail` in a `google.rpc.Status` `Any` detail (the standard rich-error model, available through `tonic-types` 0.14 or a vendored `google/rpc/status.proto`); the README's "no `tonic-types`, a few lines in each SDK" row cannot hold for TypeScript. Minor: pnpm's current major is 12, not 10; pin whatever `corepack`/`packageManager` resolves at implementation time and record it.
