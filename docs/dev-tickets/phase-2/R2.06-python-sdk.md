# R2.06 Python SDK

Phase 2 · Size S · Depends on: R2.01 (`crates/reef-api/proto/reef/daemon/v1/*.proto`, the error envelope, `ErrorDetail`), R1.28 (the release workflow the publish job joins) · Unblocks: R2.11 (presence from the SDKs' workspace handles), R2.17 (the Python arm of the token benchmark, if it is written in Python)

## Context

Agents are written in Python and TypeScript far more than in Rust (`docs/design.md`, "gRPC over a bespoke protocol"), and ADR 0004 promised SDKs generated from the schema. Until now the only clients are the Rust `Client` and the `reef` binary, so a Python harness that wants a workspace shells out to `reef ws run` and parses `-o json`. This ticket publishes `reef-vcs` on PyPI: the generated gRPC stubs for `reef.daemon.v1`, and a thin wrapper that does what `reef ws run` does in-process (resolve the socket, create, heartbeat, release) with Reef's error contract (`kind`, `hint`, `next`) as a Python exception.

The SDK is a client of the v1 API and nothing else: it reads no `config.toml`, opens no database, and never imports jj. R2.01 fixes the schema this ticket generates from; R2.11 adds presence reporting to the workspace handle this ticket creates.

### What was verified while writing this ticket

Reef at `d156d1e` (0.1.0); PyPI and docs fetched on 2026-10-25.

- **Socket resolution in the daemon** (`crates/reef-daemon/src/config.rs:14-24`, `:884-926`): `REEF_SOCKET` (or `--socket`) wins; else the file's `daemon.socket`, relative to the state directory; else, when the state directory is the platform default (no `REEF_STATE_DIR`), `$XDG_RUNTIME_DIR/reef/daemon.sock` on Linux if `XDG_RUNTIME_DIR` is set, otherwise `<state>/daemon.sock`; the state directory is `REEF_STATE_DIR`, else `$XDG_STATE_HOME/reef` (default `~/.local/state/reef`) on Linux and `~/Library/Application Support/reef` on macOS (ADR 0013). A socket path over 104 bytes is refused (`:64`, `:927-931`). The CLI connects through `Config::load` and `Client::connect` (`crates/reef-vcs/src/cli/mod.rs:431-456`) and starts the daemon when nothing answers unless `--no-autostart` (`cli/autostart.rs:46-103`: `reef-daemon` beside `reef`, else on `PATH`, else `reef daemon run`).
- **The Rust client** (`crates/reef-daemon/src/client/mod.rs:110-128`) connects with a dummy URI (`http://[::]:0`) and a connector that opens the Unix socket; the URI is ignored. One method per RPC; `ClientError::Rpc { kind, message, chain, status }` is decoded from `ErrorDetail` in the status details (`:70-83`, `crates/reef-daemon/src/error.rs:290-298`). R2.01 moves this to `reef_api::client`; the Python wrapper mirrors its method list.
- **The error envelope on the wire.** `status_from` (`error.rs:236-250`) puts `ErrorDetail`'s bytes into tonic's `details`, which tonic sends base64-encoded in the `grpc-status-details-bin` trailer (tonic 0.14.6 `src/status.rs:561-567`, `GRPC_STATUS_DETAILS` at `:622`). The gRPC convention is that this trailer holds a `google.rpc.Status`, and grpc-core's `-bin` metadata handling base64-decodes it for the caller; Python's `grpc` exposes the trailer through `RpcError.trailing_metadata()` (the `grpc.Call` interface: `code()`, `details()`, `trailing_metadata()`; grpc.github.io/grpc/python, fetched today). Python can decode raw bytes from that trailer whatever they are; connect-es cannot (see R2.07). **The envelope R2.01 chooses decides this ticket's decoder**; see "Proposed departure from the README".
- **`grpc.aio`** exists in grpcio 1.84.1 (`grpc.aio.insecure_channel`, checked by importing it under Python 3.12 with `uv run --with grpcio==1.84.1`). gRPC's naming doc (grpc/grpc `doc/naming.md`) lists `unix:path` and `unix:///absolute_path` as targets "most gRPC implementations support", Unix only; grpcio is C-core, which defines them.
- **Codegen.** `grpcio-tools` 1.84.1 bundles the well-known types: `grpc_tools/_proto/google/protobuf/` exists in the installed wheel (checked by `uv run --with grpcio-tools==1.84.1 python -c ...`), so `-I <that dir>` resolves `google/protobuf/timestamp.proto` and `duration.proto`, which `types.proto` imports. `python -m grpc_tools.protoc --python_out --grpc_python_out --pyi_out` generates `*_pb2.py`, `*_pb2_grpc.py`, `*.pyi`. Generated modules import each other by the proto path (`from reef.daemon.v1 import types_pb2`), so the proto package `reef.daemon.v1` must be a Python package `reef.daemon.v1`, which fits a distribution whose top-level module is `reef`.
- **PyPI**: `reef-vcs` is unregistered (`https://pypi.org/pypi/reef-vcs/json` is 404; `reef` is taken, 200). grpcio, grpcio-tools 1.84.1, protobuf 7.36.2 and hatchling 1.32.4 all require Python ≥ 3.10. PyPI trusted publishing (docs.pypi.org, "Using a publisher"): the job needs `permissions: id-token: write` at the job level, uses `pypa/gh-action-pypi-publish@release/v1` with no token, and a GitHub environment (`pypi`) is "strongly encouraged"; the publisher (owner, repository, workflow file name, environment) is configured on PyPI first, as a pending publisher before the project exists. `uv publish` also supports trusted publishing without credentials (docs.astral.sh/uv, "Building and publishing").
- **Hatch build hooks** (hatch.pypa.io, build hook reference): `initialize(version, build_data)` runs before each build and may append to `build_data["artifacts"]` or set `build_data["force_include"]`; a custom hook is the `custom` plugin configured under `[tool.hatch.build.hooks.custom]`, which loads `hatch_build.py` beside `pyproject.toml` by default (the default path is from hatch's custom-hook guide, not re-fetched; `path` names another file).
- **Test fixtures that exist**: `TestDaemon` is Rust-only (`crates/reef-daemon/src/testing.rs`); the spawned-binary harness (`crates/reef-daemon/tests/common/spawned.rs:66-84`) writes a `config.toml`, sets `REEF_STATE_DIR` to a short temp dir (`/tmp` on macOS because `$TMPDIR` makes socket paths too long, `tests/common/mod.rs:33-37`, `testing.rs:219-227`) and waits for the socket. ## Decisions

- **Layout.** `sdk/python/`: `pyproject.toml`, `README.md`, `hatch_build.py`, `proto/` (a copy of `crates/reef-api/proto`, see drift), `src/reef/` (`__init__.py`, `_socket.py`, `_errors.py`, `_client.py`, `_workspace.py`, `_owner.py`, `aio.py`, `py.typed`), `src/reef/daemon/v1/` (generated at build; git-ignored), `tests/`. Managed with `uv` (`uv.lock` committed); Python 3.10+; distribution `reef-vcs`, import `reef`.
- **Generated code is built, not committed.** `hatch_build.py` runs `grpc_tools.protoc -I proto -I <grpc_tools/_proto> --python_out=src --grpc_python_out=src --pyi_out=src proto/reef/daemon/v1/*.proto` in `initialize`, writes `__init__.py` into `src/reef/daemon/` and `src/reef/daemon/v1/`, and adds the directory to `build_data["artifacts"]`, so sdists and wheels carry it and a developer's `uv sync` runs the hook too. `[build-system] requires = ["hatchling", "grpcio-tools>=1.84"]`. Runtime dependencies: `grpcio>=1.84` and `protobuf` at the floor the generated `_pb2.py` files demand (they validate the runtime version against the generator's; the exact floor is read from the generated file on the first build and pinned in `pyproject.toml` with a comment).
- **Proto drift.** `just sdk-proto` copies `crates/reef-api/proto/reef/daemon/v1/*.proto` to `sdk/python/proto/reef/daemon/v1/` (and `sdk/typescript/proto/...`, R2.07) with a header line `# generated by just sdk-proto; do not edit`. CI's `sdk` job runs it and fails on `git diff --exit-code sdk/*/proto`. The copy, not a symlink, so sdists are self-contained.
- **Socket resolution** (`reef._socket.default_socket()`), the daemon's rules without the config file: `REEF_SOCKET` if set and non-empty; else the state directory is `REEF_STATE_DIR` if set, else the platform default (Linux: `$XDG_STATE_HOME/reef` or `~/.local/state/reef`; macOS: `~/Library/Application Support/reef`); on Linux with the default state directory and `XDG_RUNTIME_DIR` set, `$XDG_RUNTIME_DIR/reef/daemon.sock`; else `<state>/daemon.sock`. A `daemon.socket` key in `config.toml` is not read; the README says to set `REEF_SOCKET` in that case, and `reef daemon status -o json` prints the socket the daemon uses. Windows raises `ReefError(kind="Unavailable")` at construction (RX.05).
- **`reef.Client`.** `Client(socket: str | os.PathLike | None = None, *, autostart: bool = False, timeout: float = 60.0)`. Connects lazily on first use with `grpc.insecure_channel("unix:" + path)` (the absolute path form, `unix:///path`, is used when the path has characters `unix:` would misread; both are C-core targets). `autostart=False` is the default: an SDK must not start daemons behind a harness's back; a connection failure raises `DaemonNotRunning` (a `ReefError` with `kind="Unavailable"`, `hint="start the daemon"`, `next=["reef","daemon","start"]`). `autostart=True` runs `reef daemon start` from `PATH` (`subprocess.run`, 10 s), then connects; `reef` absent raises `DaemonNotRunning` with a hint naming the installer. Namespaces mirror the services: `client.daemon.status()`, `client.repositories.register(path, init_alongside_git=True)`, `.list()`, `.forget(repo)`, `client.workspaces.create(...)`, `.list(...)`, `.inspect(...)`, `.release(...)`, `.snapshot(...)`, `.heartbeat(...)`, `.move(...)`, `.status(...)`, `client.changes.*`, `client.operations.*` (`subscribe` returns an iterator of frames), `client.trees.*`, `client.presence.*`, `client.symbols.*`, `client.queries.*`, `client.maintenance.*` (`backup` iterates progress), `client.stores.*`. Every method takes keyword arguments named as the request's fields and returns the generated response message (no second object model: the `.pyi` stubs give completion and types). A service R2.01 stubbed answers `UNIMPLEMENTED`, which the SDK surfaces as `ReefError(kind="Internal", code=StatusCode.UNIMPLEMENTED)` with the daemon's `not implemented until R2.xx` hint; the SDK does not hide services behind feature flags.
- **Errors.** `reef.ReefError(Exception)` with `kind: str` (one of the eight `ErrorKind` names), `message: str`, `chain: list[str]`, `hint: str`, `next: list[str]`, `code: grpc.StatusCode`; `str(error)` is the message, and `error.advice()` returns `hint` and the `next` argv joined for display as the CLI prints them. Subclasses by kind (`NotFound`, `AlreadyExists`, `InvalidArgument`, `Conflict`, `Unavailable`, `PermissionDenied`, `IoError`, `Internal`), so `except reef.NotFound:` works; `DaemonNotRunning(Unavailable)` for connection failures. Every RPC in the wrapper is called inside one `_call()` helper that catches `grpc.RpcError`, reads `trailing_metadata()` for `grpc-status-details-bin`, decodes the envelope R2.01 fixes (see departure) into `ErrorDetail`, and raises; a status with no detail maps the gRPC code to a kind as `kind_from_status` does (`error.rs:300-310`). The decoder is one function, `reef._errors.from_rpc_error`, unit-tested against bytes recorded from a real daemon.
- **Workspace handle.** `client.workspace(*, repo=None, purpose="", owner=None, change=None, new_on=None, lease=None, backend=None, missing_stores="fail", keep=False, snapshot_on_exit=True) -> Workspace`, a context manager mirroring `reef ws run` (`crates/reef-vcs/src/cli/ws_run.rs`): `__enter__` calls `Create` (`repo` defaults to the current directory's repository, resolved by the daemon from `os.getcwd()` as the CLI does; the owner defaults to `<user>@<host>:<pid>` as `default_owner` does) and starts a daemon thread that calls `Heartbeat` every `lease.heartbeat_every` from the response, retrying a failed heartbeat with backoff (1 s doubling to 30 s), warning once through `logging` (`reef.lease`) when the lease lapses, and stopping on a `Conflict` (the lease is no longer ours; the handle's `lapsed` flag is set and the next call on it raises); `__exit__` stops the thread and calls `Release(snapshot_first=snapshot_on_exit)` unless `keep`, on exceptions too. Attributes: `id`, `path` (`pathlib.Path`), `repo_id`, `change_id`, `lease`, `workspace` (the message); methods `heartbeat()`, `snapshot(description="")`, `release()`, `move(change=|new_on=)`, `inspect()`, `env() -> dict[str,str]` (`REEF_WORKSPACE`, `REEF_WORKSPACE_PATH`, `REEF_REPO`, `REEF_SOCKET`, as `cli/env.rs:10-17`, for `subprocess.run(..., env={**os.environ, **ws.env()})`), and `run(argv, **popen_kwargs)` which runs a subprocess in the workspace with that environment and `cwd=path`. R2.11 adds presence (`Presence.Report` for the handle's lifetime) through a `_presence` hook this ticket leaves as a no-op.
- **`reef.aio`.** The same surface over `grpc.aio.insecure_channel`: `async with reef.aio.Client() as client`, `async with client.workspace(...) as ws`, heartbeats as an `asyncio.Task`, streaming RPCs as async iterators. One implementation of the request building and error decoding, shared through `reef._client` helpers; only the channel and the awaiting differ.
- **Versioning and publishing.** `pyproject.toml`'s `version` equals `scripts/version.sh`; `just sdk-version-check` asserts it (and R2.07's `package.json`), and `release.yml`'s `check-version` job runs it. `release.yml` gains `publish-python` after `release`: `uv build` in `sdk/python`, `pypa/gh-action-pypi-publish@release/v1` with `environment: pypi` and `permissions: id-token: write`, publishing `sdk/python/dist/*`. On dry runs and PRs (`publish == false`): build, `uv run --with twine twine check dist/*`, install the wheel into a fresh venv, and `python -c "import reef; reef.Client"` on both runner OSes. The PyPI pending publisher (owner `reef-vcs`, repository `reef`, workflow `release.yml`, environment `pypi`) is configured by the user before the first publish; the brief's acceptance criterion says so. ADR 0038 records the codegen-at-build decision, the import layout, trusted publishing, and R2.07's section.
- **Logging and threads.** The SDK uses `logging.getLogger("reef")` and never prints. The heartbeat thread is a daemon thread so a forgotten handle does not hang interpreter exit; the lease then lapses and the daemon reclaims, which is the designed outcome.

## Implementation notes

- Generate into `src/reef/daemon/v1/` and add that path to `.gitignore`; `__init__.py` files must be written by the hook (protoc does not), or the wheel imports fail silently as namespace packages on 3.10.
- grpc-core base64-decodes `-bin` metadata before handing it to Python; do not decode again. The value may arrive as `bytes` in a `grpc.aio` `Metadata` object and as a tuple entry in the sync API; `from_rpc_error` normalizes both.
- Deadlines: pass `timeout=` on every call (the client's `timeout`, default 60 s); `Backup`, `Stores.Build` and `Operations.Subscribe` take `timeout=None`.
- `Create`'s `repo` for the current directory: send `os.getcwd()` (absolute) and let the daemon resolve, exactly as the CLI's `RepoArg::Path` does; relative paths are refused by the daemon (ADR 0017), so `os.path.abspath` every path argument.
- Heartbeat cadence: `heartbeat_every` is a `google.protobuf.Duration`; use `ToTimedelta()`; the daemon already clamps it to a third of the lease.
- Keep the wrapper free of logic the daemon owns: no id prefix resolution, no revision parsing, no retries except heartbeats. If a request needs a repository and none is given, send the cwd; the daemon registers it under R1.25's rules only when the CLI asks, so the SDK passes `IfNotJj.INIT_ALONGSIDE_GIT` on an explicit `register()` only and documents that a `NotFound` with `next == ["reef","repo","register",...]` means "register first".
- The tests' daemon must find `git` on `PATH` for the fixture repository; skip with a message otherwise, as the Rust tests do.

## Out of scope

- Presence reporting from the handle (R2.11 fills the hook).
- A remote transport (`REEF_REMOTE`, TLS, tokens: R2.08 adds `Client(remote=..., token=...)` to both SDKs in its own PR, after this one lands).
- Reading `config.toml`; a `reef.Config` type; starting daemons by default.
- Windows.
- A higher-level agent framework; the wrapper stops at the API's shape.

## Risks

- **The error envelope.** If R2.01 keeps raw `ErrorDetail` bytes in `grpc-status-details-bin`, Python decodes them fine but the TypeScript SDK cannot (R2.07); if R2.01 adopts the standard `google.rpc.Status` envelope, this ticket's decoder reads `Status.details[0]` (an `Any` of `ErrorDetail`). Write the decoder against whichever R2.01 ships, in one function, with recorded fixtures, so a later envelope change is a one-file fix in both SDKs.
- **Generated code and the protobuf runtime floor.** grpcio-tools pins a minimum protobuf runtime in generated files; a user with an older `protobuf` sees an import error. The floor is pinned in `pyproject.toml` from the generated file and the README says so.
- **Hatch custom hook default path.** If `hatch_build.py` is not the default, `path = "hatch_build.py"` under `[tool.hatch.build.hooks.custom]` is the fix; one line.
- **Daemon threads and interpreter exit.** A heartbeat thread mid-RPC at exit can print a traceback from grpc's own shutdown; `atexit` closes the channel first. Test 5's teardown watches for stray output.

## Proposed departure from the README

*Accepted 2026-10-25: the README's Errors row now fixes the `google.rpc.Status` envelope with `ErrorDetail` as an `Any` detail through `tonic-types` 0.14, and R2.01 implements it. The decoder below reads `Status.details`.*

The README's "Errors" row says the SDKs "decode `ErrorDetail` from the status details in a few lines" and that `tonic-types` is not adopted. For Python that holds whatever the bytes are. For TypeScript it does not: connect-es decodes `grpc-status-details-bin` as `google.rpc.Status` with no fallback (R2.07's verification), so raw `ErrorDetail` bytes break every error on that client. R2.01 should put `ErrorDetail` inside a `google.rpc.Status` as an `Any` detail (`type_url = "type.googleapis.com/reef.daemon.v1.ErrorDetail"`), the standard rich-error model, which `tonic-types` 0.14's `StatusExt` or a vendored `google/rpc/status.proto` compiled by protox gives in a few lines; ADR 0017 already named this as the thing to revisit in R2.01. This brief's decoder then reads `Status.details`, and the Python SDK also interoperates with `grpcio-status`.
