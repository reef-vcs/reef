# R2.06 Python SDK

Phase 2 · Size L (the row says S; see "Size") · Depends on: R2.01 (`reef.api.v1`, the error envelope, ADR 0029), R2.05 (`reef-client`, whose surface and socket discovery this mirrors), R2.08 (the remote listener and its client rules, ADR 0049), R2.11 (the presence reporting contract and `reef_client::presence::Reporter`), R2.25 (`release.yml`'s publish-by-OIDC pattern) · Unblocks: R2.07 (ADR 0054's shared decisions and the shared fixtures under `sdk/fixtures/`)

## Context

Every client of the daemon today is Rust (`reef`, `reef mcp`) or the web UI's generated TypeScript. A Python program that wants a workspace has two options: shell out to `reef` and parse its JSON, or generate its own stubs from `crates/reef-api/proto` and work out by itself the socket path, the `:authority` the daemon accepts, how errors are packed, how to pin a remote daemon's key and how presence is reported. ADR 0004 promised "Python and TypeScript SDKs generated from the same schemas", and ADR 0029 shaped the schema for them (decision 14 names `grpcio-status` as the stock decoder of the error detail; R2.01 renamed `GetDiffRequest.from` because `from` is a Python keyword).

The row asks for three things: code generated from the schema, a package on PyPI named `reef-vcs`, and a thin idiomatic wrapper. Earlier briefs left this ticket five promises:

- **R2.05** (line 364): mirror `reef-client`'s surface: one method per RPC, page followers, the agent metadata, and the probe for a mismatched daemon.
- **R2.08** (line 768): document the remote connection (`https://` URL, SPKI pin or CA roots, `authorization: Bearer`, the reasons), and read `REEF_REMOTE`, `REEF_REMOTE_TOKEN` and `REEF_REMOTE_FINGERPRINT` as the CLI does.
- **R2.11** (line 260): a workspace helper that holds a workspace for a block of code reports one `ACTIVITY` entry with the `Refresh` cadence (10 s, TTL 30 s) and clears it when the block exits; the agent is rule 7; `Reporter`'s unit tests 1 to 6 are the behaviors to port.
- **R2.12, R2.14 to R2.16** (lines 437, 389, 466, 621): expose their fields and RPCs through the client. Generation does this by construction.
- **R2.24** (line 351): generate from the protos or the descriptor set.

The user's standing direction applies: the SDK is agent-agnostic. No harness is named in its API, docstrings, README or docs page; an agent is a name the caller passes (`agent=`, or `REEF_AGENT`), as for the CLI.

### What was verified while writing this ticket

**In the repository**, at the 0.3.0 release (`776e3c8`; API revision 14, ADR 0053 the last merged ADR, so this ticket's is 0054, renumbered if another PR takes it first). Paths are under `crates/` unless they start with `docs/`, `scripts/`, `sdk/` or `.github/`.

- **The schema.** `reef-api/proto/reef/api/v1/` holds 16 files (`reef-api/build.rs`'s `V1` list), 14 services and 43 RPCs. Ten are paged (`page_token` in, `next_page_token` out): `ListChanges`, `GetDiff`, `ListFiles`, `QueryChanges`, `ListOperations`, `ListRemoteTokens`, `ListRepositories`, `ListStores`, `ListSymbols`, `ListWorkspaces`. Two of those responses have two repeated fields (`GetDiffResponse`: `files`, `from_commit_ids`; `QueryChangesResponse`: `changes`, `groups`); the others have one. Four RPCs stream from the server: `Backup`, `BuildStore`, `SubscribeOperations`, `SubscribePresence`. No request field is a Python keyword. One request field, `BuildStoreRequest.timeout`, has the name a per-call option would naturally take. Imports outside the package are `google/protobuf/{descriptor,duration,timestamp}.proto` only.
- **Versions.** `reef_api::API_REVISION` (`reef-api/src/lib.rs:49`, 14) is the schema's revision, reported by `GetDaemonStatus.api_revision`; `[workspace.package] version` in `Cargo.toml` (0.3.0) is the release version, read by `scripts/version.sh`. `buf` lints with `STANDARD` and `COMMENTS` and checks `FILE` breaking rules (`buf.yaml`); codegen never uses `buf` (ADR 0029 decision 18).
- **Socket discovery** (`reef-client/src/paths.rs`): explicit argument, else `REEF_SOCKET`, else `config.toml`'s `[daemon] socket` (joined to the state directory), else on Linux `$XDG_RUNTIME_DIR/reef/daemon.sock` when the state directory is the default one, else `<state>/daemon.sock`. The state directory is `REEF_STATE_DIR`, else `~/Library/Application Support/reef` (macOS) or `$XDG_STATE_HOME/reef`, default `~/.local/state/reef`. The config file is `REEF_CONFIG` (which must exist), else `<state>/config.toml` (which may not). Empty variables count as unset; relative paths are made absolute. A socket path over 103 bytes is an error. The client reads only `daemon.socket`, `daemon.pid_file` and `repo.auto_register` and ignores the rest.
- **The Rust client** (`reef-client/src/lib.rs`): `Client::connect` dials the socket eagerly; `connect_remote` verifies TLS before anything is sent, then adds `authorization: Bearer <token>` beside `reef-agent`, with HTTP/2 keepalive every 30 s; `with_agent` trims and refuses anything but visible ASCII up to 256 bytes (`check_agent`). `ClientError` maps a status to a kind (`kind_from_status`: the detail's kind, else the gRPC code's), and `call` turns a bare `UNIMPLEMENTED`, `UNKNOWN_METHOD`, or `NOT_IMPLEMENTED` from a daemon of another version into `Incompatible` after probing `GetDaemonStatus`, then 0.1's `reef.daemon.v0.Daemon/Status`. A request over 4 MiB is refused before sending (`TooLarge`). The CLI owns its own advice table; API callers keep the daemon's `hint` and `next` (R2.05).
- **Remote** (`reef-client/src/remote.rs`, R2.08): `REEF_REMOTE` is a profile name or an `https://` URL (then `REEF_REMOTE_TOKEN` is required); `REEF_REMOTE_TOKEN` and `REEF_REMOTE_FINGERPRINT` override a profile's. Profiles are `<state>/remotes.toml`, one table per name with `url`, `fingerprint` and `token`. `RemoteUrl::parse` takes `https://<host>[:<port>][/]`, port 443 by default, IPv6 bracketed. A fingerprint is `sha256:` and the lowercase hex SHA-256 of the leaf's SubjectPublicKeyInfo. With a pin, name, chain and validity are not checked; without one, the OS's roots and the URL's host decide. The daemon's generated certificate is a self-signed ECDSA P-256 leaf with SANs from `[remote] names` plus the bound IP, valid 397 days and renewed with the same key. The listener answers a host it does not serve with HTTP 421 (`RemoteMisdirected`). ADMIN RPCs are never served remotely. A refused token is `PERMISSION_DENIED` with a reason, not a new kind.
- **Presence** (`reef-client/src/presence.rs`): `Reporter` with `Cadence::Refresh { every: 10 s, ttl: 30 s }` and `Burst { ttl: 60 s }`, `set`, `clear` (bounded by 2 s), `is_live`, and the agent rule `agent(given, owner, fallback)`. Its tests: `refresh_reports_replaces_and_clears`, `rereports_after_not_found`, `coalesces_within_a_second`, `failures_do_not_stop_it`, `failures_with_an_entry_held`, `burst_drops_a_refused_report` (R2.11's 1 to 6), then `burst_does_not_refresh`, `clear_is_bounded`, `agent_rule`.
- **Leases** (`reef-vcs/src/cli/heartbeat.rs`): `ws run` renews every `Lease.heartbeat_every` (the daemon's `lease.heartbeat`, at most a third of the length), with a 5 s deadline per renewal and backoff of 1, 2, 4, 8, 16 then 30 s while the daemon is unreachable, and stops when the daemon says the lease ended. `ws run`'s owner is `<user>@<host>:<pid>` (`default_owner()` plus the pid).
- **Release** (`.github/workflows/release.yml`): `check-version` sets `publish` (true only for a `v<version>` tag or a non-dry dispatch); `release` attests and creates the GitHub release; `homebrew` and `mcp-registry` follow it and warn rather than fail, with the manual command in the warning. `mcp-registry` is the existing OIDC job (`permissions: id-token: write`). Pull requests touching `packaging/**`, `scripts/**` and a few other paths run the dry run.
- **CI** (`.github/workflows/ci.yml`): `check` (Ubuntu; macOS on main and with the `macos` label), `web` and `web-e2e` (Node, not in `just ci`), `api` (buf), and `ci-ok` requiring them. The web UI's TypeScript is generated at every build and never committed (`web/buf.gen.yaml`, `.gitignore`, ADR 0047). `.github/dependabot.yml` covers `github-actions` and `cargo`.

**Run while writing this ticket**, in a scratch venv (CPython 3.11, the pins above) against the installed 0.3.0 daemon (API revision 14) and a scratch 0.3.0 daemon with its remote listener on `127.0.0.1:17470`, `names = ["reefvm.test"]`:

1. `python -m grpc_tools.protoc -I crates/reef-api/proto --python_out --grpc_python_out --mypy_out --mypy_grpc_out` over the 16 v1 files writes `reef/api/v1/<file>_pb2.py`, `_pb2.pyi`, `_pb2_grpc.py` and `_pb2_grpc.pyi`, importing each other absolutely (`from reef.api.v1 import options_pb2`) and the well-known types from `google.protobuf`. The generated code checks its runtime: `ValidateProtobufRuntimeVersion(PUBLIC, 7, 35, 1)` in each `_pb2.py` and `GRPC_GENERATED_VERSION = '1.85.1'` in each `_pb2_grpc.py`. No `protoc` or `buf` install was needed.
2. **grpcio's default `:authority` breaks every call over the socket.** A `unix:` target connects (with the path as is, as `unix:///` and percent-encoded, spaces included), but every call fails `INTERNAL: Stream removed (RST_STREAM (Received RST_STREAM with error code 1))`. grpc's trace shows why: it sends the percent-encoded socket path as `:authority` (`Users%2Farsood%2FLibrary%2FApplication%20Support%2Freef%2Fdaemon.sock`), which the daemon's HTTP/2 server refuses as a protocol error. With the channel option `grpc.default_authority = "localhost"`, `GetDaemonStatus` answers (`0.3.0`, revision 14). Every SDK channel to a socket sets it.
3. `grpc_status.rpc_status.from_call(error)` and `Any.Unpack` into `reef.api.v1.ErrorDetail` give the daemon's detail: `GetWorkspace` of an unknown id is `NOT_FOUND`, kind `ERROR_KIND_NOT_FOUND`, reason `WORKSPACE_NOT_FOUND`, `next` `["reef", "ws", "list", "--all"]`, hint "List the workspaces to find its id.", metadata `{"workspace": …}`. `grpc.aio`'s `AioRpcError.trailing_metadata()` carries `grpc-status-details-bin` too.
4. `grpc.aio` iterates `SubscribeOperations` (live frames with no operations are keepalives) and cancels cleanly.
5. **Pinning works through grpcio.** A Python `ssl` handshake with verification off and ALPN `h2` reads the leaf; a 30-line DER walk to the SubjectPublicKeyInfo hashes to exactly `GetDaemonStatus.remote.certificate.fingerprint`. Then `grpc.ssl_channel_credentials(root_certificates=<that leaf as PEM>)` composed with `grpc.access_token_call_credentials(token)` serves `GetDaemonStatus` with `grpc.ssl_target_name_override` set to either SAN (`reefvm.test` or `127.0.0.1`), with or without `grpc.default_authority = "127.0.0.1:17470"`: the generated self-signed, non-CA leaf is accepted as grpc's only root. A wrong token is `PERMISSION_DENIED`, reason `REMOTE_TOKEN_INVALID`, with the daemon's hint.

## Decisions

### Size

L. The row's S assumed a generator run and a publish step. The work found here:

1. A build that generates the gRPC code and the wrapper's methods from the protos, with the version and API revision from the repository, testable as `uv build` builds it (sdist, then the wheel from the sdist).
2. A wrapper generator: 43 typed methods on a sync and an asyncio client, page iterators for 10 RPCs, stream handles for 4, docstrings from the schema's comments.
3. Transport: socket discovery as `paths.rs` settles it, the `:authority` fix, and R2.08's remote connection with key pinning done outside grpc's TLS (DER parsing, the name override, re-pinning after a renewal).
4. Errors as exceptions by kind, with the daemon's `hint`, `next` and `metadata`, the incompatible-daemon probe, and client-side errors with their own advice.
5. A workspace block that heartbeats its lease and reports presence under R2.11's contract, in a thread and in a task, from one sans-I/O core with the reporter's tests ported.
6. Unit tests, integration tests against `reef-daemon` built in CI (local and remote), a CI job, a release job that builds and smoke-tests the wheel on every dry run, and PyPI trusted publishing on tags.
7. ADR 0054 (decisions R2.07 shares), a docs page, cross-language fixtures checked by a Rust test as well.

No API change, no daemon change, no new crate. The user chose L over an M without the asyncio client and the workspace block (2026-11-02).

### Layout and names

- **`sdk/python/`** is the project root: `pyproject.toml`, `hatch_build.py`, `uv.lock`, `README.md` (the PyPI description), `codegen/`, `src/reef/`, `tests/`. `sdk/fixtures/` holds the cross-language fixtures R2.07 reads too.
- **Distribution `reef-vcs`, import package `reef`.** The generated modules must be importable as `reef.api.v1` (the proto package), because protoc's Python output imports by the proto path and has no prefix option; rewriting its imports would be a fragile post-processing step. The wrapper lives in the same top-level package: `import reef; client = reef.connect()`. The unrelated `reef` sdist on PyPI would collide only if both were installed; the user accepted that (2026-11-02).
- **Messages** are re-exported by name from `reef.api.v1` (a generated `__init__.py`): `from reef.api.v1 import CreateWorkspaceRequest, Backend`. Names are unique in the package, which buf's lint already requires.

### Codegen: grpcio-tools at build time, not committed

- **Generator**: `grpcio-tools` (its bundled `protoc` and the gRPC Python plugin) for `_pb2.py` and `_pb2_grpc.py`, and `mypy-protobuf` for the `.pyi` stubs of both (`--mypy_out`, `--mypy_grpc_out`), so messages, enums, sync stubs and `grpc.aio` stubs are typed. Not betterproto: its v2 has been in beta for years and is built on grpclib, which has no story for R2.08's TLS pinning, and ADR 0029 decision 14 already settled on `grpcio-status` for errors. Not `buf generate`: building must not need `buf` (ADR 0029 decision 18).
- **Input**: the `.proto` files in `crates/reef-api/proto/reef/api/v1/`, the source of truth, so neither `cargo` nor `reef schema --descriptor-set` (R2.24) is needed to build the SDK. The file list is every `*.proto` in that directory (the same 16 files as `reef-api/build.rs`'s `V1` array), so a new file needs no SDK edit and no Rust source is parsed for it; the hook fails if it finds none.
- **Not committed**, as R2.18 decided for the web UI's TypeScript (ADR 0047): `_pb2.py` holds serialized descriptors that review cannot read, and generated code that cannot drift needs no freshness check. `sdk/python/.gitignore` lists `src/reef/api/`, `src/reef/_build.py`, `src/reef/_methods.py`, `src/reef/aio/_methods.py` and `LICENSE`.
- **`hatch_build.py`** holds a hatchling build hook and a metadata hook. In a checkout (where `../../crates/reef-api/proto` exists) the build hook runs `codegen/generate.py`, which:
  1. runs `grpc_tools.protoc` with `-I ../../crates/reef-api/proto` and grpcio-tools' own include directory (for `google/protobuf/*.proto`), writing into `src/reef/api/v1/`, plus `--descriptor_set_out` with `--include_source_info` to a temporary file;
  2. writes `src/reef/api/__init__.py` (empty) and `src/reef/api/v1/__init__.py` (the re-exports);
  3. runs `codegen/clientgen.py` over the descriptor set, writing `src/reef/_methods.py` and `src/reef/aio/_methods.py` (below);
  4. writes `src/reef/_build.py`: `VERSION` (the workspace version, normalized to PEP 440 with `packaging.version.Version`, so `0.4.0-rc.1` becomes `0.4.0rc1`), `API_REVISION` (read from `reef-api/src/lib.rs`'s `pub const API_REVISION: u32 = N;`), and `COMMIT` (`git rev-parse --short HEAD` or `jj log -r @ -T commit_id.short()`, empty when neither works);
  5. copies `../../LICENSE` to `sdk/python/LICENSE`.

  Outside a checkout (building the wheel from the sdist) the hook generates nothing and fails with a clear message if `_build.py` is missing. The sdist carries the generated files through hatch's `artifacts` setting (it includes VCS-ignored files). The metadata hook sets `version` from `Cargo.toml` in a checkout and from `_build.py` otherwise.
- **Pins**: `[build-system] requires = ["hatchling==1.33.0", "grpcio-tools==1.85.1", "mypy-protobuf==5.1.0"]`, exact, so a build is reproducible. Runtime dependencies follow the generated code's own checks: `grpcio>=1.85.1,<2`, `grpcio-status>=1.85.1,<2`, `protobuf>=7.35.1,<8`. Nothing else at runtime (`tomllib` is in the standard library from 3.11). Bumping grpcio-tools raises the floors in the same PR; `test_floors_match_the_generator` (below) checks they agree. Dependabot gains a `uv` entry for `/sdk/python`.
- **Python floor 3.11.** grpcio supports 3.10, but 3.10 is past its end of life (2026-10-01); 3.11 brings `tomllib` (for `config.toml` and `remotes.toml`), `asyncio.TaskGroup` and `asyncio.timeout`. CI tests 3.11 and 3.15, the floor and the newest. The wheel is pure Python (`py3-none-any`); grpcio supplies the platform wheels.
- **Staying in sync.** Nothing generated is committed, and the CI job builds from the same commit's protos, so the SDK always matches its commit's schema. `test_api_revision_matches_the_daemon` checks `reef.API_REVISION` against a daemon built from the same commit (catching a broken regular expression), and `codegen` tests check that every RPC in the descriptor set has a method on both clients. ADR 0029's API review checklist gains item 12: "`just python-check` passes: the SDK generates the new RPC's methods; a new paged RPC whose response has more than one repeated field names its items in `codegen/clientgen.py`'s `PAGE_ITEMS`."

### The wrapper's methods, generated

`codegen/clientgen.py` reads the descriptor set (with comments) and writes one mixin per client, so the sync and asyncio surfaces cannot differ:

- **One method per RPC**, the RPC's name in snake case on the client itself (`client.create_workspace`, `client.get_status`, `client.subscribe_operations`), as `reef_client::Client` has. Services are not separate objects: RPC names are unique across the package, and an agent writing code finds every call on one object.
- **Signature**: `def create_workspace(self, _request: CreateWorkspaceRequest | None = None, /, *, repo: str | None = None, change: str | None = None, …) -> CreateWorkspaceResponse`. Every request field is a keyword-only parameter defaulting to `None`, typed from the descriptor (scalars as `str`, `int`, `bool`, `bytes`, `float`; enums as the enum's `ValueType` or its name as `str`; messages as their class; `repeated` as `Iterable[...]`; `map` as `Mapping[...]`; `Timestamp` as `datetime | Timestamp`; `Duration` as `timedelta | Duration`). Only fields given are set, so a `oneof` works as protobuf's constructor does. Passing `_request` and a field is a `TypeError`. The positional parameter is `_request` because buf's lint forbids a field name with a leading underscore, so no field can clash with it.
- **Docstrings** are the RPC's leading comment, then each field's, from the descriptor's source info. R2.01 wrote them for an SDK reader.
- **Call options** are not parameters (`BuildStoreRequest.timeout` would clash, and any future field could): `reef.connect(timeout=…)` sets a default deadline for unary calls (none by default, as gRPC's), and `client.with_options(timeout=…, agent=…)` returns a client sharing the channel with other options, as Python HTTP SDKs do. Streams take no deadline.
- **Pages**: every paged RPC gets `<method>_pages(...)`, which yields each response, following `next_page_token` lazily with the same request otherwise. RPCs whose items are known get `<method>_all(...)`, which yields the items: the response's single repeated field, or `PAGE_ITEMS`' entry (`GetDiff`: `files`). `QueryChanges` gets `_pages` only, since its items are `changes` or `groups` depending on the request. The generator fails on a paged RPC with several repeated fields and no `PAGE_ITEMS` entry. Async: `async for`.
- **Streams**: a server-streaming method returns a `Stream[T]`: iterable (async iterable on `AsyncClient`), a context manager that cancels on exit, `cancel()`, and errors mapped as for unary calls, mid-stream included. No automatic resume: `SubscribeOperations`' `cursor` resumes a stream and the docs page shows the loop (see "Out of scope").
- **ADMIN RPCs** are generated like the rest (registration, maintenance, store builds, remote tokens, web sessions). The remote listener refuses them; the method's docstring says "ADMIN: local socket only" from the `(reef.api.v1.access)` option.

### Hand-written surface

```python
import reef

client = reef.connect()                       # socket discovery, as the CLI
client = reef.connect(socket="/path/daemon.sock", agent="planner-3")
client = reef.connect(remote="vm")            # a profile in <state>/remotes.toml
client = reef.connect(remote="https://vm:7470", token=..., fingerprint="sha256:…")

with reef.connect() as client:
    status = client.get_status(workspace=ws_id)
    for op in client.list_operations_all(repo=repo_id, page_size=200):
        ...
    with client.workspace(repo=repo_id, new_on="trunk()", purpose="fix the parser") as ws:
        (ws.path / "src/parser.py").write_text(...)
        ws.snapshot()
        ws.activity("running the tests")

async with reef.aio.connect() as client:      # the same surface, awaited
    async with client.subscribe_operations(repos=[repo_id]) as stream:
        async for frame in stream: ...
```

- **`reef.connect(socket=None, *, remote=None, token=None, fingerprint=None, state_dir=None, config=None, agent=None, timeout=None, connect_timeout=5.0) -> Client`**, and `reef.aio.connect(...)` returning `AsyncClient` (a coroutine). `Client` and `AsyncClient` are context managers with `close()`. `Client` is thread-safe; `AsyncClient` belongs to the loop it was created on.
- **Properties**: `client.target` (the socket path, or the remote's origin), `client.agent`, and module constants `reef.__version__`, `reef.API_REVISION`, `reef.COMMIT`.
- **`client.workspace(...)`** and **`client.attach(workspace, *, release=False)`**, below.
- **`reef.presence.Reporter`** and `reef.aio.presence.Reporter`, the contract's reporter for callers that report finer activity (an `EDITING` entry for paths, `PROGRESS`), as `reef presence report` does from a shell.
- **`reef.errors`**, below. Everything above is exported from `reef` (and `reef.aio`), typed, with `py.typed`.

### Transport: the socket

- **Discovery** ports `ClientConfig::load` exactly: arguments (`socket`, `state_dir`, `config`) over `REEF_SOCKET`, `REEF_STATE_DIR`, `REEF_CONFIG`, over `config.toml`'s `[daemon] socket`, over the platform default, with the rules listed above (empty is unset, relative made absolute, a named config must exist, an implicit one may not, a `[daemon] socket` relative to the state directory, the `$XDG_RUNTIME_DIR` socket only for the default state directory, 103 bytes at most). Only `daemon.socket` is read from the file; a file that is not TOML, or whose `daemon.socket` is not a string, is a `ConfigError`, as the CLI refuses it.
- **Shared fixture**: `sdk/fixtures/socket-paths.json`, a list of cases (`platform`, `env`, `config` text or absent, `args`, `home`, expected `socket` or `error`), read by the Python test `test_socket_paths_follow_the_shared_table` and by a new Rust unit test in `reef-client/src/paths.rs`, `paths_follow_the_shared_table` (through `ClientConfig::load_with` with the case's environment and defaults), so the two implementations cannot drift. R2.07 reads the same file.
- **The channel**: `grpc.insecure_channel("unix:" + path, options=[("grpc.default_authority", "localhost"), ("grpc.max_send_message_length", 4 MiB), ("grpc.max_receive_message_length", 4 MiB)])`. `localhost` is required, as verified above. The 4 MiB limits match tonic's defaults on both sides: a request over 4 MiB fails locally (`RESOURCE_EXHAUSTED`), which the SDK maps to `InvalidArgumentError` with `TooLarge`'s hint ("Edit large files in a workspace, or split the edits across requests.").
- **Connect is eager**, as `Client::connect` is: `connect()` waits up to `connect_timeout` for the channel to be ready. A missing socket, a refused connection, or no answer is `DaemonNotRunningError` (kind `unavailable`), with hint "Start the daemon: `reef daemon start`, or run any `reef` command, which starts it." and `next` `["reef", "daemon", "start"]`.
- **No autostart.** The SDK never starts a daemon. Starting one means finding `reef-daemon`, which the wheel does not ship, and leaving a detached process behind a library call; a script that wants one runs `reef daemon start` first. The CLI's restart of an idle daemon of another version is the CLI's too: the SDK reports the mismatch and does nothing.

### Transport: a remote daemon

- **Choosing a remote**, as the CLI's `remote::target` does: the `remote` argument, else `REEF_REMOTE`. An `https://` URL needs a token (`token`, else `REEF_REMOTE_TOKEN`), with the fingerprint from `fingerprint`, else `REEF_REMOTE_FINGERPRINT`. Any other value is a profile name in `<state>/remotes.toml` (the state directory as discovered above), whose token and fingerprint the arguments or variables override. `socket` and `remote` together are a `TypeError`. With neither, the socket is used; a set `REEF_REMOTE` makes `reef.connect()` remote, as it makes the CLI remote. URLs parse as `RemoteUrl::parse` does; the cases go in `sdk/fixtures/remote-urls.json`, read by `test_remote_urls_follow_the_shared_table` and by a Rust test in `reef-client/src/remote.rs`, `urls_follow_the_shared_table`.
- **Pinned** (a fingerprint is given), in `reef/_tls.py`:
  1. Open TCP to the URL's host and port and handshake with Python's `ssl` (`CERT_NONE`, ALPN `h2`, SNI the URL's host when it is a name), within `connect_timeout`, and read the leaf (`getpeercert(binary_form=True)`). Nothing is sent but the handshake.
  2. Hash the leaf's SubjectPublicKeyInfo, found by a minimal DER walk (certificate, TBS, skip the optional version, serial, signature algorithm, issuer, validity and subject). A mismatch is `RemoteTlsError` with `presented` and `expected` and `PinMismatch`'s hint from `remote_tls_advice`. The handshake's signatures are verified again by grpc below.
  3. Build `grpc.ssl_channel_credentials(root_certificates=<the leaf as PEM>)`, composed with `grpc.access_token_call_credentials(token)` (which sends `authorization: Bearer <token>`), with options `grpc.ssl_target_name_override` set to the URL's host if the leaf's SANs contain it, else the leaf's first SAN (read by the same DER walk: `dNSName` and `iPAddress`); `grpc.default_authority` set to the URL's authority (`host:port`, IPv6 bracketed), which the listener's Host check reads; `grpc.keepalive_time_ms` 30,000 and `grpc.keepalive_permit_without_calls` 1, as the Rust client keeps idle streams alive through NATs.

  grpc now trusts exactly the certificate whose key was pinned, so the token reaches only a server holding that key (S-35 holds). Unlike the Rust verifier, grpc also checks the leaf's validity dates. The daemon renews its generated certificate 30 days before expiry, so that is not a practical difference, and the docs page says so.
- **Re-pinning after a renewal.** A long-lived channel made from yesterday's leaf fails to reconnect after the daemon renews its certificate (same key, new certificate). When a call fails `UNAVAILABLE` with no Reef detail on a pinned channel, the client reads the leaf again (step 1). If the key still matches the pin and the certificate differs, it rebuilds the channel. It retries the call once only when the method's `(reef.api.v1.access)` is `ACCESS_READ`: an `UNAVAILABLE` can also come from a connection reset mid-call (a daemon restarting with its renewed certificate), after which a write may have landed, so a write's `UnavailableError` is raised and the next call uses the new channel. `test_remote_repins_after_renewal` covers it by restarting the daemon with a new certificate for the same key through `[remote] tls_cert` and `tls_key`.
- **CA-verified** (no fingerprint): `grpc.ssl_channel_credentials()` with grpcio's bundled roots, which are Mozilla's, not the operating system's as in the Rust client, and the URL's host as the name. A private CA is passed as `reef.connect(..., root_certificates=pem_bytes)` or through grpc's own `GRPC_DEFAULT_SSL_ROOTS_FILE_PATH`. The docs page states the difference. `test_remote_ca_verified` covers a supplied certificate from a test CA.
- **Errors**: nothing answering is `RemoteConnectError` (kind `unavailable`, `RemoteConnect`'s hint). A certificate that does not validate with roots is `RemoteTlsError` with `Untrusted`'s hint, including the presented fingerprint (read by step 1's handshake after the failure). HTTP 421 (grpc reports `UNKNOWN` with "HTTP status code 421", as tonic does) is `RemoteMisdirectedError` with its hint. The daemon's refusals (`REMOTE_TOKEN_INVALID`, the write rules, ADMIN) are ordinary `PermissionDeniedError`s with the daemon's detail.

### Errors

`reef.errors` (re-exported from `reef`):

- **`ReefError(Exception)`**: `kind` (an `ErrorKind` `str` enum whose values are the CLI's kind text: `not_found`, `already_exists`, `invalid_argument`, `conflict`, `unavailable`, `permission_denied`, `io`, `internal`, `unsupported`), `reason` (empty when none), `message` (the chain joined with `: `), `chain`, `hint`, `next` (a `list[str]` argv starting `reef`, empty when none), `metadata` (`dict[str, str]`), `code` (`grpc.StatusCode` or `None` for a client-side error), `method` (the RPC's full name, or `None`). `str(error)` is the message, followed by the hint on its own line when there is one. Python callers get the API's words: the CLI's advice table stays the CLI's (R2.05).
- **One subclass per kind**: `NotFoundError`, `AlreadyExistsError`, `InvalidArgumentError`, `ConflictError`, `UnavailableError`, `PermissionDeniedError`, `IoError`, `InternalError`, `UnsupportedError`. A status with a Reef detail takes the detail's kind; one without takes the code's (`kind_of_code`'s table, ported). An `ERROR_KIND_UNSPECIFIED` reads as `internal`.
- **Client-side subclasses**: `DaemonNotRunningError(UnavailableError)`; `RemoteConnectError(UnavailableError)`; `RemoteTlsError(PermissionDeniedError)` with `failure` (`pin_mismatch`, `untrusted`, `handshake`), `presented` and `expected`; `RemoteMisdirectedError(NotFoundError)`; `ConfigError(InvalidArgumentError)` for discovery and profile errors, with `PathsError`'s and `ProfileError`'s messages; `IncompatibleError(UnsupportedError)` with `daemon_version`, `daemon_api` (`v0` or `v1`), `active_workspaces`, reason `API_VERSION_MISMATCH`, hint "The daemon is reef X (API vN); this SDK is reef Y. Restart the daemon with the matching reef (`reef daemon stop`, then any reef command), or install reef-vcs==X." and `next` `["reef", "daemon", "stop"]`.
- **The incompatible-daemon probe** ports `is_unserved` and `incompatible`: a bare `UNIMPLEMENTED`, `UNKNOWN_METHOD`, or `NOT_IMPLEMENTED` from a daemon whose version differs leads to at most two calls (`GetDaemonStatus`, then `reef.daemon.v0.Daemon/Status`, whose two messages are generated from the frozen v0 files as `reef.daemon.v0`) and an `IncompatibleError`; a `NOT_IMPLEMENTED` from a daemon of the same version stays an `UnsupportedError`. The SDK compares versions, not revisions, as the Rust client does.
- **The API revision.** `client.daemon_status()` is the generated `get_daemon_status` with `skip_backends=True`, cached for the client's life. `client.require_revision(n)` raises `IncompatibleError` when the daemon's `api_revision` is lower, for a caller about to send a field added later (the daemon ignores unknown fields, so such a field would otherwise be silently dropped). The docs page shows it next to `GetDaemonStatus`'s comment ("A client checks `api_revision` before calling an RPC added after revision 1").
- **Agent names** follow `check_agent`: trimmed, empty means none, otherwise visible ASCII of at most 256 bytes, else `InvalidArgumentError` reason `INVALID_AGENT` at `connect()` or `with_options()`, before any call. The agent comes from `agent=`, else `REEF_AGENT`, and is sent as `reef-agent` on every call.

### The workspace block and presence

`client.workspace(repo, *, change=None, new_on=None, purpose=None, owner=None, backend=None, lease_length=None, activity=None, keep=False, report_presence=True)` is a context manager (async context manager on `AsyncClient`) yielding a `WorkspaceHandle`: the equivalent of `reef ws run` for a block of Python.

- **Enter**: `CreateWorkspace` with `owner` defaulting to `<user>@<host>:<pid>`, as `ws run`'s, so `reef ws list --owner` and the attach rule treat it alike. The user is the password database entry, else `$USER`, else the uid; the host is `socket.gethostname()`, else `localhost` (`default_owner()`'s rules).
- **Heartbeats**: renews the lease every `Lease.heartbeat_every`, with `heartbeat.rs`'s 5 s deadline and backoff, logging (Python `logging`, logger `reef`) at `warning` once when the link is lost or the lease lapses, and stopping when the daemon says the lease ended. It never raises into the block; `handle.lease_lost` (a `bool`) tells the block if it cares.
- **Presence**, per R2.11's contract, unless `report_presence=False`: one `ACTIVITY` entry for the workspace with the `Refresh` cadence (every 10 s, TTL 30 s), reported after the workspace exists. Its text is `activity`, else `purpose`, else `running <sys.argv joined by spaces>` cut to 200 characters as `purpose_of` cuts. Its agent follows rule 7: the client's agent, else the workspace's owner. `handle.activity(text)` replaces it at most once a second. Failures never reach the block (rule 6).
- **Exit**, whether the block returned or raised: clear the entry (within 2 s, rule 5), stop the heartbeats, then `ReleaseWorkspace` with `snapshot_first` unless `keep=True`. The final snapshot keeps every edit, as `ws run`'s does. An exception from the release is raised only when the block itself succeeded; otherwise it is logged and the block's exception propagates.
- **`WorkspaceHandle`**: `id`, `path` (a `pathlib.Path`, the directory on the daemon's machine, which is local for a socket), `repo_id`, `change_id` (current as of the last call through the handle), `workspace` (the last `Workspace` message), and the workspace-scoped calls an agent makes most, each filling `workspace=` for it: `snapshot()`, `status()`, `diff(**fields)`, `read_file(path, **fields)`, `edit_files(**fields)`, `move(**fields)`, `release()` (early), `activity(text)`. Everything else is on the client.
- **`client.attach(workspace, *, release=False, report_presence=True, activity=None)`** holds an existing workspace the same way (heartbeats on its current lease, presence) and releases it at exit only with `release=True`. This covers a workspace another process created, as `ws run --workspace` does.
- **Remote**: `workspace()` and `attach()` work over a remote with a `write` token. `path` is then on the daemon's machine, and the docs page says to use `read_file` and `edit_files` there, as the CLI's remote mode does.
- **One core, two drivers.** `reef/_presence_core.py` is a sans-I/O state machine (inputs: `set(state)`, `tick(now)`, the outcome of a report or clear; outputs: the next request to send and the next wake-up), ported from `presence.rs`'s `run` with the same rules (coalescing within a second, re-report without an id on `PRESENCE_NOT_FOUND`, stop for good on a gone subject or `UNIMPLEMENTED`, keep the id while the daemon is unreachable, `TOO_MANY_PRESENCE_ENTRIES` retried at the next refresh). `reef.presence.Reporter` drives it from a daemon thread; `reef.aio.presence.Reporter` from a task. The lease heartbeater is built the same way (`_lease_core.py`). The ported tests run against the core with a fake clock, so both drivers share one tested behavior, and each driver has one integration test.

### Documentation

- **`docs/adr/0054-sdks.md`** (accepted), indexed in `docs/adr/README.md`. Decisions, written for R2.07 to reuse:
  1. Each SDK is generated from the protos at build time and not committed; the wrapper's methods are generated too, one per RPC on one client object, with page and stream helpers by rule.
  2. Versions follow the workspace version; the generated API revision is exported; mismatches are found by the probe, as `reef-client` does.
  3. Socket discovery and remote selection follow `reef-client` exactly, checked through the shared fixtures in `sdk/fixtures/`.
  4. No autostart, no daemon restart.
  5. Errors are one class per kind with the daemon's `reason`, `hint`, `next` and `metadata`; client-side failures are subclasses with their own advice.
  6. Remote pinning happens before the token is sent, by reading the leaf on a separate handshake and trusting only it.
  7. The workspace helper is `ws run`'s contract: heartbeats, one `ACTIVITY` entry, release with a final snapshot.
  8. Publishing is from `release.yml` by OIDC trusted publishing, after `release`, warning on failure.
  9. No harness is named in an SDK's API or documentation.

  Alternatives: committed generated code with a freshness check (unreadable diffs for no drift protection the build does not already give); betterproto or grpclib (beta, and no way to pin through it); hand-written methods (43 of them, twice, drifting); a separate object per service (11 more names for an agent to learn); per-call keyword options (`BuildStoreRequest.timeout` clashes); autostart (a library spawning a daemon it does not ship); a TLS-terminating proxy thread for pinning (more code, needed only if grpcio refused a non-CA root, which it does not); `cryptography` for the DER walk (a large dependency for two fields); a token stored by the SDK (profiles are the CLI's file and stay so).

## Implementation notes

- **`grpc.aio` and threads.** `AsyncClient` creates its channel on its loop; using it from another loop is a `RuntimeError` with a message saying so. The sync client's heartbeat and presence threads are daemon threads that finish their clears before `__exit__` returns.
- **Eager connect**: `grpc.channel_ready_future(channel).result(timeout=connect_timeout)` (sync) and `await asyncio.wait_for(channel.channel_ready(), connect_timeout)` (async).
- **Detail decoding**: `grpc_status.rpc_status.from_call` (sync) and `rpc_status.from_call` over `AioRpcError` (it reads `trailing_metadata()`); unpack the first `Any` whose type URL is `type.googleapis.com/reef.api.v1.ErrorDetail`.
- **v0 messages**: the hook also compiles `proto/reef/daemon/v0/{daemon,error}.proto` into `reef/daemon/v0/` for the probe; they are frozen and not re-exported.
- **Leaf fetch on a remote that answers 421 or slowly**: the pre-handshake reads nothing after the handshake and closes, so the listener's handshake limits (64 at once, 10 s each) see one short connection per `connect()`.
- **Logging** uses the `reef` logger at `debug` for presence and heartbeat attempts and `warning` for a lost link or lease, never `print`.
- **Generated code formatting**: `clientgen.py` emits code that `ruff format` leaves unchanged, so mypy and ruff run on it without exclusions.
- **macOS and Linux** run the same code; the CI legs differ only in the default state directory, which the tests do not use.

## Performance expectations

- `reef.connect()` to a local daemon takes under 20 ms, and a `get_status` call adds under 2 ms to the daemon's own time for it; the PR reports both from the integration fixture.
- A pinned remote `connect()` costs one extra TLS handshake (under 10 ms on loopback).
- `import reef` takes under 150 ms (grpc and protobuf dominate); the PR reports `python -X importtime`.
- The wheel is under 600 KiB (the generated modules and stubs); the PR reports its size.
- The `python` CI job takes under 8 minutes per leg when the Rust cache is warm.

## Out of scope

- **The TypeScript SDK** (R2.07), which reuses ADR 0054 and `sdk/fixtures/`.
- **Resuming subscriptions automatically** after a daemon restart: the docs page shows the `cursor` loop; a `follow_operations` helper is a follow-up issue if users want one.
- **Reason constants** (`reef_api::error`'s are Rust constants, not schema). Callers compare strings; generating them would need the constants in the schema first.
- **Windows**: no daemon runs there.
- **Bundling `reef` or `reef-daemon` in the wheel**, or a platform wheel per target: the daemon is installed as the quickstart says.
- **The MCP server's Python listing** (the registry accepts PyPI packages): `reef mcp` is not a Python program, and R2.25's MCPB listing covers it.
- **Attaching the wheel to the GitHub release**: PyPI holds it, with its own attestations.
- **Reading `config.toml` beyond `daemon.socket`**, and writing `remotes.toml` (`reef remote add` writes it).

## Risks

- **The name is unreserved until the first upload.** A pending publisher does not hold `reef-vcs`, so someone could register it first. The one-time setup below says to add the publisher before the next tag, and the user picks a fallback if the name is taken.
- **grpcio's TLS behaviors** were verified at 1.85.1 only. A later grpcio that stopped accepting a non-CA leaf as its root, or changed `ssl_target_name_override`, would break pinning. Tests 23 to 29 run on every PR, so a Dependabot bump that breaks it fails; the fallback is the TLS-terminating proxy named in ADR 0054's alternatives.
- **The `:authority` refusal** is the daemon's HTTP/2 server's behavior, not documented anywhere: a future grpcio that changed its default would still be overridden by the SDK's explicit `localhost`. R2.07 (`@grpc/grpc-js`) must check the same thing.
- **A regular expression over Rust source** (`API_REVISION`) breaks if that line changes shape. The hook fails loudly, and test 14 catches a wrong revision.
- **grpc and `fork`**: a client created before `os.fork()` misbehaves in the child. The docs page says to create clients after forking, as grpc's documentation does.
- **The validity-date difference** between grpc's check and the Rust verifier matters only for a generated certificate the daemon failed to renew; the error is then `RemoteTlsError` (`handshake`), and the docs page names it.

## Choices this brief made, and why

- **Generated at build time, not committed**: the web UI's precedent, and generated code that cannot drift needs no freshness check.
- **The wrapper generated too**: 43 methods twice by hand would drift from the schema the first time an RPC is added; generated, every later ticket's RPC reaches Python with no SDK work.
- **One client object, methods by RPC name**: what `reef-client` has, and what an agent writing Python can discover with `dir()`.
- **Sync and asyncio from one generator**: orchestrators of many agents are asyncio, scripts are not, and the generator makes the second surface nearly free.
- **grpcio, with pinning done beside it**: the stock stack ADR 0029 named, and the experiment above showed pinning works through it without a proxy or a TLS library.
- **No autostart**: a library should not spawn a daemon it did not ship.
- **The `ws run` contract for the block**: one workspace, one entry, one release, so the fleet panel shows a Python agent exactly as it shows a `ws run`.
- **Warn, don't fail, on PyPI**: the release is the binaries; the channels follow, as R1.28 and R2.25 decided.

## What later tickets inherit

- **R2.07** reuses ADR 0054's decisions, the two fixtures under `sdk/fixtures/`, the error class tree, the workspace block, and the publish-after-release pattern (npm's trusted publishing), and checks `@grpc/grpc-js`'s `:authority` over a Unix socket.
- **Every API change** reaches Python by generation; ADR 0029's checklist item 12 covers the one case that needs a decision (paged items).
- **Every release** publishes `reef-vcs` at the workspace version with nothing to bump; the person tagging checks the `pypi` job's warning, as they check the tap's and the registry's.
- **R3.05 and later services** get methods without SDK work; a new streaming RPC gets a `Stream` by rule.
- **RX.03 telemetry**, if it adds a client-side opt-in, has one place in the SDK to read it (`reef.connect`).

## Decided by the user (2026-11-02)

1. **The SDK publishes from the start**: `release.yml` publishes `reef-vcs` to PyPI by trusted publishing over GitHub OIDC on every release tag. The user sets up the trusted publisher on PyPI; the first upload goes out with the next release tag.
2. **Agent-agnostic**: no harness is named in the SDK's API, docstrings, README or docs page.
3. **Size L**, with both clients and the workspace block.
4. **`import reef`**, the proto package's name, beside the distribution `reef-vcs`.
5. **The GitHub environment is `pypi`**, entered as the pending publisher's environment.
6. **No fallback name now.** If `reef-vcs` is taken before the first upload, the user decides then.

## User one-time setup

Nothing is needed before the PR merges: the dry run builds and tests the wheel and publishes nothing. Before the next release tag (the release after this merges):

1. **Add a pending publisher on PyPI** (pypi.org, signed in as the account that should own the project, then Account settings, Publishing, "Add a new pending publisher", GitHub tab):
   - PyPI Project Name: `reef-vcs`
   - Owner: `reef-vcs`
   - Repository name: `reef`
   - Workflow name: `release.yml`
   - Environment name: `pypi`

   Enable two-factor authentication on that account if it is not already; PyPI requires it to manage publishers.
2. **Leave GitHub Actions' OIDC tokens allowed** for `reef-vcs/reef`. They are on by default, and `release` and `mcp-registry` already use them, so this is a check, not a change. The `pypi` environment is created by the job's first run; protection rules on it are optional.
3. **After the tag's run**, check the `pypi` job for a warning, then `pip install reef-vcs==<version>` in a fresh venv and run the README's first example against your daemon. If the job warned with `invalid-publisher`, compare the four fields above with the run (the warning prints the workflow and environment it presented) and re-run the `pypi` job.
4. **Optionally, after the first upload**: add a second owner to the PyPI project, so the name does not depend on one account.
