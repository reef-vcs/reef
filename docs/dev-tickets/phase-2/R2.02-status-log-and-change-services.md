# R2.02 Status, log, and change services

Phase 2 · Size L · Depends on: R2.01 (the schema, the page codec, `written_operation`) · Unblocks: R2.03, R2.05, R2.09, R2.12, R2.14, R2.23

## Context

R2.01 declared the read side of `reef.api.v1` in full and left six RPCs answering `NOT_IMPLEMENTED`: `GetStatus`, `ListChanges`, `GetChange`, `GetDiff`, `ListOperations` and `GetOperation`. This ticket implements them over jj-lib, and with them the machinery every later read and write depends on: revision resolution over jj's revset language with Reef's aliases, reads at an operation, snapshot-before-read, classification of operations Reef did not just write, and the effects of an operation, filled wherever an `Operation` is built. It switches `CreateWorkspace` and `MoveWorkspace` (and `BuildStore`, whose `revision` is the same reference) from Phase 1's resolution to the new one.

The CLI gains nothing a user sees: `reef status`, `log` and `diff` are R2.05's. `Client` gains one method per implemented RPC.

R2.01's rule binds this brief: it implements what R2.01 declared and only adds fields, enum values and reasons. Five places where the declared schema cannot be implemented as written are named below under "Schema additions", fixed with eight fields and one enum value; nothing R2.01 declared changes meaning.

## Decisions

### Where the code lives, and which thread runs it

- **jj work stays in `reef_lib::jj`.** New modules `revset.rs` (resolution, aliases, the hex change id resolver, evaluation), `log.rs` (`ChangeInfo` and the log graph), `diff.rs` (tree diffs and hunks) and `effects.rs` (operation effects), plus additions to `oplog.rs` (classification, operation lookup, a resumable walk). They take `&Arc<ReadonlyRepo>` and return Reef structs; the daemon converts those to `v1` messages in `convert.rs`. `reef-lib` gains `chrono` (the version jj-lib resolves, `default-features = false`, feature `clock`) and `pollster`, both already in `Cargo.lock`.
- **Reads run off the repository thread.** A read takes its `Arc<ReadonlyRepo>` from one short job on the repository thread, then does its work on `spawn_blocking` under `pollster::block_on`, holding a permit of a new `read::Reads` semaphore (`max(2, available_parallelism())` permits, a constant, no configuration key). A slow diff therefore never delays a snapshot's commit, and reads of one repository run in parallel. This is ADR 0012's workspace-scan pattern applied to reads; ADR 0030 records it.
  - Change, diff and status reads take the head through `RepoHead::refresh`, as a snapshot does, so `jj` CLI writes on the registered root are seen. Operation reads (`ListOperations`, `GetOperation`, effects) take `RepoHead::readonly` with no refresh, and read the operation heads themselves from the op heads store, so they never reload and never merge divergent heads: they are truly side-effect free.
  - A read that panics (`JoinError::is_panic`) fails with `INTERNAL` and sends the repository thread a job calling `RepoHead::note_panicked`, so the next job reopens the store the panic may have poisoned (#63). `RepoHandle::reopen_after_panic` is that job.
  - A read stops early when its RPC is dropped: the handler holds a guard whose drop sets an `AtomicBool` the blocking loop checks between entries, and the daemon's shutdown token sets it too. A single jj-lib call between two entries (one revset filter step, one file's diff) is not interrupted.
  - Reads never import git refs. A colocated repository's git changes that jj has not imported (a `git commit` in the root) are not visible until a write imports them (`CreateWorkspace` and `MoveWorkspace` do, `create.rs:601`).
- **Two small caches in `Reads`**, with no new dependency (a `Mutex<HashMap>` plus a FIFO `VecDeque` of keys):
  - repositories loaded at an operation other than the head, keyed by `(RepoId, operation id)`, 8 entries, so later pages at a pinned operation do not reload its index;
  - computed `OperationEffects`, keyed by `(RepoId, operation id)`, 4,096 entries. Operations are immutable, so an entry is never stale; GC (R1.17) rewrites operation ids, and `CollectGarbage` and `ForgetRepository` clear both caches for the repository afterwards.

### Revisions and revsets

- **`revision` and `revset` are jj's revset language, parsed and resolved by jj-lib**, with jj's symbol order: tags, local bookmarks, commit id prefixes in hex, change id prefixes in reverse hex. Reef adds one `SymbolResolverExtension`, `HexChangeIds`, which runs after jj's resolvers and resolves a symbol of hex digits (optionally `/<n>` for the n-th of a divergent change's commits, as jj's own change resolver does) as a change id prefix. So hex text is a commit id prefix first and a change id prefix second, and reverse hex is only a change id. A full 32-digit change id, which every response carries, can only match a commit by a 128-bit coincidence. `change_id("…")` keeps jj's meaning and takes reverse hex only; the `changes.proto` comment says so.
- **This changes `CreateWorkspace`, `MoveWorkspace` and `BuildStore`** for two inputs, both recorded in the CHANGELOG: a bookmark whose name is also a valid id prefix (`cafe`, `works`) now resolves to the bookmark, removing the warning on `Repo::resolve_revision`; and hex text that prefixes both a commit id and a change id now resolves to the commit. A divergent change id and a conflicted bookmark are now `INVALID_ARGUMENT`, reason `AMBIGUOUS_REVISION` (exit 2), where Phase 1 said `Conflict` (exit 5), as R2.01's reference rules require ("several are `INVALID_ARGUMENT`").
- **Reef's aliases**, built per read from the view being read, and no others (the user's jj `revset-aliases` configuration is not read; a client must get the same answer from every daemon):
  - `trunk()` is `commit_id("<hex>")` of the first of R1.31's default-start bookmarks that exists in the view (`main`, origin's HEAD local then `@origin`, `master`, `trunk`, then `main`, `master`, `trunk` on `origin`; a conflicted one skipped with a warning), else `root()`. Not the `default` workspace's working-copy commit, R1.31's last fallback: that commit is the user's mutable work, and calling it trunk would make it immutable. The bookmark search moves from `create.rs` to `reef_lib::jj::revset::trunk`, which returns `Trunk { commit_id, bookmark }` (`main`, `main@origin`); `default_start` keeps the root-checkout fallback on top of it. origin's HEAD is read from git's refs as they are now, even for a read at an older operation.
  - `immutable_heads()` is `trunk() | tags()`.
  - `immutable()` is `::(immutable_heads() | root())` and `mutable()` is `~immutable()`, as jj defines them. The `changes.proto` header comment lists all four.
- **`@` is the request's workspace's working-copy commit**: the view's working-copy commit for jj workspace `reef-<id>` at the operation read, which is jj's meaning. After a snapshot the files and the view agree; with `skip_snapshot` the view may already point at another workspace's rewrite of a shared change that this workspace has not adopted (ADR 0018). Other workspaces are reachable as `reef-<id>@` and `default@`, and every working copy as `working_copies()`. Without a request workspace, `@` is `INVALID_ARGUMENT`, reason `WORKSPACE_REQUIRED`. A workspace with no working-copy commit in the view read (released, or not yet created at `at_operation`) is `NOT_FOUND`, reason `WORKING_COPY_NOT_FOUND`.
- **Parsing always has a workspace context**, so `files()` works without a request workspace. To learn whether an expression uses `@`, `revset::parse` parses it first with a sentinel workspace name (`\0reef-at-` followed by a per-process random hex nonce, which no user can type) and checks the expression's `Debug` output for that name's `WorkingCopy` node; then it parses again with `reef-<id>`, or keeps the sentinel parse when there is no workspace and `@` is not used. jj-lib offers no public expression walk; a unit test pins the `Debug` form, so a jj-lib bump that changes it fails there (Risks). `ParsedRevset::uses_working_copy` is the answer.
- **"Exactly one commit."** `revset::resolve_one` evaluates and takes two commits at most: none is `NOT_FOUND`, reason `REVISION_NOT_FOUND`; two or more is `INVALID_ARGUMENT`, reason `AMBIGUOUS_REVISION`, with up to ten commit ids in `metadata["commit_ids"]` (comma-separated) and the hint "It names several commits; name one by commit id: <ids>." jj's own resolution errors map the same way: `NoSuchRevision` is `REVISION_NOT_FOUND` (jj's candidate names in the hint, "Did you mean …?"), `DivergentChangeId` and `ConflictedRef` are `AMBIGUOUS_REVISION` with their commits, `AmbiguousCommitIdPrefix` and `AmbiguousChangeIdPrefix` are `INVALID_ARGUMENT`, reason `AMBIGUOUS_ID_PREFIX`, `WorkspaceMissingWorkingCopy` is `WORKING_COPY_NOT_FOUND`, and a parse error is `INVALID_ARGUMENT`, reason `INVALID_REVSET`, with jj's message (span and all) as the error's message. An empty `revision` where one is required is `INVALID_ARGUMENT`, reason `REVISION_REQUIRED`. A commit named by id that is hidden at the operation read resolves, as in jj, and its `Change.hidden` is set.
- **Parse settings**: `user_email` from the daemon's jj settings; `DatePatternContext` from `chrono::Local::now()`; `default_ignored_remote` `git`, as jj does for colocated repositories; no fileset aliases; the path converter rooted at the registered root for both `cwd` and `base`, so `files()` patterns are repository-relative. Parse warnings (deprecated functions) are logged at `debug` and dropped.

### Operations to read at

- **`at_operation`** is an operation id or a unique prefix of lowercase hex, nothing else: `@`, `@-` and jj's other operation expressions are `INVALID_ARGUMENT`, reason `INVALID_OPERATION_ID`. A full-length id is read directly (`read_operation`); a shorter one goes through the store's prefix lookup, which lists every operation, so page tokens always store full ids. No match is `NOT_FOUND`, reason `OPERATION_NOT_FOUND`; several are `INVALID_ARGUMENT`, reason `AMBIGUOUS_OPERATION_ID`. Any operation in the store qualifies, including ones an undo left off the head's ancestry. The repository is loaded at it with `RepoLoader::load_at` (cached, above); when it is the head, the head's `Arc<ReadonlyRepo>` is used. A read at an operation never snapshots. Every response's `at_operation` is the full id read.
- `GetOperation.operation_id` resolves the same way; empty is `INVALID_OPERATION_ID`.

### Snapshot before read

- **Which reads snapshot.** With a request workspace that is `active`, no `at_operation`, no `page_token`, and `skip_snapshot` false: `GetStatus` always; `GetChange` when `revision` uses `@`; `ListChanges` when `revset` uses `@` or is empty (the default set includes every working copy); `GetDiff` when either revision uses `@` or `to_revision` is empty. Later pages read the operation the first page pinned and never snapshot. A workspace that is not `active` is never snapshotted; `GetStatus` on one is `FAILED_PRECONDITION` (the existing `ManagerError::NotActive`, with its advice). `reef-<id>@` and `working_copies()` read other workspaces' last recorded snapshots.
- **The snapshot** is `Manager::snapshot_for_read(id, arrived)`, kind `explicit`, the default description, through the same pipeline as `SnapshotWorkspace`. It coalesces: `WorkspaceEntry` records when its last scan started (set in `run_snapshot` with the scan lock held); a read snapshot that gets the scan lock and finds a scan that started after the request `arrived` returns `Covered` without scanning, since that scan saw every write the client finished before sending. N concurrent reads of one workspace cost at most two scans.
- **A failed snapshot fails the read** with the snapshot's error, plus the hint "Pass skip_snapshot to read the last recorded snapshot." (an `Advise` on the new `ReadError::Snapshot`).
- **`StatusSource`**: `SNAPSHOT` when this request snapshotted, found nothing new, or was covered; `LAST_SNAPSHOT` with `skip_snapshot`. `WorkspaceStatus.snapshot` is the operation this request recorded, unset when it recorded none (nothing new, or covered). `INDEX` and `WALK` stay R2.23's.

### Pagination over jj state

- **Positional cursors at a pinned state.** `page.rs` gains `PageRequest::cursor() -> Option<&str>`, `PageRequest::pinned() -> Option<&str>` (the token's `at_operation`), and `PageRequest::token_at(cursor, pinned) -> String`. The token format and its version do not change: R2.01's tokens never set `at_operation`. The three jj lists use them:
  - `ListChanges`: pinned to the operation read; cursor `<entries returned so far>:<last commit id>`. A page re-evaluates the revset at the pinned operation and skips that many entries, checking the last skipped commit against the cursor (`INVALID_PAGE_TOKEN` if it differs).
  - `GetDiff`: pinned to the operation read; cursor the last path returned. A page streams the diff and skips paths up to and including it.
  - `ListOperations`: pinned to the sorted, comma-joined ids of the operation heads the first page walked from; cursor `<operations examined so far>:<last examined id>`. A page re-walks from the pinned heads and skips.
  Skipping costs index or op-store reads, not commit or file reads; deep pages cost more than early ones (Risks).
- **Page bytes.** Every page also stops before its encoded response would pass 3 MiB (`MAX_PAGE_BYTES`, under tonic's 4 MiB default), with a non-empty `next_page_token`. A page may therefore hold fewer than `page_size` items; the RPC comments say so. A single item larger than the budget (one file's hunks) is still returned alone; its own caps keep it under the limit.
- **A pinned operation that is gone** (GC rewrote the log) is `NOT_FOUND`, reason `OPERATION_NOT_FOUND`, hint "The operation the first page was read at is gone; read from the first page again."

### `GetStatus`

- `repository`: the record. `at_operation`: the operation read, after the snapshot.
- `repository_status`, from the same view:
  - `trunk` and `trunk_bookmark`: `revset::trunk`'s commit as a `Change` and its bookmark; unset and empty when no candidate bookmark exists (`trunk()` is then `root()`).
  - `active_workspaces`: the repository's active workspace rows, newest 100, as `ListWorkspaces` builds them (the conversion moves into a shared helper); `active_workspace_count`: all of them.
  - `heads`: `heads(mutable())` as `Change`s, newest committer time first, ties by commit id descending, at most 100; `head_count`: all.
  - `conflicted_change_ids`: change ids of `mutable() & conflicts()` in log order, deduplicated, at most 100. `divergent_change_ids`: change ids of `divergent()`, the same way.
  - `last_operation`: the operation read, classified, with effects.
- `workspace_status`, when a workspace is named: `workspace` as `GetWorkspace` builds it; `working_copy` and `parents` as `Change`s; `changed_files`: the working-copy commit against its parents merged, exactly as `GetDiff` with `DIFF_FORMAT_SUMMARY` (renames and copies included), in path order, at most `max_files`; `changed_file_count`: all; `conflicted_paths`: the working-copy tree's conflicted paths in path order, at most 1,000 with the new `conflicted_path_count` (Schema additions); `source` and `snapshot` as above.
- `max_files`: 0 means 100, above 1,000 means 1,000, negative is `INVALID_ARGUMENT` (comment updated to say so).

### `ListChanges`, `GetChange`, and `Change`

- **The default log set** is `trunk() | working_copies() | mutable()`: every working copy in the view (the active Reef workspaces' and `default`'s), every visible mutable commit, which is every mutable head and its ancestors back to `trunk()` (or a tag), and `trunk()` itself. This is R2.01's "every active workspace's working-copy commit, their ancestors back to `trunk()`, `trunk()` itself, and every visible mutable head", read so that a stack nobody's workspace is on is shown whole rather than as its head alone, as `jj log` shows it, and with "active workspaces" taken from the view read, which is the only record of them at an `at_operation`. A working copy on an immutable commit (a workspace editing `trunk()`) is included through `working_copies()`. The `ListChangesRequest.revset` comment is reworded to this definition. In a repository with no default-start bookmark, `trunk()` is `root()` and the set is the whole visible history, as in jj.
- **Order and edges.** Entries are `stream_graph` grouped by `TopoGroupedGraph`, children first, branches kept together: the order `jj log` prints without `--reversed`. No branch is prioritized (that would panic for a node outside the set). Each entry's `edges` are jj's `GraphEdge`s mapped one to one (`DIRECT`, `INDIRECT`, `MISSING`). The `GRAPH_EDGE_KIND_DIRECT` comment's "the next entry's commit" is wrong (a direct parent need not be the next entry); it is reworded to "A direct parent, itself in the log."
- **`GetChange`**: `resolve_one(revision)`, then the `Change`. `ListChanges` with an empty revset and no workspace is the default set with no `@`.
- **`Change`**, built by `log::describe`, with the view's bookmarks, tags and working copies indexed by commit once per request:
  - `change_id`, `commit_id`, `parent_commit_ids` in jj's order, `parent_change_ids` in the same order (parents read from the store's cache), `description` in full, `author` and `committer` (`at` is the signature's instant in UTC; jj's time zone offset is not carried).
  - `tree_id`: the resolved tree's hex id, empty when conflicted. `empty`: the tree equals the parents' merged tree (`merge_commit_trees`); the root commit is empty. `conflict`: `has_conflict()`.
  - `divergent`: the change has more than one visible commit in the view read. `immutable`: the commit is in `immutable()`. `hidden`: not in `::visible_heads()` at the operation read.
  - `bookmarks`: local bookmarks as `name` and remote bookmarks as `name@remote` that have this commit among their targets, every remote except `git`, sorted; a conflicted bookmark appears on each of its targets. `tags`: local tags, the same way.
  - `workspace_ids`: Reef workspaces (jj `reef-<id>`) whose working-copy commit it is; `jj_workspaces`: the other jj workspaces' names.

### `GetDiff`

- `to_revision` resolves to one commit, empty meaning `@` (so `WORKSPACE_REQUIRED` without a workspace). `from_revision` resolves to one commit; empty means `to`'s parents, merged with `merge_commit_trees`, and `from_commit_ids` lists them (several for a merge). Both resolve at the same operation.
- **Files** come from `diff_stream_with_copies`, path order (the new path for a rename). Copy records are the git backend's between each from-commit and the to-commit, all added to one `CopyRecords`, as `jj diff` does; a backend without copy records gives none. Kinds: a copy record's rename or copy is `RENAMED` or `COPIED` with `old_path`; absent before is `ADDED`; absent after is `DELETED`; otherwise `MODIFIED`, including a type change only (an executable bit, which `old_type` and `new_type` show). `EntryType` comes from each side's tree value: `CONFLICT` for an unresolved value, `SUBMODULE` for a git link.
- **`paths`**: each must be a repository-relative `/`-separated path without `.`, `..` or empty components (`RepoPathBuf::from_internal_string`), else `INVALID_ARGUMENT`, reason `INVALID_PATH`, metadata `path`; matching is by whole components (`src` matches `src/a.rs`, not `srcx`), with jj's prefix matcher. An empty string is the root.
- **Per file, by format.** Every format computes `conflict` (either side unresolved) and `binary` (either side's first 8,000 bytes hold a NUL, git's rule; conflicts, symlinks and submodules are never binary), reading at most the first 8,000 bytes of each side for `SUMMARY`. `STAT` and `HUNKS` read both sides, materializing a conflict with jj's default marker style, and count `lines_added` and `lines_removed` over the whole file with `diff_by_line`; a binary or too large file has counts 0 and no hunks. `HUNKS` adds `unified_diff_hunks` with `context_lines` (unset is 3), converted to `Hunk`: `old_start` and `new_start` count from 1, and a side with no lines gets the number of the line before (0 at the top), as git writes it; `lines` is each line prefixed `' '`, `'-'` or `'+'`, newline-terminated. The hunks stop at `max_lines_per_file` body lines (0 means 1,000), or when one file's hunks would pass 1 MiB of `lines`, whichever comes first: the hunk at the limit is cut to the lines that fit, its `old_lines` and `new_lines` recounted from what it keeps, later hunks are dropped, and `truncated` is set. Without the byte limit one file could exceed the 4 MiB message limit, since `max_lines_per_file` has no declared maximum; the field's comment gains "hunks also stop at 1 MiB per file", which bounds the declared behavior rather than changing it.
- **Where the declared fields cannot say what the content is**, the new fields do (Schema additions): `old_no_final_newline` and `new_no_final_newline` (`lines` are newline-terminated by declaration, so the last line's missing newline needs a flag), `too_large` (a side above 16 MiB is not read past 16 MiB: no counts, no hunks), and `invalid_utf8` (`Hunk.lines` is a protobuf `string`, so bytes that are not UTF-8 become U+FFFD; the counts stay exact).
- **Paging**: `page_size` files (0 means 100); `total_files` is the count over every page, so each page streams the whole diff without reading contents; `next_page_token` as above.

### `ListOperations` and `GetOperation`

- **Order**: jj's `op_walk::walk_ancestors` from the current operation heads, which is what `jj op log` prints: newest end time first among operations whose children have all been listed. Paged as above.
- **Bounds.** `ended_before` skips operations that ended at or after it. `ended_after` stops the walk at the first operation that ended at or before it: the walk emits in descending end time as long as every operation ends after its parents, which holds on one clock; with skewed clocks across hosts sharing one repository, older-looking operations past that point are omitted. The field comment says so.
- **Filter**, values ORed within a field and fields ANDed: `workspaces` are resolved first with `resolve_workspace` (any state; an unknown or ambiguous one fails the request as `GetWorkspace` would) and matched against `Operation.workspace_id`; `agents` match `Operation.agent` exactly; `kinds` match `Operation.kind`; `changes` are hex or reverse-hex prefixes (anything else is `INVALID_ARGUMENT`, reason `INVALID_CHANGE_ID`) matched as prefixes against the change ids in the operation's effects, which are computed for that (cached).
- **Budgets.** A page examines at most 10,000 operations and computes at most 200 uncached effects (for `changes` filtering), then returns what it has with a token. A sparse filter may therefore return empty pages with tokens.
- `include_effects` fills `effects` on returned operations. `GetOperation` always does.
- **Every listed `Operation`** is built by `convert::operation` from `oplog::classify` (below) and the daemon's records: `workspace_id` from the attribute `reef.workspace`, else jj's workspace `reef-<id>`, else the `<id>` in a Reef description (so a create, move or release, recorded in `default`, names its workspace, as R2.01's write path does); `jj_workspace` as R2.01 fills it; `agent` from the attribute `reef.agent`, else the owner of that workspace's row in any state, else empty (R1.17 GC deletes old rows). Snapshot-index rows and owners are read with one query each per page.

### Operation effects

- **Definition** (ADR 0030 records it). For operation O with parents P1…Pn: *after* is O's view; *before* is, for commits, the union of the parents' visible commits, and, for bookmarks and working copies, each parent's value. The root operation's effects are empty.
  - **Commits.** `A` = visible after and not before = `walk_revs(wanted = O's heads, unwanted = every parent's heads)`; `R` = the reverse. Both stream `(commit, change)` pairs from an index holding every commit involved: the current head's index when it has all of O's and the parents' heads (`has_id`), else O's own (`load_at`).
  - **Changes**, grouped by change id, sorted by change id then commit id, one `ChangeEffect` per commit:
    - a commit in `A` that has a predecessor (`predecessors_for_commit`) of the same change is `REWRITTEN`, `previous_commit_id` that predecessor, whether or not the predecessor was visible before (rewriting a commit another workspace already rewrote makes the change divergent, and this is how it shows);
    - other commits in `A`: when the change was visible before, `REWRITTEN`, with `previous_commit_id` the change's only commit in `R` not consumed by the step above if there is exactly one (an undo or restore brings back an old commit), else empty; when it was not, `CREATED`;
    - commits in `R` not consumed above: `ABANDONED` when the change has no visible commit after, else the new `HIDDEN` (one of a divergent change's commits hidden, the change still visible).
    "Visible before" and "visible after" are change id lookups through `ReadonlyIndex::change_id_index` built over the parents' heads and over O's heads, on the same index. Those walk lazily from the heads (an `AncestorsBitSet`, jj-lib `default_index/composite.rs:720`), so looking up recent changes is cheap and nothing is built per operation. For operations written before jj recorded predecessors (`stores_commit_predecessors()` false), the predecessor step is skipped and the rest applies.
  - **Bookmarks**: every local bookmark and every remote bookmark except remote `git` whose target differs from every parent's. `commit_id` is the target afterwards, empty when deleted; `previous_commit_id` the first parent's; a conflicted target reports its first added commit and the new `conflicted` (Schema additions). Sorted by name, local before remote, remotes by name. Tags are not reported.
  - **Working copies**: every jj workspace whose working-copy commit differs from every parent's: `workspace_id` for `reef-<id>`, `jj_workspace` for the others; `commit_id` empty when forgotten, `previous_commit_id` empty when added. Sorted by jj name.
  - **Caps**: `changes` and `bookmarks` hold at most 1,000 entries each, with the new `change_count` and `bookmark_count` giving the totals: a `jj git fetch` of 50,000 commits would otherwise put megabytes into one `Operation`. The walk itself still covers every commit, from the index alone.
- **Where effects are filled.** `written_operation` computes them for every operation a write RPC reports (`CreateWorkspace`, `SnapshotWorkspace`, `MoveWorkspace` and its `final_snapshot`, `ReleaseWorkspace` and its `final_snapshot`, `GetWorkspace`'s `snapshot`, `BuildStore`'s `release_operation`), and `GetStatus` for `snapshot` and `last_operation`, `GetOperation` always, `ListOperations` with `include_effects`. A failure to compute them is logged at `warn` and leaves `effects` unset; it never fails the RPC, whose write has happened. `unread_operation` leaves them unset.
- **Cost.** The operation a write just recorded is the head, so its index is at hand: one view read per parent, two index walks over what changed, and no commit reads, a few milliseconds at most. A historical operation off the head's ancestry adds one `load_at`. Results are cached (above). Test 23 bounds what the write path adds, and `create_api/small` is recorded before and after.

### Schema additions

`reef_api::API_REVISION` becomes 2 and `API_DIGESTS` gains its second entry. Each addition is at the next free number and has a leading comment (ADR 0029 checklist). Nothing declared changes meaning; the comment-only rewordings named above (`GRAPH_EDGE_KIND_DIRECT`, `ListChangesRequest.revset`, `GetStatusRequest.max_files`, `GetDiffRequest.max_lines_per_file`, `ListOperationsRequest.ended_after`, the page-size notes, the `changes.proto` alias list, the per-RPC "Errors:" paragraphs and the removal of "Declared; R2.02 implements it") do not change the digest.

```proto
// operations.proto
enum ChangeEffectKind {
  // …R2.01's values…
  // One of the change's commits is no longer visible, and the change still
  // is, through another: a divergent change resolved.
  CHANGE_EFFECT_KIND_HIDDEN = 4;
}
message BookmarkEffect {
  // …R2.01's fields 1 to 4…
  // The bookmark is conflicted afterwards; `commit_id` is the first of its
  // targets.
  bool conflicted = 5;
}
message OperationEffects {
  // …R2.01's fields 1 to 3; `changes` and `bookmarks` hold at most 1,000
  // entries each, sorted…
  // Changes touched, in all; more than `changes` holds when it was capped.
  uint32 change_count = 4;
  // Bookmarks touched, in all; more than `bookmarks` holds when it was
  // capped.
  uint32 bookmark_count = 5;
}

// status.proto
message WorkspaceStatus {
  // …R2.01's fields 1 to 8; `conflicted_paths` holds at most 1,000, in
  // path order…
  // Conflicted paths, in all.
  uint32 conflicted_path_count = 9;
}

// diff.proto
message FileDiff {
  // …R2.01's fields 1 to 7…
  // The old side does not end with a newline: its last line in `hunks` had
  // one added. With DIFF_FORMAT_HUNKS.
  bool old_no_final_newline = 8;
  // The new side does not end with a newline, as for the old side.
  bool new_no_final_newline = 9;
  // A side is larger than 16 MiB: no line counts and no hunks. With
  // DIFF_FORMAT_STAT and DIFF_FORMAT_HUNKS.
  bool too_large = 10;
  // A side is not valid UTF-8: `hunks` show U+FFFD for the bytes that are
  // not; the line counts are exact.
  bool invalid_utf8 = 11;
}
```

Why each is needed: an operation can touch tens of thousands of changes and bookmarks (a fetch), and a conflict can span thousands of paths, while a response must stay under 4 MiB; `ChangeEffectKind` has no value for a hidden commit of a still-visible change (R2.03's divergence resolution produces exactly that), and `BookmarkEffect` none for a conflicted target; `Hunk.lines` is declared newline-terminated text in a `string`, which cannot hold a last line without a newline or bytes that are not UTF-8; and the brief caps file reads at 16 MiB. R2.15 adds its symbol fields to `FileDiff` from 12 and to `GetDiffRequest` from 13.

## Amendments made during implementation

Made in R2.02's PR; the decisions above still describe the behavior.

- **`@` detection compares two parses.** `revset::parse` parses the text as two workspace names no one can type and compares the parsed expressions' `Debug` forms; only `@` differs. Nothing depends on the exact `Debug` text, so test 4 checks every form of `@` by behavior instead of pinning a literal. A third parse with the request's workspace runs only when `@` is used.
- **`Repo::resolve_revision` stays**, reimplemented over `revset::resolve_revision` with `@` that `Repo`'s own working copy, so tests and callers holding a `Repo` keep one call. `ResolvedVia` and `Resolved::via` are gone, and `ResolveError` keeps only what `resolve_bookmark` returns.
- **`oplog::walk_from`'s visitor is async and takes the `Operation`**, so `ListOperations` computes effects for a `changes` filter during the walk, under the walk's budgets.
- **`ListOperations` reads every workspace row's owner once before the walk** (rows are few; GC deletes old ones), so the `agents` filter applies inside the walk and pages are not thinned afterwards. Snapshot-index kinds are read after the walk for the operations returned.
- **`WORKING_COPY_NOT_FOUND`'s `at_operation`** is filled where the revset is evaluated: `RevisionError::WorkingCopyNotFound` carries it.
- **Tests 22 and 23 are one test**, `written_operations_carry_effects`. Its timing prints `GetOperation`'s median after a create; the uncached cost of effects is the `reads/<preset>/effects_snapshot` bench.
- **`BuildStore` in test 24** resolves `trunk()` up to the spec read (the fixture declares no store, so the error names trunk's commit) and fails `nope` with `REVISION_NOT_FOUND`, instead of building.
- **Renames and copies stop at 1,000 differing files**, git's default `diff.renameLimit`. The git backend's rename and copy detection grows faster than the files that differ (764 ms of `diff_summary_full`'s 770 ms on `medium`, against 6 ms for the tree diff), and every page would pay it again. `diff_page` counts the differing paths first and asks for copy records only at or under the limit; past it, files are added and deleted. The `GetDiff` comment says so (comment only; the digest is unchanged). Test `renames_stop_at_the_limit` covers it.
- **`ReadError::Snapshot`** wraps the snapshot's own error and keeps its advice when it has one; the hint "Pass skip_snapshot to read the last recorded snapshot." is the fallback.

## Implementation notes

- Order: the schema additions and reasons first (bump the revision, `buf lint`, `buf format`, `buf breaking` against main), then `revset.rs` with tests 1 to 4, then the create/move/build switch and tests 24 and 26, then `log.rs`, `diff.rs`, `oplog.rs` and `effects.rs` with their tests, then `Reads` and the handlers, then `written_operation`, then the client, the bench, and the documents.
- Never await a jj-lib future on a tokio worker. Each handler resolves its `repo` and `workspace` on the async side, takes the head by a job, and moves an `Arc<ReadonlyRepo>` into `Reads::run`. SQLite stays off the repository thread and off the blocking read (snapshot-index rows and owners are read on the async side, before or after).
- `HexChangeIds` resolves synchronously, as jj's own resolvers do: `pollster::block_on(repo.resolve_change_id_prefix(..))` inside `resolve_symbol`. It must not run on a tokio worker; it never does, since resolution happens inside `Reads::run` or a repository job.
- Build the aliases map per read (`trunk()` differs by view); it is a handful of strings.
- Use `RevsetExpression`'s `Debug` only for the sentinel check, through one function with test 4 pinning it.
- `TopoGroupedGraph` buffers within a branch; never call `prioritize_branch`.
- The byte budget: encode each item's message length (`prost::Message::encoded_len`) as it is converted and stop before the sum passes `MAX_PAGE_BYTES`, so the reef-lib side returns more than a page and the daemon trims; give reef-lib a generous `limit` (`page_size` plus one) and let the daemon set the cursor from the last item it keeps.
- Reading at most 8,000 bytes for `SUMMARY`'s binary check: read `MaterializedFileValue`'s reader with a `take(8000)`; for `too_large`, a `take(max + 1)`. `file_content_for_diff` reads everything and is not used directly.
- `ChangeEffect` predecessors may name commits outside `R`; look up their change ids with `commit_change_ids` over `RevsetExpression::commits(..)` on the same index.
- The `reef.kind` vocabulary is written by R2.03; this ticket only reads it. Test 11 writes attributes with `Transaction::set_attribute` in its fixtures.
- Linux: nothing here is `cfg(target_os = "linux")`, and the unfiltered fuse-overlayfs run in CI covers `reads.rs`. Add `| (binary(reads) & test(/status_snapshots_first/))` to the kernel overlay root filter (`ci.yml:210`). ## Performance expectations

Measured with `benches/reads.rs` and recorded in `docs/benchmarks.md`; trend data, not gates, as the other benches are. The expectations, release build on the M2 Max baseline machine; investigate and explain in the PR anything more than three times over:

| Bench | What | Medium | Large |
| --- | --- | --- | --- |
| `status_diff` | working-copy commit against its parent, one file changed, plus `repository_status` | < 5 ms | < 20 ms |
| `log_default` | the default set, first page | < 5 ms | < 5 ms |
| `change_describe_100` | 100 `Change`s | < 10 ms | < 10 ms |
| `diff_summary_full` | the fixture's first commit against root: page 1 and `total_files` | < 150 ms | < 1.5 s |

End to end, `GetStatus` with a snapshot costs the explicit snapshot (`docs/benchmarks.md`: `modify_1`, and the full scan an explicit snapshot does) plus `status_diff`; with `skip_snapshot`, `status_diff` plus the RPC. ## Risks

- **Effects are specified by meaning, now with an algorithm.** The predecessor pairing covers jj's own rewrites; operations from tools that do not record predecessors, and exotic histories, fall back to coarser answers (`REWRITTEN` with no previous commit). Test 10 pins the cases R2.03 and R2.09 rely on.
- **Unbounded revset work.** A `diff_lines()` or `files()` filter over a large history evaluates inside jj-lib between two entries and cannot be interrupted there; the cancellation guard stops it only at the next entry. R2.08's remote scopes may want a per-request deadline.
- **Deep pages cost more.** Each page re-walks and skips: index walks for the log, a tree-diff walk for diffs, op-store reads for the operation log (about 10 to 20 µs per operation, so a page 100,000 operations deep re-reads them). R2.12's replay uses time bounds, which prune. A cached walk order is the follow-up if this shows up.
- **The sentinel check depends on jj-lib's `Debug` output.** Test 4 pins it; a jj-lib bump that changes it fails that test, and the fallback is an upstream request for a public expression visitor.
- **Behavior change on create and move.** Agents that relied on Phase 1's id-first order with bookmarks named like ids, or on exit 5 for a divergent change, see different results; the CHANGELOG says so, and `reason` lets a client tell `AMBIGUOUS_REVISION` from other invalid arguments.
- **Reads share jj-lib stores across threads.** That is ADR 0012's existing model for scans; a panic in a read now also schedules a reopen. A jj-lib bump that drops `Send + Sync` breaks the static assertion first.
- **Classification before R2.03** cannot tell Reef's repository initialization from the `jj` CLI's, and reports both as `EXTERNAL`.
- **Clock skew** across hosts sharing a repository can make `ended_after` omit operations; the field comment says so.
- **Repositories without a trunk bookmark** make `mutable()` the whole history, so the default log, `heads`, and the conflict scan in `GetStatus` grow with it, as `jj log` does; pagination bounds the log, and the status lists are capped at 100, but the conflict scan reads every mutable commit.
