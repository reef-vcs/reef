# Phase 2 tickets

Source of truth for scope: [`docs/dev-phases.md`](../../dev-phases.md) (Phase 2 tables) and [`docs/design.md`](../../design.md) (API, Subscriptions, Architecture, Scale). These files expand each Phase 2 row into an implementation brief. They are written for an implementing agent, not for humans: every decision that could be made in advance has been made here, and the brief says so. If a brief and `dev-phases.md` disagree on scope, the brief wins for the implementation and the disagreement is fixed in `dev-phases.md` in the same PR. Where a brief departs from `dev-phases.md`, the departure is listed under "Departures from dev-phases.md" below, and `dev-phases.md` was edited to match when the brief was written. Briefs are added as each ticket starts, so the table below grows with them.

The schema R2.01 writes is the authority for every later Phase 2 ticket that touches the API. A later brief implements the RPCs R2.01 declared and adds fields, values and RPCs. It never changes what R2.01 declared; a declaration that proves wrong is deprecated and replaced (ADR 0029).

Phase 1 is complete and released as 0.1.0 (2026-10-25). What it left behind, and what every Phase 2 brief builds on:

- **The v0 API** (`reef.daemon.v0`, ADR 0017): `Daemon`, `Repositories`, `Workspaces` (create, list, inspect, release, snapshot, heartbeat, move), `Maintenance` (GC, backup, quiesce, resume) and `Stores` (build, list), generated with `protox` and `tonic-prost-build` in `crates/reef-daemon/build.rs`. Errors carry `ErrorDetail { kind, chain, hint, next }`, with `ErrorKind` from `reef_lib::error` (ADR 0009) and advice from `Advise` (ADR 0025). R2.01 replaces this API with `reef.api.v1`.
- **The client and the CLI**: `reef_daemon::client::Client` (one method per RPC), `client::json` (the CLI's stable JSON), and the `reef` CLI under the agent-facing contract (ADR 0025: never interactive, `hint` and `next` on errors, `reef here`, additive names, exit codes by kind). The CLI still links jj-lib through `reef-daemon` (`reef daemon run`); R2.05 removes that.
- **The daemon**: one process per user over a Unix socket (ADR 0012, 0013); jj workspaces as Reef workspaces (ADR 0014); copy-on-write backends and the base cache (ADR 0015, 0016); watcher snapshots with narrowed scans, Watchman for large repositories, and watch attachment off the create path (ADR 0018, 0023, 0026, 0028); the snapshot index with local marking (R1.16); leases and reclaim (ADR 0019); backup (ADR 0020); spec files and shared stores (ADR 0021, 0022); onboarding (ADR 0024).
- **`reef_lib::jj`** over jj-lib 0.46.0: open, snapshot (split into scan and commit), operation log walk, `undo_last`, revision resolution (change id, commit id, bookmark; no revsets), materialization, GC.
- **The trust model** (`docs/threat-model.md`, ADR 0027): one uid is one trust domain, the socket is the authorization, and a remote listener (R2.08) must meet the listed requirements before it serves anything.
- **Measurement**: the criterion benches and `docs/benchmarks.md` (R1.12, R1.29, R1.32), the load test (R1.23, R1.30, `docs/load-tests.md`), and the onboarding benchmark's harness (RX.07, `docs/onboarding-benchmark.md`), which R2.17 reuses.
- **CI** on `ubuntu-24.04` and `macos-15`, a privileged Linux job for overlayfs, and tag-driven releases with an installer and a Homebrew tap (R1.28). macOS never compiles `cfg(target_os = "linux")` code; the privileged `ubuntu:24.04` container in `docs/benchmarks.md` does.

## Departures from dev-phases.md

These were decided while writing the briefs. `dev-phases.md` was edited to match in the same change.

- **R2.01 grows to L and carries the whole move to v1** (2026-10-25). Beyond the row's services, it declares in full every RPC that R2.02 to R2.04 and R2.09 to R2.11 implement (files, operation subscription, presence), so those tickets only implement and add. It ports Phase 1's services to v1 in a new `reef-api` crate, and retires v0 behind a compatibility path that names a version mismatch, restarting an idle old daemon instead of failing with an empty error. It adds an `Unsupported` error kind (exit code 9), `buf` lint and breaking-change checks in CI, and ADR 0029 with the API review checklist.
- **R2.02 names diff and the operation log** among the read side it implements, with revsets and reads at an operation. **R2.03 adds abandoning a change**, which is how a divergent change is resolved (R1.13 left that to R2.03).
- **R2.02 grows to L** (2026-10-26). Beyond the six read RPCs it implements operation kinds and effects for every reported operation, switches workspace creation, moves and store builds to revset resolution (a bookmark now beats an id prefix, and a divergent change is `invalid_argument`), adds eight fields and one enum value where the declared schema cannot carry what it describes (API revision 2), and adds ADR 0030. **R2.03 depends on R2.02**: it resolves revisions, builds `Change`s and writes the `reef.kind` vocabulary R2.02 defines.
- **R2.03 grows to L** (2026-10-26). Beyond the three write RPCs it coordinates every describe, abandon and undo with the live workspaces it rewrites (their scan locks, a snapshot first, adoption after), so a write never overwrites unsnapshotted edits or makes a change divergent through a race; abandoning one commit of a divergent change hands its descendants, bookmarks and working copies to the surviving commit; undo is a revert of one operation that refuses what it cannot revert exactly (workspace creation, release and moves, git ref imports, operations later ones changed again); it writes the `reef.*` attributes and the caller's `reef-agent` on every operation Reef records, through every write path; and it adds ADR 0031. No schema additions.
- **R2.04 grows to L, implements all of `FileService` as R2.01 declared it, and adds `copy_from`** (2026-10-26). Beyond the row's read and edit, it implements `ListFiles`, edits that create a new change (`new_on`) as well as rewrite one, text replacement and the executable bit, and runs every edit through R2.03's write path, so workspaces on an edited commit are snapshotted first and take the new tree afterwards. It adds one field, `FileEdit.copy_from` (copy or, with a delete, rename a file without sending its content; API revision 3), refuses paths with `.git` or `.jj` components, under a symlink, or under a store mount, and adds ADR 0032. It grows to L: three RPCs, a fourth write through R2.03's five steps with a dry run before any snapshot, eight reasons, and a bench.
- **R2.05 splits** (2026-10-26). The row's scope is bigger than L: removing jj-lib from `reef` (two crates, the daemon binary's offline commands, packaging) stays R2.05, size M, and depends only on R2.01; the commands R2.02 to R2.04 deferred to it become a new row, R2.27, size L, whose brief was Part B of R2.05's file and is now its own. R2.24 depends on R2.27 as well.
- **R2.27 adds three things to its row** (2026-10-26). Beyond the commands, their JSON, the CLI's advice and `metadata`: writes run in a workspace return that workspace afterwards and note a divergent result, and `reef here` points a divergent workspace at `reef log` and `reef abandon` (how the CLI shows issue #80 until it is fixed); and the daemon gains one reason, `SNAPSHOT_FAILED`, on a snapshot that fails before a read or a write, so the CLI can offer `--no-snapshot` without reading a message. Size stays L. `dev-phases.md`'s row names them.
- **R2.13 grows to L and leaves the MCP registry listing to R2.25** (2026-10-26). The registry lists only servers with a package it can verify (npm, PyPI, NuGet, crates.io, OCI, or an MCPB bundle on GitHub releases), and Reef publishes none, so the listing is release-workflow packaging, R2.25's kind of work; R2.25 grows from S to M. Beyond the row, R2.13 heartbeats the leases of workspaces it creates while it runs and releases none at exit, returns the workspace after a write as R2.27's commands do, exposes no ADMIN RPC (the server runs outside harness sandboxes, S-07), and depends on R2.27 for its JSON and scope rule. Tool descriptions and the server's instructions are its own, not R1.26's guide (CLI text, full to its budget); what it reuses from R1.26 is `hint` and `next`. The wait tool polls the operation log until R2.09 implements the subscription. `dev-phases.md`'s R2.13 and R2.25 rows say so.
- **R2.09 grows to L and depends on R2.13 and R2.27** (2026-10-27). Beyond the row's stream, filters, resume and frames, it decides how the daemon learns of operations (a wake-up from the repository thread after every job that moves the head, and a 200 ms poll of the op heads for other `jj` writers), positions as frontiers with an opaque cursor, resume at most 10,000 operations back, frames of at most 1,000 operations and 1 MiB with live frames 50 ms apart, flow-control backpressure with nothing dropped, GC, forget and shutdown, and a cap of 1,024 subscriptions. It delivers within 100 ms for one to ten subscribers and puts the per-subscription log read behind `Feed::read`, which R2.22's broker replaces; R2.22's row is unchanged. It adds one field, `SubscribeOperationsResponse.head_operation_ids` (API revision 4), four reasons, and ADR 0036; moves R2.13's `wait_for_operations` onto the stream with its contract and tool list unchanged; and adds `reef op watch`, R2.27's deferred `op log --follow`, which ends by itself (`--for`, default 30 s, or `--count`) unless `--follow` and prints JSON Lines. `dev-phases.md`'s R2.09 row says so.
- **R2.10 grows to L, implements all three presence RPCs, and gives R2.11 `reef ws renew`** (2026-10-27). R2.01 assigned `ReportPresence` and `ClearPresence` to R2.11; their semantics (ids, fixed identity, TTL clamped to 1 s to 10 minutes, caps of 4,096 entries and 32 per agent that refuse rather than evict, per-entry publish coalescing) are the channel's, so R2.10 implements them, and R2.11 keeps every entry a client reports on an agent's behalf (`ws run`, the MCP server, the SDKs, `reef presence report` and `clear`). Beyond the row, R2.10 decides a second stream on the same connection rather than a multiplexed one, the current set then changes with `synced`, no cursor, a broadcast with resync from state, the daemon's `LEASE` entries as observed liveness lapsing after two missed heartbeats, `EDITING` from committed snapshot diffs, `PROGRESS` for creates and store builds after 250 ms, and `reef presence watch`; it adds `Presence.lease`, `Presence.by_daemon` and `PresenceEvent.end_reason` with `PresenceEndReason` (API revision 5), six reasons, and ADR 0037, and no MCP tool (`tools/list` is 17 bytes under its budget). A renew command is a client-side heartbeat, so R2.11's row gains `reef ws renew`. `dev-phases.md`'s R2.10 and R2.11 rows say so.
- **R2.11 grows to M and adds the MCP server's reporting** (2026-10-27). Beyond the row's `ws run` reporting, `presence report` and `clear`, and `ws renew`, it writes the reporting contract every client follows (one entry per process and subject, replaced by id at most once a second, refreshed every 10 s with a 30 s TTL by long-lived reporters, re-reported on `PRESENCE_NOT_FOUND`, cleared at exit, the agent from `reef-agent` else the workspace's owner) into `ReportPresence`'s comment for R2.06 and R2.07, with `reef_client::presence::Reporter` as its reference implementation; makes `reef mcp` report one entry per workspace naming the tool it serves; gives `presence report` `--id` and `--id-file` so an entry can outlive the process that reported it; and has `reef here` suggest `reef ws renew` for a lease in its grace period. `ws run` keeps `<user>@<host>:<pid>` as the owner (R2.10's open question 1). No daemon code, no schema change, no ADR. `dev-phases.md`'s R2.11 row says so.
- **R2.22 grows to L, builds the broker unconditionally in its own crate, and makes the daemon accept 500 clients** (2026-10-27). R2.09's brief and ADR 0036 left the broker conditional on the measurement; the row and R4.19 do not, so it is built, and the generator's first run (before it) and last run (after it) are both published. The broker is a new crate, `reef-broker` (no jj-lib, gRPC or Reef dependency, enforced by `crate_graph`), generic over topic, position and item so the phase-four store reuses it; the daemon reads each operation once per followed repository into a bounded ring, and a second `session::Source`, `BrokerSource`, serves sessions from it and falls back to R2.09's `feed::read` behind it, so frames do not change. Presence stays on `PresenceHub`, measured beside. The load generator is a sibling of R1.23's (`tests/subscription_load.rs`, `REEF_LOAD=1`, in `load.yml`) with 500 operation and 500 presence subscribers over 500 connections, latency from each operation's `ended_at`, every delivery checked for loss, duplication and order, and a gate of p99 within 100 ms. Beyond the row, the `reef-daemon` binary raises its open-file limit and backs off accepts at it instead of spinning in tonic's accept loop, without which 500 clients cannot connect to a daemon started from a macOS shell. No schema change, ADR 0038. `dev-phases.md`'s R2.22 row says so.
