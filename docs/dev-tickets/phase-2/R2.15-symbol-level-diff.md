# R2.15 Symbol-level diff

Phase 2 · Size M · Depends on: R2.14 (the `symbols`, `symbol_refs`, `symbol_files`, `commit_files` tables, `tree_blobs`, the fixtures' `before/` trees), R2.02 (`Changes.Diff` with `FILES` and `LINES` levels, `rev` resolution, reads off the repository thread), R2.05 (`reef diff`) · Unblocks: R2.17 (the Reef arm's token cost rests on this), R3.18 (minimal check sets), R3.31 (the proposal view's diff); the symbol exit criterion

## Context

Phase 2's fourth exit criterion is "Symbol-level diffs work for Python, TypeScript, Go, and Rust." The design puts the symbol summary first and the lines behind an expand ("The diff defaults to a symbol-level summary with affected call sites and expands to lines on demand", `docs/design.md`, Human interface), and names it as the token lever: a reviewer or agent asks what changed, not which lines. R2.02 gives `Changes.Diff` three levels (`STAT`, `FILES`, `LINES`) over jj's tree diff and `ContentDiff::by_line`; R2.14 gives every blob its definitions and references. This ticket adds the fourth level, `SYMBOLS`: per file, which definitions were added, removed, changed or only moved, and for each changed or removed one where it is called, with a count of files the index does not cover. `reef diff --symbols` prints it and `--expand <name>` opens one symbol's lines.

The README fixes the vocabulary (`added`, `removed`, `changed`, `moved`, `call_sites`, `unindexed_files`), the CLI words, the fixtures' location, and that the `SYMBOLS` level answers `UNIMPLEMENTED` until this ticket. This brief adds the algorithm, the matching rule, what a call site is from each source, the fixtures' edit sets, and the token comparison R2.17 reuses.

### What was verified while writing this ticket

jj-lib 0.46.0, jj-core 0.46.0 (vendored under `~/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/`), the Reef tree at `d156d1e`, and R2.14's findings, which this ticket inherits (tree walks, blob reads, the tags queries, SCIP roles).

- **Line hunks.** `jj_core::diff::ContentDiff::by_line(inputs)` (`jj-core/src/diff.rs:752`) tokenizes with `find_line_ranges` (`:32`); `ContentDiff::hunk_ranges()` (`:777`) yields `DiffHunkRange { kind: Matching | Different, ranges: SmallVec<[Range<usize>; 2]> }` (`:935-945`), byte ranges per side, from which line numbers follow by counting newlines; `hunks()` (`:771`) yields the texts (`DiffHunk { kind, contents }`, `:868-872`). R2.02's `LINES` level is specified over these; this ticket consumes R2.02's `DiffHunk { old_range, new_range, lines }` records (line-numbered) rather than calling the differ again.
- **Which files changed.** `MergedTree::diff_stream` (`jj-lib/src/merged_tree.rs:286`) yields `TreeDiffEntry { path, values: Diff<MergedTreeValue> }` with `before` and `after` (`:370-375`); `TreeValue::File { id, executable, .. }` (`jj-core/src/backend.rs:393-411`). R2.14's `commit_files` rows hold the same for a commit against its first parent, with `blob_id` and `old_blob_id`; a diff between two arbitrary revisions walks `diff_stream` instead.
- **Tags give calls, SCIP gives references.** The tags queries mark calls with `@reference.call` (python, go, rust and javascript's `queries/tags.scm`; the TypeScript configuration is the JavaScript query plus TypeScript's, R2.14); SCIP's `SymbolRole` bitset has `Definition`, `Import`, `WriteAccess`, `ReadAccess`, `Generated`, `Test`, `ForwardDefinition` (`scip-0.10.0/src/generated/scip.rs:4083-4100`) and no call role, so R2.14 stores SCIP references with `is_call = 0`. A call site's label therefore depends on the source, and this ticket says so in the response.
- **Call-site names are unresolved from the tags source.** A `reference.call` carries the callee's name as written (`area`, or the attribute `scale` of `c.scale()`), not which `area`. Two functions named `area` in two files share call sites. SCIP references carry the full symbol string and resolve; R2.14 reduces it to `name` and `parent`, so this ticket matches SCIP references on `(parent, name)` when the definition has a parent, else on `name`.
- **What `reef diff` prints today.** Nothing: `diff` is R2.02's command, with `--stat`, `--files` and the unified text rendering of `LINES`, and `--symbols` is a stub (`not implemented until R2.15`) from R2.05 on. `reef_api::json` holds the `LINES` record types this ticket extends.
- **The token estimate.** ADR 0025 settled four bytes per token as the budget rule, and RX.07 measures real tokens end to end; this ticket records bytes and the estimate, and R2.17 measures.

## Decisions

- **The symbol diff is a function of two blobs and their line hunks.** For every file the `FILES` diff lists, `symbol_diff(before: &[SymbolRow], after: &[SymbolRow], hunks: &[DiffHunk]) -> FileSymbolDiff`. A file is in scope when its path's extension names an enabled language (R2.14's `Lang::from_path`); other files count in `other_files` and get no entry. The rows come from `symbols_for_blobs` on the two blob ids, `scip` preferred per blob; a blob with no `symbol_files` row and a supported language is indexed synchronously through the indexer (`Indexer::index_blob(repo, path, blob)`, a new entry point that runs one extraction on the indexer thread and waits), bounded by `[symbols] max_file_size`; a blob over the size or whose extraction fails is counted in `unindexed_files` and the file gets an entry with `indexed = false` and no symbols.
- **Matching rule.** A symbol's key is `(kind, parent, name)`. Rows with equal keys on the two sides are paired in order of appearance (the k-th `before` row with the key pairs with the k-th `after` row; overloads and Go methods on different receivers, whose tags parent is `''`, pair positionally). Unpaired `before` rows are `removed`; unpaired `after` rows are `added`. A paired row is `changed` when any `Different` hunk's old line range intersects the `before` row's `[start_line, end_line]` or its new line range intersects the `after` row's; else `moved` when the two ranges differ (the body is byte-identical but sits elsewhere in the file); else unchanged and omitted. A rename is a removal plus an addition, by this rule and by design: the index has names, not identities (SCIP symbols would support a rename heuristic; deferred to R3.38's time axis, which needs it).
- **Nested symbols.** A method inside a class whose body changed is `changed`; the class is `changed` too when the hunk intersects its range, which it does by containment. The response carries both; the text rendering indents a child under its parent (by `parent`) and the JSON is flat. `--summary` collapses to top-level symbols.
- **Call sites.** For each `changed` or `removed` symbol, and for every `added` one when `--callers-of-added` is set (an added function has callers only when the change also added them; off by default), `symbol_refs` rows on the `to` tree's blobs (R2.14's `tree_blobs(to_commit)`, walked once per request and cached in the request) whose `name` equals the symbol's `name` and, for `scip` rows when the symbol has a parent, whose stored `parent` matches; tags rows are matched on `name` alone. Each becomes `CallSite { path, line, kind: call | reference, enclosing_symbol: Option<String> }` where `enclosing_symbol` is the innermost `symbols` row of the same blob whose line range contains the line, as `parent.name`. References inside the symbol's own range are excluded (recursion is not a caller). Sites are capped at `[symbols] max_call_sites = 200` per symbol with `truncated = true`; the cap is this ticket's one new key. For a `removed` symbol the sites are where it is still called at `to`: the agent's "what breaks" list.
- **`unindexed_files`** counts regular files in the `to` tree whose extension names an enabled language and whose blob has no `symbol_files` row after the request's synchronous indexing of the diff's own files; it tells the reader how much of the call-site answer is missing. `reef symbols index --all` is the fix, and the CLI's `hint` says so when the count is non-zero.
- **Scope of a request.** `Changes.Diff { change }` diffs the change's commit against its first parent (a merge's second parent is R5's problem) and reads `commit_files` when R2.14 wrote them, else walks `diff_stream`. `{ from, to }` always walks. `paths` prefixes filter files before anything is indexed. Binary files (R2.02's detection) count in `other_files`.
- **Response shape** (`changes.proto`, this ticket's additions to R2.01's `DiffResponse`):

  ```proto
  message SymbolDiff { repeated FileSymbolDiff files = 1; uint32 unindexed_files = 2; uint32 other_files = 3; string from_commit = 4; string to_commit = 5; }
  message FileSymbolDiff { string path = 1; string status = 2 /* added, modified, removed */; bool indexed = 3; string lang = 4; string source = 5 /* tags, scip, or mixed */; repeated SymbolChange symbols = 6; }
  message SymbolChange { string status = 1 /* added, removed, changed, moved */; string name = 2; string kind = 3; string parent = 4; string signature = 5;
                         LineRange before = 6; LineRange after = 7; repeated CallSite call_sites = 8; bool call_sites_truncated = 9; }
  message LineRange { uint32 start = 1; uint32 end = 2; }   // 0-based, inclusive, as the index stores them
  message CallSite { string path = 1; uint32 line = 2; string kind = 3 /* call, reference */; string enclosing_symbol = 4; }
  ```

  `DiffResponse.symbols` is set when `level = SYMBOLS`; the other levels leave it unset. The JSON twin `reef_api::json::SymbolDiff` has the same fields with 1-based lines for humans (`start_line`, `end_line`), as `reef symbols lookup` prints.
- **`reef diff --symbols`** text, per file: a header `<path>  (<status>, <source>)`, then one line per symbol, `+ ` added, `- ` removed, `~ ` changed, `> ` moved, as `<marker><kind> <parent.>name  L<start>-<end>` (the `after` range, or `before` for removed), then `    called from <path>:<line> in <enclosing>` per site (`referenced from` for `reference` sites), then a footer `N files not indexed (reef symbols index --all)` when `unindexed_files > 0` and `M other files` when `other_files > 0`. `--expand <name>` (repeatable; `<parent.>name` or `name`) appends, under that symbol, the `LINES` hunks of its file that intersect its range, rendered as R2.02's unified text does. `--summary` keeps top-level symbols only. `--callers-of-added` as above. JSON is the `SymbolDiff` object with `expanded: { "<name>": [hunks] }` when `--expand` was given.
- **The token comparison is recorded, not gated.** For each language fixture and for one real change in this repository (the PR's own first commit), the PR records `wc -c` of `reef diff -o text` (unified) and of `reef diff --symbols -o text`, and bytes/4 as the token estimate, in a table in `docs/benchmarks.md` under a new "Symbol diff size (R2.15)" section. R2.17 cites that table and measures real tokens with a model. The exit criterion for this ticket is the four fixtures, not a ratio.
- **No ADR.** The symbol model's decisions are ADR 0035's; this ticket is a consumer. The matching rule and the call-site semantics live in `changes.proto`'s comments and `docs/api.md`.

## Implementation notes

- Lines in the index are 0-based (R2.14); R2.02's `DiffHunk` line ranges are 1-based for humans. Convert once, at the boundary of `symbol_diff`, and test both ends of a hunk against both ends of a range (closed intervals) so a hunk on a symbol's last line counts.
- Reuse R2.02's `LINES` computation for the hunks rather than diffing again: call its internal `line_hunks(before_bytes, after_bytes)` helper; the two blobs are already read for indexing, so pass the bytes along instead of reading them twice.
- Pair rows "in order of appearance" by `start_line`, which is how `symbols_for_blobs` orders them (`symbols_by_blob`'s index); do not sort by name first.
- The `to` tree walk is the expensive step; do it once, after the per-file work has decided which names need sites, and skip it entirely when no symbol is `changed` or `removed` (and `callers_of_added` is off).
- Keep `symbol_diff` free of I/O so the unit tests run in microseconds and R3.18 can call it on rows it fetched itself.
- `--expand` is a CLI concern: the CLI makes a second `Diff` call at `LINES` for the one file (`paths = [path]`) and filters hunks by the symbol's range; no new RPC.

## Out of scope

- Rename detection, symbol identity across moves between files, and semantic equivalence (a reformatted body is `changed`).
- Call sites beyond the `to` tree (other changes, other workspaces); R2.16's `changes_touching_symbol` answers "who else touched it".
- Merge commits' second parents, conflicted files, and submodules.
- Rendering in the web UI (R3.31) and the minimal check set (R3.18).
- Measuring real tokens with a model: R2.17.

## Risks

- **Name-based call sites over-approximate.** Two `area` functions in two files share callers from the tags source; the `kind`/`source` fields say which rows are resolved (`scip`) and which are by name. An agent that needs precision ingests a SCIP index; the fixture README says so.
- **The `to` tree walk per request.** On `large` it is the same cost R2.14 measured for `Lookup`; two agents asking for symbol diffs at once hold two read permits for that long. If the number from test 11 is bad, a per-commit `(path, blob)` cache in SQLite is the fix and a separate ticket.
- **Synchronous indexing inside a read.** A change touching 500 source files indexes 500 blobs before answering; bounded by `max_file_size` per file and by the one indexer thread, which also serves the hook. The response time is the cost of asking for symbols on a huge change; `--stat` is the cheap question.
- **Per-language parent conventions leak into the output.** A Go or Rust method has `parent = ''` from tags; the fixtures pin it and the README explains it, but a user comparing languages sees an inconsistency SCIP fixes. The vocabulary row in R2.14 and this brief's fixture README carry the explanation; a Reef-owned Rust query is the fallback R2.14 names.
