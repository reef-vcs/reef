# R2.15 Symbol-level diff

Phase 2 · Size L (the row said M; see "Size") · Depends on: R2.14 (the symbol index: entries per path and file content, digests, enclosing definitions, `ensure`, the name and symbol lookups), R2.02 (`GetDiff`, its paging, rename detection and hunks), R2.27 (`reef diff` and the CLI's JSON conventions), R2.13 (the MCP `get_diff` tool and the `tools/list` budget) · Unblocks: R2.17 (token-efficiency benchmark), R3.18 (minimal check set), R3.31 (proposal view)

## Context

The design says diffs "are available at the symbol level as well as the line level, which is both more useful to an agent and far cheaper in tokens than a unified diff" (`docs/design.md`, Query layer), and the review surface "defaults to a symbol-level summary with affected call sites and expands to lines on demand" (Interaction model). Phase 2's exit criterion is "symbol-level diffs work for Python, TypeScript, Go, and Rust". R2.14 built the index this reads: tags for six file types extracted by the daemon, uploaded SCIP checked by digest, entries keyed by path and file content, with each definition's range, enclosing definition and a body digest.

This ticket answers "what changed" in symbols. For a diff it reports, per file, which definitions were added, removed, changed or moved, and where the changed, removed and moved ones are referenced in the new tree. It says, per file, when it cannot answer, so a caller can fall back to lines. One symbol's lines can be asked for alone. It adds fields to `GetDiff`, `--symbols` and `--expand` to `reef diff`, and a `symbols` format and an `expand` input to the MCP `get_diff` tool.

R2.01's rule binds this brief: it adds and never changes. R2.02 left `GetDiff` room for exactly this: "R2.15 adds its symbol fields to `FileDiff` from 12 and to `GetDiffRequest` from 13", and `diff.proto`'s header says so. `API_REVISION` goes up by one (see "Schema").

## Decisions

### Size

L, not M. The work: five request and response fields with three enums and three messages; the whole-diff matching of definitions with renamed-file rewriting, moves and duplicates; per-definition line diffs for counts, nesting and expansion; call-site lookups with a new store query, since today's costs a second per common name on `large`; coverage per file; the handler's page and byte bounds; client JSON, CLI text, two CLI flags and the MCP tool; an ADR; 22 tests and a bench. Each part is small, but together they are the size of R2.02's diff work plus a store change, not an M.

### Where it lives in the API: fields on `GetDiff`, not a new RPC

- **`GetDiff` gains the symbol fields.** A symbol diff is a view of the same diff: the same two sides, the same paths filter, the same rename detection, the same pinned pages. A caller asking "what changed" gets files and symbols in one call, and files with no symbol answer stay in the same list, which is how R3.18 sees where the index is missing. A separate RPC would repeat the revision, paging and rename logic and still have to list uncovered files.
- **`symbols` is a flag beside `format`, not a fourth `DiffFormat`.** The two are independent: `SUMMARY` with symbols is the cheap view, `STAT` with symbols adds line counts, and `HUNKS` with `expand_symbols` is "expand to lines". `DiffFormat` keeps its meaning.
- **The new types live in `diff.proto`**, which imports `symbols.proto` for `SymbolKind`, `SymbolSource`, `SymbolSkipReason`, `SourceRange`, `SymbolOccurrence` and `SymbolIndexStatus`. buf's `FILE` rules make placement final, and these are diff concepts.
- `GetDiff` stays `ACCESS_READ` and `IDEMPOTENT`. Like `ListSymbols`, it may extract missing entries, which are derived and rebuilt on demand (ADR 0042, decision 7).

### What a symbol change is

- **Only files that differ are read.** A definition can only change if its file did. The work scales with the diff, not the tree.
- **Each file pair answers from one source.** SCIP when both sides that exist have a SCIP entry for their exact content (one side for an added or deleted file), else tags. Comparing a SCIP side with a tags side would show every symbol rewritten, so they are never mixed within a pair (R2.14, "What later tickets inherit"). `symbol_source` set to `TAGS` or `SCIP` forces one for every pair. A pair that cannot have the forced source is `NO_SCIP`.
- **Definitions are matched across the whole diff, by symbol string.** The old definitions of every differing file's old side are grouped by symbol string, as are the new side's. The match key is the symbol string, after one rewrite: a definition on the old side of a renamed file has the old path's components in its symbol replaced by the new path's (below). Matching is global rather than per file pair, so a Go method moved between files of one package, or a SCIP symbol whose identity is package-scoped (scip-go, rust-analyzer, scip-java), matches across files.
- **The rewrite for renamed files.** For a tags symbol, the leading namespace descriptors are the file's path components (the directory's for Go). They are replaced by the new path's. For a SCIP symbol, the rewrite applies when its descriptors hold a run of namespaces equal to the old path with some leading components `p` removed (an indexer run in a subdirectory), and the new path also starts with `p`. The run is replaced by the new path with `p` removed. Otherwise a SCIP symbol is left alone, which is right for package-scoped schemes. Copies are not rewritten. A copied file's definitions are new.
- **Pairing within one key.** Overloads, Python's conditional definitions and Go's build-tagged variants give one key several definitions. Old and new definitions of a key are paired in two rounds: first equal digests, in source order (path order, then position); then the rest, in source order. Removing the middle of three TypeScript overloads therefore shows that one `REMOVED`, not a `CHANGED` and a `REMOVED`.
- **The kinds:**
  - **`CHANGED`**: a pair whose digests differ.
  - **`MOVED`**: a pair whose digests are equal and whose files differ, other than by the file's own rename. Every definition of a renamed file is not a move.
  - **`ADDED`**, **`REMOVED`**: unpaired.
  - Equal digests in the same file, or in a renamed file, are not reported.
- **Moves under file-scoped identity.** Python, TypeScript and Rust tags, and scip-typescript and scip-python, put the file in the symbol. So a function moved from `a.py` to `b.py` has a new key. After matching, unpaired `REMOVED` and `ADDED` definitions are grouped by `(name, kind, digest)`. A group with exactly one of each becomes one `MOVED`, with `old_symbol` set. A move that also changed the body cannot be told from a removal and an addition under these schemes, and is reported as both.
- **Renamed symbols are not detected.** The digest covers the name, so a rename is a `REMOVED` and an `ADDED`. The removed one's call sites are the affected ones, which is the useful answer for checks (see "Out of scope").
- **Definitions without a digest.** A SCIP definition with no range (other languages, indexers that omit `enclosing_range`) can be added, removed or moved. It is `CHANGED` only when a changed line of its file pair touches its name's line. ADR 0043 records this as a limit.
- **Nesting.** A class whose method changed has a changed digest too. Both are reported, and the parent's `nested_only` is set when every changed line in its range, on both sides, lies inside a child definition's range. This makes "the class changed only in `parse`" readable, and R3.18 can skip the class's own callers. Changed lines come from the line diff of the two definition texts (below). The `enclosing_symbol` of each change lets a client nest them.
- **Line counts per symbol.** For a `CHANGED` pair, `lines_added` and `lines_removed` come from `diff_by_line` over the old definition's lines against the new one's, nested definitions included. For `ADDED` and `REMOVED` they are the range's line count. For `MOVED` they are 0.
- **Where a change is reported.** A change goes under the `FileDiff` of its new path, and a `REMOVED` one under its old path. `old_path` is set on a change whose old definition was in a file other than this file or this file's own `old_path`. Within a file, changes with a new side come in new-file order, then `REMOVED` ones in old-file order.
- **Parse errors.** A side whose tags entry has `has_errors` sets `parse_errors` on the file. Tags in the damaged part may be missing, so a definition there can show as removed. The file is still `COVERED`.

### Coverage: when the index cannot answer

Every `FileDiff` of a request with symbols carries a `coverage`, so R3.18 and an agent know per file whether the symbol answer is whole:

| Coverage | When | Changes |
| --- | --- | --- |
| `COVERED` | Each side that exists has an entry from the pair's source. A side that is not a supported language and has no SCIP counts as having no definitions, so `a.py` renamed to `a.txt` removes its symbols. | complete |
| `UNSUPPORTED` | Neither side is a supported file type, and neither has SCIP. Symlinks, submodules, directories and binary files with no language are here. | none |
| `SKIPPED` | A side was skipped (`skip_reason`: `TOO_LARGE`, `BINARY`, `PARSE_TIMEOUT`, `TOO_MANY_OCCURRENCES`, or `CONFLICTED` for a conflicted side, including a merged old side that does not resolve). | none |
| `NO_SCIP` | `symbol_source` is `SCIP` and a side has no SCIP entry. | none |
| `DIFF_TOO_LARGE` | More than 1,000 files differ (below). | none |

The response's `symbol_summary` counts the files by coverage and the changes by kind, over every page.

### Index readiness and cost bounds

- **At most 1,000 differing files.** Symbols are computed only when at most `RENAME_LIMIT` (1,000) files differ, the bound under which R2.02 detects renames. The two limits must be the same: matching across a renamed file needs the rename, and past the limit there are none. Past it, every `FileDiff` is `DIFF_TOO_LARGE`, `symbol_summary.diff_too_large` is set, and nothing is extracted. A narrower `paths` brings a large diff under the limit. A diff of over 1,000 files is a vendored import or a mechanical rewrite, where a symbol listing is not what anyone reads.
- **Both sides' entries are made inline.** Each differing file's entry on each side (by path and file id) is looked up, and missing ones are extracted with `extract_missing` on the index's threads. That is at most 1,000 files per side, the same bound as `ListSymbols`' inline path. With background indexing the new side is usually indexed already (a snapshot-first read queues its tree), and the old side is its parent's. A merged old side may hold content no commit has, and it is extracted like any other.
- **Matching runs over the whole diff on every page.** It needs only definitions and digests from the store, which costs milliseconds for 1,000 files, so it is not cached between pages. This is like R2.02, which walks the whole diff on every page to count `total_files`. The line diffs, nesting, call sites and expansion are done only for the page's own files. The bench `diff_paged` measures it, and open question 3 says when a cache is added.
- **The new tree must be indexed for call sites.** A name or symbol lookup needs the tree `COMPLETE` (R2.14). When a page has a change that needs a lookup, the handler calls `ensure(to_commit)` and waits up to 10 s in total per request. In the usual case it joins a running pass, which is incremental from the parent and takes milliseconds. Past 10 s the pass continues in the background, those changes are `INDEX_INCOMPLETE`, and `symbol_summary.to_index` says `INDEXING`. A caller that wants to wait longer calls `IndexSymbols` first. The old tree is never needed whole.
- **Never hold a read permit across the index.** The handler resolves and diffs inside `reads.run` as today. It extracts, waits for the pass and runs store queries outside, then takes `Reads::loaded` again for the blob reads of the per-symbol line diffs.

### Call sites

- **Which changes get lookups:** `CHANGED` (unless `nested_only`), `REMOVED` and `MOVED`. A moved symbol changes its import path, so its callers are affected. `ADDED` symbols have no callers outside the diff that predate it.
- **Where:** references in the new tree only. For a `REMOVED` symbol these are the references that still name it, which are likely broken. References in the old tree that the diff also removed are not affected.
- **How.** A SCIP change is looked up by its exact symbol in files whose source is SCIP, and by name in files whose source is tags. Each call site carries its `source`, so `SCIP` call sites are exact and `TAGS` ones are by name. A tags change is looked up by name in every file, with each file answering from its own source.
- **Name lookups are narrowed** by language family and by kind:
  - **Language family**: Python; TypeScript, TSX and JavaScript; Go; Rust. A changed Python function is not called from Go.
  - **Kinds**: a `FUNCTION` or `METHOD` definition matches `FUNCTION` references (calls). `CLASS`, `STRUCT`, `INTERFACE`, `ENUM` and `TYPE` match `CLASS`, `TYPE` and `INTERFACE` references. `MACRO` matches `MACRO`.
  - **No lookup**: a tags `FIELD`, `VARIABLE`, `CONSTANT` or `MODULE` has none, since tags record no such references. Its status is `NOT_TRACKED`.
  - **SCIP references** found by name are kept under the same kind rule, using the kind R2.14 normalized.
- **Ambiguity is reported, not hidden.** A change whose call sites came by name gets `name_definitions`: the number of definitions in the new tree with that name and a compatible kind, in the same family. More than one means some call sites may belong to another definition. Zero, for a `REMOVED` symbol, means no definition of the name remains.
- **Excluded:** references inside the changed definition's own new range, such as a recursive call. A call from a sibling definition is kept.
- **Each call site is a `SymbolOccurrence`** (R2.14's message): path, range and source, with `enclosing_symbol` the caller and SCIP's test flag where it applies. They come in path order, then by position.
- **Bounds.**
  - **Per change**: `max_call_sites` (unset means 10, 0 means no lookups at all, more than 100 is 100) are listed. `call_site_count` is the number found, counted up to 10,000 candidate rows. Past that the status is `CAPPED` and the count is a lower bound.
  - **Per page**: at most 1,000 changes get lookups. The rest are `PAGE_LIMIT`.
  - **The full list** is `ListSymbols` by symbol or by name, which pages.
- **The lookup is one query per page, reading rows, not files.** A new `Store::find_refs(keys, roles, limit_per_key)` takes every name and symbol the page needs. It selects only the hit rows and each hit's enclosing definition's symbol (a self-join on `(file, enclosing)`), stops at 10,000 rows per key, and returns them with their entry's path and file id. It never loads a whole file's occurrences. The tree check (`files::tree_file` per path) is cached for the request, across keys. `query::by_lookup` switches to the same row read, so `ListSymbols` by name gets faster too (the bench records it before and after). Pushing the tree filter itself into SQL stays R2.16's.

### Line-level on expand

- **`expand_symbols`** names symbols to show as lines. It needs `format: DIFF_FORMAT_HUNKS` and turns `symbols` on. The response then holds only the files with a change to one of them, and each such file's `hunks` are only those symbols' lines. Paging, `total_files` and the token work as for any diff.
- **What an entry matches.** An entry matches a change when it equals the change's `symbol`, its `old_symbol` or its `name`, or when it is a suffix of `symbol` that begins after a descriptor boundary (a space, `/`, `#`, `.` or `` ` ``). A final `.` may be left off. `Parser#parse()`, `Parser#parse().`, `parse` and the full string all match `` reef-tags . . . src/`parser.py`/Parser#parse(). ``. One entry may match several changes, and all of them expand. An entry that matches nothing contributes nothing, and is not an error, as a `paths` entry that names nothing is not.
- **The hunks.** For a `CHANGED` pair, the hunks are `unified_diff_hunks` of the old definition's lines against the new definition's lines, with `context_lines` (clipped to the definitions) and numbered in file lines, so they agree with the file's own diff over the same lines. An `ADDED` change gives one hunk of `+` lines. A `REMOVED` change gives one hunk of `-` lines, under the old path. A `MOVED` change has no lines. When an expanded change encloses another expanded one, only the outer one's hunks are given. `max_lines_per_file` and the 1 MiB cut apply as for any file. A change without a definition range has no hunks. `lines_added` and `lines_removed` stay the file's.
- **The CLI** shows the hunks as `reef diff` shows any hunks.

### Paging and bytes

- **A page still holds whole files and stops before 3 MiB.** A file's symbol changes count toward its size.
- **Per file at most 1,000 changes** are listed, with `truncated` set past that. The summary still counts them all.
- **An oversized file.** If a single `FileDiff` passes 3 MiB, its call sites are dropped from the last change backwards, and each such change's status becomes `PAGE_LIMIT`, until it fits. This keeps every response under tonic's 4 MiB.

### Errors and reasons

No new reasons.

| Reason | Kind | Metadata | When |
| --- | --- | --- | --- |
| `SYMBOLS_DISABLED` | `FAILED_PRECONDITION` | | `symbols` or `expand_symbols` with `[symbols] enabled = false`. A diff without them works as before. |
| `INVALID_SYMBOL_QUERY` | `INVALID_ARGUMENT` | `field` | `expand_symbols` with a format other than `HUNKS`, an empty entry, or more than 100 entries (`expand_symbols`); `max_call_sites` set without `symbols` or `expand_symbols` (`max_call_sites`); `symbol_source` set without them (`symbol_source`) |

`SYMBOLS_NOT_INDEXED` is never returned by `GetDiff`, because it degrades per file and per change instead. A symbol pass that fails is logged, its files become `SKIPPED` with no reason (`SYMBOL_SKIP_REASON_UNSPECIFIED`), and the diff is returned. The CLI's hint for `SYMBOLS_DISABLED` is R2.14's.

### Schema

`diff.proto` imports `reef/api/v1/symbols.proto`. `API_REVISION` becomes **8**, with the digest commented "R2.15: symbol-level diff fields in `diff.proto`". Every element gets its full leading comment when written (ADR 0029 checklist). The sketch:

```proto
message GetDiffRequest {
  // ... 1 to 12 as declared
  // Report each file's symbol changes and their call sites.
  bool symbols = 13;
  // Call sites listed per changed, removed or moved symbol: unset means
  // 10, 0 looks none up, more than 100 is 100. Needs `symbols` or
  // `expand_symbols`.
  optional uint32 max_call_sites = 14;
  // With DIFF_FORMAT_HUNKS: only files with a change to one of these
  // symbols, and only those symbols' hunks. Each is a symbol string, a
  // suffix of one from a descriptor boundary, or a display name; at most
  // 100. Implies `symbols`.
  repeated string expand_symbols = 15;
  // One source for every file pair; unspecified: SCIP when both sides have
  // it, else tags. Needs `symbols` or `expand_symbols`.
  SymbolSource symbol_source = 16;
}
message GetDiffResponse {
  // ... 1 to 6 as declared
  // Over every page; unset without `symbols`.
  SymbolDiffSummary symbol_summary = 7;
}
message FileDiff {
  // ... 1 to 11 as declared
  // Unset without `symbols`.
  FileSymbolDiff symbols = 12;
}
enum SymbolChangeKind { SYMBOL_CHANGE_KIND_UNSPECIFIED = 0; SYMBOL_CHANGE_KIND_ADDED = 1;
  SYMBOL_CHANGE_KIND_REMOVED = 2; SYMBOL_CHANGE_KIND_CHANGED = 3; SYMBOL_CHANGE_KIND_MOVED = 4; }
enum SymbolCoverage { SYMBOL_COVERAGE_UNSPECIFIED = 0; /* symbols not asked for */ SYMBOL_COVERAGE_COVERED = 1;
  SYMBOL_COVERAGE_UNSUPPORTED = 2; SYMBOL_COVERAGE_SKIPPED = 3; SYMBOL_COVERAGE_NO_SCIP = 4;
  SYMBOL_COVERAGE_DIFF_TOO_LARGE = 5; }
enum CallSiteStatus { CALL_SITE_STATUS_UNSPECIFIED = 0; /* not looked up: not asked, ADDED, nested only */
  CALL_SITE_STATUS_FOUND = 1; CALL_SITE_STATUS_CAPPED = 2; CALL_SITE_STATUS_NOT_TRACKED = 3;
  CALL_SITE_STATUS_INDEX_INCOMPLETE = 4; CALL_SITE_STATUS_PAGE_LIMIT = 5; }
message SymbolChange {
  SymbolChangeKind kind = 1;
  string symbol = 2;              // the new side's; the old side's when REMOVED
  string old_symbol = 3;          // the old side's when it differs: a renamed file, a move by digest
  string name = 4;
  SymbolKind symbol_kind = 5;
  string enclosing_symbol = 6;    // the innermost containing definition, on the side `symbol` is from
  string old_path = 7;            // the old definition's file when it is not this file or its old_path
  SourceRange old_range = 8;      // definition ranges; unset on the side that has none
  SourceRange new_range = 9;
  uint32 lines_added = 10;
  uint32 lines_removed = 11;
  bool nested_only = 12;
  CallSiteStatus call_site_status = 13;
  uint32 call_site_count = 14;    // counted up to 10,000 candidates
  repeated SymbolOccurrence call_sites = 15;
  uint32 name_definitions = 16;   // with call sites by name only
}
message FileSymbolDiff {
  SymbolCoverage coverage = 1;
  SymbolSkipReason skip_reason = 2; // with SKIPPED
  SymbolSource source = 3;          // the pair's, with COVERED
  bool parse_errors = 4;
  repeated SymbolChange changes = 5;
  bool truncated = 6;               // more than 1,000 changes
}
message SymbolDiffSummary {
  uint32 added = 1; uint32 removed = 2; uint32 changed = 3; uint32 moved = 4;
  uint32 files_covered = 5; uint32 files_unsupported = 6; uint32 files_skipped = 7; // SKIPPED and NO_SCIP
  bool diff_too_large = 8;
  SymbolIndexStatus to_index = 9;   // the new tree's, as call sites saw it; unset when none were looked up
}
```

`optional uint32 max_call_sites` is optional because zero is meaningful and distinct from the default (ADR 0029, decision 9). Counts are `uint32`, as `total_files` is. `GetDiff`'s "Errors:" paragraph gains the two reasons. `diff.proto`'s header line about R2.15 becomes a sentence describing the fields, which is a comment change.

### Where the code lives

- **`reef-symbols`**: `src/diff.rs` (new, pure). It has `rewrite_for_rename(symbol, old_path, new_path, go_scoped)`, `matches_expand(entry, change)`, and `match_definitions(old: &[SideDef], new: &[SideDef], renames) -> Vec<DefChange>`, which does the key grouping, the two pairing rounds and the move-by-digest round. No line diffing: that needs jj-lib's diff, which this crate must not link.
- **`reef_lib::jj::diff`**:
  - `FileDiffInfo` gains `old_file_id` and `new_file_id` (`Option<Vec<u8>>`, files and executables only).
  - `DiffOptions` gains `pairs: bool`. When it is set and at most `RENAME_LIMIT` files differ, `DiffPage.pairs` lists every differing file's `(path, old_path, kind, old file id, new file id, conflicted sides)` from the walk the page already does.

  - `src/symbols/diff.rs` (new): `symbol_diff(index, state, target, page, request) -> SymbolDiff`. It makes the inline entries, chooses the source per pair, matches, does the per-page line diffs, nesting and expansion, the call-site lookups, and the summary.

  - `src/service/diff.rs`: the request checks, the call, and the byte bounds. `src/service/convert.rs`: the messages.

### CLI

- **`reef diff --symbols`** sends `symbols: true` with `SUMMARY`, or with `STAT` when `--stat` is given too.
  - `--call-sites N` sets `max_call_sites` (default: unset, so 10; `0` for none).
  - `--source tags|scip` sets `symbol_source`, as `reef symbols list` does.
  - Both need `--symbols` or `--expand` (clap `requires`).
- **`reef diff --expand SYMBOL`**, repeatable, sends `HUNKS` with `expand_symbols`. It conflicts with `--summary`, `--stat` and `--symbols`. `--context` applies.
- **Text for `--symbols`.** Each file gets its summary line, as `--summary` prints it (`M src/parser.py`, `R old -> new`). Then its changes follow, two spaces in, plus two more per level when the enclosing symbol is also listed:

  ```text
  M src/parser.py
    ~ class Parser  +8 -2, in members
      ~ method Parser#parse()  +8 -2
          3 call sites: src/cli.py:41 in main(), src/api.py:88 in Handler#post(), and 1 more (by name, 2 definitions)
    + function tokenize()  +14
    - function legacy_parse()  -30
          1 call site: src/old.py:12 in run() (by name, no definition remains)
  A src/text/slug.py
    > function slugify()  moved from src/util.py
  M src/util.py
  M README.md  (no symbols: unsupported)
  4 files changed; symbols: 2 changed, 1 added, 1 removed, 1 moved
  ```

  - **Marks**: `+` added, `-` removed, `~` changed, `>` moved.
  - **Each change** shows the kind's name, the short symbol and the line counts (`, in members` when nested only).
  - **The short symbol** is the descriptors after the scheme, the package and any leading namespaces that spell the file's path or directory, with a final `.` dropped.
  - **The call-site line** shows up to three call sites (`path:line in caller`, 1-based), then `and N more`. It ends with `(exact)` when every call site is SCIP's, else `(by name, …)` with the definition count when it is not 1.
  - **Other statuses** print `call sites not tracked by tags for constants` (and so on per kind), `call sites pending: the index is being built`, or `call sites not looked up: page limit`.
  - **Files that are not covered** get a note after the summary line: `(no symbols: unsupported)`, `(no symbols: skipped, too large)` and so on.
  - **The last line** is the summary. With `--stat`, `| +A -R` follows each summary line.
- **Notes on stderr**, in both modes, unless `-q`:
  - **Pending call sites**: `reef: call sites are pending while <to_commit_id 12> is indexed; run reef symbols index -r <to_commit_id> to wait, then this command again` when any change is `INDEX_INCOMPLETE`.
  - **Too many files**: `reef: no symbols: more than 1,000 files differ; name paths to narrow the diff` when `diff_too_large`.
  - **No match**: `reef: no changed symbol matches <entry>` for an `--expand` entry that matched nothing. The command still exits 0, as R2.27's diff does with no differences.
- **JSON.** `Diff` gains `symbol_summary` and each `FileDiff` gains `symbols`, but only when they were asked for (`skip_serializing_if`). Plain `reef diff -o json` stays byte-identical to 0.2.0's. R2.27's "the shape never changes with the flag" was about `--stat` and `--summary`, which only empty fields. This is a different view, and adding keys to every plain diff would cost tokens in the case R2.17 measures as the baseline.
  - **Names**: `FileSymbolDiff` is `{coverage, skip_reason, source, parse_errors, changes, truncated}`, and `SymbolChange` has the message's field names. Enum values are lower snake (`changed`, `nested_only`, `found`, `index_incomplete`, `diff_too_large`). Ranges are R2.14's four-number arrays, and empty strings are `null`.
  - **Call sites are compact**: `{path, range, caller, source}`, plus `flags` when SCIP gave any. The other fields of `SymbolOccurrence` repeat the change's own name, kind and role.
- **Help.** `reef diff`'s `after_help` gains `reef diff --symbols` and `reef diff --expand Parser#parse`. Help texts stay within `help_text_is_short`. `reef guide` is unchanged: it is at its budget, and `reef diff --help` is where an agent finds a flag. `target/cli-shape-<os>.json` gains the three flags.

### MCP

- **`get_diff` gains `format: "symbols"`**, which sends `SUMMARY` with `symbols: true` and the default call sites, and **`expand`** (an array of strings), which sends `HUNKS` with `expand_symbols`. `expand` with `format` other than `hunks` or unset is the daemon's `INVALID_SYMBOL_QUERY`. The result is R2.27's `Diff` JSON with the keys above, plus `next_page_token`, as now. `max_call_sites` and `symbol_source` are not tool inputs. The defaults serve an agent, and `list_symbols` would be a new tool with no room for it.
- **The texts**, final wording the implementer's within the byte budget:
  - **Description**: "Show what a change changes against its parents, or between two revisions, a page of files at a time. Returns {from_commit_ids, to_commit_id, files, symbol_summary, next_page_token}."
  - **`format`**: "`hunks` (lines), `stat` (counts per file), `summary` (paths) or `symbols` (changed symbols and their call sites) [default: hunks]."
  - **`expand`**: "Only these symbols' hunks (symbol or name)."
  - **`max_lines_per_file`** is corrected to "[default: 1000]".
- **The budget rises from 20,000 to 20,250 bytes.** These texts take `tools/list` from 19,983 to about 20,147 bytes (measured by editing the installed server's output). The symbols view is the one Reef feature whose purpose is fewer tokens per answer. About 40 tokens per session for it is the trade R2.17 measures against what it saves. Trimming other tools' descriptions to pay for it would make them less clear for every agent. The test's constant and its comment say so, and the PR records the new size. Raising it again needs the same argument in that ticket's brief.
- **The same for every harness.** No harness is named and no behavior depends on which one connects. The tool's input and result are the CLI's.

## Out of scope

- Detecting renamed symbols (a removed and an added definition whose bodies match with the name masked). It needs a second digest per definition, which is a new extractor version and a re-index. It is a follow-up once R2.17 shows how often renames appear in agents' diffs.
- Moves that also change the body under file-scoped identities, and moves within a file (a definition reordered with the same bytes is not reported at all).
- Call sites in the old tree; transitive callers; references through aliases or re-exports that tags cannot see.
- `reef show --symbols`, symbol changes in `GetStatus`, symbol changes per operation or commit stored for queries (R2.16), the proposal view's rendering (R3.31), and choosing checks (R3.18).
- `ListSymbols` and `IndexSymbols` as MCP tools; SDK wrappers (R2.06 and R2.07 wrap the client).
- Pushing the tree filter into SQL for name lookups (R2.16).

## Risks

- **Tags call sites are by name** (the design's open risk). Common names over-match, and calls through aliases, `getattr`, interfaces or dynamic dispatch are missed. The answer says so per call site (`source`) and per change (`name_definitions`), and SCIP uploads make it exact. R3.18 must treat `TAGS` call sites as a hint, not a proof.
- **SCIP references can be stale for a reused entry** (ADR 0042's consequence). A SCIP entry for an unchanged caller file was resolved against its uploading revision. Call sites through it can name a symbol as it was there.
- **Moves by digest can pair the wrong two** when one function is deleted and an identical one added elsewhere for another reason. That is rare, and the answer, `MOVED`, is still true of the bytes.
- **Global matching costs every page.** Each page re-reads up to 2,000 entries' definitions. The `diff_paged` bench bounds it, and a cache is the remedy (open question 3).
- **A large `tools/list`.** Every session pays the 164 bytes, used or not. R2.17 measures whether it pays back.

## Choices this brief made, and why

- **Fields on `GetDiff`**: one call answers "what changed" in files and symbols, uncovered files stay visible, and paging, renames and pinning are reused.
- **Global matching by symbol string**: package-scoped identities (Go, SCIP for most languages) match across files without heuristics, and renamed files need only a rewrite.
- **The 1,000-file limit equals the rename limit**: matching across renamed files needs the rename, and the two limits failing together is easier to explain than two thresholds.
- **One source per file pair**: comparing SCIP with tags would rewrite every symbol.
- **Reporting nested changes with `nested_only`**: a parent's digest does change, and hiding it would lose the parent's own edits, while the flag keeps R3.18 from over-selecting.
- **Call sites in the new tree only**: the question is what still depends on the changed code.
- **A row-level reference query now**: call sites at today's lookup cost would make the feature unusable on large repositories, and the fix is local to the store.
- **Expansion by diffing definitions**: the lines are exactly the symbol's, numbered as the file's diff numbers them, without the file's other hunks.
- **Plain JSON unchanged**: R2.17's baseline and existing consumers read `reef diff` as it is.
- **Raising the MCP budget by 250 bytes**: the symbols view is what the budget exists to make room for.

## What later tickets inherit

- **R2.17** measures "what changed" through `reef diff --symbols` and the MCP `get_diff` tool's `symbols` format against git porcelain, starting from this PR's byte comparison.
- **R3.18** reads `FileSymbolDiff.coverage` and falls back to the full check set for any file that is not `COVERED`, and whenever `diff_too_large` is set. It takes `CHANGED` (not `nested_only`), `REMOVED` and `MOVED` symbols and their call sites as the affected set, weighs `TAGS` call sites as approximate, and pages `ListSymbols` for symbols whose call sites are `CAPPED` or `PAGE_LIMIT`.
- **R3.31** renders `symbol_summary` and each file's changes, nested by `enclosing_symbol`, and expands one with `expand_symbols`.
- **R2.16** can push the tree filter of `find_refs` into SQL, and owns any stored history of symbol changes.
- **R2.06 and R2.07** wrap the new request fields and messages.

## Open questions

1. **The default number of call sites.** 10 per change is a guess at what an agent needs to judge impact. R2.17's measurement may show 3 or 0 is better for tokens in the common case. Changing the default is a comment change and a CHANGELOG line, not a schema change.
2. **Whether `reef diff` should default to `--symbols` for agents** (JSON output, or no terminal). This ticket keeps the default unchanged. R2.17 decides from its numbers, and a change would be its own CHANGELOG entry under ADR 0025's additive rule.
3. **A cache of the whole-diff match between pages.** If `diff_paged` is more than 200 ms over a plain page of the same diff, the implementer adds an LRU of 8 matches keyed by the two tree keys, `paths` and `symbol_source`, and records the before and after in the PR. Otherwise no cache.
4. **The budget.** If the implementer finds the same bytes by tightening `get_diff`'s own texts without losing meaning, the budget stays at 20,000, and the budget clause of this ticket's departure is removed from `README.md` and `dev-phases.md`.
