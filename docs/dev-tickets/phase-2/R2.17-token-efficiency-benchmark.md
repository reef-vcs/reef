# R2.17 Token-efficiency benchmark

Phase 2 · Size M (the row said S; see "Size") · Depends on: RX.07 (the harness: trial isolation, the agent runner, the stream parser, pins, the results-PR workflow), R2.15 (`reef diff --symbols` and the MCP `get_diff` symbols format, for "what changed"), R2.16 (`reef history` and the MCP `query_changes` tool, for "who touched this"), and through them R2.27 (`reef status`, `log`, `show`, `diff`) and R2.13 (`reef mcp` and its `tools/list`) · Unblocks: Phase 2's exit criterion on the token cost of "what is the state of this repo"; the follow-up issues its numbers decide (see "What this ticket decides for earlier tickets")

## Context

The design treats tokens as a performance metric: "A unified diff that costs 40k tokens to read is slow regardless of how fast it computed" (`docs/design.md`, Principles). Phase 2 built the surfaces that are supposed to cut that cost: a typed CLI with JSON for every message (R2.27), an MCP server (R2.13), symbol-level diffs (R2.15) and a query layer over history (R2.16). Each of those briefs left the proof to this ticket, and Phase 2's exit criteria include: "Token cost to answer 'what is the state of this repo' is measured and at least five times lower than parsing git output."

This ticket measures what it costs an agent that already knows Reef to answer six standard questions about a repository where several agents are working: its own state, the repository's state, what an agent's work changed (a small change and a large one), and who touched a file and a function. It measures the same questions answered with git porcelain, the Reef CLI, and the Reef MCP server, in two ways. A scripted part runs fixed command sequences against a fixture and counts their text in bytes and in two vendors' tokenizers. A live part runs real agents headless on RX.07's harness, grades their answers against ground truth, and counts what they actually read and paid. It publishes both beside RX.07's results page, through a workflow that runs only when dispatched.

It changes nothing in Reef itself. Findings that call for a change (a terser JSON field, a different default) become follow-up issues with the numbers attached, so the PR that measures is never the PR that tunes.

## Decisions

### Size

M, not S. The work:

- Moving RX.07's runner, isolation, scrubbing and table code into a shared module, with onboarding's behavior unchanged.
- A harness adapter seam, with Claude Code moved onto it as its only adapter.
- A fixture builder that replays Reef's own history twice, once for git and once for Reef.
- Six questions, each with ground truth and a grader.
- Scripted sequences with a sufficiency check.
- A minimal MCP client.
- Three counters, one of them a feature-gated dependency and one a network call.
- A results page, a workflow and tests.

RX.07 was M, and most of its machinery is reused. Nothing in the daemon, the CLI, the API or the MCP server changes, so it is not L. With the second harness out of scope (decided by the user 2026-10-30), it is still not S. The bulk was never the second adapter. It is the fixture built twice with its ground truth, the grader, the scripted candidates with their sufficiency check, the MCP client, and three counters, and each of those is a real part. Dropping Codex takes it from the top of M to the middle. It is not split. Without the live part, the numbers describe an idealized agent. Without the scripted part, they cannot be reproduced and are tied to one vendor's billing.

### What is measured: answer tokens

- **Answer tokens** are the tokens that enter an agent's context because of the question: the text of every tool call it makes (a shell command line, or an MCP call's arguments) plus the text of every result it reads. They exclude the harness's own system prompt and tool definitions, which every arm pays alike. They exclude the agent's reasoning and output, which are reported apart.
- **A fixed cost per session** is reported apart from answer tokens. It covers the MCP server's `tools/list` result and its `initialize` instructions, which every session that loads the server pays whether it calls a tool or not (ADR 0035). Where the harness's stream reports per-request usage, the first request's input tokens are also reported, as each arm's session overhead.
- **Billed usage** comes from the harness: input, cache creation, cache read and output tokens, turns, and cost. It is what an operator pays. It includes everything above and grows with the number of turns, because each turn rereads the context.
- **A count for a wrong answer is not a measurement.** Medians are taken over correct trials only (see "Grading").

### Two parts, and why both

- **The scripted part** runs, for each question and arm, fixed sequences of commands or MCP calls (candidates) against the fixture, and counts each step's call text and output. It is deterministic, needs no model, and costs nothing beyond Anthropic's free token counting. Its numbers can be reproduced on a laptop and compared across Reef commits. It measures what a competent agent that already knows the best commands would pay. It is the steelman for each arm, git included.
- **The live part** runs real agents on the same fixture and questions, three trials each, and grades their answers. It measures what agents actually do: whether they find `reef history` (which `reef guide` does not mention), whether they pass `-o text`, whether they read `--help` first, and whether they get the answer right. It costs money and varies between runs and model versions.
- **Each would mislead alone.** The scripted part cannot see that agents miss the cheap command, and the live part cannot separate Reef's output from an agent's habits.

### The fixture

One logical repository is built twice, from objects in the Reef checkout the harness runs in. No network is needed for the repository, and the workflow checks out with `fetch-depth: 0`. The commits are pinned in `crates/reef-testing/tokens/scenario.toml`. If they are missing (a shallow clone, or a rewritten `main`), setup fails, and the error names the missing commit.

- **History, identical in both copies.**
  - **The import** is one orphan root commit holding `b5741e8f`'s tree, authored `import <import@fixture.invalid>`. It has the subject "Initial import", and its time is the time of the build.
  - **Every agent and harness configuration file is removed from that tree**: `AGENTS.md`, `CLAUDE.md`, `.claude/`, `.cursor/`, `.codex/` and `.mcp.json`. The list lives in `scenario.toml`. With them gone, no arm and no harness starts with project instructions, and Reef's own instructions to agents do not leak into the git arm. Session diffs drop those paths too.
  - **The landed sessions** are three commits on `main`, applied in order. Each one is authored `bot-N <bot-N@agents.invalid>`, carries the original commit's subject, and holds that commit's diff:

    | Session | Agent | From | Size |
    | --- | --- | --- | --- |
    | L1 | `bot-1` | `a4fb5b5a` | 1 file |
    | L2 | `bot-2` | `74ebfcb4` | 52 files |
    | L3 | `bot-3` | `b68578b7` | 1 file |

- **Work in progress**, on `main` after L3:

  | Session | Agent | Content | Size |
  | --- | --- | --- | --- |
  | P1 | `bot-4` | `f4e34d3d`'s diff | 4 files, small |
  | P2 | `bot-5` | `79ad4548`'s diff | 59 files, 14 of them new, large |
  | self | `bot-0` | `tokens/patches/self.patch`, written for this ticket against L3's tree | one file modified, one added, one deleted |

  The trial's agent works in `bot-0`'s checkout.
- **The git copy.** A plain git repository with that history. Each work-in-progress session is a `git worktree add -b agent/bot-N <root>/worktrees/bot-N main` with the session's diff applied and left uncommitted, so its new files are untracked, as an agent's unfinished work in a worktree is. There is no `.jj`, and no `reef` is on the arm's `PATH`.
- **The Reef copy.** The same history in a second repository, registered with `reef repo register`. Each work-in-progress session is `reef --agent bot-N ws create --owner bot-N --new-on main`, with the diff applied in the workspace directory (`git apply` run there) and then `reef ws snapshot`. The landed commits reach Reef through the registration's import, so their changes are `LANDED`. Their history rows have no agent and keep the author email `bot-N@agents.invalid` (R2.16: imported changes within `[history] retention` get rows, dated by committer time). That is why the import and landed commits are dated at build time: commits dated in the past would fall out of the 90-day retention and silently change the truth.
- **Settled before any trial.** The harness polls `reef history -o json --limit 1` until `coverage.backfilling` is false and `pending` and `behind` are 0, and until `reef diff -r <bot-5's change> --symbols -o json` reports every Rust file covered. The limit is 5 minutes, after which setup fails.
- **Built once per run and arm family, and checked around every trial.** A fingerprint is taken before and after each trial and each scripted run:
  - git: each worktree's `git status --porcelain=v1 -uall` and `git rev-parse main`;
  - Reef: each workspace's working-copy tree id from `reef status --workspace <id> --no-snapshot -o json`, and `main`'s commit.

  A trial that changed the fingerprint is marked `mutated`, kept out of the medians, and the fixture is rebuilt before the next trial. Fixture workspaces are created with a 24-hour lease (`reef ws create --lease 24h`), longer than any run, so no renewal is needed; a lapsed or reclaimed workspace changes the fingerprint and the trial counts as mutated.
- **Ids are random, so truth never uses them.** Change ids, workspace ids and, because of build-time dates, commit ids differ between builds. Questions and truth name agents, paths, symbols and subjects only. The fixture's version is `scenario.toml`'s digest together with the pinned commits, and every row records it.

### The questions

Six questions. Every prompt starts with the same two sentences: "Several agents work in this repository at the same time, each in its own checkout, and agents are named like `bot-1`. You are in yours." Then it gives the arm's tool sentence (below), the question, "Do not change any files.", and the answer format. The prompts live in `crates/reef-testing/tokens/prompts/<id>.txt` and are versioned. Changing one starts a new baseline.

| Id | Question | Answer line | Truth (the implementer computes and records it in `scenario.toml`) |
| --- | --- | --- | --- |
| `state-own` | Which files have you changed so far, and what is the first line of the description of the commit your work is based on? | `ANSWER: <A\|M\|D> <path>; ... \| base: <first line>` | The self patch's three paths and statuses; L3's subject. |
| `state-repo` | Which other agents have work in this repository that is not on `main` yet, and how many files has each of them changed? | `ANSWER: <agent> <count>; ...` | `bot-4 4; bot-5 59` (counted as `git diff --name-only` counts, with no renames in either session). |
| `changed-small` | Which functions and methods (test functions included) did `bot-4`'s work in progress add, remove or change? Ignore files that are not code. | `ANSWER: added <names>; removed <names>; changed <names>`, with `-` for none | From P1's Rust files. |
| `changed-large` | The same, for `bot-5`'s work, in `crates/reef-daemon/src/symbols/` only. | as above | From P2's files under that directory: 10 functions and methods across `query.rs` and `store.rs`. Asking for functions and methods only (not types, fields, constants, macros or modules) keeps the truth under 15 names without narrowing to one file. |
| `who-file` | Which agents have changed `crates/reef-client/src/json.rs`, on `main` or in work in progress, not counting the initial import? For each, is its change on `main`? | `ANSWER: <agent> landed\|open; ...` | `bot-2 landed; bot-4 open; bot-5 open` |
| `who-symbol` | The same, for the function `by_lookup` in `crates/reef-daemon/src/symbols/query.rs`. | as above | `bot-2 landed; bot-5 open`, confirmed by definition matching rather than hunk headers |

- **Why these six.** They are the row's three questions (state, what changed, who touched this), with each one split where the split changes the answer's cost:
  - **Own state against the repository's state.** Git answers its own checkout's state cheaply, and the design's case is the repository with many agents in it.
  - **A small diff against a large one.** The symbols view's value grows with the size of the diff.
  - **A file against a symbol.** R2.16 measured both.
- **`state-repo` is the exit criterion's question.** "The state of this repo" in a repository with several agents is who has work in flight and how much. Git answers it by enumerating worktrees and asking each one.
- **The truth is computed independently of Reef, then cross-checked.**
  - **Agents, paths, counts and outcomes** come from the git copy: `git diff --name-status`, `git log` and the worktrees.
  - **Symbol names** are written by hand from the diffs, then checked against `reef diff --symbols` on the Reef copy. A disagreement is settled by reading the code, and the decision is recorded in `scenario.toml` with a comment.
  - **`self.patch`** is chosen so the truth is unambiguous: no renames, and no file under a directory that is otherwise empty.

### Grading

- **The answer line.** The grader reads the last line of the final answer that starts with `ANSWER:`, after stripping Markdown emphasis and backquotes. No such line means incorrect.
- **Normalization.**
  - Case and surrounding whitespace are ignored.
  - Paths lose a leading `./`.
  - Symbol names reduce to their last segment after `::`, `.` or `#`, without `()` or generic parameters, so `Current::holds`, `holds()` and `holds` match.
  - Outcomes accept `landed` or `main`, and `open` or `in progress`.
  - A subject matches with or without a trailing ` (#NNN)`.
- **Correct means exact.**
  - **Exact sets**: `state-own`'s (status, path) pairs, `state-repo`'s (agent, count) pairs, and `who-*`'s (agent, outcome) pairs.
  - **The base subject** must match.
  - **For `changed-*`**, the union of names must equal the truth's union. Per-category accuracy (added, removed, changed) is reported but not required, since "moved" and "changed" are honest disagreements.
- **Every trial's JSON also records precision and recall** over its names, so near misses are visible.
- **Medians are over correct trials only.** A cell with fewer than two correct trials out of three shows `—` and the correct count, and that arm is "not answered reliably" for that question.

### The arms

| Arm | What the agent has | Tool sentence in the prompt |
| --- | --- | --- |
| `git` | A shell (and the harness's file reader) in `bot-0`'s worktree of the git copy; no `reef` on `PATH` (RX.07's `agent_path` shadowing) | "Answer with git." |
| `reef` | A shell (and the file reader) in `bot-0`'s workspace of the Reef copy; `reef` and `reef-daemon` on `PATH` | "Answer with the `reef` command." |
| `mcp` | `reef mcp` started in `bot-0`'s workspace, and no built-in tools where the harness allows that | "Answer with the reef tools." |

- **Symbol-level diff and the query layer are not separate arms.** An agent chooses its commands, and an arm that forced `--symbols` would measure the prompt. Inside the `reef` and `mcp` arms the agent may use any view.
- **Separate views are separate scripted candidates.** Plain `reef diff` (ADR 0043's unchanged baseline) sits against `--symbols`, and `reef history` against `reef op log`, so each view's cost is visible.
- **Escapes are counted.** In the `reef` arm, a shell call running `git` is recorded as `escaped_to_git`. In the `mcp` arm, any shell call, where the harness could not disable the shell, is recorded as `escaped_to_shell`. RX.07's command splitter decides what a call ran. An escape does not fail a trial: the answer is graded and the escape is shown.

### The scripted part

- **Steps.** Each candidate is a list of steps. A step is one shell command line or one MCP tool call, and its whole output enters the count. Pipes into `grep`, `awk`, `jq`, `head` or `wc`, and shell loops, are not allowed in candidates, because an agent cannot filter output whose format it has not seen.
- **Expansion from the fixture.** A step that needs a value an earlier step printed (a worktree path, a workspace id, a change id) uses a placeholder (`{wt:bot-4}`, `{ws:bot-4}`, `{change:bot-4}`) that the harness fills from the fixture, as if the agent had read it. A per-item step (for each worktree, for each workspace) is expanded into one step per item, and each one is counted.
- **Several candidates per arm, cheapest sufficient wins.** `scenario.toml` lists candidates for each (question, arm). The harness runs them all, counts them all, and reports as the arm's number the cheapest candidate that passes the sufficiency check. The first set, which the implementer may add to but never thin out:
  - **git**:
    - `state-own`: `git status --porcelain=v1 -uall` then `git log -1 --format=%s`; also plain `git status` with `git log -1`.
    - `state-repo`: `git worktree list`, then per worktree `git -C {wt} status --porcelain=v1 -uall`.
    - `changed-*`: `git worktree list`, then `git -C {wt} diff` with `-U0`, the default context, or `--function-context`, plus `git -C {wt} status --porcelain -uall` for the new files, and their contents read where a new file's definitions count.
    - `who-file`: `git log --format='%an %s' main -- <path>`, then `git worktree list` and per worktree `git -C {wt} status --porcelain -- <path>`.
    - `who-symbol`: `git log -L :by_lookup:<path> main` with and without `-s`/`--no-patch` and `--format`, then per worktree `git -C {wt} diff --function-context -- <path>`.
  - **reef**, each with the default output (JSON in a pipe) and with `-o text`:
    - `state-own`: `reef status`.
    - `state-repo`: `reef ws list`, then per workspace `reef status --workspace {ws}` with the default list and with `--max-files 1` (`0` means the default of 100, so 1 is the least that still carries `changed_file_count`), and `reef diff -r {change} --summary`; also `reef status` at the root.
    - `changed-*`: `reef ws list`, then `reef diff -r {change}` (plain, the R2.15 baseline), `--stat`, `--symbols`, and `--symbols --call-sites 0` and `3`, each with the question's path for `changed-large`.
    - `who-file`: `reef history <path>`.
    - `who-symbol`: `reef history --symbol by_lookup`, and `reef history --symbol by_lookup crates/reef-daemon/src/symbols/query.rs`.
  - **mcp**:
    - `state-own`: `get_status`.
    - `state-repo`: `list_workspaces`, then per workspace `get_status`.
    - `changed-*`: `list_workspaces` then `get_diff` with `format: summary`, `hunks` and `symbols`.
    - `who-*`: `query_changes` with `paths`, and with `symbols` (with and without `paths`).
- **Sufficiency check.** A candidate is sufficient when every name in the question's truth appears in its concatenated output: agent names, paths, symbol names and the base subject. Counts and outcomes are not checked mechanically. So the PR lists every arm's chosen candidate and the reviewer confirms by reading its saved output that an agent could answer from it. A candidate that cannot answer is marked `insufficient = true` in `scenario.toml`, with the reason.
- **The arm numbers on the page.**
  - **git** is git's cheapest sufficient candidate: the steelman.
  - **reef (default)** is the cheapest sufficient candidate without `-o text`, which is what an agent's shell gets unless told otherwise. **reef (text)** is the cheapest one with it.
  - **mcp** is the cheapest sufficient tool sequence. Its fixed cost is shown beside it, and one figure includes the fixed cost.
- **The diff sweep, R2.15's comparison.** For each of the last 20 commits of `main` before the pinned base, the harness records the bytes and tokens of `git show --format= <c>`, `git show --stat`, `reef diff -r <c>`, `--stat`, `--symbols` and `--symbols -o text`, together with the median ratio of `--symbols` to `reef diff`. These run in a scratch registered clone of the checkout. They answer R2.15's question of how big the symbols view is against the unified diff across ordinary commits, and they have their own table.

### What is counted, and with which tokenizers

- **The text of a step.** For a shell call, the command line plus its stdout and stderr, which is what a shell tool returns. For an MCP call, the arguments as compact JSON plus the result's `content` text blocks, which is what clients put in context. `structuredContent` is counted and reported apart, so the number is visible if a harness forwards both.
- **Three counters, all reported. None of them alone decides anything.**
  - **`bytes`**: UTF-8 bytes. Vendor-neutral and free.
  - **`anthropic`**: Anthropic's token counting endpoint for the pinned Claude model. Each text is sent as one user message, with the count of a one-character message subtracted. Each distinct text is counted once and cached by digest in the results directory. The harness calls the endpoint with `curl`, the key passed through a `--config` read from stdin so it never appears in a process's arguments. Requests go one at a time, and a 429 is retried after its `retry-after`. The counter is skipped, and says so, without `ANTHROPIC_API_KEY`. The MCP fixed cost is counted as the model sees it: the count with the server's tools (name, description, input schema) minus the count without.
  - **`o200k`**: OpenAI's `o200k_base` encoding, through the `tiktoken-rs` crate. It is a published BPE from a second vendor, runs offline with no key, and is deterministic. So the scripted numbers can be reproduced anywhere, and no single vendor's tokenizer decides the ratios. The implementer records the crate's version in each row, so a change of encoding starts a new baseline.
- **The dependency is feature-gated.** `tiktoken-rs` sits behind a `tokenizers` feature of `reef-testing`, off by default. Crates that dev-depend on `reef-testing`, and the ordinary CI matrix, never build it. ADR 0025 rejected a tokenizer dependency to budget `reef guide` in a unit test, because of build weight; this one is built only by the benchmark. `cargo deny` must pass with the feature on.
- **Why two vendors and bytes.** The ratio between two outputs depends on the tokenizer. JSON with hex ids tokenizes worse than prose. Counting with one vendor's tokenizer would make that vendor's model the benchmark's reference, which the north star forbids (see "Agent-agnostic"). Bytes need no vendor at all.

### The live part

- **Adapters.** A `Harness` trait in `reef-testing/src/agent/harness/` has one implementation per harness. It turns (arm, prompt, model, trial directory) into an argv and an environment, and a stream into the common `Transcript`: tool calls with name, input text, result text and error flag, the final text, per-request usage where the stream has it, totals, turns, cost, harness version and model. Everything else is harness-blind: fixture, grading, counting, reporting.
- **Claude Code**, the existing parser extended to keep each tool call's input and result text and the first assistant event's usage. Every arm runs with `--bare`, `--output-format stream-json --verbose`, `--model`, `--permission-prompts none`, `--max-budget-usd 1` and `--no-session-persistence`. Per arm:
  - `git` and `reef`: `--tools Bash,Read --allowedTools Bash,Read`.
  - `mcp`: `--tools ""`, `--mcp-config <file>` naming `<bin>/reef mcp`, `--strict-mcp-config`, and the reef server's tools allowed by Claude Code's server-prefix rule. The implementer checks that `--tools ""` leaves MCP tools available. If it does not, the shell stays and escapes are counted.
- **One harness ships.** Claude Code is the only adapter in this ticket (decided by the user 2026-10-30). The seam is there so a second harness is one adapter and a recorded stream, with nothing else changing (see "Out of scope").
- **Trials.** Three per (question, arm): 54 per run. Trials run one at a time. The timeout is 5 minutes, after which a trial fails. A trial whose setup failed, or that never reached the model, is a setup failure and is kept out, as in RX.07.
- **Pins.** Each row records the harness version, the model, the Reef commit, the OS and the fixture version.
  - **Claude Code** is pinned in `tokens.yml` to the same version as `onboarding.yml`, and the two move together.
  - **The Claude model** is `REEF_TOKENS_MODEL`, default `claude-sonnet-5-5` like RX.07's.
  - **A new pin, prompt, fixture or question starts a new baseline.**
- **Cost.**
  - **Expected.** RX.07's trials cost $0.01 to $0.04 on the same model. These read more: `changed-large` and git's `who-symbol` can read 20 to 100 KB of diff, and cache rereads make each turn cost. Expect $0.02 to $0.15 a trial, about $2 to $8 for a full Claude Code run of 54 trials.
  - **Cap.** `--max-budget-usd 1` caps a trial, so a full run cannot exceed $54. A trial that hits the cap is a failure.
  - **The scripted part** costs nothing: counting is free, and `o200k` is offline.
  - **Total.** A full run is expected under $10. Dispatched a few times a phase, that is well under RX.07's estimate of $100 a month.

### Agent-agnostic

The project's north star: no harness gets special treatment in prompts, docs or code beyond thin adapters, and a result from one harness is a gap to note, not a proof.

- **Prompts name no harness, vendor or model.** The tool sentences name only the tool under test (`git`, the `reef` command, the reef tools), and are identical across harnesses. A unit test fails if a prompt contains `claude`, `codex`, `cursor`, `opencode`, `gemini`, `anthropic`, `openai` or `gpt`, in any case.
- **Every arm starts without project instructions.** The fixture strips every harness's configuration files, and every adapter runs its harness without user or project configuration (`--bare` for Claude Code). No arm gets `reef init`'s files. What RX.07's scenario B measures is not this ticket's question, and those files differ per harness.
- **Harness code stays in the adapters.** Argv, environment, stream parsing and the name of the MCP permission rule live in `agent/harness/<name>.rs`. Nothing else branches on the harness.
- **Counting is not one vendor's.** Bytes and two vendors' tokenizers are always reported, and the exit criterion must hold under all three (below).
- **Results say which harness they hold for.** Live rows are per harness. The page has a "Harnesses measured" line, and each conclusion names the harnesses it held for. Harnesses are named only as row labels and in that line, never in the method's instructions.
- **One harness is a gap, not a proof.** This ticket measures Claude Code only. The page's "Harnesses measured" line and the PR both say "one harness: a gap, not a proof", and so does the exit criterion's verdict in `dev-phases.md`. The PR files a follow-up issue for a second harness: Codex first, which needs an OpenAI key and a repository secret. That harness is one adapter in `agent/harness/` and a recorded stream.

### Phase 2's exit criterion

"Token cost to answer 'what is the state of this repo' is measured and at least five times lower than parsing git output" is evaluated on `state-repo`. It is met when both of these hold:

1. **Scripted.** For some Reef arm, its cost is at most one fifth of git's under every counter reported (`bytes`, `anthropic`, `o200k`). That arm is either `reef (default)`, the output an agent gets unasked, or `mcp` with its fixed cost added once. `reef (text)` is reported beside them but does not count: agents get JSON unless told otherwise, and the claim is about what they get.
2. **Live.** In every harness measured (in this ticket, Claude Code alone), the same arm's median answer tokens are at most one fifth of the `git` arm's, both with at least two correct trials out of three.

**Both halves are required (decided by the user 2026-10-30).** If the scripted ratio holds and the live one misses only because agents do not find the cheap command (for example, they never pass `--max-files 1`), the verdict is "not met". The follow-up issue is then about discoverability (`reef guide`, `--help`), not output size.

The verdict, with its numbers, goes into `dev-phases.md`'s exit criterion bullet in the results PR, as R2.22 recorded its own: "(measured by R2.17 on `state-repo`: N× by bytes, …; `token-benchmark.md`)", or, when not met, "not met: … (R2.17)" with the issue that tracks the gap. The verification above suggests `reef status` JSON spends most of its bytes on `heads`. If the criterion is not met, the PR files an issue with the per-field breakdown below. Meeting it is that issue's work, and this one re-measures by dispatch.

**Where the bytes go.** For every JSON output a scripted candidate produces, the harness also records bytes per top-level field, and per field one level down. The page shows the breakdown for `state-repo`'s and `state-own`'s Reef candidates, so a follow-up knows what to cut.

In the unit tests of `crates/reef-testing/src/tokens/`:

3. `answers_grade`: for each of the six question kinds:
   - the truth answer is correct;
   - a missing name, an extra name, a wrong count and a wrong outcome are each incorrect, with precision and recall recorded;
   - `**ANSWER:**`, backquoted names, `Current::holds()` against `holds`, `in progress` against `open`, and a subject with ` (#112)` all grade as intended;
   - with no `ANSWER:` line, the trial is incorrect;
   - when there are two `ANSWER:` lines, the last one counts.
4. `sufficiency`: a candidate whose output lacks one truth name is insufficient. The cheapest sufficient candidate is chosen even when a cheaper one is insufficient. `insufficient = true` in the scenario overrides the check.
5. `expansion`: placeholders fill from a fixture description. Per-item steps expand once per item, in a stable order. An unknown placeholder fails the scenario's validation.
6. `counters`:
   - `Bytes` counts UTF-8 bytes.
   - `O200k` gives known counts for known strings (with `tokenizers`).

7. `field_breakdown`: a JSON output's bytes are attributed to top-level fields and one level down, and the shares sum to the whole.
8. `medians_and_gate`:
   - Medians are over correct trials only. A cell with fewer than 2 of 3 correct trials is `—`.
   - The gate fails when any counter's ratio is under 5, or when the live median of a harness is missing or under 5. It passes when all hold.
   - `mcp` is gated with its fixed cost added. `reef (text)` never satisfies it.
9. `rows_insert`: rows land at their markers. Reinserting the same run's rows does not duplicate them. A missing marker is an error that names it.
10. `scenario_valid`:

## Implementation notes

- **Order:**
  1. Move the shared code into `agent/`, behind the `Harness` trait, with onboarding unchanged (tests 1, 2, 12).
  2. Write `scenario.toml`, `self.patch` and the prompts (test 10).
  3. Build the fixture and fix the truth (test 11).
  4. The scripted part, counters and breakdown (tests 4 to 7).
  5. Grading and the live part (test 3).
  6. The report, page and workflow (tests 8 and 9).
  7. A local scripted run.
  8. One live trial per arm locally.
  9. Dispatch.
- Check `df -h` before the first build. The disk has filled from `target/` before.
- **Run `crate_graph` outside a Reef workspace.** A shared target directory bakes stale paths into it.
- **Do not tune Reef in this PR.** If a number looks wrong because of a Reef bug, file it and say so in the PR. Fixing it here would leave the benchmark without a before.
- **Save every scripted step's output in the results.** The reviewer reads them to confirm sufficiency, and a follow-up reads them to see what to cut.
- **What the agent saw is what counts.** Claude Code truncates long tool output. Count the result text in the stream, not the command's full output, and note truncations in the trial JSON.
- **Leases.** Fixture workspaces must not lapse during a run: they are created with a 24-hour lease. A lapsed or reclaimed workspace changes the fingerprint, so the trial counts as mutated, is left out, and the fixture is rebuilt.
- **The daemon.** The fixture's daemon runs under the fixture's `REEF_STATE_DIR` and is stopped at the end of the run (`reef daemon stop`), with `--keep` keeping the directories, as RX.07's `finish` does.
- **Local runs** isolate as RX.07's do, and have the same caveat: the agent has an unrestricted shell on your machine.

## Risks

- **The baseline rests on Reef's own history.** `main` was force-pushed once (2026-10-25). If a pinned commit disappears, setup fails loudly, and re-pinning is a new fixture version and a new baseline. The commits are also referenced in `scenario.toml`'s comments by subject, so they can be found again.
- **Live numbers move with models and harnesses.** Pins and baselines handle it as in RX.07. A row with a new pin is not a regression.
- **The steelman is a judgment.** The git candidates could be beaten by a cleverer command, and so could Reef's. The candidate lists are open to additions, the cheapest sufficient one wins, and the reviewer is asked to look for a cheaper git command specifically. The sufficiency check is necessary, not sufficient; the saved outputs are the evidence.
- **Imported landed history has no agent in Reef**, only the author email. If `reef history`'s text form does not show the email, Reef-arm agents will fail the `who-*` questions on landed work. That is a finding, not a fixture bug, and it gets an issue.
- **The `anthropic` counter depends on a free endpoint's rate limits.** The cache keeps repeat runs cheap. If it is unavailable, the scripted rows are still written with `bytes` and `o200k`, and the exit criterion stays unevaluated until it is back. The gate requires every counter.
- **One harness.** Every live conclusion holds for Claude Code alone until the follow-up adds a second. The page says so wherever it states one.
- **`--dangerously-bypass-approvals-and-sandbox`** runs the agent's shell unconfined. In CI the runner is disposable. Locally it is RX.07's caveat, stated on the page.

## Choices this brief made, and why

- **Scripted and live**: reproducibility and vendor-neutral counting from one, and the truth of what agents do from the other.
- **The fixture from Reef's own history, built twice with identical commits**: real code and real diff sizes, no network, and the git and Reef copies differ only in how unfinished work is held. That difference is the one under test.
- **Configuration files stripped and harnesses run bare**: every arm and harness starts equal. The cost of onboarding is RX.07's.
- **Exact grading, medians over correct trials**: a cheap wrong answer is not efficiency.
- **Cheapest sufficient candidate per arm**: neither git nor Reef is measured through a strawman.
- **The gate on default output**: agents get JSON unless told otherwise, so the claim must hold for what they get. The text form is shown so the fix is obvious.
- **Three counters, the gate under all**: no vendor's tokenizer decides Reef's claim.
- **A sibling page and workflow**: the onboarding page stays about onboarding, and one concurrency group keeps the two off one rate limit.
- **Measurement only**: the PR that measures does not also tune what it measures.
