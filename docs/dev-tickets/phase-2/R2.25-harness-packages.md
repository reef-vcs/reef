# R2.25 Harness packages

Phase 2 · Size S · Depends on: R1.27 (the renderers in `reef_vcs::agents`), R1.28 (the release workflow the packages ship from), R2.13 (`reef mcp`, the `.mcp.json`, Codex and opencode renderers, `server.json`, the `.mcpb` asset) · Unblocks: RX.07's scenario F (an installed plugin), R2.17 (an installed plugin is one of its arms)

## Context

R1.27 made `reef init` write the files a harness reads from a repository: `AGENTS.md`, `CLAUDE.md`, a Claude Code skill, a Cursor rule, and from R2.13 on `.mcp.json` and the Codex and opencode MCP entries. That configures one repository at a time, after `reef` is installed, by someone who runs `reef init` there. Harnesses also have a second channel that configures the harness itself, once, for every repository: Claude Code's plugins (a directory with a manifest, skills, hooks and an MCP server, installed from a marketplace with one command), Codex's `config.toml` and opencode's `opencode.json` at the user level. This ticket ships Reef through that channel: one install line per harness, built from the same renderers as `reef init` so the two cannot drift, packaged by the release workflow so a release carries its plugins, and checked in CI so a committed plugin that no longer matches the renderer fails the build.

The plugin is also where Reef's MCP server gets its registry listing published (R2.13 wrote `server.json`; this ticket publishes it) and where RX.07's benchmark gains the scenario that measures the plugin: an agent that has the plugin installed and nothing else.

### What was verified while writing this ticket

- **Claude Code plugins** (code.claude.com/docs/en/plugins-reference and plugins/marketplace-reference, fetched 2026-10-25). Layout: `.claude-plugin/plugin.json` (manifest, optional; fields `name` (required, kebab-case, namespaces every component), `displayName`, `version` ("Setting it keeps users on that version until you change it"), `description`, `author { name, email?, url? }`, `homepage`, `repository`, `license`, `keywords`), with every other file at the plugin root: `skills/<name>/SKILL.md`, `hooks/hooks.json` (`{"hooks": {<event>: [{matcher?, hooks: [{type: "command", command, timeout?}]}]}}`), `.mcp.json` (same shape as the project file; `${CLAUDE_PLUGIN_ROOT}` expands in `command`, `args`, `env`). A `CLAUDE.md` at the plugin root is not loaded and draws a validation warning; a `bin/` directory keeps claude.ai and Cowork from installing the plugin. Names starting `claude-`, `anthropic-` or `cc-plugin-` are reserved. `claude plugin validate <dir>` (`--strict` turns warnings into failures). `--plugin-dir <dir>` loads a plugin for one session without a marketplace. Marketplace: `.claude-plugin/marketplace.json` at the marketplace root with `name` (letters, digits, `.`, `_`, `-`; many reserved names, `reef-vcs` is not one), `owner { name, email?, url? }`, `plugins[]` entries `{ name, source, description?, version?, category? }` where `source` is a relative path from the marketplace root starting `./`; `claude plugin marketplace add owner/repo` (or `/plugin marketplace add`) finds `.claude-plugin/marketplace.json` at the repository root; `/plugin install <plugin>@<marketplace>`. Project-scope plugins installed from the main checkout also load in that repository's worktrees.
- **Claude Code hooks** (docs/en/hooks, fetched 2026-10-25): `SessionStart` matchers `startup`, `resume`, `clear`, `compact`, `fork`; on exit 0 the hook's stdout is added to Claude's context; JSON `{"hookSpecificOutput": {"hookEventName": "SessionStart", "additionalContext": "..."}}` is the structured form; `timeout` in seconds (default 600); plugins declare hooks in `hooks/hooks.json` and get `CLAUDE_PLUGIN_ROOT` in the environment. "Only `type: "command"` and `type: "mcp_tool"` hooks are supported" for SessionStart, and "keep these hooks fast".
- **Claude Code MCP tool names from a plugin** (docs/en/mcp): `mcp__plugin_<plugin>_<server>__<tool>`, so the plugin's server is `mcp__plugin_reef_reef__reef_status`; the project `.mcp.json` form is `mcp__reef__reef_status`. A plugin and a project file that both declare `reef` give the model two servers; R2.13's `reef init` renderer and this plugin therefore must not both be active in one repository, which the plugin's skill says.
- **Codex** (learn.chatgpt.com/docs/extend/mcp, fetched 2026-10-25): user scope `~/.codex/config.toml`, project scope `.codex/config.toml` "only for trusted projects"; `[mcp_servers.reef] command = "reef" args = ["mcp"]`, optional `startup_timeout_sec`, `tool_timeout_sec`, `enabled`; `codex mcp add reef -- reef mcp` writes the user-scope entry. Codex has no plugin format comparable to Claude Code's on that page; the harness-level package for Codex is the user-scope config entry plus `AGENTS.md`, which Codex reads from the repository (R1.27's verification).
- **opencode** (opencode.ai/docs/config, /mcp-servers, /plugins, fetched 2026-10-25): global config `~/.config/opencode/opencode.json`, project `opencode.json` at the root, merged (project over global); `"mcp": {"reef": {"type": "local", "command": ["reef", "mcp"], "enabled": true}}`; plugins are npm packages listed under `"plugin": [...]` (installed with Bun at startup) or `.js`/`.ts` files in `.opencode/plugins/` or `~/.config/opencode/plugins/`, exporting `async ({ project, client, $, directory, worktree }) => ({ hooks })` with hooks such as `event` (`session.created`, `session.idle`), `tool.execute.before|after`, `shell.env`. An opencode plugin is JavaScript; Reef's package for opencode is the config entry plus `AGENTS.md`, and a `shell.env` plugin is out of scope (below).
- **MCP registry publishing** (github.com/modelcontextprotocol/registry `docs/modelcontextprotocol-io/github-actions.mdx`, fetched 2026-10-25): on `push: tags: ["v*"]`, with `permissions: id-token: write`, download `mcp-publisher` pinned to a release tag (`MCP_PUBLISHER_VERSION: v1.8.1` in the example) and verify its Sigstore bundle with `cosign verify-blob --bundle ... --certificate-identity https://github.com/modelcontextprotocol/registry/.github/workflows/release.yml@refs/tags/<tag> --certificate-oidc-issuer https://token.actions.githubusercontent.com`, then `./mcp-publisher login github-oidc` and `./mcp-publisher publish`. ## Decisions

- **`plugins/` at the repository root holds one directory per harness, all rendered, none hand-written.** `plugins/claude-code/` is a Claude Code plugin; `plugins/codex/` and `plugins/opencode/` hold the user-scope configuration entry, a short `README.md` with the install line, and the `AGENTS.md` section for pasting. The directories are committed, so the marketplace works from the git repository with no release, and regenerated by `reef init --render-plugins plugins` (below); `just agent-files` runs it with `--check`, so a renderer change without a regenerated plugin fails CI, as a stale `AGENTS.md` does today.
- **The Claude Code plugin** (`plugins/claude-code/`):
  - `.claude-plugin/plugin.json`: `name: "reef"`, `displayName: "Reef"`, `version: <Cargo version>`, `description: "Isolated, leased workspaces for coding agents: reef ws run, reef here, and Reef's API as MCP tools."`, `author: { "name": "Reef contributors", "url": "https://github.com/reef-vcs" }`, `homepage: "https://github.com/reef-vcs/reef"`, `repository`, `license: "Apache-2.0"`, `keywords: ["vcs", "workspaces", "agents", "jujutsu"]`. `version` is set on purpose: a user stays on the plugin that matches their `reef` until the marketplace moves, and the `preface` line in every rendered file already names the `reef` version.
  - `skills/reef/SKILL.md`: byte-identical to what `reef init` writes at `.claude/skills/reef/SKILL.md` (R1.27's long form with its frontmatter and `generated-by: reef init`), plus one paragraph the repository skill does not have: "This skill comes from the `reef` plugin; a repository that also ran `reef init --agents claude` has the same skill twice and two `reef` MCP servers. Prefer the plugin for your own machine and `reef init` for a repository your team shares."
  - `.mcp.json`: R2.13's entry, `{"mcpServers": {"reef": {"type": "stdio", "command": "reef", "args": ["mcp"]}}}`. `command` is `reef` on `PATH`, not `${CLAUDE_PLUGIN_ROOT}/...`: the plugin configures a `reef` the user installed (R1.28), it does not bundle one, so the plugin has no `bin/` and claude.ai can install it.
  - `hooks/hooks.json`: one `SessionStart` hook, matcher `startup|resume`, `{"type": "command", "command": "reef here -o text 2>/dev/null || true", "timeout": 10}`. `reef here` is the one call that answers "where am I" (ADR 0025 rule 4): inside `ws run` it names the workspace and lease; outside it names the repository and says `reef ws run -- <command>` is next, in at most 12 lines, and exits 0 either way, which SessionStart adds to the context. It starts the daemon when none runs (the designed behavior of every command; the daemon is cheap and the hook has 10 s). `|| true` keeps a missing `reef` (the plugin installed before the binary) from printing an error into every session; the skill tells the model what to install. No `UserPromptSubmit` or `PreToolUse` hooks: the design says Reef never steers the agent, and a hook that rewrote `git worktree` into `reef ws create` would be exactly that (R2.26's adapter is opt-in for that reason).
  - No `commands/`, `agents/`, `CLAUDE.md`, or `bin/`.
- **The marketplace** is `.claude-plugin/marketplace.json` at the repository root: `name: "reef-vcs"`, `owner: { "name": "Reef contributors", "url": "https://github.com/reef-vcs" }`, `description`, `plugins: [{ "name": "reef", "source": "./plugins/claude-code", "description": <the manifest's>, "category": "version-control" }]`. R2.26 adds its `reef-worktrees` plugin as a second entry. Install: `/plugin marketplace add reef-vcs/reef`, then `/plugin install reef@reef-vcs` (or the `claude plugin ...` shell forms). The quickstart's "Set up your agent" section gains these two lines as the per-machine alternative to `reef init`.
- **Codex and opencode packages** are configuration, not code: `plugins/codex/config.toml` holds the `[mcp_servers.reef]` table (`command = "reef"`, `args = ["mcp"]`, `startup_timeout_sec = 20`: the first call may start the daemon), `plugins/codex/README.md` says `codex mcp add reef -- reef mcp` or where to paste the table, and `plugins/codex/AGENTS.md` is the rendered section for `~/.codex/AGENTS.md` (Codex reads a user-level `AGENTS.md`; R1.27 verified the repository-level one, the user-level path is checked in the PR and dropped from the README if it does not exist). `plugins/opencode/opencode.json` holds the `mcp.reef` entry for `~/.config/opencode/opencode.json`, with a README saying to merge it. Both are rendered by the same functions R2.13's `reef init --agents codex|opencode` uses, so the project-scope and user-scope entries are one string.
- **`reef init --render-plugins <dir>`** writes the three directories under `<dir>` (`claude-code/`, `codex/`, `opencode/`) from the renderers, replacing files whose frontmatter or a leading comment carries `generated-by: reef init` (JSON has no comments: the manifest's `metadata.generatedBy` field, which Claude Code ignores, and `_comment` keys in `.mcp.json` and `opencode.json`, carry it) and skipping any other file as `reef init` skips a foreign skill; `--check` with it exits 3 listing stale files. It does not register a repository or touch the cwd; it conflicts with `--agents`, `--print`, `--user`. `just agent-files` becomes `reef init --agents claude,codex,opencode --no-register --check` plus `reef init --render-plugins plugins --check`.
- **The release workflow** (`release.yml`) gains, in the `publish` job: `scripts/package-plugins.sh <version> dist` producing `reef-plugins-<version>.tar.gz` (the `plugins/` tree and `.claude-plugin/marketplace.json`) attested with the other assets and attached to the release; and a new `mcp-registry` job after `release`, modeled on the `homebrew` job (a failure does not fail the release; the formula-style fallback is `mcp-publisher publish` by hand): `permissions: id-token: write, contents: read`, download `mcp-publisher` pinned and Sigstore-verified exactly as the registry's guide shows, rewrite `server.json`'s `fileSha256` values from `dist/SHA256SUMS` (the `.mcpb` hashes are known only after the build), `./mcp-publisher login github-oidc`, `./mcp-publisher publish`. The job is skipped on dry runs. `server.json`'s `version` is checked against the tag by `check-version` as `Cargo.toml`'s is. The plugin tarball exists for an `archive` plugin source and for mirrors; the marketplace itself is the git repository.
- **Scenario F, "plugin installed", joins the onboarding benchmark**: A's checkout (no `reef init`), Claude Code not bare, started with `--plugin-dir <trial>/plugins/claude-code` (a copy of the committed plugin, so the trial measures the plugin as shipped without touching the runner's `~/.claude`), prompt `a.txt`, `--allowedTools Bash,Read,Edit,mcp__plugin_reef_reef__*`. Measured as B and E are; a trial whose `init` event lists neither the `reef` skill nor a `mcp__plugin_reef_reef__` tool is a setup failure. Target: B's (median at most 4 calls, 0 failed `reef` calls). `onboarding.yml`'s default scenarios become `A,B,C,D,E,F`.
- **Versioning.** The plugin's `version`, `server.json`'s `version` and every rendered preface are the Cargo version. A version bump (R1.28's runbook) therefore regenerates `plugins/` and `server.json`; `scripts/version.sh` checks all three and `just agent-files` fails until they are regenerated, which is what the Phase 2 README's "what a version bump must touch" list already requires of `install.sh` and the tap.

## Tests

1. `rendered_plugins_match_the_committed_tree` (`crates/reef-vcs/tests/init.rs`): `reef init --render-plugins <tmp>` produces files byte-identical to `plugins/` and `.claude-plugin/marketplace.json` in the checkout (the test that `just agent-files` runs in CI, from the other side).
2. `plugin_skill_is_the_init_skill_plus_the_plugin_paragraph`: `plugins/claude-code/skills/reef/SKILL.md` minus the plugin paragraph equals `reef init --print --harness claude-skill`'s output (R2.13's `--harness`), frontmatter included.
3. `plugin_mcp_entry_is_the_init_entry`: the `reef` server object in `plugins/claude-code/.mcp.json`, `plugins/opencode/opencode.json`'s `mcp.reef`, and `plugins/codex/config.toml`'s table equal R2.13's renderer constants.
4. `render_plugins_skips_foreign_files_and_check_exits_3`: a `SKILL.md` without `generated-by` in the target is `skipped`; a stale `plugin.json` makes `--check` exit 3 with `next == ["reef", "init", "--render-plugins", <dir>]`.
5. `manifest_and_marketplace_are_valid_json_with_the_required_fields`: `plugin.json` has `name == "reef"`, `version == CARGO_PKG_VERSION`, `author.name`; `marketplace.json` has `name == "reef-vcs"`, one entry per plugin directory under `plugins/` that has a `.claude-plugin/`, each `source` starting `./plugins/` and existing; no `bin/`, `CLAUDE.md`, or `commands/` under `plugins/claude-code/`.
6. `plugin_validates` (`tests/cli.rs`, skipped without `claude` on `PATH`): `claude plugin validate --strict plugins/claude-code` and `claude plugin validate --strict .` exit 0.
7. `session_start_hook_is_fast_and_quiet` (against `TestDaemon`): run the hook's command line through `sh -c` with the test's `REEF_SOCKET`, outside a workspace: exit 0, stdout at most 12 lines naming `reef ws run`, under 10 s; with `PATH` lacking `reef`: exit 0, empty stdout; inside a workspace (`REEF_WORKSPACE` set): the workspace id on stdout.
8. `package_plugins_tarball_holds_the_tree` (`scripts/test-install.sh`'s neighbor, run by `just installer`): the tarball unpacks to `plugins/` and `.claude-plugin/marketplace.json` matching the checkout.
9. `version_script_checks_plugins_and_server_json`: `scripts/version.sh` exits non-zero when `plugin.json`'s or `server.json`'s version differs from `Cargo.toml`'s.
10. `onboarding_parses_plugin_tool_names` (`reef-testing` unit): a recorded scenario F stream yields `mcp_calls` for `mcp__plugin_reef_reef__*` and the skill check accepts a `reef` skill from the plugin.

## Implementation notes

- Render first, then commit the output: the committed `plugins/` must be the renderer's output, never edited by hand, or test 1 fails. The one hand-written file is `plugins/README.md`, which the renderer leaves alone.
- Keep the plugin-only paragraph in the skill as a constant in `agents/plugins.rs` beside the manifest fields; it is the one place the plugin's text differs from `reef init`'s.
- For `claude plugin validate` in CI, reuse `onboarding.yml`'s install step (`npm install --global --prefix "$RUNNER_TEMP/claude" @anthropic-ai/claude-code@$CLAUDE_CODE_VERSION`); read the pin from one place (`onboarding.yml`'s `env` is not shareable; put the version in `.github/claude-code-version` and have both workflows read it).
- The `mcp-registry` job must not run on dry runs or forks: gate on `needs.check-version.outputs.publish == 'true'` as `homebrew` does, and give it `continue-on-error`-equivalent semantics by not making `release` depend on it.
- `server.json`'s `fileSha256` rewrite uses `jq` over `SHA256SUMS`; keep the committed `server.json` with placeholder hashes (`"fileSha256": "0000...0"`) and a comment in `plugins/README.md` saying the release fills them in, so `mcp-publisher validate` passes on the checkout (it does not check hashes).
- Test by hand once: `claude plugin marketplace add <path to the checkout>`, `/plugin install reef@reef-vcs`, a new session in a plain git checkout, and read what SessionStart put in the context and what `/mcp` lists; record it in the PR with the Claude Code version.

## Out of scope

- A bundled `reef` binary inside the plugin (a `bin/` directory keeps claude.ai from installing it; the installer is the distribution).
- An opencode JavaScript plugin (`shell.env` setting `REEF_*`, or `session.created` running `reef here`): the config entry and `AGENTS.md` give opencode the same surface Codex gets; a plugin is a follow-up when an opencode user asks.
- Hooks that steer the agent (`PreToolUse` on `git worktree`): R2.26's opt-in adapter.
- Submitting the plugin to Anthropic's directory (the `icon`, `documentationUrl`, `supportUrl` fields): after the first release that carries it, by hand.
- Codex and opencode onboarding scenarios (RX.07 names Codex as the second harness once its non-interactive mode is verified).

## Risks

- **Two `reef` servers in one session.** A repository that ran `reef init --agents claude` and a user with the plugin both declare `reef`; Claude Code shows two servers with different tool prefixes. The skill paragraph says which to prefer; a later `reef init` could detect an installed plugin (`~/.claude/plugins/`) and skip `.mcp.json`, but that reads the home directory, which R1.27 chose not to do.
- **Plugin format churn.** Claude Code's plugin reference versions its fields by Claude Code version; `claude plugin validate --strict` in CI catches a field that stops validating, and the renderers are small.
- **The registry publish is a network step on the release path.** It is isolated in its own job that cannot fail the release, like the Homebrew push, and the by-hand command is recorded.
- **`SessionStart` starting a daemon.** A user who installs the plugin and never uses Reef gets a daemon started by every new session. The hook is documented in the skill, `|| true` keeps it quiet, and `reef daemon stop` ends it; if that is friction in practice, the hook moves to `--no-autostart` and the skill says to start the daemon.
