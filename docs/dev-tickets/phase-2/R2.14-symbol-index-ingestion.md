# R2.14 Symbol index ingestion

Phase 2 · Size L · Depends on: R2.02 (`RepoHandle::head()`, reads off the repository thread, `Changes.Diff`), R2.01 (`reef.daemon.v1`, the `reef-api` crate, `Symbols { Index, Ingest, Lookup }` as stubs), R1.16 (the `snapshots` index and its reindex), R1.17 (`Gc`) · Unblocks: R2.15 (the symbol diff reads this index), R2.16 (the queries join it), R3.38 (symbol search)

## Context

Design principle 7 of the agent problem: the consumer of history is an agent, and tokens are a performance metric. A unified diff of a 400-line file costs the model the whole file; "`parse_args` changed, `main` calls it" costs a line. The design puts a symbol model under the query layer and under diffs ("Symbol model for queries and diffs: SCIP, tree-sitter tags as fallback", `docs/design.md`, Technology choices), keyed by file content hash so unchanged files share entries across snapshots (Scale: "The symbol index is the largest store"). This ticket builds that store and the two ways into it: the daemon's own extraction with tree-sitter tags for the four Phase 2 languages, and ingestion of a SCIP index an external indexer produced. R2.15 reads it to answer `diff --symbols`; R2.16 queries it.

The README fixes the shape: migration `0008_symbols`, rows keyed by blob id, the three RPCs, the `[symbols]` configuration section, the crate set, and ADR 0035. This brief adds how indexing is scheduled, what a symbol row means for each source, the kind vocabulary, how rows die, and the fixtures R2.15 inherits.

## Decisions

- **One vocabulary, two sources.** A `symbols` row is a definition; a `symbol_refs` row is a use. `SymbolKind { Function, Method, Class, Struct, Enum, Interface, Trait, Type, Module, Constant, Variable, Field, Macro, Other }`, stored as its lowercase name in `symbols.kind`. From tags: `function → function`, `method → method`, `class → class`, `interface → interface`, `module → module`, `macro → macro`, `constant → constant`, `type → type`, anything else `other`. Rust's tags query files `struct_item`, `enum_item`, `union_item` and `type_item` all as `definition.class`, so from the tags source a Rust struct is a `class`; the SCIP source tells them apart (`Struct`, `Enum`, `TypeAlias`). The vocabulary is per row, not per repository, and a consumer that wants the finer kind asks whether the row's `source` is `scip`. From SCIP (`SymbolInformation.kind`): `Function, StaticMethod → function`; `Method, AbstractMethod, Constructor, SingletonMethod, TraitMethod → method`; `Class, SingletonClass → class`; `Struct → struct`; `Enum, Union → enum`; `Interface, Protocol → interface`; `Trait, TypeClass → trait`; `Type, TypeAlias, TypeFamily, TypeParameter → type`; `Module, Namespace, Package → module`; `Constant, EnumMember → constant`; `Variable, StaticVariable → variable`; `Field, Property, StaticField, StaticProperty → field`; `Macro → macro`; everything else, `UnspecifiedKind` included, `other`. Only occurrences with the `Definition` role become `symbols` rows; every other non-`Import` occurrence of a non-local symbol becomes a `symbol_refs` row with `is_call = 0` (SCIP has no call role; R2.15 labels them `reference`). Tags references: `reference.call → is_call = 1`; `reference.type`, `reference.class`, `reference.implementation → is_call = 0`.
- **Names.** From tags, `name` is the source text of `Tag::name_range`; `parent` is the innermost enclosing definition tag's name (by range containment within the same file), else `''`; `signature` is the first line of the tag's `line_range` text, whitespace-trimmed, cut at 200 bytes. From SCIP, `name` is the last descriptor's `name` (`parse_symbol`), `parent` the preceding descriptors' names joined with `.` after the package descriptors, `signature` is `display_name` when set, else `''`; local symbols (`is_local_symbol`) are skipped. Ranges are 0-based lines and columns in `symbols`, from `Tag::span` or the occurrence's `enclosing_range` (falling back to `range` when `enclosing_range` is empty).
- **Blob-keyed rows; commit rows for changed files only.** The README's `commit_files` is the index's bridge from a commit to blobs. A row per tracked file per commit (100,000 rows per `large` snapshot) is what the design's "largest store" warning is about, so `commit_files` holds the commit's diff against its first parent: one row per changed path with `blob_id` (after; NULL when removed), `old_blob_id` (before; NULL when added), `status IN ('added','modified','removed')` and `indexed_at`. The README's `PRIMARY KEY (repo_id, commit_id, path)` stands. A lookup over a whole tree reads the tree from jj (below), not from this table.
- **Where indexing runs.** `reef_daemon::symbols::Indexer`, one per daemon, owning one `std::thread` (`reef-symbols`) with its own `TagsContext` and `TagsConfiguration`s, fed by a bounded `mpsc` of `Job { repo: RepoId, commit: CommitIdHex, scope: Changed | Tree, reply: Option<oneshot::Sender<Report>> }` (capacity 1,024). The thread runs jj reads under `pollster::block_on` on an `Arc<ReadonlyRepo>` from `RepoHandle::head()`, never touching the repository thread; SQLite writes go through `Db` in batches of one file. Jobs for the same `(repo, commit)` coalesce; a `Changed` job for a workspace whose newer commit is already queued is dropped. One thread, by decision: tree-sitter is CPU-bound, the scan pool (`max_concurrent_scans`) already owns the cores a snapshot burst needs, and the index is a cache nothing waits on. `[symbols] auto = true` registers a `SnapshotHook` in `Daemon::start` that sends `Changed` for every `changed` outcome (`try_send`; a full queue drops the job with a `warn` counter, and the daily reconciliation below catches up).
- **What a `Changed` job does.** `diff_stream(parent_tree, commit_tree)` of the commit against its first parent; for each entry whose `after` is a resolved `TreeValue::File`: write the `commit_files` row; if the path's extension names an enabled language, the blob is at most `[symbols] max_file_size`, and `symbol_files` has no `(repo, blob, 'tags')` row, read the blob and extract. Removed paths get their `commit_files` row (`blob_id NULL`). Conflicted entries (an unresolved `Merge`) are skipped with a `debug` line. A `Tree` job walks `entries_matching` of the commit's tree and extracts every unindexed eligible blob, writing no `commit_files`; `Symbols.Index` with `scope = TREE` is how an agent primes a repository so R2.15's call sites cover the whole tree. A file that fails to parse (tree-sitter returns `has_error = true`) is still indexed with whatever tags came out and `symbol_files.errors = 1`; a file that is not UTF-8 is indexed anyway (tree-sitter works on bytes; names that are not UTF-8 are lossily decoded).
- **Languages by extension.** `.py` python; `.ts`, `.mts`, `.cts` TypeScript; `.tsx` TSX (the second typescript grammar, same queries); `.go` go; `.rs` rust. `.js`/`.jsx` are not indexed in Phase 2 even though the grammar is present: the exit criterion names four languages and the fixtures cover four. `[symbols] languages` subsets these; an unknown name is a configuration error at start.
- **`Symbols.Ingest`** is client-streaming: the first `IngestChunk` carries `repo`, `rev` and `source = "scip"`; every chunk carries `bytes`; the daemon concatenates (cap: 256 MiB, else `RESOURCE_EXHAUSTED`), decodes `scip::types::Index`, and for each `Document` resolves `relative_path` in the commit's tree to a blob id (a document whose path is not a regular file in the tree is counted in `skipped_documents`), then writes `symbol_files (source = 'scip')`, `symbols` and `symbol_refs` for that blob, replacing any earlier `scip` rows of the same blob in one transaction per document. Tags rows of the same blob are left alone; a reader prefers `scip` rows when both exist (R2.15, R2.16 read with `ORDER BY source = 'scip' DESC` and take the first source per blob). `reef symbols ingest <file.scip> [--rev <rev>]` is the CLI; `scip-rust-analyzer`, `scip-python`, `scip-typescript` and `scip-go` produce the input, none of which Reef runs or ships.
- **`Symbols.Lookup { repo, rev, name, kind, exact, page }`.** Resolves `rev` (default `@`), walks the tree's entries once (`entries_matching(&EverythingMatcher)`), keeps `(path, blob_id)` of regular files, and returns `symbols` rows whose blob is in that set and whose `name` equals `name` (or starts with it when `exact = false`), as `Symbol { path, blob_id, name, kind, parent, signature, start_line, start_col, end_line, end_col, source }`, ordered by path then line, paged. The tree walk is the cost (100,000 entries on `large`; measured and recorded in the PR), and R2.15 reuses the same helper (`symbols::tree_blobs(repo, commit) -> Vec<(RepoPathBuf, FileId)>`) with a per-request cache.
- **Rows die with GC.** `maintenance::gc::run_repo` gains a `symbols` step after `remove_ended_rows`: delete `commit_files` rows with `indexed_at < keep_newer` whose `commit_id` is neither a `snapshots.commit_id` nor a `workspaces.commit_id` of the repository nor a head of the current view (read on the repository thread with the other jj steps); then delete `symbol_files`, `symbols` and `symbol_refs` rows whose `blob_id` no remaining `commit_files` row names in `blob_id` or `old_blob_id` **and** whose `symbol_files.indexed_at < keep_newer` (a blob indexed by a `Tree` job has no `commit_files` row; the age test keeps recent ones). `GcReport` gains `symbol_rows_removed` (sum over the four tables) and `maintenance.proto`'s `GcReport` field 15. Dry runs count.
- **Reconciliation at start.** None beyond GC: the index is a cache, and a missing row is indexed on the next snapshot or on demand (R2.15 indexes a missing blob synchronously when the diff needs it). The `snapshots`-style reindex is not needed because blob-keyed rows cannot go stale: a blob's contents never change.
- **Feature `symbols`** on `reef-daemon`, default on, gating the tree-sitter and scip dependencies (the grammars compile C). Without it `Symbols.*` answer `UNAVAILABLE` with the hint `this daemon was built without symbols`, and the hook is not registered. CI's existing `--no-default-features` check covers the build.
- **ADR 0035, "Symbol index"**: blob-keyed rows and why (sharing across snapshots, no staleness), `commit_files` as the commit's diff rather than its tree, two sources with one vocabulary and the Rust `class` consequence, one indexer thread off the repository thread and the scan pool, tree-sitter tags as the always-available source and SCIP as the precise one, GC by reachability plus age, the TypeScript query concatenation, and the alternatives: rows keyed by `(commit, path)` (rejected: 100k rows per snapshot), indexing in the snapshot's own thread (rejected: a parse of 100 changed files on the snapshot path), a tree-sitter `locals`-based scope resolution (deferred: needs per-language work), running SCIP indexers from the daemon (rejected: ADR 0027 and R2.27, the daemon stops running repository-declared commands), LSIF (rejected: superseded by SCIP).

## Deliverables

### `crates/reef-daemon/src/db/migrations/0008_symbols.sql`

```sql
-- R2.14: the symbol index. Rows are keyed by blob id (the git blob SHA-1 in this phase, ADR
-- 0011), so unchanged files share rows across snapshots. `commit_files` is a commit's diff
-- against its first parent, not its tree. Released migrations are never edited.
CREATE TABLE symbol_files(repo_id TEXT NOT NULL, blob_id TEXT NOT NULL, lang TEXT NOT NULL,
             source TEXT NOT NULL CHECK (source IN ('tags','scip')), errors INTEGER NOT NULL DEFAULT 0,
             indexed_at INTEGER NOT NULL, PRIMARY KEY (repo_id, blob_id, source));
CREATE TABLE symbols(id INTEGER PRIMARY KEY AUTOINCREMENT, repo_id TEXT NOT NULL, blob_id TEXT NOT NULL,
             source TEXT NOT NULL CHECK (source IN ('tags','scip')),
             name TEXT NOT NULL, kind TEXT NOT NULL, start_line INTEGER NOT NULL, start_col INTEGER NOT NULL,
             end_line INTEGER NOT NULL, end_col INTEGER NOT NULL, parent TEXT NOT NULL DEFAULT '',
             signature TEXT NOT NULL DEFAULT '');
CREATE TABLE symbol_refs(repo_id TEXT NOT NULL, blob_id TEXT NOT NULL,
             source TEXT NOT NULL CHECK (source IN ('tags','scip')),
             name TEXT NOT NULL, line INTEGER NOT NULL, col INTEGER NOT NULL, is_call INTEGER NOT NULL);
CREATE TABLE commit_files(repo_id TEXT NOT NULL, commit_id TEXT NOT NULL, path TEXT NOT NULL,
             blob_id TEXT, old_blob_id TEXT, status TEXT NOT NULL CHECK (status IN ('added','modified','removed')),
             indexed_at INTEGER NOT NULL, PRIMARY KEY (repo_id, commit_id, path));
-- Lookup by name within a set of blobs (R2.14 Lookup, R2.15, R2.16).
CREATE INDEX symbols_by_name ON symbols(repo_id, name, kind);
CREATE INDEX symbols_by_blob ON symbols(repo_id, blob_id, source, start_line);
CREATE INDEX symbol_refs_by_name ON symbol_refs(repo_id, name, is_call);
CREATE INDEX symbol_refs_by_blob ON symbol_refs(repo_id, blob_id, source);
-- GC's reachability test, and R2.16's joins from a commit to its blobs.
CREATE INDEX commit_files_by_blob ON commit_files(repo_id, blob_id);
CREATE INDEX commit_files_by_old_blob ON commit_files(repo_id, old_blob_id);
```

The `source` column on `symbols` and `symbol_refs` (not in the README's column list) lets the two sources of one blob coexist and a reader prefer `scip`. The `errors` and `indexed_at` columns on `symbol_files`, and `old_blob_id`, `status`, `indexed_at` on `commit_files`, are this ticket's additions.

```rust
    pub async fn index_now(&self, repo: RepoId, commit: CommitIdHex, scope: Scope) -> Result<Report, SymbolsError>;   // Symbols.Index; waits for the reply
    pub fn snapshot_hook(self: &Arc<Self>) -> SnapshotHook;   // enqueue(Changed) when outcome.changed
    pub fn stop(&mut self);   // shutdown hook: drain nothing, stop after the job in flight
}
```

`SymbolsError` wraps `SymbolsError::Unavailable` (built without the feature), `Db`, `Backend`, `Scip`, `TreeSitter`, `UnknownRevision`, `TooLarge`, with `Classify` (`Unavailable`, `Internal`, `InvalidArgument`, `NotFound`, `InvalidArgument`) and an `Advise` for `Unavailable`.

### `crates/reef-daemon/src/service/symbols.rs`, `crates/reef-api/proto/reef/daemon/v1/symbols.proto`

R2.01 wrote the messages; this ticket fills them in if a field is missing and implements the handlers. The shape this ticket implements:

```proto
service Symbols {
  rpc Index(IndexRequest) returns (IndexResponse);              // scope CHANGED | TREE; waits; INVALID_ARGUMENT for an unknown rev
  rpc Ingest(stream IngestChunk) returns (IngestResponse);      // first chunk: repo, rev, source; every chunk: bytes
  rpc Lookup(LookupRequest) returns (LookupResponse);           // repo, rev, name, kind, exact, page -> repeated Symbol, Page
}
message IndexRequest { string repo = 1; string rev = 2; enum Scope { CHANGED = 0; TREE = 1; } Scope scope = 3; }
message IndexResponse { string commit_id = 1; uint64 files_seen = 2; uint64 files_indexed = 3; uint64 files_skipped_size = 4; uint64 files_with_errors = 5; uint64 symbols = 6; uint64 refs = 7; uint64 elapsed_ms = 8; }
message IngestChunk { string repo = 1; string rev = 2; string source = 3; bytes bytes = 4; }
message IngestResponse { string commit_id = 1; uint32 documents = 2; uint32 skipped_documents = 3; uint64 symbols = 4; uint64 refs = 5; }
message Symbol { string path = 1; string blob_id = 2; string name = 3; string kind = 4; string parent = 5; string signature = 6; uint32 start_line = 7; uint32 start_col = 8; uint32 end_line = 9; uint32 end_col = 10; string source = 11; }
```

## Implementation notes

- Keep `TagsContext` and the `TagsConfiguration`s on the indexer thread; `TagsConfiguration` is built once per language at thread start (`new` compiles the query, tens of milliseconds each). The TypeScript configuration's query string is `format!("{}\n{}", tree_sitter_javascript::TAGS_QUERY, tree_sitter_typescript::TAGS_QUERY)` with `tree_sitter_typescript::LOCALS_QUERY`; TSX uses the same strings with `LANGUAGE_TSX`. Add a unit test that `TagsConfiguration::new` of the concatenation succeeds, because a grammar bump that renames a node breaks the query at construction, not at parse.
- `Tag::syntax_type_id` to kind goes through `config.syntax_type_name(id)`, which returns the part after `definition.`/`reference.` (`function`, `call`, ...).
- `parent` for tags: sort definition tags by `range.start`; keep a stack of open definitions; a tag whose range is inside the top's range gets the top's name. Rust methods inside `impl` blocks have no enclosing definition tag (an `impl_item` is a `reference.implementation`, not a definition), so their `parent` is `''` from the tags source; SCIP gives it. Say so in the fixture README.
- The hook must not block: `try_send` and return. The indexer reads `AppState` through a `Weak` so shutdown is not kept alive by the thread.
- `tree_blobs` on a `MergedTree` with conflicts: `entries()` yields `MergedTreeValue`s; take only `as_resolved()` values that are `TreeValue::File`.
- Blob reads for `Changed` jobs use `Store::read_file(path, id)` with the entry's path; the backend ignores it today, and passing the real path keeps a future backend honest.
- The per-document transaction in `Ingest` keeps a 50 MB index from holding the database lock for seconds; `Db` is one connection under a mutex, and snapshots write rows through it.
- A `Lookup` whose `rev` has a tree the daemon cannot read (RX.01 S-18's hostile entries) must fail `InvalidArgument` through the existing `check_git_head_tree_names` path before walking.
- CI: the grammars compile C with `cc`; the `check` matrix already builds `--all-targets`. Expect 20 to 40 s of extra compile time per fresh build; record the number in the PR's dogfooding notes.

## Out of scope

- The symbol diff (R2.15), the queries (R2.16), symbol search in the UI (R3.38).
- JavaScript, TSX-specific component tagging beyond the grammar's query, and any language beyond the four; `.js` files, although the grammar is linked.
- Scope and reference resolution (which `area` a call means): tags are name-based; SCIP carries resolved symbols and R2.15 uses what each source gives.
- Running an indexer (`scip-*`) from the daemon or the CLI: ADR 0027 and R2.27.
- Indexing the user's `default` workspace's uncommitted files: the index is over commits, and the root checkout's files are not snapshotted by Reef.
- A symbol table over the whole tree per commit (`commit_files` as a tree), and search by signature or documentation.

## Risks

- **Rust ADTs appear as `class` from the tags source.** The grammar's query collapses `struct`, `enum`, `union` and `type` into `definition.class`. Options were a Reef-owned Rust tags query (one more file to maintain against grammar bumps) or a post-pass on node kinds (a second parse). The vocabulary row explains it, SCIP corrects it, and if R2.15's fixtures or users find it misleading a Reef-owned query is a one-file change.
- **TypeScript relies on two queries.** If a tree-sitter-typescript release changes node names so the JavaScript query no longer compiles against it, `TagsConfiguration::new` fails at indexer start; test 2 catches it, and the language is disabled with a `warn` rather than taking the indexer down.
- **One indexer thread lags a burst.** Twenty workspaces each snapshotting 100 changed source files is 2,000 parses in a row, a few seconds; the queue holds 1,024 jobs and coalesces per workspace. A dropped job is caught by the next snapshot of that workspace or by `Index`; the `dropped` counter is logged so RX.03 can report it.
- **`Lookup` walks the tree.** 100,000 entries per call on `large`, hundreds of milliseconds; acceptable for an agent's lookup, measured in test 15, and R2.15 caches the walk per request. A per-commit path cache is the fix if the number is bad; `commit_files` was deliberately not that cache.
- **GC's reachability test is conservative.** A blob indexed by a `Tree` job and never named by a `commit_files` row lives until it is older than `keep_newer`; a repository that only ever runs `Index --all` carries its symbol rows for the undo window. Bounded and documented.
- **SCIP ranges are 0-based and half-open; tree-sitter points are 0-based.** Both land in the same columns; the fixtures pin the convention so R2.15's intersections do not go off by one.
