# R2.14 Symbol index ingestion

Phase 2 · Size L · Depends on: R2.02 (revision resolution, `at_operation`, snapshot-first reads, page tokens, the read side's `Reads::loaded`), R2.04 (`reef_lib::jj::files`, whose tree reading this extends, and `EditFiles`, whose commits are indexed too), R2.27 (the CLI's scope rule and JSON conventions) · Unblocks: R2.15 (symbol-level diff), R2.16 (query layer), R3.38 (symbol search in the file browser); R3.18 through R2.15, and R2.17 measures through R2.15

## Context

The design gives Reef a query layer whose diffs are "available at the symbol level as well as the line level, which is both more useful to an agent and far cheaper in tokens than a unified diff" (`docs/design.md`, Query layer), picks "SCIP, tree-sitter tags as fallback" as the symbol model (Technology choices), and says "the symbol index is the largest store, since indexers produce output per snapshot. It is keyed by file content hash so unchanged files share entries across snapshots" (Scale). Its data-placement table puts the symbol index on local disk, not authoritative, "rebuilt by re-indexing" (Durability). Phase 2's exit criterion is "symbol-level diffs work for Python, TypeScript, Go, and Rust", which R2.15 delivers on top of this ticket.

This ticket builds the index and nothing that reads it for meaning. It extracts tree-sitter tags itself for the four languages, accepts SCIP documents a caller uploads for a revision and checks each against the file it claims to describe, and stores definitions and references with their ranges in a per-repository SQLite cache keyed by path and file content. It exposes three RPCs: index a revision, upload SCIP documents, and list the symbols of a file or the occurrences of a name or symbol in a revision. The list is the read that proves ingestion works, and it is also the lookup R2.15 needs for call sites. Diff semantics are R2.15's, and history queries are R2.16's.

R2.01's rule binds this brief: it adds and never changes. It adds a new service in a new file, `symbols.proto`, so `API_REVISION` goes up by one (see "Schema").

## Decisions

### Size

L, as the row says. The work: a new crate with five grammars and Reef's own tag queries; SCIP decoding and normalization; a per-repository cache database with eviction; a background indexer fed by snapshots and edits; three RPCs; three CLI commands; a GC step; an ADR; and about 22 tests and two benches. The row's scope grows in what it names, not in size (see "Departures").

### What "per snapshot" means

- **A snapshot is a commit** (R2.04: the snapshot hash is a commit id). Every RPC takes a `revision`, resolved as R2.02 resolves one. Snapshot-first applies when it uses `@`, and `at_operation` and `skip_snapshot` work as on every read.
- **Symbols depend on the tree, not the commit.** The index records coverage per tree, keyed by the commit's tree ids joined (as `rewrite::working_copies` compares conflicted trees). A describe, which rewrites the commit and keeps the tree, needs no new indexing. Responses report the `commit_id` the request resolved.
- **The stored data is keyed by file, not by tree.** One entry is `(path, file id, source)`, where the file id is the backend's content id (a git blob id today). A tree is never copied into the index: jj's tree is already the path-to-content map. A tree with N files shares every unchanged file's entry with its parent. A tree costs one coverage row plus the entries of the files it changed. This is the design's "keyed by file content hash", plus the path. The path is part of the key for three reasons: the language comes from the extension, a symbol's identity includes its file (SCIP's for TypeScript and Python, and this brief's for tags), and SCIP documents are per path. A rename extracts the file once more under its new path.

### Who produces symbols

- **The daemon extracts tags itself** for Python (`.py`, `.pyi`), TypeScript (`.ts`, `.mts`, `.cts`, `.d.ts`), TSX (`.tsx`), JavaScript (`.js`, `.mjs`, `.cjs`, `.jsx`, parsed with the TSX grammar, which accepts JavaScript and JSX), Go (`.go`) and Rust (`.rs`). This is how R2.15's exit criterion works with no user-supplied index. Tags are never uploaded. There is no stable interchange format for tree-sitter tag output: the `tree-sitter tags` CLI prints a human format, and ctags is another model. A team with another language uploads SCIP, which has indexers for Java, C and C++, Ruby, C#, and more.
- **SCIP is uploaded** by a caller that ran an indexer (`scip-typescript`, `scip-python`, `scip-go`, `rust-analyzer scip`, ...) in a checkout of the revision: an agent in its workspace, or CI. The daemon never runs an indexer. Indexers need toolchains, dependencies and minutes of compile time, and running them is the executor's business (Phase 3).
- **Both sources are kept per file.** A file with a SCIP entry also has its tags entry (tags fill SCIP's missing definition ranges, below). A read returns one source per file, SCIP when it has an entry for that exact `(path, file id)`, else tags, and says which. A caller can force either one.

### When tags are extracted

- **In the background, for the trees of new snapshots and edits.** `record_commit` and the `Write::Edit` arm call `SymbolIndex::notice(repo, commit_id)` after their commit. The call only enqueues and never blocks the write. The queue keeps one pending commit per workspace, a later snapshot replacing an earlier one, plus up to 256 edit commits (the oldest dropped first). A dropped commit is indexed on demand if anything asks.
- **On demand,** by `IndexSymbols` and by `ListSymbols` (bounded, below), through `SymbolIndex::ensure`, which R2.15 and R2.16 call too.
- **Incrementally.** Indexing a tree first looks for a complete tree to diff from: the first parent's, then trunk's. If it finds one, it diffs the two trees and extracts only the files added or modified there that have no entry yet. If it finds none, it walks the tree and looks up every supported file's entry in one prepared statement, then extracts the missing ones. Either way, a file whose entry exists is never parsed again.
- **Single flight per tree.** Concurrent requests for one tree wait on one pass.
- **Off the repository thread and the read pool.** Workers take the repository with `Reads::loaded` (one short job), then read blobs and parse on `symbols.workers` threads of their own, driving jj-lib futures with `pollster` (ADR 0008). Subscriptions and reads keep their permits. Each worker lowers its own priority at start: `setpriority(PRIO_PROCESS, gettid(), 10)` on Linux, `pthread_set_qos_class_self_np(QOS_CLASS_UTILITY, 0)` on macOS. A first index of a large repository is a CPU burst that agents' snapshots should not queue behind.
- **Configuration**, `[symbols]` in `config.toml`, defaults shown: `enabled = true` (false: no background work, no database file, and the three RPCs fail with `SYMBOLS_DISABLED`); `background = true`; `workers = 0` (auto: `max(1, min(4, cores / 4))`); `max_file_size = "1MiB"` (as `[snapshot] max_new_file_size`); `max_size = "2GiB"` per repository. `TestDaemon` and the spawned-binary harness set `background = false` unless a test turns it on, so existing timing tests see no new CPU load.

### The tag extractor

- **Reef's own queries,** one `.scm` per language in `reef-symbols/queries/`, written from the grammars' upstream `tags.scm` (MIT; credit kept in each file's header) and extended where those fail (above). They use the tags convention (`@definition.<kind>`, `@reference.<kind>`, `@name`) plus one capture of Reef's, `@scope`: the type a definition belongs to when the syntax does not nest it there. For Go that is a method's receiver type, pointer stripped. For Rust it is an `impl`'s self type, with `impl Trait for T` giving `T`. Extraction runs `tree_sitter::QueryCursor` directly, not `tree-sitter-tags`, which has no such capture.
- **`TAGS_VERSION: u32 = 1`**, together with each grammar crate's version, forms the entry's `extractor` string (`tags/1/rust/0.24.2`). Changing a query or a grammar bumps it. Lookups ask only for the current extractor, so old entries are never read and GC sweeps them.
- **What is captured**, per language, maps to `SymbolKind`:

  | Language | Definitions | References |
  | --- | --- | --- |
  | Python | `class_definition` CLASS; `function_definition` FUNCTION, or METHOD directly in a class; the `decorated_definition` around either is the definition range; module-level `NAME = ...` in upper case CONSTANT | `call` on an identifier or an attribute's last name; `class` bases |
  | TypeScript, TSX, JavaScript | `class_declaration` and `abstract_class_declaration` CLASS; `method_definition` and signatures METHOD; `function_declaration`, `generator_function_declaration`, and a `const`/`let` declarator whose value is an arrow or function expression FUNCTION; `interface_declaration` INTERFACE; `enum_declaration` ENUM; `type_alias_declaration` TYPE; `internal_module` and `module` MODULE; class fields FIELD | `call_expression` on an identifier or a member's property; `new_expression`; type identifiers in annotations; `extends` and `implements` clauses |
  | Go | `function_declaration` FUNCTION; `method_declaration` METHOD with `@scope` the receiver type; `type_spec` STRUCT, INTERFACE or TYPE by its type; top-level `const_spec` CONSTANT and `var_spec` VARIABLE | `call_expression` on an identifier or a selector's field; type identifiers |
  | Rust | `struct_item` and `union_item` STRUCT; `enum_item` ENUM; `trait_item` INTERFACE; `type_item` TYPE; `function_item` FUNCTION, or METHOD in a trait or in an `impl` (`@scope` the self type); `mod_item` MODULE; `macro_definition` MACRO; `const_item` and `static_item` CONSTANT; struct fields FIELD | `call_expression` on an identifier, a field or the last segment of a scoped identifier; `macro_invocation`; the trait and type of an `impl` |

- **Identity.** A tags definition gets a symbol string in SCIP's grammar, under the scheme `reef-tags`, with an empty package (`reef-tags . . . `). Its descriptors are the file's path components as namespaces, then the chain of enclosing definitions: `/` for a module, `#` for a class, struct, interface, enum or type, `().` for a function or method, `.` for a field, variable or constant, and `!` for a macro. Names are escaped with backticks as SCIP escapes them. For example, `` reef-tags . . . src/`parser.py`/Parser#parse(). ``. **Go is scoped by its directory, not its file** (a package is a directory), so `` reef-tags . . . pkg/store/Store#Close(). `` is the same symbol in whichever file of `pkg/store` declares it, as Go's identity is. Two definitions with one string are two definitions of one symbol: overloads, Python's conditional definitions, Go's build-tagged variants. There are no disambiguators. A tags reference has no symbol (`symbol` empty), only its `name`. Resolving it by name is R2.15's heuristic.
- **The enclosing definition** of every occurrence is the innermost definition whose definition range contains it, computed by range containment after extraction for both sources. For a reference, that is the caller, which is what "affected call sites" means in R2.15.
- **Ranges** are 0-based lines and UTF-8 byte columns, with the end exclusive. `range` is the name and `definition_range` the whole definition node, which is set for definitions only.
- **A digest per definition**: the first 8 bytes of blake3 over the definition range's bytes, stored and not exposed. It lets R2.15 tell a changed body from an unchanged one without reading either blob.
- **Skips**, recorded as an entry with no occurrences so they are not retried: over `max_file_size` (`TOO_LARGE`); a NUL in the first 8 KiB (`BINARY`); a parse that has not finished in 1 s, stopped through `ParseOptions`' progress callback (`PARSE_TIMEOUT`); more than 100,000 occurrences (`TOO_MANY_OCCURRENCES`). A conflicted path is counted as `CONFLICTED` in the tree's coverage and stores nothing. Symlinks and submodules are never read. A parse with error nodes is kept, with `has_errors` set on the entry, since tree-sitter recovers and most of the file's tags survive.

### SCIP ingestion

- **One unary RPC, called in batches.** `UploadScipDocuments` carries up to 1,000 documents and must stay under tonic's 4 MiB (ADR 0029: no client streaming). Each document is `{ path, content_digest, document }`. `path` is repository-relative. `content_digest` is the blake3 hex of the bytes the indexer read. `document` is one encoded `scip.Document`, opaque to the API. The API does not import SCIP's schema. SCIP changes on its own schedule, and its naming would fail buf's lint. The daemon decodes with its vendored copy, which ignores unknown fields. Batches are independent: no session, no commit step, and a failed batch is retried by itself.
- **Each document is checked against the revision's tree** and then accepted or rejected alone. The request still succeeds when every document is rejected. The checks, in order: the path passes `files::check_path` (`INVALID_PATH`); it is unique in the request (`DUPLICATE_PATH`); the tree holds something there (`PATH_NOT_FOUND`) that is a file or an executable, not a symlink, directory, submodule or conflict (`NOT_A_FILE`); its size is within `max_file_size` (`FILE_TOO_LARGE`); blake3 of the blob equals `content_digest` (`CONTENT_MISMATCH`, which also covers a malformed digest); the bytes decode as a `scip.Document` (`INVALID_DOCUMENT`); there are at most 100,000 occurrences after locals are dropped (`TOO_MANY_OCCURRENCES`); and every range lies within the file once converted (`RANGE_OUT_OF_BOUNDS`).
- **Why a digest and not trust.** A document has no hash of its own. An indexer run before an edit and uploaded after it would otherwise describe the wrong text, with ranges that look plausible. The uploader has the files the indexer read, and the daemon has the blob, so comparing the two is exact. blake3, not the git blob id, because it does not depend on the backend (R4.03 changes object ids) and the client links no SHA-1.
- **Normalization.** Positions are converted to UTF-8 byte columns using the blob's lines. An unspecified encoding is UTF-16 for tools named `scip-typescript` or `scip-python` (both are built on TypeScript compilers) and UTF-8 for any other tool. A typed range wins over the deprecated `repeated int32` one, and both three- and four-element forms are read. `local N` symbols, diagnostics, documentation, syntax kinds, relationships and `external_symbols` are dropped. The kind comes from the document's `SymbolInformation.kind`, mapped to `SymbolKind`, else from the last descriptor's suffix. The name is `display_name`, else the last descriptor's name. Roles map Definition to `DEFINITION` and anything else to `REFERENCE`, with Import, WriteAccess, Test and Generated kept as flags. A definition with no enclosing range takes the definition range of the tags definition whose name range equals its range, when the language is one of the four. Otherwise its definition range is unset.
- **Stored** as the entry `(path, file id, SCIP)`. The extractor string is the tool's `name/version`, and an upload replaces any SCIP entry for the same path and file id. The entry applies to every tree that has that file at that path. That is right for its definitions. Its references to other files' symbols were resolved against the uploaded revision's dependencies, which a later tree may have changed. ADR 0042 records this as a known approximation (see Risks).

### The store

- **One SQLite file per repository**, `repos/<repo-id>/symbols.sqlite3`, not a table in `reef.sqlite3`. The index can reach gigabytes. `reef.sqlite3` is one mutex-guarded connection that lease heartbeats share, and backup copies it whole, but the index is a cache that is rebuilt rather than restored. ForgetRepository deletes it with the directory. Backup does not copy it, and the backup tests assert that. A restore rebuilds it on demand. Its connections: one writer behind its own mutex, and up to `workers + 2` readers, in WAL mode with `synchronous = NORMAL` and `auto_vacuum = INCREMENTAL`.
- **No migrations.** `meta.format` is `1`. A file whose format differs, or that fails to open as a database (`NOTADB`, `CORRUPT`), is deleted and recreated, with a `warn` naming the cause. `reef.sqlite3`'s `SCHEMA_VERSION` stays 5.
- **Tables:**

  ```sql
  CREATE TABLE meta (key TEXT PRIMARY KEY, value TEXT NOT NULL);
  CREATE TABLE names (id INTEGER PRIMARY KEY, name TEXT NOT NULL UNIQUE);
  CREATE TABLE symbols (id INTEGER PRIMARY KEY, symbol TEXT NOT NULL UNIQUE,
                        name INTEGER NOT NULL REFERENCES names(id));
  CREATE TABLE files (id INTEGER PRIMARY KEY, path TEXT NOT NULL, file_id BLOB NOT NULL,
                      source INTEGER NOT NULL,          -- 1 tags, 2 SCIP
                      extractor TEXT NOT NULL, language TEXT NOT NULL,
                      skip INTEGER,                      -- NULL, or the SymbolSkipReason
                      has_errors INTEGER NOT NULL, occurrences INTEGER NOT NULL,
                      created_day INTEGER NOT NULL, used_day INTEGER NOT NULL,
                      UNIQUE (path, file_id, source));
  CREATE TABLE occurrences (file INTEGER NOT NULL, seq INTEGER NOT NULL,
                      symbol INTEGER, name INTEGER NOT NULL, role INTEGER NOT NULL,
                      kind INTEGER NOT NULL, flags INTEGER NOT NULL,
                      line INTEGER NOT NULL, col INTEGER NOT NULL,
                      end_line INTEGER NOT NULL, end_col INTEGER NOT NULL,
                      def_line INTEGER, def_col INTEGER, def_end_line INTEGER, def_end_col INTEGER,
                      enclosing INTEGER,                 -- seq of the enclosing definition
                      digest INTEGER,                    -- definitions only
                      PRIMARY KEY (file, seq)) WITHOUT ROWID;
  CREATE INDEX occurrences_by_symbol ON occurrences (symbol, file) WHERE symbol IS NOT NULL;
  CREATE INDEX occurrences_by_name ON occurrences (name, file);
  CREATE TABLE trees (tree TEXT PRIMARY KEY, commit_id TEXT NOT NULL, state INTEGER NOT NULL,
                      files INTEGER NOT NULL, indexed INTEGER NOT NULL, skipped TEXT NOT NULL,
                      languages TEXT NOT NULL, scip_files INTEGER NOT NULL,
                      indexed_at INTEGER, used_day INTEGER NOT NULL);
  ```

  Symbol strings and names are interned, since a SCIP symbol string is often 60 to 120 bytes and repeats in every reference. `seq` is source order. `skipped` and `languages` are small JSON objects of counts. Days are days since the Unix epoch, so a read updates `used_day` at most once a day per entry.
- **Writes** are batched: a worker commits every 64 files or every 100 ms, whichever comes first. A file's rows are written in one transaction, so a reader never sees half a file.
- **Coverage is a hint, not a promise.** A tree's `state` becomes `COMPLETE` when a pass has found or written an entry for every supported file. GC can later remove entries such a tree uses. So every read looks up each file's entry and extracts a missing one on the spot (bounded, below). The index heals itself, and nothing trusts `COMPLETE` blindly.

### Lookups (for this ticket's RPC and for R2.15, R2.16 and R3.38)

`symbols::query` provides `file_symbols(repo, path, file_id, source) -> Option<FileSymbols>`; `in_tree(repo, tree, Lookup::{Symbol(s), Name(n)}, after) -> page`; and `ensure(repo, commit, Scope::{Paths(..), Tree}, deadline) -> Status`. `in_tree` finds candidate entries through the symbol or name index, joined to `files` in `(path, seq)` order after the cursor. It keeps a candidate only when the tree holds that file id at that path. That check is a `path_value` lookup, cached per path for the page. Older versions of a file therefore never leak into a tree's results.

### `IndexSymbols`

Resolves the revision, starts or joins the tree's pass, and waits up to `wait`, which defaults to 10 s when unset, returns at once when 0, and is capped at 10 minutes. It returns the tree's `SymbolIndexStatus`: state, supported file count, indexed and skipped counts by reason, SCIP files, and files by language. A pass outlives its RPC and finishes in the background. `wait: 0` is the status query. `ACCESS_READ` and `IDEMPOTENT`: it records no operation, and what it writes is derived and rebuildable.

### `ListSymbols`

- **By path**: `path` names a file or a directory prefix, matched by whole components as `GetDiff.paths` is. The occurrences of the files under it come in jj's path order, then by position. When at most 1,000 files in scope have no entry, they are extracted inline. Past that it fails with `SYMBOLS_NOT_INDEXED`, metadata `commit_id` and `missing`, and `next` `reef symbols index -r <commit_id>`.
- **By name or symbol**: `name` (exact display name) or `symbol` (an exact symbol string) across the tree, or under `path` when that is set too. This needs the tree `COMPLETE`, else `SYMBOLS_NOT_INDEXED`. It is the lookup R2.15 needs for call sites. It is exposed here because it costs nothing more and is the clearest proof that ingestion holds.
- **Filters**: `roles` and `kinds`, ORed within each field and ANDed across fields (ADR 0029). `source` set to `TAGS` or `SCIP` forces that source. Unset means per file: SCIP if present, else tags. A name query that forces SCIP never returns a tags reference.
- **Refusals**: `INVALID_SYMBOL_QUERY` (`INVALID_ARGUMENT`, metadata `field`) for an empty `path` with neither filter, for `name` and `symbol` both set, or for a `symbol` that does not parse in SCIP's grammar.
- **Pages** follow ADR 0029 and 0030: `page_size` 0 means 100, and above 1,000 means 1,000. The token is bound to the request and pins the operation, and it carries the last `(path, seq)`. A page stops before 3 MiB. `ACCESS_READ`, `IDEMPOTENT`.

### Errors and reasons

| Reason | Kind | Metadata | RPCs |
| --- | --- | --- | --- |
| `SYMBOLS_DISABLED` | `FAILED_PRECONDITION` | | all three |
| `SYMBOLS_NOT_INDEXED` | `FAILED_PRECONDITION` | `commit_id`, `missing` | `ListSymbols` |
| `INVALID_SYMBOL_QUERY` | `INVALID_ARGUMENT` | `field` | `ListSymbols` |
| `INVALID_UPLOAD` | `INVALID_ARGUMENT` | `field` (`documents` for none or more than 1,000, `tool` for an empty tool name) | `UploadScipDocuments` |

All three RPCs also return R2.02's revision, workspace and `at_operation` reasons, and `ListSymbols` returns `INVALID_PAGE_TOKEN` and `INVALID_PATH`. Hints: `SYMBOLS_DISABLED` says "Set `[symbols] enabled = true` in config.toml and restart the daemon." `SYMBOLS_NOT_INDEXED` says "Index the revision first; a large repository's first index takes a while." with the `next` above. Per-document SCIP rejections are values of `ScipRejection` in the response, not errors.

`UploadScipDocuments` is `ACCESS_WRITE`: a read-only token (R2.08) must not be able to plant symbol data that others read. It records no operation, so it joins decision 12's list of exceptions. ADR 0042 says so, and `options.proto`'s `ACCESS_WRITE` comment gains "or the symbol index". That is a comment rewording, which the digest ignores. `uint32` is enough for positions; counts are `uint64`. A request with all 1,000 documents is rejected early when its encoded size passes 4 MiB: `Client::upload_scip_documents` checks before sending (`ClientError::TooLarge`, R2.04).

### CLI

- **`reef symbols index [-r REV] [--wait DUR]`**: prints the status. Exits 0 when the state is `COMPLETE`. Otherwise it exits 6 (`Unavailable`: try again), with `hint` "Indexing continues in the background." and `next` the same command with a longer `--wait`. `--wait` defaults to 10 s, as the RPC's does.
- **`reef symbols upload <FILE> [-r REV] [--root DIR] [--prefix PATH]`**: reads the SCIP index and splits it with `reef_client::scip`. Each document's repository path is `--prefix` (default: the indexer's `project_root` relative to the repository root, when it is a `file://` URI inside it, else empty) joined to its `relative_path`. Each digest is blake3 of `--root` (default: `project_root`, else the current directory) joined to the `relative_path`. A file that cannot be read is skipped and reported, not sent. Batches hold at most 1,000 documents and 3 MiB, and a single document over 3 MiB is skipped and reported. The JSON object is `{commit_id, accepted, rejected: [{path, reason, message}], skipped: [{path, reason}], status}`. Exits 0 when anything was accepted, and 2 (`InvalidArgument`) when nothing was, with the first rejection's reason in `hint`.
- **`reef symbols list [PATH] [-r REV] [--name N | --symbol S] [--kind K]... [--definitions | --references] [--source tags|scip] [--limit N]`**: text lines `path:line:col  kind  role  name` (1-based for people), or JSON with the API's 0-based ranges. Each command's default revision follows R2.27's scope rule, as `reef file read` does. `sym` is an alias. Help texts are within `help_text_is_short`. `reef guide` is unchanged (its token budget). `target/cli-shape-<os>.json` gains the group.
- **No MCP tool.** `tools/list` has no room left (17 bytes under 20,000). R2.15 decides whether `get_diff` gains a symbols flag, and pays for it there.

### GC

A fifth per-repository step in `maintenance/gc.rs`, `symbols`, after the four Phase 1 steps. It runs under GC's lock, with no create lock, since it touches no workspace. It runs on #95's timer once that lands.

1. **Mark**: the live trees are trunk's tree plus every active workspace's working-copy commit tree, deduplicated. Walk trunk's supported files and set `used_day = today` on their entries, then each other live tree through `changed_files` from trunk. Only the diffs are walked, not every tree.
2. **Sweep**: delete `trees` rows used before `keep_newer` that are not live. Delete entries (with their occurrences) whose `used_day` is before `keep_newer`, and every entry whose extractor is not current. Then delete names and symbols no occurrence references.
3. **Cap**: while the file is larger than `max_size`, delete unmarked entries in `used_day` order, oldest first, in batches of 1,000 entries. Then run `PRAGMA incremental_vacuum`. Marked entries are never evicted. A repository whose live trees alone pass the cap keeps them and logs a `warn` naming `max_size`.

It logs one `info` line with the bytes before and after and the entry counts. `GcReport` gains no field, so the schema stays as above. A sweep or a cap can leave a `COMPLETE` tree incomplete, and the next read re-extracts what it needs.

## Implementation notes

- Order: reef-symbols with tests 1 to 9 (write the queries against the goldens first); `files::walk_files` and `changed_files` with test 10; the store and a tree pass with tests 12, 13 and 17; the schema, handler and client with tests 15, 16, 20 and 21; background with test 14; GC with tests 18 and 19; the CLI with tests 11 and 22; benches, the hostile test, and the documents.
- Check `df -h` before the first build: five grammars add C objects to `target/` in debug and release, and the disk has filled before.
- tree-sitter 0.25 and later drop `Parser::set_timeout_micros`. Use `parse_with_options` and a progress callback that checks an `Instant`. `QueryCursor::matches` returns a `StreamingIterator`. Reuse one `Parser` and one compiled `Query` per language per worker thread. Compiling the TypeScript query costs milliseconds and must not happen per file.
- `ensure`'s single flight is a `HashMap<(RepoId, TreeKey), Shared<…>>` guarded by a mutex, removed when the pass ends. `IndexSymbols` awaits the shared future with a timeout.
- Never hold the store's writer mutex across a blob read or a parse. Extract first, then write.
- The priority calls are `cfg(target_os = "linux")` and `cfg(target_os = "macos")` code, so macOS never compiles the Linux branch. Before pushing, run `CARGO_BUILD_WARNINGS=deny cargo build --workspace --all-targets` and clippy with and without `--all-features` in the privileged `ubuntu:24.04` container (`docs/benchmarks.md`, "Linux"), and `cargo nextest run -p reef-daemon --test symbols` there.
- Run R1.23's load test once on `medium` with `REEF_LOAD_SYMBOLS=1` and compare with `docs/load-tests.md`'s baseline. The synthetic files are about 70% grammar input, so this is the realistic worst case for background indexing under 200 workspaces. Record the result in the PR.

## Departures in the implementation

Found while implementing (2026-10-28). The decisions above are as written; these are where the code differs, and why.

- **A pass diffs from the first parent's tree only, not trunk's.** Resolving `trunk()` needs a revset scope, which a background pass does not have. A workspace's change usually sits on trunk, so its first parent's tree is trunk's. With no complete parent the pass walks the tree, and every file whose entry exists is still skipped.
- **Use times are milliseconds, `created_at` and `used_at`, not days.** With days, GC with a zero undo window could not tell an entry it had just marked live from one used earlier that day. GC marks unconditionally. Reads refresh `used_at` at most once a day, as the brief intended.
- **GC's live trees are every working-copy commit in the view,** the user's own jj workspaces included, not trunk's tree plus the active Reef workspaces. The view lists them without a revset, and a user's working copy is as live as an agent's.
- **Background notices come from hooks.** Snapshots notify through the scheduler's `on_snapshot` hook (as R2.10's editing entries do) rather than `record_commit`, and `EditFiles` notifies from its handler rather than from the `Write::Edit` arm. Both see every commit the brief names, and neither touches the write path.
- **`reef_lib::jj::files` grows a little more than listed:** `commit_tree`, `commit_and_parent_trees`, `tree_file`, `working_copy_commits`, `ChangedFile` with both sides (the incremental counts need the old side), and `Tree` re-exported. `read_file_id` takes a `&str` path, because the daemon does not link jj-lib's path types.
- **Tags references get kinds:** a call is `FUNCTION`, `new` and `extends` targets are `CLASS`, type references are `TYPE`, an `impl`'s trait is `INTERFACE` and a macro invocation is `MACRO`. The brief left references' kinds unspecified. A TypeScript `constructor` is not a definition, as upstream's query has it.
- **A tree's `scip_files` is as of its last pass or upload.** An upload covers `(path, content)` in every tree, but only the uploading tree's row is updated. Others catch up at their next pass. The proto comment says so.
- **With JSON, a failing `symbols index` or `upload` prints only the error object,** so stdout holds one value. In text mode the status or result is printed before the error lines.
- **The `extract` bench repeats the test fixtures** to about 2,000 lines, rather than checking in four new 2,000-line files. Rust's is Reef's `reef-lib/src/jj/files.rs`, as written.
- **`ListSymbols` of a path that names nothing is empty,** not `PATH_NOT_FOUND`. A directory prefix may legitimately hold no supported file, and the brief lists no such reason.
- **Added after review (R2.14's PR):**
  - **Tree rows are dropped whenever entries they may use are deleted.** GC's sweep and cap drop every row but the live trees', and an outdated extractor drops all of them. `meta.extractors` records the extractor set, and a store opened under another set drops every row. A `COMPLETE` row is never older than its entries, so a name query never answers from part of a tree.
  - **GC's cap estimates the index's size from the share of occurrences left.** Deletes leave B-tree pages part full, so the live page count falls far more slowly than the data would suggest. The cap prunes names and symbols after batches 1, 2, 4, 8 and so on, rather than once per batch. It steps `PRAGMA incremental_vacuum` to completion.
  - **At most two passes run at once,** and passes stop between batches at shutdown.
  - **`by_path` walks only the requested path** (`files::walk_files_in`). It reads each entry together with its occurrences in one transaction. Writing identical tags again keeps the existing entry.
- **Open question 1, resolved:** `background` stays on everywhere. R1.23's `medium` profile with it on passed the gate with a steady-state p95 of 767 ms, against 739 ms with it off, run back to back, and an unchanged burst ([`load-tests.md`](../../load-tests.md)). `large` indexes in 92 s.
- **Open question 2, resolved:** `scip-typescript` 0.5.2 and `scip-python` 0.6.8 both leave `position_encoding` unset and count UTF-16 code units, as the rule assumes. Their real output is checked in under `crates/reef-symbols/tests/fixtures/scip/`, and test `scip_normalize::real_indexer_output` reads it. `scip-python` needs a git repository and `--project-version`. Without them it hits a fatal error and writes an index with no documents, which an upload then reports as nothing accepted.
- **Test 19 checks a garbage file and `ForgetRepository`.** A file of another `meta.format` takes the same code path. Backup copies only the paths its layout lists, so `symbols.sqlite3` is never copied, and no separate backup assertion was added.

## Out of scope

- Symbol-level diffs, matching symbols across renames, and resolving tags references (R2.15); history queries and any table joining symbols to changes or operations (R2.16); symbol search in a UI (R3.38).
- Running SCIP indexers in the daemon; uploading tags; languages beyond the six file types; SCIP relationships, documentation, hover text, diagnostics and external symbols.
- An MCP tool; SDK wrappers (R2.06, R2.07 wrap the client methods).
- Backing the index up, sharing it between machines, and the store's symbol index (Phase 4).
- Access scopes for remote callers (R2.08 applies the access levels declared here).

## Risks

- **Tags are syntax, not semantics** (the design's open risk). A tags reference is a name, so call sites resolved from tags over-match common names and miss calls through aliases. The `reef-tags` identity also changes when a file moves. R2.15 must say which source each answer came from. SCIP is the precise path.
- **A SCIP entry is reused across trees.** Its definitions are right for any tree that holds the same file, but its references may name symbols as they resolved at the uploaded revision. Uploads per revision (CI) keep that window small, and the response's `source` lets a caller tell.
- **The unspecified position encoding is a heuristic.** Indexers that set it are read exactly. The tool-name rule covers the two known older producers, and a wrong guess shows up as `RANGE_OUT_OF_BOUNDS` or shifted columns on non-ASCII lines only.
- **C parsers in the daemon.** A grammar bug could crash the daemon on hostile content. tree-sitter is widely run on untrusted code, and the size cap, timeout and test 9 bound the exposure. Running extraction in a child process is the fallback if a crash is ever seen.
- **Background CPU.** A first index of a large repository is minutes of CPU on up to four low-priority threads. The load-test run measures the steady state, and `background = false` turns it off.
- **Binary size and build time grow** by the grammars. The PR measures both. `reef` is unaffected by construction.

## Choices this brief made, and why

- **Key by path and content, not by snapshot**: the tree already is the map, and copying it per snapshot would make the index proportional to snapshots times files.
- **A separate, disposable database**: the index is a cache by the design's own table, and it must neither bloat backups nor share the metadata connection's mutex with lease heartbeats.
- **The daemon tags, callers upload SCIP**: the exit criterion needs symbols without any setup, and SCIP needs toolchains only the caller has.
- **Reef's own queries**: upstream ones cannot tell `A::close` from `B::close` in two of the four languages.
- **A blake3 digest per document**: the only exact check that an index describes the bytes in the tree.
- **Opaque SCIP bytes in the API**: the API stays Reef's, reviewed and lint-clean, while SCIP evolves on its own.
- **Name and symbol lookups now**: they are the call-site query R2.15 needs and the proof that ingestion works, at no extra storage.

## What later tickets inherit

- **R2.15** calls `SymbolIndex::ensure` for both sides of a diff and `query::file_symbols` per changed file. It compares definitions by `symbol` and `digest`, and finds call sites with `in_tree` by symbol (SCIP) or by name (tags), taking `enclosing` as the affected caller. It must compare both sides with one source, which means tags unless both sides have SCIP, or every file that gains an upload shows as rewritten. It decides `GetDiff`'s symbol fields (`diff.proto` reserves them) and whether the MCP diff tool gains a flag within the budget.
- **R2.16** attaches `symbols.sqlite3` (`ATTACH DATABASE`) beside `reef.sqlite3` for its SQL, and owns any table of symbol changes per commit.
- **R3.18** treats a tree that is not `COMPLETE` as "the index is missing" and falls back. **R3.38** builds its search on `ListSymbols` by name.
- **R2.08** scopes `UploadScipDocuments` as a write. **R4.x** reuses `reef-symbols` for the store's index. **Phase 5** shares its grammars with structural merge.

## Open questions

1. **The default for `background` on very large repositories.** This brief turns it on everywhere. If the load-test run or the `large` bench shows the first index starving snapshots, the fallback is to default it off above `watcher.watchman_threshold_files` (50,000 files) and index those repositories on demand only. The implementer decides from the measurement and records the result in ADR 0042.
