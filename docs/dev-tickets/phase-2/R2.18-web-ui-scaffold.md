# R2.18 Web UI scaffold

Phase 2 · Size L (the row says M; see "Size") · Depends on: R2.09 (`SubscribeOperations`, its cursor, `live` and resume), R2.10 (`SubscribePresence`, its set-then-changes contract and `synced`), R2.05 and R2.27 (the thin CLI, its JSON and error conventions) · Unblocks: R2.19 (smartlog), R2.20 (workspaces and fleet panel), R2.21 (activity feed), R3.31, R3.34, R3.35, R3.36, R3.38 (the later views), R2.08 (the gate, the session check and the assets the remote listener reuses), R3.39 and R3.40 (the shells that wrap the same app)

## Context

The design gives humans one web application: "React and TypeScript, one codebase served by the daemon and by remote stores", with a "generated gRPC-web client from the protobuf schemas" (`docs/design.md`, Technology choices). It runs in a browser against the local daemon, and later inside the Tauri shells for desktop and mobile (ADR 0005, R3.39, R3.40). "Both surfaces subscribe to the operation log and the presence channel and never fetch on a timer", and five rules apply everywhere, the first being "one state color per object, used everywhere. Draft, proposed, queued, testing, landed, failed, conflicted" (Live by default).

Nothing of that exists. The daemon listens only on a Unix socket, which a browser cannot reach. The trust model is "one uid is one trust domain, the socket is the authorization" (ADR 0027, `docs/threat-model.md`). The threat model's "Requirements for a remote listener" say any listener that is not the socket must satisfy five requirements before it serves an RPC. The repository has no JavaScript, no Node toolchain and no way to ship static files in a binary.

This ticket builds the foundation every view stands on. It covers:

- an app in `web/`, built by CI and the release workflow into static assets that a new crate, `reef-web`, embeds in the daemon (a Node-free `cargo build` embeds a placeholder page instead);
- a loopback listener in the daemon, started on demand, serving those assets and the read side of the API over gRPC-web, behind a per-session token and browser-origin checks;
- `reef ui`, which opens a browser on a session without putting the token on any command line;
- the stream layer later views share, the state-color system, and one live view (registered repositories with their latest operation and active agents) that proves the pipe end to end without taking R2.19's, R2.20's or R2.21's views.

R2.01's rule binds this brief: it adds one RPC and five reasons and changes nothing declared.

The user decided this brief's open questions on 2026-10-31; "Decisions (2026-10-31)" at the end records them, and the brief is written to them.

## Decisions

### Size

L. The row's three items each grew in the writing:

- "Served by the daemon" means a second listener with its own security model, which the threat model says must exist before any RPC is served off the socket. That is a gate, sessions, a launch path that keeps the token out of command lines, an ADMIN RPC, a CLI command, and threat-model rows with tests.
- "React and TypeScript app" means a Node toolchain beside a Rust-only build: a CI job, a release job whose assets every target embeds, and a placeholder so `cargo build` still needs no Node.
- "A bridge for streams" means a stream layer that keeps R2.09's "nothing dropped" and R2.10's "set then changes" contracts in a browser, within a browser's six connections per origin.

Add the state colors, one live view, an ADR and about thirty tests. That is R2.10's breadth.

It is not more than L, so it is not split. The views are R2.19 to R2.21, remote access is R2.08, and the app has two routes and one live view. Splitting the daemon side from the app was considered and rejected: neither half can be tested end to end without the other, and the row is one deliverable.

### Where the line with R2.19, R2.20 and R2.21 is

- **R2.18 ships** the app shell (layout, routing, connection, error display, theme), the stream layer, the state-color system with a reference page, and one live view: the **overview** at `/`. It lists registered repositories, each with its latest operation (kind, agent, workspace, time) and the number of agents active in it now, updating live from both streams. It is the page R2.19 to R2.21 link their per-repository views from.
- **R2.19** draws changes and stacks as a graph (`ListChanges`, the state colors' first real consumer). **R2.20** lists workspaces with owner, lease, disk and presence, and agents with their current change. The overview shows a count of agents per repository, not who they are or what they hold. **R2.21** shows the operation feed, its coalescing and counts, and the scrubber over R2.12. The overview shows one operation per repository, not a feed or history.
- Every overview element R2.21 or R2.20 will make a link (an operation, an agent) is rendered as text with its id here. The design's "every live element links to its cause" is met when those views exist, and this brief says so rather than adding placeholder routes.

### Transport: gRPC-web through `tonic-web`, not a WebSocket bridge

The browser speaks gRPC-web, binary framing only (`application/grpc-web` and `application/grpc-web+proto`), through `tonic_web::GrpcWebLayer` on the daemon and Connect-ES's gRPC-web transport (`@connectrpc/connect-web`, with `@bufbuild/protobuf` messages generated by `protoc-gen-es`) in the app. The reasons:

- **Flow control holds end to end.** Connect-ES reads a streaming response through `fetch`'s `ReadableStream`. A tab that stops reading stops the browser reading the socket, TCP pushes back, and R2.09's session is held back by its channel of one, as for any client. The browser's `WebSocket` API has no backpressure: `onmessage` fires whether or not the page keeps up (`WebSocketStream` is not in Firefox or Safari). A bridge would have to buffer without bound in the tab or drop and coalesce in the daemon, breaking R2.09's "nothing dropped" for exactly the client the design has in mind.
- **No second protocol.** gRPC-web is the API itself. The same request and response messages, errors with `ErrorDetail` (ADR 0029 decision 14), access levels and revision checks all apply, and the same tests cover them. A WebSocket bridge would be a protocol of Reef's own to design, version, document and secure: cross-site WebSocket hijacking, since browsers apply no same-origin rule to the handshake, and its own framing for errors and keepalives.
- **R2.08 needs it anyway.** The remote listener must "serve the same API and web UI". With TLS, browsers negotiate HTTP/2 by ALPN, and `GrpcWebLayer` serves browsers and native gRPC clients on one port (`tonic-web`'s own documentation). A bridge would be a third surface R2.08 has to secure.
- **Cost.** `tonic-web` is tonic's own crate at tonic's version. Its nine small dependencies are all already in the lockfile, and all are MIT or Apache-2.0. It is a tower layer, so it composes with the gate below.

What it costs, and how this brief pays:

- **No client streaming.** The schema already has none (ADR 0029 decision 13).
- **HTTP/1.1 on loopback.** Browsers speak HTTP/2 only over TLS, so on `http://127.0.0.1` each open stream holds one of the browser's six connections per origin, shared by every tab. Three tabs with two streams each would leave no connection for unary calls. The stream layer therefore opens at most one operation stream and one presence stream per browser, shared across tabs ("The stream layer"). Remotely, over TLS, HTTP/2 lifts the limit.
- **Base64 text mode is refused.** `application/grpc-web-text` exists for clients that cannot read binary streams. Connect-ES reads binary, and refusing text halves what the gate must handle (`415`).

### The listener: loopback, on demand, the web UI only

- **Where.** `[ui] listen`, default `127.0.0.1:0`: a port the kernel picks, new at every daemon start. Only an IP literal in `127.0.0.0/8` or `::1`, with a port, is accepted. `localhost`, `0.0.0.0`, `::` and any other address are a configuration error, naming R2.08's remote listener as the way to listen elsewhere. A fixed port (`127.0.0.1:7878`) is allowed, for an SSH forward or a bookmark.
- **When.** The listener is bound by the first `CreateWebSession`, not at start. A daemon whose user never runs `reef ui` opens no TCP port. Once bound it stays bound until the daemon stops: a tab's origin is its port, so rebinding would orphan open tabs. If the bind fails (the fixed port is taken, say), `CreateWebSession` fails with `WEB_UI_UNAVAILABLE` naming the address, the daemon serves the socket as before, and the next `CreateWebSession` tries again. There is never a fallback to another port, because a port the user did not choose cannot be assumed to be Reef's.
- **Off.** `[ui] enabled = false` makes `CreateWebSession` fail with `WEB_UI_DISABLED`, and nothing is ever bound. Default `true` (decision 2).
- **Not built.** A daemon built without the app (`!reef_web::BUILT`, "Serving the assets") makes `CreateWebSession` fail with `WEB_UI_NOT_BUILT`, and nothing is bound, so `reef ui` never opens a page that cannot work. The checks run in this order: enabled, built, bind.
- **What it serves.** The embedded assets (GET and HEAD), and gRPC-web calls to `ACCESS_READ` methods with a valid session. Everything else is refused (see the gate, below). It does not serve native gRPC, the `reef.daemon.v0` beacon, any WRITE or ADMIN method, CORS, WebSockets or `OPTIONS`.
- **How.** A second tonic server over the same services: `server.rs` splits `router` into `routes(state) -> Routes` (the 14 services, so `SERVED` and its test stay one list) and the socket's `router`, which is `Server::builder().layer(CompatLayer).add_routes(routes(state))`, unchanged in behavior. The web server is `Server::builder().accept_http1(true).layer(WebGateLayer).layer(GrpcWebLayer::new()).layer(CompatLayer).add_routes(routes(state))`, served with `serve_with_incoming_shutdown` on `AppState::shutdown`. `limits::Accepting` becomes generic over the listener (`UnixListener`, `TcpListener`), so the TCP accept loop backs off at the open-file limit too. The TCP accept loop also caps open connections at 64 (`web::Limits::max_connections`): one more is accepted and closed at once, with a `warn` at most every 10 s. A shutdown hook joins the web server within `SHUTDOWN_GRACE` and then aborts it, as `supervise` does for the socket's server.
- **One state.** Both servers share one `AppState`, so the subscription cap, the broker and presence are shared. A browser's streams count against the 1,024 subscriptions like any client's.

### The session: a bearer token per `reef ui`, alive while the daemon is

- **Minting.** `DaemonService.CreateWebSession` (ADMIN, over the socket only) binds the listener if needed and mints a session. The session's token is 32 bytes from the OS-seeded CSPRNG (`rand`'s thread RNG), base64url without padding (43 characters). The daemon keeps only `blake3(token)` as the session's key, so comparing a presented token is a hash-map lookup on a digest and never a byte comparison on the secret. Each session records its creation, its last use, and whether its launch file is pending.
- **Lifetime.** A session lives until the daemon stops, or until 24 hours pass with no request on it and no stream open on it (`web::Limits::session_idle`). Sessions are never persisted, so a daemon restart ends every session. At 32 live sessions (`web::Limits::max_sessions`), minting one more ends the least recently used. Minting is ADMIN over the socket, so only the user can churn sessions, and refusing them would lock the user out of their own UI.
- **Why per process, not persisted.** A tab left open across a daemon restart keeps retrying its port. While the daemon is down, any local user can bind that port: the port was visible in `netstat`, and nothing reserves a port for a stopped process. The tab would then send its token to the squatter. A token that died with the old daemon is worth nothing to the squatter. A persisted secret would be worth every registered repository.
- **Presenting it.** Every gRPC-web request carries `authorization: Bearer <token>`, set by a Connect interceptor. The gate removes the header before the request reaches tonic, so no handler, log line or error message ever sees it. There are no cookies: cookies are scoped to a host and not a port, so a cookie set by `127.0.0.1:<port>` would be sent to any other port on `127.0.0.1`, including a server another local user runs there, the moment the user's browser is lured to it. A header set from the page's own storage goes only where the page sends it.
- **In the browser.** `localStorage` under the key `reef.session`: per origin, which includes the port, so every tab of the session shares it and a link opened in a new tab works. It is not `sessionStorage`, which is per tab, so a middle-clicked link would land on the "no session" page. Persisting it in the browser's profile costs nothing: the token dies with the daemon process, and a squatter on the same port after a restart reads only a dead token (see "Why per process"). A tab with no token shows the "no session" page, and a session that the daemon refuses (`WEB_SESSION_INVALID`) is removed from storage and shows the same page. The page's text is "This page has no session with the daemon. Run `reef ui` in a terminal."

### `reef ui`: opening a browser without the token in a command line

A token in a URL passed as an argument (`open http://...#session=...`, `xdg-open ...`) is readable by every local user through `ps` or `/proc/<pid>/cmdline` while the opener runs, and on Linux the browser it launches has it in its own argv too. The launch path avoids that.

1. `reef ui` calls `CreateWebSession { launch_file: true }` over the socket (autostarting the daemon like every command, and honoring `--no-autostart`).
2. The daemon writes `<state>/ui/open-<16 hex>.html`, mode `0600`, in `<state>/ui/`, mode `0700` (created and checked as S-01 checks the state directory). It holds a `<meta http-equiv="refresh" content="0; url=...">` to the session URL, `http://127.0.0.1:<port>/#session=<token>`, and a plain link to it, with no script. It is deleted after the first authenticated request with its token, or 60 s after it was written (`web::Limits::launch_file_ttl`), whichever is first, and every `open-*.html` left by an earlier run is deleted when the daemon starts.
3. The CLI opens the file's path, not the URL: `$BROWSER <path>` if `BROWSER` is set, else `open <path>` on macOS and `xdg-open <path>` on Linux. The browser runs as the user, reads the file, and follows the refresh. The token travels in the fragment, which browsers send in no request line and no `Referer`.
4. The app's bootstrap reads `#session=`, stores the token, and replaces the URL with `history.replaceState`, so the address bar, a bookmark, a copy-and-paste or a screenshot of the URL carries no token.

The command:

- **Usage**: `reef ui [--print | --open]`. `about`: "Open the web UI in a browser". `after_help`: "Example: reef ui --print". It sits after `presence` in `--help`, which grows to 47 lines. It is not in the agent guide.
- **On a terminal**, it opens the launch file and prints `Opened http://127.0.0.1:<port>/ in your browser.` (stdout), with no token. If the opener fails or no opener is found (no `DISPLAY` or `WAYLAND_DISPLAY` on Linux, or `SSH_CONNECTION` set), it prints the session URL instead, with a note that it is a credential. Under SSH the note also says to forward the same port (`ssh -L <port>:127.0.0.1:<port>`), since the Host check below accepts only the daemon's own authority.
- **`--print`** asks for no launch file, opens nothing, and prints the session URL. **`--open`** opens even when stdout is not a terminal.
- **Not on a terminal** (and without `--open`), it opens nothing: a command an agent runs must not pop a window on the user's desktop. It prints `{"url", "launch_path", "opened": false}` in every JSON mode (`brief` and `json` are the same small object), with no token unless `--print` is given, which adds `session_url`. `reef_client::json::WebSession` defines the object.
- **Errors** follow the CLI's contract: `WEB_UI_DISABLED` and `WEB_UI_NOT_BUILT` are exit 6 (`Conflict`), with hints naming `[ui] enabled`, and `just web-build` or a release install, respectively; `WEB_UI_UNAVAILABLE` is `Unavailable` with the address.

### The gate: what the listener accepts, in order

`WebGateLayer` sits outside `GrpcWebLayer`, so it sees every request first. It answers refusals itself and adds the response headers below to every response.

1. **Host.** The `Host` header (or HTTP/2 `:authority`) must equal the bound authority exactly: `127.0.0.1:<port>`, or `[::1]:<port>` when bound there. Anything else, `localhost:<port>` included, is `421 Misdirected Request` with an empty body, for assets and API alike. This defeats DNS rebinding: a page at `attacker.example`, rebound to `127.0.0.1`, sends `Host: attacker.example:<port>`. URLs Reef prints always use the IP literal, never `localhost`. Besides failing the Host check, `localhost` may resolve to `::1` first, where another local user could be listening on the same port number while the daemon holds only `127.0.0.1`.
2. **No upgrades, no preflight.** A request with an `Upgrade` header is `400`. `OPTIONS` is `405` with no `Access-Control-*` header, so every cross-origin preflight fails. The listener never sends an `Access-Control-Allow-Origin` header on any response.
3. **Assets.** `GET` and `HEAD` on any path that is not an API path serve from `reef-web` (see "Serving the assets"). They are public: they are the same bytes as every released binary's, they carry no secret, and `frame-ancestors 'none'` stops another page from framing them.
4. **API path and method.** A path of the form `/reef.api.v1.<Service>/<Rpc>` must be `POST`, else `405`. Any other path on `POST` is `404`.
5. **Origin.** On an API request, an `Origin` header, if present, must equal `http://<bound authority>`, and a `Sec-Fetch-Site` header, if present, must be `same-origin`. Otherwise the answer is `403` with an empty body. Browsers send `Origin` on every `fetch` `POST`, so a request from another page is refused before its token is even looked at. A request with neither header is not from a browser page. It is judged by its token alone, since a non-browser process can forge both headers anyway.
6. **Content type.** It must be `application/grpc-web` or `application/grpc-web+proto`. `application/grpc-web-text*` is `415`, and anything else, native `application/grpc` included, is `415`.
7. **Session.** `authorization: Bearer <token>` must name a live session. A missing, malformed or unknown token is refused with gRPC `PERMISSION_DENIED`, reason `WEB_SESSION_INVALID`. The header is then removed.
8. **Access.** `reef_api::access(path)` must be `Some(Access::Read)`. A WRITE, ADMIN or unknown method is `PERMISSION_DENIED`, reason `WEB_ACCESS_DENIED`, metadata `method` and `access` (`write`, `admin` or `unknown`). `CreateWebSession` is ADMIN, so a session cannot mint sessions.
9. **Pass.** The request goes to `GrpcWebLayer`, then `CompatLayer`, then the service, and the session's last use is updated. An open stream counts as in use until it ends.

Refusals in steps 7 and 8 are gRPC-web "trailers-only" responses, so Connect-ES surfaces them as typed errors with `ErrorDetail`: HTTP `200`, `content-type: application/grpc-web+proto`, and `grpc-status`, `grpc-message` and `grpc-status-details-bin` in the headers, with an empty body. They are built from the same `tonic::Status` the daemon's errors use (`crate::error`, `Status::into_http`), with the content type rewritten. Steps 1 to 6 are plain HTTP answers, because a client that fails them is not a gRPC-web client of this origin.

**Headers on every response**, assets and API:

- `Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; manifest-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`
- `X-Content-Type-Options: nosniff`
- `Referrer-Policy: no-referrer`
- `X-Frame-Options: DENY`
- `Cross-Origin-Opener-Policy: same-origin`
- `Cross-Origin-Resource-Policy: same-origin`
- `Permissions-Policy: camera=(), microphone=(), geolocation=(), usb=(), payment=()`
- `Cache-Control: no-store` on API responses and on `index.html`

The CSP has no `'unsafe-inline'` and no `'unsafe-eval'`: Vite's production build emits no inline script, and React sets styles through the DOM, which CSP does not block.

**Bounds.** Request bodies keep tonic's 4 MiB decode limit. Header blocks are hyper's default.

### The security model, stated against the threat model

The listener is the first that is not the socket, so the threat model's requirements apply to it. This brief meets them as follows, and records the result in ADR 0047 and in the threat model.

- **Other local users.** They can connect to any loopback port. They get the public assets, and every API call is refused without a token. The token is 256 bits, never in a command line, a log, a cookie, a `Referer` or a file another user can read. It lives in the user's browser storage, in a `0600` launch file for at most 60 s, and in the response to an ADMIN RPC on the user's own socket. Packet capture on loopback needs root on Linux (`CAP_NET_RAW`) and on macOS (the BPF devices are root's by default), and root is outside the model.
- **Other browser origins.** A malicious page in the user's browser can send requests to `127.0.0.1:<port>`. It cannot read the responses (no CORS), cannot send `authorization` without a preflight that fails (step 2), is refused by `Origin` before its token is looked at (step 5), and does not know the token. That covers cross-site request forgery: there are no cookies to ride on, and the API needs a header. A form `POST` cannot send `application/grpc-web` (step 6) or the header (step 7). Cross-site WebSocket hijacking is covered too: there is no WebSocket endpoint (step 2).
- **DNS rebinding.** Refused by the exact Host check (step 1), before the assets, so a rebound page cannot even read the app.
- **Port squatting.** The port is random per start by default, so a URL from an earlier run points nowhere Reef controls, and Reef never opens it. `reef ui` always gets the URL from the daemon over the socket, the one channel another user cannot answer on, so it never opens a squatter's page. A fixed port that someone else holds fails the bind, and the daemon reports it rather than moving elsewhere. A tab that outlives its daemon sends a dead token (see "The session"). Binding the exact loopback address, not a wildcard, means no more specific bind by another user can take precedence on macOS. Printing `127.0.0.1` and never `localhost` keeps the browser off `::1`, where the daemon does not listen.
- **Hostile repository content in the page.** Descriptions, paths, bookmark names and agent names come from repositories and operation logs. A cloned repository is the threat model's "repository content" actor, so it can be hostile, and script injection in the app would carry the token. React escapes text, the app never uses `dangerouslySetInnerHTML` (an ESLint error), it renders no Markdown or HTML from the API, and the CSP refuses inline and foreign scripts, so an injection that got through escaping would still not run.
- **What a leaked token buys.** Every `ACCESS_READ` RPC on every registered repository, including `ReadFile` and `GetDiff`, and the snapshots a read may take, until the daemon stops or the session idles out. No write, no admin, no registration, no path on the host outside registered repositories.

Against the requirements for a listener that is not the socket (`docs/threat-model.md`):

1. **TLS.** Not met, and not needed on loopback. TLS protects traffic between hosts, and a loopback listener has none. Encrypting loopback would need a certificate the browser trusts for `127.0.0.1`, meaning a local CA installed into the user's trust store, a worse risk than it removes. This brief amends the requirement to apply to any listener reachable from another host, and adds the loopback rules as their own subsection (decision 3). R2.08's listener still needs TLS.
2. **A per-client token with scopes.** Met: a token per session, with one fixed scope, READ. R2.08 generalizes scopes.
3. **The full API never exposed by default.** Met: READ methods only, by the schema's own classification, and the listener exists only after `reef ui`.
4. **Rate limits on the unauthenticated surface.** Met in the form loopback needs. A 256-bit token cannot be guessed at any rate, so the limit is on resources: the connection cap, tonic's body limit, and a refusal that costs one hash and one lookup. Denial of service by a local user is not a boundary in Phase 1 (threat model, "Not boundaries").
5. **Audit of every remote mutation.** Met trivially: there are no mutations. R3.31's first write from the UI brings audit with it (decision 4).

### Serving the assets: the `reef-web` crate

No built bundle and no generated code is committed (decision 1). The app is built where it ships: in CI, to test it, and in the release workflow, once, for every target. Every other build embeds a placeholder.

- **A new crate**, `crates/reef-web`, with no dependencies. `crates/reef-web/assets/` is in `.gitignore` and is where `npm run build` writes (Vite's `outDir` is `../crates/reef-web/assets`).
- **`build.rs` embeds whichever is there.**
  - When `assets/index.html` exists, it walks `assets/` in sorted order and writes `assets.rs` with one entry per file: the path, `include_bytes!` of it, the content type from a fixed map by extension (`html`, `js`, `css`, `svg`, `json`, `txt`, `woff2`, `png`, `ico`), and whether it is immutable (under `assets/assets/`, where Vite puts hashed names). It sets `BUILT` to `true`.
  - Otherwise it embeds the placeholder from `crates/reef-web/placeholder/` (committed, hand-written): an `index.html` that says "This reef-daemon was built without the web UI. Released binaries include it (install from https://github.com/reef-vcs/reef/releases). To build it from source, run `just web-build` before `cargo build`.", and one stylesheet at `assets/placeholder-0.css`, marked immutable like a hashed asset. It has no script, and it passes the same CSP. It sets `BUILT` to `false` and prints a `cargo:warning` saying the web UI is the placeholder.
  - It prints `cargo:rerun-if-changed=assets` and `cargo:rerun-if-changed=placeholder`, so running `just web-build` and then `cargo build` picks the real assets up.
- **The API**: `pub struct Asset { pub path, pub bytes, pub content_type, pub immutable }`, `pub fn get(path: &str) -> Option<&'static Asset>`, `pub fn index() -> &'static Asset`, and `pub const BUILT: bool`. The placeholder has the same shape as a real build (an index and one immutable asset), so the daemon's serving code and its tests are the same for both.
- **Serving.** An exact path match serves the asset. Immutable assets get `Cache-Control: public, max-age=31536000, immutable`, and others `no-cache` (`index.html` gets `no-store`, above). Any other path whose last segment has no `.` serves `index.html`, so client-side routes work on reload. Anything else is `404`. There is no compression on loopback (a few hundred KiB, local), and R2.08 may add gzip for remote clients.
- **Who gets what.**

  | Build | Assets | `reef ui` |
  | --- | --- | --- |
  | Release tarballs, `install.sh`, the Homebrew formula, `cargo binstall` | real, the same bytes on all four targets | works |
  | The CI `web` job | real | not run (see "Build, CI and developer flow") |
  | `cargo build`, `cargo install --path`, `cargo install --git`, the CI `check` jobs | placeholder | `WEB_UI_NOT_BUILT` |
  | `just web-build` then `cargo build` | real | works |

  The README's install section and CONTRIBUTING say this.
- **The daemon refuses a placeholder session.** `CreateWebSession` checks `web::Limits::assets_built`, which defaults to `reef_web::BUILT`. When it is false, the call fails with `WEB_UI_NOT_BUILT`. `TestDaemon` sets it to `true`, so the daemon's tests serve the placeholder through the full gate. One test sets it to `false` to check the refusal, which therefore runs on any machine, whatever is embedded. This is a test seam rather than an `allow_placeholder` switch, so the refusal is testable on a machine that has built the real assets too.
- **Licenses.** `npm run build` writes `assets/THIRD_PARTY_LICENSES.txt`: each bundled package's name, version, license and license text, read from `node_modules` for the production dependency tree. It fails on a license outside the list in `deny.toml`'s `allow`. The page footer links it. No license-checker dependency: `web/scripts/licenses.mjs`, about 40 lines, run after Vite.
- **No inline script.** `reef-web`'s `table_is_sound` test fails if the built `index.html` has a `<script>` without `src`, or any inline event handler, so the CSP's `script-src 'self'` can never be relaxed to make a build work.
- **Budgets.** The `reef-web` test `bundle_budget` holds the assets to 600 KiB uncompressed in all, and the JavaScript to 450 KiB. The PR records the actual sizes, and the `dist` binary's growth (expected under 1 MiB).
- **Generated TypeScript is not committed either.** `web/src/gen/` is in `.gitignore`. `npm run gen` writes it, through `buf generate` with the `@bufbuild/buf` binary from `package-lock.json` (pinned at 1.74.0 like CI's) and the local `protoc-gen-es` plugin, so it needs no network and no remote plugin. `build`, `typecheck`, `lint`, `test` and `dev` run `gen` first (npm `pre` scripts), so the code always matches the protos in the checkout. A schema PR that breaks the app's types therefore fails the `web` job, which is the right place for it. For types in an editor, a developer runs `just web-gen` once and again after pulling schema changes (`just web-install` runs it too).

### The app

`web/` is a Vite project: React and TypeScript in strict mode, Connect-ES for the API, and nothing else at runtime (`react`, `react-dom`, `@connectrpc/connect`, `@connectrpc/connect-web`, `@bufbuild/protobuf`). Use the current majors at implementation time (React 19, Connect-ES 2 and protobuf-es 2 when this was written), pinned exactly in `package-lock.json`, with the versions recorded in the PR. Every runtime dependency is code that runs with the token, so the list is held short: routing is an in-house module of about 50 lines over the History API, and there is no state library (`useSyncExternalStore` over the stream layer's stores) and no component library. Dev dependencies: `typescript`, `vite`, `@vitejs/plugin-react`, `vitest`, `jsdom`, `@testing-library/react`, `eslint` with `typescript-eslint` and `eslint-plugin-react-hooks`, `prettier`, `@bufbuild/buf` and `@bufbuild/protoc-gen-es`. Node is the current Active LTS (24 when this was written), in `web/.node-version` and `package.json`'s `engines`.

Layout, under `web/src/`:

- `main.tsx`: the bootstrap. It reads `#session=`, stores the token, strips the fragment, builds the `Connection` and renders `App`.
- `api/connection.ts`: `Connection { transport, clients, label }`. `browserConnection(baseUrl, token)` uses `createGrpcWebTransport({ baseUrl, useBinaryFormat: true, interceptors: [bearer(token)] })` with `baseUrl` defaulting to `location.origin`. The app never assumes the API is same-origin except in this one default: a shell (R3.39, R3.40) or a store (R4.13) supplies its own `Connection`, such as a transport over the shell's IPC to the daemon's socket, or gRPC-web to a remote listener with its token. That keeps ADR 0005's "no Tauri-specific code outside the shell".
- `api/errors.ts`: `reefError(e)` turns a `ConnectError` into `{ code, kind, reason, message, hint, next, metadata }` from its `ErrorDetail`. Every error the app shows shows the daemon's `hint` and `next`, and the `next` command can be copied.
- `live/`: the stream layer (below).
- `state/`: the state-color system (below).
- `views/Overview.tsx`, `views/States.tsx`, `views/NoSession.tsx`, `views/NotFound.tsx`; `ui/` for the layout, the connection indicator and the router.
- `styles/`: `tokens.css` (theme and state tokens), `base.css` (system font stack, no web fonts, a 16 px gutter at phone width, no horizontal scroll), with light and dark from `prefers-color-scheme` and a `data-theme` attribute that overrides it (used by the states page and tests).

Rules the scaffold encodes for every later view:

- **No timers that fetch.** ESLint's `no-restricted-globals` bans `setInterval` everywhere. `setTimeout` is allowed only in `live/backoff.ts`. Times are shown as absolute local times (`14:03:22`, the full RFC 3339 string in `title`), never as "12 s ago", which would need a ticking clock: motion without a state change.
- **Motion only for state change.** A row whose state changed gets one background transition of at most 300 ms, and none under `prefers-reduced-motion: reduce`. No spinner, pulse or animated placeholder. Loading shows static text.
- **Coalesce into frames.** The stream layer applies everything that arrived during one animation frame as one store update, so a burst of 1,000 operations is one React commit, not a thousand. Only rendering waits for a frame. Browsers stop animation frames in hidden tabs, so the leader republishes each stream frame on the `BroadcastChannel` as it arrives, never on an animation frame. A hidden tab keeps reading its streams, so flow control is unaffected, and folds what it reads into its pending update (the latest presence state per id, and the operations a view keeps) until it is visible again.
- **Never `dangerouslySetInnerHTML`** (an ESLint `no-restricted-syntax` error on the attribute), and no rendering of API text as HTML or Markdown.
- **Accessible by default**: semantic tables and headings, visible focus, the connection indicator in an `aria-live="polite"` region, and state never shown by color alone.

### The stream layer

`live/operations.ts`, `live/presence.ts`, `live/share.ts`, `live/backoff.ts`.

- **One operation stream and one presence stream per browser**, both unfiltered: `SubscribeOperations { repos: [] }` with no start, and `SubscribePresence {}`. Views filter on the client. The broker makes an unfiltered stream cheap (R2.22), and the phase's 1,000 operations a minute is 17 a second into one tab.
- **Shared across tabs.** The tab that holds the Web Lock `reef-live` (`navigator.locks.request`, exclusive, held for the tab's life) opens the two streams and republishes every frame, still encoded, on the `BroadcastChannel` `reef-live`. Other tabs decode the same frames. A tab that joins sends `hello`, and the leader answers with its current presence set as one synthetic `synced` frame and the cursor of its last operation frame. When the leader closes, the lock passes to another tab, which resumes the operation stream from the last cursor it saw and resubscribes to presence, replacing its set. Both locks and channels are scoped to the origin, so a session's tabs share and nothing else does. If `navigator.locks` is missing, each tab opens its own streams, and the limit in "Risks" applies.
- **Operations: resume exactly.** The layer keeps the last frame's `cursor`. It resubscribes with that cursor on a transport error, or on `UNAVAILABLE` with no reason (a daemon shutting down), with `op watch`'s backoff (100 ms doubling to 2 s, then every 2 s, never giving up while the tab is open). On `TOO_FAR_BEHIND` or `OPERATION_LOG_REWRITTEN`, it subscribes fresh (no start) and tells its consumers to reload what they derived (`reset` event). On `WEB_SESSION_INVALID`, it stops and the app shows the no-session page. Consumers get `{ operations, live, reset }` per animation frame.
- **Presence: state, not history.** The layer keeps the set by id. After a resubscribe, when the new set is `synced`, entries it held that the new set lacks are ended (R2.10's rule). Consumers get the current set and a version number.
- **Connection state** is one of `connecting`, `live` (both streams have delivered their first frame: `live: true` for operations, `synced` for presence), `reconnecting`, or `ended` (session invalid). The indicator shows it as text with a shape, not a hue (see the state colors).

### The overview: the one live view

At `/`, `views/Overview.tsx`:

- **Repositories** from `ListRepositories`, all pages. Each row shows the root's last path component with the full root in `title`, the id's first 8 characters, the latest operation, and the active agents.
- **Latest operation, with no gap.** The layer's operation stream is open before the overview reads anything. Once the stream's first live frame has arrived, the overview calls `ListOperations { repo, page_size: 1 }` per repository, eight at a time. It keeps, per repository, whichever of the listed operation and every streamed operation has the latest `ended_at`, ties broken by id. An operation recorded between the two calls arrives on the stream. The cell shows the kind (a label per `OperationKind`, such as `snapshot (watcher)`, `describe`, or `external`), the agent, the workspace's first 8 characters or `-`, and the end time. A `reset` reloads the list.
- **Active agents**: the number of distinct `agent` values among live presence entries with that `repo_id`, all kinds. Entries with no repository are not counted.
- **Repositories added and forgotten.** An operation for an unknown `repo_id` triggers one `ListRepositories` reload, debounced to one per second. A forgotten repository produces no event on either stream, so its row stays until the next reload, reconnect or `reset`. The page says nothing false about it: its operations stop. This is listed under "Out of scope".
- **Empty and error states**: "No repositories are registered. Run `reef init` in one." for none, and the error component with `hint` and `next` for a failed read.
- **The header** shows "Reef", the daemon's version and API revision from `GetDaemonStatus`, and the connection indicator. The footer links the third-party licenses and `/states`.

### The state-color system

The design's seven states, two neutral states, and nothing else: one token per state, used for every object that has one, so R2.19, R2.20 and Phase 3's views agree by construction.

| State | Meaning | Light (on `#ffffff`) | Dark (on `#14161a`) | Shape |
| --- | --- | --- | --- | --- |
| `draft` | Mutable work not proposed | `#4b5a6e` (7.0:1) | `#a9b8cc` (9.0:1) | hollow circle |
| `proposed` | Put forward for main (R3.09) | `#1f5fbf` (6.1:1) | `#7fb0ff` (8.2:1) | half-filled circle |
| `queued` | In the landing queue (R3.14) | `#6a3fb5` (7.0:1) | `#b79cff` (8.0:1) | circle with a centre dot |
| `testing` | Checks running (R3.05) | `#8a5a00` (5.9:1) | `#f0b84a` (10.1:1) | circle with a quarter cut |
| `landed` | On `trunk()` | `#1e7a3c` (5.4:1) | `#5fd28a` (9.6:1) | filled circle with a check |
| `failed` | Checks or a landing failed | `#b42318` (6.6:1) | `#ff8a80` (7.9:1) | filled circle with a cross |
| `conflicted` | Needs a resolution: a conflict, or a divergent change | `#a3207a` (6.9:1) | `#f08ad0` (8.0:1) | diamond |
| `ended` | Ended without landing: abandoned, undone, declined, withdrawn, superseded | `#6b6f76` (5.1:1) | `#9a9ea6` (6.7:1) | dashed circle |
| `none` | No state, or one the app does not know | the theme's secondary text | the same | none |

- **Tokens**: `--state-<name>` (text, icon and border), and `--state-<name>-tint` (a background at about 12% of the color over the surface, for rows and badges). Light and dark live in `tokens.css`. The values above are starting points that a designer may tune. Test W1 holds each foreground to at least 4.5:1 against `--surface` and against its own tint, in both themes, so tuning cannot break contrast.
- **Never color alone.** `StateBadge` renders the shape (inline SVG, one per state) and the word. Red and green are never the only difference, for color-blind readers.
- **State colors are for object states only.** Connection status, errors and chrome use neutral tokens with text and shapes, so "green" always means landed. A later view that wants a hue for something else adds a token for it, and never reuses a state token with another meaning.
- **Mapping what Phase 2 has**, in `state/states.ts`, unit-tested:
  - `changeState(change: Change)`: `conflict` or `divergent` gives `conflicted` (labelled "conflicted" or "divergent"); else `hidden` gives `ended` ("abandoned"); else `immutable` gives `landed`; else `draft`.
  - `immutable` is Reef's `immutable_heads()` and its ancestors, which include tags and untracked remote bookmarks as well as `trunk()`. It is the closest the `Change` message has to "landed", and R2.19 may refine it with a `trunk()` revset or R2.16's outcome.
  - `outcomeState(o: ChangeOutcome)`: `OPEN` gives `draft`, `LANDED` gives `landed`, and `ABANDONED` and `UNDONE` give `ended`.
  - Proposed, queued, testing and failed have no source until Phase 3. Their tokens exist now so the palette is designed once.
- **Workspaces, leases and presence get no state color here.** They are not in the design's list. R2.20 decides whether lease health needs one, under the rule above.
- **`/states`** renders every state as a badge and as a tinted row, in both themes side by side (`data-theme`), with each foreground's contrast ratio. It is the reference R2.19 onward check against.

### Schema additions

`API_REVISION` becomes the next revision at merge (12 if #125 merges first), with one `API_DIGESTS` entry commented "R2.18: `DaemonService.CreateWebSession`". In `daemon.proto`:

```proto
  // A session for the web UI. Binds the daemon's loopback web listener
  // (`[ui] listen`) if it is not bound yet, and returns its address and a
  // new session. The session's token authorizes the web listener's
  // gRPC-web calls to ACCESS_READ methods until the daemon stops, or for
  // 24 hours without use; it is never persisted. ADMIN: it mints a
  // credential, so it is served only where ADMIN is.
  //
  // Errors: FAILED_PRECONDITION with reason WEB_UI_DISABLED (`[ui]
  // enabled = false`) or WEB_UI_NOT_BUILT (this daemon embeds only the
  // placeholder page, not the app); UNAVAILABLE with reason
  // WEB_UI_UNAVAILABLE (metadata `address`, `error`) when the listener
  // cannot be bound.
  rpc CreateWebSession(CreateWebSessionRequest) returns (CreateWebSessionResponse) {
    option (reef.api.v1.access) = ACCESS_ADMIN;
  }

// Ask for a web UI session.
message CreateWebSessionRequest {
  // Also write a launch file: a page only the daemon's user can read that
  // sends a browser on to `session_url`, so the token need not appear on a
  // command line. Deleted at the session's first request or after 60
  // seconds. False: `launch_path` is empty.
  bool launch_file = 1;
}

// A web UI session.
message CreateWebSessionResponse {
  // The web UI's address, such as `http://127.0.0.1:52817/`. No token.
  string url = 1;
  // `url` with the session's token in its fragment (`#session=<token>`).
  // A credential: whoever holds it can read every registered repository
  // through the web listener while the session lives.
  string session_url = 2;
  // The launch file's absolute path; empty unless `launch_file`.
  string launch_path = 3;
}
```

No other message changes. `GetDaemonStatus` does not report the listener: the URL without a session is useless, and with one it is a credential.

### Errors and reasons

New constants in `reef_api::error`, from a `WebError` in `reef-daemon/src/web/mod.rs` with `Classify` and `Advise`, and `web_reason` in `error.rs`:

| Reason | Kind (gRPC) | Metadata | Hint | `next` |
| --- | --- | --- | --- | --- |
| `WEB_UI_DISABLED` | `Conflict` (`FAILED_PRECONDITION`) | none | "The web UI is off: set `[ui] enabled = true` in the daemon's config.toml and restart the daemon." | none |
| `WEB_UI_NOT_BUILT` | `Conflict` (`FAILED_PRECONDITION`) | none | "This reef-daemon was built without the web UI. Install a release (https://github.com/reef-vcs/reef/releases, `install.sh`, Homebrew), or run `just web-build` before `cargo build` in a checkout, then restart the daemon." | none |
| `WEB_UI_UNAVAILABLE` | `Unavailable` | `address`, `error` | "Another process holds `<address>`. Free it, or set `[ui] listen = \"127.0.0.1:0\"` for a free port, restart the daemon, and run `reef ui` again." | none |
| `WEB_SESSION_INVALID` | `PermissionDenied` | none | "This page's session ended (the daemon restarted, or it went unused for a day). Run `reef ui` in a terminal." | `reef ui` |
| `WEB_ACCESS_DENIED` | `PermissionDenied` | `method`, `access` | "The web UI serves read RPCs only; use the CLI for this." | none |

The last two are returned only on the web listener. They use `PermissionDenied` rather than adding a tenth kind for "unauthenticated", which would add an exit code (ADR 0025) for an answer no CLI receives. R2.08, whose clients do receive it, decides whether to add the kind (see "What later tickets inherit").

### Configuration and limits

- `[ui]` in `FileConfig`, `UiSection { enabled: bool = true, listen: String = "127.0.0.1:0" }`, `deny_unknown_fields`. `listen` is validated at load: a socket address whose IP is loopback, else `ConfigError` naming the value and "the web UI listens on loopback only; a remote listener is R2.08's". `reef config show` prints it.
- `Config::web: web::Limits { max_sessions: 32, session_idle: 24 h, launch_file_ttl: 60 s, max_connections: 64, assets_built: reef_web::BUILT }`, set like `presence` and not a file key, so tests shrink it through `TestDaemon::start_with`. `TestDaemon` sets `assets_built: true`.
- `Paths::ui`: `<state>/ui`. ADR 0020's backup layout does not include it, and there is nothing to add.

### MCP: no tool

`CreateWebSession` is ADMIN, and no ADMIN RPC is a tool (R2.13). `NOT_TOOLS` gains `("/reef.api.v1.DaemonService/CreateWebSession", "ADMIN; a person runs reef ui")`. `tools/list` is unchanged.

### Build, CI and developer flow

- **`justfile`**:
  - `web-install` (`npm ci` in `web/`, then `npm run gen`);
  - `web-gen` (`npm run gen`, for an editor's types);
  - `web-build` (`npm ci && npm run build`, which generates, builds and writes `crates/reef-web/assets`);
  - `web-check` (`npm run lint && npm run typecheck && npm test && npm run build`, then `REEF_WEB_EXPECT_BUILT=1 cargo nextest run -p reef-web`);
  - `web-dev` (Vite's dev server, see below);
  - `web-clean` (removes `crates/reef-web/assets` and `web/src/gen`, back to the placeholder).

  `just build`, `just test` and `just ci` need no Node. They build and test against the placeholder unless `just web-build` has been run.
- **CI**: a new job `web` on `ubuntu-24.04`, timeout 15 minutes, with `actions/setup-node` reading `web/.node-version` and caching npm on `web/package-lock.json`, and the Rust toolchain with its cache. It runs `just web-check`: lint, typecheck and Vitest, then the build, then `reef-web`'s tests against the real assets (`built`, `table_is_sound`, `bundle_budget`). It joins `ci-ok`'s `needs`, and runs on every pull request, so a schema change that breaks the app's generated types fails here. Because `reef-web` has no dependencies, its tests compile in seconds. The job is expected to take 3 to 4 minutes warm, and the PR records the time.
- **The daemon's `web_ui` tests are not run against the real assets in CI.** They run in the `check` jobs against the placeholder, through the same serving code and the same table shape (an index, an immutable asset, the SPA fallback). Running them in the `web` job would build `reef-daemon` and its test binary there: jj-lib, gix and tree-sitter, about 8 to 10 minutes cold and 2 to 3 warm, roughly tripling the job, to re-test code the placeholder already exercises. What the placeholder cannot show (that the real app is what a released daemon serves) is checked once per release, by fetching it from an installed daemon (below).
- **The `check` jobs** on both platforms stay Node-free. They gain `reef-web`'s placeholder tests and the daemon's web tests, which need no browser. The macOS job's budget moves by those tests only, which the PR measures.
- **Release** (`.github/workflows/release.yml`):
  - **A new `web` job** on `ubuntu-24.04`, after `check-version`, timeout 15 minutes, with Node from `web/.node-version` and the Rust toolchain. It runs `npm ci` and `npm run build` in `web/`, then `REEF_WEB_EXPECT_BUILT=1 cargo test -p reef-web --locked`, and uploads `crates/reef-web/assets` as the artifact `web-assets` (retention 14 days). A release builds it without the npm cache, as the Rust jobs build without theirs; dry runs use the cache.
  - **`build` needs `web`** as well as `check-version`. It downloads `web-assets` into `crates/reef-web/assets` before `cargo build`, so all four tarballs embed the same bytes. Its "Smoke test" step gains two checks on `reef-daemon`, which cost nothing: the hashed script name from the artifact's `index.html` (`assets/index-<hash>.js`) appears in the binary (`grep -aqF`), and the placeholder's sentence "built without the web UI" does not. A placeholder build, or one with other bytes, fails its target.
  - **`install` on `ubuntu-24.04`** gains one end-to-end check after `scripts/test-install.sh`: it starts the installed `reef-daemon` on a scratch state directory, runs the installed `reef ui --print`, fetches `/` from the printed URL with `curl`, checks that the page names the same hashed script, and stops the daemon. This takes a few seconds, on one runner, and proves that a released daemon serves the real app. The other three runners rely on the grep.
  - **Artifact downloads.** `install`, `homebrew-test`, `binstall` and `publish` download every artifact into `dist/` with no pattern, so they would now also merge `web-assets` there. Nothing would publish it (`publish` names `dist/*.tar.gz` and `dist/SHA256SUMS`), but each of those downloads gains `pattern: reef-*`, plus a download of `SHA256SUMS` by name where the job reads it, so `dist/` holds only what is shipped.
  - **Dry runs.** The pull-request `paths` gain `crates/reef-web/build.rs` and `crates/reef-web/placeholder/**`, which decide what a release embeds. Changes under `web/` do not trigger a release dry run: the CI `web` job builds and tests them.
  - **Unchanged downstream.** The Homebrew formula and `cargo binstall` install the tarballs, so they get the UI.
- **Source builds** (`cargo install --path`, `cargo install --git`, `cargo build` in a checkout) get the placeholder. The README's install section gains one sentence: "A build from source has no web UI unless you run `just web-build` (Node 24) first; `reef ui` says so." CONTRIBUTING says the same.
- **`cargo deny`**: `tonic-web` and `pin-project` are MIT or Apache-2.0.
- **Dev server.** `npm run dev` serves the app on `http://127.0.0.1:5173` with Vite's proxy sending `/reef.api.v1.` paths to the daemon's web listener (`REEF_UI_URL`, the `url` from `reef ui --print`). The proxy rewrites `Host` and `Origin` to the daemon's own authority, so the gate's rules stay as they are and no dev mode exists in the daemon. The developer opens `http://127.0.0.1:5173/#session=<token>` with the token from `reef ui --print`. CONTRIBUTING says all this.

## Implementation notes

- **Order**:
  1. the schema, revision and reasons;
  2. `reef-web` with the placeholder, `BUILT`, and its table;
  3. `server::routes` and the generic `Accepting`;
  4. sessions, the gate and assets, with tests 1 to 6 and 8 to 14;
  5. streams (test 7);
  6. the client and `reef ui` (tests 18 and 19);
  7. `web/` (W1 to W8), then the real build and `reef-web`'s tests against it (15 to 17);
  8. CI's `web` job, then the release workflow's, checked by a dry run (`workflow_dispatch` with `dry_run`, or the PR's own run, since it touches `release.yml`);
  9. the threat model and the ADR.
- **The gate is a hand-written tower `Layer`**, like `CompatLayer`, not a `tower-http` stack: the rules are few and order matters, and each refusal is a test. It must never call the inner service for a refused request.
- **Strip `authorization` before tonic sees it**, and never put it in a `tracing` field. `tonic-web` logs at `debug` and `trace` with the path and content type only. Test 14 holds this.
- **`Sessions` is a `std::sync::Mutex<HashMap<[u8; 32], Session>>`**, held only to look up and touch, never across an await. The open-stream count is a guard dropped with the response body: wrap the streaming body so its drop decrements it.
- **The lazy bind** happens under the `WebUi` mutex, so concurrent `CreateWebSession` calls bind once. A failed bind leaves `None` for the next call to retry. Bind with `tokio::net::TcpListener::bind` on the exact configured address, and never set `SO_REUSEPORT`: without it on the daemon's socket, no other user's socket can bind the same address and port while the daemon listens, on Linux or macOS.
- **Linux**: nothing here is `cfg(target_os = "linux")`, but `Config` and `Paths` change under Linux-only tests. Run the build and clippy in the privileged `ubuntu:24.04` container (`docs/benchmarks.md`, "Linux") before pushing.
- **The opener**: spawn it detached with stdio closed and wait at most 5 s for it to exit. `xdg-open` returns once the browser has the file. On a non-zero exit, fall back to printing the session URL.
- **Vite configuration**: `base: "/"`, `build.outDir: "../crates/reef-web/assets"`, `build.emptyOutDir: true`, `build.sourcemap: false`, `build.assetsInlineLimit: 0` (no `data:` scripts), and `build.modulePreload.polyfill: false`. The no-inline-script rule is enforced by `table_is_sound` (test 16), which runs wherever the real assets are built.
- **`build.rs` and the placeholder.** The two branches must produce the same `assets.rs` shape, so `lib.rs` has no `cfg`. Use `CARGO_MANIFEST_DIR` for both directories. Cargo treats a `rerun-if-changed` path that does not exist as changed, so a placeholder build reruns the script on every build. That is cheap here (a directory check and a few files), and it is what makes the assets get picked up when they appear. Check this by hand: `cargo build`, then `just web-build`, then `cargo build` must embed the real assets without `cargo clean`.
- **The release's `web` job builds once**, so the four targets cannot differ. Building per target would need Node on four runners and invite platform differences in the bundle.

## Risks

- **Snap-confined browsers cannot read the launch file.** Ubuntu's default Firefox is a snap and cannot read hidden directories in the home directory, such as `~/.local/state/reef/ui/`. The opener exits zero, and the browser shows a file error. Mitigations:
  - the hint and the CONTRIBUTING and README text say to run `reef ui --print`;
  - `reef ui` prints the plain `url` beside "Opened", so the user sees where it should go;
  - a follow-up may detect a snap default browser and print instead.

  A root daemon's launch file is root's and cannot be read by a user's browser either, so `--print` is the path there too.
- **Six connections per origin without shared streams.** A browser without Web Locks (none of the current targets) would hold two connections per tab, and a fourth tab would stall. This is documented in the ADR. HTTP/2 over R2.08's TLS removes the limit remotely.
- **Source builds have no UI.** `cargo install --git` (the README's source install) and every plain `cargo build` embed the placeholder, and `reef ui` refuses it. Someone who builds from source and expects the UI finds out from `WEB_UI_NOT_BUILT`'s hint, which names both fixes. This is the cost decision 1 accepted. If R2.25 publishes the crates to crates.io, `cargo install reef-daemon` would have the same gap, unless the published `reef-web` package carries built assets (remaining open question 1).
- **Releases now need Node and the npm registry.** A release whose `web` job cannot reach npm, or whose lockfile no longer installs, does not ship. The `web` CI job runs `npm ci` on every pull request, so a broken lockfile is found before a tag. A registry outage on release day delays the release, as a crates.io outage would.
- **A placeholder build reaching users.** If `build` ran without its download (a workflow edit that drops the step), the tarballs would be placeholder builds that still pass `--version`. The grep in each target's smoke test, and the `install` job's fetch, fail the release in that case.
- **Stale generated types in an editor.** `web/src/gen/` is regenerated by every script that needs it, but an editor shows whatever was last generated. After pulling a schema change, a developer runs `just web-gen`. The `web` job is the authority.
- **npm supply chain.** The bundle carries five runtime packages and their dependencies, and they run with the token. Mitigations: exact pins in `package-lock.json`, `npm ci` only, the license list, and review of every lockfile change. An `npm audit` step in the `web` job reports, without failing (as `deny-advisories` does).
- **`immutable` is not "landed".** It includes tags and untracked remote bookmarks. R2.19 decides whether that difference shows.
- **A long-lived tab across `reef daemon stop`** keeps retrying with backoff against a port anyone may take. It sends only a dead token, but it would render whatever a squatter answers, until the squatter returns `WEB_SESSION_INVALID` or garbage. This is spoofing, not disclosure, and is recorded as a Low row (S-31).

## Choices this brief made, and why

- **gRPC-web, not a WebSocket bridge**: backpressure in the browser, one protocol, and R2.08's needs.
- **A daemon listener, bound on demand**: R2.08 needs the daemon to serve, and a user who never opens the UI opens no port.
- **Read-only**: Phase 2's views only read, and a leaked session can then write nothing.
- **Bearer headers from the page's `localStorage`, not cookies**: cookies ignore ports, which on a shared loopback is a leak to other local users.
- **Per-process tokens**: a squatted port after a restart gets nothing of value.
- **A launch file**: the only way to hand a browser a secret without a command line or a race.
- **An exact Host check and the IP literal**: DNS rebinding and IPv6 `localhost` squatting, closed with no configuration.
- **Built where it ships, never committed** (decision 1): no generated bundle in git; one release build embedded on every target; a placeholder that keeps `cargo build` and the `check` jobs Node-free; and `WEB_UI_NOT_BUILT`, so a placeholder build never opens a useless page.
- **Generated TypeScript at every build**: no drift, and a schema change that breaks the app fails the `web` job on the PR that makes it.
- **The daemon's web tests against the placeholder only**: the same code path at a third of the `web` job's cost, with the real app checked once per release from an installed daemon.
- **One stream of each kind per browser**: the HTTP/1.1 connection limit, and the broker makes unfiltered cheap.
- **A small palette with contrast tests and shapes**: designed once, accessible, and safe to tune.

## Decisions (2026-10-31)

The user decided the brief's seven open questions. The brief above is written to these answers.

1. **Where the app is built: in CI and the release only.** No built bundle and no generated TypeScript in git. This was against the brief's first recommendation, which was to commit both. The user's reason: no generated bundle in the repository, accepting Node in the release workflow and no UI in builds from source.
   - `reef-web` embeds the built assets when present, and otherwise a placeholder, with `BUILT` saying which.
   - `CreateWebSession` refuses a placeholder build with `WEB_UI_NOT_BUILT`.
   - A Linux-only CI `web` job builds and tests the app.
   - The release builds the assets once and embeds them in all four targets, and checks that none is a placeholder build.
   - `cargo build`, `cargo install` and the `check` jobs stay Node-free, with the placeholder.
2. **On by default, bound on first use.** `[ui] enabled = true`. The listener is bound by the first `reef ui` and stays until the daemon stops. A daemon whose user never runs `reef ui` opens no TCP port.
3. **TLS scoped to listeners reachable from another host.** The threat model's requirement 1 is amended so. The loopback listener's rules become their own subsection, and R2.08 still needs TLS.
4. **Read-only through Phase 2.** The web listener serves `ACCESS_READ` methods only. The first write from the UI (R3.31) extends the gate to WRITE methods and brings requirement 5's audit with it.
5. **The command is `reef ui`.** `--help` grows to 47 lines.
6. **No browser end-to-end tests in CI yet.** The PR records manual checks and files a follow-up for a Playwright smoke test in the `web` job when R2.19 lands.
7. **Sessions end at every daemon restart.** Tokens are never persisted, so a squatter on a port after a restart gets only a dead token. After an upgrade or `reef daemon stop`, every tab shows the no-session page until `reef ui` runs again.

## Open questions

2. **Detecting a snap browser.** Whether `reef ui` should detect a snap-confined default browser on Linux and print the session URL instead of opening the launch file (see "Risks"). Recommendation: a follow-up issue, decided on reports from users.
