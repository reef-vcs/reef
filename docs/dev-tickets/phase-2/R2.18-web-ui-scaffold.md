# R2.18 Web UI scaffold

Phase 2 · Size M · Depends on: R2.09 (`Operations.Subscribe` frames, `seq` in `Daemon.Status`), R2.08 (the web and remote listeners, the token model, `Remote.IssueToken`, `Daemon.Status.web_url`), R2.07 (the generated TypeScript code in `sdk/typescript`, the `pnpm-workspace.yaml`) · Unblocks: R2.19, R2.20, R2.21 (the three views), R3.31 (the proposal view is a fourth route in this shell), R3.39 (Tauri wraps this app)

## Context

The design's human interface is one web application rendered against the local daemon or, later, a store ("Where it lives", `docs/design.md`), live by default and bound by five rules: one state color per object, motion only on state change, nothing reorders under the cursor, every live element links to its cause, coalesce and never drop. Phase 2's exit criterion is "a local web UI shows the smartlog, workspaces, and fleet panel live". This ticket builds everything those views share and nothing they own: the `ui/` package, the state-color tokens, the layout shell, the data layer over `Operations.Subscribe`, the embed in the daemon and the routes that serve it, `reef ui`, the `docs/ui.md` checklist, the CI job, the Playwright harness, and ADR 0037. R2.19, R2.20 and R2.21 each add one route and one smoke test.

A browser cannot open a Unix socket, so the UI is served by R2.08's web listener (loopback, plaintext, token-checked) and, when enabled, by its remote listener (TLS). Both run tonic with `tonic-web` for the gRPC-web calls the browser makes and axum routes for the static files. The UI never speaks to the Unix socket and never holds a token with more than `read,presence,workspaces` scopes.

## Decisions

- **Stack, as the README fixes it, with the versions verified above**: Vite 8, `@vitejs/plugin-react` 6, React 19, TypeScript 5.9, `react-router` 8 in library mode (`createBrowserRouter`; three routes now, the proposal view later), `zustand` 5 for the store, `@connectrpc/connect-web` 2.2 over the generated code imported from the `sdk/typescript` workspace package (`reef-vcs`, R2.07; the UI never runs `buf` itself), Vitest 5 for units, `@playwright/test` 1.64 for the smokes, ESLint 10 with `typescript-eslint` 8. `ui/package.json` declares `"packageManager": "pnpm@12.x"` and `engines.node >= 22.12`. No CSS framework: hand-written CSS modules with the tokens below (the app is small, and a framework's palette fights the state colors).
- **State colors are design tokens, and never the only signal.** `ui/src/tokens.css` defines, on `:root` and under `[data-theme="dark"]` (which follows `prefers-color-scheme` unless the user picks one in the header), `--state-draft`, `--state-proposed`, `--state-queued`, `--state-testing`, `--state-landed`, `--state-failed`, `--state-conflicted`, plus `--fg`, `--bg`, `--surface`, `--border`, `--muted`, `--accent`. Light values (on `--bg: #ffffff`): draft `#6b7280`, proposed `#1d4ed8`, queued `#6d28d9`, testing `#a16207`, landed `#15803d`, failed `#b91c1c`, conflicted `#c2410c`; dark values (on `--bg: #0f172a`): `#9ca3af`, `#60a5fa`, `#a78bfa`, `#fbbf24`, `#4ade80`, `#f87171`, `#fb923c`. Every light value is at least 4.5:1 against white and every dark value at least 4.5:1 against `#0f172a` (checked with a WCAG contrast calculator while writing this; the Vitest token test recomputes the ratios from the CSS so a palette edit cannot regress them). Each state also has a one-letter glyph (`D P Q T L F C`) and a label, so color is redundant for a color-blind reader; the glyph sits in the node, the label in its tooltip. Phase 2 shows `draft`, `conflicted` and `landed` only; the other four are defined now and the Vitest test asserts all seven exist in both themes.
- **The shell.** `ui/src/App.tsx`: a header with the Reef mark, a repository switcher (a `<select>` over `Repositories.List`, the choice kept in `localStorage` and in the URL as `?repo=<id>`), the route tabs (Smartlog, Workspaces, Activity), a theme toggle, and a connection indicator; a main region for the route; no footer. The connection indicator is a small dot with a label driven by the data layer's state: `connecting`, `live`, `catching up` (replaying frames after a reconnect), `reconnecting (retry in Ns)`, `lagged` (the server said `Frame.lagged`; a full refetch is running), `unauthorized` (the token was refused: the page shows how to get a new one, `reef ui`). The indicator is the one element allowed to pulse, because its state is the thing changing.
- **One subscription per page, shared through the store.** `ui/src/data/daemon.ts` owns one transport (`createGrpcWebTransport({ baseUrl: location.origin, useBinaryFormat: true, interceptors: [auth] })`) and one `Operations.Subscribe` stream for the selected repository, started by the first view that mounts and kept while any view is mounted. Frames are pushed onto a queue; one `requestAnimationFrame` callback drains the queue and applies every queued frame to the zustand store in one `set`, so a burst of frames costs one render. The store keeps `lastSeq`; on a stream error the client waits `min(250ms × 2^n, 10 s)` and resubscribes with `resume_after_seq: lastSeq`, during which the indicator says `reconnecting`; on `Frame.lagged = true` it marks every view's data stale, refetches (`Changes.Log`, `Workspaces.List`, `Presence.Subscribe`'s first frame) and resumes. Views never call `Subscribe` themselves: they read `useEvents(selector)` and `useLive(query)` hooks from the store. Mutations (R2.20's release and move) go through `useMutation`, which calls the RPC and lets the resulting event update the view, never the response, so the view shows what the daemon recorded.
- **Token hand-off.** `reef ui` opens `<web_url>/#token=<token>`. `ui/src/data/auth.ts` reads the fragment on load, stores the token in memory and `sessionStorage` (`reef.token`), and replaces the URL with `history.replaceState` so the token is not in the address bar or any referrer; on a later load with no fragment it reads `sessionStorage`. The `auth` interceptor sets `req.header.set("Authorization", "Bearer " + token)` on every call, unary and streaming. An `UNAUTHENTICATED` status clears the token and shows the unauthorized screen with the one command to run (`reef ui`). The token never goes in `localStorage` (it would outlive the 12-hour expiry's purpose) and never in a cookie (R2.08's listener reads none).
- **Serving.** `crates/reef-daemon/src/listener/static_files.rs`, behind the Cargo feature `ui` (default on; enables the optional `rust-embed` dependency with features `interpolate-folder-path`, `debug-embed`, `mime-guess`): `#[derive(Embed)] #[folder = "$CARGO_MANIFEST_DIR/../../ui/dist"] #[allow_missing = true] struct UiAssets;`. `debug-embed` so a debug daemon embeds the files too (without it rust-embed reads them from the process's working directory, which autostart does not control); `allow_missing` so `cargo build` with no `ui/dist` still compiles. `pub fn routes() -> axum::Router`: `GET /assets/{*path}` serves the embedded file with its `mimetype()`, `Cache-Control: public, max-age=31536000, immutable` (Vite names assets by content hash), and `ETag` from `sha256_hash()`; every other `GET` that is not a gRPC-web path serves `index.html` with `Cache-Control: no-cache`, so `/workspaces` and `/activity` deep-link (the router is history-based; the token lives in the fragment, which never reaches the server). When `UiAssets::iter().next().is_none()` (the folder was missing at build time) every route serves one embedded HTML page, `ui/stub/index.html`, saying `This reef-daemon was built without the web UI. Run just ui and rebuild, or install a release binary.` Every response carries `Content-Security-Policy: default-src 'self'; connect-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; frame-ancestors 'none'; base-uri 'none'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`. `style-src 'unsafe-inline'` is for React's `style=` attributes; no inline `<script>` exists (Vite 8 emits `<script type="module" src>` tags only, checked on the built `index.html` by a Vitest test). The gRPC services on these listeners are wrapped per service, `ServiceBuilder::new().layer(cors).layer(GrpcWebLayer::new()).into_inner().named_layer(svc)`, where `cors` is R2.08's `CorsLayer` (allow only the listener's own origin), so the static routes see neither layer; the two routers are merged with `Routes::from(grpc_routes.into_axum_router().merge(static_files::routes()))` and served with `Server::accept_http1(true)` on the web listener (plaintext HTTP/1.1 from the browser) and without it on the remote listener (ALPN). The merge point is a function R2.08 leaves in `listener/mod.rs`, `fn http_routes(state: &Arc<AppState>) -> axum::Router`, which this ticket fills; until R2.18 lands it returns an empty router.
- **`reef ui [--no-open] [--expires <duration>]`** (`crates/reef-vcs/src/cli/ui.rs`): calls `Daemon.Status` for `web_url` (an error with the hint `enable [web] in config.toml` when the listener is off), then `Remote.IssueToken { name: "ui-<yyyy-mm-dd>-<4 hex>", scopes: ["read", "presence", "workspaces"], expires_in: 12h }` over the socket, prints `<web_url>/#token=<token>` (text mode: the URL alone on stdout, so `open "$(reef ui --no-open)"` works; JSON: `{ "url", "web_url", "token", "expires_at" }`), and unless `--no-open`, stdout is not a terminal, or `REEF_UI_NO_OPEN` is set, runs `open <url>` on macOS or `xdg-open <url>` on Linux detached, ignoring a missing opener with a one-line warning. Never reads stdin; errors carry `hint`/`next` (ADR 0025). A `--remote <host:port>` flag is out of scope (the remote listener's URL is the operator's to know; R2.08's quickstart section covers it).
- **`docs/ui.md`** is the UI's contract, in three parts: the five live rules as a checklist every view PR copies into its description and ticks with a sentence each (which element is colored by state and where the token comes from; what animates and on which state change; how new items are held and accepted; which element links to which operation; how events are coalesced and how the count is kept right); the token palette with its contrast ratios and glyphs; and how to run the UI against a daemon (`just ui-dev`), the tests, and the smokes. ADR 0037 records the stack and serving decisions; `docs/ui.md` is the living document.
- **Developer loop.** `just ui` (`pnpm install --frozen-lockfile && pnpm --filter ui build`) writes `ui/dist`; `just ui-dev` runs `reef ui --no-open -o json` to get the URL and token, then `pnpm --filter ui dev` with `VITE_REEF_URL` and `VITE_REEF_TOKEN` in the environment, and `vite.config.ts` proxies `/reef.daemon.v1.*` to `VITE_REEF_URL` and injects the token through `import.meta.env` when present (dev only; production builds contain no token). `just ui-check` runs lint, typecheck, Vitest and the build; `just ui-e2e` the Playwright smokes against `target/debug`. `just ci` gains `ui-check` after `build` (it needs Node; on a machine without `pnpm` the recipe prints `pnpm not found; skipping the UI (just ui-check)` and exits 0, and CI's `ui` job is where it is required).
- **CI job `ui`** on `ubuntu-24.04` only: `pnpm/action-setup` (version from `packageManager`), `actions/setup-node` 22 with pnpm cache, `pnpm install --frozen-lockfile`, `just ui-check`, `cargo build -p reef-vcs -p reef-daemon -p reef-testing --bins` (so the daemon embeds the `ui/dist` just built), `npx playwright install --with-deps chromium`, `just ui-e2e`, and `playwright-report/` uploaded as an artifact when the job fails. It runs on every push and pull request; the `check` matrix is unchanged except that `just build` on a machine without `ui/dist` still passes (the `allow_missing` embed). macOS does not run the UI job: the browser is the same Chromium and the runner minutes cost ten times as much.
- **Release.** `release.yml`'s `build` job gains a `Build the web UI` step before `cargo build` (`pnpm install --frozen-lockfile && pnpm --filter ui build`, with Node 22 and pnpm set up on each of the four runners), and the smoke test step asserts `reef ui --no-open -o json` fails with the expected hint when no daemon runs (it must not start one in the release job) and that `strings target/$TARGET/dist/reef-daemon | grep -c 'Run just ui'` is 0 (the stub page is not what shipped). `scripts/package.sh` is unchanged: the UI is inside `reef-daemon`.
- **Playwright harness.** `ui/e2e/global-setup.ts` builds nothing (the job built first) and spawns `target/debug/reef-daemon` with `REEF_STATE_DIR` set to a fresh short temp directory (socket paths must fit 104 bytes, Phase 1's lesson) and a written `config.toml` (`[web] listen = "127.0.0.1:0"`, `[lease] default = "10m"`, `[watcher] debounce = "100ms"`), waits for `<state>/web.json`, generates a `small` synthetic repository with `target/debug/reef-synth gen --preset small --seed 1`, registers it and creates one workspace with `target/debug/reef` (`REEF_OUTPUT=json`), gets a URL and token from `reef ui --no-open -o json`, and writes `ui/e2e/.daemon.json` `{ url, token, pid, stateDir, repoId, workspaceId, reefBin }`; `global-teardown.ts` SIGTERMs the daemon and removes the directory. Tests read the file through `ui/e2e/fixtures.ts`, which extends Playwright's `test` with `daemon` (the JSON plus a `reef(args)` helper that runs the binary) and a `page` that has already visited `${url}/#token=${token}`. One worker; the views' smokes share the daemon, so each test creates what it needs under a unique purpose string and never asserts on counts of other tests' objects. The scaffold's own smoke: the shell renders, the connection indicator reaches `live` within 5 s, the repository switcher lists the fixture, a wrong token shows the unauthorized screen with the text `reef ui`.
- **ADR 0037, "Web UI stack and serving"**: React and TypeScript as the design chose (ADR 0005 keeps the UI a plain web app so Tauri or Electron can wrap it), Vite 8 and pnpm, Connect over gRPC-web rather than a WebSocket bridge (gRPC-web carries the server streams the UI needs; a bridge would be a second protocol with no client), the embed in the daemon binary rather than a separate static server or a CDN (one binary, one listener, one origin for CSP), the per-service `GrpcWebLayer` so static routes stay plain HTTP, the token in the fragment and `sessionStorage`, Chromium-only smokes on Linux, and the alternatives (a WebSocket bridge; serving `ui/dist` from disk; Tailwind; TanStack Router; `grpc-web` the Google client; Vite 7 for an older plugin set).

`src/data/daemon.ts`, the shape the views depend on:

```ts
type Connection = "connecting" | "live" | "catching-up" | "reconnecting" | "lagged" | "unauthorized";
interface DaemonState {
  repoId: string | null; setRepo(id: string): void;
  connection: Connection; retryAt: number | null;
  lastSeq: bigint;                       // from Frame.to_seq
  events: Event[];                       // the ring of the last 5,000 events, newest last; views select from it
  stale: number;                         // bumped on lagged; useLive refetches when it changes
  subscribe(): () => void;               // starts the stream for repoId if not running; returns a release
}
```

Frames are applied in one `set` per animation frame; `events` is capped at 5,000 (older ones fall off; the Activity view pages the index through `Operations.Log` for anything older).

## Implementation notes

- Build order matters for the embed: `cargo build` after `pnpm build`, or the daemon has the stub. `just ui-e2e` and the CI job do it in that order; `just build` alone does not build the UI (a Rust contributor without Node is not blocked), which is why the stub page exists.
- `debug-embed` makes every `ui/dist` change a `reef-daemon` rebuild (rust-embed emits `rerun-if-changed` for the folder). For UI work use `just ui-dev`: Vite serves the app and proxies the gRPC-web calls, so the daemon is rebuilt only when Rust changes.
- The `CorsLayer` is R2.08's and allows exactly the listener's origin; the gRPC-web preflight needs `allow_headers` to include `authorization`, `content-type`, `x-grpc-web`, `x-user-agent` and `expose_headers` to include `grpc-status`, `grpc-message`, `grpc-status-details-bin`, or the browser cannot read Reef's `ErrorDetail`. Put the list in R2.08's layer with a test; this ticket's smoke (`wrong token → unauthorized`) is what fails without it.
- gRPC-web paths are `/reef.daemon.v1.<Service>/<Method>`; the static router's fallback must not shadow them. Since the gRPC routes are merged first and have exact paths, axum routes them before the fallback; a unit test requests one gRPC path without a body and asserts it does not get `index.html`.
- `rAF` does not fire in a hidden tab; frames queue. On `visibilitychange` back to visible, drain once synchronously so the view catches up in one render rather than animating through the backlog (the "motion only for state change" rule: the state changed while hidden, once).
- Keep `src/data/state.ts` the one place that maps a `Change` to a state name. In Phase 2: `conflicted` when `Change.conflicted`, `landed` when a bookmark that `Changes.Log` marks as trunk points at it (R2.02's `Change.bookmarks`), else `draft`. Phase 3 extends it.
- Vitest runs in jsdom; the Connect transport is replaced by a fake in unit tests (`createRouterTransport` from `@connectrpc/connect` serves handlers in memory and is the documented way to test Connect clients without a server; use it for `daemon.test.ts`).
- The Playwright `globalSetup` must generate the synthetic repository with the same `reef-synth` flags `tests/common` uses (`--preset small --seed 1`) so the smokes see a tree the Rust tests already exercise.
- `scripts/doc-links.sh`: `docs/ui.md` links to `ui/` paths and the ADR; both exist once this lands.

## Out of scope

- The three views (R2.19, R2.20, R2.21) and the proposal view (R3.31); the desktop shell (R3.39).
- The listeners, the token model, scopes and CORS policy (R2.08); the UI only consumes them.
- Internationalization; the UI is English, as the CLI is.
- Service workers, offline mode, or installability.
- A `grpc-web` text (base64) mode; Connect's binary format is the default and tonic-web serves it.
- Serving the UI from a store (R4.13).

## Risks

- **Vite 8 is four months old and its plugin set is moving** (`@vitejs/plugin-react` 6 only supports it). If a needed plugin lags, pin Vite 7 with `@vitejs/plugin-react` 5 and note it in the ADR; nothing in this brief depends on a Vite 8 feature.
- **`debug-embed` lengthens the Rust edit loop for anyone who also has `ui/dist`**: every UI build triggers a daemon rebuild. The alternative (reading from disk in debug) breaks autostarted daemons. Documented in `docs/ui.md`; `just ui-dev` is the loop for UI work.
- **gRPC-web server streams through a browser's `fetch`** are long-lived HTTP/1.1 responses on the loopback listener; Chromium allows six connections per origin on HTTP/1.1, and the app holds one stream per page plus `Presence.Subscribe` (R2.20). Three streams fit; a fourth view must share, not open its own. The data layer's "one subscription per page" rule is the guard.
- **Playwright smokes on a shared runner flake** the way Phase 1's timing tests did. Bounds are loose (5 s to `live`), tests are serialized, and a failure is compared against `main` before it is blamed on a change (Phase 1's rule).
- **The token in the URL fragment** is visible to a shoulder-surfer for the moment the tab opens and to any browser extension with page access. It is scoped, expires in 12 hours, and `reef remote token revoke` ends it; ADR 0033 (R2.08) owns the threat-model rows, and this ticket adds the row for the fragment hand-off.
