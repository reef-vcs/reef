# R3.07 Policy file and CEL evaluation

Phase 3 · Size M, at its top end, with the scope lines below · Depends on: R3.01 (evidence on a tree, `reef-evidence`), and builds on R3.03 (`KeyIdentity` on every evidence read: identity, kind, actor, agent, session, presence, authority, status at witness time), R3.04 (provenance records found by change), R3.05 (`job_evidence.fresh`), R3.06 (`reef-checks.toml` at the tree) and R2.02 (revisions, `trunk()`, the diff) · Unblocks: R3.08, R3.13, R3.20, R3.24, R3.28, R6.03; through them R3.14, R3.15, R3.31 and R3.33

## Context

The design names policy in four places. Landing: "The landing service verifies that each evidence object's snapshot hash matches the submitted tree and that the attestor is trusted by repository policy. It applies policy rules such as required test kinds, maximum diff size, forbidden paths, and human sign-off for designated areas. It refuses a change that still contains a conflict." What evidence proves: the gate checks "an attestor that repository policy trusts, which excludes the submitting agent signing its own test run; policy satisfaction, where the required evidence kinds for the touched paths are all present". Open ecosystem: "Trust is declared per repository… each repository's policy names the attestor identities it accepts. A solo developer trusts their own machine. A large project trusts its CI identity and nothing else. Evidence from an untrusted attestor is stored but carries no weight at landing." Technology choices: "Policy language | CEL via cel-rust | Non-Turing-complete, auditable, fast to evaluate at landing. Rego is the fallback if policies grow large."

ADR 0006 adds: one policy file per repository, in the repository, "Its name is settled in R3.07"; "A policy is a set of expressions over an input object, which the evidence and policy specification (R6.03) must document"; CEL "cannot reach beyond" its input, so aggregate rules "need host-provided functions or precomputed inputs"; and "The maturity of `cel-rust` is a risk to re-check when R3.07 starts."

Every Phase 3 ticket so far has deferred one question here. R3.01: "Nothing in the API says 'trusted': R3.07 evaluates trust, and R3.13 refuses on it." R3.03: "R3.07 evaluates `evidence.identity.status == "bound"`, `identity.key.identity`, `identity.key.identity_kind`, `identity.key.actor`, `identity.key.presence` and `identity.key.authority_key_id` in CEL. Its trusted attestors are identities, optionally with an actor and an authority. It also owns identity groups and the 'excludes the submitting agent signing its own test run' rule", and, for #222, "this path needs manual evidence from someone in this group, and requiring `presence`". R3.02: "R3.07 can read `artifacts[].state` in CEL (for example, require a stored log for `test` evidence)." R3.04: "R3.07 evaluates provenance in CEL: for a proposed change, every record's `signature == valid`, `identity.status == bound`." R3.05: "R3.07 reads, for a job's evidence, the signer's `KeyIdentity` … and `fresh`." R3.06: "R3.07 can require `sandbox=` labels or annotations, and should make `reef-checks.toml` (and the policy file itself) a sign-off path by default, since a change to it changes how a tree is judged."

So this ticket builds the policy and the means to ask it a question, and nothing that acts on the answer:

1. **The file**: `reef-policy.toml` at the root of a tree, a strict TOML file of declared tables whose conditions are CEL expressions, format version 1.
2. **The input**: what a policy sees about one change, built by the daemon from the change's commit, its diff, the evidence on its tree with each signer's identity, and the change's provenance, with every trust fact precomputed (which attestor sets each evidence object satisfies, whether it came from the change's own session).
3. **The evaluator**: `reef-policy`, a new crate with no jj-lib, that parses and checks a policy, bounds its cost before running it, and evaluates it with `cel` (cel-rust) into a decision with a result per rule, the evidence still missing, and the sign-offs still needed.
4. **The surface**: `PolicyService.EvaluatePolicy` (READ, API revision 20) and `reef policy check|eval|init`.

Enforcement is R3.13's: nothing refuses anything because of a policy in this ticket. What else stays out is under "Out of scope".

### The file: `reef-policy.toml`, declared tables with CEL conditions

A policy is **`reef-policy.toml` at the root of a tree**, a TOML file whose tables declare what the design names (attestors, required evidence, limits, forbidden paths, sign-off areas, conflict tiers) and whose conditions are CEL expressions, plus free CEL rules for anything else.

Why not a pure `.cel` file, which the row suggested: a CEL expression yields a value, and the landing service needs data, not a boolean. R3.13 must know which evidence kinds and targets to request when a requirement is missing, from which attestors; R3.18 must know the kinds policy requires; R3.31 and R3.33 must show "needs a sign-off from `maintainers`"; R3.28 must read a tier and a cap. A single expression returning `false` says none of that. The established pattern for CEL policy (Kubernetes' validating admission policies, Envoy's RBAC) is the same: a declarative document whose fields are CEL expressions, each with its own message. TOML follows `reef.toml` and `reef-checks.toml`. ADR 0006 rejected rule tables alone as "not expressive enough for path-conditional rules"; here every table can take a CEL `when`, and `[[rule]]` is pure CEL.

```toml
version = 1                                # required; the format version this file is written for

[owners]                                   # required: who signs off a change to the policy files
groups = ["maintainers"]                   # groups and identities; at least one between them
identities = []
count = 1                                  # distinct identities needed; default 1
presence = "none"                          # none | user_verified (R3.43); default none

[groups]                                   # named sets of identities, by name or by id (idn_…)
maintainers = ["alice", "idn_8f3a0c2d91e4b675"]

[attestors.ci]                             # a named set of signers whose evidence counts
identities = ["ci-main"]                   # names or ids; with `groups`, at least one entry
groups = []
identity_kinds = ["ci"]                    # person | ci; default either
actors = ["executor"]                      # human | agent | executor; default ["executor"]
authorities = []                           # authority key ids; empty: any authority this daemon verifies
presence = "none"                          # the least presence accepted; default none
self = "exclude"                           # exclude | allow: evidence from the change's own session or agent
when = 'e.fresh && e.artifacts.exists(a, a.state == "stored")'   # optional CEL over `e`

[[require]]                                # evidence the change needs
name = "tests"                             # unique in the file: [a-z0-9][a-z0-9_-]{0,63}
paths = ["crates/**"]                      # applies when a touched path matches; absent: every change
except = ["crates/**/*.md"]
kinds = ["test", "lint"]                   # each needs a passing object from one of `attestors`
targets = []                               # each kind needs these targets; empty: the whole check (no target)
attestors = ["ci"]
when = 'change.lines_added > 0'            # optional CEL over the input
message = "crate changes need CI's tests and lint"   # optional; one is generated otherwise

[limits]                                   # optional; each key optional
max_files = 400                            # touched paths
max_lines = 4000                           # lines added plus removed
max_file_size = "5MiB"                     # the new side of any added or modified file
except = ["Cargo.lock", "web/package-lock.json"]   # not counted

[[forbid]]                                 # paths no change may touch
name = "secrets"
paths = ["**/*.pem", "secrets/**"]
except = []
when = ''                                  # optional
message = "no keys in the tree"

[[signoff]]                                # areas that need a person's sign-off
name = "ci-config"
paths = [".github/**", "scripts/release*"]
groups = ["maintainers"]
identities = []
count = 1
presence = "none"
kinds = ["signoff"]                        # evidence kinds that count as a sign-off; default ["signoff"]
when = ''

[conflicts]                                # tiers and caps; R3.28 applies them
tier = "approve"                           # land | approve | ask; default approve
attempts = 3                               # 1 to 20; default 3

[[conflicts.rule]]
paths = ["docs/**"]
tier = "land"
attempts = 5
when = ''                                  # optional CEL over `conflict`

[[rule]]                                   # anything else, in CEL
name = "provenance"
when = 'change.files.size() > 0'           # optional: false makes it not apply
expr = 'provenance.all(r, r.signature == "valid" && r.key.status == "bound")'
message = "every commit of the change has a signed, bound provenance record"
```

- **Strict.** Unknown keys and tables are errors with their line and column, as `reef.toml`'s are. A later ticket that adds a table (R3.15's transfer rules, R3.20's budgets) keeps `version = 1` and is additive; an older daemon then reports the newer file `INVALID_POLICY`, which blocks every landing. For policy that is the right failure: an old daemon must never land a change under rules it cannot read.
- **References** are checked at load: every attestor, group and identity entry named exists or has the form of an id (`idn_` and 16 hex), group members are names or ids, and names are unique across `[[require]]`, `[[forbid]]`, `[[signoff]]` and `[[rule]]`.
- **Globs** are `globset` patterns over repository-relative paths with `/` separators: `*` and `?` never cross `/`, `**` does, `{a,b}` alternates, and a pattern that names a directory (`docs`) matches only that path, not its contents (`docs/**` does). Matching is **ASCII case-insensitive** everywhere (S-95). A pattern that does not compile is a load error.
- **Limits** (format 1, the same in every implementation): the file at most 256 KiB; at most 256 entries across `[[require]]`, `[[forbid]]`, `[[signoff]]`, `[[conflicts.rule]]` and `[[rule]]`; at most 64 groups of at most 256 members, 64 attestor sets, and 256 patterns per list; each CEL expression at most 8 KiB of source, 1,000 AST nodes after macro expansion, and a parser depth of 48.
- **Durations and sizes** use the forms `config.toml` uses (`"5MiB"`, `humantime`), as R3.06's files do.

### Where a policy comes from: the destination, never the change

A change must not be judged by a policy it wrote. So:

- **The policy in force is the one at `policy_revision`**, `trunk()` by default, resolved at the same operation as the change. R3.13 reads it from the head of the branch it lands onto. The change's own `reef-policy.toml` takes effect only once it has landed.
- **Changes to the policy files need the owners.** The built-in rule `builtin:owners` applies to every change that touches `reef-policy.toml` or `reef-checks.toml` (R3.06's declaration file, which changes what a check runs) and needs `[owners]`'s sign-off, as a `[[signoff]]` would. It cannot be removed, because a policy that a change can switch off for itself is not a policy. `[owners]` is therefore required.
- **A change's own policy must load.** The built-in rule `builtin:policy-file` applies when the change touches `reef-policy.toml` and the file is still present: it must parse and pass the static check, so main never receives a policy that would block everything. Deleting the file is allowed, with the owners' sign-off; afterwards the repository has no policy.
- **No file is `NO_POLICY`.** When `policy_revision`'s tree has no `reef-policy.toml` (or `trunk()` resolves to nothing, which reads `root()`), the decision is `NO_POLICY` and no rule runs. R3.13 lands nothing automatically under `NO_POLICY` (recorded in its row). `reef policy init` writes a starter file to commit by hand ("The CLI"). The first policy therefore reaches main outside the landing gate, which is the only way it can.
- **A file that does not load is `INVALID_POLICY`**, with every diagnostic (line, column, rule, message), and blocks as `NO_POLICY` does.
- **Versioning.** The file's `version` is the format version; this ticket reads 1 and reports any other as `INVALID_POLICY` ("this daemon reads policy version 1"). The policy itself is versioned by the repository: every evaluation reports the commit, the blob id and the SHA-256 of the bytes it evaluated, which R3.13 pins with each landing.

### What a policy sees: the input

The daemon builds one input per evaluation. CEL sees it as variables; `reef schema policy input` prints it as JSON Schema. Strings for enumerations, integers for counts and times (milliseconds since the Unix epoch), no `null`: an absent value is an empty string, zero or an empty list.

```text
change      the change judged
  id, commit, tree             hex ids
  parents                      list of parent commit ids
  description                  its full description
  author.name, author.email
  empty, conflicted            bool
  paths                        every touched path, sorted; a rename contributes its old and new path
  files                        list of {path, old_path, status: added|modified|deleted|renamed|copied,
                               binary, too_large, lines_added, lines_removed, size}
  lines_added, lines_removed   totals over `files`
evidence    list, by witness time then id: the evidence on change.tree whose signature verifies
  id, kind, result: pass|fail|error, target, started_at, finished_at, added_at, added_by_agent
  artifacts                    list of {name, sha256, media_type, state: stored|collected|absent, size}
  annotations                  map: the attestor's own data, unverified (S-97)
  key                          {id, status: unbound|bound|expired|revoked|invalid, identity, identity_id,
                                identity_kind: person|ci, actor: human|agent|executor, agent, session,
                                presence: none, custody: client|daemon, authority}
  fresh, job                   whether an executor job accepted it fresh (R3.05), and the job's id
  self                         whether it came from the change itself (below)
  attestors                    the names of the attestor sets it satisfies
provenance  list, by recorded time: every provenance record of change.id
  id, commit, tree, workspace, session, sequence, kind, agent, recorded_at,
  model, harness, task, instruction_sha256, client_session, signature: valid|invalid, key
groups      map from group name to its members as written
```

- **Evidence is filtered before CEL, not trusted by it.** Only objects whose signature verifies at this read enter `evidence`; the rest are counted (`input.evidence_ignored`). Every object that satisfies some attestor set is included, up to 10,000; others (untrusted, or from keys no set names) are included newest first up to 1,000, so a writer flooding a tree with junk cannot push trusted evidence out of view (S-94). Over 10,000 trusted objects is `builtin:input` `ERROR`.
- **`self`** is true when the object's key was certified for a session that also signed a provenance record of this change (R3.04's sessions), or when its key's declared `agent` label is non-empty and equals the `agent` of one of the change's provenance records with the same identity. The first is a signature fact; the second is a declaration, and on one uid both can be avoided by an agent that wants to (S-92). It implements the design's "excludes the submitting agent signing its own test run" as far as Reef can know it, and `docs/policy.md` says what to trust instead.
- **Touched paths** come from the diff against the change's merged parents (`diff_page` with stats, all pages), the same as `reef diff -r <change>`. At most 100,000 files; a larger change is `builtin:input` `ERROR`, which blocks it. A binary or `too_large` file counts 0 lines and sets its flag; `size` is the new side's length, 0 for a deletion.
- **No clock.** Nothing in the input is "now", and identity status is judged at each object's witness time (R3.03), so an evaluation depends only on the policy's bytes and the input.
- **What later tickets add** (each additive, each a new field the static check learns): `change.state` (R3.09), `stack` (R3.10, for R3.24's rules), the `conflict` object for `[[conflicts.rule]]` (R3.25, R3.27, R3.28; this ticket defines its first fields, below), `budget` (R3.20), and `batch` (R3.14). A policy that names a field this daemon does not know is `INVALID_POLICY`, so a policy written for a later Reef fails closed on an earlier one.

### Trusted attestors

An `[attestors.<name>]` set is a predicate over one evidence object's signer, evaluated in Rust from the declared keys, then by its optional CEL `when`:

1. `e.key.status == "bound"`: certified, witnessed within the key's window and before every revocation that applies. Not configurable: unbound, expired, revoked and invalid keys never count.
2. Its identity is one of `identities` or a member of one of `groups`, matched by id for `idn_…` entries and by the certificate's name otherwise. Names are never reused within one daemon's database, but a restore can bring a name back with a new id, so `docs/policy.md` tells a policy that must not be fooled to pin ids and `authorities` (S-93).
3. `identity_kinds`, `actors` (default `["executor"]`), and `authorities` (each a 64-hex authority key id; empty for any authority this daemon verifies), when given.
4. `presence` at least the set's (`none` < `user_verified`); every key today has `none`, so a set asking for `user_verified` matches nothing until R3.43.
5. `self = "exclude"` (the default) drops objects with `e.self`.
6. `when`, a CEL expression over `e` (one evidence object) and `groups`, for what the declared keys cannot say: `e.fresh` (accepted by a job Reef queued), a stored log (`e.artifacts.exists(a, a.name == "test.log" && a.state == "stored")`), or the reference executor's sandbox (`e.annotations.sandbox.kind == "bubblewrap"`, an unverified claim of the trusted attestor itself).

A `when` that errors on an object means that object does not satisfy the set (trust fails closed), and the evaluation's `diagnostics` gain one warning per set naming the first such object and the error.

The names of the sets an object satisfies are `e.attestors`, which free rules can use (`evidence.exists(e, "ci" in e.attestors && e.kind == "build")`).

A solo developer's set names their own person identity and, to say "my machine", their daemon's authority key id (`reef identity authority show`). A team's names its `ci` identity, whose keys only CI's token can obtain (R3.03), and nothing else.

### Required evidence, limits, forbidden paths, sign-offs: evaluated in Rust

The declared tables are evaluated by `reef-policy` itself, not compiled to CEL, so their results carry data and their cost is linear and known. Each applies when its `paths` match a touched path (after `except`), or always when it has none, and its `when` is true.

- **`[[require]]`**: for each `kind`, and each of `targets` (or the whole check when empty), the objects of that kind and target from a named attestor set decide. **The newest verdict by witness time wins**: the latest `pass` or `fail` among them is the requirement's outcome, and `error` objects never count, since R3.01 defines `error` as no verdict. So a flaky run that failed and then passed on the same tree is satisfied, and a pass followed by a fail is not. No object: the pair is **missing**. Newest `fail`: the pair is **failed**, with the failing object's id. A per-target object never satisfies a whole-check requirement: how targets compose into a whole is R3.19's.
- **`[limits]`**: `max_files` over `change.paths`, `max_lines` over `lines_added + lines_removed`, `max_file_size` over each file's `size`, all after `except`. One rule, `limits`, reports which limit failed and by how much.
- **`[[forbid]]`**: unsatisfied when any touched path matches, listing up to 20 of them and the total. A rename out of a forbidden path touches it too.
- **`[[signoff]]`** and **`builtin:owners`**: sign-offs are evidence on the change's tree of one of `kinds` (default `signoff`), with `result: pass`, from a bound key with actor `human` certified for a `person` identity in `groups` or `identities`, with at least `presence`; `count` distinct identities are needed. Self-exclusion does not apply: a person signs off the work of their own agents. Sign-offs need no new producer: `reef evidence add --kind signoff --result pass --actor human` signs one today, R3.09's accept transition and R3.31's proposal view will sign them from the UI, and R3.43 adds presence. A sign-off is on the exact tree; carrying it across a later edit is R3.15's.

### Free rules: `[[rule]]`

`when` (optional) and `expr` are CEL over the whole input. `when` false: `NOT_APPLICABLE`. `expr` true: `SATISFIED`; false: `UNSATISFIED` with the rule's `message`; any other value, or any error at run time: `ERROR` with the error's text. The `when` of a `[[require]]`, `[[forbid]]` or `[[signoff]]` follows the same rule: one that errors, or yields anything but a boolean, makes its rule `ERROR`. (An attestor set's `when` is per object, above; a `[[conflicts.rule]]`'s that errors makes `conflict_tier` return the error, and R3.28 treats it as the strictest tier, `ask`.)

### The CEL environment

- **The standard library and the standard macros**, through `Env::stdlib()`, with optional syntax on and **no extensions**, and without `chrono`: times are integers, so `duration` and `timestamp` are not needed, and their absence keeps four crates out of the lockfile. `matches` uses the `regex` crate, which runs in linear time.
- **Reef's functions**, all pure:

  | Function | Means | Cost charged |
  | --- | --- | --- |
  | `glob(path, pattern)` | `path` matches the glob `pattern` (the file's glob rules) | 1 |
  | `any_glob(paths, patterns)` | some path matches some pattern | the length of `paths` |
  | `all_glob(paths, patterns)` | every path matches some pattern | the length of `paths` |
  | `matching(paths, patterns)` | the paths that match, in order | the length of `paths` |

  Patterns written as literals are compiled and checked at load; others are compiled once per evaluation, and an invalid one is the rule's `ERROR`.
- **Variables per expression**: a `[[require]]`, `[[forbid]]`, `[[signoff]]` or `[[rule]]` expression sees `change`, `evidence`, `provenance` and `groups`; an attestor's `when` sees `e` and `groups`; a `[[conflicts.rule]]` `when` sees `conflict` and `groups`.
- **The static check**, Reef's own, since cel-rust has none. It walks each expression's AST after parsing and refuses, with the expression's line and column in the file:
  - an identifier that is neither a variable of that expression nor bound by an enclosing comprehension;
  - a field selected on a value whose shape is known (the input's schema, followed through select chains and through the element type of a comprehension's range) that the schema does not have, such as `change.pahts` or `change.files.all(f, f.lines)`; below `annotations` and anything else of unknown shape, nothing is checked;
  - a call to a function that is neither CEL's standard library nor Reef's;
  - a comprehension whose range is a map of known shape (`groups`, `annotations` or below), whose iteration order cel-rust leaves undefined;
  - an expression over the limits above.

  What the check cannot see (a wrong type, a missing key under `annotations`) fails at run time as the rule's `ERROR`, which blocks.
- **The cost bound**, also Reef's own, computed before each expression runs from the input it is about to see, so it is exact about sizes and deterministic. Every AST node costs 1 and Reef's list functions their charge; a comprehension costs its range, accumulator and result once, plus `bound(range) × cost(loop condition and step)`. `bound` is: a list literal's length; for a select chain from a variable or a comprehension variable of known shape, the longest list at that path in this input (for `change.paths`, its length; for `e.artifacts`, the most artifacts any evidence object has); for `x.map(…)`, `x.filter(…)` and `matching(x, …)`, `bound(x)`; for `a + b`, the sum; for anything else, the input's total list elements plus the expression's literal ones. An expression over **10,000,000** is not run and is its rule's `ERROR` ("cost 3.2e9 over 1e7"); the sum over an evaluation is bounded at **50,000,000**, past which every remaining expression is `ERROR`. At the measured 0.14 µs per node, the worst case is about 7 seconds of one core, and real policies cost a few times the number of paths. The bound is in `docs/policy.md` as part of format 1, so another implementation agrees on what is too costly.
- **Determinism.** The same policy bytes and the same input give the same decision and the same status for every rule: inputs are sorted, nothing reads a clock or the environment, `all` and `exists` commute, and comprehensions over maps are refused. An error's text may name a different element between runs; its status does not change.

### The result

```text
Evaluation
  decision          ALLOW | BLOCK | NO_POLICY | INVALID_POLICY
  source            {revision, commit_id, path, blob_id, sha256, version}; for request text, only sha256 and version
  diagnostics       the load errors of INVALID_POLICY, each {rule, field, line, column, message}
  change_id, commit_id, tree_id, at_operation
  rules             every rule, built-ins first, then in file order:
                    {name, kind: builtin|require|limits|forbid|signoff|rule,
                     status: SATISFIED | UNSATISFIED | NOT_APPLICABLE | ERROR, message,
                     paths (at most 20) and paths_total,
                     missing and failed: [{kind, target, attestors, evidence_ids}],
                     signoff: {groups, identities, count, have, signed_by, presence, kinds},
                     evidence_ids (what satisfied it)}
  input             {paths, lines_added, lines_removed, evidence, evidence_ignored, provenance, conflicted}
  cost              the evaluation's total
  input_json        the input as JSON, only when asked for
```

- **`ALLOW`** when no rule is `UNSATISFIED` or `ERROR`; **`BLOCK`** otherwise. Every rule is evaluated and reported, so a blocked change sees every reason at once, which is the "structured reason" the phase's exit criterion asks for.
- **The built-in rules**, always first and always present: `builtin:input` (the input could be built within its limits), `builtin:conflicts` (the change's tree has no conflict: the design's "refuses a change that still contains a conflict"), `builtin:policy-file` and `builtin:owners` (above).
- **Fail closed.** A rule that errors blocks. An invalid policy blocks. Nothing in the result means "allow because the policy could not tell".
- **Conflict tiers and attempt caps** are not part of a change's evaluation. `reef_policy::Policy::conflict_tier(&ConflictInput) -> ConflictDecision { tier, attempts, rule }` returns the first `[[conflicts.rule]]` whose `paths` match one of the conflict's paths and whose `when` holds, else the `[conflicts]` defaults (`approve`, 3 when the table is absent). `ConflictInput` starts as `{change_id, paths, sides: [{change_id, identity, agent}]}`; R3.25 to R3.28 fill it from conflict objects and may add fields. R3.28 calls it; this ticket tests it with synthetic inputs and through `reef policy check --input`.

### Where the code lives: a new crate, `reef-policy`

`crates/reef-policy` is the format and the evaluator, with no Reef crate but `reef-error`, and no jj-lib, gRPC, tokio or SQLite, as `reef-evidence` is: the daemon evaluates with it, the `reef` binary checks files offline with it, the Phase 4 store evaluates with it (R4.11), and R6.03 documents what it implements. Dependencies: `cel` (`=0.15.0`, `default-features = false`, `features = ["regex"]`), `toml`, `serde`, `serde_json`, `globset`, `humantime`, `schemars`, `thiserror`, `reef-error`. `crate_graph` gains it with `reef-evidence`'s rule, and `reef-vcs` may depend on it.

Modules: `format` (the TOML schema and its checks), `glob`, `env` (the CEL environment and Reef's functions), `check` (the static check), `cost` (the bound), `input` (the input types, `Serialize` and `JsonSchema`), `eval` (attestors, tables, rules, the result), `conflict`. All of cel-rust's API is used from `env`, `check` and `cost` only, behind Reef's own types, so a breaking cel-rust release touches three modules.

`cel` is pinned exactly (`=0.15.0`), because each of its minor releases has broken its API and could change an expression's result. An upgrade is its own PR that runs the policy test corpus (tests 1 to 10) and the docs' examples.

In the daemon, `reef-daemon/src/policy/`: `load.rs` (the file at a revision through `Repo::read_file_at`, compiled and cached by blob id, 16 entries per daemon), `input.rs` (the input from the diff, `evidence_rows` and `key_identity`, `read_records`, and `job_evidence`), and `service/policy.rs`. The input is built on the repository thread and in the database's blocking pool as other reads are; the evaluation runs in `spawn_blocking`.

### The API: `PolicyService`, API revision 20

A new file, `reef/api/v1/policy.proto`:

```proto
// Repository policy (R3.07, ADR 0061): `reef-policy.toml` at a revision's root, evaluated over one
// change. Evaluation reads; it never refuses anything. Enforcement is the landing service's (R3.13).
service PolicyService {
  rpc EvaluatePolicy(EvaluatePolicyRequest) returns (EvaluatePolicyResponse) { option (reef.api.v1.access) = ACCESS_READ; option idempotency_level = NO_SIDE_EFFECTS; }
}
enum PolicyDecision { POLICY_DECISION_UNSPECIFIED = 0; POLICY_DECISION_ALLOW = 1; POLICY_DECISION_BLOCK = 2;
                      POLICY_DECISION_NO_POLICY = 3; POLICY_DECISION_INVALID_POLICY = 4; }
enum PolicyRuleKind { POLICY_RULE_KIND_UNSPECIFIED = 0; POLICY_RULE_KIND_BUILTIN = 1; POLICY_RULE_KIND_REQUIRE = 2;
                      POLICY_RULE_KIND_LIMITS = 3; POLICY_RULE_KIND_FORBID = 4; POLICY_RULE_KIND_SIGNOFF = 5; POLICY_RULE_KIND_RULE = 6; }
enum PolicyRuleStatus { POLICY_RULE_STATUS_UNSPECIFIED = 0; POLICY_RULE_STATUS_SATISFIED = 1; POLICY_RULE_STATUS_UNSATISFIED = 2;
                        POLICY_RULE_STATUS_NOT_APPLICABLE = 3; POLICY_RULE_STATUS_ERROR = 4; }
message PolicySource { string revision = 1; string commit_id = 2; string path = 3; string blob_id = 4; string sha256 = 5; uint32 version = 6; bool from_request = 7; }
message PolicyDiagnostic { string rule = 1; string field = 2; uint32 line = 3; uint32 column = 4; string message = 5; }
message PolicyEvidenceNeed { string kind = 1; string target = 2; repeated string attestors = 3; repeated string evidence_ids = 4; }
message PolicySignoff { repeated string groups = 1; repeated string identities = 2; uint32 count = 3; uint32 have = 4;
                        repeated string signed_by = 5; string presence = 6; repeated string kinds = 7; }
message PolicyRuleResult { string name = 1; PolicyRuleKind kind = 2; PolicyRuleStatus status = 3; string message = 4;
                           repeated string paths = 5; uint32 paths_total = 6; repeated PolicyEvidenceNeed missing = 7;
                           repeated PolicyEvidenceNeed failed = 8; PolicySignoff signoff = 9; repeated string evidence_ids = 10; }
message PolicyInputSummary { uint32 paths = 1; uint64 lines_added = 2; uint64 lines_removed = 3; uint32 evidence = 4;
                             uint32 evidence_ignored = 5; uint32 provenance = 6; bool conflicted = 7; }
message PolicyEvaluation { PolicyDecision decision = 1; PolicySource source = 2; repeated PolicyDiagnostic diagnostics = 3;
                           string change_id = 4; string commit_id = 5; string tree_id = 6; string at_operation = 7;
                           repeated PolicyRuleResult rules = 8; PolicyInputSummary input = 9; uint64 cost = 10; string input_json = 11; }
message EvaluatePolicyRequest {
  string repo = 1; string workspace = 2;
  string revision = 3;          // the change judged, one commit; `@` by default with `workspace`, required without
  string policy_revision = 4;   // where reef-policy.toml is read; empty for trunk()
  bytes policy = 5;             // a policy file's bytes to evaluate instead, at most 256 KiB (R3.08 builds on it)
  string at_operation = 6; bool skip_snapshot = 7;
  bool include_input = 8;       // fill `input_json`
}
message EvaluatePolicyResponse { PolicyEvaluation evaluation = 1; }
```

- **Errors**: the revision errors of `changes.proto` for `revision` and `policy_revision`; `INVALID_ARGUMENT` with reason `POLICY_SOURCE_CONFLICT` when both `policy` and `policy_revision` are set, `POLICY_TOO_LARGE` when `policy` is over 256 KiB. `NO_POLICY`, `INVALID_POLICY` and `BLOCK` are decisions, not errors: the call succeeded, and the answer is that the change would not land. Each reason is documented on the RPC, as ADR 0029 requires.
- **Who may call it**: every caller of a READ RPC, on the socket, the web listener and the remote listener. `policy` text from a remote `read` token is attacker-chosen CEL, which the cost bound and the limits keep to seconds of one core (S-91).
- **Review checklist**: ADR 0029's, item by item in the PR. `SERVED` gains `PolicyService`; `API_REVISION` 20 with its digest; no database migration (schema stays 11); no new WRITE RPC, so `remote/rules.rs` is unchanged.

### The CLI: `reef policy`

```
reef policy check [<file> | -r <rev>] [--input <json>]
reef policy eval  [-r <rev>] [--policy-revision <rev> | --policy-file <file>] [--input-json] [--require-allow]
reef policy init  [--stdout]
```

- **`check`** loads a policy, `./reef-policy.toml` by default, with no daemon: parse, references, globs, the static check. It prints the rules it found and every diagnostic as `file:line:column: rule: message`, and exits 0, or 2 (`InvalidArgument`) with the first diagnostic as the error and the rest in `hint`. `-r <rev>` reads the file at a revision through `FileService.ReadFile` and checks it the same way. `--input <json>` (an input as `reef schema policy input` describes, or one printed by `eval --input-json`) also evaluates offline and prints the evaluation; a JSON input with a `conflict` object evaluates `conflict_tier` instead. That is how an author tests a policy against a fixture, and how the seams for later inputs (sign-offs signed elsewhere, conflicts) are exercised before their producers exist.
- **`eval`** calls `EvaluatePolicy` for `@` (or `-r`), with the policy from `trunk()`, `--policy-revision`, or `--policy-file` (sent as `policy`). Text output: the decision, the source, then each rule not `SATISFIED` or `NOT_APPLICABLE` with its message, missing and failed evidence, and the sign-offs needed, then a count of the rest. `--input-json` prints the input. It exits 0 whatever the decision, as `reef evidence show` exits 0 for `invalid`; `--require-allow` exits 5 (`Conflict`, reason `POLICY_BLOCKED`) for anything but `ALLOW`, with the first unmet rule as `hint` and `reef policy eval -r <rev>` as `next`.
- **`init`** writes a starter `reef-policy.toml` in the current directory, refusing to overwrite one (exit 4, `AlreadyExists`), or prints it with `--stdout`. The starter names the default person identity (from `ListIdentities`) as the owner and as the only member of an attestor set `local` with actor `executor`, requires `test` evidence from `local` on every change, and carries a commented `ci` set and `[limits]`. It passes `check`. Without a daemon it uses the placeholder name `you` and says so.
- **JSON** (`reef_client::json`, `JsonSchema`): `PolicyCheck` (source, rules, diagnostics, and an evaluation with `--input`), `PolicyEvaluation` (the message's fields), `PolicyInit` (the path written). Brief view of an evaluation: `decision`, `source.sha256`, and for each unmet rule its name, status and missing kinds. `reef schema`'s `OUTPUTS` gains rows for the three commands.
- **`reef schema policy`** prints three JSON Schemas, `file`, `input` and `evaluation`, as `reef schema evidence` prints the evidence format; `reef schema policy input` prints one.
- **Not in the root help**, which is at its 512-byte budget: `policy` is in `--help-all`, and `help_lists_every_command` gains it. `docs/agent-guide.md`'s long part gains one bullet: "`reef policy eval` says whether `@` would land under the repository's policy, and which evidence or sign-off is missing."

## Tests

In `crates/reef-policy/` (unit tests per module, and `tests/` over the corpus):

1. `format`: a file with every key parses. Each of these is refused with its line, column and rule: an unknown key or table; `version = 2`; no `[owners]`; a duplicate rule name; an attestor, group or identity reference that names nothing; a bad glob; 257 rules; a 257 KiB file; an expression that does not parse; an expression with 1,001 nodes or a depth of 49; an unknown variable (`chnage.paths`); an unknown field on a known shape (`change.pahts`, `change.files.all(f, f.lines)`, `e.key.idnetity`); an unknown function; `e` in a `[[rule]]`; a comprehension over `groups` or `e.annotations`. Every diagnostic of a file is reported, not just the first.
2. `glob` (S-95): `*` does not cross `/` and `**` does; `docs` matches only `docs`; `Secrets/a.pem` matches `secrets/**`; `except` removes paths; a rename's old path counts.
3. `attestors` (S-92, S-93, S-97): one object against sets selecting by name, by id, by group, by identity kind, actor, authority and presence; `user_verified` matches nothing today; `unbound`, `expired`, `revoked` and `invalid` keys never match; `self` by session and by agent label is excluded by default and kept with `self = "allow"`; `when` over `e.fresh`, an artifact's `state` and an annotation; a `when` that errors leaves the object out and is reported.
4. `require`: a missing pair lists its kind, target and attestors; a trusted `fail` lists its object; pass-then-fail is failed and fail-then-pass satisfied (by witness time, not claimed time); `error` objects are ignored; an untrusted `pass` does not count; `targets` need one object each; a per-target object does not satisfy a whole-check requirement; `paths`, `except` and `when` decide applicability.
5. `tables` (S-90): `[limits]` with each key, `except`, binary and `too_large` files; `[[forbid]]` with paths listed up to 20 and the total; `[[signoff]]` counting distinct identities, requiring actor `human`, a `person` identity, the kind and the presence; `builtin:owners` on a change to `reef-policy.toml` and to `reef-checks.toml`, satisfied by an owner's sign-off; `builtin:policy-file` with a broken new policy; `builtin:conflicts`.
6. `rules`: `when` false is `NOT_APPLICABLE`; `expr` true, false, a string, and a runtime error give `SATISFIED`, `UNSATISFIED`, `ERROR`, `ERROR`; any `UNSATISFIED` or `ERROR` makes `BLOCK`; every rule is reported, built-ins first, then in file order.
7. `cost` (S-91): `change.paths.all(a, change.paths.exists(b, a == b))` over 100,000 paths is refused before it runs, with its bound in the message, in under 10 ms; the same over 100 paths runs; list literals, `map`, `filter`, `+` and `matching` are bounded as specified; a policy of 300 cheap rules over 100,000 paths hits the evaluation's total and reports the rest `ERROR`; the bound for one input is the same on every run.
8. `determinism`: one input evaluated 50 times, with its evidence, provenance and `annotations` inserted in a different order each time, serializes to the same evaluation.
9. `conflict`: the first matching `[[conflicts.rule]]` wins; `when` over `conflict`; defaults with and without `[conflicts]`; `attempts` outside 1 to 20 is a load error.
10. `corpus`: every policy and input under `tests/corpus/` evaluates to its expected JSON; every marked `toml` block in `docs/policy.md` and the `init` starter load; the three JSON Schemas validate the corpus's inputs and evaluations (`jsonschema`).

In `crates/reef-daemon/tests/policy.rs` (`TestDaemon`, `testing::no_automatic_snapshots` in new fixtures):

11. `evaluate` (S-92, S-94): a repository whose `main` has a policy requiring `test` from a `ci` set, and a change under `crates/`:
    - no evidence: `BLOCK`, `tests` missing `(test, "", [ci])`;
    - evidence signed with a session key for `ci-main` with actor `executor`, through a remote token linked to it: `ALLOW`, the rule's `evidence_ids` naming it;
    - the same claim signed with the default person identity, with an `agent` key, with a bare `--key`, and by a key revoked `--since` before it was witnessed: none counts, and each is in `evidence` with an empty `attestors`;
    - evidence added from the change's own workspace with the workspace's `reef-agent`: `self` is true and the default set drops it;
    - 2,000 untrusted objects on the tree: the trusted one is still read, `evidence_ignored` counts the rest.
12. `sources` (S-90, S-96): `policy_revision` defaults to `trunk()`; a change that edits `reef-policy.toml` to remove its requirement is judged by `main`'s and needs the owners' sign-off; `--policy-revision` and `policy` text are used when given; both at once is `POLICY_SOURCE_CONFLICT`; no `main` is `NO_POLICY`; a broken policy on `main` is `INVALID_POLICY` with its diagnostics; `source` carries the commit, blob id and SHA-256; a second evaluation of the same blob compiles nothing (a counter); `at_operation` evaluates the change as it was.
13. `inputs`: `change.paths`, `files` and the line totals equal `GetDiff`'s stat for the change, renames included; a conflicted change fails `builtin:conflicts`; provenance records of the change appear with their `KeyIdentity`; `include_input`'s JSON validates against `reef schema policy input`, and `reef policy check --input` on it gives the same evaluation.
14. `remote` (S-91): a remote `read` token evaluates; `policy` text of 257 KiB is `POLICY_TOO_LARGE`; text whose rule costs too much returns at once with that rule `ERROR`.

- **Order**:
  1. Feasibility first, in `reef-policy` with nothing else: add `cel = "=0.15.0"` (no default features, `regex`), run `cargo deny check`, and write a spike test that parses with `Env::stdlib().parser().max_recursion_depth(48)`, walks the AST (comprehensions included), binds a serde input with `Context::add_variable`, registers `any_glob`, evaluates with `Value::resolve`, and times 100,000 paths in release. Record the numbers and the lockfile's new crates in the PR. If any of it is not public or behaves otherwise in 0.15.0, stop and report before building on it.
  2. `format` and `glob` (tests 1, 2).
  3. `env`, `check` and `cost` (tests 1, 7), the cost model written down in `docs/policy.md` as it is built.
  4. `input`, `eval` and `conflict` (tests 3 to 6, 8, 9), then the corpus (test 10).
  5. The daemon's `load` and `input`, then `PolicyService` (tests 11 to 14), then the CLI (15), then the documents.
- **Building.** Every local build, on macOS and in the Linux container, sets `CARGO_INCREMENTAL=0` and `CARGO_PROFILE_DEV_DEBUG=line-tables-only`, and checks that at least 50 GiB of disk is free first (`df -g .`, or `df -BG .` in the container); stop and clean (`cargo clean`, the container's `reef-target` volume) below that. This ticket has no `cfg(target_os)` code, so the hosted Linux leg covers Linux; the privileged container is for reproducing a Linux-only failure.
- **The input's shape is one Rust type**, `reef_policy::input::Input`, serialized for CEL with `cel::to_value`, for `input_json` with `serde_json`, and described by `schemars`; the static check's field schema is derived from the same `JsonSchema`, so the three cannot drift.
- **Attestor matching and the tables are plain Rust** over `Input`, run before any CEL, and the per-object `attestors` and `self` are filled in then.
- **Globs**: one `globset::GlobSet` per list, built at load with `literal_separator(true)` and `case_insensitive(true)`.
- **Evaluation in the daemon** runs on `spawn_blocking`; the compiled `Policy` is an `Arc` in the cache, keyed by the blob id, since `Program` is `Send + Sync`.
- **Diagnostics' positions**: `toml`'s spans for keys and values, plus cel-rust's `SourceInfo` offset within the expression's string, mapped back to the file's line and column (for a basic string, through its escapes).
- **No new configuration.** Limits are format 1's, the same everywhere; the daemon's `config.toml` gains nothing.

## Risks

- **cel-rust is young and moves fast.** No type checker, no cost tracking, a breaking API in every minor release, and a tree-walking interpreter. Mitigations: an exact pin; cel-rust used from three modules; Reef's own static check and cost bound; the corpus as the regression suite for any upgrade; fail closed on any error. If it proves wrong, `cel-cxx` is the CEL fallback and Rego the design's.
- **The cost bound is conservative and may refuse a reasonable rule.** A rule over an unknown-shape list is charged the whole input. Mitigations: Reef's list functions are charged exactly; the message prints the bound; `docs/policy.md` shows how to write path rules with `any_glob` and the tables instead of nested comprehensions.
- **Trust is easy to misread on one uid.** A policy that trusts the developer's own identity trusts every agent running as that user (S-59, S-92). Mitigations: `self` exclusion where Reef can see it, `actors` defaulting to `executor`, the docs' recipes, and the threat model's rows; the real answer is a `ci` identity and, later, verified presence.
- **Strict parsing makes policy upgrades all or nothing.** A policy using a table from a later Reef blocks every landing on an older daemon. That is intended, and `docs/policy.md` says to upgrade daemons before policies.
- **The first policy reaches main outside the gate**, and so does every change while there is none. Documented in `docs/policy.md` and handled by R3.13's refusal under `NO_POLICY`.
- **Large changes are expensive to judge.** Line counts read both sides of every file. Mitigations: the 100,000-file cap, the diff's `too_large` limit, and the benchmarks.

## Choices this brief made, and why

- **Tables with CEL conditions, in TOML**, because the landing service, the queue and the inbox need to know what is missing and who must sign, which a boolean expression cannot tell them.
- **The destination's policy, with the policy files as a built-in owners' area**, because a change must not choose the rules that judge it.
- **Trust computed in Rust before CEL**, because attestor sets must be data for R3.13, and because flooding and self-attestation are easier to get right once than in every policy.
- **Newest witnessed verdict wins**, because a retried flaky check should pass on the same tree, and witness time is the one time a signer cannot claim.
- **Sign-offs as `signoff` evidence**, because R3.03 already signs `human` evidence on a tree, and the UI tickets only need to sign one.
- **Reef's own static check and cost bound**, because cel-rust has neither, and a policy that a remote READ caller can send must not be able to hold a core.
- **Fail closed everywhere**, because a policy that cannot tell must not let things land.
- **A crate of its own**, because the daemon, the CLI, the store and the specification all need the evaluator, and none of them needs it to link jj-lib.
- **No storage and one READ RPC**, because nothing acts on a decision until R3.13, and an evaluation must be repeatable from the tree and the evidence alone.

## Decisions for the user

Grouped for asking; the brief's body follows every recommendation.

**Group 1: the file and where it comes from**

1. **Format and name.** `reef-policy.toml` at the tree's root: strict TOML tables (attestors, require, limits, forbid, signoff, conflicts) whose conditions are CEL, plus `[[rule]]` tables of free CEL, `version = 1`. *Recommended*: as stated. The alternatives are a pure `reef-policy.cel` expression (no data for the landing service about what is missing), or a `.reef/policy.toml` directory layout.
2. **Which policy judges a change.** The destination's (`trunk()` by default; R3.13's landing branch), never the change's own; a built-in, unremovable `builtin:owners` sign-off on changes to `reef-policy.toml` and `reef-checks.toml`; a change's own new policy must load. *Recommended*: yes. The alternatives are the change's own tree (it would judge itself) or the daemon's configuration (not reviewed with the repository).
3. **No policy file.** `NO_POLICY`: nothing lands automatically until a policy is committed, and `reef policy init` writes a starter that trusts this machine's default identity as an executor and requires `test`. *Recommended*: as stated. The alternatives are a built-in permissive default (everything lands) or a built-in default trusting this machine.

**Group 2: what counts as trusted evidence**

4. **Attestor sets.** Named sets of bound keys, selected by identities and groups (names or pinned ids), identity kind, actor (default `executor`), authority key ids, and presence, excluding by default evidence from the change's own provenance session or agent label, with an optional CEL `when` over the object (freshness, stored artifacts, annotations). *Recommended*: yes. The alternative is trust written entirely in CEL over raw evidence.
5. **Conflicting verdicts on one tree.** The newest `pass` or `fail` by witness time decides; `error` never counts. *Recommended*: newest wins, so a retried flaky check can pass. The alternative is that any trusted `fail` blocks the tree for good.
6. **Sign-offs.** Evidence of kind `signoff` (configurable per area), `result: pass`, actor `human`, from a `person` identity in the area's groups, at least the area's presence, `count` distinct people, on the exact tree. *Recommended*: yes, since `reef evidence add` already signs these and the UI tickets only need to sign one. The alternative is a separate sign-off object and RPC in R3.09.
7. **Path matching.** Globs match ASCII case-insensitively everywhere; a rename touches its old and new paths. *Recommended*: case-insensitive, since macOS checkouts merge case variants. The alternative is case-sensitive matching, as git compares paths.

**Group 3: evaluation**

8. **Limits and cost.** A static cost bound computed from the real input before each expression runs (10,000,000 per expression, 50,000,000 per evaluation), with file and expression size limits, all fixed in format 1 rather than configurable; over the bound is the rule's `ERROR`. *Recommended*: yes, deterministic and the same on every daemon. The alternatives are a wall-clock timeout (not deterministic, and cel-rust cannot be interrupted) or limits in each daemon's configuration.
9. **Failure.** Every rule is evaluated and reported; a rule error blocks; an invalid or missing policy is a decision (`INVALID_POLICY`, `NO_POLICY`), not an RPC error. *Recommended*: fail closed, as stated.
10. **The engine.** `cel` 0.15.0 (cel-rust), pinned exactly, without `chrono` or extensions, in a new `reef-policy` crate with no jj-lib, behind Reef's own static check. *Recommended*: yes. The alternatives are `cel-cxx` (Google's checker and cost limits, through a C++ build) or Rego through `regorus` (the design's fallback).

**Group 4: the surface and the line with later tickets**

11. **The surface.** `PolicyService.EvaluatePolicy` (READ, API revision 20) with optional policy text and the input as JSON; `reef policy check` (offline, also against a JSON input), `eval` (`--require-allow` exits 5) and `init`, in `--help-all` only; `reef schema policy`; MCP `NOT_TOOLS`; no database change. *Recommended*: yes. The alternatives are offline `check` only (no way to ask about a real change before R3.13), or also an MCP tool (over `tools/list`'s budget).
12. **Scope lines.** Enforcement R3.13; simulation R3.08 (on the policy-text field); conflict tiers and caps parsed and looked up here, applied by R3.28; budgets R3.20, transfer R3.15, stack rules R3.24, lifecycle input R3.09, each additive to this file. *Recommended*: yes, which keeps this ticket M.
