# R3.04 Provenance records

Phase 3 · Size M, at its top end, with the split below (L without it) · Depends on: R3.03 (`custody: daemon` in the certificate format, `session_keys`, `identity::retention::pinned`, `KeyIdentity`, schema 9, API revision 17), R3.02 (GC's seventh step, whose mark and sweep this ticket's eighth step follows) · Unblocks: R3.25, R3.37, and the follow-up row this brief adds, R3.44 (provenance from harnesses and SDKs); through them R3.07's "require provenance" rule, R3.31's intent section, R3.35 and R4.07

## Context

The design states provenance twice. Data model: "Each snapshot carries a provenance record: agent identity, model and version, session ID, originating task reference, a hash of the instruction that produced the change, and a signature over all of it. This is what makes a thousand agent commits auditable after the fact." Provenance section: the same fields, "signed by a short-lived session key", bound to an operator or CI identity "so provenance chains to a person or pipeline without long-lived agent secrets", and "Policy can require provenance for landing, and the query layer can filter and aggregate on it."

Three earlier tickets left this one its jobs:

- **R3.01** left the format question open: provenance "may reuse this envelope, these key ids, and the `evidence_keys` table, with its own predicate type and a `gitCommit` subject; R3.04 decides that."
- **R3.03** reserved the key custody: "`custody: daemon` keys, in memory, one per workspace session, issued with `reef_evidence::session::certify` and recorded in `session_keys`. It signs provenance with them, and extends `identity::retention::pinned` to keys that provenance names. A workspace's session id is the provenance record's session." Its durability note says "a restore invalidates them" holds for these keys, because they live only in memory. ADR 0057 adds the limit: "R3.04's daemon-held keys sign provenance only", never as a signing oracle for evidence. R3.03 also left the workspace `owner` an opaque string and moved "binding a workspace's work to a session" here (R1.01's row).
- **R2.16** (ADR 0044) left attribution: "'Who wrote it' is whoever the operation names; `reef-agent` is not authentication. R3.04's provenance makes it durable and signed", and R3.37 reads "R3.04's provenance per commit".

The design also says what Reef will not do: "Reef never starts an agent or holds the prompt that started one." So the instruction is a hash that Reef is given, never text that Reef keeps.

This ticket builds five things, all local:

1. **A provenance record format**: a third predicate type in R3.01's envelope, about one commit, with the commit's change, tree, workspace, session and a declared context (model, harness, task reference, instruction hash, client session).
2. **Daemon-held session keys**: one session per workspace, certified by R3.03's authority with `custody: daemon`, held only in the daemon's memory, renewed in the same session after a restart.
3. **A record for every commit the daemon records for a workspace**: each snapshot that commits, and each `EditFiles` that names the workspace. Signing never makes a snapshot fail.
4. **Declarations**: the context is declared at workspace creation and replaced with a new `DeclareProvenance` RPC, which snapshots first so that edits already on disk keep the context they were made under.
5. **Reads and retention**: `GetProvenance` and `ListProvenance` re-verify every record and report R3.03's `KeyIdentity` beside the signature; GC compacts and expires records.

Harness hooks, the MCP server and the SDKs' workspace blocks are the clients that would declare automatically. They become a follow-up row, R3.44 ("Departures"). This ticket gives them the API, the CLI they call, and the format.

### What a record is about: one commit the daemon recorded

- **One record per commit the daemon records for a workspace.** That means each snapshot that commits, of any kind (`watcher`, `explicit`, `final`, `move`, `shutdown`, and the carried follow-ups of ADR 0039), and each `EditFiles` that names the workspace (kind `edit`). A snapshot that finds nothing changed commits nothing and records nothing. The design's "snapshot" is a commit (data model table: "a tree hash, parent snapshot hashes, author, timestamp, and the change ID"). A record about the commit says what produced that exact content, in which session and under which declared context.
- **The subject is the commit (`gitCommit`), not the tree.** Evidence binds to the tree because it is a claim about content, and two changes with one tree share it (R3.01). Provenance is a claim about an act, and two sessions can write the same tree. Binding to the tree would merge their records. The predicate also carries the tree, so a reader can join a record to the evidence on it without opening jj.
- **The change is in the predicate, and readers look records up by change.** A commit id dies with every describe, rebase or squash, and none of those writes a record, because they add no content. "Who produced this change" is therefore every record of its change id, across rewrites. R3.37 and R3.25 look provenance up by change, not by the exact commit they hold ("What later tickets inherit"). This corrects R2.16's "R3.04's provenance per commit".
- **Nothing is written into the commit.** No trailer, no description, no jj attribute. The record lives in `reef.sqlite3`, keyed by commit id. A git push (R3.17) or a git export therefore carries no provenance, which is the design's "evidence, provenance, and conflicts stay local". The commit id does not change because a record exists.
- **Commits written by the user's own jj or git, outside a Reef workspace, get none.** A `reef-<id>` workspace snapshotted by the `jj` CLI, which R1.16's reindex picks up, gets none either. The daemon did not record those commits, so it does not attest them.

### The statement: a third predicate type in the same envelope

The record is an in-toto Statement v1 in R3.01's DSSE envelope, with the same PAE, canonical envelope, size, depth, duplicate-key and key rules (ADR 0055), signed once by a daemon-held session key:

```json
{
  "_type": "https://in-toto.io/Statement/v1",
  "subject": [{"name": "commit", "digest": {"gitCommit": "5d41402abc4b2a76b9719d911017c592ae2b6a3e"}}],
  "predicateType": "urn:reef-vcs:provenance:v1",
  "predicate": {
    "change": "8f3a0c2d91e4b6751c2d0e9f4a7b3c18",
    "tree": {"gitTree": "4b825dc642cb6eb9a060e54bf8d69288fbee4904"},
    "workspace": "0123456789abcdef",
    "kind": "watcher",
    "session": "ses_41c9e07ab2d35f18",
    "sequence": 42,
    "agent": "builder-3",
    "recordedOn": "2026-11-06T10:12:03.418Z",
    "context": {
      "model": "example-provider/model-x-2026-10",
      "harness": "example-harness/2.1.0",
      "task": "https://tracker.example/T-123",
      "instruction": {"sha256": "9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08"},
      "clientSession": "c0ffee00-1234",
      "declaredOn": "2026-11-06T10:11:58.002Z"
    }
  }
}
```

| Field | Required | Meaning | Source | Checked |
| --- | --- | --- | --- | --- |
| `subject` | yes | Exactly one, `name` `"commit"`, `digest` `{"gitCommit": <hex>}` | observed | 40 or 64 lowercase hex; no other digest key in v1 |
| `change` | yes | The commit's change id, as `Change.change_id` gives it | observed | 32 lowercase hex |
| `tree` | no | `{"gitTree": <hex>}`; absent when the commit's tree is conflicted | observed | as the subject |
| `workspace` | yes | The Reef workspace id | observed | 16 lowercase hex |
| `kind` | yes | What recorded it: a snapshot kind, or `edit` | observed | `^[a-z][a-z0-9-]{0,31}$`; an unknown kind is kept and shown, never refused, so a later kind is readable by this reader |
| `session` | yes | The workspace's provenance session, `ses_<16 hex>`: the R3.03 session the signing key is certified for | observed | pattern; at read, equal to the certificate's `session` |
| `sequence` | yes | This record's number in its session, from 1 | observed | 1 to 2^53 |
| `agent` | no | The session's agent label: the creating request's `reef-agent`, else the workspace's `owner`, fixed for the session | declared | R3.03's `agent` rule |
| `recordedOn` | yes | When the daemon recorded it: the operation's end time for a snapshot, the write's for an edit | observed (the daemon's clock) | R3.01's time format, milliseconds |
| `context` | yes (may be `{}`) | The declared context in effect when the commit was recorded | declared | below |
| `context.model` | no | The model and its version, in the client's own naming | declared | 1 to 128 bytes, visible ASCII |
| `context.harness` | no | The agent runtime and its version, `name/version` | declared | 1 to 128 bytes, visible ASCII |
| `context.task` | no | The originating task: a URI or an opaque reference | declared | 1 to 512 bytes UTF-8, no control characters |
| `context.instruction` | no | `{"sha256": <hex>}` of the instruction ("The instruction hash") | declared | 64 lowercase hex; no other key in v1 |
| `context.clientSession` | no | The harness's own session id, which groups the workspaces of one harness session (subagents included) | declared | 1 to 128 bytes, visible ASCII |
| `context.declaredOn` | no | When this context was last declared | observed (the daemon's clock) | R3.01's time format |

- **Identity is not in the predicate. It is in the key's certificate.** The certificate binds the signing key to an operator identity, an actor, an agent label, the session and `custody: daemon` (R3.03). So the design's "agent identity" is the certified identity and actor plus the declared agent label. A reader gets both from `KeyIdentity`. The record has no field in which anyone names itself.
- **No operation id.** GC rewrites operation ids, so a signed one would go stale. The operations of a commit are R2.16's to find.
- **No repository.** Reef's repository ids are local to one daemon. The row is keyed by repository (ADR 0003), and R4.07 names the repository when it publishes.
- **Bytes.** `reef-evidence` writes compact JSON in the order of the example and leaves out absent optional fields, so the same record gives the same bytes. The record's id is the SHA-256 of the canonical envelope, as an evidence id is. ADR 0055's stability rules apply to `urn:reef-vcs:provenance:v1`: fields are only added, and a change of meaning is a new predicate type.
- **Keys.** The signing key's SPKI is recorded in `evidence_keys` when it first signs, as R3.03 does for every session key. That table now holds the keys of evidence and of provenance. Its name stays, and ADR 0058 says so.

### Signed, observed, declared: what a record proves

A valid, `BOUND` record proves one thing beyond its integrity. **The holder of a key that this daemon's authority certified for session S, bound to identity I with `custody: daemon`, signed a statement that commit C, of change X with tree T, was recorded in workspace W at time t, while the declared context was K.** Each field is one of three kinds:

| Kind | Fields | What the reader may rely on |
| --- | --- | --- |
| Observed by the daemon | commit, change, tree, workspace, kind, session, sequence, `recordedOn`, `declaredOn` | That the daemon recorded them, as far as the daemon's key is trusted |
| Certified by the authority | identity, identity kind, actor, custody, the session's agent label, the key's window | What R3.03's certificate says, with its limits (S-58, S-59) |
| Declared by a client | `agent`, `model`, `harness`, `task`, `instruction`, `clientSession` | Only that a client with access to the workspace declared them. Reef verifies none |

**The one-uid limit, stated.** On the socket, any same-uid process can do four things (ADR 0027):

- write a file into a workspace, which makes the daemon record and sign a commit the agent never wrote;
- call `DeclareProvenance` with any model, task or instruction;
- read `authority.pem`, and sign records of its own with a key it certifies;
- attach a debugger to the daemon and read a held key.

So against a same-uid agent, a record shows what the daemon saw and what it was told, not who typed what (S-67, S-68). What the record does guarantee:

- **Remote callers.** A remote caller declares only for workspaces its own token created, and those workspaces bind only its token's linked identity (S-69).
- **Commits.** A record exists only for a commit the daemon itself recorded. No caller chooses its subject.
- **Integrity.** Any change to a stored record, or to its key or certificate rows, is reported at every read.

**Not a signing oracle.** ADR 0057 rejects "a signing RPC with daemon-held keys". Here, the bytes the daemon signs are always a provenance predicate about a commit it has just recorded. A caller controls only the declared fields, which are bounded strings, and never the subject or the predicate type. A held key never signs evidence, a certificate or a proof. `reef-evidence`'s `provenance::sign` takes a `Record`, not bytes, and the daemon's held keys are reachable only through it.

### The instruction hash

- **Of what.** The instruction text the agent was given for this work, as UTF-8, exactly as delivered, with no trimming or normalization: a person's prompt, the task message of a non-interactive run, or (R3.12) a review comment addressed to the agent. A harness's own system prompt and context files are not the instruction. "Exactly as delivered" means anyone who holds the text can check it: `printf %s "$text" | shasum -a 256`.
- **Algorithm.** SHA-256, lowercase hex, in a DigestSet (`{"sha256": …}`), so another algorithm can be added beside it later. It is the hash every Reef id outside jj uses (ADR 0055), so R3.12 can compute a comment's hash the same way and R3.37 can link the two.
- **The text is never stored, and never sent.** The CLI hashes a file or stdin in the process and sends only the digest. The API takes only `instruction_sha256`. This follows the design's "Reef never … holds the prompt". A short instruction can be recovered from its hash by guessing ("fix the bug"), and anyone who can read provenance can try (S-70). Question 4 asks whether to salt it instead.
- **One instruction at a time.** A record carries the instruction in effect when its commit was recorded. A new instruction replaces the old one at its declaration. Compaction (below) keeps the first and last record under each instruction, so "which instruction was this change made under" survives it.

### The context: declared at creation, replaced by `DeclareProvenance`

- **At creation.** `CreateWorkspaceRequest.provenance` (a `ProvenanceDeclaration`) sets the initial context, the identity and the actor. The identity and the actor are fixed for the session; the context is not.
- **Later.** `DeclareProvenance(workspace, declaration)` replaces fields of the context. A field that is set replaces the old value, and an empty string clears it. A field left unset keeps its value. `declaredOn` becomes now. Identity and actor cannot change: a different identity is a different workspace.
- **It snapshots first.** Edits already on disk were made under the old context. `DeclareProvenance` therefore takes an explicit snapshot of the workspace, which records under the old context, and swaps the context only once that snapshot is done, under the workspace's scan lock, so no snapshot sees half of it. `no_snapshot: true` skips the snapshot, for a client that has just snapshotted. The response carries the snapshot's operation, unset when nothing changed, as `SnapshotWorkspace`'s does. A harness's prompt hook (R3.44) therefore snapshots once per prompt, which it already does for the re-hold, within its timeout.
- **It is stored.** The current context of each live session is a row in `provenance_sessions`, so it survives a restart and a restore. Only the current context is kept. The records hold the history.
- **It records no operation of its own.** The context is daemon metadata and not jj state, so undo has nothing to revert. The only operation in the response is the snapshot's. A declaration is logged under `reef_daemon::provenance::audit` (workspace, session, which fields changed, the caller's `reef-agent`, the remote token), and remote calls are logged in `remote::audit` too.
- **Who may declare.** Every socket client, since one uid is one trust domain. Through the remote listener, the token that created the workspace, by `Rule::OwnWorkspace`, which `remote/rules.rs` already has. The web listener serves no WRITE method.

### Sessions and daemon-held keys

**One provenance session per workspace**, from creation to release or reclaim. Its id is a `ses_<16 hex>`, allocated when the workspace is created, or lazily at the first record for a workspace older than this ticket. When the first key is certified, the R3.03 `sessions` row is written with the session's identity, actor, agent and channel.

**Which identity a workspace's session binds**, following R3.03's issuance rules through an internal path:

| Workspace created through | Identity | Actor | When the rules refuse |
| --- | --- | --- | --- |
| The socket, no identity named | The default `person` identity | `agent`, or the one declared (`human` with `presence: none`, `executor`) | No usable default: the workspace is created, and its records are signed by an uncertified held key (`UNBOUND`, `problem: no_default_identity`) |
| The socket, an identity named | That `person` identity | As declared | Creation is refused with R3.03's reason (`IDENTITY_NOT_FOUND`, `IDENTITY_REVOKED`, `SESSION_KEY_REFUSED` with `ci_over_socket` or `human_for_ci`) |
| The remote listener, token linked to X | X, and naming another is refused | `agent` or `executor`; `human` is refused (`human_over_remote`) | Creation is refused with R3.03's reason |
| The remote listener, token with no link | None | `agent` | Records are signed by an uncertified held key (`UNBOUND`, `problem: token_not_linked`) |
| Older than this ticket, or a restore | As the row's `remote_token_id` says: the token's link, else the default | `agent` | As the rows above |

A request that names nothing is never refused because of provenance. An explicit identity or actor that the rules refuse fails the creation, because the caller asked for something it cannot have.

**The key's life**:

| Event | Session | Held key |
| --- | --- | --- |
| Workspace created | `provenance_sessions` row, with the context; nothing certified yet | none |
| First record | the R3.03 `sessions` row is written with the first certificate | generated in the daemon (`SigningKey::generate`), certified by `certify` with `custody: daemon`, `presence: none`, for `[session_keys] max_lifetime` (24 hours by default); `session_keys` row; SPKI in `evidence_keys` |
| A record within 5 minutes of the key's `notAfter`, or after it | same | a new key in the same session (renewal), before signing |
| Daemon restart | same: the row persists | gone. The next record issues a new key in the same session |
| Restore | same | gone. The next key comes from the new authority (R3.03 retires the restored one); old records still verify |
| `MoveWorkspace` | same | same |
| `DeclareProvenance` | same; context replaced after the snapshot | same |
| R3.03 revokes the session (`session revoke`) | the next record starts a **new session** for the workspace, logged in `provenance::audit` | dropped |
| R3.03 revokes the identity | records go on with an uncertified held key (`UNBOUND`, `problem: identity_revoked`) | dropped |
| R3.03 rotates the authority without `revoke` | same | kept until it expires; renewals come from the new authority |
| … with `revoke`, or `RevokeAuthority` of the key's authority | same | dropped; the next key comes from the current authority |
| The creating remote token is revoked or expires | same | renewal falls back to an uncertified held key (`problem: token_revoked`) |
| Release or reclaim | the final snapshot records, then `ended_at` is set | dropped |
| `[provenance] enabled = false` | no row; nothing records | none |

- **Why a held key lives `max_lifetime`, not `lifetime`.** A short life limits what a leaked client key can do, and witness-time validity makes a key's window matter for evidence that arrives later. A held key signs at the instant the daemon witnesses, and the process that holds it can read `authority.pem` anyway. One key per session per day, rather than per hour, keeps `session_keys` at about one row per workspace session per day, plus one per restart. Records pin these rows, so the difference adds up. Question 7.
- **The issuing path.** `identity::issue::issue_held(identity, actor, agent, session, channel) -> HeldKey { signing_key, key_id, not_after, certificate }` applies R3.03's rules table with the session's stored channel (`socket` or the creating token's id), skips the proof of possession (the daemon generated the key), certifies with `custody: daemon`, and inserts `sessions` (if new) and `session_keys` in one transaction. It counts toward R3.03's 10,000-key limit per identity. No RPC reaches it: only the provenance signer calls it.
- **Revocation reaches memory.** R3.03's revoking handlers call `Provenance::revoked(scope)` after their transaction commits, which drops every held key the revocation covers. The signer also checks, before it signs, that its key's session, identity and authority are not revoked in the database (one cached read per key, refreshed by those calls), so a revocation written behind the daemon takes effect at the next renewal at the latest.
- **Uncertified held keys.** When no identity can be bound, the daemon still signs, with a held key it generates per session and does not certify. The record reads `UNBOUND`, exactly as evidence signed with a bare `--key` does. Recording nothing would leave R3.37 nothing to show, and an `UNBOUND` record still says what the daemon saw. `Workspace.provenance.problem` says why. Question 8.
- **Memory.** A held key is ring's `Ed25519KeyPair`, which cannot be wiped (R3.03's S-65 note). Nothing is written to disk. A core dump of the daemon would hold the keys, which is ADR 0027's limit.

### Recording, and never failing a snapshot

- **Where.** `record_commit`, on the snapshot's blocking half, after the index row, and the `EditFiles` path after `write_change` returns. Both call `Provenance::record(repo, workspace, commit, change, tree, kind, recorded_on)`. That function, under the session's mutex, does the following in order:
  1. renews the key if needed;
  2. builds the predicate from the session row and the commit;
  3. signs it;
  4. in one `IMMEDIATE` transaction, inserts the record, bumps `next_sequence`, and inserts the key's `evidence_keys` row if it is new.
- **The tree.** `SnapshotCommit` gains `tree_id: Option<String>`, filled by `commit_snapshot` from the commit it has just written, so recording needs no store read. `EditFiles` takes it from the `Change` it returns.
- **Never fails the snapshot.** Any error in recording (issuance, signing, the insert) is logged at `warn` under `reef_daemon::provenance` with the workspace and commit. It increments the session's `missing_records`, and the snapshot's outcome is unchanged. Provenance is an attestation about work, and losing one never loses the work. A crash between the snapshot's commit and the record's insert also leaves a commit with no record. Nothing backfills it, because a later signature would claim a later `recordedOn`. `sequence` has no gap there, since the number is taken in the insert's transaction. Compaction's gaps are deliberate.
- **Ordering.** Records of one session are inserted in sequence order: snapshots of one workspace are serialized by its scan lock, and an `EditFiles` naming it records under the same session mutex.
- **One record per commit.** `(repo_id, commit_id)` is unique. A second insert for the same commit (which no path is expected to cause) is skipped and logged.

### Reading and verification

`GetProvenance` and `ListProvenance` re-verify every record at every read, in ADR 0055's order, with R3.01's rule that a read takes every field from the verified payload, never from the columns:

1. The envelope, size and depth; the key by `keyid` from `evidence_keys`; the signature over the PAE; then the statement and the predicate. Then every index column (`commit_id`, `change_id`, `tree_id`, `workspace_id`, `session_id`, `sequence`, `kind`, `recorded_at`, and the context columns) must equal the payload. All of that passing is `signature: SIGNATURE_CHECK_VALID`, R3.01's enum. Anything else is `INVALID`, with the payload's values where it parsed.
2. The identity: R3.03's `check_certificate` for the key and `status_at` with `witnessed_at` set to the row's `recorded_at`. The daemon is its own witness, so a record is `BOUND` unless something is revoked from before it. On top of R3.03's rules, a record reads `INVALID` when its certificate's `custody` is not `daemon`, or its certificate's `session` is not the predicate's `session`. A client-held key cannot sign provenance that reads as the daemon's, and a held key cannot vouch for another session. `UNBOUND`, `EXPIRED`, `REVOKED` and `INVALID` have R3.03's meanings. A revocation made later is reported beside `BOUND`.
3. A page looks its keys up in one query and checks each distinct certificate once. Both checks run on the blocking pool, as R3.03's evidence reads do.

Nothing in a read says "trusted". R3.07 decides that, as for evidence.

### What survives what

| Event | Records | Session and keys |
| --- | --- | --- |
| Describe, rebase, squash, abandon, undo | Unchanged: they name the commit that was recorded, which may become hidden; the change still finds them | Unchanged |
| Operation GC (step 1) and `git gc` | Unchanged: keyed by commit id. A record's commit may leave the object store; the record still reads, and still names its change and tree | Unchanged |
| GC's eighth step | Compacted and expired (below) | Keys no record or evidence names are swept by R3.03's sweep; ended sessions with no record go |
| Restart | Kept | Session kept; held key gone, a new one at the next record |
| `reef backup`, `restore` | Copied and restored with the database (no layout change) | Rows copied; held keys are in memory and gone; the new authority certifies the next ones |
| `reef repo forget` | **Deleted** with the repository's other rows, in the same transaction, as evidence is | `provenance_sessions` of the repository deleted; R3.03's tables untouched, swept later |
| A daemon upgrade | Kept; `format` says which reader | Kept |

### Retention: GC's eighth step

Records are the highest-volume authoritative data Reef keeps: one per watcher snapshot that commits, about 1.3 KiB each with its index. A busy workspace commits a snapshot every few seconds while its agent writes. GC gains an eighth step, **provenance**, after evidence and artifacts and before the reindex. It runs under the create lock `run_repo` holds, reads the head after step 1, honours `dry_run`, and never touches a record recorded at or after `keep_newer`.

1. **Compact.** Among records recorded before `min(now − [provenance] compact_after, keep_newer)`, group by session, change and context digest, in sequence order, as maximal runs of consecutive records with the same digest. Keep the first and the last of each run. Also keep any record whose commit is visible in the head's view (the change's current commit, when a snapshot wrote it). Delete the rest. What survives says, for every change, which sessions worked on it, under which contexts and instructions, with the first and last commit each produced. The watcher snapshots in between, which only tracked an agent's typing, go.
2. **Expire.** For each distinct change id among the remaining records recorded before `min(now − [provenance] retention, keep_newer)`, resolve the change in the head's view (`resolve_change_id`, an index lookup, not a revset walk). Records of a change with no visible commit (abandoned work, or work undone away) are deleted. Records of visible changes, landed or open, are kept for good once compacted. Landed history is what "auditable after the fact" means. R3.13's landing pins the changes a landing consumed, so a projection that hides them (R3.16) does not expire their provenance ("What later tickets inherit").
3. **Sessions.** `provenance_sessions` rows that ended before `keep_newer` and have no record left are deleted.
4. **Keys.** `identity::retention::pinned()` becomes `"k.key_id IN (SELECT key_id FROM evidence) OR k.key_id IN (SELECT key_id FROM provenance)"`. R3.03's sweep then removes held keys that no remaining record names, once their window has ended and the floor has passed. `provenance_by_key` serves that subquery.

Deletion runs 1,000 records per transaction. `GcReport` gains `uint32 provenance_compacted = 22`, `uint32 provenance_removed = 23` and `string provenance_error = 24`. A failure is logged and the run goes on, but it is reported as an error for a requested run (`reef ws gc` exits 8), as R3.02's step is, because these are authoritative data. `reef ws gc`'s text line gains `provenance <n> compacted, <n> removed`.

### Storage: migration `0010_provenance.sql`, schema 10

```sql
-- R3.04: provenance records (signed in-toto statements about the commits the daemon records for a
-- workspace, in DSSE envelopes) and each workspace's provenance session with its declared context.
-- `envelope` is the canonical envelope; `id` is its sha256. Every other provenance column is read
-- from the payload at insert, an index over it. No instruction text and no private key is stored.
-- Released migrations are never edited.
CREATE TABLE provenance(repo_id TEXT NOT NULL, id TEXT NOT NULL,
             envelope BLOB NOT NULL, format INTEGER NOT NULL,        -- 1: urn:reef-vcs:provenance:v1
             commit_id TEXT NOT NULL, change_id TEXT NOT NULL, tree_id TEXT,
             workspace_id TEXT NOT NULL, session_id TEXT NOT NULL, sequence INTEGER NOT NULL,
             kind TEXT NOT NULL, key_id TEXT NOT NULL REFERENCES evidence_keys(id),
             agent TEXT, model TEXT, harness TEXT, task TEXT, instruction_sha256 TEXT,
             client_session TEXT, context_digest TEXT NOT NULL,   -- sha256 of the canonical context
             recorded_at INTEGER NOT NULL,
             PRIMARY KEY (repo_id, id)) WITHOUT ROWID;
CREATE UNIQUE INDEX provenance_by_commit ON provenance(repo_id, commit_id);
CREATE INDEX provenance_by_change ON provenance(repo_id, change_id, recorded_at);
CREATE INDEX provenance_by_session ON provenance(session_id, sequence);
CREATE INDEX provenance_by_recorded ON provenance(repo_id, recorded_at DESC, id);
CREATE INDEX provenance_by_key ON provenance(key_id);
CREATE TABLE provenance_sessions(session_id TEXT PRIMARY KEY,          -- ses_<16 hex>; in `sessions` once certified
             repo_id TEXT NOT NULL, workspace_id TEXT NOT NULL,
             identity_id TEXT, actor TEXT NOT NULL, agent TEXT,
             channel TEXT NOT NULL,                                -- 'socket', or the creating token's id
             model TEXT, harness TEXT, task TEXT, instruction_sha256 TEXT, client_session TEXT,
             declared_at INTEGER, declared_by_agent TEXT,
             next_sequence INTEGER NOT NULL DEFAULT 1, missing_records INTEGER NOT NULL DEFAULT 0,
             problem TEXT,                                         -- why records are unbound, if they are
             started_at INTEGER NOT NULL, ended_at INTEGER);
CREATE UNIQUE INDEX provenance_sessions_live ON provenance_sessions(workspace_id) WHERE ended_at IS NULL;
CREATE INDEX provenance_sessions_by_repo ON provenance_sessions(repo_id, started_at);
```

- **Keyed by repository** (ADR 0003). `provenance_sessions.session_id` has no foreign key to `sessions`, because an uncertified session never gets a `sessions` row.
- **`context_digest`** is the SHA-256 of the canonical JSON of the predicate's `context` object, without `declaredOn`. It exists for compaction's grouping, and a read checks it like any other column.
- **Times** are unix milliseconds. `recorded_at` equals the payload's `recordedOn`: both come from one clock read.
- **Backups** copy both tables with the database. ADR 0020's layout is unchanged.

### The API: `ProvenanceService`, API revision 18

A new file, `reef/api/v1/provenance.proto`:

```proto
// Provenance (R3.04, ADR 0058): one signed record per commit the daemon records for a workspace,
// saying which session recorded it and what context a client declared for that session. The
// daemon signs with a key it holds for the workspace's session, certified by its authority
// (R3.03). Model, harness, task and instruction hash are declared, never verified; whom to trust
// is policy's (R3.07).
service ProvenanceService {
  rpc DeclareProvenance(DeclareProvenanceRequest) returns (DeclareProvenanceResponse) { option (reef.api.v1.access) = ACCESS_WRITE; }
  rpc GetProvenance(GetProvenanceRequest) returns (GetProvenanceResponse) { option (reef.api.v1.access) = ACCESS_READ; option idempotency_level = NO_SIDE_EFFECTS; }
  rpc ListProvenance(ListProvenanceRequest) returns (ListProvenanceResponse) { option (reef.api.v1.access) = ACCESS_READ; option idempotency_level = NO_SIDE_EFFECTS; }
}

// What a client declares. Set fields replace, an empty string clears, unset keeps.
message ProvenanceDeclaration {
  optional string model = 1; optional string harness = 2; optional string task = 3;
  optional string instruction_sha256 = 4;   // 64 lowercase hex; the text is never sent
  optional string client_session = 5;
  string identity = 6;                      // CreateWorkspace only: a person identity's name or id; empty: by the rules
  SessionActor actor = 7;                   // CreateWorkspace only; unspecified: agent
}
message ProvenanceContext {
  string model = 1; string harness = 2; string task = 3; string instruction_sha256 = 4;
  string client_session = 5; google.protobuf.Timestamp declared_at = 6;
}
// A workspace's provenance session, on `Workspace.provenance`.
message ProvenanceSession {
  string session_id = 1; string identity = 2; IdentityKind identity_kind = 3; SessionActor actor = 4;
  string agent = 5; ProvenanceContext context = 6; google.protobuf.Timestamp started_at = 7;
  google.protobuf.Timestamp ended_at = 8; uint64 records = 9; uint64 missing_records = 10;
  string problem = 11;   // empty, or no_default_identity, token_not_linked, token_revoked, identity_revoked
}
message ProvenanceRecord {
  string id = 1; string commit_id = 2; string change_id = 3; string tree_id = 4; string workspace_id = 5;
  string session_id = 6; uint64 sequence = 7; string kind = 8; string agent = 9;
  google.protobuf.Timestamp recorded_at = 10; ProvenanceContext context = 11; string key_id = 12;
  SignatureCheck signature = 13;            // R3.01's
  KeyIdentity identity = 14;                // R3.03's, at recorded_at
  bytes envelope = 15;                      // GetProvenance only
}

message DeclareProvenanceRequest { string repo = 1; string workspace = 2; ProvenanceDeclaration declaration = 3; bool no_snapshot = 4; }
message DeclareProvenanceResponse { ProvenanceSession session = 1; Operation operation = 2; }   // the snapshot's; unset when nothing changed
message GetProvenanceRequest {
  string repo = 1; string workspace = 2;    // the workspace `@` refers to
  oneof target { string revision = 3; string commit_id = 4; string id = 5; }   // id: full, or a unique prefix of 8+
}
message GetProvenanceResponse { ProvenanceRecord record = 1; }
message ListProvenanceRequest {
  string repo = 1;
  repeated string change_ids = 2;           // at most 100; hex, as Change.change_id
  string workspace_id = 3; string session_id = 4;
  google.protobuf.Timestamp since = 5;      // recorded at or after
  int32 page_size = 6; string page_token = 7;
}
message ListProvenanceResponse { repeated ProvenanceRecord records = 1; string next_page_token = 2; }
```

Each element gets the full leading comment ADR 0029's checklist requires. The sketch abbreviates. The rules:

- **`CreateWorkspaceRequest.provenance = 10`** and **`Workspace.provenance = 22`**, filled by `GetWorkspace`, `ListWorkspaces` (one join per page) and `CreateWorkspace`. Unset when `[provenance] enabled` is false. `DeclareProvenance` refuses a workspace that is not `active`, with the reasons `SnapshotWorkspace` already uses.
- **`GetProvenance` with a `revision`** resolves it through the reading layer (`Target`, `snapshot_first`, so `@` includes what is on disk), and returns that commit's record. A commit with none is `PROVENANCE_NOT_FOUND`, metadata `commit_id` and `change_id`. Its hint says the commit was written by something other than a workspace (a describe, a rebase, the jj CLI) and that `reef provenance list --change <id>` lists its change's records. `commit_id` takes a full id, which may be hidden. `id` takes a record id.
- **`ListProvenance`** returns records newest first (`recorded_at`, then `id`). `int32 page_size` works as in R3.03: 0 means 100, capped at 1,000, and a negative value is `INVALID_ARGUMENT`. More than 100 `change_ids` is `INVALID_PROVENANCE` (`field` `change_ids`). The filters combine with AND.
- **Remote**: `remote/rules.rs` gains `DeclareProvenance` with `Rule::OwnWorkspace`. `CreateWorkspace`'s rule is unchanged, and its handler applies the identity table above. The READ methods are served to `read` tokens and web sessions by their classification.
- **No exception to ADR 0029 decision 12**: `DeclareProvenanceResponse` has `operation`, the snapshot's.
- `API_REVISION` becomes 18 with its digest. `SERVED` gains `reef.api.v1.ProvenanceService` (19 entries).

**Reasons** (new constants in `reef_api::error`, each documented on its RPCs and mapped in `error.rs`):

| Reason | Kind | Metadata | RPCs |
| --- | --- | --- | --- |
| `INVALID_PROVENANCE` | `INVALID_ARGUMENT` | `field` (`model`, `harness`, `task`, `instruction_sha256`, `client_session`, `identity`, `actor`, `change_ids`) | `CreateWorkspace`, `DeclareProvenance`, `ListProvenance` |
| `PROVENANCE_NOT_FOUND` | `NOT_FOUND` | `commit_id` and `change_id`, or `id` | `GetProvenance` |
| `AMBIGUOUS_PROVENANCE_ID` | `INVALID_ARGUMENT` | `id`, `ids` (up to 10) | `GetProvenance` |
| `PROVENANCE_DISABLED` | `FAILED_PRECONDITION` | none | `DeclareProvenance`; `CreateWorkspace` with a non-empty declaration |

`CreateWorkspace` also documents R3.03's `IDENTITY_NOT_FOUND`, `IDENTITY_REVOKED` and `SESSION_KEY_REFUSED` for an explicit identity or actor. `identity`, or `actor` on `DeclareProvenance`, is `INVALID_PROVENANCE` (`field` `identity` or `actor`): they are fixed for the session.

| Key | Default | Range | Meaning |
| --- | --- | --- | --- |
| `enabled` | `true` | | Record provenance for every Reef workspace. `false` records nothing, issues no held key, and refuses declarations; existing records stay readable |

### Documentation

- **`docs/adr/0058-provenance-records.md`** (accepted), indexed in `docs/adr/README.md`.
  - **Decisions**:
    1. one record per commit the daemon records for a workspace (snapshots that commit, and `EditFiles` naming it), nothing written into the commit;
    2. a third predicate type in ADR 0055's envelope, subject `gitCommit`, with the fields above, and the observed, certified and declared split;
    3. one provenance session per workspace, signed by a daemon-held key certified with `custody: daemon` for `max_lifetime`, renewed in the session after a restart, with uncertified held keys where no identity can be bound;
    4. declarations at creation and through `DeclareProvenance`, which snapshots first, with the identity and actor fixed per session;
    5. the instruction as a SHA-256 of its exact bytes, whose text Reef never receives;
    6. verification at every read, with `KeyIdentity` at `recorded_at` and the custody and session checks;
    7. recording never fails a snapshot;
    8. compaction and retention in GC's eighth step, with held keys pinned by records.
  - **Alternatives**:
    - the tree as subject (merges two sessions' identical trees);
    - the change as subject (not content-addressed, and it says nothing about which commit);
    - one record per session, or per context, listing its commits as several subjects (a crash loses the unsigned tail, and a reader of one commit needs a list it cannot check alone);
    - client-held keys signing provenance (the watcher's snapshots happen with no client present);
    - one daemon key for all workspaces (no session to revoke or to join on);
    - operation attributes as provenance (unsigned, and rewritten by GC);
    - a trailer in the commit (rewrites commits, and leaks into git);
    - storing the instruction text (the design's non-goal);
    - a salted instruction hash (question 4);
    - backfilling missing records (a signature that claims a later time);

## Implementation notes

- **Order**:
  1. `reef-evidence`'s `provenance` module, tests 1 to 3. This is the format R4.07 publishes, and questions 2 to 4 fix its shape.
  2. The migration, `db/provenance.rs`, test 4.
  3. `issue_held` and the session state, then `record` at the two call sites (tests 5, 6, 9, 14).
  4. The service and declarations (7, 8, 12).
  5. Revocation and tampering (10, 11).
  6. GC and config (13, 15).
  7. The client and the CLI (16), then schema, MCP, help and SDKs (17), then the documents.
- **The session mutex** is per workspace session, not global. Recording holds it for renewal, signing and the insert, which take well under a millisecond, except for a renewal's certification (about 100 µs). Snapshots of different workspaces never wait on each other for provenance. The authority's `RwLock` from R3.03 is taken only by renewal.
- **Signing is on the snapshot's blocking half** that already runs `record_commit`, never on a tokio worker or the repository thread (ADR 0012). The insert is one statement batch in its own `IMMEDIATE` transaction after the index row's, not inside it: a failed record must not roll back the index row.
- **Compaction in SQL.** A window function over `provenance_by_session` (`LAG` and `LEAD` of `context_digest` partitioned by `session_id, change_id`, ordered by `sequence`) marks the first and last of each run. The visible-commit pin uses the `LiveSet` machinery's temporary-table join (R3.02), filled with the commit ids of the changes' visible commits.
- **Instruction hashing in the CLI** streams the file through `sha2` (already in the lockfile), so a large file is never held in memory, and the bytes are never logged.
- **Linux**: no `cfg(target_os)`. Build and lint in the privileged `ubuntu:24.04` container anyway, since the snapshot pipeline, GC and `server.rs` change and the Linux-only daemon tests construct `TestDaemon`.

## Risks

- **Provenance on one uid is weaker than its fields suggest.** A reader who takes a record's `model` or `instruction` as fact, or takes "recorded in workspace W" for "written by the agent of W", is wrong whenever another same-uid process can reach the socket or the workspace directory (S-67, S-68). Mitigations:
  - the observed, certified and declared split, in the API comments, the CLI text and `docs/provenance.md`;
  - remote callers bound to their token's identity;
  - R3.07's docs.
- **Snapshots are hot.** A record is a signature and an insert on every committing snapshot. Mitigations: the gate on overhead and on the load test; per-session mutexes; never failing the snapshot. A regression in the load test blocks the merge.
- **Volume.** Without compaction, a fleet of 200 busy workspaces could write hundreds of megabytes a day. Mitigations: compaction after 7 days, which test 13 measures on a watcher-heavy fixture, and the GC bench. A `[provenance] enabled = false` escape hatch exists.
- **Compaction loses detail.** After 7 days, the record of a mid-run watcher snapshot is gone, so "which commit within an instruction's run introduced this line" can no longer be answered by an exact record. R3.37 answers at the run's level. `compact_after = "0s"` keeps everything.
- **Deleting authoritative data.** Retention expires records of changes that are no longer visible. A wrong visibility check would delete records of live work. Mitigations: the floor at `keep_newer`, the per-change lookup in the head's view, the dry run, and test 13.
- **Hash disclosure.** Instruction hashes of short prompts are guessable (S-70). Question 4.

## Choices this brief made, and why

- **A record per recorded commit**, because the design's snapshot is a commit, and a per-commit record can be checked alone.
- **The commit as subject and the change in the predicate**, because provenance is about an act, and readers find it across rewrites by change.
- **A daemon-held key per workspace session**, because the watcher records commits with no client present, and R3.03 reserved exactly this custody for it.
- **Uncertified held keys rather than no record**, because `UNBOUND` is an honest status that R3.03 already defines.
- **Declarations that snapshot first**, because edits on disk belong to the instruction they were made under.
- **Hash only, computed by the client**, because Reef never holds the prompt.
- **Never failing a snapshot**, because losing an attestation is recoverable and losing work is not.
- **Compaction plus visibility-based retention**, because the volume is per snapshot, and the audit value is per change and context.
- **Harness integration as its own row**, because it touches the harness packages, the MCP server, both SDKs and the agent guide, and the core is already M at its top end.

## Departures found while implementing

- **`recordedOn` is when the daemon signed the record, not the operation's end.** A key issued for the very record it signs has a window that starts after the snapshot's operation ended, so a record stamped with the operation's end read `EXPIRED`. The record now carries the later of the two, which is the signing time in practice, and its identity is judged at it. The operation's end is still jj's to read.
- **The agent label is the first valid one.** A remote client's `reef-agent` (or a workspace's owner) is not always a label R3.03's certificate can carry (visible ASCII and spaces, 1 to 256 bytes); a session takes the request's `reef-agent` if it is one, else the owner if it is one, else none, so a label never makes issuance fail.
- **The CLI takes `--workspace`, not `-w`.** `reef provenance show`, `list` and `declare` take the scope flags every VCS command takes (`--workspace`, `--repo`, ADR 0034), and default to the workspace you are in or `REEF_WORKSPACE`. `list --mine` is the workspace filter, since `--workspace` names the scope.
- **The provenance flags of `ws create` and `ws run` are hidden from their `--help`.** `ws run --help` was within 130 bytes of its 2,176-byte budget (ADR 0051), and `--help-all` lists only the global options. Both commands' after-help names the five flags, and `reef provenance declare --help` describes the context ones. `--identity`, `--actor` and `--instruction-file` with `ws run --workspace` are a usage error: an existing workspace's session is fixed, and its context is `provenance declare`'s.
- **`declare` clears with an empty value.** `--task ""` clears the task, as the API's empty string does; on `ws create` and `ws run`, an empty value (such as an empty `REEF_MODEL`) declares nothing.
- **The brief view nests `context`.** ADR 0045's subset rule (`brief_views_are_subsets`) keeps a view's keys the full type's, so `brief.ProvenanceRecord` keeps `context` (when anything is declared) rather than lifting its fields.
- **`show --envelope` prints the envelope and statement as JSON fields**, as `evidence show -o json` does, rather than the canonical bytes; `latest_of` names the change when the commit had no record of its own.
- **`GetProvenance` with no target is `@`.**
- **A test that counts `evidence_keys` turns provenance off** (`evidence::survives_gc_backup_and_forget`): the table now also holds the held keys that sign provenance.

- **Review F1: an edit records only the workspace's own work.** `EditFiles` names a workspace for attribution, but may write any change, and its remote rule is `Rule::None`, so any token could have had a record signed in another token's session, bound to that token's identity. An edit now records only when it wrote the workspace's own change, and, through the remote listener, came from the token that created the workspace.
- **Review F2: a creation race rebinds.** A record that lands between a workspace's creation and its session's start starts a session by the rules with nothing named. `begin` now replaces a live session whose identity, actor or channel differs from the creation's plan (ended, its records kept, a new session with the plan's binding), instead of only declaring onto it.
- **Review F3: an ended workspace gets no session.** `DeclareProvenance` refuses a workspace that is not active whether or not it snapshots, and a record or declaration that raced a release finds no live session and starts none (the workspace's row must be active or releasing). The reclaim of a workspace whose directory is gone ends its session too.
- **Review F4: the environment never fails a command.** `REEF_MODEL` and `REEF_TASK` default only `ws create` and `ws run`, a value the daemon would refuse is ignored, and a declaration made only of them is dropped when the daemon records no provenance. `provenance declare` reads only its flags, so an inherited value never reverts a later declaration. A socket creation naming nothing whose default identity was revoked records unbound (`identity_revoked`) rather than failing.
- **Review F6: a revocation drops only the held keys it covers**: the key, the session's, the identity's, or the authority's. Dropping every key made every live workspace issue a new key per revocation, against the identity's key limit. A revocation written behind the daemon takes effect at the next renewal, as above; no per-record database check was added.
- **Review F8, left as is: two orderings are approximate.** A declaration snapshots and then swaps the context under the workspace's provenance lock, not the scan lock, so an edit written in the milliseconds between them records under the new context. An `EditFiles` record is signed after the write returns, so a carried follow-up snapshot that records first gets the lower `sequence`. Both are the order the daemon signed in, which is what `sequence` means.
- **Review F9: counting.** GC's dry run counts a record both rules take once, as a real run does; a commit whose snapshot index row failed is still recorded; a database error while choosing a lazy session's identity is reported as such, not as `identity_revoked`.

## Decisions for the user

1. **Split harness integration into R3.44 (S).** It covers prompt hooks, `reef mcp`, the SDK blocks, env-signal facts and the agent guide. *Recommended*: yes. Keeping it here makes R3.04 L.
2. **Granularity.** One record per recorded commit, compacted after 7 days. The alternative is one record per session context listing its commits as several subjects, which is cheaper on hot paths but loses the unsigned tail on a crash and cannot be checked per commit. *Recommended*: per commit, with the overhead gate.
3. **Subject.** `gitCommit`, with change and tree in the predicate. The alternatives are the tree (as evidence), or the change. *Recommended*: the commit.
4. **Instruction hash.** A plain SHA-256 of the exact bytes, with the text never sent. The alternatives are a salted hash per record (resists guessing, but kills "which commits did this instruction produce"), or optionally storing the text. *Recommended*: plain SHA-256, never stored.
5. **On by default** for every Reef workspace, with `[provenance] enabled = false` to turn it off. *Recommended*: on.
6. **Retention defaults.** `compact_after = "7d"`, and `retention = "90d"` for records of changes no longer visible. Records of visible changes are kept for good once compacted. *Recommended*: as stated.
7. **Held key lifetime: `[session_keys] max_lifetime` (24 hours)** rather than `lifetime` (1 hour), so there is about one `session_keys` row per workspace session per day. *Recommended*: 24 hours.
8. **Unbindable workspaces still record**, with an uncertified held key (`UNBOUND`, with the problem shown), rather than recording nothing. This covers an unlinked token, no default identity, or a revoked identity. *Recommended*: record.
9. **A revoked session restarts automatically.** The workspace's next record starts a new session, logged, rather than recording unsigned or stopping. *Recommended*: a new session.
10. **`DeclareProvenance` snapshots first** by default, with `no_snapshot` to skip. *Recommended*: yes.
11. **A top-level `reef provenance`**, with `restore` leaving the root help's "Also:" line. *Recommended*: yes.
12. **No MCP tools, and a new ADR 0058.** *Recommended*: yes.
