# R3.24 Independent test authorship rules

Phase 3 · Size S, at its top end, with the scope lines below · Depends on: R3.07 (`reef-policy.toml`, the declared tables evaluated in Rust, `[[signoff]]`, the static check and the cost bound), R3.10 (`land::stack`, the gate's and a batch's stack groups, sign-offs from the changes above), and builds on R3.04 and R3.44 (provenance records: workspace session, declared client session, agent label), R3.13 and R3.14 (the gate, batch formation), R3.45 (`EvaluatePolicy` over a stack, the automatic status), R3.43 (sign-offs from a person, `presence`) · Unblocks: none listed; R3.23 may reuse the `tests` globs, and R3.30 may read the `stack` input (see "Parallel tickets")

## Context

The design names the problem in "What evidence proves": "an agent that writes both the code and its tests produces circular evidence. … for designated paths, policy can require tests to come from a different change than the code, or require human sign-off on test changes even when code changes need none."

R3.07 left this ticket two things. Its brief says "stack and test-authorship inputs (R3.24)" are out of its scope, and `docs/policy.md:214` lists `stack` under "What later tickets add". R3.10 then decided that a stack's dependency edges are jj's parent edges, never stored ("a stack is a change and its ancestors not yet on the destination, at most 32"), and handed over: "The `stack` policy input is R3.24's … `{size, position, changes}` and what its rules need."

Nothing in the policy input today says who wrote a change other than the one judged, or which other changes land with it. `reef_policy::Input` (`reef-policy/src/input.rs:24`) has `change`, `evidence`, `provenance`, `landing` and `batch`, and no `stack`.

So this ticket builds:

1. **The `stack` input**: every change of the stack being judged, bottom first, with its touched paths and who wrote it (from its provenance records), built by the daemon once per stack and given to every member's evaluation. A CEL variable, `stack`, like `batch`.
2. **`[[independent_tests]]`**: a declared table in `reef-policy.toml`, evaluated in Rust like `[[signoff]]`. For its `code` and `tests` paths, a change is blocked when code and tests in its stack were written by one author, unless a person signs off.
3. **The surface**: one rule kind in the API (`POLICY_RULE_KIND_INDEPENDENT_TESTS`), its mapping in the daemon and the CLI, and the documents.

"Test changes need human sign-off" needs nothing new: `[[signoff]]` with `paths` set to the test globs does it today (R3.07). This ticket documents it as a recipe and does not add a second way (decision 5).

### The rule

For one `[[independent_tests]]` entry and one change judged in its stack:

- A path is a **test path** when `tests` covers it, and a **code path** when `code` covers it and `tests` does not. `except` removes paths from both. Globs are R3.07's (ASCII case-insensitive, `**` crosses `/`). A rename touches its old and new path, as everywhere in policy.
- The rule is **not applicable** when the judged change touches no code path and no test path, or when its `when` is false.
- A **conflict** is a pair (code, tests) written by one author in the stack being judged, where one side is the judged change:
  - the judged change touches both code and test paths (one change is never independent of itself, decision 6), or
  - the judged change touches code paths and another member touches test paths, or the other way round, and the two **share an author** (decision 1).
- **Satisfied** with no conflict. With conflicts: **unsatisfied**, unless the entry allows a sign-off (`signoff = true`, the default) and enough person sign-offs are on the judged tree (or on a member above it, R3.10), in which case **satisfied**, with the sign-off evidence in `evidence_ids` (decision 5).
- Both members of a conflict are blocked, whichever is lower (decision 4). At the gate the lower one ends the prefix; the members above it are returned `UNLANDED_PARENTS`, as R3.10 already does.

A member of the stack with more than `MAX_STACK_PATHS` (10,000) touched paths, whose paths the input therefore cuts, is treated as touching both code and test paths, so it conflicts whenever it shares an author. The judged change is judged on `change.paths` (up to 100,000), never on its cut copy.

### Authors (decision 1)

Two changes **share an author** when either has no provenance record (Reef did not see who wrote it, so it cannot be called independent), or when their records have in common:

| `by` | what is compared |
| --- | --- |
| `"workspace"` | a workspace provenance session (`provenance[].session`) |
| `"session"` (default) | a workspace session, or a declared client session (`provenance[].client_session`, non-empty) |
| `"agent"` | a workspace session, a declared client session, or an agent label (`provenance[].agent`, non-empty) |

Each level includes the one above it, so a stricter `by` never lets more through. Every record of the change counts, signature valid or not: more authors only make a conflict likelier, so a bad record cannot buy independence.

Why `session` is the default: a workspace session alone lets one agent pass by writing its tests in a second workspace, and the reference harness hooks declare the same client session for every workspace a harness session creates (R3.44), which closes that. An agent label alone blocks every local fleet that keeps the default `<user>@<host>` label. The cost of `session`: the subagents of one orchestrating harness session share its client session (verified above), so a "tests" subagent and a "code" subagent of one session are one author. A repository that runs that pattern on purpose writes `by = "workspace"`.

### Designating paths (decision 2)

Each entry names its own `code` and `tests` globs. A repository with several areas writes several entries. A path in both lists is a test path, so `code = ["crates/**"]` with `tests = ["crates/*/tests/**"]` reads naturally. Tests written inside code files (Rust's `#[cfg(test)]` modules) are code to this rule; `docs/policy.md` says so (S-303).

### A table and an input (decision 3)

Both. The table is evaluated in Rust because its result carries data (the paths at issue, the conflicting changes in the message, the sign-off need that R3.45's status, R3.31's Accept and R3.16's `Reviewed-by` read), and because the same rule in CEL is a comprehension over pairs of members and their paths that the cost bound would refuse on a large stack (32 × 32 members × 10,000 paths is past `MAX_EXPRESSION_COST`, 1e7). The `stack` variable is also given to CEL, as R3.10 promised, so a repository can write other rules over it (a recipe below).

### How far it looks (decision 4)

The stack being judged, below and above the judged change: at the gate and in `EvaluatePolicy --stack`, the stack from the destination to the head named (`judge_slots`' slots); in a batch, the change's stack group. Above matters for two reasons. Under `[landing] checks = "batch"` (the default) the batch's tested tree, which holds the members above, supplies the `[[require]]` evidence of every member at or below it (R3.14), so tests above a change can be the evidence that lands it. And R3.10's sign-offs reach down. So a code change and its author's tests block each other in either order.

`EvaluatePolicy` without `stack`, and simulation, judge one change alone (their `Input` sites keep an empty `stack`, which the evaluator reads as a stack of one). Only the single-change conflict shows there; `docs/policy.md` says to use `reef policy eval --stack`.

What it does not see: changes already on the destination. Tests landed first by the same author, then the code, are two stacks (S-303). Reading the destination's recent landings' authors is the alternative, and a follow-up.

### Sign-offs (decision 5)

- `signoff = true` (the default): when a conflict is found, a person's sign-off satisfies the rule. Who may sign is the entry's `groups`, `identities`, `count`, `presence` and `kinds`, as `[[signoff]]` reads them; with neither `groups` nor `identities`, any person (`Members { anyone: true }`, as `builtin:resolution`). A person signs off their own agents' work, as R3.07 allows.
- `signoff = false`: independence is required. `groups`, `identities`, `count`, `presence` or `kinds` with `signoff = false` is a load error ("has no sign-off to configure").
- "Test changes need a person's sign-off, even when code changes need none" is `[[signoff]]` with `paths` set to the test globs, documented as a recipe with a `when` that limits it to modified and deleted tests. No new key.

### One change that touches both (decision 6)

Never independent of itself: it conflicts, and a sign-off (when allowed) is the way through. Splitting the tests into a change by another author is the other. A change written by a person is held to the same rule; the person signs off their own change.

### The `stack` input

In `reef-policy/src/input.rs`:

```rust
/// The stack the change lands in (R3.10, R3.24): its changes, bottom
/// first, the judged one among them. The daemon fills `changes`; the
/// evaluator sets `size`, `position` and each change's `position`, and
/// replaces the judged change's entry with one built from `change` and
/// `provenance`. Empty `changes` reads as a stack of one, the change.
#[derive(Clone, Debug, Default, PartialEq, Serialize, Deserialize, JsonSchema)]
#[serde(default, deny_unknown_fields)]
#[schemars(rename = "policy.Stack")]
pub struct Stack {
    /// How many changes: 1 for a change on the destination.
    pub size: i64,
    /// The judged change's place, from 1 at the bottom.
    pub position: i64,
    /// Each change, bottom first.
    pub changes: Vec<StackChange>,
}

/// One change of the stack, and who wrote it.
#[derive(Clone, Debug, Default, PartialEq, Serialize, Deserialize, JsonSchema)]
#[serde(default, deny_unknown_fields)]
#[schemars(rename = "policy.StackChange")]
pub struct StackChange {
    pub id: String,
    pub commit: String,
    pub tree: String,
    /// Its place, from 1 at the bottom.
    pub position: i64,
    /// Whether its tree has a conflict.
    pub conflicted: bool,
    /// Its touched paths, sorted, at most [`crate::MAX_STACK_PATHS`].
    pub paths: Vec<String>,
    /// How many there are; more than `paths` holds when it was cut.
    pub paths_total: i64,
    /// Its provenance records read; 0: Reef did not record who wrote it.
    pub records: i64,
    /// The distinct workspace sessions, client sessions, agent labels,
    /// models and key actors of those records, each sorted, empty values
    /// left out.
    pub sessions: Vec<String>,
    pub client_sessions: Vec<String>,
    pub agents: Vec<String>,
    pub models: Vec<String>,
    pub actors: Vec<String>,
}
```

Each field gets a doc comment (`missing_docs` is on); the ones above without one need it.

- `impl StackChange { pub fn of(change: &Change, provenance: &[Provenance]) -> StackChange }`: the one function that builds an entry, used by the evaluator for the judged change and by the daemon for the others. `position` is left 0.
- `pub const MAX_STACK: usize = 32;` and `pub const MAX_STACK_PATHS: usize = 10_000;` in `reef-policy/src/lib.rs`, beside `MAX_PATHS`. `MAX_STACK` equals `reef_lib::jj::land::MAX_STACK` (`reef-lib/src/jj/land.rs:39`), which `reef-policy` cannot import (no jj-lib, `reef-policy/Cargo.toml`); a daemon unit test asserts they are equal.
- `Input.stack: Stack`, documented: "The stack the change lands in (R3.24). Empty outside a stack judgment: `EvaluatePolicy` without `stack` and simulation."
- **Normalized in `Policy::prepare`**, after the `MAX_PATHS` check and before the CEL variables are bound: build `StackChange::of(&input.change, &input.provenance)`; if `stack.changes` is empty, the stack is that one change; else replace the entry whose `id` equals `change.id` (none: an input problem, "the stack does not contain the change judged", which makes `builtin:input` an error); more than `MAX_STACK` changes is an input problem too, and the list is cut. Then set each change's `position` (index + 1), sort, dedup and cut each `paths` to `MAX_STACK_PATHS` with `paths_total` at least the length before the cut, and set `size` and `position`.
- **The CEL variable** `stack`, in `Scope::Change` only, bound and sized like `batch`. `format.rs:1047` (`reads_destination`) stays as it is: R3.45's key already covers the members.

### The table

```toml

name = "core-tests"                        # unique across [[require]], [[forbid]], [[signoff]], [[independent_tests]], [[rule]]
code = ["crates/**"]                       # required: the code paths
tests = ["crates/*/tests/**", "crates/*/benches/**"]   # required: the test paths; a path in both is a test path
```

### Evaluation

New file `reef-policy/src/authorship.rs`, pure functions with unit tests:

- `pub(crate) fn classify(rule: &IndependentTests, paths: &[String]) -> Touches { code: Vec<String>, tests: Vec<String> }`.
- `pub(crate) fn shared(a: &StackChange, b: &StackChange, by: Authorship) -> Option<Shared>`, where `Shared` is `Unrecorded(position)`, `Workspace(String)`, `ClientSession(String)` or `Agent(String)`, the first in that order, values compared in sorted order so the answer is deterministic.
- `pub(crate) fn conflicts(rule, change_paths: &[String], stack: &Stack) -> Vec<Conflict>`, where `Conflict` is `Itself` or `With { position, change, shared: Shared }`, in stack order.

In `eval.rs`, `fn independent_tests(&self, evaluator: &mut Evaluator, rule: &IndependentTests) -> RuleResult`, called from `evaluate_here`'s `match entry`:

1. Classify `change.paths`; neither kind touched: `NotApplicable`.
2. `when` (error: `Error` "when: …"; false: `NotApplicable`).
3. Charge `evaluator.charge(n)` with `n` the paths classified (the change's plus every other member's); an error is the rule's `Error` with its text (S-304).
4. `conflicts`; none: `Satisfied`, `with_paths` the change's code and test paths.
5. With conflicts and `signoff: None`: `Unsatisfied`. With a spec: `signed(self, evaluator, spec, RuleKind::IndependentTests, &paths)`; when unsatisfied, replace the message.
6. The message, unless the entry has one: `code and tests by one author: {items}; move the tests to a change by another author{tail}`. Items, at most 3, then `and {n} more`: `this change touches both`, or `change {12 hex} {below|above} it, which shares {workspace session X | client session X | agent X}` or `… which Reef has no provenance record of` (`this change has no provenance record` when the judged change is the unrecorded one). Tail with a sign-off spec: `, or get {count} sign-off{s} from {who} ({have} so far)`, `who` the groups and identities joined by `, ` or `a person`.

## Decisions for the user

Answered 2026-11-27: the user took the recommendation on all six. The rest of this brief already follows them.

1. **What "a different change" means.** *Recommended*: a different change with no author in common, an author being a workspace session or a declared client session (`by = "session"`), with `by = "workspace"` and `by = "agent"` on the table; a change with no provenance record is never independent. Alternatives: literally a different change (the row's wording; one agent passes by splitting its work); the workspace session only (verified by the daemon, but one agent with two workspaces passes); the agent label (blocks every fleet with default labels); the identity (every local agent shares the person's).
2. **How paths are designated.** *Recommended*: `code` and `tests` globs on each `[[independent_tests]]` entry, a path in both being a test. Alternatives: one global `[tests] paths` table that R3.23 also reads; test paths declared in `reef-checks.toml`; `tests` only, every other path being code.
3. **A table, an input, or both.** *Recommended*: both: the table evaluated in Rust (data for the status, the proposal view and `Reviewed-by`; bounded cost) and `stack` as a CEL variable. Alternatives: only the `stack` input with CEL recipes (smaller, but the pairs comprehension passes the cost bound on large stacks and gives no sign-off data); only the table (R3.10 promised the input).
4. **How far it looks.** *Recommended*: the whole stack being judged, below and above, and both members of a pair are blocked. Alternatives: only below (tests first), which lets a code change land on its author's tests through a batch's tested tree; also the destination's recent landings, which catches tests landed first (M: reads history and landed provenance).
5. **Sign-offs.** *Recommended*: a person's sign-off satisfies the rule by default (`signoff = false` makes independence mandatory), signers named as `[[signoff]]` names them or any person, sign-offs from above counting; "every test change needs a sign-off" stays a `[[signoff]]` recipe. Alternatives: a `mode = "independent" | "signoff"` key that duplicates `[[signoff]]`; only `[owners]` may sign.
6. **One change that touches both.** *Recommended*: never independent; a sign-off or a split is the way through, for people too. Alternatives: independent when its records split by path between sessions (per-snapshot attribution, M); exempt when every record's actor is `human`.
