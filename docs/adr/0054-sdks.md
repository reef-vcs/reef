# 0054. SDKs

- Status: accepted
- Date: 2026-11-02
- Ticket: R2.06

## Context

ADR 0004 promised Python and TypeScript SDKs generated from the same schemas, and ADR 0029 shaped the v1 schema for them. Before R2.06, a program in another language had two options. It could shell out to `reef` and parse its JSON. Or it could generate its own stubs and work out by itself the socket path, the `:authority` the daemon accepts, how errors are packed, how to pin a remote daemon's key and how to report presence. R2.06 (Python) settles these questions once, for R2.07 (TypeScript) as well.

## Decision

1. **Generated at build time, never committed.** Each SDK is built from `crates/reef-api/proto` by its language's stock generator (grpcio-tools with mypy-protobuf for Python), as the web UI's TypeScript is ([0047](0047-web-ui-transport-and-local-listener.md)). The wrapper's methods are generated too: one method per RPC, named in the language's case, on one client object. Every request field is a keyword (or a field of an options object), and a whole request message can be passed instead. A paged RPC also gets a `_pages` iterator, and an `_all` iterator where its items are known. A server-streaming RPC returns a stream that cancels when its scope ends. Docstrings are the schema's comments. A generated SDK cannot drift from the schema of its commit, so no freshness check is needed.
2. **Versions follow the workspace.** The package's version is `Cargo.toml`'s workspace version (in the language's normal form), read at build time, so a release bumps nothing for an SDK. The generated API revision is exported. A mismatched daemon is named by `reef-client`'s probe: a bare `UNIMPLEMENTED` (or `UNKNOWN_METHOD`, or `NOT_IMPLEMENTED` from a daemon of another version) leads to `GetDaemonStatus`, then 0.1's `Daemon/Status`, and an `IncompatibleError`. `require_revision(n)` guards a field added later, which a daemon would ignore.
3. **The socket and the remote as `reef-client` settles them.** Discovery follows `paths.rs` exactly, and remote selection follows the CLI's (`REEF_REMOTE`, `REEF_REMOTE_TOKEN`, `REEF_REMOTE_FINGERPRINT`, `<state>/remotes.toml`). The cases are in `sdk/fixtures/socket-paths.json` and `remote-urls.json`, which both the SDK's tests and `reef-client`'s (`paths_follow_the_shared_table`, `urls_follow_the_shared_table`) read. Over the socket, `:authority` is `localhost`: the daemon refuses gRPC's default, the percent-encoded socket path.
4. **No autostart, no daemon restart.** A library does not spawn a daemon it does not ship.
5. **Errors are one class per kind.** Each carries the daemon's `reason`, `hint`, `next` (an argv) and `metadata`. Failures the SDK finds itself (no daemon, a refused certificate, a misdirected host, a mismatched daemon, a request over 4 MiB) are subclasses with their own advice.
6. **A remote's key is pinned before the token is sent.** The SDK reads the leaf on a handshake of its own that sends nothing after it, hashes its SubjectPublicKeyInfo, and gives the gRPC library that certificate as its only trusted root. Without a pin, the same handshake verifies against the roots the library will trust. The library checks the certificate's names and a call's `:authority` against them even with a pin. So when the URL's host is not one of the names, the SDK names one that is: the pin, not the name, authenticates the daemon. After a renewal (same key, new certificate), the SDK pins the new certificate. It retries a READ call once on the new channel and raises a WRITE's failure rather than repeat it.
7. **The workspace block is `ws run`'s contract.** It creates a workspace (owner `<user>@<host>:<pid>`) or attaches to one under `ws run --workspace`'s rule. While the block runs, it renews the lease on the daemon's cadence and reports one `ACTIVITY` presence entry under R2.11's contract. At the end, it clears the entry and releases the workspace with a final snapshot. The presence and lease logic are state machines with no I/O, ported with `presence.rs`'s tests, and drive both the sync and the async clients.
8. **Published from `release.yml` by trusted publishing.** The SDK is built and smoke-tested against the run's daemon on every dry run. On a tag it is published over the registry's OIDC exchange after the GitHub release, and it warns rather than fails, as the tap and the MCP listing do.
9. **No harness is named** in an SDK's API, docstrings, README or guide. An agent is a name the caller passes (`agent=`, or `REEF_AGENT`).

## Consequences

- An RPC added to the schema reaches every SDK with no SDK work. A new paged RPC whose response has more than one repeated field must name its items: ADR 0029's checklist, item 12.
- A daemon change that breaks a non-tonic gRPC client fails the SDK's integration tests. R2.06 found one: the remote listener sent a service's error as headers and then an empty DATA frame. tonic accepted it; grpcio refused it as "Stream removed". The listener now sends trailers-only answers as gRPC requires (`service_errors_are_trailers_only`).
- The Python SDK sets `GRPC_ENABLE_FORK_SUPPORT=false` unless the program set it: grpc's fork handlers log at INFO on every `subprocess` call made while a channel is open. Child processes inherit the setting.

## Alternatives considered

- **Committed generated code with a freshness check.** Its diffs are unreadable (serialized descriptors), and the build already gives the same protection against drift.
- **betterproto or grpclib.** Beta, and no way to pin a key through them; ADR 0029 named `grpcio-status`.
- **Hand-written methods.** Forty-three of them, twice (sync and async), drifting from the schema at the first new RPC.
- **A client object per service.** Eleven more names for an agent to learn, when RPC names are unique across the package.
- **Per-call options as keywords.** `BuildStoreRequest.timeout` would clash, and any later field could; `with_options()` returns a client that shares the connection.
- **A TLS-terminating proxy thread for pinning.** More code, needed only if the gRPC library refused a non-CA leaf as its root, which grpcio 1.85 does not.
- **`cryptography` for the DER walk.** A large dependency for two fields of one certificate.
- **Autostart.** A library spawning a daemon it does not ship, and leaving a detached process behind a library call.
