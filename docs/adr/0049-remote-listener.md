# 0049. Remote listener

- Status: accepted
- Date: 2026-10-31
- Ticket: R2.08
- Amends: [0027](0027-trust-boundaries-in-phase-1.md), [0031](0031-writes-over-jj-state.md)

## Context

The [design](../design.md) says the daemon "exposes a typed protocol over a local socket with structured responses, and optionally over TLS with token authentication so a daemon on a remote machine can be reached by the same clients", and [0004](0004-grpc-over-unix-socket.md) recorded it. Until R2.08 nothing off the machine could reach a daemon: the Unix socket is the authorization ("one uid is one trust domain", [0027](0027-trust-boundaries-in-phase-1.md)), and R2.18's web listener ([0047](0047-web-ui-transport-and-local-listener.md)) is loopback only, gRPC-web only, READ only. The threat model lists five requirements a listener that is not the socket must meet before it serves an RPC, written by RX.01 for this ticket. Phase 2's exit criterion asks that "a daemon in a VM is reachable from another machine over TLS with a token, serving the same API and web UI".

tonic's own TLS does not fit: its acceptor offers ALPN `h2` only (gRPC-web over HTTP/1.1 is what a client without HTTP/2 falls back to), builds its server config once (no certificate reload), uses the process's default crypto provider, and its client verifies only against CA roots (no pinning).

## Decision

1. **One TLS port for native gRPC, gRPC-web and the assets.** The remote listener is a third tonic server over the same routes as the socket's and R2.18's, sharing `AppState`. `GrpcWebLayer` already sorts gRPC-web from native gRPC, and one port is one firewall rule and one certificate. Native gRPC is served off the socket only here.
2. **Off by default; on by `[remote] enabled` or `--remote`; bound at start, retrying.** `--remote` is on `reef-daemon`, and `reef daemon start|run --serve-remote` passes it (`reef daemon` takes subcommands, and `--remote <name>` is the CLI's own option for choosing a remote daemon). The listener binds as step 11 of the start sequence, after the socket serves; a failed bind or certificate leaves the socket serving, reports `FAILED` with the error, and retries with backoff from 1 s to 60 s. `[remote] listen` defaults to `0.0.0.0:7470` (decided by the user): the listener refuses everything without a token, and the quickstart recommends a private network until an external review (RX.02). The CLI's version restart passes `--remote` on when the old daemon reported it, so an upgrade does not close the listener.
3. **Reef terminates TLS with rustls on ring; there is no plaintext mode.** Not on any address, loopback included. ALPN offers `h2` and `http/1.1`; TLS 1.3 and 1.2 with rustls's default suites; no 0-RTT. Handshakes run off the accept loop, 64 at once at most, 10 s each. ring, not aws-lc-rs: a C compiler is all it needs on the four release targets, and nothing needs FIPS. A `crate_graph` test keeps aws-lc and OpenSSL out of every shipped crate's graph.
4. **A generated key pinned by its SPKI digest, or supplied files reloaded on change** (decided by the user). By default the daemon makes an ECDSA P-256 key once (`<state>/remote/key.pem`, `0600`, not backed up) and a self-signed certificate for `[remote] names` (default: the host name) and the bound IP, valid for 397 days, reissued for the same key with 30 days left or other names. Clients pin `sha256:` of the leaf's `SubjectPublicKeyInfo`, so renewal never breaks a pin. With `[remote] tls_cert` and `tls_key`, the pair is re-read during a handshake when either file changed, at most once a minute; a pair that does not load keeps the previous one serving. A client with a pin checks only the key (name, chain and validity add nothing to a pin) and still verifies the handshake signatures; without one it uses the OS's roots and the URL's host. Either way the daemon is verified before anything is sent, and a refusal names the fingerprint presented, so a person compares it with `reef remote show` on the daemon's machine.
5. **Named, scoped, expiring tokens, stored as digests.** `reef_<16 hex id>_<43 base64url secret>`; only `blake3(secret)` is stored, in `remote_tokens` (migration 0006): a 256-bit random secret needs no slow hash. Scopes are `read` (ACCESS_READ methods) and `write` (also ACCESS_WRITE); a new token is `read` and expires in 30 days unless asked otherwise (decided by the user). Rotation gives a new secret, the old one valid for an overlap of at most 7 days. Revocation takes effect at the next request and ends open streams within a second, whether or not their clients are reading; a rotation ends the streams opened with the old secret, which resume with whichever secret their client holds. Four ADMIN RPCs in `RemoteService` issue, list, rotate and revoke them, so only the socket can. A refused token is `PERMISSION_DENIED` with reason `REMOTE_TOKEN_INVALID` and `state` (`unknown`, or `expired`/`revoked` only to a caller holding the secret); there is no tenth error kind (decided by the user).
6. **ADMIN is never served remotely** (decided by the user). No store build, backup, quiesce, GC, registration, web session or token RPC; administration happens on the daemon's machine, over SSH if it is remote. This resolves S-10 (any client can `Quiesce`) for remote callers.
7. **A rules table covers every WRITE method.** The gate sees only encoded bytes, so handlers apply the rules: `CreateWorkspace` with a `path` is refused (the workspace goes under the daemon's root); `ReleaseWorkspace`, `MoveWorkspace` and `RenewLease` act only on workspaces the caller's token created (`workspaces.remote_token_id`); the other WRITE methods have no rule beyond the scope. A test fails when a WRITE method is missing from the table.
8. **The gate is R2.18's, for a non-loopback origin.** `Host` must be a name in `[remote] names` or an IP literal, any port (a port forward changes it); no upgrades or preflights, no CORS; assets public with R2.18's security headers; `Origin` must be `https://` and the request's own `Host`, `Sec-Fetch-Site` `same-origin`; binary gRPC-web or native gRPC only. Then the token, its scope, and its per-token limits (32 calls, 16 streams). The gate puts the caller in the request's extensions, which no client can set, and strips `authorization` and any `reef-remote*` header.
9. **The token is on every operation a remote call causes.** As `reef.remote-token` and `reef.remote-token-name`, typed as `Operation.remote`. The daemon carries the token along the paths that already carry the agent: a remote call's agent string is marked with it (`RemoteToken::mark`), and `OpMeta` splits it into the attributes; a `reef-agent` value is visible ASCII and a workspace owner may hold no control character, so neither can carry the mark. Snapshots a call takes first are marked too. A remote call's agent defaults to the token's name, not the workspace's owner. This amends [0031](0031-writes-over-jj-state.md), decision 2.
10. **Every remote write, refusal and token change is in the daemon's log**, under the target `reef_daemon::remote::audit`, with the token, the peer, the method and the outcome read from the trailers. Token refusals from one address are logged at most once per 10 s with a count. No line holds a secret. The threat model's requirement 5 is amended from "the operation log's description" to the operation's attributes and the daemon's log.
11. **Limits on the unauthenticated surface.** 256 connections, 32 per IPv4 address or IPv6 /64; an address with 10 token refusals within a minute is in backoff for a minute, doubling to an hour: its new connections are closed before TLS and its open connections' requests refused. A connection that makes no authenticated request within 30 s of its handshake is closed, so connections without a token cannot hold the slots. The backoff is for resources and log volume; no rate makes a 256-bit guess succeed.
12. **The CLI reaches a remote daemon through profiles.** `reef remote add <name> <url> --fingerprint … --token-file -` saves `<state>/remotes.toml` (`0600`) after checking the pin and the token; the token is never an argument. `reef --remote <name> …`, or `REEF_REMOTE` (a profile, or an `https://` URL with `REEF_REMOTE_TOKEN` and `REEF_REMOTE_FINGERPRINT`), points a command at it. The noun is `reef remote` (decided by the user); git-remote settings can live under `reef git` later. Commands that need this machine (`here`, `ws run`, `ui`, `init`, `mcp`, `daemon` other than `status`, `config`, `backup`, `restore`) or call ADMIN RPCs (`ws gc`, `store build`, `repo register|forget`, `remote token`) are refused with exit 9 before connecting; in remote mode a command needs `--workspace` or `--repo`, and paths are sent as given.

## Consequences

- A daemon in a VM is reachable from another machine with one flag and one token, through the CLI, the SDKs' gRPC, and a browser.
- The generated certificate shows a browser warning once per origin; a phone's browser needs a supplied certificate, which the quickstart says.
- A leaked `write` token can describe, abandon, undo and edit in every registered repository until it expires or is revoked; every operation it causes names it.
- A restored state directory has no key: clients get a pin mismatch whose hint says to compare and re-add.
- `--remote` is a top-level option (`reef --remote vm status`), as `git -C` is, so every command's long help stays within its budget.

## Alternatives considered

- **tonic's `tls_config`**: no `http/1.1` ALPN, no reload, no pin (context).
- **aws-lc-rs**: CMake and a larger static archive on musl, for no need here.
- **A plaintext mode behind a reverse proxy**: one misconfiguration from tokens in the clear; a proxy can speak TLS to the daemon.
- **Pinning the certificate rather than the key**: every renewal would break every pin.
- **Mutual TLS instead of tokens**: no browser story, and a certificate is harder to hand to a phone than a string.
- **Tokens hashed with a slow KDF**: protects nothing a 256-bit random secret needs.
- **An `admin` scope**: would make store builds, which run commands in the daemon, reachable from the network.
- **CORS now**: no client needs it until the mobile shell (R3.40).
- **An `Unauthenticated` error kind**: a new exit code for one answer every client already tells by its reason.
- **Binding on first use**, as R2.18 does: a remote client cannot ask a daemon to bind.
- **Threading a typed caller through every write path** instead of marking the agent: the same effect with a parameter on some thirty functions.
