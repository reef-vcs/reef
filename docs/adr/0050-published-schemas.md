# 0050. Published schemas

- Status: accepted
- Date: 2026-11-01
- Ticket: R2.24
- Amends: [0035](0035-mcp-server.md)

## Context

A harness that wants Reef as tools had three partial sources, and a person had to put them together: `reef --help` in prose, `reef guide -o json`'s list of command words, and `reef mcp`'s `tools/list`, with input schemas and no output shapes. Nothing outside Rust could read the API's descriptor set, and nothing said what any command prints. [0035](0035-mcp-server.md) decision 5 left the MCP tools' `outputSchema` to this ticket, to be derived from the same types as the CLI's output.

The output types already existed: `reef_client::json` for every command's full JSON, `reef_client::brief` for the views a pipe gets ([0045](0045-brief-json-by-default.md)), a dozen types of the CLI's own, and the MCP server's result wrappers. Two constraints shape what can be published. Every session that loads the MCP server pays for `tools/list` in tokens, and #116 already finds that cost higher than six questions save. And a schema written by hand drifts from the code that prints.

## Decision

1. **One offline command.** `reef schema [PART [NAME]...]` prints one JSON document; `PART` is `cli`, `mcp` or `api`, and `NAME` picks one command or a group's commands (by its words, resolved by clap itself: names, aliases, unique prefixes), one tool, or one service, message or enum of the package. `reef schema --descriptor-set` prints the API's `FileDescriptorSet`, with comments. It reads no configuration, connects to no daemon, ignores `--remote`, and describes the binary that runs. Always JSON: pretty on a terminal or with `-o json`, compact on a pipe or with `-o brief`. A name that matches nothing fails `not_found` with reason `SCHEMA_NAME_NOT_FOUND` and `next: reef schema <part>`. It is listed in `--help`, after `mcp`.
2. **The document is a JSON Schema 2020-12 resource.** `$id` is `urn:reef-vcs:schema:<version>`; `reef` carries the version, commit, target, `schema_version` (1), the API package, `api_revision` and `api_digest`. `cli`, `mcp` and `api` are annotations; every schema they use is under `$defs`: `reef_client::json`'s types by Rust name, brief views as `brief.<Name>`, the CLI's own types as `cli.<Name>`, the API's messages and enums by full name. An MCP tool's `outputSchema` is self-contained, with its own `$defs` (MCP results there as `mcp.<Name>`). Keys print sorted; two runs print the same bytes. A part or a name keeps only the definitions it reaches.
3. **Inputs from clap.** Each leaf command gets `input`, a plain JSON Schema object usable as a tool's input schema unchanged (clap's argument ids, help as `description`, `required`, `default`, value types from the value parser's type), with what clap enforces beyond each value: a required group as `anyOf`, each pair clap refuses together as `not: {required: [a, b]}`, and what an argument needs as `dependentSchemas`. Beside it, `argv` says how to turn an input into words (`flag`, `short`, `position`, `after_dashes`, `repeat`, `conflicts_with`, `requires_one_of`), and `cli.argv_rules` says how to assemble them. The global flags appear once; `before_command` marks the one that must precede the words (`--remote`). clap keeps `requires` private, so those are listed by hand; a test probes clap with every argument alone and every pair, and fails until the schema says what clap does. A value type not classified fails a test, so a new one is classified on purpose.
4. **Outputs from the types that print them, in each form.** A table, one row per leaf command, gives the schema `-o json` prints, the brief form's (the same, or a view), what a pipe gets without `-o`, whether the output is one value per line (`op watch`), whether it ends stdout after another program's (`ws run`), whether it exits non-zero with its result (`ws run` and a failed `store build` with their program's code, `ws gc` when a repository's jj step failed), and which flags make a pipe get text (`init --print`) or stdout bytes (`schema --descriptor-set`). Every other failure prints the error document when the output is JSON, once in `cli.errors` with each kind's exit code. Types derive `schemars::JsonSchema` under the serialize contract: an `Option` without `skip_serializing_if` is required and nullable, one with it is optional. A string filled by a name function (`state_name`) lists its values from that function, so they cannot drift. Brief views take their descriptions and value lists from their full types and never allow `null`. Nothing sets `additionalProperties: false`, so a newer Reef's added keys never fail an older schema.
5. **The API as canonical proto3 JSON**, converted from the descriptor set in the repository: `json_name` keys, 64-bit integers as decimal strings, enums as names, `bytes` as base64, `Timestamp` and `Duration` inlined as strings, a `oneof`'s members mutually exclusive, comments as descriptions. Each method, keyed by name, carries its path, input and output, streaming, access level and idempotency. A printer emits an enum value its descriptors do not know as a number, so a newer daemon's new value fails an older schema's `enum`; the API adds values only with a revision, which `api_revision` names. The v0 package is not described.
6. **MCP output schemas are published, not declared** (amends [0035](0035-mcp-server.md) decision 5). Every tool has an output schema, self-contained, and `reef schema mcp` gives each tool as `tools/list` does plus its `outputSchema`, the server's instructions, and the error result's schema. `tools/list` stays byte for byte as it was (21,211 bytes): declaring every output schema would make it 141,756 bytes, 6.7 times the fixed cost #116 already finds too high; the descriptions already name each result's shape; and MCP binds structured results to a declared schema, which Reef's error results (decision 6 of 0035) would have to join on every tool. If #116 is solved by loading tool definitions only when used, declaring them can be measured again.
7. **Stability.** `schema_version` changes only when a member of the document is renamed or moved. Command names and full JSON only grow ([0025](0025-agent-facing-cli-contract.md), [0034](0034-cli-over-the-vcs-services.md)), and so do their schemas; a brief view's description says which keys it keeps may change in a minor release ([0045](0045-brief-json-by-default.md)); the API's part changes with `api_revision`, by addition ([0029](0029-daemon-api-v1.md)). No API revision: nothing in `reef-api` changes.
8. **Tests check real output against the schemas.** The VCS, CLI and MCP integration tests validate every command line's stdout and every tool result they produce, and one script runs every command that can run against a test daemon, in each form. Canonical JSON from prost-reflect validates against every message of the API.

## Consequences

- A harness generates tool definitions, typed clients or result checks from one call, and `reef schema cli <words>` gives one command's (about 20–30 KB with the definitions it reaches; the whole document is about 450 KB).
- Every PR that adds a command adds its row to the outputs table, every new output type derives `JsonSchema`, and every new tool names its output type; tests fail until they do.
- `reef` links `prost-reflect` (no features) for the API part. `jsonschema` is a dev-dependency only.
- The agent pays nothing new: `tools/list` and the guide are unchanged, and `--help` gains one line (about 90 bytes, #122).
- Text output has no schema; `reef-daemon`'s own commands are not described (`config show -o json` is an object).

## Alternatives considered

- **Hand-written schemas**: they drift, and nothing would check them.
- **A committed copy of the document with a drift test**, as `API_DIGEST` is: every output change would regenerate a file of 450 KB, and the validation tests check the same thing against real output.
- **`outputSchema` in `tools/list`, always or behind a flag**: the cost in decision 6, and a flag no configuration would set.
- **`protoc-gen-jsonschema` or `buf` plugins**: a Go or `protoc` toolchain at build time, which R1.03 and R2.01 avoided.
- **OpenAPI**: the API is gRPC, and nothing serves it as REST.
- **Extending `reef guide -o json`**: the guide is prose for agents and stays small.
- **A separate schema crate**: two modules and a dependency do not need one.
