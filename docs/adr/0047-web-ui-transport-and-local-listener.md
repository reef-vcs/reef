# 0047. Web UI transport and local listener

- Status: accepted
- Date: 2026-10-31
- Ticket: R2.18

## Context

The [design](../design.md) gives humans one web application, "React and TypeScript, one codebase served by the daemon and by remote stores", over a "generated gRPC-web client from the protobuf schemas", which later runs inside the desktop and mobile shells too ([0005](0005-tauri-desktop-shell.md)). It subscribes to the operation log and the presence channel and never fetches on a timer, and it shows "one state color per object, used everywhere".

The daemon listened only on its Unix socket, which a browser cannot reach, and the socket's mode was the whole of its authorization ([0027](0027-trust-boundaries-in-phase-1.md)). The [threat model](../threat-model.md) required any other listener to meet five requirements before it served an RPC. [0004](0004-grpc-over-unix-socket.md) had left "gRPC-web or a WebSocket bridge" open, while [0029](0029-daemon-api-v1.md) already assumed gRPC-web: server streaming only (decision 13) and errors that Connect-ES decodes with stock tooling (decision 14). The repository had no JavaScript, no Node toolchain and no way to ship static files in a binary.

## Decision

1. **gRPC-web through `tonic-web` and Connect-ES, binary framing only.** The daemon wraps its services in `tonic_web::GrpcWebLayer`; the app uses Connect-ES's gRPC-web transport with messages generated by `protoc-gen-es`. Connect-ES reads a stream through `fetch`'s `ReadableStream`, so a tab that stops reading stops the browser reading the socket, TCP pushes back, and R2.09's session is held back as for any client: nothing is dropped. gRPC-web is the API itself, with the same messages, `ErrorDetail`, access levels and revision checks, and R2.08's listener serves it to browsers anyway. Only `application/grpc-web` and `application/grpc-web+proto` are accepted; the base64 text mode is `415`. The schema has no client streaming to lose.
2. **A loopback listener, bound on demand, serving the app and READ RPCs only.** `[ui] listen` defaults to `127.0.0.1:0`, a port the kernel picks at each start; only a loopback IP literal with a port loads, and anything else is a configuration error naming R2.08. The first `CreateWebSession` binds it, and it stays bound until the daemon stops, since a tab's origin is its port. A daemon whose user never runs `reef ui` opens no TCP port. A failed bind is `WEB_UI_UNAVAILABLE` and the next call retries; there is no fallback to another port. `[ui] enabled = false` is `WEB_UI_DISABLED`. The listener is a second tonic server over the socket's services (`server::routes`), behind the gate, `GrpcWebLayer` and `CompatLayer`, sharing one `AppState`, so a browser's streams count against the 1,024 subscriptions. It serves the embedded assets and gRPC-web calls to `ACCESS_READ` methods; it serves no native gRPC, no WRITE or ADMIN method, no `reef.daemon.v0` beacon, no WebSocket and no CORS. It caps open connections at 64 and backs off at the open-file limit like the socket's accept loop. It never sets `SO_REUSEPORT`.
3. **A session is a per-process bearer token, never a cookie, never persisted.** `DaemonService.CreateWebSession` (ADMIN, so served only on the socket) mints 32 bytes from the thread's CSPRNG as 43 base64url characters; the daemon keeps only its blake3 digest. A session lives until the daemon stops, or for 24 hours with no request on it and no stream open; at 32 sessions the least recently used one with no stream open ends. The app sends `authorization: Bearer <token>` from `localStorage` (per origin, so every tab of the session shares it); the gate removes the header before tonic sees it, so no handler, log line or error carries it. Cookies are scoped to a host and not a port, so a cookie for `127.0.0.1:<port>` would go to any server on `127.0.0.1`, another local user's included. A persisted token would let whoever binds the port after a restart collect it; a token that died with its daemon is worth nothing.
4. **A launch file keeps the token off every command line.** A URL passed to `open` or `xdg-open` is readable through `ps` while the opener runs. `reef ui` asks for a launch file, `<state>/ui/open-<16 hex>.html` (`0600` in a `0700` directory), a page with no script whose meta refresh goes to `http://127.0.0.1:<port>/#session=<token>`, and opens the file's path: `$BROWSER`, else `open` or `xdg-open`. It is deleted at the session's first request, 60 seconds after it was written, or at the next start. The token travels in the fragment, which no request line or `Referer` carries, and the app removes it with `history.replaceState`. A command that is not on a terminal opens nothing, so an agent never pops a window on the user's desktop; `--print` prints the session URL instead, as a credential.
5. **The gate checks Host, then the method, then Origin and fetch metadata, then the token, and sends no CORS.** In order: `Host` (or `:authority`) must equal the bound authority exactly, else `421` (DNS rebinding); an `Upgrade` header is `400` and `OPTIONS` is `405`, so every cross-origin preflight fails; `GET` and `HEAD` off API paths serve the assets; an API path must be `POST`; an `Origin`, if sent, must be the listener's own and a `Sec-Fetch-Site`, if sent, must be `same-origin`, else `403` before the token is looked at; the content type must be binary gRPC-web, else `415`; the token must name a live session, else `PERMISSION_DENIED` with `WEB_SESSION_INVALID`; the method must be `ACCESS_READ`, else `WEB_ACCESS_DENIED` (metadata `method`, `access`). The last two are gRPC-web trailers-only responses, so Connect-ES reads them as typed errors with their hint; the others are plain HTTP, since a client that fails them is not a gRPC-web client of this origin. Every response carries a strict CSP (`script-src 'self'`, no `'unsafe-inline'` or `'unsafe-eval'`, `frame-ancestors 'none'`), `nosniff`, `no-referrer`, `X-Frame-Options: DENY`, same-origin opener and resource policies, an empty permissions policy, and `Cache-Control: no-store` on API answers and `index.html`. The assets are public: they are the same bytes as every release's, with no secret in them. Both new reasons use `PermissionDenied` rather than a tenth error kind, since no CLI receives them; R2.08 decides.
6. **Reef prints the IP literal, never `localhost`.** `localhost` fails the Host check, and it may resolve to `::1` first, where another local user could listen on the same port number while the daemon holds only `127.0.0.1`. Binding the exact address rather than a wildcard leaves no more specific bind for another user to take on macOS.
7. **The threat model's TLS requirement applies to listeners reachable from another host.** TLS protects traffic between hosts, and loopback carries none; encrypting it would need a local CA in the user's trust store, a larger risk than it removes. The requirement is rescoped, the loopback rules are stated in their own subsection, and R2.08's listener still needs TLS. Packet capture on loopback needs root on Linux and macOS, and root is outside the model.
8. **The app is built only where it ships, and embedded by a dependency-free crate.** No built bundle and no generated code is committed (the user's decision). `npm run build` in `web/` writes `crates/reef-web/assets/`, which git ignores; `reef-web`'s `build.rs` embeds it when `assets/index.html` exists and otherwise a committed placeholder page, with the same shape (an index and one immutable asset) and `BUILT` saying which. `cargo build`, `cargo install` and CI's `check` jobs therefore need no Node and embed the placeholder, and `CreateWebSession` refuses a placeholder build with `WEB_UI_NOT_BUILT`, so `reef ui` never opens a page that cannot work. CI's `web` job builds and tests the app; the release builds it once, embeds the same bytes in all four targets, checks each binary for the built script's name and against the placeholder's sentence, and fetches the real page from an installed daemon.
9. **TypeScript is generated at every build, never committed.** `npm run gen` writes `web/src/gen/` with `buf generate` and the local `protoc-gen-es`, pinned in `package-lock.json`, needing no network. `build`, `typecheck`, `lint`, `test` and `dev` run it first, so a schema change that breaks the app's types fails the `web` job on the pull request that makes it.
10. **One stream of each kind per browser, shared across tabs.** Browsers speak HTTP/2 only over TLS, so on loopback each open stream holds one of six connections per origin. The tab holding the Web Lock `reef-live` opens one unfiltered `SubscribeOperations` and one `SubscribePresence` and republishes every frame on the `BroadcastChannel` `reef-live`; a joining tab gets the presence set and the last cursor, and when the leader closes the next holder resumes from the last cursor it saw. Operations resume exactly from the cursor, with `op watch`'s backoff; `TOO_FAR_BEHIND` and `OPERATION_LOG_REWRITTEN` subscribe fresh and tell views to reload. The app never fetches on a timer, and applies what arrives in one animation frame as one update.
11. **Seven state colors, two neutral states, and rules for using them.** `draft`, `proposed`, `queued`, `testing`, `landed`, `failed` and `conflicted` from the design, plus `ended` and `none`, each a `--state-<name>` token and a `--state-<name>-tint` in light and dark, held by a test to at least 4.5:1 against the surface and against the tint. A state is always shown with a shape and a word, never by color alone. State colors mean object states only: connection status, errors and chrome use neutral tokens, so green always means landed. `/states` renders them all as the reference later views check against.

## Consequences

- `reef ui` opens a live view of every registered repository in a browser, and R2.19 to R2.21 add views to the same app, stream layer and palette.
- A daemon that has served a session holds one TCP port on loopback until it stops; any local user can fetch the app from it and nothing else.
- Every daemon restart, upgrades included, ends every session: open tabs show the "no session" page until `reef ui` runs again.
- A leaked session URL reads every registered repository through every `ACCESS_READ` RPC, `ReadFile` and `GetDiff` included, until the daemon stops or the session idles out. It writes nothing.
- Releases need Node and the npm registry; a registry outage on release day delays a release.
- Builds from source have no UI unless `just web-build` runs first, and `reef ui` says so. If R2.25 publishes the crates, `cargo install reef-daemon` has the same gap unless the published `reef-web` carries built assets (its `include` is ready for either).
- A browser without Web Locks opens two streams per tab, so a fourth tab would stall on loopback. HTTP/2 over R2.08's TLS removes the limit remotely.
- A snap-confined browser cannot read the launch file under a hidden directory; `reef ui --print` is the way there, and for a root daemon.

## Alternatives considered

- **A WebSocket bridge.** A browser's `WebSocket` has no backpressure, so the bridge would buffer without bound in the tab or drop in the daemon, breaking R2.09's "nothing dropped". It is also a second protocol to design, version and secure (cross-site WebSocket hijacking), and R2.08 serves gRPC-web anyway.
- **A per-command proxy in `reef ui`** instead of a daemon listener. It dies with the command, and R2.08 needs the daemon to serve.
- **Binding at start.** Every daemon would open a port whether or not its user ever opens the UI.
- **A fixed default port.** Another user can take a known port first; a fixed port remains available as configuration.
- **Cookies.** They ignore ports, so they would leak to any other server on loopback.
- **Persisted tokens.** Whoever binds the port while the daemon is down would collect a live credential.
- **A one-time code in the URL, exchanged for a token.** The code sits on a command line for a race to steal.
- **TLS on loopback with a local CA.** A CA in the user's trust store is a larger risk than plaintext on an interface no other host reaches.
- **Building the assets in `build.rs` with Node.** Every Rust build would need Node and the network.
- **Committing the built bundle**, with a source digest and a CI job that reproduces it, so source builds have the UI too. Rejected by the user (2026-10-31): no generated bundle in git, which would be collapsed in review and drift-checked forever, at the cost of Node in the release workflow and no UI in source builds.
- **Committing the generated TypeScript.** It drifts, and a schema change that breaks the app's types would surface only when someone regenerates.
- **Building the assets once per target in the release.** Four Node setups, and four chances for the bytes to differ.
- **A router or a state library.** Every runtime dependency runs with the token; routing is about 50 lines over the History API, and state is `useSyncExternalStore` over the stream layer.
- **Streams per tab.** Three tabs with two streams each would use every connection the browser allows an origin over HTTP/1.1.

## Amendment, 2026-11-01 (web UI design pass): brand chrome, relative times and developer mode

- **Chrome may use the brand tokens.** Decision 11's "chrome uses neutral tokens" now reads: chrome may use the brand tokens (`--brand*`, `--ocean*`, `--coral`), which never mark an object's state or health, and whose teal the token test holds at least 30° of hue from `--state-landed`. Coral sits near `--state-failed`, so it appears only on the ocean app bar, where no object is shown. Connection status, errors, lease health and attention stay neutral. Green still means only landed.
- **Relative times.** The app shows times relative to a clock that ticks once a minute, at the minute, through `after`, and reads nothing over the network; the exact time is in each time's `title` and in developer mode. R2.18's "absolute, never relative" is replaced. The scrubber's track still reads no clock, and periods (the feed's summary, "Loaded back to", "Go to time") stay absolute.
- **Developer mode.** A per-origin setting in `localStorage` (`reef.devMode`), off by default, that renders every page as before the design pass: ids, CLI commands, the smartlog's revset, exact times and the API's words. Off, those elements are not in the DOM.
