# 0057. Operator identities and session keys

- Status: accepted
- Date: 2026-11-06
- Ticket: R3.03
- Amended by: [0058](0058-provenance-records.md) (`custody: daemon` keys issued internally for provenance, without a proof of possession, for `max_lifetime`; records pin their keys; revocation drops held keys), [0066](0066-sigstore-keyless-session-keys.md) (a second issuer kind, `sigstore`; OIDC matches on identities; a binding's revocation beside the others)
- Amends: [0055](0055-evidence-object-format.md) (identity beside the signature; a second predicate type in the format crate), [0049](0049-remote-listener.md) (tokens linked to identities, `Rule::LinkedIdentity`), [0029](0029-daemon-api-v1.md) (decision 12's exceptions gain `IssueSessionKey`), [0020](0020-local-backup-format.md) (the authority key is outside backups, and a restore retires it)

## Context

[0055](0055-evidence-object-format.md) made the attestor a key: an evidence object says which key signed it and nothing about who holds the key. The [design](../design.md) wants provenance that "chains to a person or pipeline without long-lived agent secrets", short-lived session keys a daemon issues "in the keyless Sigstore pattern" that "can be revoked without touching anything else", and per-repository policy that "names the attestor identities it accepts": "A solo developer trusts their own machine. A large project trusts its CI identity and nothing else." Its durability table says session keys are short-lived and never backed up.

What exists is declared, not authenticated: a request's `reef-agent`, a workspace's `owner`, jj's operation user and host. The remote listener's tokens ([0049](0049-remote-listener.md)) are the one authenticated attribution, and they authenticate a connection, not a signature. On one uid, any process the user runs can do whatever the user can on the socket ([0027](0027-trust-boundaries-in-phase-1.md)).

Sigstore keyless signing needs an OIDC flow, Fulcio and Rekor; verifying it needs a TUF trusted root and X.509 checks. Verification can keep the tree's ring-only rule through `sigstore-verify` with a ring crypto provider; signing needs an HTTP client. That is its own ticket, R3.42. A verified human presence (a passkey's user-verified assertion) is R3.43.

## Decision

1. **Identities are `person` or `ci`, machine-wide, named once and forever; agents are actors, not identities.** An operator identity (`identities`) has an id (`idn_<16 hex>`), a name (`[a-z0-9][a-z0-9._-]{0,62}`, never starting with the id prefixes `idn_` or `ses_`, so a text names an identity by one rule; unique among all identities, revoked ones included, and never reused within one database's history, so a policy naming `alice` is not satisfied by a newcomer; restoring an older backup can bring back a name with a new id, so a policy pins the id and the authority, not the name alone), a kind, and an optional display name and email that Reef does not verify. Only the daemon's user creates and revokes them, through ADMIN RPCs. An agent acts for an identity in a session, and its label is recorded as a declared claim. At the first start with no identity, the daemon creates a `person` identity named after the login user (`operator` when that sanitizes to nothing) and records it as the default (`meta.default_identity_id`); `[session_keys] default_identity` names another; one that names no live person identity is logged and leaves the daemon without a default (requests for it are refused, `DEFAULT_IDENTITY_UNAVAILABLE`) rather than unable to start. The current default cannot be revoked (`IDENTITY_IS_DEFAULT`). `[identity]`, the daemon's commit author, is unrelated.
2. **A per-daemon ed25519 authority key, on disk and not backed up, whose public keys are kept for good.** The current authority's private key is PKCS#8 at `<state>/identity/authority.pem` (`0600` in `0700`, written to a temporary file created new, synced, renamed and the directory synced); its public key and key id are in `identity_authorities`, which backups copy. At every start the file is checked against the current row: missing, unreadable or another key retires the row and makes a new key, logging both ids; a loose mode is fixed with a warning. `RotateAuthority` retires the current key and makes a new one; with `revoke`, the old one is revoked too. `RevokeAuthority` revokes an authority already retired (by a restore, a replaced key file, or a rotation without `revoke`); the current one is refused, since it would go on issuing. A retired authority's certificates still verify by its kept public key. A stable key lets another party (R4.09's store, R3.07's policy, a teammate) pin a machine.
3. **Certificates are a second predicate type in [0055](0055-evidence-object-format.md)'s envelope.** An in-toto Statement v1 whose one subject is `{"name": "session-key", "digest": {"sha256": <the key's id>}}`, predicate type `urn:reef-vcs:session-key:v1`, predicate `publicKey`, `identity` (`id`, `name`, `kind`), `actor`, `agent`, `session`, `presence`, `custody`, `notBefore`, `notAfter` and `issuer` (`kind`, `keyId`, `host`), in a DSSE envelope signed once by the authority, with the envelope's size, depth, duplicate-key, key and PAE rules. `reef-evidence`'s `session` module certifies and checks them, purely, so R4.10's store issues and verifies the same thing; `check_certificate` takes the authority by the envelope's `keyid` through a lookup, verifies the signature before it parses the statement, and refuses a `presence`, `custody`, `actor`, kind or issuer kind it does not know. [0055](0055-evidence-object-format.md)'s stability rules apply to the predicate type. The certificate is authoritative in `session_keys`; its other columns index it, and every read checks it again and reports the certificate's fields.
4. **Client-held session keys, issued with a proof of possession, live 1 hour by default and 24 hours at most, renewed by session.** The requester generates an ed25519 key and signs `PAE("application/vnd.reef-vcs.session-key-proof", "reef-session-key-proof/v1\n" + authority_key_id + "\n" + key_id + "\n" + identity + "\n" + actor + "\n" + session + "\n")` with it, so nobody can bind someone else's key, and a proof cannot be replayed for another binding or at another authority: the current authority's key id (`ListAuthorities`) is its audience, checked again as the certificate is signed, and a refusal names the current one so a client that raced a rotation signs again. The daemon never sees a private session key and stores none; the CLI holds one in memory for one command, and `reef identity session issue` prints one only as JSON. A key already certified, or one that already signed evidence as a bare key, is refused, so a session key is always fresh. `[session_keys] lifetime` (default 1 hour) and `max_lifetime` (default 24 hours, at most 7 days), each at least 5 minutes, bound a key's window; `reef evidence add` issues one for five minutes, which no configuration can refuse. Renewal issues a new key in the same session with the same identity, actor and channel (the socket, or the same remote token; `sessions.channel`). An identity holds at most 10,000 unexpired keys, counted in the insert's transaction. Issuing records no operation.
5. **The issuance rules.** On the socket: any live `person` identity (empty is the default), never a `ci` identity, and `human` allowed with `presence: none`. Through the remote listener: a `write` token linked to an identity gets keys for that identity alone, never `human`; a token with no link gets none (`Rule::LinkedIdentity`). `human` is never certified for a `ci` identity. The web listener serves no WRITE method. So a `ci` key needs CI's token, not one socket call, and a remote caller signs only as its token's identity. A token is linked at creation and never relinked; rotation keeps the link.
6. **Validity at witness time, and revocation as `invalid_from`.** A signature's status is judged at the evidence row's `added_at`, when a trusted clock first saw it, never at a time it claims: `BOUND` inside `[notBefore, notAfter]` and before every applicable `invalid_from` (the key's, its session's, its identity's, its authority's); `EXPIRED` outside the window; `REVOKED` at or after an `invalid_from`; `INVALID` when the certificate does not verify; `UNBOUND` with no certificate. A revocation records `revoked_at` and `invalid_from` (default `revoked_at`); `--since`, `--since-issued` and `--since-created` backdate it for a compromise, a later revocation only moves it earlier, and a future one is refused. A revocation made after the witness time is reported beside `BOUND`.
7. **`KeyIdentity` beside `signature`, with no trust decision.** `Evidence.identity` reports the status and the certified key (identity, kind, actor, agent, session, presence, custody, issuer, window, the earliest applicable revocation) at every read; `ListEvidence` looks a page's keys up in one query and checks each certificate in the job that checks the envelopes. Identity is looked up only by a key id whose signature verified at the read: an object whose signature does not verify reads `INVALID` with no key, so an `evidence.key_id` changed behind the daemon borrows no other key's identity. A key whose certificate is invalid reports only its id, `certificate_valid: false` and the daemon's own records of the row (`issued_at`, `issued_by_agent`, `remote_token_id`, its own revocation); nothing else of its columns. The `identities` filter selects by the columns, then keeps only what the verified certificate confirms; invalid certificates are excluded. A key is live only while it, its session, its identity and its authority are unrevoked. Whom to trust is R3.07's.
8. **`presence` and `IssuerKind` are the seams.** R3.03 issues `presence: none` only: the daemon's user, or anything running as that user, asked for a key declared human. R3.43 adds `user_verified` with a passkey assertion kept in the certificate. `IssuerKind` is `reef-daemon` here; R4.10 adds `reef-store` and R3.42 `sigstore`, each a sibling of `check_certificate` that yields the same binding for `status_at`.

## Consequences

- Evidence answers "which identity is key K bound to" for every read, so R3.07 can write policy over identities, actors, presence and authorities, and R3.13 can refuse on a status.
- `reef evidence add` signs with a session key by default: no key file exists, and evidence reads `BOUND`. `--key` keeps R3.01's behaviour and reads `UNBOUND`.
- On one uid an identity proves little: any same-uid process can call `IssueSessionKey` or read `authority.pem` and get keys for any `person` identity and any actor (S-58, S-59). What it does distinguish is other local users, remote callers, and `ci` keys, which need CI's token (S-60, S-61).
- A restore retires the restored authority: the restored daemon makes a new one at its first start, and every old certificate still verifies. A client-held key keeps its certificate until it expires.
- GC sweeps keys that ended a week and `keep_newer` ago that no evidence names, with their empty sessions, in the first report of a run. Identities and authorities are never deleted.
- Revocation is the daemon's record, which the same uid can edit, as it can anything in `reef.sqlite3`; distributing revocations to other verifiers is R4.10's.

## Alternatives considered

- **X.509 certificates through `rcgen` and `x509-parser`.** An ASN.1 parser on the daemon's input path, and still not Fulcio's chain; R3.42 reads Sigstore's certificates through its own issuer kind.
- **An authority key per daemon start, in memory only.** Nobody could pin a machine.
- **The authority key in the OS keychain.** No Linux equivalent without D-Bus, and unsigned binaries prompt on every upgrade on macOS; a follow-up, with hardware-backed keys.
- **The authority key in `reef.sqlite3`.** It would be in every backup.
- **Daemon-generated session keys returned to the client.** The daemon would see every private key.
- **A signing RPC with daemon-held keys for evidence.** A signing oracle any socket client can call, and the attestor would be the daemon; R3.04's daemon-held keys sign provenance only.
- **Agents as identities.** Long-lived agent records, against the design.
- **Remote tokens as identities.** A token is a transport credential that rotates, and its holder is not necessarily a person or pipeline.
- **Claimed time (`finishedOn`) for validity.** The attestor's own claim.
- **Revocation that invalidates everything always, or nothing.** The first punishes routine ends of sessions; with the second, a leaked key's past signatures keep counting.
- **Full Sigstore keyless here.** A ticket on its own: R3.42.
- **CRL or OCSP distribution.** The daemon is its own only verifier until R4.10.
