# reef-daemon

The local service of **Reef**, version control built for a world where AI agents write most of the code. It owns snapshots, workspaces, merge, and queries on behalf of agents, and hosts the typed API, workspace materialization backends, the lease manager, and filesystem watchers. It builds the `reef-daemon` binary.

The version-control data model and merge logic live in `reef-lib`, which this crate depends on. Its own model is the inventory it keeps in SQLite (repositories, workspaces, leases, reclaims), in `reef_daemon::model` and `reef_daemon::db`. It contains no CLI code.

The `reef` binary (`reef-vcs`) does not depend on this crate: it talks to the daemon through `reef-client`, which this crate re-exports as `reef_daemon::client`, and runs this crate's binary for `reef daemon run` and for the two commands that need its library but no running daemon, `reef-daemon config show` and `reef-daemon restore` ([ADR 0033](../../docs/adr/0033-thin-client.md)). This crate never depends on `reef-vcs`. The design document and roadmap are at <https://github.com/reef-vcs/reef>.

Run it in the foreground with `cargo run -p reef-daemon` (state in the platform state directory, or `REEF_STATE_DIR`); it stops cleanly on Ctrl-C or SIGTERM. The process and threading model is [ADR 0012](../../docs/adr/0012-daemon-process-model-and-threading.md); the state directory and `config.toml` are [ADR 0013](../../docs/adr/0013-daemon-state-directory-and-configuration.md), and `reef config show` prints the effective configuration. The API schema, `reef.api.v1`, is in the `reef-api` crate, compiled at build time without `protoc`; its conventions and error model are [ADR 0029](../../docs/adr/0029-daemon-api-v1.md). This crate serves it (`server`, `service`), and clients use `reef_daemon::client::Client`.

The read RPCs (`GetStatus`, `ListChanges`, `GetChange`, `GetDiff`, `ListOperations`, `GetOperation`) take the repository from its thread in one short job and do their work on the blocking pool (`reef_daemon::read::Reads`), so a slow read never delays a snapshot; the jj work itself is in `reef_lib::jj` (`revset`, `log`, `diff`, `oplog`, `effects`). [ADR 0030](../../docs/adr/0030-reads-over-jj-state.md) records how revisions, reads at an operation, pages, operation kinds and effects work. An operation the daemon did not just write is classified by its `reef.kind` attribute, else by the description Reef wrote:

A lifecycle transition's operation also carries `reef.lifecycle`, the transitions as compact JSON, format 1 (`reef_lib::jj::lifecycle::LifecycleRecord`), and changes nothing in the view. A landing's operation (`reef: land change <id> on <bookmark>`, or `reef: land <n> changes on <bookmark> (batch <id>)`) carries `reef.lifecycle` with its `landed` transitions, `reef.batch` with the batch's id, and `reef.landing` with the landing's id when it lands one change, and moves the bookmark. A batch's trial commit is written by `reef: test batch <id> on <bookmark> (prefix <k> of <n>)` and its trial commits abandoned without a landing by `reef: end batch <id>`, both with `reef.batch`. A comment's operation (R3.12) carries `reef.comment`, its events as compact JSON, format 1 (`reef_lib::jj::comments::CommentRecord`): ids and states, never a comment's text; it changes nothing in the view.

### Landing service

`landing/` ([ADR 0064](../../docs/adr/0064-landing-service-local.md), [docs/landing.md](../../docs/landing.md)) judges a proposal at the gate (`land_change`: the preview and the destination's policy over the recorded commit), queues it with an enqueue transition, and lands queued changes with one worker per repository (`landing::worker`): under the repository's create lock shared from its judgment to its record, then the lifecycle lock, through `Manager::rewrite_held` with `Write::Land`. Start-up resumes every repository's queue. Records are `landings`, `landing_changes`, `landing_evidence` (pins, part of retention's `PINNED`) and `landing_policies`. The worker lands batches (`landing::batch`, [ADR 0067](../../docs/adr/0067-batching-and-bisect.md)): it forms one from the queue under the create lock shared, tests prefixes with no lock held (trial commits, executor jobs through `Executor::submit`, waiting on `Executor::changed`), bisects a failing head, and lands a prefix in one `Write::Land`; start-up finishes open batches `interrupted`. Batches are `landing_batches`, `landing_batch_members` and `landing_batch_trials`.

### Change lifecycle

`lifecycle/` ([ADR 0063](../../docs/adr/0063-change-lifecycle.md), [docs/proposals.md](../../docs/proposals.md)) records each transition as a `pending` row in `lifecycle_transitions`, then its operation, then the row committed with the operation's id in the transaction that updates `lifecycle`, under the repository's create lock (shared) and its lifecycle lock. Start-up step 5 commits or drops what a crash left pending; GC maps the rows' operation ids through its rewrite; `lifecycle::observe` records a recorded change as landed when it reaches `trunk()`; `UndoOperation` of a transition's operation reverts it in the rows.

| Table | Key | Holds |
| --- | --- | --- |
| `lifecycle_transitions` | `(repo_id, id)`, `id` `trn_<16 hex>` | Every transition: change, commit, from, to, cause, round, reason, superseded-by, destination, the operation (or `operation_collected`), and who: agent, actor, identity, session, remote token; `seq` orders a repository's committed transitions |
| `lifecycle` | `(repo_id, change_id)` | Each recorded change's state: its latest committed transition, and who made its latest proposal |

`DescribeChange`, `AbandonChange` and `UndoOperation` run through `Manager::rewrite` (`workspace/rewrite.rs`): plan on the repository thread, then take the repository's create lock shared and each moved workspace's scan lock in id order (as GC does), snapshot those workspaces one at a time, descendants first (abandon and undo), write one operation, and have each moved workspace take its new commit, descendants first. A workspace the write kept on its change keeps the edits it made meanwhile: they are carried onto its new commit in the same change, an overlap left as a conflict there ([ADR 0039](../../docs/adr/0039-carrying-edits-through-a-write.md)).

`FileService` (`service/files.rs`, [ADR 0032](../../docs/adr/0032-files-without-a-workspace.md)) reads files and lists directories at a revision on the read pool, and `EditFiles` is a fourth write through `Manager::rewrite`: the edits (`reef_lib::jj::files`) are checked as a dry run when the write is planned, workspaces on the edited commit and its descendants (on the parent, for a new change) are snapshotted, the edits are applied to the tree and recorded as one commit, and workspaces on a rewritten commit take the new tree through jj's checkout, with any edits they made during the write carried onto it (ADR 0039). No directory is created for the edit itself.

`SubscribeOperations` (`subscribe/`, [ADR 0036](../../docs/adr/0036-operation-log-subscriptions.md)) streams the operation log. The repository thread compares its head before and after every job and tells `subscribe::OpEvents` when it moved, which covers every operation Reef records; a 200 ms poll of the op heads of followed repositories finds other `jj` writers. A subscription's position is a frontier per repository (the op heads it has everything up to), handed out as an opaque cursor; `reef_lib::jj::oplog::walk_after` reads what follows it with a bound. Each subscription is a task (`subscribe/session.rs`) that reserves its channel slot before reading the log, so a slow client is held back rather than queued for, and catches up from the log; frames hold at most 1,000 operations and 1 MiB, live ones are spaced 50 ms apart, and an empty frame every 15 s is a keepalive. GC moves subscriptions to the rewritten head, those behind it after reading up to the head it rewrote. Sessions read through the broker (`subscribe/broker.rs`, [ADR 0038](../../docs/adr/0038-subscription-broker.md)): for each repository some session follows, one ingest task reads each new operation once, converts it once (`subscribe::feed::deliver`), and appends it to a bounded ring of `reef-broker`'s (4,096 operations, 8 MiB; 64 MiB for every ring; dropped a minute after its last follower). A session whose position the ring holds is served from memory; any other position is read from the log by `subscribe::feed::read`, R2.09's path, so frames are the same either way. GC restarts a ring at the rewritten head; an outside rewrite, or more new operations than a ring holds, restarts it at the op heads. A per-minute `subscription broker summary` line reports rings, bytes, ingests and how many session reads were served from rings and from the log. `subscribe.ring_operations = 0` (tests only) turns the broker off.

Presence (`presence/`, [ADR 0037](../../docs/adr/0037-presence-channel.md)) is the ephemeral channel beside it, in memory only. `presence::PresenceHub` holds the live entries, each with a daemon-assigned id, four fixed fields (kind, agent, repository, workspace) and a clamped TTL; one timer task expires them and runs deferred broadcasts, since an entry's changes are broadcast at most once per 50 ms. Client entries are capped (4,096, 32 per agent) and refused past the cap, never evicted. Each `SubscribePresence` is a task (`presence/session.rs`) that sends the current set, then drains the broadcast into one pending state per entry and sends the latest, resynchronizing from the hub's set if it falls behind. The daemon reports three kinds itself (`presence/publish.rs`): a lease entry on every issue and renewal that lapses after two missed heartbeats, an editing entry from the paths each watcher or explicit snapshot committed, and the progress of creates and store builds once they have run 250 ms.

The symbol index (`symbols/`, [ADR 0042](../../docs/adr/0042-symbol-index.md)) is a cache beside the metadata database: one SQLite file per repository, `repos/<id>/symbols.sqlite3`, outside backup and migrations and recreated when unreadable. `symbols::SymbolIndex` opens each repository's store on first use, runs passes over trees (`symbols/index.rs`: diff from the first parent's complete tree, or walk it; extract the supported files without an entry on its own low-priority rayon threads; record the tree's counts), shares one pass among concurrent requests for a tree, and queues snapshots that change a tree and `EditFiles` commits for background indexing. Extraction itself is `reef-symbols`' (tags for six file types, SCIP normalization). `symbols/query.rs` answers `ListSymbols` by path, extracting up to 1,000 missing files inline, and by name or symbol on a complete tree; `symbols/upload.rs` checks each SCIP document's digest against the blob at its path; `symbols/gc.rs` is GC's fifth step.

Symbol-level diffs (`symbols/diff.rs`, [ADR 0043](../../docs/adr/0043-symbol-level-diff.md)) hang off `GetDiff`: the diff page lists every differing file's two sides (`DiffOptions::pairs`), `symbols::diff::compute` looks up or extracts both sides' entries, matches definitions across the whole diff with `reef_symbols::diff`, and works out line counts, nesting and expansion for the page's files from per-definition line diffs (`reef_lib::jj::diff::range_diff`); then the handler waits for the new tree's pass, without a read permit, and `symbols::diff::call_sites` reads references by name and symbol with `Store::find_rows`.

The history index (`history/`, [ADR 0044](../../docs/adr/0044-history-index-and-query-layer.md)) is a second cache of the same kind: `repos/<id>/history.sqlite3`, outside backup and migrations, recreated (then backfilled from the operation log) when unreadable. Its format is not a contract: read it through `QueryChanges`, not with SQL. It keeps one row per change with its outcome, its activity per agent and workspace, and the paths and symbols its net diff touches. `history/follow.rs` reads each open repository's log after a stored frontier through `subscribe::feed`, applies each operation's effects, and backfills older operations newest first; `history/touch.rs` computes a change's touches once it settles, with `symbols::diff::compute`; `history/query.rs` turns a request into one `SELECT`; `history/gc.rs` is GC's sixth step, and GC maps the operation ids its jj step rewrote with the follower paused. `[history]` has four keys: `enabled` (true), `retention` (`"90d"`, from 1 day to 10 years), `max_size` (`"512MiB"`, at least 16 MiB) and `backfill_operations` (100,000; 0 for none). `ListSymbols` by name or symbol reads in path order (`Store::find_ordered`, the `reef_path` collation) and stops at the end of its page.

## Evidence

Evidence (`service/evidence.rs`, `db/evidence.rs`, [ADR 0055](../../docs/adr/0055-evidence-object-format.md)) is a signed claim about a tree, stored in `reef.sqlite3` by migration `0007_evidence`, so backups carry it. The format is `reef-evidence`'s; the daemon holds no signing key.

| Table | Key | Holds |
| --- | --- | --- |
| `evidence_keys` | `id`, the SHA-256 of `public_key` | Each signer's DER SubjectPublicKeyInfo and algorithm (`ed25519`), machine-wide, recorded when it first signs evidence; never deleted |
| `evidence` | `(repo_id, id)`, `id` the SHA-256 of `envelope` | The canonical envelope, its `format` (1), and index columns read from its verified payload at insert: `tree_id`, `kind`, `result`, `target`, `key_id`, `started_at`, `finished_at`; plus `added_at`, `added_by_agent` (`reef-agent`) and `remote_token_id` of the first add |
| `evidence_links` | `(repo_id, change_id, evidence_id)` | The change an add named in `revision`, and the commit it resolved to |

`AddEvidence` runs `reef_evidence::Verified::check` on the blocking pool (the envelope's size, nesting and duplicate keys, `payloadType`, one signature, the key, the `keyid`, the signature over the DSSE pre-authentication encoding, and only then the payload), then on the read pool checks that the subject's tree is in the repository (`reef_lib::jj::files::tree_presence`) and resolves `revision` at the head without a snapshot, refusing a conflicted commit or one with another tree. Only then does it take the database, for one transaction that inserts the key, the evidence and the link, each unless already there; adding a stored object again changes nothing and answers `created: false`. No operation is recorded. `GetEvidence` and `ListEvidence` check each row's signature again on the blocking pool and take every field from the verified payload, never the index columns; a row whose envelope or columns were changed behind the daemon reads `SIGNATURE_CHECK_INVALID` with the payload's values, a filtered listing leaves out a row whose payload does not match the filter, and re-adding the genuine envelope repairs the row. Rows are read leniently (`LEFT JOIN` on the key, columns of the wrong type read as zero), so a changed row never fails a page. A prefix lookup is a `GLOB` range of the primary key. `ListEvidence` reads `evidence_by_tree` for a revision (resolved, snapshotting `@` first) or a tree, `evidence_links` for a change (with `current` against the change's visible commits' trees), and pages newest added first by `(added_at, id)`. `ForgetRepository` deletes the repository's evidence and links in its transaction and keeps the keys. `remote/rules.rs` gives `AddEvidence` `Rule::None`: a `write` token adds evidence in every registered repository.

### Artifacts

Artifacts (`artifacts/`, `service/artifacts.rs`, `db/artifacts.rs`, [ADR 0056](../../docs/adr/0056-evidence-artifact-store-and-retention.md)) are the bytes evidence names by SHA-256. The bytes are files; their index is in `reef.sqlite3`, added by migration `0008_artifacts` (schema 8):

```text
<state>/repos/<id>/artifacts/sha256/<first 2 hex>/<remaining 62 hex>   stored, mode 0444
<state>/repos/<id>/artifacts/incoming/<sha256>.<size>                   a partial upload, mode 0600
```

| Table | Key | Holds |
| --- | --- | --- |
| `artifacts` | `(repo_id, sha256)` | `size`, `stored_at`, `used_at` (stored, uploaded again, or named by evidence added), `collected_at` (set on a tombstone: retention deleted the bytes while evidence still names them), and the adder and remote token of the upload that last stored the bytes |
| `evidence_artifacts` | `(repo_id, evidence_id, sha256)` | Which digests each evidence object's payload names; no foreign key to `artifacts`, since evidence may name bytes never uploaded |

`AddEvidence` writes its object's `evidence_artifacts` rows from the verified payload in its transaction (rewriting them on a re-add) and marks each named artifact row used; it reads the row back in the same transaction, so a GC deleting it meanwhile never fails the add. Evidence stored under schema 7 is indexed once by `db::index_evidence_artifacts`, the one Rust step after the migrations, which reads every stored payload without checking signatures and sets `meta.evidence_artifacts_indexed_at`. Reads of evidence fill each artifact's `state`, `size` and `collected_at` from `artifacts` with one `IN` query per page.

Only a `Digest` (64 lowercase hex digits, checked) names a path. `ArtifactBytes` (`artifacts/store.rs`) is the seam a remote store replaces: `received`, `append`, `check`, `commit`, `open`, `stat`, `remove`, `stored` and `sweep_incoming`, all blocking and run on the blocking pool; `LocalArtifacts` (`artifacts/local.rs`) implements it over the layout above. An append opens the partial upload with `O_APPEND` and checks its length first, under one of 32 striped mutexes, so two writers never interleave inside a chunk; a check fsyncs the complete file and hashes it with ring, deleting it on a mismatch; a commit then makes it `0444`, renames it into `sha256/` and fsyncs the directory. No method creates a directory above `artifacts/`, so nothing recreates a forgotten repository's directory. `AppState::artifacts` holds each repository's store and `ArtifactLock`, a `tokio::sync::Mutex` taken by GC while it collects, by `ForgetRepository`, by an upload's commit after the hash (the repository checked again, the rename, the row), by an upload's stored-digest answer when a stored row matches, and by a damaged read's quarantine while it deletes; never by appends or hashing. GC and forget both take it after the repository's create lock.

`UploadArtifact` is a chunked unary call keyed by digest and size: a stored digest (its row stored and its file present at the row's size; a read, then the lock only when a row matches) answers at once with the record and `created: false`; otherwise the chunk is appended at `offset`, which must be the bytes received (`ARTIFACT_OFFSET_MISMATCH` with `received`); an empty call at offset 0 is a probe; once the bytes reach the size, they are hashed without the lock, and the commit, holding it, checks the repository is still registered (`REPOSITORY_NOT_FOUND` after a forget), renames them and inserts or updates the row, only while the repository's row exists (a tombstone becomes stored again). `max_object_size` is checked on every call after the dedup check and before anything is written, and a chunk is at most 1 MiB (`artifacts::MAX_CHUNK`). `ReadArtifact` streams from the blocking pool through a channel of four messages; the first carries the record. A read of the whole artifact hashes what it sends: on a mismatch the daemon hashes the file again and, if it is still wrong, takes the lock and, unless an upload repaired it meanwhile, makes the row a tombstone and deletes the file, then ends the stream with `ARTIFACT_DAMAGED` after the data; a stored row whose file is missing, or of another length than the row's size, is `ARTIFACT_DAMAGED` (`missing`, `size`) before any data, or `ARTIFACT_COLLECTED` when GC collected it since the row was read. No artifact RPC records an operation. `remote/rules.rs` gives `UploadArtifact` `Rule::None`, and the web listener serves `GetArtifact` and `ReadArtifact`, which are `ACCESS_READ`.

Backups copy each repository's `artifacts/sha256/` to `<dest>/repos/<id>/artifacts/sha256/` with `Existing::Keep`, after the database and before its jj state (`BACKUP_STEP_ARTIFACTS`), leaving partial uploads out, and record `artifact_files` and `artifact_bytes` in the manifest; GC, the only thing that deletes genuine artifacts, cannot run meanwhile, so every stored row of the database copy has its file; a damaged read's quarantine (only bytes failing their digest) and `ForgetRepository` (a whole repository) are the exceptions. Restore stages the copy beside `<state>/repos/<id>/artifacts` and renames it into place with the repository's other copies, keeping what was there as `.replaced-<nanos>`. `ForgetRepository` deletes the repository's `artifacts` and `evidence_artifacts` rows, and the files go with `repos/<id>/`.

### Retention

GC's seventh step (`artifacts/retention.rs`), after history and before the reindex, under the create lock, keeps what live work needs and deletes the rest:

1. **Mark**: `reef_lib::jj::files::live_set` evaluates `trunk() | bookmarks() | working_copies() | mutable()` once, with Reef's aliases, on the read pool, and the live trees and changes go into temporary tables on the database connection (`Db::create_live_tables`). Evidence is pinned (`db::PINNED`) when its tree is a live tree or a link ties it to a live change.
2. **Evidence**: what is not pinned and was added before `min(now - [evidence] retention, keep_newer)` is recorded in `temp.gc_doomed`, then deleted with its links and `evidence_artifacts` rows, 1,000 objects per transaction, each checked again in its transaction. Evidence keys stay.
3. **Artifacts**, with the `ArtifactLock` held: nothing used at or after `keep_newer` is touched; an artifact no evidence names loses its row and file once used before `min(keep_newer, now - UPLOAD_GRACE)` (a day, so an upload waiting for its evidence survives `[gc] undo_window = "0s"`), and one named only by evidence that is not pinned becomes a tombstone once used before `now - [artifacts] retention`.
4. **Cap**: while the stored sizes pass `[artifacts] max_size`, the least recently used of what may be collected goes; what is pinned, or used within the upload grace, never does, and the step warns when those alone pass the cap.
5. **Tidy**: tombstones no evidence names lose their rows; partial uploads last written more than a day ago go; stored files with no stored row and an mtime more than an hour old go; a stored row with no file becomes a tombstone, logged, so it reads as collected.

A row changes, in a transaction that checks its planned `used_at` again, before its file is removed, so a crash leaves only an orphan file for the next tidy. A dry run decides the same and changes nothing. `GcReport` gains `evidence_removed`, `artifacts_collected`, `artifact_bytes_freed`, `artifact_bytes` and `evidence_error`: a failure of this step is logged and the run goes on, but it is reported, since evidence and artifacts are not a cache. `[evidence]` has `retention` (`"90d"`; `0s`, or 1 day to 10 years; `0s` keeps everything); `[artifacts]` has `retention` (`"30d"`, the same range; `0s`: never by age), `max_size` (`"10GiB"`, at least 64 MiB) and `max_object_size` (`"1GiB"`, 1 KiB to 64 GiB). A reader of deleted evidence gets `EVIDENCE_NOT_FOUND`; a collected artifact reads `ARTIFACT_STATE_COLLECTED`, and `ReadArtifact` of it is `ARTIFACT_COLLECTED`.

## Identity

Operator identities and session keys (`identity/`, `service/identity.rs`, `db/identity.rs`, [ADR 0057](../../docs/adr/0057-operator-identities-and-session-keys.md), [docs/identity.md](../../docs/identity.md)) bind the keys that sign evidence to a person or a CI pipeline. Migration `0009_identity` (schema 9) adds four machine-wide tables, all in backups; none holds a private key.

| Table | Key | Holds |
| --- | --- | --- |
| `identity_authorities` | `id`, the SHA-256 of `public_key` | Each authority key the daemon has had: its DER SubjectPublicKeyInfo, host, `created_at`, `retired_at` (unset for the current one), and its revocation; never deleted |
| `identities` | `id`, `idn_<16 hex>` | Each identity's unique, never-reused `name`, `kind` (`person` or `ci`), display name, email, and revocation; never deleted |
| `sessions` | `id`, `ses_<16 hex>` | The identity, actor and channel (`socket`, or the remote token's id) of a session's keys, and its revocation |
| `identity_oidc` | `id`, `oidc_<16 hex>` | Each OIDC issuer and subject an identity accepts keyless keys for (R3.42), and its revocation; never deleted |
| `session_keys` | `key_id`, the evidence key id | Each key's certificate (a canonical DSSE envelope, or a keyless key's Sigstore bundle with `issuer_kind` `sigstore` and its `oidc_id`), the columns that index it (session, identity, authority, actor, presence, custody, window), the issuer's `reef-agent` and remote token, and its revocation |

`remote_tokens` gains `identity_id`, the identity a token is linked to.

**The authority.** `identity::authority` loads `<state>/identity/authority.pem` (`0600` in `0700`) at start, after the migrations and before the socket serves, and checks it against the current row; a missing, unreadable or mismatched file retires the row and makes a new key (written to a temporary file created new, synced, renamed, and the directory synced), logging both key ids, and a loose mode is fixed with a warning. A restore retires the restored authority in the database (`maintenance::restore`), so the next start makes a new one whatever file is there. The private key is held in `Identities` behind a `std::sync::RwLock` that issuance takes only to sign, and `RotateAuthority` swaps. The same start creates the default `person` identity, named after the login user, when there is none (`meta.default_identity_id`), and logs, and runs with no default, when `[session_keys] default_identity` names no live person identity.

**Issuance** (`identity::issue`). `IssueSessionKey` checks the key and the proof of possession, addressed to the current authority's key id, on the blocking pool; then the identity by the channel's rules (socket: any live `person`, never `ci`; remote: only the token's linked identity, never `human`, and none without a link, `Rule::LinkedIdentity`); a continued session's identity, actor, channel and revocation; that the key is neither certified nor a bare evidence key already (`SESSION_KEY_EXISTS`); Then the authority signs the certificate (`reef_evidence::session::certify`), refusing if a rotation moved the authority since the proof was checked, and one transaction counts the identity's unexpired keys against its limit of 10,000 and inserts the session, if new, and the key. No operation is recorded. Every issuance and revocation is logged under `reef_daemon::identity::audit`.

**Reads** (`identity::read`). Every read of a key checks its certificate again (`check_certificate` against the authorities' recorded keys) and reports the certificate's fields; it is valid only when it verifies, is the row's bytes, and certifies the row's key. An invalid one reports only the key id and the daemon's records of the row. Evidence whose signature does not verify reads `INVALID` with no key, whatever its `key_id` column names. Revocations are looked up by the certificate's session and identity, never the columns. Evidence reads join a page's key ids to `session_keys` in one query, check the certificates in the blocking job that checks the envelopes, and report `Evidence.identity`: the status at the evidence's `added_at` (`UNBOUND`, `BOUND`, `EXPIRED`, `REVOKED` or `INVALID`) and the key. `ListEvidence`'s `identities` filter selects by the columns and keeps only what the certificates confirm.

**Revocation** sets `revoked_at` and `invalid_from` on a key, a session, an identity or an authority (`RevokeAuthority` for a retired one, `RotateAuthority` with `revoke` for the current one); a later revocation keeps the first `revoked_at` and only moves `invalid_from` earlier. The current default identity cannot be revoked. A key is live (`ListSessionKeys`, `live_session_keys`) while it, its session, its identity and its authority are all unrevoked.

**GC** (`identity::retention`) sweeps, in the first report of a run, keys whose `not_after` is before `min(now - 7 days, keep_newer)` and that no evidence or provenance record names (`pinned()`), then sessions left with no key; `GcReport.session_keys_removed` counts them. `ForgetRepository` touches none of these tables.

**Keyless keys** (`identity::sigstore`, [ADR 0066](../../docs/adr/0066-sigstore-keyless-session-keys.md)). `identity_oidc` holds each identity's exact OIDC issuers and subjects (one live match per pair). `RegisterSigstoreKey` verifies a Sigstore bundle offline with `reef_evidence::sigstore::check_sigstore_bundle` against the trusted root `[sigstore]` loaded at start (the one Reef ships, or `trusted_root`; none when `enabled = false` or it does not load), on the blocking pool; finds the live match of the certificate's issuer and subject; applies the identity (live, never `human` for `ci`) and the statement's session (a keyless session, channel `sigstore`, with the same identity and actor); records the Fulcio CA in `identity_authorities` (`kind` `sigstore`, retired from the start); and stores the key in `session_keys` with `issuer_kind` `sigstore`, the bundle as `certificate`, Fulcio's window, and `oidc_id`. The same bundle again returns the record. Reads verify the bundle again and take the identity from the recorded match, which must still name the certificate's issuer and subject; the match's revocation applies beside the others.

## Provenance

Provenance records (`provenance/`, `service/provenance.rs`, `db/provenance.rs`, [ADR 0058](../../docs/adr/0058-provenance-records.md), [docs/provenance.md](../../docs/provenance.md)) are the daemon's signed statements that it recorded a commit for a workspace. Migration `0010_provenance` (schema 10) adds two tables, per repository, in backups, deleted by `ForgetRepository`.

| Table | Key | Holds |
| --- | --- | --- |
| `provenance` | `(repo_id, id)`, `id` the SHA-256 of `envelope` | One canonical DSSE envelope per recorded commit (unique by `commit_id`), and columns indexing its payload: change, tree, workspace, session, sequence, kind, key, agent, the declared context and its digest, `recorded_at` |
| `provenance_sessions` | `session_id`, `ses_<16 hex>` | Each workspace's session: its identity (none when unbound), actor, agent label and channel, fixed; the context declared last; `next_sequence`, `missing_records`, `problem`, `started_at`, `ended_at` (one live per workspace) |

**Recording** (`provenance::record`). Each snapshot that commits calls `Provenance::record` on its blocking half after `record_commit`; `EditFiles` naming an active workspace calls it after the write. Under the workspace's lock it finds the live session (starting one by the rules for a workspace without one), renews the held key when there is none, it is for another session, or it is within five minutes of its end (a new session when R3.03 revoked this one; an uncertified key, with `problem`, when no identity binds), builds the record with `recordedOn` the signing time, signs it with `reef_evidence::provenance::sign`, and inserts it with its key's `evidence_keys` row in one transaction that moves `next_sequence` past it. A failure is logged at `warn` and counted in `missing_records`; the snapshot's outcome never changes. `identity::issue::issue_held` certifies held keys with `custody: daemon`, without a proof, for `[session_keys] max_lifetime`; they live only in `Provenance`'s memory and every revocation handler drops them (`Provenance::revoked`).

**Sessions** (`provenance::session`). `CreateWorkspace` plans the session before creating anything (an identity or actor the rules refuse fails the creation), then starts it with the workspace; release and reclaim end it after the final snapshot. `DeclareProvenance` snapshots first unless `no_snapshot`, then replaces fields of the context under the workspace's lock. Declarations are logged under `reef_daemon::provenance::audit`, naming fields, never values.

**Reads** (`provenance::read`) check every record: the envelope, the key from `evidence_keys`, the signature, the statement, then every index column against the payload; then the key's certificate with R3.03's `read_keys` and `key_identity` at `recorded_at`. A certificate whose custody is not `daemon`, or whose session is not the record's, reads `INVALID`.

**GC** (`provenance::retention`), step 8: resolves each change of the old records in the head's view (`files::visible_commits_of_changes`), compacts records older than `[provenance] compact_after` to the first and last of each run by context digest (and any of a visible commit), deletes records of changes with no visible commit older than `retention`, and ended sessions with no record, 1,000 per transaction; `GcReport.provenance_compacted`, `provenance_removed` and `provenance_error`.

## Executor protocol

The executor protocol's job queue (`executor/`, `service/executor.rs`, `db/jobs.rs`, [ADR 0059](../../docs/adr/0059-executor-protocol.md), [docs/executor-protocol.md](../../docs/executor-protocol.md)): requesters submit jobs (checks of some evidence kinds and targets on a tree), and executors, processes outside Reef that dial the daemon, claim them under a lease and return signed evidence. The daemon never connects to an executor and never runs anything. Migration `0011_jobs` (schema 11) adds two tables, per repository, in backups, deleted by `ForgetRepository`.

| Table | Key | Holds |
| --- | --- | --- |
| `jobs` | `(repo_id, id)`, `id` `job_<16 hex>` unique across the daemon | The spec (tree, sorted kinds, targets and requirements as JSON, budget, priority, commit and change), its SHA-256 for the dedupe, the state with its outcome or end reason, attempts, the submitter, the current claim (its token's blake3 digest, lease, deadline), the executor's declared fields, its token and linked identity, progress, usage, `elapsed_ms` |
| `job_evidence` | `(repo_id, job_id, evidence_id)` | Each evidence object a job accepted: the attempt, its kind and target from the verified payload, `created`, `fresh`, `accepted_at`; no foreign key to `evidence`, whose retention is its own |

**Transitions.** Every one (submit, claim, update, release, complete, cancel, lapse, deadline, queue timeout) is one immediate transaction that reads the job again (`Executor::transition`, `Db::transact`); there is no per-job lock. After the commit, still under the database lock (`Db::transact_then`), the job's presence entry is published, waiting claims wake when it was queued again, and the timer wakes, so publishes keep commit order. The timer (`Executor::tick`) reads the open rows (at most `[executor] max_open_jobs`), applies what is due through the same transactions, and sleeps until the next due time, at most 30 s. The queue's clock is the wall clock plus an offset that tests move (`Executor::advance`, `testing` feature). At start, running claims get at least one more lease and every open job's entry is published again.

**Claims** (`ClaimJob`) wait on a `Notify` signalled by submissions and requeues (at most 16 per remote token, `MAX_WAITING_PER_TOKEN`; past it a claim answers at once), select the best matching queued job in Rust inside the transaction, and return a claim token `"<attempt>.<32 random bytes, base64url>"`; only its blake3 digest is stored, compared in constant time. The attempt in the token tells `lapsed` from `wrong_token`.

**Evidence** (`executor::accept`). The service checks the job and its owner, verifies the call's envelopes on the blocking pool with `Verified::check`, and binds them to the job's tree and kinds; then one transaction applies any lapse that came due, checks the claim, checks completeness for `DONE`, and stores each object through `db::add_evidence_in` (the insert `AddEvidence` uses, rows from `service::evidence::evidence_rows`) with a `job_evidence` row. Evidence is added by tree, with no link.

**Presence** (`executor::presence`): one daemon entry per open job, kind `JOB`, `DaemonKey::Job`; the terminal state is published and the entry ended (`CLEARED`). `ReportPresence` refuses kind `JOB` (`DAEMON_PRESENCE`).

**Remote rules**: `SubmitJob` `Rule::None`, `ClaimJob` `Rule::LinkedToken` (through `service::identity::channel_of`), `UpdateJob` and `CompleteJob` `Rule::OwnClaim`, `CancelJob` `Rule::OwnJob`. Transitions are logged under `reef_daemon::executor::audit`; a claim token never is.

**GC** (`executor::retention`), step 9: finished jobs older than `[executor] job_retention` and `keep_newer` go with their `job_evidence` rows, 1,000 per transaction; `GcReport.jobs_removed` and `jobs_error`.

## Web UI

The web UI's listener (`web/`, [ADR 0047](../../docs/adr/0047-web-ui-transport-and-local-listener.md)) is the daemon's second, after the socket. Nothing is bound at start. The first `DaemonService.CreateWebSession` (ADMIN, so only on the socket) checks `[ui] enabled` and that the daemon embeds the built app rather than `reef-web`'s placeholder (`web::Limits::assets_built`, default `reef_web::BUILT`), then binds `[ui] listen` (a loopback IP literal with a port, `127.0.0.1:0` by default) under `WebUi`'s mutex, so concurrent calls bind once and a failed bind leaves the next call to retry. The listener is a second tonic server over the same services and `AppState` (`server::routes`, `server::web_router`): HTTP/1.1 and HTTP/2, `WebGateLayer`, then `tonic_web::GrpcWebLayer`, then `CompatLayer`. Its accept loop is `limits::Accepting` over a `TcpListener`, capped at 64 open connections (one more is accepted and closed), and a shutdown hook joins its server within the shutdown grace. It stays bound until the daemon stops.

The gate (`web/gate.rs`) checks every request in order, and never calls the inner service for one it refuses: `Host` is the bound authority exactly (`421`); no `Upgrade` (`400`) and no `OPTIONS` (`405`); `GET` and `HEAD` off API paths serve the embedded assets (`web/assets.rs`: an exact path, else `index.html` for a path whose last segment has no `.`, else `404`); an API path is `POST` (`405`); `Origin` and `Sec-Fetch-Site`, when sent, are this origin's (`403`); the content type is binary gRPC-web (`415`); `authorization: Bearer <token>` names a live session (`WEB_SESSION_INVALID`), and the header is removed; the method is `ACCESS_READ` (`WEB_ACCESS_DENIED`). The last two answer as gRPC-web trailers-only responses built from the same `tonic::Status` as every other error. Every response carries the security headers in `gate::SECURITY_HEADERS` and, unless it set its own, `Cache-Control: no-store`; no response carries CORS headers.

Sessions (`web/session.rs`) are kept in memory only, keyed by the blake3 of their token: 32 bytes from the thread's CSPRNG, base64url. A request holds its session in use until its response body ends (`web/body.rs`), so a session with a stream open never idles; one unused for `session_idle` (24 hours) with nothing open ends when next looked up or at the next mint, and at `max_sessions` (32) a mint ends the least recently used session with no stream open (the least recently used of all only if every one has a stream open). Launch files (`web/launch.rs`) are `<state>/ui/open-<16 hex>.html`, `0600` in a `0700` directory: a page with no script that refreshes to the session URL, for `reef ui` to open by path. Each is deleted at its session's first request, after `launch_file_ttl` (60 s), or by the sweep in start's first step. The token never enters a `tracing` field.

## Remote listener

The remote listener (`src/remote/`, [ADR 0049](../../docs/adr/0049-remote-listener.md)) is the daemon's third listener, and the only one reachable from another host. `RemoteListener::start` runs at start-sequence step 11: it starts the tokens' upkeep (last use flushed once a minute, expired tokens' streams ended within a second) and, when `[remote] enabled` or `--remote` asks, a task that loads the certificate (`remote/tls.rs`: generated in `<state>/remote`, or `[remote] tls_cert` and `tls_key` re-read on change) and binds `[remote] listen`, retrying both with backoff while the socket serves. Its accept loop (`remote/incoming.rs`) closes connections from addresses in backoff and over the connection caps before TLS, handshakes in tasks of their own (64 at once, 10 s each), and hands finished connections to a tonic server over the same routes as the socket's (`server::remote_router`): `RemoteGateLayer`, `tonic_web::GrpcWebLayer`, `RemoteCallLayer`, then `CompatLayer`.

The gate (`remote/gate.rs`) is R2.18's for a non-loopback origin, then the bearer token (`remote/tokens.rs`, blake3 digests, in memory and in `remote_tokens`), its scope against the method's access level (never ADMIN), and its per-token limits. It puts a `remote::Caller` in the request's extensions; `service::caller_of` marks the request's agent with the token (`oplog::RemoteToken::mark`), so every operation the call records carries `reef.remote-token`, and handlers apply the WRITE rules (`remote/rules.rs`). `RemoteCallLayer` (`remote/streams.rs`) sees native gRPC whatever the client spoke: it ends a stream whose token ended and logs every WRITE call's outcome under `reef_daemon::remote::audit`.
